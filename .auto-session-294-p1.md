# Auto-session 294 P1: Disassemble 0x03013A (main key acquisition delegate)

## Context
The TI-84 Plus CE OS keyboard input chain has been traced through three levels:
- 0x02FCB3 (GetCSC wrapper) → CALL 0x02FD8F
- 0x02FD8F (key acquire) → CALL 0x03013A (this target)
- Neither 0x02FCB3 nor 0x02FD8F contain any IN instructions or keyboard MMIO (0xE00900) reads

0x03013A is the main key acquisition delegate — it likely contains the IN instructions that actually read keyboard hardware port 0xE00900, or calls the function that does.

## Task
Create a probe file `TI-84_Plus_CE/probe-phase294-03013a-key-acquire.mjs` that:

1. Reads `TI-84_Plus_CE/ROM.rom` directly (raw binary, 4MB)
2. Uses `TI-84_Plus_CE/ez80-decoder.js` to decode instructions starting at 0x03013A
3. Follows the linear instruction stream (stop at RET/JP/JR unconditional, note but continue through CALL)
4. For EACH instruction, check:
   - Does it use IN (port read)? Log the port address
   - Does it reference 0xE00900-0xE009FF (keyboard MMIO range)?
   - Does it read/write D0058C (scan code storage)?
   - Does it read/write D0058E (keyExtend)?
   - Is it a CALL? Log the target address
   - Is it a conditional branch (JP cc / JR cc / DJNZ)? Log both paths
5. At conditional branches, follow the fall-through path but log the branch target
6. Report: total instruction count, total byte range, all CALL targets, all IN instructions, all MMIO references, all D0058C/D0058E accesses
7. If NO IN instructions found, report that clearly — it means we need to go deeper into one of the CALL targets

## Reference
Use `TI-84_Plus_CE/probe-phase293-02fd8f-key-acquire.mjs` as a template for the probe structure, imports, and formatting utilities. It follows the exact same pattern.

## Key technical details
- ROM file is raw binary, byte at file offset N = ROM address N
- ez80-decoder.js: `decodeInstruction(romBuffer, address)` returns instruction object
- Instruction object has: `.tag`, `.length`, various operand fields depending on tag
- eZ80 addresses are 24-bit (3 bytes). ROM occupies 0x000000-0x3FFFFF
- D0058C and D0058E are RAM addresses (data segment)
- Keyboard MMIO is at 0xE00900 range

- Maximum 500 instructions before stopping (prevent infinite loops)
