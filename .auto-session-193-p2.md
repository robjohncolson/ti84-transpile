# Auto-Session 193 P2: STAT LDDR Block Inspection — Why 0x092265 Is Never Reached

## Context
In session 192, we confirmed that seed 0x092265 exists in PRELIFTED_BLOCKS (the block walker already discovered it). The LDDR instruction is at 0x092263, and the static disassembly of 0x092265 shows valid code (LD DE, POP BC, ADD HL,BC, LDIR, INC (HL), RET). However, when tracing from 0x058BA9 (STAT entry), the LDDR block is reached but execution falls to the boot vector (0x000000) instead of continuing to 0x092265.

The hypothesis is that the transpiler treats LDDR as a block-terminating instruction that always falls through to address 0 (or some wrong target), OR the LDDR's BC register is 0 causing immediate termination and wrong fallthrough.

## Task
Create a new probe `TI-84_Plus_CE/probe-phase193-stat-lddr-inspect.mjs` that:

1. **Inspects the transpiled block containing 0x092263** — read ROM.transpiled.js and find the block function that starts at or contains address 0x092263. Extract:
   - The block's start address
   - What the LDDR instruction does with registers (BC, DE, HL)
   - What the block's fallthrough/next target is after LDDR completes
   - Whether there's a conditional that checks BC==0 after LDDR

2. **Single-step trace from the LDDR block entry** — set up CPU state as if we just arrived at the LDDR block from the STAT trace:
   - Execute the STAT trace from 0x058BA9 up to just before the LDDR block fires (use the 87-block trace from session 192 as reference)
   - At the moment 0x092263 is about to execute, log: BC, DE, HL, SP, A, flags
   - Then execute the LDDR block alone and log: what address it jumps to next, and register state after

3. **Check the transpiled source** of the 0x092263 block:
   - Use a regex or string search in ROM.transpiled.js to find the block function
   - Print the first 50 lines of that function
   - Look for: does it call `blocks[0x092265]` or `missing_block(0x092265)` or just fall off?

## Approach for Reading Transpiled Block
The transpiled JS has blocks as functions. Search for a pattern like:
```
blocks[0x092263] = function
```
or
```
blocks["092263"] = function
```
The exact format depends on the transpiler output. Check `scripts/transpile-ti84-rom.mjs` for the block naming convention if needed. Alternatively, look at how existing probes reference blocks.
