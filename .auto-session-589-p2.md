## Background
0x061DEF is called in the type≥0x62 extended symbol lookup path of the multi-type symbol lookup dispatcher 0x09D49A (session 588). When the type byte at D005F9 is ≥ 0x62 but NOT 0x72 or 0xAA, the dispatcher checks D005FA (subfield) and calls 0x061DEF when the subfield is zero. This is one of 5 new call targets discovered in session 588.

The symbol lookup system works with: D005F8 (result byte), D005F9 (type byte / search key), D005FA (subfield byte). The symbol table searcher 0x0846EA does backward search from D0259D/D3FFFF toward D02590.

## Decoder API (CRITICAL — use exactly this)
```javascript
import { readFileSync } from 'fs';
import { decodeInstruction } from './ez80-decoder.js';

const rom = readFileSync('TI-84_Plus_CE/ROM.rom');

// Decode one instruction:
const inst = decodeInstruction(rom, address, 'adl');
// inst.length  — bytes consumed
// inst.asm     — formatted assembly string
// Raw bytes: rom.slice(address, address + inst.length)

let pc = 0x061DEF;
const endAddr = pc + 128;
while (pc < endAddr) {
  const inst = decodeInstruction(rom, pc, 'adl');
  const bytes = rom.slice(pc, pc + inst.length);
  const hex = Array.from(bytes).map(b => b.toString(16).padStart(2, '0')).join(' ');
  console.log(`0x${pc.toString(16).padStart(6, '0')}  ${hex.padEnd(20)}  ${inst.asm}`);
  // Stop at unconditional RET or JP (not JR, not conditional)
  if (inst.asm === 'RET' || inst.asm.startsWith('JP ') && !inst.asm.includes(',')) break;
  pc += inst.length;
}
```
