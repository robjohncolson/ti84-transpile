# Task: Trace the 14 Zero-Caller Vector Table Entries

## Context
The TI-84 Plus CE OS has a 56-entry jump vector table starting at `0x000578`. Each entry is a 4-byte JP instruction (eZ80 ADL mode). Session 309 mapped all 56 entries and found that 14 entries have ZERO direct CALL sites in the ROM. These entries must be reached via computed jumps, table indexing, or JP (not CALL).

   - Searches the entire ROM for any reference to the vector address as a 3-byte LE value (not just CALL — also LD, JP, data references) to find computed-jump or table-lookup patterns
   - For entries 51/52 (targets 0x0060F7/0x0060FA): since they have many direct callers, investigate what the vector entries add — do any callers use the vector address instead of the direct address?

## Technical Details

- ROM file: `TI-84_Plus_CE/ROM.rom` (4MB, read with `readFileSync`)
- Decoder: `import { decodeInstruction } from './ez80-decoder.js'` — usage: `decodeInstruction(romBuffer, address, 'adl')` returns `{tag, length, target?, ...}`
- Vector table: starts at 0x000578, 56 entries × 4 bytes each, ends at 0x000658
- SDK reference: `TI-84_Plus_CE/references/ti84pceg.inc` — search for vector addresses to find SDK names
- To search for a 3-byte LE address pattern in ROM: scan for bytes `[addr & 0xFF, (addr >> 8) & 0xFF, (addr >> 16) & 0xFF]`
