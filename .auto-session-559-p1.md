# Task: Decode 0x0A1799 — The Actual Glyph Renderer

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80). We're decoding OS functions to understand the text rendering pipeline.

**Call chain**: 0x0A1CAC (string loop) → 0x0A1B5B (per-char dispatch) → **0x0A1799** (glyph renderer — THIS TARGET).

0x0A1799 is the function that actually writes glyph pixels to the framebuffer. It's called from 0x0A1B5B after the special-token check (CP 0xD6) passes. The character to render is likely in register A when called.

## Known architecture
- Font table at ROM 0x07BF3E, base offset 0x0380, 13px wide fixed-width, 256 glyphs
- 4BPP glyph renderer at 0x07B75F (161B, row calc + nibble write, double-buffer D09466/D0EA1F)
- Mono/4bpp/16bpp routing at 0x0A1B14+0x0A1B1C
- Framebuffer address computed to D0059C
- D000C6 bit 2 = BPP mode flag
- IY base = D00080 (system flags)
- D008D5 = primary Y coordinate (265 refs)
- D0231A = cursor position

## Deliverable
Create `TI-84_Plus_CE/probe-phase559-decode-0A1799.mjs` that:
1. Reads the ROM binary at `TI-84_Plus_CE/ROM.rom`
2. Disassembles starting at 0x0A1799 for up to 256 bytes (or until RET/JP found)
3. Documents each instruction with comments
4. Identifies: what registers hold on entry, how it indexes the font table, how it writes pixels, what BPP dispatch it uses
5. Prints a structured summary of the function's purpose, size, call targets, and RAM addresses used

Use the eZ80 instruction set (24-bit addresses, 3-byte LD ops). Key opcodes:
- ED prefix = extended instructions (MLT, LEA, etc.)
- DD/FD = IX/IY prefix
- CB = bit operations
- 3-byte addresses in little-endian
