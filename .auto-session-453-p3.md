# Task: Increase Step Budget to 700K and Test Polling Loop Exit

## Context
In the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, session 452 decoded the polling loop at 0x003D6B:

```
LD BC, 0x0800 (2048 inner iterations)
DJNZ with B=0x34 (52 outer iterations)  
CALL 0x003C63 (debounce) per iteration
Total: 52 × (debounce + 8192 steps) ≈ 425-500k steps
```

This is the _GetCSC key-scanning delay loop. After processing a key, the event loop calls _GetCSC again. Since no second key is injected, _GetCSC enters the full delay loop. With 500k post-consume steps, execution hits the step limit mid-loop. At 700k steps, the loop should exit naturally (XOR A/RET when no key found), and execution should return to the event loop.

## Deliverable
Create `TI-84_Plus_CE/probe-phase453-700k-budget.mjs` — a probe based on `probe-phase451-enhanced-workflow.mjs` with:

1. **POST_CONSUME_STEPS increased from 500,000 to 700,000**.

2. **Only inject ONE key** (key "1", scan 0x12) — we want to observe what happens after _GetCSC's delay loop exits, not test multi-key rendering.

3. **Track the final PC after 700k steps** — did execution exit the polling loop and return to the event loop? Report the final PC and whether it's back near 0x003A73 (event loop) or somewhere else.

4. **Track whether the probe reaches HALT** (DI+HALT at 0x001933-0x001942) — if the polling loop exits and returns to the event loop, the event loop should eventually re-enter the HALT barrier waiting for an interrupt.

5. **Print timing breakdown**: steps consumed by burst (scan code consumption), steps for key processing (0x001713→0x0008BB→display path), steps for _GetCSC polling loop, steps after polling loop exit.

6. **Add breadcrumb tracking** for key addresses:
   - 0x003D5A (_GetCSC entry)
   - 0x003D6B (polling loop body)
   - 0x003A73 (event loop re-entry)
   - 0x001933-0x001942 (HALT range)
   Track the LAST step at which each was visited (not just first).
