# Auto-Session 394 P4: Coverage Push — Gap Analysis + New Seeds

## Context
Current coverage: ~95.92% of non-erased ROM bytes. 144,311 transpiled blocks. We need to push coverage higher by finding new seed addresses from gap analysis.

## Task

1. Run the coverage gap analyzer:
   ```
   node TI-84_Plus_CE/coverage-analyzer.mjs
   ```
   Capture its output — it identifies the largest uncovered ROM regions.

2. Run the true-coverage audit:
   ```
   node TI-84_Plus_CE/audit-true-uncovered.mjs
   ```
   This gives the actual coverage percentage and identifies uncovered byte ranges.

3. From the gap analysis output, identify 8-12 candidate seed addresses. Good seeds are:
   - At the START of uncovered regions (not in the middle)
   - In code regions (not data tables, not erased 0xFF regions)
   - Aligned to likely function starts: look for common eZ80 prologue bytes at the candidate address:
     - 0xC5 (PUSH BC), 0xD5 (PUSH DE), 0xE5 (PUSH HL), 0xF5 (PUSH AF)
     - 0xDD E5 (PUSH IX), 0xFD E5 (PUSH IY)
     - 0x3E (LD A,n), 0x21 (LD HL,nn), 0x01 (LD BC,nn)
     - 0xCD (CALL nn)

4. Read the ROM file to verify each candidate:
   - Read bytes at the candidate address
   - Check if it looks like code (not 0xFF fill, not ASCII data, not table entries)
   - Verify it's not already covered by checking against the transpiler output

5. Add the verified seeds to the transpiler. Read `scripts/transpile-ti84-rom.mjs` to find the seeds array, then add your new seeds.

6. Run the transpiler:
   ```
   node scripts/transpile-ti84-rom.mjs
   ```

7. Run the golden regression:
   ```
   node TI-84_Plus_CE/probe-phase99d-home-verify.mjs
   ```
   This MUST pass. If it fails after adding seeds, remove the seeds that caused the failure.

8. Run the coverage audit again to measure improvement:
   ```
   node TI-84_Plus_CE/audit-true-uncovered.mjs
   ```

9. Print summary: how many seeds added, how many new blocks, old vs new coverage percentage.
