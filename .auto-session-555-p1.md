# Task: Find Small Font Table — Code-Path Trace Through BIT 1,(IY+0x14)

## Context
The TI-84 Plus CE ROM at `TI-84_Plus_CE/ROM.rom` has been partially reverse-engineered. We know:
- **0x07BF3E** is the glyph table lookup function (76B). It calls 0x000380 which returns font base = 0x003D6E.
- **0x0A23E5** is the character renderer/blit loop (~512B).
- **BIT 1,(IY+0x14)** is the global font size flag — checked by 0x0801B9 (125 callers). When set = "small font mode".
- Session 554 confirmed only ONE font table exists at 0x003D6E (256 glyphs × 28B). The "small font" flag likely controls **rendering** (row skip, scale, stride), NOT a separate table.
- 0x07B75F Entry A: when BIT 1,(IY+0x14) is set, uses H=0x5D (93 rows) instead of H=0x85 (133 rows) for 8bpp mode.

## Task
1. **Disassemble 0x07BF3E fully** (the glyph table lookup, 76B from 0x07BF3E to ~0x07BF8A). Read `TI-84_Plus_CE/ROM.rom` bytes directly. Trace what happens when BIT 1,(IY+0x14) is set vs clear — does the function change the font base pointer, glyph size, or table offset?

2. **Check 0x07BF8B+ region** — session 552 mentioned a "variable-width font lookup" near here. Disassemble the next ~100 bytes after 0x07BF3E to see if there's a secondary path.

3. **Trace 0x0A23E5 for small-font behavior** — in the blit loop (~0x0A24C8-0x0A26C7), look for BIT 1,(IY+0x14) or BIT 1,(IY+0x20) checks. When small font is active, does the renderer change row height, skip every other row, or use a different stride?

4. **Search for alternate font pointers** — grep the ROM for any 24-bit value pointing near 0x003D6E (but NOT 0x003D6E itself). Try: search for bytes 0x6E 0x3D 0x00 in different orderings in the ROM. Also search for 0x85 0x3D 0x00 (the vector at 0x003D85). Any OTHER pointer into the font table region (0x003D6E-0x00596E) would indicate a second font or alternate glyph offset.
