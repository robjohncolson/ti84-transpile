# Auto-Session 206, Priority 2: Debug STAT error condition — why does the OS hit an error?

## Context

In the TI-84 Plus CE ROM transpilation project, session 205 traced the STAT pipeline to 50000 steps and found it **loops at 0x082BE2** in a tight 5-block event/redraw loop (0x082BE2/0x084716/0x08471B/0x084723/0x084711, each visited 9207 times). The STAT structure at 0xD008E6 contains "Error" at offset 14 (`45 72 72 6F 72`). OP1=`03 2D` (type=0x03 string/error).

The OS entered an error condition and is spinning in an event loop waiting for user dismiss that never comes in headless mode.

Session 202 found the root cause of the huge BC value: list data was seeded at 0xD10000 (60K from OS list area). Seeding near 0xD01600 reduces BC to 245. Session 204 confirmed the LDDR block executes fully and STAT pipeline continues to 264 unique blocks.

## Task

Build a probe `TI-84_Plus_CE/probe-phase206-stat-error-debug.mjs` that investigates WHY the STAT computation hits an error condition:

1. **Dump the full STAT structure** at 0xD008E6 (32 bytes) at multiple points during execution: before STAT entry, after LDDR, and at step 3000 (before the error loop starts). Show hex + ASCII interpretation.

2. **Check list data format correctness**: The TI-84 stores list elements as 9-byte BCD floats. A properly formatted list L1={1.0, 2.0, 3.0} at address P should have:
   - `P+0`: element count as 16-bit LE (0x03, 0x00)
   - `P+2`: first float (9 bytes): `00 80 10 00 00 00 00 00 00` for 1.0
   - `P+11`: second float: `00 80 20 00 00 00 00 00 00` for 2.0
   - `P+20`: third float: `00 80 30 00 00 00 00 00 00` for 3.0
   
   Verify the seeded list data is in correct TI-OS BCD format.

3. **Check the VAT entry format**: The Variable Allocation Table entry for L1 must be correct. A real TI-84 VAT entry for a real list has:
   - Type byte (0x01 for real list)
   - 3-byte pointer to data (little-endian, the address where list data starts)
   - Version byte
   - Flags byte  
   - Name length + name bytes (L1 = name `5D 00` for system list 1)
   
   Check what session 194's probe seeded at 0xD1A800 and verify it matches the real VAT format. Also check if the VAT pointer chain at 0xD1A888 (pTemp) / OS VAT pointers is set up.

4. **Investigate STAT-mode context RAM**: Check these addresses before and after STAT entry:
   - 0xD02504: menu mode byte
   - 0xD008E0-0xD008FF: STAT workspace (what values does the OS expect here?)
   - 0xD01508: LIST_PTR_TABLE
   - 0xD01D0B: list count register
   - FreqList settings / STAT calculation mode flags

5. **Try different initializations** to avoid the error:
   - Experiment A: Current setup (near seed at 0xD01600, BC=245) — baseline, confirm error
   - Experiment B: Set 0xD02504 = 0x40 (STAT mode) before entry
   - Experiment C: Pre-populate 0xD008E6 STAT structure with valid header bytes
   - Experiment D: Seed the list with proper element count prefix (if not already done)
   - For each: trace to 5000 steps, check if "Error" appears in STAT structure, report OP1 value
