# Task: Decode 0x0A5424 Font Table Lookup

## Context
You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80). The transpiler is at `scripts/transpile-ti84-rom.mjs`. The runtime is `TI-84_Plus_CE/cpu-runtime.js`. Peripherals are in `TI-84_Plus_CE/peripherals.js`.

## What we know
- 0x0A5424 is a font table lookup function
- Called by the variable-width text renderer at 0x054FC6 (stride 25, record 0 in the font descriptor table at 0x0525D4)
- Also called by the glyph width calculator at 0x055167 (returns width in HL)
- Both callers use `MLT HL` with stride 25 before calling 0x0A5424
- The font descriptor table at 0x0525D4 has two records:
  - Record 0 (sel=0): variable-width font — renderer=0x054FC6, width=0x055167, height=0x05518C (returns 13px)
  - Record 1 (sel=1): fixed-width font — renderer=0x054E21, width=0x054FBC (returns 12px), height=0x054FC1 (returns 15px)
- The variable-width path uses 0x0A5424; the fixed-width path uses 0x07BF3E

## Your task
Build a probe script `TI-84_Plus_CE/probe-phase327-font-lookup.mjs` that:

1. **Disassembles 0x0A5424** by reading raw bytes from the ROM. Trace from 0x0A5424 until RET or unconditional JP outside the function. Decode eZ80 instructions manually (read ROM bytes, match opcodes). Document every instruction.

2. **Identifies the font table base address**: 0x0A5424 likely loads a base address from ROM and indexes into a glyph table. Find:
   - Where is the font data stored in ROM?
   - What is the record size (stride)?
   - How is the character code mapped to a table index?

3. **Reads sample glyph data**: Once you know the table base and stride, read a few glyph entries (e.g., ASCII 'A'=0x41, '0'=0x30, space=0x20) and dump the raw bytes. Are these bitmap data? Width+bitmap? Something else?

4. **Runs a dynamic trace**:
   - Load the transpiled JS: `eval(zlib.gunzipSync(fs.readFileSync('TI-84_Plus_CE/ROM.transpiled.js.gz')).toString());`
   - Create CPU + peripherals (with `timerInterrupt: false`)
   - Set up registers as 0x054FC6 would (if identifiable from the static disassembly)
   - Call 0x0A5424 and trace which ROM addresses it reads
   - Log the return value (HL or wherever the glyph pointer ends up)

## Output format
- Part A: Static disassembly of 0x0A5424
- Part B: Font table location, stride, and indexing scheme
- Part C: Sample glyph data dumps (hex bytes for 2-3 characters)
- Part D: Dynamic trace results
