# Task: Add z80-mode Seed at 0x00D7BE + Retranspile + Verify

## Context
The 10K-step boot trace (probe-phase352-extended-boot-10k.mjs) revealed that boot hits a missing block at 0x00D7BE in z80 mode — 4 times during 10K steps (at steps 2191, 4390, 6589, 8788). This is a periodic hit from a loop. No z80-mode seed exists at this address. Adding it should allow boot to progress further.

## Deliverable
1. Add a z80-mode seed `{ pc: 0x00d7be, mode: 'z80' }` to `scripts/transpile-ti84-rom.mjs` in the seeds array
2. Place it near other z80-mode seeds in the 0x00xxxx range (look for seeds like `{ pc: 0x00001a, mode: 'z80' }` or `{ pc: 0x000800, mode: 'z80' }`)
3. Run the transpiler: `node scripts/transpile-ti84-rom.mjs` — report the new block count
4. Run the golden regression: `node TI-84_Plus_CE/probe-phase99d-home-verify.mjs` — confirm it still passes (all 5 assertions)
5. Run the boot probe: `node TI-84_Plus_CE/probe-phase352-extended-boot-10k.mjs` — report:
   - Does 0x00D7BE still appear in missing blocks? (should NOT)
   - New unique block count (was 265)
   - New furthest PC
   - Any NEW missing blocks that weren't there before

## How to Find the Seeds Array
In `scripts/transpile-ti84-rom.mjs`, search for `seeds` or `mode: 'z80'`. The seeds array looks like:
```javascript
{ pc: 0x000000, mode: 'z80' },
{ pc: 0x00001a, mode: 'z80' },
...
```

Add the new seed in numerical order among the z80 seeds.

## Constraints
- ONLY modify `scripts/transpile-ti84-rom.mjs` (to add the seed)
- Do NOT modify any probe files, runtime files, or peripherals
- Do NOT modify ROM.transpiled.js.gz (it's committed but too large to regenerate in CI)
- Run ALL THREE verification steps (transpile, golden regression, boot probe)

## Success Criterion
- Transpiler produces more blocks than before (was ~147,205)
- Golden regression still passes (all 5 assertions)
- 0x00D7BE no longer appears as a missing block in the boot probe
- Boot progresses further or visits more unique blocks
