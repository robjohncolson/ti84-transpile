# Auto-Session 286 — P2: Trace 0x0159C0 Foreground Keyboard Scanner End-to-End

## Context
Session 285 discovered the TI-84 CE hardware keyboard scan engine. The central foreground scanner is at 0x0159C0:
- Loads IY=0xE00800 (keyboard controller base)
- Zeroes matrix controller registers (IY+0 through IY+15)
- Sets scan mode: (IY+7)=1, (IY+8)=1, (IY+15)=5
- Polls BIT 1,(IY+24) until set (scan complete)
- Reads LD A,(0xE00900) for scan result

We need to trace: (1) How does 0x0159C0 get called? (2) What happens AFTER the LD A,(0xE00900) — how is the scan code processed?

## Task
Create a probe `TI-84_Plus_CE/probe-phase286-0159c0-kbd-scanner.mjs` that:

1. **Static disassembly** of 0x0159C0 — decode at least 120 bytes. Map the full function until RET. Identify:
   - The BIT 1,(IY+24) poll loop
   - The LD A,(0xE00900) read
   - What happens after the read (store to RAM? return in A? call something?)
   - Where does the function RET to?

2. **Caller analysis** — Search the ROM bytes for CALL instructions targeting 0x0159C0. A CALL in eZ80 is opcode 0xCD followed by 3-byte little-endian address (C0 59 01 for ADL mode). Search the ROM binary for bytes CD C0 59 01 (or with RST variants). Also search ROM.transpiled.js for references.

3. **Dynamic trace** — Set PC=0x0159C0, IY=0xE00800. Pre-seed memory:
   - 0xE00818 (IY+24) = 0x02 (BIT 1 set, so poll exits immediately)
   - 0xE00900 = 0x35 (simulated scan code for STAT key)
   Run 100 steps. Log all instructions, memory accesses, and the final state of A.

4. **Post-scan processing** — After 0x0159C0 returns, what's the return value and where does it go? Check if A contains the scan code directly or if it's stored to a RAM location.
