# Task: Trace 0x049E07 switch dispatcher (called by 0x02F68A key pipeline)

## Context
In the TI-84 Plus CE ROM transpilation project, we've decoded 0x02F68A as a 334-byte key processing pipeline that reads hardware port 0x3082, then calls 0x049E07 TWICE. 0x049E07 is a switch-table dispatcher that resolves key codes via the state byte at (D177B9). This is likely where scan-to-keycode conversion happens.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase224-049e07-switch-dispatch.mjs` that:

1. **Static disassembly**: Read ROM.rom directly (fs.readFileSync) and disassemble 0x049E07 through at least 200 bytes. Look for:
   - The dispatch mechanism: does it read (D177B9) and use it as a table index? JP (HL)? Indirect jump?
   - Any lookup tables referenced (addresses loaded into HL/DE for indexing)
   - Sub-calls made from within the dispatcher
   - RET conditions

2. **Dynamic trace**: Boot a runtime (use the pattern from existing probes like probe-phase223-*.mjs):
   ```js
   import { createCPU } from './cpu-runtime.js';
   import { createPeripheralBus } from './peripherals.js';
   ```
   Set up with `timerInterrupt: false`. Load ROM.rom into memory. Set PC to 0x049E07 with various D177B9 values (try 0x00, 0x01, 0x02, 0x03, 0x55) and trace execution for 200 steps each. Log visited blocks, A register at RET, and any memory writes.

3. **Find the key code table**: If 0x049E07 indexes a table, dump that table's contents. The table likely maps scan codes or intermediate values to TI-OS key codes (0x5A-0xFF range).
