# Auto-Session 271 P2: Context Registration (0x09E2EC) Before Event Loop

## Goal
Test whether calling 0x09E2EC (the context registration function) before entering the event loop initializes the dispatch table pointers (D0259D, D025A3) and enables the polling loop to exit.

## Background
- The event loop at 0x082BE2 is a 5-block polling loop that searches a dispatch table
- The dispatch table uses 9-byte entries at D3FFFF downward
- Table pointers D0259D and D025A3 are 0x000000 after boot — never initialized
- Session 270 proved that manually writing entries to the table doesn't help — the loop never exits
- 0x09E2EC is the "context registration" function. Session 259 found 30 D007E0 write sites; handler[8] and handler[19] both call 0x09E2EC with A=mode
- 0x0620AE writes A=0x49 to D007E0, 0x0620C0 writes A=0x40 — these bracket cxMain caller 0x0620C4
- The hypothesis: 0x09E2EC initializes dispatch table infrastructure (pointers, entry counts, etc.), not just writes individual entries

## Task
Create a probe file `TI-84_Plus_CE/probe-phase271-context-reg-init.mjs` that:

1. Boots the system using the standard boot sequence (see reference below)
2. Runs these experiments:

**Experiment A — Call 0x09E2EC with A=0x49 (home screen context), then enter event loop**
- After boot, set A=0x49 (home-screen mode value from 0x0620AE)
- Set PC=0x09E2EC
- Run up to 2000 steps
- Check D0259D and D025A3 — are they still 0x000000 or initialized?
- Record all unique blocks visited
- Check if execution reaches 0x082BE2 (event loop entry)

**Experiment B — Call 0x09E2EC with A=0x40 (alternate home context), then enter event loop**
- Same as A but A=0x40 (from 0x0620C0)

**Experiment C — Full sequence: D007E0=0x49 + D007E8=0x06C546 + 0x09E2EC(A=0x49) + 0x0582BC event loop**
- Write D007E0=0x49, D007E8=0x06C546 (handler address that prevents the LDIR zeroing bug)
- Call 0x09E2EC with A=0x49 for up to 2000 steps
- Then set PC=0x0582BC (home body) and run up to 10000 steps
- Report: does the polling loop exit? Any new blocks beyond the 5 polling blocks?
- Check D0259D, D025A3 values after context registration

**Experiment D — Dump what 0x09E2EC actually does**
- Set A=0x49, PC=0x09E2EC
- Step through up to 500 steps, logging every block PC and every memory write
- Report the first 50 unique blocks visited
- Report all memory writes in the D025xx-D026xx range and D3Fxxx range (dispatch table area)

3. For each experiment, print:
   - Steps executed
   - Unique blocks visited (count + list)
   - Values of D0259D (3 bytes), D025A3 (3 bytes) before and after
   - Whether execution hit 0x082BE2 (event loop)
   - Whether execution exited the 5-block polling set

## Boot Sequence Reference
```javascript
import { readFileSync } from 'fs';
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';

const rom = readFileSync(new URL('./ROM.rom', import.meta.url));
const peripherals = createPeripheralBus({ timerInterrupt: false });
const cpu = createCPU(rom, peripherals);

// Standard boot
cpu.pc = 0x000000;
cpu.run(50000);  // cold boot
cpu.pc = 0x020028;
cpu.run(50000);  // kernel init
cpu.pc = 0x020830;
cpu.run(50000);  // mem init

cpu.ix = 0xD1A860;
cpu.pc = 0x021124; cpu.run(50000);  // stage 4
```
