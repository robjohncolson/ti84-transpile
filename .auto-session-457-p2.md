# Session 457 P2: Trace What Populates D0058D in Normal Operation

## Context
You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The OS ROM is lifted to JavaScript and executed in Node.js probes.

## Discovery from Session 456
The keyboard ISR writes raw scan codes to D00587. But `GetK` at 0x03FC1C reads from **D0058D** — a different address. Something in the OS translates/copies from D00587 to D0058D. We need to find this translation step.

Candidates:
- `_GetCSC` at 0x001713 (called from the event loop)
- 0x0008BB (called by _GetCSC)
- The keyboard ISR itself
- Some other OS function

## Task
Create a probe file `TI-84_Plus_CE/probe-phase457-d0058d-writer.mjs` that:

1. Boots to home screen using the standard boot sequence (copy the `bootToHomeScreen` function and constants from `probe-phase456-irq-frontend-trace.mjs` — lines 57-100 with all constants from lines 17-43)

2. After boot:
   - Set `mem[0xD14091] = 1` (key processing enable)
   - Set `mem[0xD177B7] = 0x55` (display dirty)
   - Set `mem[0xD00587] = 0x12` (raw scan code for key '1')
   - Set `mem[0xD00080] |= 0x08` (bit 3 key-available flag)
   - Set `mem[0xD0058D] = 0x00` (clear destination to track writes)

3. **Instrument memory writes to D0058D**: Use a memory write hook or post-step inspection. The approach:
   - Run the event loop from 0x003A73 in 'adl' mode
   - Every N steps (e.g., every step or every 10 steps), check if `mem[0xD0058D]` has changed from 0x00
   - When it changes, record:
     - The step number when it changed
     - The value written
     - The current PC at that step
     - The value of D00587 at that moment
   - Continue running for another 10,000 steps after the write to see what happens next

   Alternative (preferred if available): The `createExecutor` might support an `onWrite` hook or you can patch the memory. Check `cpu-runtime.js` for write hooking. If no hook exists, use the step-by-step approach:
   
   ```js
   let prevD0058D = 0;
   const writes = [];
   // Run in small chunks, checking D0058D each chunk
   for (let chunk = 0; chunk < 100; chunk++) {
     const result = executor.runFrom(currentPc, 'adl', { maxSteps: 5000, maxLoopIterations: 500, diHaltBypass: true });
     if (mem[0xD0058D] !== prevD0058D) {
       writes.push({ chunk, step: chunk * 5000, newVal: mem[0xD0058D], pc: result.lastPc, d00587: mem[0xD00587] });
       prevD0058D = mem[0xD0058D];
     }
     currentPc = result.lastPc;
     currentMode = result.lastMode || 'adl';
     if (result.termination !== 'max_steps') break;
   }
   ```

4. Also disassemble the ROM bytes around these key addresses to find the write instruction:
   - Read ROM bytes at 0x001713-0x001740 (_GetCSC area)
   - Read ROM bytes at 0x0008BB-0x0008F0
   - Search for byte patterns that could be `LD (D0058D), A` or `LD (D0058D), reg`:
     - `LD (nn), A` in ADL mode = `32 8D 05 D0` (opcode 0x32, little-endian address)
     - `LD (nn), HL` = `22 8D 05 D0`
   - Search the ROM for bytes `8D 05 D0` (little-endian D0058D) to find all references

5. Print JSON summary with:
   - All D0058D write events (step, value, PC)
   - ROM byte sequences at _GetCSC and 0x0008BB
   - All ROM addresses containing the byte pattern for D0058D references
