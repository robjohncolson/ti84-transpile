# Task: Test Combined Idle+Display Paths (D00000 alternation)

## Context
We're transpiling the TI-84 Plus CE ROM (eZ80) to JavaScript. Previous sessions showed:
- D00000=1 → display update path fires (0x03D1BE→0x030078→0x040D11), LCD port config, but minimal VRAM
- D00000=0 → idle cursor path fires (0x03013A→0x030202), produces 72 VRAM bytes (cursor blink)

The question: what if we START with D00000=1 for a few iterations to get LCD setup, then SWITCH to D00000=0 for cursor rendering? Or vice versa?

## Deliverable
Create `TI-84_Plus_CE/probe-phase481-combined-paths.mjs` that runs THREE experiments:

### Experiment 1: D00000=1 first, then 0
- Boot, set D00000=0x01 initially
- Run event loop. After 0x030078 fires once (detected via onBlock), set D00000=0x00
- Continue for 500K steps total
- Report VRAM bytes changed, hit counts for key PCs

### Experiment 2: D00000=0 first, then 1
- Fresh boot, set D00000=0x00 initially
- Run 200K steps (get cursor pixels), then set D00000=0x01
- Continue for 300K more steps
- Report VRAM bytes changed

### Experiment 3: Alternating every N iterations
- Fresh boot, D00000=0x01
- In onBlock at EVENT_LOOP_HEAD, alternate D00000 between 0x01 and 0x00 every 100 iterations
- Run 500K steps total
- Report VRAM bytes changed

For each experiment, track: 0x02FDBE, 0x03013A, 0x030202, 0x04E950, 0x09EF44, 0x0059C6, 0x005A75, 0x030078, 0x03D1BE, 0x040D11, 0x03030E.

## Template Pattern (MUST follow exactly)
```javascript
import { readFileSync } from "node:fs";
import { createExecutor } from "./cpu-runtime.js";
import { createPeripheralBus } from "./peripherals.js";
import { PRELIFTED_BLOCKS } from "./ROM.transpiled.js";

const MEM_SIZE = 0x1000000;
const VRAM_BASE = 0xd40000;
const VRAM_SIZE = 320 * 240 * 2;
const STACK_RESET_TOP = 0xd1a87e;
const EVENT_LOOP_HEAD = 0x02fdbe;
const RET_POINTS = new Set([0x02fe88, 0x02fde5, 0x02fe21]);

const mem = new Uint8Array(MEM_SIZE);
const rom = readFileSync(new URL("./ROM.rom", import.meta.url));
mem.set(rom.subarray(0, MEM_SIZE), 0);
const peripherals = createPeripheralBus();
const executor = createExecutor(PRELIFTED_BLOCKS, mem, { peripherals });

function runFrom(pc, steps, onBlock) {
  return executor.runFrom(pc, "adl", { maxSteps: steps, maxLoopIterations: 200000, onBlock });
}
function hex(v, w = 6) { return "0x" + (v >>> 0).toString(16).toUpperCase().padStart(w, "0"); }

// 3-stage boot
runFrom(0x080000, 150000);
runFrom(0x0802b2, 150000);
runFrom(0x08c331, 150000);

// Mode state setup
mem[0xd00824] = 0x48;
mem[0xd007e0] = 0x48;
mem[0xd14091] = 0x01;
mem[0xd00092] = 0x16;
mem[0xd00089] |= 0x10;
mem[0xd000c6] = 0x01;
mem[0xd000b4] = 0x01;
mem[0xd00080] |= 0x18;
mem[0xd00595] = 0x00;
mem[0xd00596] = 0x00;
mem[0xd0058b] = 0x70;
executor.cpu.mbase = 0xd0;
executor.cpu._iy = 0xd00080;
executor.cpu.sp = STACK_RESET_TOP;
```

In the onBlock for the event loop:
- At EVENT_LOOP_HEAD: refresh D000C6 |= 0x01, D00092 |= 0x16, reset SP to STACK_RESET_TOP - 3
- At RET_POINTS: return "stop"

IMPORTANT: For each experiment, you need a FRESH boot. Since you can't easily re-create the executor, you can save the mem state after boot and restore it before each experiment:

```javascript
const bootSnapshot = mem.slice();  // after 3-stage boot, before state setup
// Before each experiment:

// Then re-apply mode state
```
