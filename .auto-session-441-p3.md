# Task: Map D14038 (co-accessed with D1407B SOF flag and D1407C pipe-pending)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). We are mapping USB state variables.

Session 440 traced D1407B (SOF-received flag, 19 refs) and found it co-accessed with D14038 at multiple sites. Session 439 traced D1407C (pipe-pending, 17 refs) and also found D14038 nearby at 4/17 sites. The question: what role does D14038 play? Is it a threshold, counter, bitmask, or state byte?

D14038 sits in the D14000-D1404F range, which is likely part of the USB controller state structure. The D14070-D1407F block is the pipe state group; D14038 is 56 bytes earlier and may be in a different functional sub-block.

## Your task
Create a probe script at `TI-84_Plus_CE/probe-phase441-trace-D14038.mjs` and a report at `TI-84_Plus_CE/phase441-trace-D14038-report.md`.

### Methodology (follow exactly — see `TI-84_Plus_CE/probe-phase440-trace-D1407D.mjs` for the template)

1. **Find all ROM references** to address D14038 by scanning for the 3-byte little-endian pattern `[0x38, 0x40, 0xD1]` in the ROM.
2. **For each reference site**, decode:
   - What instruction accesses D14038 (LD A,(D14038), LD (D14038),A, XOR A + LD (D14038),A, INC (D14038), DEC (D14038), etc.)
   - Whether it's a READ or WRITE
   - What value is written (if write): 0x00 via XOR A? 0x01 via LD A,0x01? A computed value? INC/DEC?
   - What condition gates the access (CP/JR Z/JR NZ before or after)
   - What nearby D140xx/D1407x bytes are co-accessed within ±32 bytes (wider window since D14038 may link to the D1407x block)
   - What nearby port I/O (IN/OUT with 0x30xx/0x31xx/0x50xx ports) happens within ±32 bytes
3. **Classify the variable**: boolean (0/1)? enum (multi-value)? counter (INC/DEC)? bitmask (AND/OR/XOR)? threshold?
4. **Identify the containing function** for each site (scan backward for function prologue: PUSH AF/IX/IY or `__frameset` CALL 0x00218A/0x002197)
5. **Note dual-banking**: references in 0x00xxxx, 0x02xxxx, 0x04xxxx, 0x0Bxxxx are mirrors of the same logical function
6. **Pay special attention** to how D14038 relates to D1407B (SOF) and D1407C (pipe-pending) — are they read together in conditionals? Does D14038 gate whether D1407B/D1407C get written?

### Output format
The probe script should:
- Read ROM.rom
- Scan for all `[0x38, 0x40, 0xD1]` occurrences
- For each site: print address, read/write, value, nearby co-accessed D140xx/D1407x bytes, nearby port I/O
- Print summary statistics (total refs, read count, write count, unique values written)
- Write a markdown report

The report should contain:
- Total reference count (reads vs writes)
- Classification (boolean/enum/counter/bitmask/threshold)
- All write values observed
- All read patterns (how reads are used — OR A + JR Z? CP N? AND mask? etc.)
- Co-access summary (which D140xx/D1407x bytes appear most often nearby, especially D1407B and D1407C)
- Port I/O summary
- Relationship to D1407B/D1407C (how are they linked?)
- Suggested semantic name and role hypothesis
