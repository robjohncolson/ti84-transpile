# Task: Increase kernel init step limit to test natural context dispatch

## Context
This is a TI-84 Plus CE ROM transpilation project. During session 336, Approach A tried pre-seeding the context byte (0xD007E0 = 0x41) before kernel init, but kernel init got stuck at PC=0x00069A after 100,000 steps and never reached the context dispatch code at 0x08C8B5.

We want to test whether increasing the step limit to 500K and 1M allows kernel init to naturally reach the context dispatch and set cxMain to the home handler.

**Key addresses**:
- Kernel init entry: 0x08C331
- Context dispatch code: 0x08C8B5 
- Context byte: 0xD007E0
- cxMain pointer: 0xD007CA
- Home handler: 0x058241
- Stuck loop: 0x00069A

## Deliverable
Create `TI-84_Plus_CE/probe-phase337-extended-init.mjs` that:

1. **TEST A — 500K steps**: 
   - Phase 1 boot: `executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
   - Set `mem[0xD007E0] = 0x41` (context byte = 'A', which IS in the valid table)
   - Reset cpu state: `cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;`
   - Reset stack: `cpu.sp = 0xD1A87E - 3; mem.fill(0xFF, cpu.sp, cpu.sp + 3);`
   - Run kernel init: `executor.runFrom(0x08C331, 'adl', { maxSteps: 500000, maxLoopIterations: 500000 })`
   - Use `onBlock` to track:
     - Whether PC ever hits 0x08C8B5 (context dispatch)
     - Whether PC ever hits 0x08C8C7 (the JR NZ after table lookup)
     - How many times PC visits 0x00069A (the stuck loop)
     - Every unique block PC (for coverage)
     - The value of cxMain (read24 at 0xD007CA) every 50000 steps
   - After completion: print termination, steps, cxMain value, context byte value, whether context dispatch was reached

2. **TEST B — 1M steps**: Same as Test A but with `maxSteps: 1000000, maxLoopIterations: 1000000`. Print the same metrics.

3. **TEST C — Analyze the stuck loop**: During the 500K run, record the last 30 unique PCs visited before termination. Disassemble the block at 0x00069A using `decodeInstruction(romBytes, addr, 'adl')` — decode 15 instructions. This tells us what the loop is doing and why it can't escape.

4. Print timing for each test (use `performance.now()` or `Date.now()`).

## Boot helper
```javascript
function read24(buffer, addr) {
  return (buffer[addr] | (buffer[addr + 1] << 8) | (buffer[addr + 2] << 16)) >>> 0;
}
function write24(buffer, addr, value) {
  buffer[addr] = value & 0xFF;
  buffer[addr + 1] = (value >>> 8) & 0xFF;
  buffer[addr + 2] = (value >>> 16) & 0xFF;
}
```
