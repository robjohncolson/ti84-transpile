# Task: Trace D14075 and D14076 (USB state block — remaining unmapped bytes)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). We are tracing USB state variables in the D14070-D1407F USB state block (16 bytes, 14 active).

Already mapped in this block:
- D14070: port-config (session 437)
- D14071: port-config (session 437)
- D14072: physical-connection flag (boolean, port 0x3082 bit 5, 19 refs)
- D14073: device-connected flag (boolean, port 0x3082 bit 4, 52 refs)
- D14074: USB active flag (boolean, 29 refs)
- D14075: **UNMAPPED** — between D14074 (USB active) and D1407B (SOF received)
- D14076: **UNMAPPED**
- D14077-D1407A: **UNMAPPED** (4 more bytes)
- D1407B: SOF-received flag (boolean, 19 refs)
- D1407C: pipe-pending flag (boolean, 17 refs)
- D1407D: bus-reset notification (boolean, 6 refs)
- D1407E: pipe-active flag (boolean, 28 refs)
- D1407F: transfer-active flag (boolean, 12 refs)

**D14075 and D14076 are the first 2 of 6 remaining unmapped bytes** in the gap between D14074 and D1407B.

## Your task
Create TWO probe scripts and TWO reports:
1. `TI-84_Plus_CE/probe-phase441-trace-D14075.mjs` + `TI-84_Plus_CE/phase441-trace-D14075-report.md`
2. `TI-84_Plus_CE/probe-phase441-trace-D14076.mjs` + `TI-84_Plus_CE/phase441-trace-D14076-report.md`

### Methodology (follow exactly — see `TI-84_Plus_CE/probe-phase440-trace-D1407D.mjs` for the template)

For EACH target address (D14075 and D14076 separately):

1. **Find all ROM references** by scanning for the 3-byte little-endian pattern in the ROM:
   - D14075: `[0x75, 0x40, 0xD1]`
   - D14076: `[0x76, 0x40, 0xD1]`
2. **For each reference site**, decode:
   - What instruction accesses the target (LD A,(addr), LD (addr),A, XOR A + LD (addr),A, etc.)
   - Whether it's a READ or WRITE
   - What value is written (if write): 0x00 via XOR A? 0x01 via LD A,0x01? Something else?
   - What condition gates the access (CP/JR Z/JR NZ before or after)
   - What nearby D140xx bytes are co-accessed within ±20 bytes
   - What nearby port I/O (IN/OUT with 0x30xx/0x31xx ports) happens within ±32 bytes
3. **Classify the variable**: boolean (0/1)? enum (multi-value)? counter? bitmask?
4. **Identify the containing function** for each site (scan backward for function prologue: PUSH AF/IX/IY or `__frameset` CALL 0x00218A/0x002197)
5. **Note dual-banking**: references in 0x00xxxx, 0x02xxxx, 0x04xxxx, 0x0Bxxxx are mirrors of the same logical function

### Output format
Each probe script should:
- Read ROM.rom
- Scan for all occurrences of the target LE pattern
- For each site: print address, read/write, value, nearby co-accessed D140xx bytes, nearby port I/O
- Print summary statistics (total refs, read count, write count, unique values written)
- Write a markdown report

Each report should contain:
- Total reference count (reads vs writes)
- Classification (boolean/enum/counter/bitmask)
- All write values observed
- All read patterns (how reads are used — OR A + JR Z? CP N? etc.)
- Co-access summary (which D140xx bytes appear most often nearby)
- Port I/O summary
- Suggested semantic name (e.g., `usb_Xxx`)

### Constraints
- Do NOT modify any existing files
- Do NOT run the transpiler or modify ROM.transpiled.js
- Each probe is a standalone Node.js ESM script (import fs, path, url)
- Use `#!/usr/bin/env node` shebang
- The ROM is raw binary — no headers, byte 0 = address 0x000000
- eZ80 uses 3-byte (24-bit) addresses in little-endian format
- Watch for eZ80 mode prefixes before instructions: 0x40=SIS, 0x49=LIS, 0x52=SIL, 0x5B=LIL
- Reference the template probe at `TI-84_Plus_CE/probe-phase440-trace-D1407D.mjs` for code structure
