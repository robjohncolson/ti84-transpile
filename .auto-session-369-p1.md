# Task: Extend Event Loop Probe to Reach Post-Scan Path

## Context
The TI-84 Plus CE OS event loop has been fully decoded (session 368). The structure is:
- 0x003A70: `LD B, 100` (poll counter)
- 0x003A72: `PUSH BC` → 0x003A73: `CALL 0x003D5A` (_GetCSC) → 0x003A77: `POP BC` → 0x003A78: `OR A` → 0x003A79: `JR NZ, 0x003A7D` (key found) → 0x003A7B: `DJNZ 0x003A72` (loop 100 times)
- After 100 failed scans: 0x003A7D: `CALL 0x001713` → 0x003A81: `JP NZ, 0x001933` → 0x003A85: `JP 0x003A89` → 0x003A89: `CALL 0x001853` → 0x003A8D: `XOR A` → 0x003A8E: `JP 0x000721`

The problem: _GetCSC's inner delay loop at 0x003D6B is so slow that 200K steps only completes ~99 scan iterations. The 100-scan DJNZ at 0x003A7B never reaches B=0, so the post-scan path (0x001713, 0x001933, 0x001853, 0x000721) is never entered.

## Deliverable
Create `TI-84_Plus_CE/probe-phase369-post-scan.mjs` — a probe that:
1. Runs the standard 3-phase cold boot (same as probe-phase367-boot-50k.mjs)
2. Enters the event loop at 0x003A73 with `maxLoopIterations: 10` (or even 5) so the _GetCSC delay loop at 0x003D6B exits quickly. This makes each _GetCSC call fast, so the DJNZ B=100 counter reaches 0 within reasonable step counts.
3. Runs for 500K steps to ensure the post-scan path is reached.
4. Tracks block visits and reports:
   - Whether blocks 0x001713, 0x001933, 0x001853, 0x000721 were visited
   - How many total unique blocks were seen
   - New blocks not in cold boot
   - Any missing_block terminations
   - CPU state at end
   - Top 20 hottest blocks

## Reference: probe-phase367-boot-50k.mjs pattern
```javascript
#!/usr/bin/env node
import fs from 'node:fs';
import path from 'node:path';
import { fileURLToPath, pathToFileURL } from 'node:url';
import { createExecutor } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));
const romModule = await import(pathToFileURL(path.join(__dirname, 'ROM.transpiled.js')).href);
const BLOCKS = romModule.PRELIFTED_BLOCKS;

const STACK_RESET_TOP = 0xD1A87E;

function hex(v, w = 6) {
  return v == null ? 'n/a' : '0x' + (v >>> 0).toString(16).padStart(w, '0');
}

const mem = new Uint8Array(0x1000000);
mem.set(romBytes);

const peripherals = createPeripheralBus({ pllDelay: 2, timerInterrupt: false });
const executor = createExecutor(BLOCKS, mem, { peripherals });
const { cpu } = executor;

// Phase 1: Z80 cold boot
const r1 = executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 });
// Phase 2: Kernel init
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
cpu.sp = STACK_RESET_TOP - 3;
mem.fill(0xFF, cpu.sp, cpu.sp + 3);
const r2 = executor.runFrom(0x08C331, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 });
// Phase 3: Post-init
cpu.mbase = 0xD0; cpu._iy = 0xD00080; cpu._hl = 0;
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
cpu.sp = STACK_RESET_TOP - 3;
mem.fill(0xFF, cpu.sp, cpu.sp + 3);
const r3 = executor.runFrom(0x0802B2, 'adl', { maxSteps: 100, maxLoopIterations: 32 });
```

Then for Phase 4 (event loop), use:
```javascript
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
cpu.f = 0x40;
cpu._ix = 0xD1A860;
cpu._iy = 0xD00080;
cpu.sp = STACK_RESET_TOP - 12;
mem.fill(0xFF, cpu.sp, cpu.sp + 12);

const r4 = executor.runFrom(0x003A73, 'adl', { maxSteps: 500000, maxLoopIterations: 10 });
```

The key difference from previous probes: `maxLoopIterations: 10` (instead of 500 or 2000). This forces the _GetCSC delay loop to exit after 10 iterations instead of thousands, making each _GetCSC scan fast enough that the DJNZ B=100 loop completes within the step budget.
