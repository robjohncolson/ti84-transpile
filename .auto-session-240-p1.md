# Task: Run 0x09EFDE VRAM fill with 150K+ steps to find completion point

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript and executed via `cpu-runtime.js`.

0x09EFDE is a VRAM row-fill loop (_RectFill) that the OS uses to clear the screen after a key press. The call chain is: 0x04EDD0 → 0x04ECCE → 0x07F984 → 0x08BF22 → 0x09EFDE.

Session 239 ran this with 80K steps and it did NOT complete. VRAM was nearly full (152,906/153,600 non-zero bytes). The loop alternates between 0x09EFDE (VRAM fill) and 0x0A1xxx (computation). DE writes 0xAA52 pattern. SP changes indicate re-entry from different call depths.

## Task
Create a probe `TI-84_Plus_CE/probe-phase240-09efde-150k-complete.mjs` that:

1. Boots the CPU (use the pattern from existing probes — import from `cpu-runtime.js`, create CPU, createPeripheralBus with timerInterrupt:false)
2. Sets up the call chain starting at 0x04EDD0 (or directly at 0x09EFDE via the chain 0x04ECCE → 0x07F984 → 0x08BF22 → 0x09EFDE)
3. Runs for 150,000 steps (or until the function returns — detect via SP recovery or reaching a block outside the 0x09xxxx/0x0Axxxx range)
4. Tracks:
   - Total steps executed
   - Whether the fill loop completed (did execution leave the 0x09xxxx-0x0Axxxx range?)
   - Final PC when it exits (the return address)
   - Final SP vs initial SP (did the stack recover?)
   - VRAM fill statistics (how many non-zero bytes in 0xD40000-0xD52C00)
   - The block visited immediately AFTER the fill loop exits
5. If 150K isn't enough, report how close to completion it appears (VRAM coverage, iteration count pattern)
