# Task: Trace Fixed-Width Text Renderer 0x054E21

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The fixed-width font table has been fully decoded (session 327):
- Font table base: ROM 0x003D6E (via trampoline CALL 0x000380→JP 0x003D85→LD HL,0x003D6E; RET)
- Table spans 0x003D6E-0x00596D (7168 bytes, 256 entries)
- Record size: 28 bytes (14 rows × 2 bytes/row, 1bpp MSB-first, 12px constant width)
- No width metadata byte — all glyphs are 12px wide
- Font lookup function 0x07BF3E copies 28 bytes to RAM at D005A1 (with 4-byte header at D005A1-D005A4 zeroed)

This is the HOME SCREEN font (sel=1 from 0x023D7B). It's the most important renderer for our goal of rendering the home screen.

## Target
Function at **0x054E21** — this is the fixed-width text renderer for the home screen.

## Deliverables
Create a probe file `TI-84_Plus_CE/probe-phase328-fixedwidth-renderer.mjs` that:

1. Disassembles 0x054E21 to trace the full function body
2. Answers these specific questions:
   - How many instructions / basic blocks does the function have?
   - What VRAM addresses does it write to? (LCD framebuffer at 0xD40000, 320×240×2 bytes)
   - How does it compute VRAM addresses from the screen position? (formula: base + y*640 + x*2 for 16bpp)
   - Where does it get the current cursor row/column from? (Check IY-relative offsets, D005xx RAM)
   - Does it call 0x07BF3E (fixed-width font lookup) internally?
   - How does it render the 14-row × 12-bit-wide glyph from the 28-byte record?
   - Does it advance the cursor after drawing? By how much (12 pixels)?
   - What foreground/background colors does it use? Where are they stored?

3. Uses dynamic tracing with test character ASCII 0x41 = 'A':
   - Set up the font data at D005A1 for 'A' (or let the function call 0x07BF3E)
   - Set a plausible cursor position (row 0, col 0)
   - Run 0x054E21 and log all VRAM writes (D40000-D65FFF)
   - Log RAM reads to identify state variables (cursor, colors, etc.)
