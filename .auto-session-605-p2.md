# Auto-Session 605 — P2: Test Port 0x03 Bit 4 Bypass to Prevent Wipe

## Context

The TI-84 Plus CE OS ROM is transpiled to JavaScript. During key processing, a bulk wipe at 0x0018F8 clears 82KB of RAM. Session 604 found a guard gate at 0x001872:

```
IN0 A,(port 0x03)    ; read hardware port 0x03
BIT 4,A              ; test bit 4
JR NZ,+0x36          ; if bit 4 SET → jump OVER the wipe to 0x0018AC
```

If port 0x03 bit 4 is set, the wipe sequence is skipped entirely.

The peripherals system handles port I/O. Port 0x03 is read via `IN0 A,(port)` which calls `peripherals.readPort(0x03)`.

## Task

Create a probe `TI-84_Plus_CE/probe-phase605-port03-bypass.mjs` that:

1. Boots the OS the same way as `probe-phase603-context-restore-fix.mjs` (cold boot → launch-init → paint) — copy the boot sequence from that file verbatim
2. After paint completes, save D007CA, D0231A, D0243A, VRAM pixel count
3. **Intercept port 0x03 reads** to return bit 4 SET. Check `TI-84_Plus_CE/peripherals.js` for how ports work. The most reliable approach:
   - After creating the peripherals object, override or hook the port read mechanism
   - Look at peripherals.js for how `readPort` works and how to intercept it
   - The goal: when port 0x03 is read, bit 4 (0x10) should be set in the returned value
   - Try `peripherals.readPort` override if it exists, or set the port value directly
4. Seed first keypress: `mem[0xD0058C] = 0x90; mem[0xD0058E] = 0x90; mem[0xD0009F] |= 0x20;`
5. Run from 0x08C331 with maxSteps=500000, tracking:
   - 0x0585E9 (cxMain)
   - 0x001872 (port guard)
   - 0x0018F8 (bulk wipe)
   - 0x0158E0 (IY+0x42 guard)
6. Report:
   - cxMain dispatched?
   - Port guard hit? (0x001872)
   - Wipe reached? (0x0018F8)
   - D007CA, D0231A, D0243A preserved?
   - VRAM count
   - Steps and halt PC
7. Print "BYPASS RESULT: PORT 0x03 WIPE PREVENTED" or "BYPASS RESULT: PORT 0x03 WIPE STILL OCCURRED"
