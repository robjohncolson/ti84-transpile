# Task: Trace 0x00B74C and 0x048C50 — The Two D177B7=0x55 Writer Sites

## Context
In auto-session 453, we discovered that D177B7 has a THREE-STATE PROTOCOL:
- 0x00 = clean (10 writers via XOR A)
- 0x55 = dirty/needs-refresh (2 writers: 0x00B74C and 0x048C50 via LD A,0x55)
- 0xAA = consumed/refresh-in-progress (3 writers via LD A,0xAA)

The two 0x55 writers (0x00B74C and 0x048C50) are the only sites in the entire ROM that ARM the display-dirty flag. Understanding what functions contain them and when they're called tells us exactly when the OS decides "the screen needs a refresh."

## Deliverable
Create `TI-84_Plus_CE/probe-phase454-d177b7-arm-sites.mjs` — a disassembly/analysis probe that:

1. For each of the two addresses (0x00B74C and 0x048C50):
   a. Read the surrounding ROM bytes (256 bytes before and after) to find the function boundaries
   b. Identify the function start (look for common function prologues or CALL targets)
   c. List all CALL instructions within the function (what it calls)
   d. Search the ROM for all CALL/JP instructions that target addresses near the function start (who calls it)
   e. Check if the function accesses VRAM (0xD40000 range) or LCD MMIO ports
   f. Check what other RAM addresses the function reads/writes

2. For each function, determine:
   - Is it in the key processor path (near 0x03FA09)?
   - Is it in a mode initialization path (near 0x048xxx)?
   - Does it access D141B5 (key buffer)?
   - Does it access VRAM?
   - What triggers it to write 0x55 to D177B7?

## Implementation
This is a ROM disassembly analysis probe. Use the ROM file directly.

```javascript
import fs from 'node:fs';
import path from 'node:path';
import { fileURLToPath } from 'node:url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));
```

### For address 0x00B74C:
- Read ROM bytes around 0x00B74C (range 0x00B600-0x00B900)
- The instruction at 0x00B74C is `LD A,0x55` followed by `LD (D177B7),A`
- Find the function containing this address by scanning backward for RET/JP or forward references
- Search the full ROM for `CALL 0x00B7xx` patterns (3-byte CALL instructions: 0xCD low mid high in little-endian)

### For address 0x048C50:
- Read ROM bytes around 0x048C50 (range 0x048B00-0x048D00)
- Same analysis as above

### CALL instruction search pattern:
eZ80 CALL instructions are 4 bytes in ADL mode: `CD ll mm hh` where the target is `hh:mm:ll`.
To find all callers of address 0x00B7XX, search for bytes: `CD XX B7 00` (little-endian 24-bit).
