# Task: Decode 0x07CAB9 — FP normalize phase 1

## Context
This is a TI-84 Plus CE ROM transpilation project. We're decoding eZ80 machine code from ROM.rom.

Session 529 identified 0x07CAB9 as the first stage of the multi-phase normalization pipeline in the matrix/list FP handler (0x07D27B). It was described as: "RES 6,(IY+14); CALL 0x07CC36; check OP2→JP Z error; check OP1". We need a full decode.

## What to do

1. Create a probe file `TI-84_Plus_CE/probe-phase530-decode-07CAB9-fp-norm-phase1.mjs` that:
   - Reads ROM bytes from 0x07CAB9 through 0x07CB40 (135 bytes — generous window)
   - Disassembles them instruction-by-instruction
   - Identifies all CALL/JP/JR targets
   - Finds the RET/JP that ends this function
   - Also dump bytes for key sub-functions called (especially 0x07CC36)

2. Use the same probe template as `TI-84_Plus_CE/probe-phase529-decode-07CBB5-fp-normalize-core.mjs` (read it for reference).

3. Run the probe: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase530-decode-07CAB9-fp-norm-phase1.mjs`

4. Report: all instructions, CALL targets, function boundary (RET location), and purpose analysis.

## Key reference
- ROM file: `TI-84_Plus_CE/ROM.rom`
- eZ80 little-endian, 24-bit addresses
- OP1 at D005F8 (9 bytes), OP2 at D00603 (9 bytes), OP3 at D0060E
- IY typically points to D00080 (flags base)
- Known related functions: 0x07CC36 (called from here), 0x07CA48 (phase 2), 0x07C8B7 (phase 3)
- Common opcodes: C9=RET, CD=CALL nn, C3=JP nn, CB prefix for bit ops, FD prefix for IY ops

## Constraints

- Do NOT modify cpu-runtime.js, peripherals.js, ez80-decoder.js, or browser-shell.html
- Run the probe ONLY via `node scripts/run-probe.mjs --max-time 180 <probe>` — NEVER bare `node <probe>`

## Success criterion

- Function boundary (RET) found
