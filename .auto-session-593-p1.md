# Task: Decode ROM function at 0x07F8FE

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 ADL mode — 24-bit addresses, 3-byte immediates for LD rp,nn).

## What to do
Create a probe that statically disassembles the function at ROM address **0x07F8FE**. This function is called from the type-gated resolver loop at 0x07FEFC with **HL=D0063A** (the secondary shadow descriptor buffer). It is called at the end of a resolve iteration: after the orchestrator 0x07CFA7 runs, the resolver does `LD HL,D0063A / CALL 0x07F8FE` then loops back.

## Known context
- **D005F8** = primary descriptor buffer (11 bytes)
- **D00603** = shadow descriptor buffer (11 bytes)  
- **D0063A** = secondary shadow descriptor buffer (11 bytes, snapshot for rollback/comparison)
- The triple-buffer architecture: primary ↔ shadow swap via 0x07FD30, shadow→secondary snapshot via 0x07F98B
- The resolver 0x07FEFC iterates: check type → orchestrate → call 0x07F8FE with HL=secondary → loop
- Nearby functions: 0x07F8AC, 0x07F8B6, 0x07F8CC, 0x07F8FA are all in the same region

## Deliverable
Create file `TI-84_Plus_CE/probe-phase593-decode-07F8FE.mjs` that:
1. Reads ROM.rom from `__dirname` (use `path.join(__dirname, 'ROM.rom')`)
2. Statically disassembles starting at 0x07F8FE for up to 128 bytes in **eZ80 ADL mode** (24-bit addresses — LD rp,nn is 4 bytes, CALL nn is 4 bytes, JP nn is 4 bytes)
3. Stops at RET/JP/JR that look like function ends
4. Annotates RAM addresses with known names (D005F8=primaryDescriptorBuffer, D00603=shadowDescriptorBuffer, D0063A=secondaryShadowBuffer, D005F9=descriptorType, D005FA=descriptorFieldCheck, D007E0=displayMode, D0117F=typeDescriptorTable)
5. Scans for cross-references (callers) by searching the entire ROM for CALL 0x07F8FE (bytes CD FE F8 07) and JP 0x07F8FE (bytes C3 FE F8 07)
6. Prints raw hex bytes alongside each disassembled instruction
7. Prints a summary with function size, purpose hypothesis, RAM refs, and caller count

## eZ80 ADL decoder requirements
- This is eZ80 in ADL mode (24-bit default). All immediates and addresses are 3 bytes unless a .SIS prefix (0x40/0x49/0x52/0x5B) switches to 16-bit.
- LD rp,nn = 4 bytes (1 opcode + 3 byte immediate)
- CALL nn = 4 bytes (CD + 3 byte address)
- JP nn = 4 bytes (C3 + 3 byte address)
- JP cc,nn = 4 bytes
- LD (nn),A / LD A,(nn) = 4 bytes
- LD (nn),rp / LD rp,(nn) = 5 bytes (ED prefix + opcode + 3 byte address)
- Common pitfall: using Z80 (2-byte) immediates instead of eZ80 (3-byte) — double-check all multi-byte operands
