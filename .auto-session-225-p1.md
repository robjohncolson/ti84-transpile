# Task: Trace D0059F writers in ROM — find what sets magic values 0xFA-0xFE

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 binary). The transpiled JS is generated by `scripts/transpile-ti84-rom.mjs` and the runtime is in `TI-84_Plus_CE/cpu-runtime.js`.

We have decoded the ConvKeyToTok function at 0x05E630 which converts key codes to tokens. Its first instruction is `CALL 0x05C52C` (KeyClassifier). The KeyClassifier uses magic A values to select secondary token tables:
- A=0xFA → AlphaLock table (0x05C4A0)
- A=0xFB → Alpha table (0x05C3AA)  
- A=0xFC → 2nd table (0x05C1B0)
- A=0xFE → Fn table (0x05C01D)

The PRIMARY call site for ConvKeyToTok is at 0x04EA26, which loads A from memory address **(D0059F)**. D0059F is therefore THE key state variable that controls which token table is used.

## Your Task
Build a probe `TI-84_Plus_CE/probe-phase225-d0059f-writers.mjs` that:

1. **Static ROM scan**: Read ROM.rom binary and scan for ALL instructions that write to address 0xD0059F. Look for:
   - `LD (0xD0059F),A` — opcode patterns: `32 9F 05 D0` (z80 LD (nn),A) or with eZ80 ADL prefix `ED 39 9F 05 D0` (LD (nn),A in ADL mode). Also check for `49 32 9F 05 D0` (with MADL prefix byte 0x49).
   - `LD (HL),A` or `LD (HL),n` where HL is loaded with 0xD0059F — harder to find statically but check for `21 9F 05 D0` (LD HL,0xD0059F) nearby.
   - `LD (IX+d),A` or similar indexed writes — check for pointers to 0xD0059F.

2. **Static ROM scan for readers**: Also find all `LD A,(0xD0059F)` reads — `3A 9F 05 D0` or `ED 3B 9F 05 D0`. This tells us who consumes the value.

3. **Boot-time value**: Run the transpiled ROM through boot (z80 boot at 0x000200, kernelInit at 0x000324, memInit at 0x020814) and check what D0059F is set to. Use `cpu-runtime.js` and the transpiled ROM.

4. **Dynamic write watchpoint**: Run the event loop at 0x082BE2 for 10000 steps and check if D0059F is ever written. Sample its value at steps 0, 1000, 5000, 10000.

For the transpiled runtime, use this pattern (see existing probes for reference, e.g., `probe-phase224-049e07-switch-dispatch.mjs`):

```javascript

```

Then for boot: `cpu.call(0x000200)` with step limits, then `cpu.call(0x000324)`, etc.

**Read an existing probe first** (e.g., `probe-phase224-magic-a-producer-trace.mjs` or `probe-phase219-d003e0-bit3-setters.mjs`) to understand the exact API patterns used in this project. Match the coding style exactly.
