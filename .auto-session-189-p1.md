# Task: Trace ParseInp error recovery handler at 0x099929

## Context

Session 188 proved that PushErrorHandler (0x07C88B) + ParseInp (0x099914) + JError chain reaches 0x099929 via:
- PushErrorHandler sets up errSP frame with HL=0x099929 as the recovery target
- ParseInp hits a syntax error (errNo=0x8D) 
- JError fires → z80-mode RET intercept at 0x03E1B1→0x03E1CA → wrapper traversal → **0x099929 reached**
- Final state at 0x099929: SP=0xD1A86F, A=0x1D, OP1=all zeros

## Your Task

Create `TI-84_Plus_CE/probe-phase189-error-recovery-trace.mjs` that:

1. Sets up the same parser state as `probe-phase188-pusherrorhandler.mjs` (copy its setup pattern)
2. Runs the full PushErrorHandler→ParseInp→JError→0x099929 sequence (same as session 188)
3. **NEW**: Once PC reaches 0x099929, continues execution from there with a step limit of 2000 steps
4. Logs every instruction executed from 0x099929 onward — focus on:
   - What RAM addresses are read/written (especially OP1 at 0xD005F8, errNo at 0xD008DF)
   - Whether it returns (RET) and to where
   - Whether it jumps to cleanup code or loops
   - Any CALL instructions and their targets
5. Reports: does 0x099929 (a) clean up and return to caller? (b) set OP1/errNo? (c) enter an infinite loop? (d) crash?
