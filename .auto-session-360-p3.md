# Auto-Session 360 P3: Disassemble 0x00868E and 0x0088DD

## Context
TI-84 Plus CE ROM transpilation project. Session 359's RAM trampoline probe revealed that after bypassing the flash self-test, boot terminates at `missing_block` for two ROM addresses: **0x00868E:adl** and **0x0088DD:adl**. These are the new frontier — understanding what code lives there will determine the next steps.

## Task
Create a probe that statically disassembles the ROM at these two addresses, then runs a dynamic boot trace to see how execution reaches them.

## Probe: `TI-84_Plus_CE/probe-phase360-disasm-frontier.mjs`

The probe should:

### Part 1: Static disassembly
For each address (0x00868E and 0x0088DD), read the raw ROM bytes and disassemble 64 bytes of eZ80 instructions starting at that address using the decoder in `TI-84_Plus_CE/ez80-decoder.js`.

Import the decoder:
```js
import { decodeInstruction as decodeEz80 } from '../TI-84_Plus_CE/ez80-decoder.js';
// Note: this import path is RELATIVE to the probe's location in TI-84_Plus_CE/
// So use: import { decodeInstruction as decodeEz80 } from './ez80-decoder.js';
```

The decoder signature is: `decodeEz80(romBytes, offset, isAdl)` where:
- `romBytes` is a Uint8Array of the full ROM
- `offset` is the byte offset into the ROM
- `isAdl` is true for ADL mode (24-bit), false for z80 mode (16-bit)

It returns an object with at minimum: `{ mnemonic, operands, size }` (or similar — read the decoder source to confirm the exact return shape).

For each address, print:
```
=== DISASSEMBLY AT 0x00868E (ADL mode) ===
  0x00868E: <bytes>  <mnemonic> <operands>
  0x008691: <bytes>  <mnemonic> <operands>
  ... (up to 64 bytes or until a RET/JP/JR unconditional)
```

### Part 2: Dynamic trace
Run a boot with RAM trampoline (same setup as probe-phase359-ram-trampoline.mjs) and record the 10 blocks executed BEFORE each frontier address is reached. This shows the call chain that leads to 0x00868E and 0x0088DD.

Use this pattern:
```js
const recentBlocks = [];
const MAX_RECENT = 15;
const frontierHits = {};

// In onBlock callback:
recentBlocks.push({ step, pc, mode });
if (recentBlocks.length > MAX_RECENT) recentBlocks.shift();

if (pc === 0x00868E || pc === 0x0088DD) {
  frontierHits[pc] = [...recentBlocks];
}
```

For the RAM trampoline, inject synthetic blocks at RAM addresses >= 0xD00000 using the same pattern from probe-phase359-ram-trampoline.mjs (see P1 prompt for the code).

### Part 3: Analysis
After both parts complete, print a summary:
- What instruction types are at each frontier address (CALL? JP? LD? LDIR?)
- Are there any CALL/JP targets that might be further missing blocks?
- Are there port IN/OUT instructions that might be peripheral gates?
- What do these blocks likely DO? (code copy, peripheral init, computation, etc.)
