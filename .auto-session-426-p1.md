# Task: Trace Descriptor Node +8/+9 Gap

## Context
In the TI-84 CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, we have decoded two descriptor node constructors:
- **0x00CB7B** (110 bytes): Body initializer, writes offsets +10 through +31 of a 32-byte descriptor slab
- **0x00CBE9** (136 bytes): Header/link-pointer writer, writes offsets +0 through +7

Neither constructor writes to offsets **+8** or **+9** of the 32-byte descriptor node. These 2 bytes are an uninitialized gap. We need to find what ROM code writes to these offsets.

## What to do
1. Read `TI-84_Plus_CE/ROM.rom` (4MB binary at the repo root).
2. Create a Node.js probe script `TI-84_Plus_CE/probe-phase426-descriptor-gap.mjs` that:
   - Scans the ROM binary for all IY-relative write instructions that target offset +8 or +9. Specifically look for:
     - `LD (IY+8), <reg>` — opcode patterns: `FD 77 08` (A), `FD 70 08`..`FD 75 08` (B-L)
     - `LD (IY+9), <reg>` — opcode patterns: `FD 77 09` (A), `FD 70 09`..`FD 75 09` (B-L)
     - `LD (IY+8), <imm>` — `FD 36 08 xx`
     - `LD (IY+9), <imm>` — `FD 36 09 xx`
     - `SET/RES n, (IY+8)` — `FD CB 08 xx`
     - `SET/RES n, (IY+9)` — `FD CB 09 xx`
   - Filter results to the ROM address range 0x000000-0x3FFFFF.
   - For each match, output: ROM address (hex), instruction bytes, decoded instruction.
   - Focus especially on matches in the 0x00CB-0x00EE range (the descriptor/slab code cluster) and the 0x00E0-0x00E9 range (slab allocator area).
3. Also search for HL-indirect writes near IY+8/+9 patterns — look for code that loads IY into HL, adds 8 or 9, then does `LD (HL), <reg>`.
4. Write a report `TI-84_Plus_CE/phase426-descriptor-gap-report.md` summarizing:
   - How many IY+8 and IY+9 write sites found
   - Which address ranges they cluster in
   - Whether any are in the descriptor constructor neighborhood (0x00CB00-0x00EE00)
   - Hypothesis about what offsets +8 and +9 represent
