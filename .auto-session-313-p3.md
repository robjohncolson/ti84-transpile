# Task: Map _seqcase Inline Table Format (C switch() Pattern)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80 binary).

In session 312, we identified `_seqcase` at vector 0x000210 → target 0x002623 with 49 callers. This is the ZDS II C compiler's `switch()` dispatch mechanism. It reads an inline case table that appears AFTER the CALL instruction in the caller's code.

## How _seqcase Typically Works (ZDS II Pattern)
The compiler generates:
```
CALL _seqcase        ; pushes return address (= start of table) onto stack
.dw case_count       ; number of cases
.dw case_value_1     ; match value
.dw3 case_target_1   ; 24-bit jump target
.dw case_value_2
.dw3 case_target_2
...
.dw3 default_target  ; fallthrough/default
```
_seqcase pops the return address, reads the table, compares the test value (in a register, likely HL or A) against each case_value, and jumps to the matching target. If no match, jumps to default.

## Task
1. **Disassemble _seqcase at 0x002623** (likely 30-60 bytes). Determine:
   - Which register holds the test value? (HL? A? DE?)
   - Table entry format: how many bytes per case? (2-byte value + 3-byte target = 5 bytes? Or 2+2=4?)
   - How does it find end of table / default case?
   - Does it use CPIR or a loop?

2. **Find 5-10 callers of _seqcase**. Search the ROM for `CALL 0x002623` (byte pattern CD 23 26 00) or calls through the vector at 0x000210 (`CALL 0x000210` = CD 10 02 00). For each:
   - Dump the inline table bytes after the CALL
   - Decode the case values and targets
   - Verify the format matches across callers

3. **Write a probe** at `TI-84_Plus_CE/probe-phase313-seqcase.mjs` that:
   - Disassembles _seqcase itself
   - Finds all 49 call sites
   - For each call site, decodes the inline case table
   - Prints: caller address, case count, case values → targets
   - Validates format consistency across all callers

4. **Write a report** at `TI-84_Plus_CE/phase313-seqcase-report.md`.
