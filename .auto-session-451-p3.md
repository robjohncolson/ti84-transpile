# Task: Coverage Push — Seed Discovery from Execution Traces (Phase 451)

Analyze the execution traces from session 450 to find new transpiler seeds that would increase coverage beyond the current 711,693 bytes.

## Context

The TI-84 ROM transpiler works by starting from "seed" addresses and following control flow (CALL/JP/JR targets, fall-through) to discover blocks. Current state: 51,398 seeds → 145,648 blocks → 711,693 covered bytes. There are 33,876 uncovered non-erased bytes remaining. Only 3,912 of those are CODE? (potentially decodable) — the rest are data/strings.

Session 450 traced 530 unique blocks during key processing, with a full call tree of 13,883 CALL transitions. Some of those call targets may not yet be in the seed list.

## What to do

1. **Read the call tree from session 450's P3 probe**: `TI-84_Plus_CE/probe-phase450-0x0067F8-calltree.mjs`. Run it and capture the output. Extract all unique CALL target addresses from the output.

2. **Read the current seed list**: The transpiler is at `scripts/transpile-ti84-rom.mjs`. Find the `SEEDS` array or equivalent (it's a large array of hex addresses). 

3. **Compare**: Find CALL targets from the trace that are NOT already seeds. These are candidate new seeds.

4. **Filter**: Only keep candidates where:
   - Address is in ROM range (< 0x400000)
   - Address is not already a seed
   - Address is in a currently uncovered range (run `node TI-84_Plus_CE/audit-true-uncovered.mjs` and check if the candidate falls within an uncovered range)

5. **Add valid candidates to the seed list** in `scripts/transpile-ti84-rom.mjs`.

6. **Regenerate**: Run `node scripts/transpile-ti84-rom.mjs` to regenerate `ROM.transpiled.js`.

7. **Re-audit**: Run `node TI-84_Plus_CE/audit-true-uncovered.mjs` and report the new coverage numbers.

8. **Verify golden regression**: Run `node TI-84_Plus_CE/probe-phase99d-home-verify.mjs` and confirm it still passes 26/26.

## Constraints

- Do NOT modify `cpu-runtime.js`, `peripherals.js`, `browser-shell.html`, or any probe files other than running them.
- You MAY modify `scripts/transpile-ti84-rom.mjs` to add new seeds.
- If adding seeds causes golden regression failure, revert the seed additions and report which seeds caused the failure.
- The transpiler regeneration takes ~2 seconds. The audit takes ~5 seconds.

## File paths

- Call tree probe: `TI-84_Plus_CE/probe-phase450-0x0067F8-calltree.mjs`
- Audit: `TI-84_Plus_CE/audit-true-uncovered.mjs`

## Success criteria

- New seeds added (if any found in uncovered ranges)
- Coverage increased (report old vs new byte count)
- Golden regression still passes 26/26
- Report: how many new seeds, how many new bytes covered
