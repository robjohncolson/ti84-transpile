# Auto-Session 298 — Priority 3: Trace Secondary Keyboard Scanner at 0x040F16-0x040F59

## Task
Disassemble and annotate the secondary keyboard scanner at ROM addresses 0x040F16 through 0x040F59 (67 bytes). Determine its purpose vs. the primary scanner at 0x0159C0, and identify when/how it's called.

## Context
Session 297 identified this as a "secondary scanner" that accesses keyboard MMIO, distinct from the primary GetCSC scanner at 0x0159C0-0x015AD2. The question is: what does this shorter routine do differently? Hypotheses:
- Quick single-group scan (vs. full 8-group scan in primary)
- Debounce/confirm routine
- Power-management keyboard wake detection

The TI-84 CE keyboard MMIO:
- 0xE00800-0xE0082F = keyboard controller registers
- 0xE00900 = keyboard data (read key state / write group select)
- 0xE00810-0xE00817 = per-group key data
- 0xE00824 = ready flag (bit 0)
- 0xE00818 = scan status (bit 1)

## Deliverable
Create file `TI-84_Plus_CE/probe-phase298-secondary-scanner.mjs` that:

1. Reads `ROM.rom` from disk
2. Decodes every eZ80 instruction from 0x040F16 to 0x040F59
3. For each instruction, prints: `0xADDRESS: HEX_BYTES    MNEMONIC    ; annotation`
4. Identifies all MMIO accesses (IY-relative or direct 0xE009xx)
5. Scans the ROM for CALL 0x040F16 instructions to find all callers (CALL nn in eZ80 ADL mode = CD lo mid hi, so search for CD 16 0F 04)
6. Prints a summary comparing this scanner to the primary at 0x0159C0

## eZ80 Decoder Reference
- eZ80 ADL mode: 24-bit addresses, 3-byte immediates
- IY prefix = FD. FD 77 dd = LD (IY+d),A. FD 7E dd = LD A,(IY+d)
- FD CB dd 46 = BIT 0,(IY+d). FD CB dd C6 = SET 0,(IY+d)
- LD A,(imm24) = 3A lo mid hi. LD (imm24),A = 32 lo mid hi
- CALL imm24 = CD lo mid hi. JP imm24 = C3 lo mid hi
