# Task: Find Other General-Purpose Utility Clusters

## Context
Session 310 mapped the utility family at `0x04C960-0x04CA40` — 16 entries with ~440 total callers. The most-called are:
- cpHL_DE (252 callers) at 0x04C979
- cpHL_DE_modeDependent (134 callers) at 0x04C973

These are dense clusters of small, general-purpose helper functions (compare, negate, add, string measure, etc.) that many ROM functions call. There are likely similar clusters elsewhere.

## Your Deliverables

1. **Create `TI-84_Plus_CE/probe-phase311-utility-clusters.mjs`**: A Node.js probe that:
   - Scans the ROM for "utility cluster" patterns: sequences of small functions (≤30 bytes each) that collectively have high caller counts
   - Specifically examines these candidate regions:
     * `0x04CA40-0x04CC00` — immediately after the known cluster. Continue the scan.
     * `0x04C800-0x04C960` — immediately before the known cluster
     * `0x04D000-0x04D200` — nearby in the same ROM bank
     * `0x000200-0x000400` — low-address helper region (contains FindFirstCertField, etc.)
   - For each region, identifies function boundaries by looking for RET (0xC9) instructions and checking if the next byte starts a valid instruction sequence
   - Counts callers for each identified function entry point
   - Flags any function with ≥10 callers as a "high-traffic utility"
   - Prints a summary table of discovered clusters with their entry counts and total caller counts

2. **Create `TI-84_Plus_CE/phase311-utility-clusters-report.md`**: A markdown report documenting:
   - Each discovered utility cluster: address range, entry count, total callers
   - The top 20 highest-caller utility functions across all clusters
   - Comparison with the known 0x04C960-0x04CA40 cluster
   - Any string/memory utility functions found (memcpy, strlen, memset patterns)

## Technical Details

- ROM file: `TI-84_Plus_CE/ROM.rom` (4MB, read with `readFileSync`)
- Decoder: `import { decodeInstruction } from './ez80-decoder.js'` — `decodeInstruction(romBuffer, address, 'adl')` returns `{tag, length, target?, ...}`
- RET opcode in eZ80: 0xC9
- CALL pattern: 0xCD + 3-byte LE address
- JP pattern: 0xC3 + 3-byte LE address
- Known utility cluster for reference: 0x04C960-0x04CA40 (16 entries, see `TI-84_Plus_CE/phase310-utility-family-report.md`)
- A "function" starts at a CALL/JP target or after a RET, and ends at the next RET
- To count callers of address X: scan for CD [X_lo] [X_mid] [X_hi] pattern across all 4MB
