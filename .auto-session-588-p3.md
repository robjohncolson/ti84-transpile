# Task: Decode 0x0801D9 — First Call from Symbol Table Computation Dispatcher

## Context
0x0992C3 is the SYMBOL TABLE COMPUTATION DISPATCHER (67B+, decoded session 587). After saving D0243A→D008D6, D0008A→D0008B, HL→D00687, it makes 6 cascading sub-calls. The FIRST call is to 0x0801D9, with the Z flag result gating the subsequent dispatch chain.

The 0x0801xx-0x0802xx area contains symbol table management routines:
- 0x08011F: type-check guard (7B, session 585)
- 0x080064: multi-byte prefix check (17B, session 570)
- 0x0800A0: multi-stub cluster (29B, session 563)
- 0x080075: multi-byte prefix table cross-referenced (session 572)
- 0x080151: gate function (session 578)
- 0x080259: split-flag test (5B, session 564)

## Deliverable
Create `TI-84_Plus_CE/probe-phase588-decode-0801D9.mjs` that:
1. Reads `TI-84_Plus_CE/ROM.rom` (path relative to repo root)
2. Disassembles starting at 0x0801D9 for up to 200 bytes
3. Follows all branch/call targets within the function
4. Identifies all RAM references (0xD00000-0xD3FFFF range), IY-relative refs, port I/O
5. Cross-references all CALL targets and JP targets
6. Prints formatted disassembly with hex addresses, raw bytes, and mnemonics
7. Prints summary: function boundaries, purpose hypothesis, all call targets, all RAM refs

## Decoder API
Use a HAND-ROLLED inline decoder. Do NOT import from ez80-decoder.js. The working pattern:
- `const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');`
- Read bytes directly: `rom[offset]`, `rom[offset] | (rom[offset+1] << 8)` for 16-bit, add `| (rom[offset+2] << 16)` for 24-bit
- Handle eZ80 prefixes: 0xDD=IX, 0xFD=IY, 0xED=extended, 0xCB=bit ops
- Handle .SIS prefix 0x40 (forces 16-bit operands in ADL mode)
- Key opcodes:
  - 0xFE = CP n (immediate compare), NOT a prefix
  - 0xCD = CALL nn (3-byte address in ADL mode)
  - 0xC3 = JP nn, 0x18 = JR d, 0x20/0x28/0x30/0x38 = JR cc,d
  - 0xC9 = RET
  - 0x3E = LD A,n
  - 0xED prefix for block ops and IN/OUT
