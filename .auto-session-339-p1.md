# Task: Investigate why cxMain dispatch at 0x08BF82 is never reached + disassemble 0x0BD3FE key processing

## Context

In the TI-84 Plus CE ROM transpilation project, CoorMon (the OS event loop at 0x08BF22) calls GetCSC (0x042366) to read the keyboard scan code from mem[0x3B0033]. When a key is present, branch at 0x08BF3C is TAKEN → jumps to 0x08BF68. From there, execution goes 0x0BD3FE→0x08C308→0x0BD402→0x0BD411 (key processing), then falls into a VRAM fill loop at 0x09EFDE (88% of all visits). Execution returns via epilogue at 0x08BF9E WITHOUT ever reaching cxMain dispatch at 0x08BF82.

Session 338 confirmed: ENTER (0x09) and RIGHT (0x03) produce identical traces (246 blocks, 0 divergent). cxMain dispatch at 0x08BF82 is NEVER reached. HOME_HANDLER (0x058241) is NEVER entered.

## Your task

Create a probe `TI-84_Plus_CE/probe-phase339-cxmain-gate.mjs` that:

1. **Disassembles 0x0BD3FE through 0x0BD430** (at least 30 instructions) using the eZ80 decoder. Show raw bytes + disassembly. This is the key processing routine entered from the key-present branch.

2. **Disassembles 0x08BF68 through 0x08BFA0** (the key-present branch through the dispatch area and epilogue). Show all conditional branches, calls, and jumps.

3. **Traces a CoorMon call with ENTER key (scan code 0x09)** and records:
   - Every conditional branch instruction encountered (JP cc, JR cc, CALL cc, RET cc)
   - Whether the branch was TAKEN or NOT TAKEN
   - The register/flag state at each branch point (specifically: A register, flags Z/C/NZ/NC, and (IY+offset) values if any IY-relative instruction appears)

4. **Specifically watches for the gate to 0x08BF82**: what instruction could jump/fall-through to 0x08BF82? What condition would need to be true? What is the actual value of that condition during our trace?

5. **Tests multiple CoorMon iterations** (5 calls in a row with the same key) to see if repeated calls eventually reach 0x08BF82. Maybe state accumulates across iterations.
