# Task: Fix SP Drift + Extend VRAM Test (Continuous VRAM Writes)

## Context
You are working on a TI-84 Plus CE ROM transpiler project. The transpiler lifts eZ80 ROM into JavaScript. We have probes that boot the OS and run the event loop.

In session 477, we achieved the FIRST EVER VRAM WRITES from the event loop — 280 bytes changed during the first iteration. But two problems remain:

1. **SP DRIFT**: SP grows by 3 bytes per iteration because we write a return address at `cpu.sp` at each RET point intercept but never reset SP. Over 17K iterations, that's ~50KB of stack drift.

2. **SINGLE-SHOT**: The 280 VRAM bytes came from the FIRST iteration only, via `0x030078→0x04E950→0x09EF44`. After that, D000C6 bit 0 is cleared by the OS and never re-set, so the `CALL NZ 0x030078` at the display path never fires again.

## What to do

Create a new probe file: `TI-84_Plus_CE/probe-phase478-continuous-vram.mjs`

Based on the working probe at `TI-84_Plus_CE/probe-phase477-full-mode-setup.mjs`, make these TWO changes:

### Fix 1: Reset SP at each RET point intercept
In the `onBlock` function, where `retPcs.has(npc)` fires `writeLoopReturn()`, ALSO reset `cpu.sp` to `STACK_RESET_TOP - 3` BEFORE writing the return address. This prevents SP drift.

Change:
```javascript
if (retPcs.has(npc)) writeLoopReturn();
```
To:
```javascript
if (retPcs.has(npc)) {
  cpu.sp = STACK_RESET_TOP - 3;
  writeLoopReturn();
}
```

### Fix 2: Re-set D000C6 bit 0 every iteration
In `onBlock`, when `npc === 0x02FDBE` (event loop head), set `mem[0xD000C6] |= 0x01` so the single-shot display flag is refreshed every iteration. This should make `0x030078→0x04E950→0x09EF44` fire EVERY iteration, not just the first.

Add inside onBlock:
```javascript
if (npc === 0x02FDBE) {
  mem[0xD000C6] |= 0x01;
}
```
