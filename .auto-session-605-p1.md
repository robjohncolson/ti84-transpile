# Auto-Session 605 — P1: Test IY+0x42 Bit 7 Bypass to Prevent Wipe

## Context

The TI-84 Plus CE OS ROM is transpiled to JavaScript. During key processing (pressing '2', scan code 0x90), the OS calls a bulk wipe at 0x0018F8 that clears 82KB of RAM (D00000-D13FD7), destroying D007CA (context pointer), D0231A/D0243A (edit cursors), and other OS state.

Session 604 found TWO guard gates on the wipe path:
1. **At 0x0158E0**: `BIT 7,(IY+0x42); RET NZ` — if IY+0x42 bit 7 is already SET, the function returns WITHOUT reaching the wipe.
2. **At 0x001872**: `IN0 A,(port 0x03); BIT 4,A; JR NZ,+0x36` — hardware port gate.

IY is always 0xD00080 in this OS, so IY+0x42 = address 0xD000C2.

## Task

Create a probe `TI-84_Plus_CE/probe-phase605-iy42-bypass.mjs` that:

1. Boots the OS the same way as `probe-phase603-context-restore-fix.mjs` (cold boot → launch-init → paint) — copy the boot sequence from that file verbatim
2. After paint completes, save the state of D007CA, D0231A, D0243A, and VRAM pixel count
3. **SET bit 7 of address 0xD000C2** (IY+0x42) with `mem[0xD000C2] |= 0x80`
4. Seed the first keypress: `mem[0xD0058C] = 0x90; mem[0xD0058E] = 0x90; mem[0xD0009F] |= 0x20;`
5. Run from 0x08C331 (outer loop) with maxSteps=500000 and onBlock tracking for:
   - 0x0585E9 (cxMain entry)
   - 0x0158E0 (the guard gate itself)
   - 0x0018F8 (the bulk wipe)
   - 0x001872 (the port guard)
6. After the run, report:
   - Did cxMain dispatch? (0x0585E9 hit?)
   - Was the guard gate hit? (0x0158E0 hit?)
   - Was the wipe reached? (0x0018F8 hit?)
   - D007CA value (if still 0x0585E9, bypass worked!)
   - D0231A, D0243A values (preserved?)
   - VRAM non-white pixel count (should be >0 if display survived)
   - Step count and halt PC
7. Print a clear PASS/FAIL line: "BYPASS RESULT: WIPE PREVENTED" if 0x0018F8 was NOT hit, or "BYPASS RESULT: WIPE STILL OCCURRED" if it was.
