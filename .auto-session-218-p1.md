# Auto-Session 218 P1: Trace parent function at ~0x04EB6x — enter-edit-mode conditions

## Context
Session 217 confirmed that 0x04EC1C is the "enter edit mode" helper function (29 bytes: RES 0,(IY+14) / CALL 0x05E3AE / CALL 0x0972FE / LD A,(D00596) / CALL 0x0A2CBF / RES 6,(IY+5) / SET 4,(IY+5) / RET). It has exactly 2 callers:
- JP Z at 0x04EB82 (after CALL 0x05E3E8, which follows RES 4 / RES 2 on IY+5)
- JP Z at 0x04EB8D (when A == 0x0E)

Both are in the same parent function somewhere around 0x04EB60-0x04EBFF.

## Task
Build probe `TI-84_Plus_CE/probe-phase218-04eb-parent-trace.mjs` that:

### Part A: Static disassembly of 0x04EB60-0x04EC40
Read ROM.rom and disassemble the parent function containing the two JP Z instructions. Find:
- Function entry point (scan backwards from 0x04EB82 for a RET instruction to find the boundary)
- All CP/BIT/JR/JP/CALL instructions between the entry and 0x04EC1C
- What conditions make the JP Z at 0x04EB82 fire (Z flag = what prior operation?)
- What sets A == 0x0E for the JP Z at 0x04EB8D

### Part B: Static caller scan
Scan the entire ROM (4MB) for CALL/JP instructions targeting the parent function's entry point. Binary patterns to search:
- `CD xx xx xx` (ADL CALL) where bytes 1-3 match the entry point (little-endian 24-bit)
- `C3 xx xx xx` (ADL JP) where bytes 1-3 match the entry point
- `CA xx xx xx` (JP Z)
- `C2 xx xx xx` (JP NZ)
Also check for indirect calls via pointer tables (scan for the entry address as a 3-byte LE value in ROM).

### Part C: Dynamic trace
Boot the system (z80 boot → kernelInit → memInit), then:
1. Call the parent function entry directly with A=0x0E (should trigger JP Z at 0x04EB8D → 0x04EC1C)
2. Call it with A=0x00 (should NOT trigger the 0x0E check — test what else happens)
3. Call it from 0x04EB82's predecessor (after CALL 0x05E3E8) with Z flag forced SET
Track: which path enters 0x04EC1C, what IY+5 becomes, step count, unique blocks visited.
