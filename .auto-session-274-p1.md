# Task: Run 0x09E2EC with VRAM pre-filled to skip fill loop, check for D3FFxx dispatch table writes

## Context
In the TI-84 Plus CE ROM transpilation project, we've been investigating the OS event loop dispatch table. Session 272 found that 0x09EFDE is a VRAM fill loop (_RectFill) that takes 100K+ steps. Session 273 confirmed 0x09F736 is just a function return epilogue (POP AF / POP IX / RET PO / EI / RET), NOT dispatch table registration.

The hypothesis: after the VRAM fill loop completes at 0x09EFDE, execution may continue to code that writes dispatch table entries at D3FFxx. But we've never gotten past the fill loop because it takes too many steps.

## Task
Create a probe `TI-84_Plus_CE/probe-phase274-09e2ec-post-fill.mjs` that:

1. Sets up a standard TI-84 CE execution environment (import createExecutor from cpu-runtime.js, createPeripheralBus from peripherals.js, load ROM.rom)
2. Boots the CPU (kernel init at 0x000280, fallback 0x020028, 5000 steps)
3. Pre-fills VRAM (0xD40000-0xD52BFF) with 0xFFFF pattern so the fill loop exits immediately
4. Sets A=0 before entering 0x09EFCB (the outer fill loop entry) OR alternatively set D0059C past the fill range so the loop condition fails immediately
5. Starts execution at 0x09E2EC with PC=0x09E2EC, SP=0xD1A87E, IX=0xD1A860, IY=0xD00080, MBASE=0xD0
6. Runs for 10,000 steps
7. Monitors ALL writes to the D3F000-D3FFFF range (dispatch table area)
8. Logs every unique block visited
9. Reports: did any D3FFxx writes occur? What addresses? What values? What blocks were visited after the fill loop?

- Kernel init: PC=0x000280, fallback=0x020028, 5000 steps

## Approach to Skip Fill Loop
The fill loop at 0x09EFDE does: LD (HL),E / INC HL / LD (HL),D / INC HL (DJNZ inner), outer loop decrements A and adds 0x280 to HL. To skip it:
- Option A: Set register A=0 at the 0x09EFCB entry so the outer loop's DEC A / JP NZ exits immediately
- Option B: Pre-fill VRAM and start execution at 0x09E2EC normally, but with a step limit of 100K+ to get past the fill
- **Prefer Option A** — it's deterministic and fast
