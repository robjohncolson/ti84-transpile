# Auto-Session 462 — P1: Event Loop with Proper Timer Interval

## Task
Create a new probe `TI-84_Plus_CE/probe-phase462-timer-interval.mjs` that tests the event loop with a much larger timer IRQ interval (5000 blocks between timer ticks instead of the session 461 probe's 200).

Session 461 found that with `TIMER_IRQ_INTERVAL = 200`, the ISR processing consumed ALL CPU time — the key processor at 0x03FA09 was never reached. The hypothesis is that a larger interval (5000-10000) will allow the foreground event loop to make progress between IRQs.

## Architecture

Copy the structure from `TI-84_Plus_CE/probe-phase461-event-loop-timer.mjs` (the existing probe), but change:

1. `TIMER_IRQ_INTERVAL` from 200 to **5000**
2. `POST_BOOT_STEPS` from 200,000 to **500,000** (more steps to let event loop progress)
3. `maxLoopIterations` from 500 to **2000** (the event loop may iterate more between IRQs)
4. Add a **second run** variant that uses `peripherals.setTimerEnabled(true)` with `timerInterval: 5000` passed to `createPeripheralBus()` instead of manual `triggerIRQ()` calls. This lets the runtime's `tick()` function fire timer interrupts naturally (tick() is called after every block by the executor).

The probe must:
- Boot with `timerInterrupt: false` (standard cold boot pattern)
- After boot, do the manual-trigger run first (5000 blocks between triggerIRQ calls)
- Then do the setTimerEnabled run: create a FRESH executor+mem+peripherals with `timerInterrupt: false` for boot, boot it, then call `peripherals.setTimerEnabled(true)` and set `interruptState.timerInterval = 5000` (via the public API — check if there's a setter, otherwise just use `setTimerEnabled(true)` and pass `timerInterval: 5000` to `createPeripheralBus` from the start but with `timerInterrupt: false` to disable during boot, then enable after)

Actually, simplest approach for the second run:
- Create peripherals with `{ pllDelay: 2, timerInterrupt: false, timerInterval: 5000 }`
- Boot as normal
- After boot, call `peripherals.setTimerEnabled(true)` — this enables the tick()-based timer with interval 5000

## Cold boot pattern (copy from probe-phase461-event-loop-timer.mjs)
```js
const BOOT_ENTRY = 0x000000;
const BOOT_MODE = 'z80';
const BOOT_MAX_STEPS = 20000;
const BOOT_MAX_LOOP_ITERATIONS = 32;
const STACK_RESET_TOP = 0xD1A87E;
const KERNEL_INIT_ENTRY = 0x08C331;
const POST_INIT_ENTRY = 0x0802B2;

// Boot sequence:
executor.runFrom(BOOT_ENTRY, BOOT_MODE, { maxSteps: BOOT_MAX_STEPS, maxLoopIterations: BOOT_MAX_LOOP_ITERATIONS });
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
cpu.sp = STACK_RESET_TOP - 3; mem.fill(0xFF, cpu.sp, cpu.sp + 3);
executor.runFrom(KERNEL_INIT_ENTRY, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 });
cpu.mbase = 0xD0; cpu._iy = 0xD00080; cpu._hl = 0;
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
cpu.sp = STACK_RESET_TOP - 3; mem.fill(0xFF, cpu.sp, cpu.sp + 3);
executor.runFrom(POST_INIT_ENTRY, 'adl', { maxSteps: 100, maxLoopIterations: 32 });
```
