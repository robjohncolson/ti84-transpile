## How the ParseInp pipeline works (from probe-phase190)
1. Boot: 0x000000 (20K steps), kernelInit: 0x08C331 (100K steps), postInit: 0x0802B2 (100 steps), memInit: 0x09DEE0 (100K steps)
2. CreateReal (Ans): entry 0x08238A with OP1 = ANS_NAME_OP1 `[0x00, 0x72, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]`, stack has return sentinel 0x7FFFFE
3. For each expression:
   - BufInsert tokens at BUF_START (0xD00A00) one at a time via entry 0x05E2A0
   - Set begPC/curPC/endPC pointers: begPC=BUF_START, curPC=BUF_START, endPC=BUF_START+token_count
   - Set edit buffer pointers: editTop=BUF_START, editCursor=BUF_START+token_count, editTail=BUF_START+token_count, editBtm=BUF_END(0xD00B00)
   - Set FPS/OPS stack pointers from their base addresses
   - Call PushErrorHandler (0x07C88B) with HL=0x099929 (hlPayload target), max 8000 steps
   - Call ParseInp (0x099914) with max 5000 steps
   - When ParseInp hits JError (errNo=0x8D), the z80-mode RET intercept fires at block `03e1b1:z80` — intercept it by setting cpu.pc=0x03E1CA (ERROR_WRAPPER_AFTER_HELPER) and cpu.madl=1
   - Continue execution — it should reach 0x099929 (hlPayload target)
   - Read OP1 at 0xD005F8 (9 bytes) — this is the BCD float result
   - Read OP2 at 0xD00603 (9 bytes)
   - Read errNo at 0xD008DF

## Key implementation details from probe-phase190
- The z80-mode RET intercept: in the executor's block trace callback, check if the current block key starts with `03e1b1:z80`. When it fires, set `cpu.pc = 0x03E1CA`, `cpu.madl = 1` to skip the z80-mode RET and jump to the ADL-mode wrapper continuation.
- After the intercept, run a recovery trace (up to 2000 steps) that should reach 0x099929.
- BufInsert tokens for TWO-BYTE tokens: insert each byte as a separate BufInsert call (the buffer holds raw token bytes, not parsed tokens). So sin(0) = 4 BufInsert calls for bytes [0x5E, 0x25, 0x30, 0x11].
