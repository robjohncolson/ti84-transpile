# Task: Decode BCALL 0x1E Abort Mechanism

## Context
You are analyzing the TI-84 Plus CE OS ROM (eZ80, file `TI-84_Plus_CE/ROM.rom`, 4 MB). This is a 24-bit eZ80 CPU in ADL mode.

## Background
Session 320 discovered that BCALL 0x1E is a programmatic abort/crash invocation. In the TI-84 CE OS, "BCALL" means a direct CALL to the OS mega-table at 0x020110 (2175 entries, each a 3-byte JP target). Entry 0x1E in the mega-table would be at address 0x020110 + (0x1E × 3) = 0x020110 + 0x5A = 0x02016A.

Session 318 corrected the BCALL mechanism: real BCALL = direct CALL to mega-table entries (not RST 28h/30h which are error traps). The mega-table spans 0x020110-0x022308.

Session 320 also identified:
- D0301B = error context pointer, cleared before crash
- 0x0019B5 = crash/halt handler (hardware halt via port 0x00 write)
- One of the 19 crash sites uses BCALL 0x1E as its crash mechanism

## Deliverables
Create `TI-84_Plus_CE/phase321-bcall-abort-report.md` with:

1. **Mega-table entry decode** — read the 3-byte JP target at 0x02016A (entry 0x1E). What address does BCALL 0x1E jump to?
2. **Full disassembly of the target function** — decode from that target address until RET or crash. Show hex bytes + mnemonics.
3. **Abort mechanism** — how does it reach the crash handler 0x0019B5? Does it set up error context first? What does it store in D0301B?
4. **Caller analysis** — search the ROM for all sites that CALL the mega-table entry for 0x1E. List each caller address and its surrounding context (what OS operation was it performing when it decided to abort?).
5. **Error context format** — what data structure does D0301B point to? How many bytes? What fields?
6. **Relationship to other crash paths** — compare this programmatic abort to the direct JP/CALL 0x0019B5 sites from session 320. Is BCALL 0x1E a "clean" abort (with error context) vs the direct crashes (hardware paranoia)?

## Method
1. Read `TI-84_Plus_CE/ROM.rom` as binary
2. Read 3 bytes at offset 0x02016A to get the JP target for BCALL 0x1E
3. Disassemble the target function
4. Search for CALL patterns to that target address throughout the ROM
5. Also search for references to D0301B (the error context pointer) — bytes DB 01 D0 in LD instructions
6. Cross-reference with `TI-84_Plus_CE/phase320-crash-references-report.md`
