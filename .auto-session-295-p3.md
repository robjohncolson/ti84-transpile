# Auto-Session 295 — P3: Trace 0x022331 (CoorMon dispatch — CLEAR token handler)

## Context
The TI-84 Plus CE CLEAR key handler at 0x08C4E9 works like this:
1. LD A,(D0058C) — read scan code
2. CP cascade: 0xEF, 0xF9, 0xF3, 0x69, 0x5B, then **0x28** (CLEAR)
3. When A=0x28: SET 7,(IY+0x16), LD A,0xDA (CLEAR token code)
4. CALL **0x022331** (CoorMon dispatch) — THIS IS THE TARGET
5. Then CALL 0x08C72F, RES 4,(IY+0x09), etc.

0x022331 is called with A=0xDA (CLEAR token code). It is where the token code becomes an actual screen-clearing action. Other handlers in the 0x08C4E9 cascade also call 0x022331 with different token codes.

## Task
Disassemble and trace **0x022331** by creating a probe that:
1. Reads the ROM file at `TI-84_Plus_CE/ROM.rom`
2. Uses the eZ80 decoder at `TI-84_Plus_CE/ez80-decoder.js` to decode instructions starting at 0x022331
3. Decode all reachable blocks (follow JR/JP/CALL targets within reasonable range — up to 400 bytes total)
4. Produces a full annotated disassembly listing with:
   - Address, hex bytes, mnemonic for each instruction
   - Annotations for any CP instructions (token code comparisons — does it dispatch on A=0xDA?)
   - Annotations for any CALL targets (what subroutines does it invoke for CLEAR?)
   - Annotations for any VRAM/LCD-related addresses (0xD4xxxx range, 0xE30xxx LCD controller)
   - Annotations for any memory clears (LDIR with 0x00, etc.)
5. Determine: does 0x022331 directly clear the screen, or does it dispatch to yet another handler?
