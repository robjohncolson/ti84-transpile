# Auto-Session 218 P3: Investigate what sets 0xD02575 during normal OS operation

## Context
Session 217 decoded the dispatcher gate at 0x061290: the variable at 0xD02575 controls routing for the A=0x03 and A=0x04 dispatcher branches. Specifically:
- `LD A,(0xD02575) / AND 0x0F / JR Z` at dispatcher entry
- If low nibble is zero: A=0x03 takes zero-path (0x0612B6), SKIPPING SET 4,(IY+5)
- If low nibble is non-zero: A=0x03 takes non-zero-path (0x06129C), but IY+5 gets smashed to 0xFF
- A=0x04 with D02575=0x0F CLEANLY visits 0x0612E4 and sets IY+5=0x10

**Question**: What OS code writes to 0xD02575? When is the low nibble set non-zero during normal calculator operation?

## Task

### Part A: Static ROM scan for 0xD02575 references
Scan the entire ROM (4MB, file `TI-84_Plus_CE/ROM.rom`) for all references to address 0xD02575:
1. Search for byte pattern `75 25 D0` (little-endian 24-bit address) — matches LD instructions like `LD A,(0xD02575)`, `LD (0xD02575),A`, `LD HL,0xD02575`, etc.
2. For each hit, decode the instruction prefix to determine if it's a read or write:
   - `3A 75 25 D0` = LD A,(0xD02575) — READ
   - `32 75 25 D0` = LD (0xD02575),A — WRITE
   - `2A 75 25 D0` = LD HL,(0xD02575) — READ
   - `22 75 25 D0` = LD (0xD02575),HL — WRITE
   - `21 75 25 D0` = LD HL,0xD02575 — pointer load (could be used for indirect write)
   - Also check for `ED 4B 75 25 D0` = LD BC,(0xD02575), `ED 5B` = LD DE, `ED 7B` = LD SP
   - And `ED 43 75 25 D0` = LD (0xD02575),BC, `ED 53` = LD (0xD02575),DE
3. Report each hit's address, instruction type (READ/WRITE/POINTER), and the surrounding 8 bytes of ROM context

### Part B: Check for IY-indexed access
0xD02575 = IY + 0x24F5 (if IY=0xD00080). That's too large for IY+d (signed -128 to +127), so IY-indexed access is impossible. Confirm this by calculating: 0xD02575 - 0xD00080 = 0x24F5 > 127. Skip IY search.

Also check if 0xD02575 might be accessed via HL/IX indirect — search for LD HL,0xD02570-0xD0257F range (any pointer that could index to 0xD02575 with a small offset).

### Part C: Dynamic boot trace with write watchpoint
1. Full boot (z80 → kernelInit → memInit → homescreen stages 1-4 with IX=0xD1A860)
2. After full boot, read 0xD02575 and report its value
3. If non-zero, add a write watchpoint during the boot to find WHEN it gets set:
   - Re-run boot with a memory write monitor that checks mem[0xD02575] after each block execution
   - Report the PC (block address) and step number when 0xD02575 first changes from 0x00

### Part D: Context around write sites
For each WRITE site found in Part A, disassemble 16 bytes before and after the write instruction. Identify:
- What function it's in (scan backwards for RET to find function boundary)
- What value is being written (is A a constant? computed?)
- What conditions gate the write (preceding CP/BIT/JR instructions)
