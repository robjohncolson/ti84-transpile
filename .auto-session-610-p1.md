# Auto-Session 610 — P1: Decode Walker Caller Loop at 0x090888

## Context

This is a TI-84 Plus CE ROM transpilation project. The ROM (eZ80 machine code) has been lifted to JavaScript. We're investigating a runaway loop during multi-key processing.

The forward walker at 0x090917 walks through edit buffer entries. Its most-hit caller is at **0x090888**. The walker's PARENT function loops forever on a degenerate (zeroed) edit buffer structure — this is the actual runaway cause (not D000A3 bit 3 as previously thought).

Session 609 proved that even with D000A3 bit 3 dynamically suppressed, the walker's caller loops 5,742+ times. The parent loop can't terminate on zeroed edit buffer pointers.

## Task

Create a probe `TI-84_Plus_CE/probe-phase610-decode-090850.mjs` that does a **static disassembly** of ROM bytes from 0x090850 to 0x090950 (256 bytes, covering 0x090888 and surrounding context).

### What to decode

1. Read raw ROM bytes from the ROM file at `TI-84_Plus_CE/ROM.rom` (4MB binary, address = file offset)
2. For each byte/instruction in the 0x090850-0x090950 range, decode the eZ80 instructions (ADL mode, 24-bit addresses)
3. Focus on finding:
   - The LOOP STRUCTURE: where does the parent function loop back? (look for JR/JP backward jumps)
   - The ITERATION VARIABLE: what register or memory address is incremented/decremented each iteration?
   - The TERMINATION CONDITION: what comparison (CP, BIT, OR A, etc.) decides when to exit?
   - What EDIT BUFFER addresses it reads (look for LD from D023xx, D024xx, D111xx ranges)
   - All CALL targets and their addresses

### Technical details

- eZ80 ADL mode: default 24-bit registers, 3-byte addresses in LD/CALL/JP
- Key opcodes: CALL nn = 0xCD nn16/nn24; JP nn = 0xC3; JR e = 0x18/0x20/0x28/0x30/0x38; RET = 0xC9; LD HL,(nn) = 0x2A; LD DE,(nn) = 0xED 0x5B; BIT b,(IY+d) = 0xFD 0xCB d (46+8*b)
- IY base = 0xD00080, so (IY+0x23) = D000A3
- The existing decoder is at `TI-84_Plus_CE/ez80-decoder.js` — you can import and use `decodeInstruction(view, offset, adl)` to decode instructions

### Implementation

```javascript
import { readFileSync } from 'fs';
import { decodeInstruction } from './ez80-decoder.js';

const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
const view = new DataView(rom.buffer, rom.byteOffset, rom.byteLength);

const START = 0x090850;
const END = 0x090950;
let pc = START;
const lines = [];

while (pc < END) {
  const instr = decodeInstruction(view, pc, true); // ADL mode
  const bytes = [];
  for (let i = 0; i < instr.length; i++) bytes.push(rom[pc + i].toString(16).padStart(2, '0'));
  lines.push(`0x${pc.toString(16).padStart(6, '0')}: ${bytes.join(' ').padEnd(20)} ${instr.mnemonic || '???'}`);
  pc += instr.length;
}

console.log('=== STATIC DISASSEMBLY 0x090850-0x090950 ===');
for (const l of lines) console.log(l);

// Also dump raw hex for manual verification
console.log('\n=== RAW HEX DUMP ===');
for (let addr = START; addr < END; addr += 16) {
  const hex = [];
  for (let i = 0; i < 16 && addr + i < END; i++) hex.push(rom[addr + i].toString(16).padStart(2, '0'));
  console.log(`0x${addr.toString(16).padStart(6, '0')}: ${hex.join(' ')}`);
}
```
