# Auto-session 463 P3: Trace D177BA lifecycle — who clears it to 0x00?

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The memory byte at 0xD177BA is an event gate that blocks key processing when nonzero (0x7F after boot). For keys to reach the processing handler at 0x001853, D177BA must be cleared to 0x00.

There are 9 ROM sites that write to D177BA:
- **Clear to 0x00**: 0x000863, 0x0008AF, 0x0014B7, 0x00F045, 0x02BA85, 0x02BBAE
- **Set to 0x7F**: 0x0014C0, 0x001855 (re-arm in key processing entry)
- **Set to 0xFF**: 0x014557

And 6 ROM sites that read D177BA:
- 0x001718, 0x00F26A, 0x00F3F3, 0x013EBF, 0x014549, 0x02BF1F

## Task
Create a probe `TI-84_Plus_CE/probe-phase463-d177ba-lifecycle.mjs` that:

1. Boots the OS using the standard 3-stage boot
2. After boot, records D177BA value (should be 0x7F)
3. Intercepts ALL writes to address 0xD177BA during boot AND during event loop execution
4. For each write, records: step number, calling PC, value written, value before
5. Runs the event loop from 0x003A73 for 500,000 steps with `diHaltBypass: true` and timer disabled
6. Reports: which of the 9 write sites actually executed? When? What values?

## Key question to answer
During normal OS operation (event loop running), does ANY of the 6 clear sites (0x000863, 0x0008AF, 0x0014B7, 0x00F045, 0x02BA85, 0x02BBAE) fire to clear D177BA to 0x00? Or does D177BA stay 0x7F forever after boot, meaning the OS expects some external trigger to clear it?

  }
  origWrite8(addr, value);
};

## Important context about the write sites
From ROM byte analysis:
- 0x000863: prev bytes `53 18 00 af` → XOR A (A=0) before write. Near ROM sig check area.
- 0x0008AF: prev bytes `fa 1a 00 af` → XOR A (A=0) before write. Near ROM sig check area.
- 0x0014B7: prev bytes `00 00 f1 af` → POP AF; XOR A before write. Near 0x0014C0 (which writes 0x7F). These may be in the same function — one path clears, another sets 0x7F.
- 0x00F045: prev bytes `36 fe 00 af` → XOR A before write. In 0x00Fxxx area.
- 0x02BA85: prev bytes `57 f5 f3 af` → LD D,A; PUSH AF; DI; XOR A before write. In mode init area (0x02xxxx).
- 0x02BBAE: prev bytes `36 fe 00 af` → XOR A before write. In mode init area.
