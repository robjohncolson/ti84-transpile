# Auto-Session 262 P1 — Bypass 0x08C69E via IY+0x25 bit 5, trace to cxMain

## Context

Session 261 found that after full boot, calling 0x062055 with B=3 passes the 0x080151 gate and enters the main path (0x062055→0x080151→0x06205A→0x06205C fall-through). But execution crashes at 0x08C69E because:

1. 0x08C69E does `BIT 5,(IY+0x25)` / `RET NZ` — if bit 5 is SET, it returns early (bypasses the crash)
2. If bit 5 is CLEAR, it does `LD HL,(D007D0)` which is 0x000000 → `JP (HL)` at 0x08C745 → cold boot vector

IY = 0xD00080 (standard), so IY+0x25 = 0xD000A5.

## Task

Create a probe `TI-84_Plus_CE/probe-phase262-bypass-08c69e.mjs` that:

1. Boots the system fully (use the same boot sequence as `probe-phase261-080151-disasm.mjs` — read that file for reference)
2. After boot, SET bit 5 of address 0xD000A5 (IY+0x25): `cpu.mem[0xD000A5] |= 0x20;`
3. Then call 0x062055 with B=3 (same as session 261's successful gate pass)
4. Run for 5000 steps with full block+register tracing
5. Log: every unique block visited, key register states (A, HL, DE, BC, IX, IY, SP), and especially:
   - Whether 0x08C69E is reached and returns (RET NZ taken)
   - Whether execution reaches 0x058241 (cxMain entry) or 0x0585E9 (cxMain dispatch)
   - Whether D007E0 gets written (log reads/writes to 0xD007E0)
   - Final PC and any crash/loop detection

## Reference files

- `TI-84_Plus_CE/probe-phase261-080151-disasm.mjs` — boot sequence and B=3 call setup
- `TI-84_Plus_CE/cpu-runtime.js` — CPU API
- `TI-84_Plus_CE/peripherals.js` — peripheral bus creation

## Constraints

- Do NOT modify any existing files
- Create ONLY `TI-84_Plus_CE/probe-phase262-bypass-08c69e.mjs`
- Use `import { createCPU } from './cpu-runtime.js'` and `import { createPeripheralBus } from './peripherals.js'`
- Use `createPeripheralBus({ timerInterrupt: false })` to disable timer IRQ
- The probe must be runnable with `node TI-84_Plus_CE/probe-phase262-bypass-08c69e.mjs`

## Success criterion

The probe runs without crashing node, prints block trace showing whether 0x08C69E's RET NZ is taken, and reports whether cxMain (0x058241 or 0x0585E9) is reached.
