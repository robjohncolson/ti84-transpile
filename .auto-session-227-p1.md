# Task: Trace 0x023B6B SET 1,(IY+53) site — find what HL contains

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80).
The transpiled JS is regenerated via `node scripts/transpile-ti84-rom.mjs`.
Runtime: `TI-84_Plus_CE/cpu-runtime.js`, decoder: `TI-84_Plus_CE/ez80-decoder.js`, peripherals: `TI-84_Plus_CE/peripherals.js`.

## What we know
- D0059F is the key state variable that holds magic values (0xFA/0xFB/0xFC/0xFE) controlling secondary token table selection
- The sole D0059F writer is at 0x051D4D: `LD A,(HL); INC HL; LD (D0059F),A` — magic values come from wherever HL points
- When BIT 1,(IY+53) is SET, function 0x02398E is called (which preserves HL from caller)
- When BIT 1,(IY+53) is CLEAR, function 0x051F1C loads HL from pointer table at 0x04F262 (UI descriptors, NOT magic values)
- **Only 2 sites SET 1,(IY+53)**: 0x023B6B (also stores HL→D02611) and 0x0454FC
- The RAM pointer at D02611 is loaded by mode-switching code, zero after boot
- 0x023B6B is the critical site — it stores HL to D02611 BEFORE setting the flag

## Task
Build a probe `TI-84_Plus_CE/probe-phase227-023b6b-hl-source.mjs` that:

1. **Static disassembly**: Read ROM.rom bytes around 0x023B6B (±100 bytes, say 0x023B00-0x023BD0). Decode the eZ80 instructions manually (byte-by-byte, like other probes in this repo do). Find:
   - The function boundary (look for RET before 0x023B6B)
   - What instructions precede the SET 1,(IY+53) at 0x023B6B
   - Where HL is loaded/computed before the store to D02611
   - Any CALL/JP targets

2. **Static ROM scan**: Search the entire ROM (0x000000-0x0BFFFF) for `CALL 0x023B6B` patterns:
   - ADL CALL: `CD 6B 3B 02` 
   - ADL JP: `C3 6B 3B 02`
   - Also search for calls to the function entry (whatever address the function starts at, found in step 1)
   
3. **Find the parent function entry**: Scan backwards from 0x023B6B looking for a RET (0xC9) or other terminator to find the function boundary. Then scan ROM for CALL/JP to that entry address.

4. **Dynamic trace**: Boot the CPU (full boot sequence like other probes), then call 0x023B6B with various HL values to see what happens. Use the standard probe pattern from existing probes (see `probe-phase226-02398e-hl-loader.mjs` for reference).

5. **Also trace 0x0454FC** — the second SET 1,(IY+53) site. Disassemble ±50 bytes around it and find its callers.

## Output format
Print all findings to stdout with clear headers. Include:
- Full disassembly of the function containing 0x023B6B
- All callers found
- What HL contains / where it's loaded
- Disassembly around 0x0454FC
- Any dynamic trace results
