# Auto-Session 345 — Priority 1: Fix .SIL/.SIS PREFIX ALU BUG IN TRANSPILER

## Context

The TI-84 Plus CE eZ80 CPU has prefix bytes (.SIS=0x40, .SIL=0x52, .LIS=0x49, .LIL=0x5B) that override the operand width of instructions regardless of the current ADL/Z80 mode. The transpiler already recognizes these prefixes and uses them correctly for memory access width (see `getWordByteWidth()` at line 118 of `scripts/transpile-ti84-rom.mjs`). However, the 16-bit ALU instructions (`add-pair`, `sbc-pair`, `adc-pair`) at lines 542-544 of the transpiler do NOT pass width information to the runtime functions.

## The Bug

In `scripts/transpile-ti84-rom.mjs` lines 542-544:
```js
if (tag === 'add-pair') return [`cpu.${instruction.dest} = cpu.addWord(cpu.${instruction.dest}, cpu.${instruction.src});`];
if (tag === 'sbc-pair') return [`cpu.hl = cpu.subtractWithBorrowWord(cpu.hl, cpu.${instruction.src});`];
if (tag === 'adc-pair') return [`cpu.hl = cpu.addWithCarryWord(cpu.hl, cpu.${instruction.src});`];
```

These call `addWord`, `subtractWithBorrowWord`, `addWithCarryWord` in `TI-84_Plus_CE/cpu-runtime.js` (lines 335, 359, 343). All three use `this.addressMask` (line 117: `get addressMask() { return this.madl ? 0xffffff : 0xffff; }`) which reads the CURRENT `cpu.madl` state at runtime. But `.SIS/.LIS` prefix forces 16-bit operands (mask 0xFFFF) and `.SIL/.LIL` prefix forces 24-bit operands (mask 0xFFFFFF), regardless of `cpu.madl`.

**Real-world impact**: Boot signature check at ROM address 0x0008BB uses `.SIL SBC HL,BC` (prefix 0x52). ROM[0x020100]=0xFFA55A, magic=0x00A55A. With correct 16-bit SBC: 0xA55A-0xA55A=0 → Z flag set → boot continues. With buggy 24-bit SBC (because `cpu.madl=1` in ADL mode): 0xFFA55A-0x00A55A=0xFF0000 → NZ → JP NZ 0x0019B5 → HALT. This is the root cause of boot diversion.

~1,935 transpiled blocks contain .SIL/.SIS-prefixed ALU ops that will be affected.

## The Fix

### Part 1: cpu-runtime.js (lines 335-373)

Add a `forceShort` parameter to all three functions. When `forceShort === true`, use 16-bit masks. When `forceShort === false`, use 24-bit masks. When `forceShort === undefined` (default), use `this.madl` as before (backwards compatible).

```js
addWord(a, b, forceShort) {
    const result = a + b;
    const mask = forceShort !== undefined ? (forceShort ? 0xffff : 0xffffff) : this.addressMask;
    this._setFlag(FLAG_H, ((a ^ b ^ result) & (mask === 0xffff ? 0x1000 : 0x100000)) !== 0);  // halfBit derived from mask
    this._setFlag(FLAG_N, false);
    this._setFlag(FLAG_C, result > mask);
    return result & mask;
}
```

Wait — `addWord` currently doesn't set S/Z/PV flags (it's ADD HL,rr which only sets H, N, C). So `addWord` is simpler. But the halfBit must still respect the width. Currently it hardcodes `0x1000` which is correct for 16-bit. In 24-bit mode it should be `0x100000`. Looking at the current code:

```js
addWord(a, b) {
    const result = a + b;
    this._setFlag(FLAG_H, ((a ^ b ^ result) & 0x1000) !== 0);
    this._setFlag(FLAG_N, false);
    this._setFlag(FLAG_C, result > this.addressMask);
    return result & this.addressMask;
}
```

**Bug within a bug**: `addWord` hardcodes halfBit as `0x1000` (16-bit), but in ADL mode it should be `0x100000`. However, let's focus on the prefix override. The fix:

For `addWord`, `addWithCarryWord`, and `subtractWithBorrowWord`:
1. Add a `forceShort` parameter (optional, default undefined)
2. Compute mask/msb/halfBit based on: if `forceShort === true` → 16-bit, if `forceShort === false` → 24-bit, else → use `this.madl`

### Part 2: transpile-ti84-rom.mjs (lines 542-544)

Modify code generation to pass the prefix-derived width:

```js
if (tag === 'add-pair') {
    const forceArg = instruction.prefix === 'SIS' || instruction.prefix === 'LIS' ? ', true'

```

### Part 3: Also fix `addWord` halfBit bug

The existing `addWord` function hardcodes halfBit as `0x1000`. This is correct for 16-bit but wrong for 24-bit (ADL mode). Fix: derive halfBit from mask, same as `addWithCarryWord` and `subtractWithBorrowWord` do.
