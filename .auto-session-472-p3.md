# Task: Trace Home Screen Mode Init at 0x08BF22

## Context

You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`.

The OS export table entry #1614 at 0x021A3C contains `JP 0x08BF22` — this is the home screen init function. Session 471 identified that display conditions at 0x02FDD8 are never met because RAM state variables (D000B4, D000C6, D000D7, D00824, D0058F) are not set correctly. The home screen mode init at 0x08BF22 should set these variables during startup.

## Deliverable

Create a NEW file: `TI-84_Plus_CE/probe-phase472-homescreen-init.mjs`

### Approach

1. Boot the OS (3-stage boot as done in existing probes)
2. After boot, enter at 0x08BF22 in ADL mode
3. Track ALL writes to the following RAM addresses during execution:
   - D000B4 (display path enable)
   - D000C6 (port/LCD setup enable)
   - D000D7 (display mode bits)
   - D00824 (key state variable)
   - D0058F (mode/context parameter)
   - D14091 (unknown, possibly display)
   - D177B7 (HALT trap control)
   - D00080 (key flags)
   - D00085 (rendering mode flag)
   - D00595 (display cursor position — 3 bytes)

### Implementation

Use the executor's `onBlock` callback to periodically snapshot these addresses (every 100 blocks). Compare with previous snapshot to detect changes. When a change is detected, log:
```
[write] D00824 changed from 0x00 to 0x05 at step <N> (pc=0x<addr>)
```

Also intercept writes by wrapping mem writes — BUT since the transpiled code writes directly to `mem[]`, the simplest approach is periodic polling in onBlock.

**Alternative approach (recommended)**: Use a Proxy or defineProperty on key addresses. Actually, since `mem` is a Uint8Array, you can't use Proxy easily. Stick with periodic polling in onBlock.

### Boot sequence (copy from existing probes)

Read `TI-84_Plus_CE/probe-phase471-looping-eventloop.mjs` for the standard 3-stage boot:
1. Boot: `runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
2. Kernel: `runFrom(0x08C331, 'adl', { maxSteps: 200000, maxLoopIterations: 500 })` with `cpu.mbase = 0xD0; cpu._iy = 0xD00080`
3. Post-init: `runFrom(0x0802B2, 'adl', { maxSteps: 200000, maxLoopIterations: 500 })`

After boot:
```js
cpu.mbase = 0xD0;
cpu._iy = 0xD00080;
cpu.halted = false;
cpu.iff1 = 0;
cpu.iff2 = 0;
cpu.sp = 0xD1A87E - 3;
// Push a sentinel return address so RET terminates cleanly
mem[cpu.sp] = 0xFF;
mem[cpu.sp + 1] = 0xFF;
mem[cpu.sp + 2] = 0xFF;
```

Then run:
```js
const result = executor.runFrom(0x08BF22, 'adl', {
  maxSteps: 500000,
  maxLoopIterations: 5000,
  diHaltBypass: true,
  onBlock,
});
```
