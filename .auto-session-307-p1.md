# Auto-Session 307 P1: Map Full 0x09F79B Scan-Code-to-Token Table + Cross-Reference ti84-keyboard.js

## Context
The TI-84 Plus CE OS converts SDK scan codes to OS tokens via a 112-byte lookup table at ROM address 0x09F79B. Session 306 partially decoded this table and identified some entries, but the full table needs systematic mapping with SDK name verification for ALL 112 entries.

The browser shell injects keyboard events via `TI-84_Plus_CE/ti84-keyboard.js`, which maps browser KeyboardEvent.code → (group, bit) pairs for the keyboard matrix. The SDK scan code is computed from these as `scanCode = (groupIndex << 3) | bitIndex` (approximately — the actual formula depends on how _GetCSC reads the matrix).

## Task
1. Read the ROM file at `TI-84_Plus_CE/ROM.rom` and extract all 112 bytes from offset 0x09F79B to 0x09F80A (inclusive).
2. For each byte position (SDK scan code 0x00 through 0x6F), document the OS token value stored there.
3. Cross-reference the SDK scan code names from the CE C SDK `keypadc.h` header (the names are already in `TI-84_Plus_CE/probe-phase306-scan-class-find.mjs` lines 92-144 as `SDK_SCAN_CODES`).
4. For each scan code that has a corresponding entry in `TI-84_Plus_CE/ti84-keyboard.js` KEY_MAP, verify the mapping chain: browser key → (group, bit) → SDK scan code → OS token. Document any mismatches or gaps.
5. Identify any SDK scan codes that are mapped in the ROM table but NOT reachable from ti84-keyboard.js (missing browser key bindings).

## Deliverables
Create `TI-84_Plus_CE/probe-phase307-scancode-token-table.mjs` that:
- Reads ROM.rom
- Dumps all 112 table entries with: index (hex), SDK name, physical key, OS token value (hex), and classification (TOKEN-DIRECT, MODIFIER, NAVIGATION, etc.)
- Cross-references with the KEY_MAP from ti84-keyboard.js to identify coverage gaps
- Prints a summary: how many scan codes are covered by browser bindings, how many are not

The probe should run with `node TI-84_Plus_CE/probe-phase307-scancode-token-table.mjs` and produce human-readable output.
