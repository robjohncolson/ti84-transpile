# Task: Trace the PutC Pipeline End-to-End

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM (eZ80 machine code) has been lifted to JavaScript. You need to trace the full text rendering pipeline from token dispatch through PutC to DrawChar to pixel writer to VRAM.

## Key addresses from prior sessions
- **0x0540D0** = `PutC_draw_advance` — draws a character and advances cursor. Has 10 callers.
- **0x0540F5** = `PutC_draw_only` — draws without advancing. Has 1 caller.
- Both call DrawChar via vtable dispatch at D005E9+3 (trampoline: LD BC,(IY+N) → JP(IY) → 0x002288 → JP(IY)).
- DrawChar eventually calls pixel writer at **0x054FC6** (variable-width font) or **0x054E21** (fixed-width font).
- Pixel writers write to VRAM at D02FE3 base (0xD40000 in 16bpp mode).
- **0x055191** = lazy-init check for vtable at D005E9.

## What to do
1. Open `TI-84_Plus_CE/ROM.transpiled.js.gz` (gunzip it), and search for all 10 callers of block_0x0540D0.
2. For each caller, determine: what function is it? What token/character triggers it? How does the character code arrive in the register?
3. Trace the call chain: caller → PutC_draw_advance (0x0540D0) → DrawChar vtable dispatch → pixel writer → VRAM write.
4. Document the full pipeline as a probe file.

## Deliverable
Create `TI-84_Plus_CE/probe-phase331-putc-pipeline.mjs` that:
- Statically finds all 10 callers of block_0x0540D0 in the transpiled JS
- Boots the calculator to home screen (use `createPeripheralBus({ timerInterrupt: false })`, run for 800000 steps)
- Hooks PutC_draw_advance to log each character drawn, the caller address (from stack), and the destination VRAM coordinates
- Reports the full call chain for at least 3 different characters
