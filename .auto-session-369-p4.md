# Task: Extended Boot Trace to Find BC31 Indirect Caller

## Context
Block 0x00BC31 is reached during extended kernel init but NOT during the standard 3-phase boot. Session 368 confirmed:
- 0x00BC2F = `JR 0x00BC3E` — NOT a fallthrough to 0x00BC31
- ZERO jump table entries for 0x00BC31 or 0x00BC47 in entire 4MB ROM
- 0x00BC31 NOT reached in standard 3-phase boot (terminates at 0xD18C22 before reaching deep kernel)
- The dispatch happens somewhere in the 476→671 block expansion after the flash self-test trampoline

The RAM trampoline is already integrated into cpu-runtime.js. Phase 2 with higher maxSteps should get past the flash self-test and into deeper kernel init where 0x00BC31 is called.

## Deliverable
Create `TI-84_Plus_CE/probe-phase369-bc31-extended-boot.mjs` that:

1. Runs the standard 3-phase boot:
   - Phase 1: `executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
   - Reset: `cpu.halted=false; cpu.iff1=0; cpu.iff2=0; cpu.sp=0xD1A87E-3; mem.fill(0xFF, cpu.sp, cpu.sp+3);`
   - Phase 2: `executor.runFrom(0x08C331, 'adl', { maxSteps: 500000, maxLoopIterations: 10000 })`
     NOTE: 500K steps (5x normal) to push past the flash self-test and into deep kernel
   - Reset: `cpu.mbase=0xD0; cpu._iy=0xD00080; cpu._hl=0; cpu.halted=false; cpu.iff1=0; cpu.iff2=0; cpu.sp=0xD1A87E-3; mem.fill(0xFF, cpu.sp, cpu.sp+3);`
   - Phase 3: `executor.runFrom(0x0802B2, 'adl', { maxSteps: 100, maxLoopIterations: 32 })`

2. Uses an `onBlock` callback during Phase 2 to track the execution order and specifically watch for:
   - Block 0x00BC31 — when it first appears, log the previous 10 blocks that executed before it
   - Block 0x00BC47 — the IX linked-list traversal
   - Block 0x00BC72 — the LD SP,IX epilogue

3. Reports:
   - Total unique blocks per phase
   - Whether 0x00BC31 was reached, and at which step
   - The 10 blocks that executed immediately before 0x00BC31 (the call chain)
   - What the termination was (missing_block, max_steps, etc.)
   - Missing blocks encountered
   - CPU state at termination

## Reference pattern (from probe-phase367-boot-50k.mjs):
```javascript
#!/usr/bin/env node
import fs from 'node:fs';
import path from 'node:path';
import { fileURLToPath, pathToFileURL } from 'node:url';
import { createExecutor } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));
const romModule = await import(pathToFileURL(path.join(__dirname, 'ROM.transpiled.js')).href);
const BLOCKS = romModule.PRELIFTED_BLOCKS;
const STACK_RESET_TOP = 0xD1A87E;

function hex(v, w = 6) {
  return v == null ? 'n/a' : '0x' + (v >>> 0).toString(16).padStart(w, '0');
}

const mem = new Uint8Array(0x1000000);
mem.set(romBytes);
const peripherals = createPeripheralBus({ pllDelay: 2, timerInterrupt: false });
const executor = createExecutor(BLOCKS, mem, { peripherals });
const { cpu } = executor;
```

For the `onBlock` tracking in Phase 2, use a circular buffer:
```javascript
const recentBlocks = [];
const BC31_TARGET = '00bc31';
let bc31Step = -1;
let bc31PrecedingBlocks = null;
let blockStep = 0;

const r2 = executor.runFrom(0x08C331, 'adl', {
  maxSteps: 500000,
  maxLoopIterations: 10000,
  onBlock: (pc, mode) => {
    const key = pc.toString(16).padStart(6, '0');
    recentBlocks.push(key + ':' + mode);
    if (recentBlocks.length > 20) recentBlocks.shift();
    if (key === BC31_TARGET && bc31Step === -1) {
      bc31Step = blockStep;
      bc31PrecedingBlocks = [...recentBlocks];
    }
    blockStep++;
  },
});
```
