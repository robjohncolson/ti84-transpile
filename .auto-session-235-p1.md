# Task: Trace 0x02FFAE — normal key dispatch block (lll)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript and executed via `cpu-runtime.js`. We are tracing the OS event loop's key processing pipeline.

**0x02FFAE** is the "normal dispatch" block reached after `CALL 0x0302EB` returns Z (i.e., non-0x44 key codes). The path is: key event → 0x02FD8F dispatcher → 0x02FE89 (CP 0xFF gate) → 0x02FF11 (09F79B table lookup) → 0x02FF1F (CALL 0x0302EB) → 0x02FF23 (BIT 0,D test) → JP Z,0x02FFAE.

Session 233 showed that 0x02FFAE leads to 0x02FE84 → 0x030300 → JP 0x02FD99. Session 234 confirmed non-0x44 keys take this path. But we don't know what 0x02FFAE itself does between entry and reaching 0x02FE84.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase235-02ffae-normal-dispatch.mjs` that:

1. Imports from `./cpu-runtime.js` (createCPU, createMemoryBus, createPeripheralBus)
2. Loads ROM from `./ROM.rom` using `fs.readFileSync`
3. Sets up the environment:
   - `createPeripheralBus({ timerInterrupt: false })`
   - `createMemoryBus(rom, peripherals)`
   - `createCPU(mem)`
   - `cpu.mbase = 0xD0`
4. Seeds a key code in the 09F79B table output position. At entry to 0x02FFAE, the key has already been looked up. Set D0058E to a test key code (try 0x9C = key code for scan code 0x8F = digit '1').
5. Seeds IY = 0xD00080 (standard OS IY base).
6. Starts execution at block 0x02FFAE with `cpu.pc = 0x02FFAE` and runs up to 500 steps using `cpu.step()`, logging each block visited (check if `cpu.block_<hex>` function exists).
7. Tests at least 3 different key codes: 0x9C (digit), 0xFC (special-path code from session 229), and 0x80 (a normal operator key code '+').
8. For each test, captures:
   - All unique blocks visited (in order)
   - Total steps
   - Key RAM locations after: D0058E, D0058D, D0059F, D00000
   - IY flag bytes: (IY+0) through (IY+5), (IY+18), (IY+29), (IY+40), (IY+87)
   - Whether execution reaches 0x02FE84, 0x030300, or 0x02FD99
   - Whether execution reaches 0x02FFED (the special-path exit)
9. Prints results as structured output showing the block chain and RAM state for each key code.

## Key constraints
- Do NOT modify any file except the probe file you're creating
- Use `{ timerInterrupt: false }` on peripheral bus
- Use `cpu.mbase = 0xD0`
- IY = 0xD00080
- The ROM file is at `TI-84_Plus_CE/ROM.rom` (relative) or use `import.meta.url` for path resolution
- Use `import { ... } from './cpu-runtime.js'` (ES module)
- Each cpu.step() call executes one transpiled block. Check for missing blocks by catching errors.
- Block functions are named `block_XXXXXX_Y` where XXXXXX is hex address and Y is adl mode (1 for ADL).

## Success criteria
- Probe runs without crash: `node TI-84_Plus_CE/probe-phase235-02ffae-normal-dispatch.mjs`
- Shows the complete block chain from 0x02FFAE through to wherever execution settles
- At least 3 key codes tested with results printed
