## Target

The 0x07FEB6 pipeline does: CALL 0x07FE5A → CALL 0x07FEE1 → CALL 0x07FE24 → CALL 0x07FD30, repeated twice. So 0x07FEE1 is a transform step between the forward type transform and the OP copy.

## eZ80 decoder notes
- Standard Z80 opcodes apply. Watch for:
  - CB prefix: bit/rotate ops
  - ED prefix: block ops, I/O, misc
  - DD prefix: IX register variants (replace HL→IX, H→IXH, L→IXL; +d displacement for (IX+d))
  - FD prefix: IY register variants (same pattern as DD but for IY)
  - FD CB dd op: IY bit ops — byte after FD CB is displacement, byte after that is the opcode
  - 0x3A = LD A,(nn) — takes 3-byte address in eZ80 ADL=0 mode (but here we use 2-byte for Z80 compat, actually check: in .SIS mode addresses are 2 bytes, in .LIS/.LIL they're 3 bytes; this ROM mostly uses 3-byte addresses for CALL/JP/LD absolute)
- For CALL nn and JP nn: read 3 bytes for the address (little-endian 24-bit)
- For LD rr,nn (16-bit immediate loads like LD HL,nn): read 3 bytes for the value in eZ80
- For LD A,(nn) opcode 0x3A: read 3 bytes for address
- For LD (nn),A opcode 0x32: read 3 bytes for address
- JR uses signed 8-bit displacement from the byte AFTER the JR instruction
