# Auto-Session 207 P1: Trace 0x058D54 return values for all token classes

## Context
In the TI-84 Plus CE ROM transpilation project, we're investigating the cxMain digit insertion path. Session 206 discovered that `CALL 0x0802C4` at 0x058AC9 does `CP 0x5A; RET C` — meaning the A register (loaded by 0x058D54) must be ≥ 0x5A (90) for BufInsert to be reached. Digits have A=0x00 from 0x058D54, so they never reach BufInsert via this path.

**KEY QUESTION**: What does 0x058D54 return in A for EACH token class (0-5)? The return value is NOT the class value itself — it's a transformed token/type. We need to map class → A return value to understand which classes can reach BufInsert (A ≥ 0x5A) and which can't.

## How 0x058D54 is reached
From session 206: The cxMain digit path goes:
```
0x0585E9 → 0x05877A (step 5) → 0x0587E9 → 0x05899D → 0x058D54 → 0x0589E5 → ...
```
At 0x058D54, the block transforms the token class into some value in A. That A value is then used in the CP chain at 0x0589E9/0x058A0C/0x058A60/0x058AC9.

## Approach
The simplest approach: enter at 0x0585E9 (cxMain entry) with different class values pre-loaded in the KeyClassifier result. The class value comes from KeyClassifier (0x07F7BD) which returns OP1[0]&0x3F. So:
- Set OP1[0] (at RAM 0xD005F8) to the desired class value before entering 0x0585E9
- Or better: enter directly at 0x058D54 if possible, setting registers to match what the upstream path would provide

For each experiment, log:
- The A register value after 0x058D54 returns
- Whether the subsequent CP chain (0x09, 0x0C, 0x0D, 0x5A) would match
- Whether BufInsert would be reachable
