# Task (ttt): Trace 0x04EDD0 — key code action handler

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript. You write Node.js probes that boot the transpiled ROM and trace execution paths.

## Background
Session 236 decoded function 0x04EB02 as a three-way key code classifier: CP 0x40, CP 0x1D, CP 0x44 all converge on `CALL 0x04EDD0 → JR 0x04EAD8` (loop). 0x1D and 0x44 take identical downstream paths through 0x04EDD0 (61 unique blocks, stuck at 0x09EFDE computation loop). Unrecognized keys return A=0x00 in 8 steps.

**Question**: What is 0x04EDD0's purpose? It may be the "key code accepted, run associated action" handler. The downstream chain enters 0x04ECCE→0x07F984→0x08BF22 before getting stuck at 0x09EFDE.

## What to do
Create `TI-84_Plus_CE/probe-phase237-04edd0-handler-trace.mjs` that:

1. Boots the transpiled ROM (full boot sequence — see existing probes for pattern)
2. Traces execution starting at 0x04EDD0 with A=0x1D (the synthetic key code that triggers it)
3. Records all unique blocks visited, max 500 steps
4. Captures key RAM reads/writes: IY flags, D00824, D0058E, D0059F, OP registers (0xD005F8-0xD00620)
5. Also test with A=0x44 (the "2" key code) — compare paths
6. Also test with A=0x40 — compare paths
7. Try to identify what 0x04EDD0 DOES: does it write to display? modify edit buffer? update mode flags?

## Boot pattern
```js
import { readFileSync } from 'fs';
const src = readFileSync('TI-84_Plus_CE/ROM.transpiled.js', 'utf-8');
const factory = new Function('module', src);
const mod = {}; factory(mod);
const ROM = mod.exports;

// Create runtime
const { createCPU } = await import('./TI-84_Plus_CE/cpu-runtime.js');
const { createPeripheralBus } = await import('./TI-84_Plus_CE/peripherals.js');
const cpu = createCPU();
const bus = createPeripheralBus({ timerInterrupt: false });
cpu.connectBus(bus);

// Load ROM
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
for (let i = 0; i < rom.length; i++) cpu.mem[i] = rom[i];
```
