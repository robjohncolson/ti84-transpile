# Task: Decode 0x08C9AC Initialization Block

## Context
Session 342 found that immediately after the 28-entry context handler table (at 0x08C958, ending at 0x08C9AB), there's a code prologue at 0x08C9AC that copies 40 bytes of initialization data:

```
0x08C9AC: LD BC,0x28        ; BC = 40 (0x28) bytes to copy
          LD HL,0x08CA09    ; source: ROM data at 0x08CA09
          LD DE,0xD031CB    ; destination: RAM at 0xD031CB
          LDIR              ; copy BC bytes from (HL) to (DE)
```

This copies 40 bytes from ROM address 0x08CA09 to RAM address 0xD031CB. This likely initializes per-context RAM state since it runs right after context table lookup.

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase343-init-block-decode.mjs` that:

1. Reads the ROM file at `TI-84_Plus_CE/ROM.rom`
2. Extracts the 40 bytes at ROM offset 0x08CA09-0x08CA30
3. Prints the raw hex dump of these 40 bytes
4. Analyzes the data structure:
   - Check if it contains 3-byte LE addresses (pointers to handlers or ROM routines)
   - Check if it contains flag bytes or small integers
   - Check if any 3-byte sequences match known handler addresses from the context table
   - Check if the stride matches any pattern (e.g., 4-byte records = 10 entries, 5-byte = 8 entries, 8-byte = 5 entries, etc.)
5. Disassembles the code AFTER the LDIR at 0x08C9AC — what happens next? (decode 40 bytes after the LDIR completes, approximately at 0x08C9AC + length of the LD BC/LD HL/LD DE/LDIR sequence)
6. Also checks what code CALLS 0x08C9AC — scan ROM for CALL 0x08C9AC or JP 0x08C9AC patterns
7. Cross-references the destination RAM range 0xD031CB-0xD031F2 — scan ROM for any other reads/writes to addresses in this range

## Technical Details
- ROM at `TI-84_Plus_CE/ROM.rom` (4MB binary)
- Use `import { decodeInstruction } from './ez80-decoder.js'` for disassembly
- eZ80 ADL mode LDIR: ED B0 (2 bytes)
- eZ80 ADL mode LD BC,nn: 01 + 3-byte LE
- eZ80 ADL mode LD HL,nn: 21 + 3-byte LE  
- eZ80 ADL mode LD DE,nn: 11 + 3-byte LE
- CALL nn in eZ80 ADL: CD + 3-byte LE address
- For ROM scanning, search for byte patterns in the full 4MB
