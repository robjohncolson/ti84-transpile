# Auto-Session 215 P3: Display-result loop BufInsert Z-flag investigation

## Context
We're reverse-engineering the TI-84 Plus CE OS ROM (eZ80). Session 214 corrected the display-result loop entry to 0x080CFE (not 0x080D08). The loop is:
```
0x080CFE: LD A,(HL) / LD DE,0 / LD E,A / INC HL / OR A / JR Z,0x080D14(exit)
0x080D08: PUSH HL / CALL BufInsert(0x05E2A0)  
0x080D0D: POP HL / JR NZ,0x080CFE(loop back)
```
Problem: BufInsert returns Z flag, so JR NZ at 0x080D0D doesn't loop back. Loop exits after 1 iteration. Edit buffer stays empty. The format buffer at 0xD0060E has "42.5\0" but only 1 BufInsert call fires.

**Hypothesis**: BufInsert returns NZ on success and Z on failure. It's returning Z (failure) because edit buffer state is missing — specifically the edit cursor pointer, edit buffer tail, or edit buffer size that BufInsert needs to know WHERE to insert.

## Task
Build a probe at `TI-84_Plus_CE/probe-phase215-bufinsert-z-flag.mjs` that:

### Part A: Trace BufInsert internals to find what causes Z return
- Boot the CPU fully (same pattern as other probes — see reference files)
- Create peripherals with `createPeripheralBus({ timerInterrupt: false })`
- Load ROM + transpiled JS
- Run kernelInit (0x000230) 2000 steps, memInit (0x08479C) 15000 steps
- Set up edit buffer state:
  - Edit cursor at 0xD00A00 (standard edit buffer start)
  - IY = 0xD00080
- Call BufInsert (0x05E2A0) directly with DE=0x000035 (token '5')
- Run for 50 steps, tracking every block visited and every memory write
- Check flags after return: is Z set or NZ?
- Check edit buffer at 0xD00A00: was the token written?

### Part B: Experiment with edit pointer initialization
The edit buffer pointers are likely at these OS RAM addresses (from session 213 notes):
- 0xD00A00 = edit buffer start (known)
- 0xD0243A = some edit position pointer (seen in session 209 at 0x0568C3: `LD (0xD0243A),DE`)
- 0xD0243D = another edit pointer (seen at 0x0568C3: `LD HL,(0xD0243D)`)

Run 4 experiments:
1. **Baseline**: Just call BufInsert with DE=0x000035, no pointer setup
2. **Cursor seeded**: Set mem16 at 0xD0243A = 0xD00A00 before calling BufInsert
3. **Both pointers**: Set 0xD0243A = 0xD00A00 AND 0xD0243D = 0xD00A00
4. **Full edit context**: Same as #3 plus set 0xD00A00-0xD00A10 = 0x00 (clear buffer), and set BIT 4,(IY+5) at 0xD00085

For each experiment, report:
- Z/NZ flag after BufInsert returns
- Edit buffer content at 0xD00A00-0xD00A0F
- Number of steps taken
- Blocks visited

### Part C: Test the full loop at 0x080CFE
If any experiment in Part B gets BufInsert to return NZ:
- Set HL = 0xD0060E, seed format buffer with "42.5\0" at 0xD0060E
- Apply the successful pointer initialization from Part B
- Enter at PC = 0x080CFE
- Run for 200 steps
- Check: does the loop iterate? How many BufInsert calls? What's in the edit buffer?
