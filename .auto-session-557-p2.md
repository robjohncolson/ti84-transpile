# Task: Decode 0x09EF20 vs 0x09EF44 — Immediate vs Deferred Rendering Paths

## Context
This is the TI-84 Plus CE ROM transpilation project. We disassemble eZ80 machine code from `TI-84_Plus_CE/ROM.rom` (4MB).

Session 556 found that the renderer at **0x0A22DA** tests `BIT 4,(IY+0x4A)` and branches:
- When bit 4 is SET (text output active): saves to (D002AC0A) + calls **0x09EF44** (deferred rendering)
- When bit 4 is CLEAR: calls **0x09EF20** (immediate rendering)

We need to understand what these two functions do and how they differ.

## What To Do

1. Create a probe script `TI-84_Plus_CE/probe-phase557-render-paths.mjs` that:
   - Loads the ROM from `TI-84_Plus_CE/ROM.rom`
   - Disassembles **0x09EF20** — determine its size, what it calls, what RAM it accesses
   - Disassembles **0x09EF44** — same analysis
   - Also disassembles the calling context at **0x0A22DA** (about 30-50 bytes around it to show the branch structure)
   - Compares the two functions — what do they share, what differs?

2. Output:
   - Full byte-by-byte disassembly of 0x09EF20 (until RET)
   - Full byte-by-byte disassembly of 0x09EF44 (until RET)
   - Calling context at 0x0A22DA (20 bytes before, 50 bytes after)
   - Comparison: shared subroutines, different behavior

## Technical Reference

- ROM file: `TI-84_Plus_CE/ROM.rom` (4,194,304 bytes, flat binary)
- eZ80 Z80-compatible with 24-bit addressing. Prefixes: 0xDD=IX, 0xFD=IY, 0xED=extended
- Key opcodes:
  - `CD xx xx xx` = CALL addr (3B LE)
  - `C3 xx xx xx` = JP addr
  - `C9` = RET
  - `FD CB ofs op` = IY+offset bit ops
  - `32 xx xx xx` = LD (addr),A
  - `3A xx xx xx` = LD A,(addr)
  - `18 xx` = JR offset (signed)
  - `28 xx` = JR Z,offset; `20 xx` = JR NZ,offset
  - `CB xx` = bit/rotate/shift operations
