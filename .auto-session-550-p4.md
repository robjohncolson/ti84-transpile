# Task: Decode 0x061986 — primary output path from counted string output (carry clear)

## Context
In the TI-84 Plus CE ROM (eZ80, `TI-84_Plus_CE/ROM.rom`, 4MB), session 549 decoded 0x088F6B as COUNTED STRING OUTPUT. Inside the DJNZ loop, when carry is CLEAR, it calls 0x061986 (primary path). When carry is SET, it calls 0x0A23E5 (alternate path). We need to decode what 0x061986 does.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase550-decode-061986.mjs` that:

1. Reads the ROM binary from `TI-84_Plus_CE/ROM.rom`
2. Dumps raw hex bytes starting at 0x061986 for ~256 bytes (0x100)
3. Disassembles the eZ80 instructions starting at 0x061986 until you hit a RET (0xC9) or unconditional JP, or ~80 instructions
4. Identifies what the function does: register usage, RAM reads/writes, subroutine calls, loops
5. Scans the entire ROM for all CALL/JP references to 0x061986 to count callers
6. If the function is short (< 30 bytes), also decode any subroutines it calls (one level deep)
7. Prints a structured summary

Use the same probe structure as `TI-84_Plus_CE/probe-phase549-decode-0A2A68.mjs` (read it for reference). The probe is a standalone Node.js ESM file that reads the ROM binary directly and prints analysis to stdout.

## eZ80 notes
- eZ80 is like Z80 but with 24-bit addresses. Default mode is ADL (24-bit).
- 3-byte addresses in LD instructions (e.g., LD HL,imm24 = 0x21 + 3 bytes LE)
- CALL nn = 0xCD + 3 bytes LE address
- JP nn = 0xC3 + 3 bytes LE address
- RET = 0xC9
- CP n = 0xFE + 1 byte
- JR cc,e = 0x20/28/30/38 + signed 8-bit offset
- DJNZ e = 0x10 + signed 8-bit offset
- BIT/SET/RES via 0xCB prefix
- IX prefix = 0xDD, IY prefix = 0xFD
- ED prefix for extended ops

## Caller scan
Search the full 4MB ROM (0x000000-0x3FFFFF) for bytes CD 86 19 06 (CALL 0x061986) and C3 86 19 06 (JP 0x061986). Print each caller address.
