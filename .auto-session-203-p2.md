# Auto-Session 203 P2: STAT Probe with List Data at 0xD01600

## Context
In the TI-84 Plus CE ROM transpilation project, the STAT 1-Var Stats path has a massive LDDR copy issue. Session 202 found the root cause: `SBC HL,DE` at block 0x09224B computes HL=0xD10000 (list data pointer) − DE=0xD0150B (OS list-count area) = 0xEAF5 (60,149 bytes). This is because our probes seed list data at 0xD10000, which is 60K away from the OS area.

On a real calculator, list data is allocated just above the OS area (~0xD015xx), making the LDDR distance small. **FIX**: Seed list data near 0xD01600 instead of 0xD10000.

## Task
Build a probe `TI-84_Plus_CE/probe-phase203-stat-near-seed.mjs` that:

1. **Seeds list L1 with 3 elements {1.0, 2.0, 3.0} at 0xD01600** (instead of 0xD10000):
   - Each real number is 9 bytes in BCD format: `[0x00, 0x80, 0x10, 0x00, ...]` = 1.0, etc.
   - List header: element count at list start
   - VAT entry pointing to 0xD01600

2. **Runs STAT 1-Var Stats entry** at 0x058BA9 (cxErrorEP from home context structure, which reaches STAT area 0x091Exx per session 194):
   - Trace up to 10000 steps
   - Log all unique blocks visited
   - Watch for LDDR at 0x092263 — record BC value at entry
   - Watch for successor 0x092265 — does it get reached now?
   - Log all writes to 0xD008E6 (STAT structure area)

3. **Comparison experiment**: Also run with data at 0xD10000 (old location) to compare BC values side-by-side.

4. **Output**: JSON with per-experiment block counts, BC at LDDR entry, successor reached (bool), RAM writes to STAT area.

## Key Addresses
- 0xD01600: NEW list data location (near OS area)
- 0xD10000: OLD list data location (60K away)
- 0xD0150B: OS list-count area (DE in SBC)
- 0x058BA9: STAT entry (cxErrorEP)
- 0x092263: LDDR block
- 0x092265: LDDR successor
- 0x09224B: SBC HL,DE block (computes distance)
- 0xD008E6: STAT structure area
- 0xD01A800: VAT entry area (or wherever existing probes put it)
