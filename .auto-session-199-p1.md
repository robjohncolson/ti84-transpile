# Auto-Session 199, Priority 1: Key Dispatch Extended Step Limit (2000-5000 steps)

## Context

Session 198 found the root cause of key dispatch crashes: at 0x08011F, `LD A,(0xD005F9); CP 0x5D` rejects digit tokens (OP1[1]=0x34 < 0x5D → carry → JError → RST 0). Two bypasses were proven:

- **Scenario A**: PushErrorHandler (0x07C88B) with target catches JError → execution continues past step 49
- **Scenario B**: Setting TOKEN_STAGING[1]=0x62 (≥0x5D) passes the CP 0x5D check

But NEITHER reached BufInsert (at 0x05851C, falls through from 0x058518 after 0x09927F returns carry-clear) within the 500-step limit used in session 198.

The post-check path goes: 0x082C58→0x082C3F→...→0x099283→0x0972C3. BufInsert is at 0x05851C.
