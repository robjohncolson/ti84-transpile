# Task: Decode 0x07CA48 — FP normalize phase 2

## Context
This is a TI-84 Plus CE ROM transpilation project. We're decoding eZ80 machine code from ROM.rom.

Session 529 identified 0x07CA48 as the second stage of the multi-phase normalization pipeline in the matrix/list FP handler (0x07D27B). It was described as: "clear guard D00601; exp-0x80; range check CP 0x0F". We need a full decode.

## What to do

1. Create a probe file `TI-84_Plus_CE/probe-phase530-decode-07CA48-fp-norm-phase2.mjs` that:
   - Reads ROM bytes from 0x07CA48 through 0x07CAB8 (112 bytes — generous window up to but not including 0x07CAB9)
   - Disassembles them instruction-by-instruction
   - Identifies all CALL/JP/JR targets
   - Finds the RET/JP that ends this function
   - Also dump bytes for any sub-functions called

2. Use the same probe template as `TI-84_Plus_CE/probe-phase529-decode-07CBB5-fp-normalize-core.mjs` (read it for reference).

3. Run the probe: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase530-decode-07CA48-fp-norm-phase2.mjs`

4. Report: all instructions, CALL targets, function boundary, and purpose analysis.

## Key reference
- ROM file: `TI-84_Plus_CE/ROM.rom`
- eZ80 little-endian, 24-bit addresses
- D00601 = OP2 guard byte
- D005F9 = OP1 exponent
- OP1 at D005F8 (9 bytes), OP2 at D00603 (9 bytes)
- Known neighbors: 0x07CAB9 is phase 1 (starts right after this), 0x07C8B7 is phase 3

## Constraints
- Do NOT modify any existing files except creating the new probe
- Do NOT modify cpu-runtime.js, peripherals.js, ez80-decoder.js, or browser-shell.html
- Run the probe ONLY via `node scripts/run-probe.mjs --max-time 180 <probe>` — NEVER bare `node <probe>`

## Success criterion
- Probe runs and prints disassembled instructions from 0x07CA48
- Function boundary (RET) found
- All CALL/JP targets listed
- Purpose of guard clearing and exponent range check documented
