# Task: Trace the Glyph Scaler Call Chain 0x053396→0x0533BD→0x053573

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80). The transpiler is at `scripts/transpile-ti84-rom.mjs`. The transpiled JS is at `TI-84_Plus_CE/ROM.transpiled.js` (regenerate with `node scripts/transpile-ti84-rom.mjs`).

Session 331 traced the scaling kernel dispatch and found the call chain: 0x053396→0x0522B2→0x0533BD→0x053540→0x05354C→0x053573. The scaler at 0x053573 loads 4 kernel pointers from a ROM table (indexed by scale level D005EC, range 0..3) into IX locals, and checks if scale<1 → skip to 0x0536A0.

## Your Task
Trace HOW a raw glyph bitmap enters the scaler pipeline. Specifically:

1. **Disassemble 0x053396** (the outermost entry point in the text renderer path). What are its arguments? Where does it get the glyph bitmap pointer? The two known font tables are at ROM 0x003D6E (main font) and 0x0A3AFA (alt/small font). How does one of these get selected and passed in?

2. **Trace 0x0533BD** — what does it do between receiving the glyph data and calling 0x053540/0x05354C/0x053573? Does it unpack the bitmap? Set up dimensions?

3. **What is the glyph bitmap format?** Fixed-size (e.g., 8×N)? Variable width? How many bytes per glyph? Is there a width table separate from the bitmap data?

4. **Where does the scaled output go?** After 0x053573 processes the glyph, where does the result land before the pixel writer (which ultimately writes to VRAM at 0xD40000)?

## Method
- Use `node -e` to read ROM bytes directly: `const rom = require('fs').readFileSync('TI-84_Plus_CE/ROM.rom'); console.log(rom.slice(addr, addr+len).toString('hex'));`
- For eZ80 disassembly, read raw bytes and decode manually. eZ80 is Z80-compatible with 24-bit address extensions. Key prefixes: 0xDD=IX, 0xFD=IY, 0x40=.SIS suffix, 0x49=.LIS, 0x52=.SIL, 0x5B=.LIL.
- Cross-reference with `ROM.transpiled.js` (gunzip first if needed: `node -e "const z=require('zlib'),f=require('fs'); f.writeFileSync('TI-84_Plus_CE/ROM.transpiled.js', z.gunzipSync(f.readFileSync('TI-84_Plus_CE/ROM.transpiled.js.gz')))"`)
- Grep the transpiled JS for block functions: `grep "function block_0x053396" TI-84_Plus_CE/ROM.transpiled.js`

## Deliverables
Create `TI-84_Plus_CE/probe-phase332-glyph-scaler.mjs` that:
- Boots the CPU runtime (use `probe-phase99d-home-verify.mjs` as reference for boot sequence)
- Traces calls through the scaler chain during home screen render
- Reports: entry arguments, glyph source address, bitmap format, output destination
- Print findings as structured output
