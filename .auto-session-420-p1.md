# Task: Trace 0x0094C0 and 0x0096CB (Non-USB Link Port Handlers)

## Context
You are working on a TI-84 Plus CE ROM reverse-engineering project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). The instruction decoder is at `TI-84_Plus_CE/ez80-decoder.js`.

Session 418 decoded 0x009B35, the USB/link masked-status service helper. When D177B7 != 0x55 (USB not initialized), it calls:
- 0x0094C0 when D14073 == 0
- 0x0096CB when D14073 != 0

These handle the TI Link protocol fallback path (non-USB serial link). We need to understand what they do.

## Deliverables

### 1. Probe file: `TI-84_Plus_CE/probe-phase420-trace-link-handlers.mjs`

Write a probe that:
1. Reads ROM.rom
2. Imports and uses `ez80-decoder.js` (use `await import('./ez80-decoder.js')` with `process.emitWarning = () => {}`)
3. Disassembles from 0x0094C0 forward until finding a RET or JP (estimate ~200 bytes per function)
4. Disassembles from 0x0096CB forward similarly
5. For each instruction, prints: address, raw hex bytes, decoded mnemonic
6. Annotates CALL targets, port I/O (IN/OUT), and RAM variable accesses (addresses in D00000-D3FFFF range)
7. Identifies the boundary of each function

Use the same probe style as `TI-84_Plus_CE/probe-phase419-trace-014D48.mjs` (read it for reference).

The decoder function signature: `decodeInstruction(romBuffer, pc, 'adl')` returns `{tag, length, nextPc, ...fields}`.

### 2. Report file: `TI-84_Plus_CE/phase420-link-handlers-report.md`

After running the probe, write a report with:
- Function boundaries (start/end addresses, byte count)
- What ports each function reads/writes
- What RAM variables (D00000-D3FFFF) each accesses
- What CALL targets each invokes
- Overall purpose assessment (what is the TI Link protocol fallback doing?)

## Constraints
