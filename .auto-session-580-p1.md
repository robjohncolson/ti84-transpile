# Task: Decode 0x0A1A36 — The REAL Key Input Handler

## Context
This is the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80).

Session 579 decoded 0x0A27DD (33B key input setup) and found it's NOT _GetCSC — it's a wrapper that tail-calls `JP 0x0A1A36` unconditionally after init guards. **0x0A1A36 is where the event loop's key scan result actually originates.** The event loop at 0x08C331 calls 0x0A27DD, which tail-jumps to 0x0A1A36, and the return value in register A is the key code (0 = no key).

_GetCSC is at 0x03FA09. The key matrix is memory-mapped via port reads. The scan code table is at 0x09F79B.

## Deliverable
Create `TI-84_Plus_CE/probe-phase580-decode-0A1A36.mjs` that:

1. Reads ROM.rom from disk (`fs.readFileSync('./TI-84_Plus_CE/ROM.rom')` — returns a Buffer)
2. Disassembles starting at 0x0A1A36 for up to 500 bytes
3. Uses the decoder: `import { decodeInstruction } from './ez80-decoder.js';` — call as `decodeInstruction(romBuffer, offset, 'adl')` which returns `{ mnem, op_str, length }` (NOT `.mnemonic`/`.operands` — those don't exist)
4. Identifies all CALL targets, JP targets, RAM references (0xD0xxxx), IY+offset operations, port I/O
5. Counts callers of 0x0A1A36 across the full ROM (scan for `CALL 0x0A1A36` = bytes CD 36 1A 0A, and `JP 0x0A1A36` = bytes C3 36 1A 0A)
6. Checks relationship to _GetCSC (0x03FA09) — does 0x0A1A36 call it? Or does it read the keyboard matrix directly?
7. Prints structured findings

## Important constraints
- The decoder API is `decodeInstruction(buffer, offset, 'adl')` → `{ mnem, op_str, length }`. The third param MUST be the string `'adl'`, not boolean `true`.
- ROM is a Node.js Buffer, NOT a DataView/ArrayBuffer. Read bytes with `rom[offset]` or `rom.readUInt8(offset)`.
- To find 3-byte LE addresses in ROM: `rom[i] | (rom[i+1] << 8) | (rom[i+2] << 16)`.
- For hex formatting: `'0x' + val.toString(16).toUpperCase().padStart(6, '0')`.
- File must be an ES module (`.mjs` extension, use `import` not `require`).
- Do NOT modify any existing files. Only create the new probe file.

## Success criterion
Running `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase580-decode-0A1A36.mjs` exits 0 and prints disassembly + caller count + relationship to _GetCSC.
