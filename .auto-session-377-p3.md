# Task: Fix Natural Key Scan Probe

## Context

This is the TI-84 Plus CE ROM transpilation project. Session 376 tried to write a "natural key scan" probe (`probe-phase376-natural-key-test.mjs`) but it has a boot setup bug — both scenarios halted at 0x0019B5 after only 7 steps with 0 unique blocks visited. The event loop setup was incomplete (missing CPU state restoration, peripheral rebuild, or step budget too small).

## What to Do

Write a NEW probe `TI-84_Plus_CE/probe-phase377-natural-key-scan.mjs` that tests whether the OS keyboard scan routine at 0x003C63 can detect a key press through the emulated keyboard matrix (ports 0xA000-0xA014) WITHOUT direct RAM injection.

The probe must use the EXACT boot pattern from `TI-84_Plus_CE/probe-phase375-both-seeds-test.mjs`. Copy its structure precisely:
- 3-phase boot (Phase 1 at 0x000000 z80, Phase 2 at 0x08C331, Phase 3 at 0x0802B2)
- CPU snapshot after boot
- `prepareEventLoop` with full CPU restore and LCD MMIO restore
- Peripheral rebuild for each scenario
- Event loop entry at 0x003A73

### Scenarios

Run THREE scenarios, each with `{ timerInterrupt: false, gpioValue: 0xEE }`:

**Scenario A — Direct RAM injection (control)**:
- After boot, seed flash at 0x020100 = [0x5A, 0xA5, 0x00]
- Seed system flag at 0xD177BA = 0x00
- Inject key via RAM: mem[0xD00587] = 0x09 (ENTER), mem[0xD00080] |= 0x08
- Run event loop with 500K steps
- Expected: dispatch at 0x003A7D reached

**Scenario B — Keyboard matrix only (natural scan)**:
- After boot, seed flash + system flag (same as A)
- Do NOT inject via RAM. Instead, set the keyboard matrix so ENTER is pressed:
  ```javascript
  const peripherals = createPeripheralBus({ timerInterrupt: false, gpioValue: 0xEE });
  peripherals.setKeyPressed(mem, 0x09); // ENTER scan code
  ```
  The `setKeyPressed` function in peripherals.js writes the scan code to 0xD00587 and sets bit 3 of 0xD00080 — check what it actually does by reading the source.
- Run event loop with 500K steps
- Track: does 0x003C63 (keyboard scan) get called? Does it read keyboard ports? Does it write to 0xD00587? Does dispatch at 0x003A7D get reached?

**Scenario C — No key (baseline)**:
- After boot, seed flash + system flag (same as A)
- No key injection, no keyboard matrix set
- Run event loop with 200K steps
- Expected: no dispatch, stuck in scan loop

### For each scenario, track and report:
- Total steps, termination reason, last PC
- Whether 0x003A7D (dispatch), 0x003C63 (scan routine), 0x003D5A (_GetCSC), 0x003D75 (key-available path) were reached
- How many times 0x003C63 was called
- Total unique blocks visited
- Key RAM values after run: mem[0xD00587], mem[0xD00080]
