# Task: Investigate why only first key renders VRAM

## Context
In the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, session 451 discovered that when injecting keys ["1", "+", "1", "ENTER"] through the OS event loop, only the FIRST key ("1", scan=0x12) produces VRAM changes (6,078 bytes from 0x00→0xFF in rows 119-128 at column 14). The subsequent three keys are consumed by the CPU (they process 500k steps each) but produce ZERO VRAM changes.

## Hypothesis
Some display-dirty or render-needed flag is consumed during the first key's render pass and never re-armed between subsequent keys. Candidates:
- **D177B7** (display refresh mode) — set to 0x55 before first key. After rendering, it may be changed to 0xAA (clean).
- **D008A8** (OS flag controlling D14091 key-processing enable)
- **D00595/D00596** (curRow/curCol cursor position)
- **D14091** (key-processing enable gate)
- Other flags in the D177xx range

The boot sequence is:
1. Create executor with `createPeripheralBus({ timerInterrupt: false })`

5. Run KERNEL_INIT_ENTRY for 2M steps
6. Run POST_INIT_ENTRY for 2M steps
7. Run each STAGE_ENTRIES[i] for 2M steps
8. Pre-copy ROM routine: `mem.copyWithin(0xD18C22, 0x000EBB, 0x000EBB + 90)`
9. Set D14091=1, D177B7=0x55
10. Then for each key: inject and run EVENT_LOOP_ENTRY
