# Auto-Session 349 — P3: Boot With Timer Enabled (100k Steps)

## Context
After session 348's port 0x3D fix, boot reaches 35 blocks but loops indefinitely with `timerInterrupt: false`. The timer IRQ fires every 200 ticks by default and goes through vector 0x1713. During early boot phases, the timer was disabled because it would hijack init. But now that init has progressed past the NMI handler, the timer interrupt might actually help break the polling loop (the real hardware uses timer ticks to advance initialization states).

## Task
Create a probe `TI-84_Plus_CE/probe-phase349-boot-timer.mjs` that:

1. Boots from PC=0x000000 with `timerInterrupt: true` (default timer at 200-tick interval)
2. Runs for 100,000 steps (or until `missing_block` termination, whichever comes first)
3. Logs:
   - Total unique blocks visited
   - Whether any NEW blocks are reached compared to the 35 from session 348 (the 35 are: look at probe-phase348-boot-nmi-wake.mjs output or just compare counts)
   - The first 5 missing_block addresses if any occur
   - Whether execution ever reaches addresses beyond 0x005998 (new territory)
   - How many timer interrupts fired (count entries to block 0x001713 or whatever the timer vector is)
4. Also runs a SECOND test: boot with timer interval=1000 (slower timer, less interrupt pressure) for 100k steps, same logging

## Key Files
- `TI-84_Plus_CE/cpu-runtime.js` — CPU runtime
- `TI-84_Plus_CE/peripherals.js` — `createPeripheralBus({ timerInterrupt: true })` enables timer; check if interval is configurable
- `TI-84_Plus_CE/probe-phase348-boot-nmi-wake.mjs` — reference: boots with timerInterrupt:false, gets 35 blocks

## Setup Pattern
```javascript
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';

// Test 1: Default timer (200 ticks)
const peri1 = createPeripheralBus({ timerInterrupt: true });
const cpu1 = createCPU(peri1);
// load ROM, run 100k steps...

// Test 2: Slow timer (1000 ticks) - check if interval param exists
const peri2 = createPeripheralBus({ timerInterrupt: true, timerInterval: 1000 });
const cpu2 = createCPU(peri2);
// load ROM, run 100k steps...
```

Check `peripherals.js` for the timer interval parameter name — it might be `timerInterval` or `interval` or something else. If there's no way to configure the interval, just run with the default for both tests but note this in the output.
