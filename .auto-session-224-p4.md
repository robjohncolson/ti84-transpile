# Task: Trace how the OS produces magic A values before calling ConvKeyToTok

## Context
In the TI-84 Plus CE ROM transpilation project, the key classifier at 0x05C52C uses "magic A values" (0xFA, 0xFB, 0xFC, 0xFE) to select secondary token tables (Fn, 2nd, Alpha, AlphaLock). Session 223 found 82 LD A,0xF? sites in ROM but NO direct LD A,0xF?→CALL pattern — magic values are set indirectly via memory loads or register copies.

Key facts:
- ConvKeyToTok at 0x05E630 calls 0x05C52C (key classifier) which reads A for table selection
- 9 CALL ConvKeyToTok sites exist in ROM
- 11 CALL KeyClassifier (0x05C52C) sites exist
- Critical cluster of magic A producers at 0x05C5EE-0x05C60A (inside reverse lookup at 0x05C5B3)
- The real key code is stored in D0058E (set by sub-function 0x02F961 in the ISR key pipeline)

We need to trace the path from a key press through modifier detection (2nd key, Alpha key) to the point where A gets set to a magic value before ConvKeyToTok is called.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase224-magic-a-producer-trace.mjs` that:

1. **Map all ConvKeyToTok call sites with context**: Read ROM.rom (fs.readFileSync). For each of the 9 CALL 0x05E630 sites found in session 223 (search for bytes CD 30 E6 05 in ROM 0x000000-0x0BFFFF), disassemble 50 bytes BEFORE each call site. Look specifically for:
   - How A is set (LD A,imm / LD A,(addr) / LD A,reg / POP AF)
   - Any BIT/SET/RES tests on IY flags that branch to different LD A paths
   - Memory addresses that might hold the modifier state (D177B9, D0058E, IY offsets)

2. **Map all 0x05C52C (key classifier) call sites with context**: Same approach for the 11 CALL 0x05C52C sites (search for CD 2C C5 05). Disassemble 50 bytes before each to find A-loading patterns.

3. **Identify the modifier state variables**: The OS must track whether 2nd, Alpha, or Fn modifiers are active. Search ROM for:
   - Known modifier-related IY offsets (check what IY+42/0xD000AA bit 1 does — found in session 221)
   - Memory writes after 2nd key (scan code 0x65) or Alpha key (scan code 0x57) are pressed
   - Any "mode" byte that gets set to 0xFA/0xFB/0xFC/0xFE

4. **Dynamic trace**: Boot runtime with timerInterrupt:false. Pick one ConvKeyToTok call site (preferably the one in the main cxMain path near 0x05E630 or 0x058xxx). Set up the context as if 2nd key was pressed (try setting IY+42 bit 1, or D177B9 to different values), then run with a digit key code (0x8F). Trace 200 steps. See if A becomes 0xFC (2nd table selector) before the 0x05C52C call.
