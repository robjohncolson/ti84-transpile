# Task: Disassemble 0x001EEB-0x001F30 (PLL Escape Path)

## Context
TI-84 Plus CE ROM transpilation project. OS ROM (eZ80) lifted to JS, executed in Node.js. Boot reaches 318 blocks.

In session 357, PLL bit 3 fix (port 0x28 returns 0x0C) let boot escape the HALT loop. The escape path calls 0x001EEB when BIT 3,A passes at block 0x000DED. We need to understand what 0x001EEB does - it appears to be timer/PLL configuration.

Call chain: 0x000DED (BIT 3,A passes) -> CALL 0x001EEB -> ... -> eventually reaches 0x001D37 -> 0x000D82 -> re-HALT.

## Deliverables

Create `TI-84_Plus_CE/probe-phase358-escape-path-disasm.mjs` that:

1. Disassembles 0x001EEB through 0x001F30 (70 bytes) from raw ROM. eZ80 ADL mode (3-byte addresses). Show address, raw bytes, mnemonic for each instruction.

2. Identifies all port I/O in this range (IN0/OUT0/IN/OUT instructions).

3. Identifies all CALL/JP/JR targets and branch conditions.

4. Dynamically traces which blocks in range 0x001E00-0x001F30 execute during a boot run (~20000 steps). Log order of execution and register state.

## How to write the probe

Read these files FIRST:
- `TI-84_Plus_CE/probe-phase357-disasm-nmi-branch.mjs` (disassembly probe template)
- `TI-84_Plus_CE/cpu-runtime.js` (createCPU)
- `TI-84_Plus_CE/peripherals.js` (createPeripheralBus)
- `TI-84_Plus_CE/ez80-decoder.js` (instruction decoder - optional, can decode manually)

Standard pattern:
```javascript
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
import fs from 'fs';
const rom = fs.readFileSync('./TI-84_Plus_CE/ROM.rom');
```

For eZ80 ADL-mode manual decode:
- ED xx pp = IN0/OUT0 (port in 3rd byte)
- CD aa aa aa = CALL addr (3 bytes LE)
- C3 aa aa aa = JP addr
- 18 dd = JR offset (signed)
- CB xx = bit operations
- DD/FD prefixes = IX/IY
