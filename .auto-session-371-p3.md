# Task: Disassemble RST 38h Dispatch Chain (0x000038→0x0006F3→0x000704→0x000710)

## Context
Session 370 confirmed the timer fires through RST 38h at 0x000038, NOT through ISR vector 0x000080. The chain 0x000038→0x0006F3→0x000704→0x000710→0x001713 needs full disassembly to understand the IM 1 interrupt dispatch mechanism. 0x000038 was visited 995 times in 200K steps with timerInterrupt:true.

## Deliverable
Create `TI-84_Plus_CE/probe-phase371-rst38-disasm.mjs` that:

1. **Boot phases 1-3** (standard):
   - Phase 1: `runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
   - Phase 2: `runFrom(0x08C331, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 })`
   - Phase 3: `runFrom(0x0802B2, 'adl', { maxSteps: 100, maxLoopIterations: 32 })`
   - Standard stack resets between phases

2. **Static disassembly of the RST 38h chain** — read ROM bytes directly and decode each block:
   - **0x000038** (RST 38h entry): Session 354 noted it does `EX AF,AF'; EXX; PUSH IX; PUSH IY; LD IY,0xD00080; JP 0x0006F3`. Verify by reading ROM bytes at 0x000038-0x00004F.
   - **0x0006F3**: This is the boot init main dispatch. Decode 0x0006F3-0x000730 (at least 60 bytes). It reads port 0x06 (BIT 2,A check). What paths does it take?
   - **0x000704**: Decode 0x000704-0x000720.
   - **0x000710**: Decode 0x000710-0x000730.
   - **0x000719**: Part of the timer path. Decode 0x000719-0x000730.
   - **0x001713**: The idle/dispatch check. Decode 0x001713-0x001730.
   - **0x001717**: Decode 0x001717-0x001730.

   For each address range, read the ROM bytes and use the eZ80 instruction decoder to produce assembly. Print each instruction's address, hex bytes, and mnemonic.

3. **Dynamic trace with timer** — Run the event loop with `timerInterrupt:true` for 50K steps and record:
   - How many times each block in the RST 38h chain is visited
   - The sequence of the first 5 RST 38h dispatch events (which blocks are hit in order)
   - What value is in A register when 0x0006F3 is entered via RST 38h vs via cold boot

4. **Report**: Print the full disassembly of each block, dynamic visit counts, and the dispatch sequence analysis.

## How to decode instructions
Import the decoder from `TI-84_Plus_CE/ez80-decoder.js`. It exports `decodeInstruction(mem, pc, adlMode)` which returns `{ mnemonic, operands, bytes, length }` or similar. Read the ROM file and use the decoder to step through instructions at each address.

If the decoder API is different, read the first 30 lines of `ez80-decoder.js` to find the export names and calling convention.

## Key setup for timer event loop
```javascript
const peripherals = createPeripheralBus({ pllDelay: 2, timerInterrupt: true });
const executor = createExecutor(BLOCKS, mem, { peripherals });
// After boot phases:
cpu.halted = false;
cpu.iff1 = 1;  // MUST be 1 for timer interrupt to fire
cpu.iff2 = 1;
cpu.f = 0x40;
cpu._ix = 0xD1A860;
cpu._iy = 0xD00080;
cpu.sp = 0xD1A87B - 12;  // or STACK_RESET_TOP - 12
// Run event loop:
executor.runFrom(0x003A73, 'adl', { maxSteps: 50000, maxLoopIterations: 10 });
```
