# Auto-Session 370 — P1: Simulate Keypress in Event Loop

## Context
The TI-84 CE OS event loop at 0x003A73 is a pure _GetCSC scan loop. It scans the keyboard matrix at port 0xA000 (MMIO mirrored at 0xE00810). When no key is pressed (all keyMatrix groups = 0xFF), the loop runs for ~100 iterations then calls 0x001713 which returns NZ → 0x001933 → HALT (idle/sleep).

When _GetCSC finds a key (OR A returns NZ at 0x003A78), execution takes JR NZ at 0x003A79 which exits the scan loop with a scan code. We need to trace what happens AFTER a keypress is detected.

## Keyboard Matrix
- `peripherals.js` `createPeripheralBus()` returns a bus with `keyboardState.keyMatrix` (Uint8Array(8), all 0xFF = no keys pressed).
- To press ENTER: `keyMatrix[1] &= ~(1 << 0)` (keyMatrix[1] bit 0 = ENTER, scan code 0x10).
- The bus is accessed via `createPeripheralBus()` and the returned object has a `.keyboardState` property.

## Task
Create `TI-84_Plus_CE/probe-phase370-keypress-event-loop.mjs` that:

1. Does the standard 3-phase boot (same as probe-phase369-post-scan.mjs):
   - Phase 1: Z80 cold boot from 0x000000, maxSteps=20000, maxLoopIterations=32
   - Reset: cpu.halted=false, cpu.iff1=0, cpu.iff2=0, cpu.sp=STACK_RESET_TOP-3 (0xD1A87E-3=0xD1A87B), mem.fill(0xFF, cpu.sp, cpu.sp+3)
   - Phase 2: ADL from 0x08C331, maxSteps=100000, maxLoopIterations=10000
   - Reset: cpu.mbase=0xD0, cpu._iy=0xD00080, cpu._hl=0, cpu.halted=false, cpu.iff1=0, cpu.iff2=0, cpu.sp=STACK_RESET_TOP-3, mem.fill(0xFF, cpu.sp, cpu.sp+3)
   - Phase 3: ADL from 0x0802B2, maxSteps=100, maxLoopIterations=32

2. Then Phase 4: Enter event loop at 0x003A73 in ADL mode WITH a keypress:
   - Set cpu state: cpu.halted=false, cpu.iff1=0, cpu.iff2=0, cpu.f=0x40, cpu._ix=0xD1A860, cpu._iy=0xD00080, cpu.sp=STACK_RESET_TOP-12 (0xD1A872), mem.fill(0xFF, cpu.sp, cpu.sp+12)
   - BEFORE running: press ENTER key by setting `peripherals.keyboardState.keyMatrix[1] &= ~(1 << 0)`
   - Run: executor.runFrom(EVENT_LOOP_ENTRY, 'adl', { maxSteps: 500000, maxLoopIterations: 10 })

3. Then Phase 5: Same but press '5' key instead:
   - Reset cpu state same as Phase 4
   - Press '5': `peripherals.keyboardState.keyMatrix[2] &= ~(1 << 2)` (keyMatrix[2] bit 2 = 5, scan code 0x22)
   - Reset all other keys to 0xFF first
   - Run same params

4. Report for each phase:
   - Total steps, termination reason, lastPc
   - Unique blocks discovered
   - NEW blocks not seen in cold boot phases (1-3)
   - The top 20 hottest blocks
   - Whether 0x001713/0x001933/0x001853/0x000721 were visited
   - Whether 0x003A79 (the JR NZ after key detect) was visited and how many times
