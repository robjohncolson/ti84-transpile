# Auto-Session 214 P2 — 0x080D08 display-result loop: determine correct entry conditions

## Context

In the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, the block at **0x080D08** is the "display result" loop. Session 209 decoded it:

```
0x080D08: block entry
0x080D09: LD HL,0xD0060E     ; format buffer address
0x080D0D: LD A,(HL)          ; load char
0x080D0E: LD E,A             ; token = char
0x080D0F: OR A               ; test null
0x080D10: JR Z,exit          ; null terminator → exit
0x080D12: PUSH HL            ; save pointer
0x080D13: CALL 0x05E2A0      ; BufInsert(DE)
0x080D17: POP HL             ; restore pointer
0x080D18: INC HL             ; next char
0x080D19: JR NZ,0x080D0D     ; loop (if BufInsert returned NZ)
```

Session 213 tested this with format buffer seeded at 0xD0060E with "42.5\0" and edit pointers initialized, but BufInsert only fired 1× and the loop didn't iterate. The edit buffer stayed zeroed.

**Hypothesis**: The `LD HL,0xD0060E` instruction at 0x080D09 loads the format buffer address INTO HL. But if the block at 0x080D08 is entered mid-function (not at 0x080D09), HL might already need to be set. OR the JR NZ at 0x080D19 fails because BufInsert returns Z (zero flag set = error/no-insert).

## Task

Create a probe script `TI-84_Plus_CE/probe-phase214-display-result-loop.mjs` that runs several experiments:

### Experiment A: Verify instruction-level behavior
Use the transpiled runtime to execute block 0x080D08 with:
- Format buffer at 0xD0060E seeded with "42.5\0" (bytes: 0x34, 0x32, 0x2E, 0x35, 0x00)
- Edit buffer at 0xD00A00 zeroed

- Trace up to 500 steps
- Log EVERY block entry with: PC, A, HL, DE, flags (Z/NZ/C/NC), and first 8 bytes of edit buffer at 0xD00A00

Key questions:
1. Does BufInsert return with Z or NZ flag? (Z would stop the loop)
2. Does HL increment correctly after POP?
3. What's in the edit buffer after each BufInsert call?

### Experiment B: Pre-set HL to 0xD0060E in registers before entry
Same as A, but explicitly set cpu.HL = 0xD0060E before executing. This tests whether the block reads HL from registers vs. the LD instruction.

### Experiment C: Pre-set D=0x00 (high byte of DE for BufInsert)
BufInsert takes DE where D=0x00 and E=token. Session 213 may not have cleared D. Set D=0x00 explicitly.

### Experiment D: Longer format string
