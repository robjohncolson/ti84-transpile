# Task: Decode 0x0025E8 — Unidentified Low-ROM Target

## Context
In the TI-84 Plus CE ROM (eZ80, file `TI-84_Plus_CE/ROM.rom`), the low-ROM region 0x000080-0x000654 contains 374 contiguous JP thunks forming the TI OS system call dispatch table. Each thunk is a 4-byte `JP addr` instruction providing a stable ABI.

Wrapper slot at 0x000204 jumps to 0x0025E8. This is the ONLY low-ROM wrapper target not yet matched to a known ZDS II C runtime function name. All other targets in the table have been identified (e.g., 0x0021C2 = null_check, 0x002623 = _seqcase, 0x00276B = _stoiu, 0x002330 = right-shift, 0x00230B = left-shift, 0x00285F = _bzero, 0x002553 = _lshru, 0x0027E8 = memcpy, etc.).

## Deliverables
1. Create `TI-84_Plus_CE/probe-phase434-decode-0025E8.mjs` — a Node.js probe that:
   - Loads the ROM from `TI-84_Plus_CE/ROM.rom`
   - Disassembles starting at 0x0025E8 (eZ80 ADL mode)
   - Traces all instructions until RET
   - Identifies: function size, instruction count, register usage pattern, CALL targets
   - Scans ROM for all CALL 0x0025E8 and CALL 0x000204 references (callers)
   - Outputs the disassembly, caller list, and a hypothesis about what C runtime function this is

2. Create `TI-84_Plus_CE/phase434-0025E8-report.md` — analysis report covering:
   - Full disassembly listing
   - Function size and structure
   - All callers (both direct 0x0025E8 and via wrapper 0x000204)
   - Register usage pattern (which registers are inputs/outputs)
   - Comparison with known ZDS II C runtime functions
   - Best-guess identification (e.g., _memcmp, _strcmp, _mulu, _divu, _sext, etc.)

## Reference

  - 0x00218A / 0x002197 = __frameset (stack frame setup)
