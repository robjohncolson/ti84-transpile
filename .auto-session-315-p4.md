# Task: Decode 32 Frame-Based _indcall Sites

## Context
You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`.

The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary, little-endian).

Session 314 mapped the _indcall callback infrastructure. There are two trampolines:
- `_indcall` at 0x00015C: does `CALL (IY)` — 22 callers
- `JP (IY)` at 0x002288: does `JP (IY)` — 22 callers
- Total: 44 dispatch sites

Of these, 12 are "slot-based" (they load IY from a fixed RAM address via `LD IY,(fixed_addr)`). The other 32 are "frame-based" — they load IY from an IX-relative offset, meaning IY comes from a C function pointer passed on the stack frame.

The probe from session 314 is at `TI-84_Plus_CE/probe-phase314-indcall.mjs` — run it first to see the output and understand the data.

## Your Task
1. Run `node TI-84_Plus_CE/probe-phase314-indcall.mjs` to get the list of all 44 dispatch sites.
2. Create a NEW probe `TI-84_Plus_CE/probe-phase315-frame-indcall.mjs` that:
   a. Identifies the 32 frame-based dispatch sites (those that use `LD IY,(IX+offset)` before calling 0x00015C or jumping to 0x002288)
   b. For each frame-based site, extracts:
      - The IX offset used (tells us which stack frame parameter holds the function pointer)
      - The ROM address of the containing function (find the nearest function prologue: PUSH IX / LD IX,SP = DD E5 DD 21 or DD E5 DD F5)
      - What the containing function does (first ~20 bytes of disassembly)
   c. Groups the 32 sites by containing function (some functions may have multiple dispatch sites)
   d. Groups by IX offset (are they all using the same parameter slot, or different ones?)
   e. Checks if the containing functions cluster in a specific ROM region (subsystem identification)
   f. Prints: per-site detail, grouping by function, grouping by IX offset, ROM region clustering

3. Run the probe and capture output.
4. Create a report `TI-84_Plus_CE/phase315-frame-indcall-report.md`.

## Reference: eZ80 instruction encoding
- `LD IY,(IX+d)` in eZ80 ADL mode: DD FD 27 dd (where dd = signed displacement byte). The IY prefix is FD but within an IX-prefixed instruction context, see the eZ80 manual for compound prefix encoding. Actually, the simpler pattern to search for: look for `FD 2A` (LD IY,(addr)) or `FD 27` / `FD 46` patterns near the CALL 0x00015C or JP 0x002288 sites.
- Better approach: for each of the 44 sites found by probe-phase314-indcall.mjs, look at the ~10 bytes BEFORE the CALL/JP instruction to find how IY was loaded. If it's from a fixed address, it's slot-based. If it involves IX+offset, it's frame-based.
