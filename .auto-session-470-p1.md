# Auto-Session 470 — Priority 1: Trace 0x03FA09 Key Processor Internal Behavior

## Context

This is the TI-84 Plus CE ROM transpilation project. The ROM (eZ80 machine code) has been lifted to JavaScript. We've confirmed that the key wait loop at 0x030052 calls 0x03FA09 (the key processor) when D00080 bit 3 is set. Session 469 proved 0x03FA09 is reached at step 42 when entering at 0x030052 with proper setup.

Now we need to understand what 0x03FA09 DOES internally.

## Task

Create a probe script `TI-84_Plus_CE/probe-phase470-keyproc-trace.mjs` that:

1. Boots the OS using the standard 3-stage boot (copy from `probe-phase469-keywait-v2.mjs` for the boot setup pattern)
2. After boot, sets up key injection:
   - `mem[0xD00587] = 0x09` (scan code for ENTER key)
   - Sets D00080 bit 3: `mem[0xD00080] |= 0x08`
   - Sets `cpu.iff1 = 1` and enables `diHaltBypass: true`
3. Enters execution at 0x030052 (the key wait loop entry)
4. Instruments execution to log EVERY `CALL` instruction executed after 0x03FA09 is first reached, including:
   - The PC of the CALL instruction
   - The target address being called
   - The current value of registers A, B, C, D, E, H, L, IX, IY at each CALL
5. Also logs every memory WRITE to addresses D141B5, D00587, D00080, and the VRAM range 0xD40000-0xD65800
6. Runs for up to 500 steps after 0x03FA09 is first reached (or until RET from 0x03FA09)
7. Reports:
   - All CALLs made from within 0x03FA09 (with targets and register state)
   - Whether D141B5 was written (and what value)
   - Whether D00587 was consumed (cleared)
   - Whether any VRAM writes occurred
   - What value A has when 0x03FA09 returns (the return value determines dispatch: A=1 or A=4 → re-enter key setup, else → JP 0x02FDD8)
   - The final PC after 0x03FA09 returns

## Key Architecture

- The transpiled ROM is a collection of `blocks` keyed by address. Each block is a function that takes `(cpu, mem, peripheralBus)`.
- `executeBlock(cpu, mem, blocks, peripheralBus, startPC)` runs one block and returns `{pc, term, steps}`.
- To run multiple blocks in sequence, loop calling `executeBlock` with the returned `pc`.
- The ROM is loaded via `loadROM(mem, romPath)` where romPath is the `.rom` file path.
- Boot sequence: execute blocks starting at PC=0x000000 for ~30,000 steps to complete OS init.
