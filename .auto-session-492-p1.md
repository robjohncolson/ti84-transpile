# Task: Decode 0x06029D — Cursor Draw Candidate

## Context
This is the TI-84 Plus CE ROM transpilation project. We've been investigating the text cursor blink mechanism. Session 491 found that 0x06029D writes 182 black pixels in a cursor-sized region (rows 86-104, cols 28-43, roughly 16 rows × 16 cols). This makes it the top candidate for the cursor DRAW function. The cursor ERASE function is 0x061000 (clear-to-screen-bottom, writes 0xFF).

## What to do

Create a probe `TI-84_Plus_CE/probe-phase492-decode-06029D.mjs` that:

### Part 1: Static disassembly of 0x06029D
Read the ROM bytes at 0x06029D and disassemble instruction-by-instruction (like probe-phase491-decode-061000.mjs does for 0x061000). Print each instruction with address, raw bytes, and mnemonic. Continue until you hit a RET or reach 100 bytes. Look for:
- References to D00595 (cursor row) and D00596 (cursor col)
- References to D0059C (VRAM pointer)
- References to D008D2/D008D5 (LCD window registers)
- CALL/JP instructions (note targets)
- LDIR/LDDR (block copy — VRAM fill)
- Any immediate values that look like glyph data or VRAM addresses (0xD40000 range)

Note: eZ80 mode prefixes are 0x40 (SIS), 0x49 (LIS), 0x52 (SIL), 0x5B (LIL). When decoding, check if a byte is a mode prefix before treating it as an opcode.

### Part 2: Find all callers of 0x06029D
Scan the entire ROM (0x000000-0x3FFFFF) for CALL 0x06029D (bytes: CD 9D 02 06) and JP 0x06029D (bytes: C3 9D 02 06). Also check with mode prefixes (e.g., 0x49 CD 9D 02 06). Report all call sites.

### Part 3: Dynamic test with multiple cursor positions
Set up the CPU with boot (120,000 steps with timer IRQ disabled), then test 0x06029D with 3 different cursor positions:
- Test A: D00595=0 (row 0), D00596=0 (col 0)
- Test B: D00595=5 (row 5), D00596=13 (col 13)
- Test C: D00595=9 (row 9), D00596=25 (col 25)

For each test:
1. Snapshot VRAM (0xD40000, size 320*240=76800 bytes) before the call
2. Set PC=0x06029D, SP=0xD1A87E, push return sentinel 0x064910
3. Run up to 50,000 steps or until PC reaches the return sentinel
4. Snapshot VRAM after
5. Compare: count changed bytes, find bounding box of changes (min/max row, min/max col where row=byteOffset/320, col=byteOffset%320)
6. Report whether the pixel region MOVES with cursor position

## API

```js
import fs from 'node:fs';
import { execFileSync } from 'node:child_process';
import { fileURLToPath } from 'node:url';
import zlib from 'node:zlib';

function ensureTranspiledRom() {
  const transpiled = new URL('./ROM.transpiled.js', import.meta.url);
  const gz = new URL('./ROM.transpiled.js.gz', import.meta.url);
  if (fs.existsSync(transpiled) || !fs.existsSync(gz)) return;
  console.log('ROM.transpiled.js missing; expanding ROM.transpiled.js.gz');
  try {
    execFileSync('gzip', ['-dk', fileURLToPath(gz)], {
      cwd: fileURLToPath(new URL('.', import.meta.url)),
      stdio: 'inherit',
    });
  } catch (error) {
    console.log(`gzip failed (${error.message}); falling back to node:zlib`);
    fs.writeFileSync(transpiled, zlib.gunzipSync(fs.readFileSync(gz)));
  }
}

ensureTranspiledRom();

const { createCPU } = await import('./cpu-runtime.js');
const { createPeripheralBus } = await import('./peripherals.js');
```

- `createCPU()` returns a cpu object. `cpu.mem` is the flat memory array. `cpu.step()` executes one instruction. `cpu.pc`, `cpu.sp`, `cpu.a`, etc. are register accessors.
- `createPeripheralBus({ timerInterrupt: false })` — MUST disable timer IRQ for probes.
- The peripheral bus is installed automatically when you call `createCPU()` — but you need to create the bus first and pass it: `const bus = createPeripheralBus({ timerInterrupt: false }); const cpu = createCPU(bus);`
- Actually, check the existing probe (probe-phase491-decode-061000.mjs) for the exact API pattern. The CPU creation may be: `const cpu = createCPU(); const bus = createPeripheralBus({ timerInterrupt: false }); bus.install(cpu);` — look at the actual file to be sure.
- Memory reads: `cpu.mem[addr]` for 8-bit. For 24-bit LE: `cpu.mem[addr] | (cpu.mem[addr+1] << 8) | (cpu.mem[addr+2] << 16)`.
- Memory writes: `cpu.mem[addr] = value & 0xFF`.
- ROM is write-protected (addr < 0x400000), so only RAM (0xD00000+) is writable.
- Push 24-bit return address: `cpu.sp -= 3; cpu.mem[cpu.sp] = addr & 0xFF; cpu.mem[cpu.sp+1] = (addr >> 8) & 0xFF; cpu.mem[cpu.sp+2] = (addr >> 16) & 0xFF;`
