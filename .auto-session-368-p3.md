# Task: Disassemble 0x003A77-0x003A7B (Event Loop No-Key Response)

## Context
In the TI-84 Plus CE ROM transpilation project, session 367's 50K boot probe discovered that blocks 0x003A77 and 0x003A7B appear at step 27,301 when _GetCSC returns "no key pressed." These represent the event loop's response to a no-key condition. We need to understand what the OS does between scan cycles.

## Deliverable
Create `TI-84_Plus_CE/probe-phase368-disasm-3A77.mjs` that:

### Part 1: Static disassembly
Read ROM bytes and disassemble the following ranges as eZ80 ADL-mode instructions:
- 0x003A60 - 0x003A90 (48 bytes — covers event loop continuation block including 0x003A72, 0x003A77, 0x003A7B, and surrounding context)

Use the ROM file at `TI-84_Plus_CE/ROM.rom`. Read raw bytes and decode manually.

Key eZ80 opcodes for reference:
- 0xC3 = JP nn (4 bytes in ADL: C3 ll mm hh)
- 0xCD = CALL nn (4 bytes in ADL)
- 0xC9 = RET
- 0x18 = JR d (2 bytes)
- 0x20 = JR NZ,d
- 0x28 = JR Z,d
- 0x38 = JR C,d
- 0x30 = JR NC,d
- 0xCB = bit/rotate prefix
- 0xDD = IX prefix
- 0xFD = IY prefix
- 0xED = extended prefix (e.g., ED 38 nn = IN0 A,(nn))
- 0x3E = LD A,n
- 0x21 = LD HL,nn (4 bytes in ADL)
- 0x01 = LD BC,nn
- 0x11 = LD DE,nn
- 0xFE = CP n
- 0xB7 = OR A
- 0xAF = XOR A
- 0x7E = LD A,(HL)
- 0x77 = LD (HL),A
- 0x3A = LD A,(nn) (4 bytes in ADL: 3A ll mm hh)
- 0x32 = LD (nn),A (4 bytes in ADL)

### Part 2: Dynamic block trace around the no-key transition
Run the standard 3-phase cold boot then event loop (same as probe-phase367-boot-50k.mjs):

Phase 1: `executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
Reset: `cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.sp = 0xD1A87E - 3; mem.fill(0xFF, cpu.sp, cpu.sp + 3);`
Phase 2: `executor.runFrom(0x08C331, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 })`
Then: `cpu.mbase = 0xD0; cpu._iy = 0xD00080; cpu._hl = 0; cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.sp = 0xD1A87E - 3; mem.fill(0xFF, cpu.sp, cpu.sp + 3);`
Phase 3: `executor.runFrom(0x0802B2, 'adl', { maxSteps: 100, maxLoopIterations: 32 })`

Then set up event loop:
```js
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
cpu.f = 0x40;
cpu._ix = 0xD1A860;
cpu._iy = 0xD00080;
cpu.sp = 0xD1A87E - 12;
mem.fill(0xFF, cpu.sp, cpu.sp + 12);
```

Run from 0x003A73 with 50K steps using `onBlock` callback. For blocks 0x003A77 and 0x003A7B:
- Log the 5 preceding blocks when each is first entered
- Log full CPU state: PC, SP, IX, IY, HL, BC, DE, A, F
- Count total visits to each block during the full 50K run
- Log the 5 blocks that FOLLOW each of these (what does OS do after no-key response?)

### Part 3: RAM memory context
After the event loop, check what RAM locations these blocks reference. Based on the register state from Part 2, read any RAM addresses that HL, IX, or IY point to during these blocks' execution. Also check:
- 0xD0058E (KEY_EVENT_BUFFER_ADDR)
- 0xD00587 (keyboard flags)
- Any (IY+offset) addresses used (IY is typically 0xD00080)

## File structure
```js
#!/usr/bin/env node
import fs from 'node:fs';
import path from 'node:path';
import { fileURLToPath, pathToFileURL } from 'node:url';
import { createExecutor } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));
const romModule = await import(pathToFileURL(path.join(__dirname, 'ROM.transpiled.js')).href);
const BLOCKS = romModule.PRELIFTED_BLOCKS;

function hex(v, w = 6) { return v == null ? 'n/a' : '0x' + (v >>> 0).toString(16).padStart(w, '0'); }

const mem = new Uint8Array(0x1000000);
mem.set(romBytes);
const peripherals = createPeripheralBus({ pllDelay: 2, timerInterrupt: false });
const executor = createExecutor(BLOCKS, mem, { peripherals });
const { cpu } = executor;
```
