# Task: Identify Scan Code 0x4E and Find the 2ND Translation Table Caller

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). The runtime is in `TI-84_Plus_CE/cpu-runtime.js`, peripherals in `TI-84_Plus_CE/peripherals.js`, transpiler in `scripts/transpile-ti84-rom.mjs`.

Session 390 discovered that scan code 0x4E triggers a kbdKey↔kbdToken swap at address 0x030300. The event builder at 0x0236F9 compares the scan code to 0x4E and conditionally writes kbdToken as event byte 2.

## Problem
0x4E = 78 decimal. Using the OS scan code formula `OS_scancode = (6-group)*8+bit+1`, the maximum natural scan code for 7 groups × 8 bits is ~56. So 0x4E exceeds the natural range — it may be a SYNTHETIC scan code generated by the translation table at 0x09F79B.

The 2ND translation table at 0x09F79B (228 bytes, 4 modifier × 57 keys) is known but we haven't found its CALLER in the ROM. Sessions 388-390 traced the chain 0x03016A→0x04E950→0x09EF44 but NONE of those functions reference the table.

## Deliverables

Write a probe file `TI-84_Plus_CE/probe-phase391-scancode-0x4E.mjs` that:

1. **Search the ROM for bytes referencing 0x09F79B and 0x09F7D3** — scan the entire 4MB ROM for the 3-byte little-endian patterns `9B F7 09` and `D3 F7 09`. Report all addresses where these patterns appear. These are likely CALL or LD instructions that reference the translation table.

2. **Search for who writes 0x4E to D007E0 or D0058C** — scan ROM for instruction sequences that load 0x4E and write to D007E0 (kbdScanCode buffer) or D0058C (kbdKey). Pattern: look for `LD A,0x4E` (3E 4E) near stores to those RAM addresses.

3. **Decode what 0x4E means in the translation table** — Read the translation table at ROM offset 0x09F79B. The table is 228 bytes with 4 modifier sections (none=0, 2nd=0x38, alpha=0x70, alpha+2nd=0xA8). Index formula: `((raw>>4)*8)+(raw&0x0F)+1`. Find which raw scan code and modifier produces output 0x4E, OR find 0x4E as an INPUT index into the table.

## How to write the probe
```javascript
import { readFileSync } from 'fs';
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');

// Pattern search: find all occurrences of byte sequence in ROM
function findPattern(rom, pattern, label) {
  const results = [];
  for (let i = 0; i < rom.length - pattern.length; i++) {
    let match = true;
    for (let j = 0; j < pattern.length; j++) {
      if (rom[i + j] !== pattern[j]) { match = false; break; }
    }
    if (match) results.push(i);
  }
  console.log(`${label}: ${results.length} matches`);
  results.forEach(a => console.log(`  0x${a.toString(16).padStart(6,'0')}`));
  return results;
}

// Search for references to 0x09F79B (LE: 9B F7 09)
findPattern(rom, [0x9B, 0xF7, 0x09], 'Refs to 0x09F79B');

// Search for references to 0x09F7D3 (LE: D3 F7 09)  
findPattern(rom, [0xD3, 0xF7, 0x09], 'Refs to 0x09F7D3');

```
