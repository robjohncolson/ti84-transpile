# Auto-Session 289 — Priority P3: Check 0x0159CD (5 CALL sites)

## Context

This is the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). The instruction decoder is at `TI-84_Plus_CE/ez80-decoder.js`.

Previous session (288, Sonnet P1) found that 0x0159C0 (the keyboard scanner function, 201 bytes) has a RET at 0x0159BC that terminates the PRECEDING function. 0x0159C0 itself is reached indirectly only (via IX register). However, **0x0159CD** (13 bytes past the scanner entry at 0x0159C0) has **5 direct CALL sites** in the ROM.

**Key question**: Is 0x0159CD the "real" public entry point for the scanner? What do callers pass in registers? Is 0x0159C0-0x0159CC just a preamble that the indirect path uses?

## Task

Write a probe script `TI-84_Plus_CE/probe-phase289-0159CD-callers.mjs` that:

1. Scans ROM (0x000000-0x0BFFFF) for CALL 0x0159CD:
   - Opcode 0xCD followed by 3-byte LE: 0xCD, 0x59, 0x01
   - Also check for JP 0x0159CD: 0xC3, 0xCD, 0x59, 0x01
   - Wait — careful with byte order. 0x0159CD in LE is: 0xCD, 0x59, 0x01. So CALL 0x0159CD = 0xCD 0xCD 0x59 0x01 (opcode 0xCD + addr LE 0xCD 0x59 0x01)
   - And JP 0x0159CD = 0xC3 0xCD 0x59 0x01

2. For each of the ~5 call sites:
   - Print the address
   - Disassemble 15 instructions BEFORE the CALL to see what registers are loaded (especially IX, HL, A, BC, DE)
   - Disassemble 5 instructions AFTER
   - Identify what value is loaded into key registers before the call

3. Disassemble 0x0159C0 through 0x0159CC (the 13-byte preamble before 0x0159CD):
   - What does this preamble do?
   - Does it set up something that 0x0159CD skips?

4. Summary: Is 0x0159CD effectively a "skip preamble" entry, or does it have different semantics?
