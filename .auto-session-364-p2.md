# Auto-Session 364 — Priority 2: Fix IX Linked-List Termination via Seed or Bypass

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The OS ROM (eZ80 machine code) has been lifted into JavaScript. Boot reaches 476 blocks then crashes at block 0x00BC72 due to SP corruption.

**The SP corruption chain (found in session 363)**:
1. Block 0x00BC31 is a loop that copies bytes. It calls block 0x00BC47.
2. Block 0x00BC47 at instruction 0x00BC4D does `LD IX, (IX-30)` — follows a linked-list pointer
3. On iteration 2, IX gets loaded with 0x014C7B (a ROM address) from RAM at 0xD14095
4. Block 0x00BC72 does `LD SP, IX; POP IX; RET` — sets SP to ROM address, crash

**Key addresses**:
- 0x00BC31: Loop body — loads BC=(IX-9), HL=(IX-3), does SBC HL,BC, JR C to 0x00BC47
- 0x00BC47: Linked-list follow — LD IX,(IX-30) at 0x00BC4D
- 0x00BC72: Function epilogue — LD SP,IX; POP IX; RET (the crash point)
- 0x00BC1D: Caller — CALL 0x014C63 which eventually reaches the loop
- IX=0xD140B3 on first iteration (valid RAM), then becomes 0x014C7B on second (ROM — bad)

## Your Task
Create a probe that tests TWO potential fixes and reports which one (or both) lets boot proceed past 476 blocks:

### Fix A: Linked-list termination guard
Before block 0x00BC47 executes `LD IX, (IX-30)`, check if the loaded value is < 0x400000 (ROM space) or > 0xFFFFFF. If so, skip the assignment and force the loop to exit by clearing the carry flag (so 0x00BC31's JR C falls through to exit). Implement this by wrapping the block 0x00BC47 function.

### Fix B: SP safety clamp
In the boot dispatch loop, after each block executes, check if SP < 0x400000. If so, log a warning and restore SP to a safe value (e.g., the SP value at step 2680, which was the last valid SP before corruption). This is a safety net, not a real fix.

## How to Build the Probe
Use `TI-84_Plus_CE/probe-phase363-sp-corruption-trace.mjs` as your template.

For Fix A:
- After loading transpiled blocks, find block `00bc47:adl` in the blocks object
- Wrap its function: save the original, replace with a wrapper that reads (IX-30) first, checks if < 0x400000, and if so skips the block and clears carry flag in cpu.flags
- Run boot for 10000 steps and report: how many blocks reached, where it terminates, any new missing_block addresses

For Fix B:
- In the dispatch loop, after each `block.execute(cpu, mem)` call, check `cpu.sp < 0x400000`
- If triggered, log the step/block and restore SP to the last known good value
- Run boot for 10000 steps and report same metrics

Run BOTH fixes independently (two separate boot runs) and compare results.
