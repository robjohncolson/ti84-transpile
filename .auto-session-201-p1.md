# Auto-Session 201 P1: Extended bit-5-SET dispatch trace (500+ steps)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript. We run probes that execute lifted blocks to trace OS behavior.

Session 200 discovered that BIT 5,(IY+68) at address 0xD000C4 controls the dispatch path after KeyClassifier. When bit 5 is SET, execution goes 0x0584C5→fallthrough→0x0584C7→CALL 0x082C50 (avoids the JError crash). But session 200's probe only ran 12 steps with a sentinel at 0x082C50 — we never saw the FULL path.

## Task
Build a probe `TI-84_Plus_CE/probe-phase201-bit5-extended-trace.mjs` that:

1. Loads the transpiled ROM runtime (same pattern as existing probes)
2. Sets up standard memory initialization (cold boot + kernelInit + memInit)
3. Pre-seeds a digit-4 key token in TOKEN_STAGING at 0xD0230E (9 bytes: `[0x00, 0x34, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]`)
4. Sets bit 5 at address 0xD000C4: `mem[0xD000C4] |= 0x20`
5. Sets IX = 0xD1A860 (home-screen convention)
6. Runs from entry point 0x0584A3 for 1000 steps (NO sentinel — let it run freely)
7. Logs EVERY unique block visited (address + step number)
8. Checks whether BufInsert at 0x05E2A0 was reached
9. Checks whether any blocks in the 0x05E2xx range were reached
10. Dumps final OP1 (9 bytes at 0xD005F8) and TOKEN_STAGING state
11. Dumps the edit buffer region 0xD00A00-0xD00A10 to see if any tokens were inserted
