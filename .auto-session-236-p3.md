# Task (rrr): Investigate 0x04EB0B — CP 0x1D / CP 0x44 Sequence

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM (eZ80 machine code) has been lifted to JavaScript.

Session 235 found that ROM at 0x04EB0B contains `FE 1D 28 04 FE 44` which decodes to:
```
CP 0x1D    ; FE 1D
JR Z,+4   ; 28 04 (jump to 0x04EB11 if A==0x1D)
CP 0x44    ; FE 44
```

Key code 0x44 = physical "2" key (scan code 0x31 in the 09F79B table). 0x1D is a synthetic internal dispatch code (43 CP 0x1D + 43 LD A,0x1D sites in ROM, not in any key/token table).

The gate at 0x0302EB replaces A with 0x1D when key code is 0x44 + BIT 4,(IY+0x4B) is SET. So 0x04EB0B handles BOTH the original key code AND its replacement.

## Deliverables
Create `TI-84_Plus_CE/probe-phase236-04eb0b-cp1d-cp44.mjs` that:

1. Disassemble ROM bytes from 0x04EAF0 to 0x04EB40 (80 bytes) to see the full function context around the CP 0x1D / CP 0x44 sequence
2. Find the function boundary — scan backward from 0x04EB0B for a RET/JP instruction to identify the function entry point
3. Find what parent function 0x04EB0B is in — is it inside 0x04EB3E (the pointer-table dispatch function from session 218)?
4. Run dynamic traces with:
   - A=0x1D (synthetic code) — what does the JR Z,+4 target at 0x04EB11 do?
   - A=0x44 (real "2" key) — what happens when CP 0x44 matches?
   - A=0x8F (digit "1" key, as control) — what path does a non-matching code take?
5. For each trace: 200 steps from 0x04EB0B, record unique blocks, RAM writes (especially D0058E, IY flags, D003E0), and final state
6. Determine: does this function modify the key code? Does it set flags that affect downstream dispatch? What is the architectural role of handling 0x1D and 0x44 together?
