# Auto-session 597 P1: Disassemble 0x040D11 — the actual key handler called by 0x030300

## Context

This is a TI-84 Plus CE ROM transpilation project. We are tracing why a keypress does NOT reach the event dispatcher at 0x099921. The flow we observe is:

```
0x02FD8F (warm key-event entry)
→ 0x03FA09 (_GetCSC, key consumed, D0058E=0x90)
→ 0x02FE89 (tests bit 7 of IY+0x28 = D000A8)
→ 0x030300 (reentrancy guard: BIT 0,(IY+0x1D) / RET NZ, then CALL 0x040D11)
→ ISR loop → halt
```

The key is consumed but 0x099921 (the 38-entry command dispatcher) and 0x03E1B4 (token processor) are NEVER hit. We need to understand what 0x040D11 does to figure out why.

## Task

Build a probe that disassembles 0x040D11 from the ROM bytes. Use the same pattern as existing decode probes in the repo.

### How to build the probe

1. Read `TI-84_Plus_CE/probe-phase594-decode-07F7D6.mjs` as a template — it shows the standard pattern for static ROM byte decode probes.
2. Create `TI-84_Plus_CE/probe-phase597-decode-040D11.mjs` following that pattern.
3. The probe should:
   - Load the ROM from `TI-84_Plus_CE/ROM.rom`
   - Read raw bytes starting at 0x040D11
   - Decode instructions using `TI-84_Plus_CE/ez80-decoder.js` (import `decodeInstruction`)
   - Decode at least 128 bytes (or until hitting 2+ unconditional RET/JP/JR in sequence)
   - Print each instruction: address, raw hex, mnemonic, operands
   - Identify CALL targets, JP targets, RAM addresses referenced, IY offsets, port I/O
   - Print a summary of all targets/refs at the end

4. Run the probe: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase597-decode-040D11.mjs`

### Critical constraints
- Do NOT modify any existing files except creating the new probe
- The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB, little-endian eZ80)
- ez80-decoder.js exports `decodeInstruction(romBuffer, pc)` returning `{tag, length, operands, ...}`
- PROBE SAFETY: run via `node scripts/run-probe.mjs --max-time 180 <probe>` — NEVER bare `node <probe>`

### Success criterion
The probe runs (exit 0) and prints a decoded disassembly of 0x040D11 showing:
- What instructions are at 0x040D11+
- What it CALLs or JPs to
- What RAM addresses it reads/writes
- Whether 0x099921 appears anywhere in the call chain
