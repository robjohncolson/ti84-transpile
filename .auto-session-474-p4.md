# Task: Add Seed at 0x02FDBE + Retranspile

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The transpiler lifts eZ80 ROM machine code into JavaScript functions (blocks). Seeds are entry points that tell the transpiler where to start disassembling.

## Problem
The block at 0x02FDB6 currently covers bytes 0x02FDB6 through ~0x02FDBE+. The idle loop can enter at 0x02FDBE directly (via JP 0x02FDBE at 0x02FE5D), but the transpiler merged 0x02FDB6-0x02FDBE into one block. This means:
- onBlock fires at 0x02FDB6 (109 hits in the idle loop)
- onBlock at 0x02FDBE fires only 1 time (from runFrom)
- JP 0x02FDBE works correctly (execution is fine) but block-level tracking misses the 0x02FDBE entries

Adding a seed at 0x02FDBE splits the block, making idle loop tracking via onBlock more natural.

## Your Task

1. **Add seed 0x02FDBE** to `scripts/transpile-ti84-rom.mjs`:
   - Find the seeds array (search for `0x02FDB6` or nearby seeds to find the right location)
   - Add `0x02FDBE` in the appropriate sorted position
   - The format is just hex numbers in a large array, e.g.: `0x02FDBE,`

2. **Retranspile**:
   ```bash
   node scripts/transpile-ti84-rom.mjs
   ```
   This generates `TI-84_Plus_CE/ROM.transpiled.js` (~214 MB) in ~2 seconds.

3. **Run golden regression**:
   ```bash
   node TI-84_Plus_CE/probe-phase99d-home-verify.mjs
   ```
   Must pass 26/26.

4. **Run coverage audit**:
   ```bash
   node TI-84_Plus_CE/audit-true-uncovered.mjs
   ```
   Report the new seed count, block count, and covered bytes.

5. **Regenerate .gz**:
   ```bash
   cd TI-84_Plus_CE && gzip -kf -9 ROM.transpiled.js
   ```

6. **Report**: Print the before/after seed count, block count, covered bytes. Confirm golden regression passes.

## Important Details
- The transpiler script is at `scripts/transpile-ti84-rom.mjs`
- Seeds are in a large array near the top of the file
- `ROM.transpiled.js` is gitignored — the `.gz` is committed
- The `probe-phase99d-home-verify.mjs` test must pass 26/26 cells

## Constraints
