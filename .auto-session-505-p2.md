# Task: Decode 0x0A1B5B — Status Area Writer

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 machine code). You need to create a probe that statically disassembles a ROM function.

## Background
0x0979E4 is a 15-byte conditional character output function in the cursor status formatter. When the cursor IS visible (0x096F67 visibility gate returns Z), it calls 0x0A1B5B instead of the normal putchar path (0x061986). When the cursor is NOT visible, it calls 0x061986 (mid-entry into putchar 0x061980, skipping the mode gate).

0x0A1B5B is likely a display-list or overlay buffer writer — it handles character output for the status bar area when the cursor is visible. Understanding it reveals the status bar rendering mechanism.

The calling context: 0x096B65 (status bar formatter) calls 0x0979E4 with characters like space (0x20), '(' (0x28), ')' (0x29), and the cursor symbol (0x3D '=' or 0x7F block from 0x060BA2). 0x0979E4 routes these to either 0x0A1B5B (visible) or 0x061986 (not visible).

Other functions in the 0x0A1xxx-0x0A2xxx range that we know about:
- 0x0A22B1, 0x0A1F12: called from 0x096B65's main body
- 0x0A2A68, 0x0A1CEC: called from 0x09798C (cursor marker handler)
- 0x0A23E5: pixel renderer (reads D008D2/D008D5 for VRAM position)
- 0x0A2D4C: called from 0x061061

## eZ80 Instruction Reference
- eZ80 is a Z80 superset with 24-bit addressing
- Standard Z80 opcodes apply, plus:
  - `ED 27` = `LD HL,(HL)` (load 24-bit value from address in HL)
  - `.SIS` prefix (0x40) = 16-bit operand override, high byte from MBASE register (0xD0)
  - `MLT rr` = multiply L×H→HL (8×8→16 multiply)
  - `TST A,n` = test A AND n without storing
  - 24-bit LD/ADD/SBC for HL,DE,BC,IX,IY
- IY base = 0xD00080 (so IY+0x11 = D00091, IY-0x04 = D0007C, etc.)
- RST 28h (0xE7) = BCALL, followed by 2-byte index into system call table

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase505-decode-0A1B5B.mjs` that:

1. Reads the ROM binary from `TI-84_Plus_CE/ROM.rom`
2. Statically disassembles starting at 0x0A1B5B, decoding at least 100 bytes (or until clear function boundaries are found)
3. For each instruction, prints: address, hex bytes, mnemonic, operands
4. Handles eZ80 prefixes (0x40 .SIS, 0x49 .LIS, 0x52 .SIL, 0x5B .LIL, CB/DD/ED/FD prefix groups)
5. Identifies all CALL/JP targets and RAM references (D0xxxx addresses)
6. Also disassemble any short helper functions called from 0x0A1B5B (within 0x0A1xxx-0x0A2xxx range) if they are ≤30 bytes
7. Prints a summary of what the function appears to do

The probe must be runnable via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase505-decode-0A1B5B.mjs`

## Constraints
- Do NOT modify any existing files — only CREATE the new probe file
- Do NOT touch `cpu-runtime.js`, `peripherals.js`, `browser-shell.html`, `ez80-decoder.js`, or any transpiler files
- The probe is a standalone Node.js script that reads ROM.rom directly with `fs.readFileSync`
- Use `process.exit(0)` at the end for clean exit
- Do NOT use dynamic execution (no cpu.step(), no loadOsIntoExecutor) — static disassembly ONLY
- The ROM file path is `TI-84_Plus_CE/ROM.rom` (NOT `TI84PCE.rom` or any other name)

## Success Criterion
The probe runs cleanly via the watchdog and outputs a complete disassembly of 0x0A1B5B showing all instructions, CALL targets, and RAM references. We can determine whether it writes to a display list, overlay buffer, or VRAM directly, and how it differs from the normal putchar path.
