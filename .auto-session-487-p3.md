# Auto-Session 487 P3: Render All 256 Character Glyphs

## Context

This is a TI-84 Plus CE ROM transpilation project. The OS ROM (eZ80 machine code) has been lifted to JavaScript. We run "probes" — Node.js scripts that boot the lifted ROM, step the CPU, and observe memory/VRAM changes.

Sessions 478-486 fully decoded the character rendering pipeline:
- 0x0059C6 = character output wrapper (takes A = character code)
- 0x005A75 = renderer (computes VRAM address from D00595 row, D00596 column)
- Font format: 28 bytes/glyph, 1bpp packed bitmap, 12×16 pixels per character (or 14×16 with D00085 bit 3)
- VRAM formula: addr = 0xD40000 + (row×20+37)×640 + (col×12+2)×2
- Each character renders 96 VRAM bytes (verified for A-Z, a-z, 0-9, spaces)

## Task

Create a probe that renders ALL 256 character codes (0x00-0xFF) via 0x0059C6 and captures each glyph's pixel pattern from VRAM. This builds a complete font atlas.

### Approach

1. **Boot the ROM** with the standard 3-stage boot pattern.
2. **For each character code 0x00-0xFF**, render it at a known position:
   - Set D00595=0 (row 0), D00596=0 (col 0) before each render
   - Take a VRAM snapshot of the character cell area before rendering
   - Call 0x0059C6 with A = character code
   - Take another VRAM snapshot after rendering
   - Compute the diff (changed pixels) as the glyph pattern
   - Store: char code, number of changed bytes, pixel positions

3. **Output format**: For each character, print:
   - Character code (hex)
   - Number of VRAM bytes changed
   - A compact pixel grid (rows × cols) showing which pixels are set

4. **Optimization**: Since we only need one character at a time and we reset position each time, this is 256 sequential calls. Each takes ~161 steps, so total ~41K steps — well within limits.

## Probe template

```javascript
import { createExecutor } from './cpu-runtime.js';

const VRAM_BASE = 0xD40000;
const CHAR_CELL_WIDTH = 12;  // pixels
const CHAR_CELL_HEIGHT = 16; // pixel rows (but 14 used for rendering, 2 padding)
const ROW_STRIDE = 640;      // bytes per pixel row (320px × 2 bytes/px)

const { cpu, mem, onBlock, runFrom } = createExecutor({
  romPath: './ROM.rom',
  peripherals: { timerInterrupt: false }
});

// 3-stage boot
runFrom(0x000000, { maxSteps: 50000, stopOnRet: false, stopAt: [0x02FDBE] });
runFrom(0x02FDBE, { maxSteps: 20000, stopOnRet: false, stopAt: [0x02FDBE] });
runFrom(0x02FDBE, { maxSteps: 20000, stopOnRet: false, stopAt: [0x02FDBE] });

// Character cell VRAM area for row 0, col 0:
// Start = 0xD40000 + 37*640 + 2*2 = 0xD40000 + 23680 + 4 = 0xD45C84
const CELL_START = VRAM_BASE + 37 * ROW_STRIDE + 2 * 2;

const results = [];

for (let charCode = 0; charCode < 256; charCode++) {
  // Reset cursor position
  mem[0xD00595] = 0; // row 0
  mem[0xD00596] = 0; // col 0
  
  // Snapshot VRAM before
  const before = new Uint8Array(CHAR_CELL_HEIGHT * ROW_STRIDE);
  for (let r = 0; r < CHAR_CELL_HEIGHT; r++) {
    for (let c = 0; c < CHAR_CELL_WIDTH * 2; c++) {
      before[r * CHAR_CELL_WIDTH * 2 + c] = mem[CELL_START + r * ROW_STRIDE + c];
    }
  }
  
  // Set A register to character code and call 0x0059C6
  // Use the runFrom pattern with register setup
  cpu.a = charCode;
  const result = runFrom(0x0059C6, { maxSteps: 500, stopOnRet: true });
  
  // Snapshot VRAM after and compute diff
  let changedBytes = 0;
  const pixels = [];
  for (let r = 0; r < CHAR_CELL_HEIGHT; r++) {
    let row = '';
    for (let px = 0; px < CHAR_CELL_WIDTH; px++) {
      const addr = CELL_START + r * ROW_STRIDE + px * 2;
      const lo = mem[addr];
      const hi = mem[addr + 1];
      const bLo = before[r * CHAR_CELL_WIDTH * 2 + px * 2];
      const bHi = before[r * CHAR_CELL_WIDTH * 2 + px * 2 + 1];
      if (lo !== bLo || hi !== bHi) {
        changedBytes += 2;
        row += '#';
      } else {
        row += '.';
      }
    }
    pixels.push(row);
  }
  
  results.push({ charCode, changedBytes, pixels });
}

// Print results
for (const r of results) {
  const printable = (r.charCode >= 0x20 && r.charCode <= 0x7E) ? String.fromCharCode(r.charCode) : '';
  console.log(`\n=== Char 0x${r.charCode.toString(16).padStart(2, '0')} ${printable} (${r.changedBytes} bytes) ===`);
  if (r.changedBytes > 0) {
    for (const row of r.pixels) {
      console.log(row);
    }
  }
}

console.log(`\n=== SUMMARY ===`);
console.log(`Total characters rendered: 256`);
console.log(`Characters with pixels: ${results.filter(r => r.changedBytes > 0).length}`);
console.log(`Characters with 0 pixels: ${results.filter(r => r.changedBytes === 0).length}`);
```

**IMPORTANT**: The above is a TEMPLATE showing the approach. You will need to adapt it to the actual API. Key things to verify:
- `createExecutor` returns `{ cpu, mem, onBlock, runFrom }` — check cpu-runtime.js for the exact API
- Setting `cpu.a` may need to use the actual register name (check cpu-runtime.js)
- `runFrom` may need a sentinel address (0x500000) between ROM and RAM — check how sessions 483-486 probes work
- The VRAM snapshot approach should work — just read/compare mem[] bytes
