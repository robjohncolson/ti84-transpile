# Auto-session 257 P1: Trace 0x09E2EC (shared context-registration function)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript and executed via `cpu-runtime.js`. We've decoded a 20-entry handler table at 0x08C958 (session 252). Handler[8] starts with `LD A,0x48; CALL 0x09E2EC` and handler[19] starts with `LD A,0x53; CALL 0x09E2EC`. We believe 0x09E2EC is a shared "context-registration" function that sets up OS context (populating cx* fields at D007CA-D007E0 in RAM).

## Task
Create a probe file `TI-84_Plus_CE/probe-phase257-09e2ec-context-reg.mjs` that:

1. **Static disassembly**: Read ROM bytes at 0x09E2EC and disassemble the first ~100 bytes manually (print hex + decoded eZ80 instructions). Look for writes to D007xx addresses (especially D007CA, D007CE, D007D2, D007D6, D007DA, D007DE, D007E0, D00824).

2. **Dynamic trace with A=0x48** (handler[8]'s mode): Set up a minimal runtime (cold boot + kernelInit + memInit), then call 0x09E2EC with A=0x48 in a register. Run for up to 2000 steps. Track:
   - All writes to D007CA-D007E0 range (watch every write8/write16/write24)
   - All writes to D00824
   - All CALL targets (first 20 unique)
   - Final values at D007CA, D007CE, D007D2, D007D6, D007DA, D007DE, D007E0, D00824

3. **Dynamic trace with A=0x00** (home-screen context): Same setup but A=0x00. Run for up to 2000 steps. Same tracking.

4. **Dynamic trace with A=0x53** (handler[19], STAT mode): Same setup but A=0x53. Run for up to 2000 steps. Same tracking.

5. Print all results clearly with labels.

```js
import { createExecutor, createMemory } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
const mem = createMemory();

const cpu = createExecutor(mem, bus);
// Load ROM
import { readFileSync } from 'fs';
const rom = readFileSync(new URL('./ROM.rom', import.meta.url));
mem.set(rom, 0);
// Cold boot
cpu.coldBoot();
// kernelInit, memInit... (check recent probes for exact pattern)
```

## Constraints
