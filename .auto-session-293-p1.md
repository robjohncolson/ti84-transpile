# Task: Disassemble 0x02FD8F — Actual Key Acquisition Function

## Context
The TI-84 Plus CE ROM transpilation project has traced the key input pipeline to function 0x02FCB3 (GetCSC equivalent), which was fully disassembled in session 292. KEY FINDING: 0x02FCB3 contains NO keyboard hardware reads — it delegates to `CALL 0x02FD8F` for actual key acquisition. 0x02FD8F is the next link in the chain.

Session 233 identified 0x02FD8F as the key-event dispatcher entry point (it starts right after the RET at 0x02FD8E that ends 0x02FCB3). It likely contains IN instructions reading keyboard MMIO at 0xE00900, or calls a function that does.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase293-02fd8f-key-acquire.mjs` that:

1. Uses `ez80-decoder.js` to disassemble starting at 0x02FD8F through the ROM bytes
2. Decodes instructions sequentially, following the linear flow
3. For each instruction, report: PC address, raw bytes, mnemonic, operands
4. Specifically flag:
   - Any IN instructions (keyboard hardware reads)
   - Any CALL/JP to other functions (note the target addresses)
   - Any LD from 0xE00900-0xE009FF range (keyboard MMIO)
   - Any LD from/to D0058C (0xD0058C — scan code storage)
   - Any CP instructions (compare — part of dispatch cascades)
   - Any RET/RETI instructions (function boundaries)
5. Continue disassembly until you hit a RET that isn't inside a conditional branch, or until you've decoded 300 instructions (whichever comes first)
6. Print a summary at the end: total instructions, total bytes, IN instruction count, CALL targets found, whether keyboard MMIO was accessed
