# Task: Decode 0x009118 Sequential Priority Init Chain

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80 binary). We have a transpiler at `scripts/transpile-ti84-rom.mjs` and probes in `TI-84_Plus_CE/probe-phase*.mjs`.

Session 429 discovered that 0x009118 is a **sequential priority init chain** — it tries 6 communication subsystem initializers in priority order via sequential CALL, stopping at the first one that returns A=1 (success). Known so far:
- Priority 1: CALL 0x0089F8 (USB init) → calls 0x00CC71 with args 0/2/2000
- Priority 3: CALL 0x008DA0 (Link init) → calls 0x00CC71 with args 0/1/300
- Priorities 2, 4, 5, 6: UNKNOWN
- Called from 0x013006 and 0x01305B

## Deliverables

1. **Create `TI-84_Plus_CE/probe-phase430-trace-009118.mjs`**: A probe that disassembles the function at 0x009118, identifying:
   - Total byte length of the function
   - All 6 CALL targets (the priority initializers)
   - The return-value check logic (how does it detect A=1 success?)
   - Any RAM variables read/written
   - Any port I/O
   - The function's own return value (does it propagate which priority succeeded?)

2. **Create `TI-84_Plus_CE/phase430-009118-report.md`**: A structured report with:
   - Full disassembly annotation
   - All 6 priorities listed with their CALL targets
   - How the "first success wins" logic works
   - Any early-exit or fallback behavior

## How to read ROM bytes
```javascript
import { readFileSync } from 'fs';
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
// Read byte at address addr: rom[addr]
// Read 3-byte little-endian address: rom[addr] | (rom[addr+1] << 8) | (rom[addr+2] << 16)
// eZ80 CALL nn instruction: 0xCD followed by 3-byte LE target address
// eZ80 RET: 0xC9
// eZ80 CP A,n: 0xFE nn (compare A with immediate)
// eZ80 JR Z,offset: 0x28 dd (jump relative if zero)
// eZ80 JR NZ,offset: 0x20 dd (jump relative if not zero)
// eZ80 OR A,A: 0xB7 (test A for zero)
// eZ80 AND A,n: 0xE6 nn
```

## Constraints
- Do NOT modify any existing files
- Do NOT run the transpiler
- The probe should be self-contained and runnable via `node TI-84_Plus_CE/probe-phase430-trace-009118.mjs`
- Focus on the exact byte range starting at 0x009118. Follow CALLs only to identify targets, don't fully decode the callees.
- Look for the pattern: CALL target, check A (OR A,A / CP 1 / AND A,A), conditional jump (JR NZ / JR Z), repeat 6 times, then RET.

## Success criterion
The probe runs without error and the report identifies all 6 priority CALL targets with their addresses.
