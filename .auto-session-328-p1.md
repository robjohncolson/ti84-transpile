# Task: Trace Variable-Width Text Renderer 0x054FC6

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The variable-width font table has been fully decoded (session 327):
- Font table base: ROM 0x0A3AFA
- Record size: 25 bytes (byte 0 = pixel width, bytes 1-2 = padding, bytes 3-24 = bitmap data)
- Font lookup function 0x0A5424 copies 25 bytes to RAM at 0xD005C5

Now we need to trace the RENDERER that actually draws glyphs to VRAM using this font data.

## Target
Function at **0x054FC6** — this is the variable-width text renderer. It is called when rendering proportional-width text (menus, dialogs, etc.).

## Deliverables
Create a probe file `TI-84_Plus_CE/probe-phase328-varwidth-renderer.mjs` that:

1. Disassembles 0x054FC6 using the transpiled ROM to trace the full function body
2. Answers these specific questions:
   - How many instructions / basic blocks does the function have?
   - What VRAM addresses does it write to? (The LCD framebuffer is at 0xD40000, 320×240×2 bytes = 153600 bytes)
   - How does it use the width byte from the font record (byte 0 at D005C5)?
   - Where does it get the current screen X,Y position from? (Check IY-relative offsets, or RAM addresses like D005xx)
   - Does it call 0x0A5424 (font lookup) internally, or expect the caller to have already loaded the glyph?
   - Does it advance the cursor position after drawing? If so, by how much and where is the cursor stored?

3. Uses dynamic tracing (execute the transpiled code) with a test character (e.g., ASCII 0x41 = 'A'):
   - Set up memory: load font data for 'A' at D005C5 (or let the function call 0x0A5424)
   - Set a plausible screen position
   - Run 0x054FC6 and log all memory writes to the D40000-D65FFF VRAM range
   - Log all RAM reads/writes to identify state variables
