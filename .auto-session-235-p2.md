# Task: Trace 0x02FFED — special/fallthrough exit path (mmm)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript and executed via `cpu-runtime.js`. We are tracing the OS event loop's key processing pipeline.

**0x02FFED** is reached two ways:
1. JP NZ from 0x02FF1F when 0x0302EB returns NZ (key code = 0x44 with BIT 4,(IY+0x4B) SET, A replaced with 0x1D)
2. Fallthrough from 0x02FFE7 (unknown what leads there)

Session 233's traces show 0x02FFED leads to 0x02FE84 → 0x030300 → 0x02FE88 (RET). We need to know what 0x02FFED does before reaching 0x02FE84.

Session 234 confirmed: after CALL 0x0302EB at 0x02FF1F, if NZ, JP NZ,0x02FFED. The NZ case happens when A=0x44 AND BIT 4,(IY+0x4B) is SET, and A gets replaced with 0x1D.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase235-02ffed-special-exit.mjs` that:

1. Imports from `./cpu-runtime.js` (createCPU, createMemoryBus, createPeripheralBus)
2. Loads ROM from `./ROM.rom` using `fs.readFileSync`
3. Sets up the environment:
   - `createPeripheralBus({ timerInterrupt: false })`
   - `createMemoryBus(rom, peripherals)`
   - `createCPU(mem)`
   - `cpu.mbase = 0xD0`
   - IY = 0xD00080
4. Tests TWO scenarios:

   **Scenario A**: Direct entry at 0x02FFED with A=0x1D (the replaced key code from 0x0302EB's 0x44 special path). This simulates the JP NZ,0x02FFED path.
   
   **Scenario B**: Direct entry at 0x02FFED with A=0x9C (a normal key code). This tests whether 0x02FFED behaves differently based on the key code in A.

5. For each scenario, run up to 300 steps, logging:
   - Every block visited (address, in order)
   - Total steps to reach a RET or sentinel
   - D0058E, D0058D, D0059F values after
   - IY flag changes (snapshot IY+0 through IY+5, IY+18, IY+29, IY+40 before and after)
   - Whether 0x02FE84, 0x030300, 0x02FD99 are visited

6. Also do a **static disassembly check**: Read ROM bytes at 0x02FFED-0x030000 and print them as hex to see the raw instructions. This gives us the ground truth of what 0x02FFED contains.

## Key constraints
- Do NOT modify any file except the probe file
- Use `{ timerInterrupt: false }`, `cpu.mbase = 0xD0`, IY = 0xD00080
- ROM at `TI-84_Plus_CE/ROM.rom`
- ES module imports from `./cpu-runtime.js`
- Set `cpu.registers.a` (or however the register is exposed — check cpu-runtime.js for the register interface) to seed A before execution

## Success criteria
- Probe runs: `node TI-84_Plus_CE/probe-phase235-02ffed-special-exit.mjs`
- Shows block chain and RAM state for both scenarios
- Includes hex dump of ROM bytes at 0x02FFED-0x030010
