# Task: Add 20 New Seeds to Transpiler

## Context
This is a TI-84 Plus CE ROM transpilation project. The transpiler is at `scripts/transpile-ti84-rom.mjs`. It lifts eZ80 machine code from `TI-84_Plus_CE/ROM.rom` into JavaScript. Seeds are entry point addresses that tell the transpiler where executable code starts.

Current state: 144,881 transpiled blocks, 708,219 covered bytes, ~95.92% true coverage.

## Task
1. Run the coverage analyzer to find uncovered gaps:
   ```
   node TI-84_Plus_CE/audit-true-uncovered.mjs
   ```

2. From the uncovered regions, identify 20 addresses that look like valid code entry points. Good candidates:
   - Start with common eZ80 instruction prefixes (PUSH AF=0xF5, PUSH BC=0xC5, PUSH DE=0xD5, PUSH HL=0xE5, LD A,n=0x3E, LD HL,nn=0x21, DI=0xF3, XOR A=0xAF, OR A=0xB7)
   - Are in the 0x000000-0x0FFFFF range (executable ROM region)
   - Are NOT in known data table regions
   - Have valid instruction sequences following them (not random data bytes)

3. Read `scripts/transpile-ti84-rom.mjs` to find where seeds are defined (look for the seeds array).

4. Add 20 new seed addresses to the seeds array in `scripts/transpile-ti84-rom.mjs`.

5. Re-run the transpiler:
   ```
   node scripts/transpile-ti84-rom.mjs
   ```

6. Run the golden regression to verify nothing broke:
   ```
   node TI-84_Plus_CE/probe-phase99d-home-verify.mjs
   ```

7. Print the before/after block count and byte count.

## Constraints
- ONLY modify `scripts/transpile-ti84-rom.mjs` (to add seeds)
- Do NOT modify cpu-runtime.js, peripherals.js, browser-shell.html, or any probe files
- Do NOT delete or modify existing seeds — only ADD new ones
- Seeds must be in the executable ROM region (0x000000-0x0FFFFF)
- Verify golden regression passes after adding seeds

## Success Criteria
- 20 new seeds added to the transpiler
- Transpiler runs successfully with increased block/byte counts
- Golden regression (probe-phase99d-home-verify.mjs) still passes
- Report the delta: how many new blocks and bytes were discovered
