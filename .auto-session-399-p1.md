# Task: Trace 0x03F9FA Key Result Producer — Who Calls It?

## Context
You are working on `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, a TI-84 Plus CE ROM transpilation project.

0x03F9FA is a critical function in the key pipeline. It writes to 0xD00587 (kbdGetKy result register) AND sets IY+0x00 bit 3 (the "key ready" flag). This signals to the consumer at 0x03FA09 that a key result is available.

The question: WHO CALLS 0x03F9FA? What processing happens between scan code deposit (at 0x003D4B writing to 0xD00587) and the result commit at 0x03F9FA? This is the missing middle of the key pipeline.

## What to do

Create a probe file `TI-84_Plus_CE/probe-phase399-trace-03F9FA.mjs` that:

1. Loads the ROM from `TI-84_Plus_CE/ROM.rom` (4MB file, raw binary)
2. Searches the ENTIRE ROM (0x000000–0x3FFFFF) for all CALL and JP instructions that target 0x03F9FA:
   - CALL nn: bytes CD FA F9 03 (3-byte address little-endian, but eZ80 uses 3-byte addresses for CALL/JP)
   - JP nn: bytes C3 FA F9 03
   - JP cc,nn: C2/CA/D2/DA/E2/EA/F2/FA followed by FA F9 03
   - CALL cc,nn: C4/CC/D4/DC/E4/EC/F4/FC followed by FA F9 03
   - NOTE: eZ80 addresses are 24-bit (3 bytes). Pattern for CALL 0x03F9FA = CD FA F9 03. Pattern for JP 0x03F9FA = C3 FA F9 03.
3. For each caller found, disassemble 32 bytes BEFORE the call site to understand the calling context
4. Also search for indirect references: LD HL,0x03F9FA (21 FA F9 03) or LD DE,0x03F9FA (11 FA F9 03)
5. Disassemble 0x03F9FA itself (64 bytes starting there) to confirm its behavior
6. Print all findings with addresses and hex dumps
