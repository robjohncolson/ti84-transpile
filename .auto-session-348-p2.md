# Auto-Session 348 — Priority 2: Investigate NMI Path (Port 0x3D Behavior)

## Context

The TI-84 CE NMI handler at 0x000066 does:
```
0x000066: PUSH AF
0x000067: IN0 A,(0x3D)       ; read port 0x3D
0x00006A: AND 3              ; mask bits 0-1
0x00006C: OUT0 (0x3E),A      ; write to port 0x3E  
0x00006F: JR Z,0x000047      ; if result is 0, jump back to signature check loop
```

Port 0x3D is likely the eZ80 "reset status register" or similar. If it returns 0, the NMI handler loops back to 0x000047 which is the boot signature-check loop (calls 0x0008BB, tests result, etc.). This creates an NMI-driven retry mechanism.

The address 0x000047 context: the boot flow around there is:
```
0x000047: CALL 0x0008BB      ; ROM signature check
0x00004A: ...                ; test Z flag
0x00004F: JP NZ,0x0019B5     ; if NZ, halt
```

## Task

1. Write a probe `TI-84_Plus_CE/probe-phase348-nmi-path.mjs` that:
   - Reads ROM.rom bytes at 0x000060-0x000080 and disassembles them (use ez80-decoder.js)
   - Reads ROM.rom bytes at 0x000040-0x000060 for the signature check loop context
   - Documents the full NMI handler flow from 0x000066 until it returns or loops
   - Identifies what port 0x3D likely represents on the eZ80 (check TI-84 CE hardware docs patterns in the codebase)
   
2. Check `TI-84_Plus_CE/peripherals.js` for port 0x3D handling:
   - Search for existing port 0x3D / 0x3E registrations
   - If not modeled, add a handler for port 0x3D that returns a reasonable default
   - Port 0x3D on eZ80 is likely the "Reset Identification" register. Bits 0-1 indicate reset source:
     - 0 = power-on reset
     - 1 = watchdog reset  
     - 2 = external reset pin
     - 3 = reserved
   - For a clean power-on boot, returning 0x01 (bit 0 = power-on) is appropriate. BUT the code does `AND 3` and `JR Z` — so if the result is non-zero, it does NOT jump back to 0x000047 and instead continues forward. That's the "normal NMI" path.
   - Actually looking again: if port 0x3D returns any value where (val & 3) != 0, NMI continues forward past JR Z. If (val & 3) == 0, NMI loops back. So for boot to proceed naturally via NMI, port 0x3D should return a non-zero value in bits 0-1.
   - Set port 0x3D to return `0x01` (power-on reset indicator) — this means NMI won't loop.

3. Also disassemble 0x000071-0x000090 to see what happens AFTER the NMI handler passes the JR Z check (the "forward" path).
