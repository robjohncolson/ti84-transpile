# Task: Decode 0x0935BF — Value Check in Blink Sub-Function

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). We are investigating the cursor blink system.

**Key finding**: In 0x096B65's sub-function (0x096BC3-0x096BED), at address 0x096BD3:
```
CALL 0x0935BF
LD A,(HL)       ; reads value at address returned in HL
CP 0x0E         ; compares against 0x0E
```

If the value != 0x0E: enters blink toggle path via `CALL 0x07F9FB; CALL 0x096BEE; RET`
If the value == 0x0E: takes alternate path via `CALL 0x096F67` (visibility gate #3), then `JP NZ,0x097960; RET`

Understanding what 0x0935BF returns and what value 0x0E represents completes the blink logic branching.

0x0935BF is in the 0x093xxx region. Session 503 shows 0x096B65 calls 0x093625 (formatting) — so the 0x093xxx region contains formatting/display helpers.

## eZ80 Instruction Reference
- In ADL mode, CALL nn = CD xx xx xx (4 bytes), JP nn = C3 xx xx xx (4 bytes)
- JR e = 18 xx (2 bytes, signed offset), JR cc,e = 20/28/30/38 xx
- LD A,(nn) = 3A xx xx xx (4 bytes), LD (nn),A = 32 xx xx xx
- LD HL,(nn) = 2A xx xx xx, LD (nn),HL = 22 xx xx xx
- LD HL,nn = 21 xx xx xx, LD A,n = 3E xx
- LD (HL),r = 70-77 (1 byte), LD r,(HL) = 46/4E/56/5E/66/6E/7E (1 byte)
- RET = C9, RET cc = C0/C8/D0/D8/E0/E8/F0/F8
- CP n = FE xx, CP (HL) = BE
- .SIS prefix = 0x40 (16-bit operands with MBASE)
- BIT/SET/RES via IY: FD CB dd xx
- RST 28h = E7 (BCALL, followed by 2-byte index)
- ADD HL,rr = 09/19/29/39 (1 byte)
- INC HL = 23, DEC HL = 2B
