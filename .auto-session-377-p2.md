# Task: Trace 0x001713 Caller After 0x0067F8 Returns HL=1

## Context

This is the TI-84 Plus CE ROM transpilation project. The OS ROM (eZ80 machine code) is lifted to JavaScript. We're tracing the key dispatch path in the OS event loop.

The key dispatch path is:
```
Event loop at 0x003A73 → _GetCSC at 0x003D5A → key available → 0x003A7D (dispatch entry)
0x003A7D: CALL 0x001713
0x003A81: JP NZ, 0x001933 (error/halt path)
0x003A85: JP 0x003A89
0x003A89: CALL 0x001853 (normal key handler)
0x003A8D: XOR A
0x003A8E: JP 0x000721
```

The function at 0x001713 calls 0x0067F8 (the GPIO checker). When 0x0067F8 returns:
- HL=0 (fail): the caller at 0x001713 does something that causes JP NZ,0x001933 → DI+HALT
- HL=1 (success): the caller should set Z flag → JP NZ not taken → falls through to 0x003A85 → 0x003A89 → 0x001853

## What to Do

Write a probe `TI-84_Plus_CE/probe-phase377-trace-001713.mjs` that:

1. **Static disassembly of 0x001713-0x001730**: Read ROM bytes and decode every instruction in this range using `ez80-decoder.js`. Show the full instruction listing with hex bytes and decoded mnemonics.

2. **Static disassembly of 0x001853-0x001870**: Same treatment for the normal key handler entry point.

3. **Dynamic trace with key injection**: 
   - Boot through all 3 phases (Phase 1 at 0x000000 z80 mode, Phase 2 at 0x08C331, Phase 3 at 0x0802B2)
   - Create peripherals with `{ timerInterrupt: false, gpioValue: 0xEE }` (bit 0 clear so GPIO check passes)
   - Seed flash signature at 0x020100 = [0x5A, 0xA5, 0x00]
   - Seed system flag at 0xD177BA = 0x00
   - Inject key: mem[0xD00587] = 0x09 (ENTER), mem[0xD00080] |= 0x08
   - Run from event loop entry 0x003A73 with 1M steps
   - Install onBlock callback that logs EVERY block visit for the first 200 steps after dispatch at 0x003A7D is reached
   - Track register state (A, F, HL, BC, DE, SP, IX, IY) at entry to each of these addresses: 0x003A7D, 0x001713, 0x0067F8, 0x001933, 0x003A85, 0x003A89, 0x001853, 0x000721
   - Report: which of the above addresses were reached, in what order, with what register values

4. **Also run a CONTROL scenario** with `gpioValue: 0xEF` (default, GPIO check fails) to confirm the old behavior (halts at 0x001933/0x001937).

Use `TI-84_Plus_CE/probe-phase375-both-seeds-test.mjs` as your template for the boot pattern. Copy its 3-phase boot, CPU snapshot/restore, `prepareEventLoop`, etc. verbatim.
