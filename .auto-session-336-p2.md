# Auto-session 336 — Priority (b): Enable keyboard input

## Goal
Find which RAM byte the OS bytecode interpreter ultimately reads for the keyboard scan result, and create a probe that injects a key press by writing directly to that RAM location, then verifies the event loop detects it.

## Context — Key dispatch flow (discovered in session 335)
1. CoorMon (0x08BF22) calls GetCSC at 0x042366 with A=3
2. Inner scan at 0x0421A7 → bytecode interpreter via jump table at 0x000310
3. Interpreter walks ROM data table at 0x3B0001 → after 68 steps returns HL=0x3B0033
4. Reads (HL) & 0x3F as scan result → stores in B
5. Critical branch at 0x08BF3C: `jr nz, +0x2A` to 0x08BF68 when A!=0 (key detected)
6. ZERO keyboard MMIO reads during event loop — the interpreter walks ROM tables, NOT hardware
7. Hardware scanning requires timer IRQ (disabled in probes)

## Three approaches (try approach (iii) first — it's the simplest)
(iii) **Direct RAM injection**: Find which RAM byte the bytecode interpreter at the jump table 0x000310 reads when walking the ROM data at 0x3B0001. The interpreter returns HL=0x3B0033 and reads `(HL) & 0x3F`. But 0x3B0033 is in ROM (read-only). The actual scan code may come from RAM locations updated by the timer ISR. Trace what the ISR at 0x1713→0x67F8 writes to RAM. Known keyboard RAM locations:
  - 0xD00587 (KBD_SCAN_CODE)
  - 0xD0058C (KBD_KEY)
  - 0xD0058E (KBD_GETCSC_RESULT)
  Try writing a scan code to each of these and running CoorMon to see if the branch at 0x08BF3C is taken.

(ii) **Call keyboard scan directly**: Find the subroutine in the 0x1713→0x67F8 ISR chain that does the actual matrix scan. Set up keyboard MMIO to return a key (write scan code to 0xE00800+group), then call that subroutine, then call CoorMon.

(i) **Enable timer IRQ with cycle limit**: Enable `timerInterrupt: true` but set a step limit so the ISR runs once and returns. Risk: may infinite-loop.

   - Did PC reach 0x08BF68 (key-detected path)?
5. Also disassembles the ROM data at 0x3B0001-0x3B0040 to understand the bytecode table structure
6. Reports which RAM location (if any) successfully injects a key
