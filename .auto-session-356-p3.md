# Task: Audit and clean up spurious z80-mode seeds in transpiler

## Context
TI-84 Plus CE ROM transpilation project. In session 355, we discovered that the eZ80 decoder had RSMIX/STMIX opcodes swapped with LD MB,A / LD A,MB. This caused the transpiler to incorrectly believe the CPU switched to z80 mode during boot, leading to spurious z80-mode seeds being added in sessions 340-352. After the fix, boot runs entirely in ADL mode — ZERO z80-mode transitions after the initial entry at 0x000000.

The transpiler file is `scripts/transpile-ti84-rom.mjs`. The z80-mode seeds are at these lines:
- Line 880: `{ pc: 0x00CA00, mode: 'z80' }` — Phase 173: error handler reset
- Line 881: `{ pc: 0x000008, mode: 'z80' }` — RST 08h vector, z80-mode entry from 0x00CA00
- Line 22298: `seedEntries.push({ pc: offset, mode: offset === 0 ? 'z80' : 'adl' });` — boot entry (offset 0 = z80, correct)
- Line 22301-22302: `{ pc: 0x00001A, mode: 'z80' }` — Phase 341: kernel init return address
- Line 22303-22304: `{ pc: 0x000800, mode: 'z80' }` — Phase 345: boot path
- Line 22305-22306: `{ pc: 0x009006, mode: 'z80' }` — Phase 342: kernel init
- Line 22307-22308: `{ pc: 0x00D7BE, mode: 'z80' }` — Phase 352: boot loop coverage

## What to do

1. **Create a probe** `TI-84_Plus_CE/probe-phase356-z80-seed-audit.mjs` that:
   - Boots from 0x000000 in z80 mode, runs 5000 steps with `timerInterrupt: false`, `pllDelay: 2`
   - Tracks which blocks are executed, specifically noting any z80-mode blocks (key ends with `:z80`)
   - Reports: how many z80-mode blocks are executed during boot? Which addresses?
   - Also checks: do any of the z80-mode seed addresses (0x00001A, 0x000800, 0x009006, 0x00D7BE, 0x00CA00, 0x000008) appear in the execution trace?

2. **If the probe confirms z80-mode seeds at 0x00001A, 0x000800, 0x009006, 0x00D7BE are NOT executed during boot**, remove those 4 seed entries from `scripts/transpile-ti84-rom.mjs` (lines 22301-22308). Keep the seeds at 0x00CA00 and 0x000008 (lines 880-881) — those are from Phase 173 (error handler) and may still be valid for non-boot paths. Keep the boot entry seed at offset 0 (line 22298) — that's the correct z80-mode entry point.

3. **After removing seeds**: run the transpiler (`node scripts/transpile-ti84-rom.mjs`) and report the new block count (was 144,190). Then run the golden regression (`node TI-84_Plus_CE/probe-phase99d-home-verify.mjs`) and confirm it still passes.

4. **Regenerate the .gz**: `cd TI-84_Plus_CE && gzip -kf -9 ROM.transpiled.js`

## Probe structure (MANDATORY)
Use the exact same boilerplate as `TI-84_Plus_CE/probe-phase355-rst38h-bypass.mjs`:
