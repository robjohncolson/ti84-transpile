# Task: Y= screen update loop 0x0A1B59 with varying counter values — row selection logic

## Context
In the TI-84 Plus CE ROM transpilation, the Y= editor display uses a 25-row counter at RAM 0xD00596. Session 196 decoded the row index formula: `C = 0x19 - D00596` at block 0x0A29D6. Session 197 entered the renderer 0x0A1799 directly but got IDENTICAL traces regardless of counter value (0/1/5) — 44 blocks in 500 steps. Hypothesis: the counter→row mapping happens in the CALLER (0x0A1B59) before 0x0A1799 is called, not inside 0x0A1799.

The screen update loop at 0x0A1B59 was decoded in session 196:
- Compares 0xD00595 vs 0xD02505
- Calls renderer 0x0A1799
- Increments 0xD00596
- Checks ≥26

## Goal
Enter at 0x0A1B59 (the screen update loop) with different values pre-loaded at 0xD00596 (the row counter: 0x19, 0x15, 0x10, 0x05, 0x00) and trace:
1. Whether different counter values produce DIFFERENT block traces (unlike 0x0A1799 direct entry)
2. Whether 0x0A29D6 (row index computation) is reached from this entry point
3. What VRAM addresses are written and whether they differ by counter value
4. How many iterations the loop runs before RET
