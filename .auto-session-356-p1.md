# Task: Trace NMI handler at 0x000066 + disassemble HALT context at 0x0019B5

## Context
This is a TI-84 Plus CE ROM transpilation project. We lift eZ80 machine code from a 4MB ROM into JavaScript. After session 355, the boot sequence now runs correctly in pure ADL mode (no spurious z80-mode transitions), reaching 273 unique blocks before HALTing at 0x0019B5 (DI + HALT). An NMI wake (PC → 0x000066) extends boot to 286 blocks, then it HALTs again.

## What to do

Create a probe file `TI-84_Plus_CE/probe-phase356-nmi-handler-trace.mjs` that:

1. **Boots the ROM** from 0x000000 in z80 mode with `timerInterrupt: false`, `pllDelay: 2`
2. **Runs until HALT** (result === -1 from `executor.runFrom`), recording all visited blocks
3. **On first HALT**: logs PC, SP, all registers (A, F, BC, DE, HL, IX, IY, MBASE), and the port I/O history leading up to HALT
4. **Triggers NMI** by setting cpu.pc = 0x000066 and continues execution
5. **Records the NMI handler path**: every block visited from 0x000066 onwards (with per-block register snapshots for A, F, SP, PC)
6. **On second HALT**: logs same register dump + all NEW blocks discovered (those not seen before the first HALT)
7. **Disassembles ROM bytes** at 0x0019B0-0x001A00 (16 bytes before HALT through 80 bytes after) using raw hex dump with annotations for common eZ80 opcodes (DI=0xF3, HALT=0x76, NOP=0x00, RET=0xC9, JP=0xC3, etc.)
8. **Disassembles ROM bytes** at 0x000060-0x0000A0 (NMI vector region) similarly
9. **Reports**: What address does boot reach before HALT? What does the NMI handler do? Does it read any ports or RAM flags? Does it return (RETN/RETI) or jump somewhere new?

## File structure pattern
Follow the exact same structure as `TI-84_Plus_CE/probe-phase355-rst38h-bypass.mjs`:
- Import pattern: `import { execFileSync } from 'node:child_process'; import fs, path, process, { fileURLToPath, pathToFileURL }`
- `process.emitWarning = () => {};`
- Constants: `MEM_SIZE = 0x1000000`, `BOOT_ENTRY = 0x000000`, `BOOT_MODE = 'z80'`
- `ensureTranspiledRom()` function that checks for ROM.transpiled.js (runs transpiler if missing via gz)
- `createMemory(romBytes)` — copies ROM into 16MB Uint8Array
- Load modules via `pathToFileURL` + dynamic import:
```js
const cpuMod = await import(pathToFileURL(CPU_RUNTIME_PATH).href);
const periMod = await import(pathToFileURL(PERIPHERALS_PATH).href);
const createExecutor = cpuMod.createExecutor ?? cpuMod.default?.createExecutor;
const createPeripheralBus = periMod.createPeripheralBus ?? periMod.default?.createPeripheralBus;
```
- Transpiled blocks loaded via: `const transpiledMod = await import(pathToFileURL(TRANSPILED_PATH).href);`
- `normalizeBlocks()` handles both array and object block formats
- Create executor: `const executor = createExecutor(blocks, mem, { peripherals });`
- Run via: `const result = executor.runFrom(cpu.pc, cpu.adl ? 'adl' : 'z80');`
- HALT detection: `result === -1`
- NMI wake: set `cpu.pc = 0x000066` then continue calling `executor.runFrom(cpu.pc, ...)`

## Key constraint
- `createPeripheralBus({ pllDelay: 2, timerInterrupt: false })` — do NOT enable timer
- The executor does NOT have a `cpu.step()` method — use `executor.runFrom(pc, mode)` which runs one block and returns the next PC (or -1 for HALT, or a string like "missing_block:ADDR" for uncovered blocks)
- Set `cpu.pc = BOOT_ENTRY` and `cpu.adl = false` (z80 mode) initially. The ROM will switch to ADL mode itself.
- The `wakeFromHalt` option on `createPeripheralBus` does NOT exist. Handle HALT manually by checking `result === -1` and then setting `cpu.pc = 0x000066`.
