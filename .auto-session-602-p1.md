# Auto-Session 602 — Priority 1: FIND THE D007CA RE-ARM MECHANISM

## Context

This is a TI-84 Plus CE ROM transpilation project. The lifted OS runs real eZ80 code as JavaScript. We've confirmed the full keypress→render round-trip works (digit '2' renders to VRAM), but **D007CA (the cxMain dispatch vector)** gets zeroed during key processing and is NEVER re-armed by any part of the key-processing or event-loop machinery.

D007CA holds the address of cxMain (0x0585E9). The outer loop at 0x08C331 does `LD HL,(D007CA); JP (HL)` — when D007CA=0, it jumps to 0x000000 (reset vector) instead of cxMain, so no further keys can be dispatched.

Session 601 confirmed: ZERO of 19 known `LD (D007CA),HL` writer addresses fire during the 276K-step first-key path (1,962 unique blocks). The outer loop's second pass also doesn't re-arm it (session 600).

## Task

Statically decode ALL 19 D007CA writer addresses to understand what function each is part of and what triggers it. The 19 addresses cluster into:

1. **INIT cluster** (near MEM_INIT 0x09DEE0):
   - 0x09D327
   - 0x09D33D  
   - 0x09D353

2. **CONTEXT-MANAGER cluster**:
   - 0x0AB767
   - 0x0AB8E7
   - 0x0ABA7D
   - 0x0ABB09
   - 0x0ABE84

3. **Descriptor machinery** (0x080xxx, 4 refs):
   - Find these 4 addresses by grepping the session logs or by searching `CONTINUATION_PROMPT_CODEX.md` for "D007CA" references.

4. **Scattered others** (remaining of 19):
   - Find these similarly.

For each address:
1. Read 64 bytes of ROM starting at the address using the ROM file at `TI-84_Plus_CE/ROM.rom` (4MB binary, little-endian eZ80 in ADL mode)
2. Decode the eZ80 instructions manually or use the decoder at `TI-84_Plus_CE/ez80-decoder.js`
3. Identify the parent function (scan backward for typical function prologues or forward references)
4. Determine what conditions trigger this code path
