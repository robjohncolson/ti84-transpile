# Task: Decode 0x07BF3E — Glyph Table Lookup

## Context
You are working on a TI-84 Plus CE ROM (eZ80) transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 machine code). We decode ROM functions by reading raw bytes and disassembling them manually (eZ80 instruction set).

0x07BF3E is called by 0x0A23C0 (pre-render setup, 28 bytes, 20 callers). The calling sequence in 0x0A23C0 is:
```
LD L,A           ; L = character code
LD H,0x1C        ; H = 28 (decimal)
ED 6C            ; MLT HL — HL = H × L = 28 × char_code
CALL 0x07BF3E    ; glyph table lookup with HL = offset
LD HL,0xD005A4
LD (HL),0x0C     ; store 12 at D005A4
RET
```

So 0x07BF3E receives HL = 28 × character_code. This strongly suggests it's a glyph table lookup — each glyph is 28 bytes, and HL is the byte offset into the glyph data. The function likely loads a pointer to the glyph bitmap/data and stores it somewhere (possibly in IX, which the renderer later uses for glyph pointer setup).

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase552-decode-07BF3E.mjs` that:

1. Reads raw bytes from ROM at 0x07BF3E for ~100 bytes
2. Disassembles them as eZ80 instructions (ADL mode, 24-bit addresses)
3. Looks for: base address addition (ADD HL,<base>), memory reads to get glyph data pointer, stores to IX or other registers, any font table base addresses in ROM
4. Prints a clear disassembly with annotations

## eZ80 Decoding Reference
- The ROM file is a flat binary. Address 0x07BF3E = file offset 0x07BF3E.
- eZ80 ADL mode: default 24-bit addresses and 24-bit registers.
- Common opcodes: CB = bit ops, ED = extended ops, DD = IX prefix, FD = IY prefix, 40 52 = SIS prefix
- LD instructions, CALL (CD xx xx xx = 4 bytes in ADL), JP (C3 xx xx xx), JR (18/20/28/30/38 xx), RET (C9)
- ADD HL,rr (09/19/29/39), LD rr,(nn) for loading base addresses
- Key: if it adds HL to a base ROM address, that base address is the font/glyph table start
