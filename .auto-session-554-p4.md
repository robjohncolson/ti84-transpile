# Task: Decode 0x0A1B14 — Sub-byte Alignment Table and Mono Blit Usage

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary).

Session 553 found that at 0x0A1B14 there is a sub-byte alignment table used in the 1bpp (monochrome) framebuffer mode:
- Table contents: [0x80, 0x40, 0x20, 0x10, 0x08, 0x04, 0x02, 0x01]
- These are single-bit masks for each bit position within a byte (MSB-first)
- Used in the mono rendering path of the framebuffer address computation (0x0A1A9D, 119B)
- In 1bpp mode, each byte represents 8 pixels, so x-coordinate modulo 8 indexes this table to get the bit mask

We need to:
1. Decode the code that USES this table (what comes before and after the table at 0x0A1B14)
2. Understand the full mono blit addressing logic
3. Find all callers/references to this table

## Known context
- 0x0A1A9D = framebuffer address computation (119B, decoded in session 553)
- 0x0A1A9D ends around 0x0A1B14 (119 bytes from 0x0A1A9D = 0x0A1B14 exactly!)
- So 0x0A1B14 may be data AFTER the 0x0A1A9D function, or the last few bytes of it
- The table is 8 bytes: 0x0A1B14-0x0A1B1B
- 0x0A1B1C was referenced as a call target in the blit loop (session 552: "CALL 0x0A1A9D and CALL 0x0A1B1C")
- So 0x0A1B1C is a SEPARATE FUNCTION right after the table

## Your task
1. Read ROM bytes from 0x0A1B00 to 0x0A1B80 (128 bytes covering the table and surrounding code)
2. Verify the 8-byte table at 0x0A1B14
3. Decode the function at 0x0A1B1C (which starts right after the table)
4. Look backward from 0x0A1B14 into the end of 0x0A1A9D to see how the table is referenced
5. Search the ROM for all references to 0x0A1B14 and 0x0A1B1C

## How to read ROM bytes
```javascript
import { readFileSync } from 'fs';
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
const start = 0x0A1B00;
const bytes = rom.slice(start, start + 128);
for (let i = 0; i < bytes.length; i += 16) {
  const addr = start + i;
  const hex = Array.from(bytes.slice(i, i + 16)).map(b => b.toString(16).padStart(2, '0')).join(' ');
  console.log('  0x' + addr.toString(16).padStart(6, '0') + ': ' + hex);
}
```

## How to search for references
Search for little-endian encodings:
- 0x0A1B14 → bytes 14 1B 0A
- 0x0A1B1C → bytes 1C 1B 0A

## eZ80 opcode reference (ADL mode)
- 0xC9 = RET
- 0xCD = CALL imm24
- 0x21 = LD HL,imm24
- 0x11 = LD DE,imm24
- 0x01 = LD BC,imm24
- 0x09 = ADD HL,BC, 0x19 = ADD HL,DE, 0x29 = ADD HL,HL
- 0xED 0x6C = MLT HL
- 0x7E = LD A,(HL), 0x77 = LD (HL),A
- 0xE6 = AND imm8
- 0xCB 0x3F = SRL A (shift right logical)
- 0xCB 0x27 = SLA A (shift left arithmetic)
- 0x40 = SIS prefix (16-bit mode)
