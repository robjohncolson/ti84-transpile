# Auto-Session 335 — Priority 1: Trace OS Key Dispatch through 0x08BF22

## Context
The TI-84 Plus CE OS main event loop has been identified at 0x08BF22 (CoorMon). Session 334 found it runs 7350 steps through 204 unique blocks. The flow includes: calls 0x042366 (GetCSC-related) → key-scanning loop at 0x001C33-0x001CE5 → LCD busy-wait at 0x09EFDE → reads scan-to-keycode table at 0x09F736 → display refresh → returns.

## Task
Write a probe `TI-84_Plus_CE/probe-phase335-key-dispatch.mjs` that:

1. Boots the OS using the standard staged-boot pattern (see any existing probe like `probe-phase334-event-loop.mjs` for the pattern)
2. After boot completes, sets up a key press by writing to the keyboard matrix. Use ENTER key: `keyMatrix[6] |= 0x01` (group 1, bit 0 — but remember keyMatrix[N] = SDK Group(7-N), so SDK group 1 = keyMatrix[6]). The keyboard matrix is in peripherals.js.
3. Runs the event loop at 0x08BF22 with a step limit of ~50000
4. Instruments reads/writes to these key RAM locations:
   - kbdScanCode: 0xD00587 (1 byte)
   - kbdKey: 0xD0058C (1 byte) 
   - kbdGetCSC result byte: 0xD0058E (1 byte)
5. For each access to those addresses, logs: the PC address, whether it's a read or write, and the value
6. Traces which blocks are visited after the key scan code is read — these are the key dispatch path
7. Maps the scan-to-keycode table at 0x09F736: dump 64 bytes starting there to see the scan code → token mapping
