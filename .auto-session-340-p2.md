# Auto-session 340 P2: Trace 0x0582B8 and HOME_HANDLER area

## Context

The TI-84 Plus CE OS CoorMon (coordinate monitor at 0x08BF22) does NOT dispatch to context handlers via the cxMain pointer at 0xD007CA. Session 339 proved this definitively. However, CoorMon has three known callers in ROM:
- 0x05CD62 (CALL NZ)
- 0x040CAD (CALL)
- 0x0582B8 (CALL — near HOME_HANDLER 0x058241)

The hypothesis is that HOME_HANDLER (0x058241) contains its own CoorMon call loop — meaning the OS architecture is "context handler wraps CoorMon" not "CoorMon dispatches to context handler."

## Task

Create a probe `TI-84_Plus_CE/probe-phase340-home-handler-disasm.mjs` that:

1. Reads the ROM binary (`TI-84_Plus_CE/ROM.rom`)
2. Disassembles the region 0x058241 through 0x0582E0 (about 160 bytes) using the eZ80 decoder
3. For each instruction, print: `addr: hex_bytes  mnemonic  [operands]`
4. Specifically annotate:
   - Any CALL instructions (target address)
   - Any JP instructions (target address)
   - Any LD instructions referencing 0xD007CA (cxMain pointer)
   - Any RET / RET cc instructions
   - The CALL at 0x0582B8 (should be CALL 0x08BF22 = CoorMon)
5. Also disassemble the other two CoorMon caller sites with 20 bytes of context each:
   - 0x05CD50 through 0x05CD70 (around the CALL NZ at 0x05CD62)
   - 0x040CA0 through 0x040CC0 (around the CALL at 0x040CAD)
6. Print a summary: "Does HOME_HANDLER contain a CoorMon loop? (look for JR/JP back to CALL CoorMon)"

## Key Architecture

- ROM file: `TI-84_Plus_CE/ROM.rom` — 4MB raw binary, load with `fs.readFileSync`
- eZ80 decoder: `import { decodeInstruction } from './ez80-decoder.js'`
  - Call: `const instr = decodeInstruction(rom, pc, /* adlMode */ true)`
  - Returns object with: `instr.length` (byte count), `instr.mnemonic`, `instr.operands` (array), `instr.bytes` (raw bytes)
  - adlMode=true for 24-bit addresses (TI-84 CE default)
- If `decodeInstruction` doesn't exist or has a different API, fall back to manual byte reading:
  - Read bytes at address, format as hex
  - Look for CALL patterns: 0xCD followed by 3-byte LE address (in ADL mode)
  - Look for JP patterns: 0xC3 followed by 3-byte LE address
  - Look for JR patterns: 0x18 (JR), 0x20 (JR NZ), 0x28 (JR Z), 0x30 (JR NC), 0x38 (JR C) followed by signed offset byte
