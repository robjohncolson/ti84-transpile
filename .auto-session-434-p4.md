# Task: Map the Full OS API Jump Table (374 JP Thunks at 0x000080-0x000654)

## Context
In the TI-84 Plus CE ROM (eZ80, file `TI-84_Plus_CE/ROM.rom`), the region 0x000080-0x000654 contains 374 contiguous JP thunks forming the TI OS system call dispatch table. Each thunk is exactly 4 bytes: `JP target_addr` (opcode 0xC3 followed by 3-byte little-endian target address). ISR vectors occupy 0x000000-0x00007F (8 bytes each, 7 vectors, DI+STMIX+JP format).

Session 433 identified this table but only named a few entries. The TI-84 CE SDK has a well-known export table. The goal is to extract ALL 374 JP targets and cross-reference as many as possible with known names.

## Deliverables
1. Create `TI-84_Plus_CE/probe-phase434-os-api-table.mjs` — a Node.js probe that:
   - Loads the ROM from `TI-84_Plus_CE/ROM.rom`
   - Reads all 374 JP thunks from 0x000080 to 0x000654 (each 4 bytes: opcode + 3-byte LE target)
   - For each slot: extract slot index, source address, target address
   - Verify each starts with 0xC3 (JP opcode); flag any non-JP entries
   - Cross-reference targets with known functions:
     - 0x0021C2 = _Null_check
     - 0x002623 = _seqcase

     - 0x0022F9 = shift-left-8
     - 0x00224C = (unknown, duplicate target for slots 53/54)
   - Count unique targets, find duplicates (multiple slots → same target)
   - Output: full table (slot#, addr, target, name_if_known), duplicate analysis, statistics

## Known TI-84 CE SDK Syscall Info
The TI-84 CE SDK (CE toolchain / CEdev) exports system calls by number. Some known mappings:
- Syscall 0 (0x000080) = typically _os_GetCSC or similar
- The SDK header files (ti/getcsc.h, ti/screen.h, etc.) define syscall numbers
- Many syscalls are in the range 0x020000-0x021000 (OS 5.x jump table in high ROM)

Note: The 0x000080 table may be the BOOT-level dispatch, while 0x020000+ is the OS-level dispatch. Map what's actually there.
