# Task: Trace 0x002288 Completion Dispatcher

You are working on a TI-84 Plus CE ROM transpilation project. Your job is to trace the function at ROM address 0x002288 — a completion dispatcher called by the Channel 2 notification completion callback at 0x015185.

## Context

- Session 414 decoded 0x015185 (33 bytes, 0x015185-0x0151A5): it clears D17779, sets D1777A=1, then calls 0x002288 with args (3, 0) on the stack.
- 0x002288 is therefore the final step of Channel 2 notification completion.
- We need to know: what does 0x002288 do? Does it update D177B7 sentinel? Clear D143EA? Route cleanup by channel ID?

   - Reads the ROM binary at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 CPU, little-endian, 24-bit addresses)
   - Disassembles starting at 0x002288, following linear flow (CALL targets noted but not followed, JP targets followed if unconditional)
   - Stops at RET or after 200 bytes
   - Reports every instruction with address, hex bytes, and mnemonic
   - Identifies all RAM references (addresses >= 0xD00000), port I/O, CALL targets, and JP targets
   - Look for patterns: stack frame setup (CALL 0x00218A or CALL 0x002197), CP comparisons (dispatching on channel ID?), RAM writes to D177B7/D143EA/D1440E or other notification RAM

## eZ80 decoding notes

- eZ80 is a superset of Z80 with 24-bit addresses. Most instructions are 1-4 bytes.
- LD r,(addr) uses 3-byte little-endian absolute addresses
- CALL addr and JP addr use 3-byte addresses
- Prefixes: 0xDD=IX, 0xFD=IY, 0xED=extended, 0xCB=bit ops
- 0x40 can be a .SIS prefix (changes immediate size to 16-bit) — check context
- Common stack frame: CALL 0x00218A (allocates frame, sets IX), CALL 0x002197 (variant)
- Common null check: CALL 0x0021C2 (SBC HL,0; JP Z exit)
