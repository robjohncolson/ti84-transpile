# Task: Disassemble 0x02FF00-0x030000 (Translation Dispatcher Continuation)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80 binary). Session 385 disassembled 0x02FE00-0x02FF20 but the translation dispatcher continues beyond that range. Key JP targets at 0x02FFF6 (2ND mode path) and 0x02FFED need disassembly.

## What you need to know
- The eZ80 CPU is a Z80 superset with 24-bit addresses (ADL mode)
- Session 385 found the translation dispatcher handles modifier keys (2ND/ALPHA)
- At 0x02FECF: BIT 3,(IY+0x12) tests 2ND mode flag → JP NZ,0x02FFF6 if set
- At 0x02FED7: BIT 4,(IY+0x12) tests ALPHA mode flag → JP NZ,0x0300CB if set
- Default path loads DE=0x09F79B + CALL 0x022346 (table lookup)
- Internal control flow loops back to 0x02FDBE/0x02FD99
- RAM refs: 0xD0058C (kbdKey), 0xD0058E (kbdToken), 0xD00591

## Your task
Write a Node.js probe at `TI-84_Plus_CE/probe-phase386-disasm-02FF.mjs` that:

1. Reads ROM.rom bytes from 0x02FF00 to 0x030000 (256 bytes)
2. Performs static eZ80 disassembly of this range in ADL mode
3. For each instruction, print: address, hex bytes, mnemonic, operands
4. Identify and annotate:
   - What happens at 0x02FFF6 (the 2ND mode JP target)
   - What happens at 0x02FFED
   - Any CALL/JP targets (both internal and external)
   - Any RAM reads/writes (especially 0xD0058C-0xD00591 range)
   - Any port I/O
   - RET/RETI instructions
   - How control flow connects back to the 0x02FE00 region

## How to disassemble eZ80
Read `TI-84_Plus_CE/ez80-decoder.js` for the instruction decoder. Use it like:
```js
import { decodeInstruction } from './ez80-decoder.js';
const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');
// decodeInstruction(rom, offset, adlMode) returns {mnemonic, operands, length, bytes}
```

## Deliverables
- `TI-84_Plus_CE/probe-phase386-disasm-02FF.mjs` — the probe script
- Run it and include output in stdout
- Summarize findings: what does the 2ND mode path do differently from ALPHA mode?
