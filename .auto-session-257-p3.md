# Auto-session 257 P3: Extended boot (200K+ steps) to find cx* field population

## Context
This is a TI-84 Plus CE ROM transpilation project. Session 256 confirmed that cx* handler fields (D007CA-D007E0) are ALL 0x000000 after cold boot + MEM_INIT + 50K CoorMon steps. The context structure is populated during APP ACTIVATION, not boot. We need to run a much longer boot to see if/when the fields get populated.

The standard boot sequence is:
1. Cold boot (cpu.coldBoot())
2. kernelInit (entry at 0x000100 or wherever the recent probes start)
3. memInit
4. Homescreen stages 1-4 (each needs IX=0xD1A860)
5. CoorMon (the main event loop)

## Task
Create a probe file `TI-84_Plus_CE/probe-phase257-extended-boot-cx.mjs` that:

1. **Full boot sequence**: Execute the standard boot through all homescreen stages, then run CoorMon for **200,000 steps** (not just 50K).

2. **Instrument D007CA-D007E0 writes**: Hook write8/write16/write24 to log ANY write in the range D007CA-D007E0. For each write, record:
   - Step number
   - Address written
   - Value written
   - Current PC (curPC from executor)

3. **Instrument D00824 writes**: Same logging for D00824.

4. **Checkpoint snapshots**: At steps 50K, 100K, 150K, and 200K, dump the full D007CA-D007E0 range (24 bytes) and D00824.

5. **Track 0x08C8CF (NewContext) calls**: If PC passes through 0x08C8CF or 0x08C79F (the context switch function), log the step number and register A.

6. **Track 0x09E2EC (context-registration) calls**: If PC passes through 0x09E2EC, log step number and register A.

## Boot setup pattern (COPY FROM recent probes — look at probe-phase256-*.mjs for exact pattern)
The boot pattern from recent probes uses:
```js
import { createExecutor, createMemory } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
import { readFileSync } from 'fs';

const mem = createMemory();
const bus = createPeripheralBus({ timerInterrupt: false });
const cpu = createExecutor(mem, bus);
const rom = readFileSync(new URL('./ROM.rom', import.meta.url));
mem.set(rom, 0);
cpu.coldBoot();
```

Then kernelInit, memInit, and homescreen stages 1-4. **Look at `probe-phase256-062055-ram-pointer.mjs` or `probe-phase256-d00824-handler-xref.mjs` for the EXACT boot sequence used in session 256** — copy it verbatim.

Important: Each homescreen stage needs `IX = 0xD1A860` set before entry. The stages are run via specific entry points — check recent probes for the exact addresses.

## Constraints
- Do NOT modify any existing files
- Create ONLY `TI-84_Plus_CE/probe-phase257-extended-boot-cx.mjs`
- Use `createPeripheralBus({ timerInterrupt: false })`
- **Disable timer interrupt** — critical
- Use ADL mode (MADL=1)
- If the boot takes too many steps before CoorMon, limit total to 300K steps
- Print progress every 50K steps

## Success criterion
Probe runs via `node TI-84_Plus_CE/probe-phase257-extended-boot-cx.mjs` and prints:
- Any D007CA-D007E0 write events with step/address/value/PC
- Any D00824 write events
- Checkpoint snapshots at 50K/100K/150K/200K
- Any 0x08C8CF/0x08C79F/0x09E2EC visits with step and A register
- Summary: did cx* fields get populated? At what step? By what function?
