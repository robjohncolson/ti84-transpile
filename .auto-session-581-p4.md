# Task: DECODE 0x08C509 — Common Key Processing Path

## Context
This is part of TI-84 Plus CE ROM transpilation. The OS event loop key dispatch cascade at 0x08C3C3+ routes multiple key codes to a common processing path at 0x08C509. Specifically, session 579 found that keys 0x3F (?), 0x28 (left paren), 0x29 (right paren), 0xFE (format), and 0xFC (recall) all route to 0x08C509 via JR/JP. This function has NOT been decoded yet.

The dispatch cascade is at 0x08C3C3 (~600 bytes). After checking for QUIT (0xB4), it cascades through CP comparisons. Keys 0x3F/0x28/0x29/0xFE/0xFC all converge to 0x08C509 for common processing before continuing to `CALL 0x022331` (key processor) + `CALL 0x08C72F` (display refresh) → `JP 0x08C331` (event loop return).

## Your Task
Write a probe at `TI-84_Plus_CE/probe-phase581-decode-08C509.mjs` that statically disassembles the function/block at 0x08C509 and write a report to `TI-84_Plus_CE/phase581-decode-08C509-report.md`.

### What to do
1. Read ROM bytes: `import fs from 'fs'; const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');` then `rom[addr]`.
2. Decode eZ80 instructions from raw bytes. eZ80 = Z80 superset, ADL mode (24-bit addresses):
   - `0xCD nn nn nn` = CALL addr (3-byte LE)
   - `0xC3 nn nn nn` = JP addr
   - `0xC9` = RET
   - `0x18 dd` = JR dd; `0x20 dd` = JR NZ; `0x28 dd` = JR Z
   - `0xCB` = bit ops; `0xFD` = IY; `0xDD` = IX; `0xED` = extended
   - `0x3E` = LD A,n; `0x21 nn nn nn` = LD HL,addr
   - `0xFE nn` = CP n
3. Decode at least 150 bytes from 0x08C509 (or until you reach 0x08C72F which is the known display refresh call, or a terminal JP).
4. Also decode the convergence path AFTER 0x08C509 — the session 579 notes say all paths converge to `CALL 0x022331` (key processor) + `CALL 0x08C72F` (display refresh) → `JP 0x08C331`. Find where these CALLs are in the byte stream.
5. Look for:
   - What "common processing" means: does it transform the key code? Store it? Set flags?
   - RAM references (0xD00000-0xD3FFFF), especially D0058E (previous key buffer), D0146D (pending key)
   - IY+offset operations
   - CALL targets — what subroutines does common processing invoke?
   - The multi-char token insertion loop at 0x08C41D (DJNZ B=8, D0065A string table) — is it before or after 0x08C509?
6. Count callers/jump-ins: grep ROM for bytes encoding references to 0x08C509.

### Report format
`phase581-decode-08C509-report.md`:
- Block address, size, instruction count
- Full annotated disassembly
- RAM refs, IY flags, CALL targets
- How many distinct entry points jump/jr into this block?
- Architectural summary: what does "common key processing" do? How does it prepare the key for 0x022331?

### Constraints
- Do NOT modify any existing file
- Do NOT run any probes
- Static analysis only

### Success Criterion
Report accurately decodes the common key processing path and explains how keys are prepared for the key processor call.
