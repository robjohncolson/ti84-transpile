# Auto-Session 605 — P4: OS State Restoration — Multi-Key Dispatch with Full State Restore

## Context

The TI-84 Plus CE OS ROM is transpiled to JavaScript. Session 603 proved that restoring D007CA after the bulk wipe enables a second keypress dispatch through cxMain. BUT the wipe recurs on every key (0x0018F8 fires again during the second key's processing).

Session 604 revealed that VRAM is NOT destroyed by the wipe (D40000+ is outside wipe range D00000-D13FD7). Only OS state is destroyed. This means the real fix may be simpler: after each wipe, restore the minimal OS state needed for continued operation.

Session 603's probe (`probe-phase603-context-restore-fix.mjs`) restored:
- D007CA: 21-byte context descriptor from ROM 0x0585D3
- D0008D: one byte from ROM 0x0585D3+21
- D0231A: edit cursor (saved from post-paint)
- D0243A: edit cursor (saved from post-paint)

This was enough for cxMain to dispatch the second key. **But we need to verify that THREE consecutive keys work, and check what other state needs restoration.**

## Task

Create a probe `TI-84_Plus_CE/probe-phase605-multikey-restore.mjs` that:

1. Boots the OS the same way as `probe-phase603-context-restore-fix.mjs` (copy Phases 0-2 verbatim)
2. After paint, save a FULL snapshot of the key OS state:
   - D007CA (3 bytes — context pointer)
   - 21 bytes starting at D007CA (the context descriptor block)
   - D0008D (1 byte)
   - D0231A, D0243A (3 bytes each — edit cursors)
   - D02434 (3 bytes — descriptor block pointer)
   - D0009F (1 byte — event flags)
   - D0058C, D0058E (1 byte each — scan codes)
   - D00080-D000FF (128 bytes — IY flag area, includes IY+0x42=D000C2)
3. Process THREE keys in sequence: '2' (0x90), '3' (0x91), '+' (0x70):
   For EACH key:
   a. Restore the saved OS state snapshot (all fields above)
   b. Seed the key into D0058C/D0058E and set D0009F bit 5
   c. Set up SP and longjmp anchor (copy from probe-603 Phase 5)
   d. Run from 0x08C331 with maxSteps=500000, tracking cxMain (0x0585E9), wipe (0x0018F8), and VRAM
   e. After run, report: cxMain hit?, wipe hit?, D007CA final value, VRAM count, steps, halt PC
4. After all 3 keys, print a summary:
   - How many of 3 keys dispatched through cxMain?
   - Was the wipe triggered on each? (expected: yes)
   - Final VRAM pixel count (does it keep growing with each key?)
5. Generate a report file `TI-84_Plus_CE/phase605-multikey-restore.md` with detailed per-key results

## Reference Files
