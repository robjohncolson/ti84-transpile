# Task: TEST IDLE CURSOR PATH (D00000=0) WITH D00092 BIT 4

## Context
This is a TI-84 Plus CE ROM transpilation project. The OS event loop at 0x02FDBE has TWO mutually exclusive paths:
- D00000=1 → display update path (0x030078 → LCD port config, NOT pixel writes)
- D00000=0 → idle/cursor path (0x03030E → 0x02FD99 → CALL 0x03013A → 0x04E950 cursor pixel rendering)

Session 479 proved the display update path (D00000=1) does NOT call 0x04E950. The cursor pixel rendering is on the IDLE path (D00000=0) through 0x03013A.

The cursor glyph selector at 0x030202 requires D00092 bit 4 SET to proceed (bit 4 clear → RET Z immediately, no cursor).

## What to do
Create `TI-84_Plus_CE/probe-phase480-idle-cursor-path.mjs` that:

1. Does 3-stage boot (0x080000, 0x0802B2, 0x08C331 — 150K steps each)
2. Sets up home mode state:
   - D00824=0x48, D007E0=0x48, D14091=0x01
   - D00000=0x00 (IDLE path — this is the key difference from previous probes)
   - D00092=0x16 (bits 1,2,4 set — bit 4 enables cursor)
   - D00089|=0x10 (bit 4, unlocks 0x03D1BE)
   - D000C6=0x01
   - D000B4=0x01
   - D00080|=0x18
   - D0059C=0xD40000 (VRAM base)
   - D00595=0x00, D00596=0x00
   - D0058B=0x70
   - mbase=0xD0, IY=0xD00080
3. At every 0x02FDBE iteration (onBlock):
   - Refresh D00092 |= 0x10 (bit 4, cursor active)
   - Refresh D000C6 |= 0x01
   - Reset SP to STACK_RESET_TOP-3 (0xD1A87E-3)
4. At RET points (0x02FE88, 0x02FDE5, 0x02FE21):
   - Write return address (EVENT_LOOP_HEAD=0x02FDBE) at SP, reset SP
5. Track hits on: 0x02FDBE, 0x03013A, 0x030202, 0x04E950, 0x09EF44, 0x0059C6, 0x005A75, 0x030078, 0x03030E
6. Run 1M steps from 0x02FDBE
7. Report: VRAM bytes changed, hit counts, D00092 final value, D00595/D00596/D0059C final values
