# Task: Decode 0x07F7BD — Type/Descriptor Utility

## Context
0x07F7BD is a frequently-called utility in the TI-84 Plus CE FPU. Known callers:
- 0x07FF03 (zero-type handler): `CALL 0x07F7BD` for low exponents (<0x1D)
- 0x07CA02 (OP1 sign toggle): `CALL 0x07F7BD` to load OP1 type
- 0x0686A8 (type sub-dispatch): `CALL 0x07F7BD` to load type
- 0x09953F (conditional FP validation): `CALL 0x07F7BD` to load type
- 0x07FF59 (calling context): `CALL 0x07F7BD; RET Z. CP 0x0E; JR Z,0x07FF77`
- 0x08017C: `CALL 0x07F7BD`, JR→0x080177

From usage patterns, this appears to be a "load OP1 type into A" utility. The callers consistently use the result in A for type comparisons (CP 0x1C, CP 0x1D, CP 0x20, CP 0x21, CP 0x0E, etc.) and test flags (RET Z, JR NZ).

A related function 0x07F7D6 is called "type sign strip" — 0x07F7BD may be related.

## Task
Write a probe script that reads the raw ROM bytes starting at 0x07F7BD and disassembles them manually. The function is likely small (5-20 bytes). Look for:
- LD A,(D005F8) — load OP1 type byte
- AND 0x3F — strip sign bits (if it does stripping)
- OR A — set flags
- RET or further processing

Also decode any bytes between 0x07F7BD and 0x07F7D6 (the next known function), as this region may contain additional small utilities.

## Deliverables
- Create `TI-84_Plus_CE/probe-phase539-decode-07F7BD.mjs`
- Run it via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase539-decode-07F7BD.mjs`
- Print: raw hex dump of 0x07F7BD-0x07F7E0 (at least), followed by manual disassembly

## eZ80 instruction reference (key opcodes)
- 3A xx xx xx = LD A,(addr) [4 bytes in ADL mode]
- E6 xx = AND imm8
- B7 = OR A (set flags from A)
- FE xx = CP imm8
- C9 = RET
- C0 = RET NZ, C8 = RET Z, D0 = RET NC, D8 = RET C
- 21 xx xx xx = LD HL,imm24 [4 bytes ADL]
- 7E = LD A,(HL)
- CB 7F = BIT 7,A; CB 77 = BIT 6,A
- E5 = PUSH HL, E1 = POP HL
- 18 xx = JR offset, 20 xx = JR NZ, 28 xx = JR Z
- CD xx xx xx = CALL addr [4 bytes ADL]
