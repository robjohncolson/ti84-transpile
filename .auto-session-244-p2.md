# Task: Trace 0x09D06B — sub-call from 0x051ADC mode filter (vvvv)

## Context
Session 243 decoded 0x051ADC as a mode filter function that reads D007E0 (mode byte) and cascades CP comparisons. The probe `probe-phase243-051adc-post-computation.mjs` showed 0x051ADC calls 0x09D06B but didn't trace that sub-function. We need to understand what state check 0x09D06B performs.

The mode filter at 0x051ADC:
- Reads D007E0 (mode byte)
- Cascades: CP 0x5B/0x52/0x59/0x5A/0x40/0x58 + checks D00824 for 0x4A
- Returns Z=set (filtered out) or Z=clear (pass through)
- Home screen (D007E0=0x00): returns Z=set in 11 steps
- Calls 0x09D06B as a sub-function

## Deliverables
Create file `TI-84_Plus_CE/probe-phase244-09d06b-mode-subcall.mjs` that:

1. **Hex dump** ROM bytes at 0x09D06B-0x09D0D0 (100 bytes)
2. **Static disassembly** of 0x09D06B-0x09D0D0 using the eZ80 decoder
3. **RUN 1**: Call 0x09D06B directly with home-screen state:
   - D007E0 = 0x00 (home screen mode)
   - D00824 = 0x00
   - IX = 0xD1A860, IY = 0xD00080, SP = 0xD1987E
   - Timer interrupts disabled
   - 200 steps, trace:
     - All unique blocks visited
     - All RAM reads and writes
     - Return value (A register, flags)
4. **RUN 2**: Call 0x09D06B with D007E0 = 0x40 (different mode)
5. **RUN 3**: Call 0x09D06B with D007E0 = 0x5B (one of the filter values)
6. **RUN 4**: Call 0x051ADC itself with 500 steps to see how 0x09D06B's return affects the filter decision

**Report**: What does 0x09D06B check? What does it return? How does its return value affect 0x051ADC's Z-flag decision?
