# Auto-Session 385 — P2: Trace 0x02FE__ Callers

## Context

This is a TI-84 Plus CE ROM transpilation project. We lift eZ80 machine code from `TI-84_Plus_CE/ROM.rom` into JavaScript.

The function around 0x02FE50-0x02FF00 is the **key-code translation dispatcher**. It reads kbdKey (0xD0058C), and if non-zero, jumps to 0x0300CB (the translation function). We need to find WHO CALLS this function to understand which OS context activates key-code translation.

## Task

Create a probe file `TI-84_Plus_CE/probe-phase385-callers-02FE.mjs` that:

1. Reads `TI-84_Plus_CE/ROM.rom` (4MB binary, 0x400000 bytes)
2. Scans the ENTIRE ROM (bytes 0x000000 through 0x3FFFFF) for any CALL or JP instruction whose target falls in the range 0x02FE00-0x02FF00.
3. eZ80 CALL/JP encoding reference (ADL mode, 3-byte addresses):
   - `CALL nn`: opcode 0xCD, followed by 3 bytes little-endian address
   - `CALL cc,nn`: opcodes 0xC4 (NZ), 0xCC (Z), 0xD4 (NC), 0xDC (C), 0xE4 (PO), 0xEC (PE), 0xF4 (P), 0xFC (M) — each followed by 3 bytes LE address
   - `JP nn`: opcode 0xC3, followed by 3 bytes LE address
   - `JP cc,nn`: opcodes 0xC2 (NZ), 0xCA (Z), 0xD2 (NC), 0xDA (C), 0xE2 (PO), 0xEA (PE), 0xF2 (P), 0xFA (M) — each followed by 3 bytes LE address

4. For each match, print: `caller_address  instruction_hex  mnemonic  target_address`
5. Also scan for any 3-byte sequence that contains an address in 0x02FE00-0x02FF00 as a potential indirect reference (JP (HL) tables, vector tables). Scan for the LE byte pattern of addresses 0x02FE00-0x02FF00 appearing anywhere in ROM.
6. Print a summary: total callers found, their addresses, and the specific target within 0x02FE00-0x02FF00 they jump to.
