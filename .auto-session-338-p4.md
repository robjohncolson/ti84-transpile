# Task: Map VRAM Fill Dynamic Call Chain During CoorMon

## Context
You are working on a TI-84 Plus CE ROM transpilation project. Session 337 found that during a no-key CoorMon call (entry 0x08BF22), there are 6,528 inner loop iterations at 0x09EFDE (the VRAM fill inner loop). This loop is reached via fall-through from 0x09EF44, NOT via a direct CALL to the FillRect entry point 0x09F008.

The question: who calls into the 0x09EF44 region during CoorMon? What's the complete call chain from CoorMon (0x08BF22) down to the VRAM fill?

## Your Task
Create a probe at `TI-84_Plus_CE/probe-phase338-vram-call-chain.mjs` that:

1. Boots the environment using the standard pattern:
   ```javascript
   // Boot phase
   executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 });
   // Reset CPU, then kernel init
   executor.runFrom(0x08C331, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 });
   // Set up: cpu.mbase = 0xD0, cpu.iy = 0xD00080, install cxMain
   write24(mem, 0xD007CA, 0x058241); // Home handler
   ```

2. Runs CoorMon from 0x08BF22 with NO key injection (`mem[0x3B0033] = 0x00`) in ADL mode

3. Implements a **call stack tracker** in the onBlock callback:
   - Maintain a shadow call stack by watching for CALL-like and RET-like block transitions
   - When a block's metadata has a `tag` of 'call' or the block is a known CALL instruction, push the return address
   - When a block's metadata has a `tag` of 'ret', pop the stack
   - Alternatively, simpler approach: just record the FULL ordered sequence of block PCs, then post-process to find the path to 0x09EFDE

4. Reports:
   - The full call chain from CoorMon (0x08BF22) to the first visit of 0x09EFDE
   - Specifically: which blocks are visited between CoorMon entry and the first VRAM fill iteration
   - Group the blocks into "call frames" if possible (which function called which)
   - How many times 0x09EFDE is visited total (should be ~6,528 per session 337)
   - The blocks visited between the LAST 0x09EFDE visit and CoorMon's return

5. Key addresses to watch:
   - 0x08BF22: CoorMon entry
   - 0x09EF44: VRAM fill setup (fall-through entry)
   - 0x09EFDE: VRAM fill inner loop
   - 0x09F008: FillRect official entry (may or may not be hit)
   - 0x08BF9E: CoorMon epilogue (pop de; pop bc; pop af; ret)

## Boot/Setup Pattern
Use the same pattern as `TI-84_Plus_CE/probe-phase337-coormon-nokey.mjs`:
- `createPeripheralBus({ timerInterrupt: false })`
- RETURN_SENTINEL = 0xFFFFFF
- Stack reset before each CoorMon call
- maxSteps: 50000, maxLoopIterations: 50000

## Important
- DO NOT modify any existing files
- Only create the new probe file
- Use ESM imports (`.mjs` extension)
- Follow the exact import pattern from existing probes in `TI-84_Plus_CE/`
- The simplest approach: record ALL block PCs in order, then slice the list to show the path from entry to first 0x09EFDE visit

## Success Criteria
- Probe runs without errors
- Shows the complete block-level call chain from CoorMon entry to VRAM fill
- Confirms the total iteration count at 0x09EFDE
- Identifies intermediate functions in the call chain
