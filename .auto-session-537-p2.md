## What we know
- 0x07FEE1 (20B, decoded session 536) is a type-check-and-merge function. When type is invalid (NC from 0x08021F validator), it does: XOR A (clear A), CALL 0x07FEFC, then OR-merges result into OP1 type at D005F8.
- So 0x07FEFC is called with A=0 when the type is invalid. It likely returns some value in A that gets merged into the type byte.
- 0x07FEE1 ends at 0x07FEF4. 0x07FEF5 is the "valid type" skip target (a separate function or continuation).
- 0x07FEFC is between 0x07FEF5 and the next known function. It may be short.

## eZ80 conventions
- eZ80 in ADL mode: 3-byte addresses, 3-byte register pairs. `LD A,(nn)` = 3A + 3 bytes. `CALL nn` = CD + 3 bytes. `JP nn` = C3 + 3 bytes. `JR e` = 18/28/20/30/38 + 1 byte.
- OP registers: OP1=D005F8 (type at F8, exponent at F9, mantissa at FA-FF+), OP2=D00603.
- Common type values: 0x00=real, 0x0C=complex, 0x20=equation, 0x21=string, 0x1C=matrix.
