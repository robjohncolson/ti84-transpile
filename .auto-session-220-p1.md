# Auto-Session 220 — P1: Trace 0x04EE1B Function (BIT 3 Gate Armer)

## Context

The TI-84 Plus CE ROM has a critical gate at 0xD003E0 BIT 3 that controls whether the enter-edit-mode path (0x04EB3E → 0x04EC1C) can execute. Session 219 found:
- Sole writer to 0xD003E0 is at address 0x04EE3E: `SET 4,A` then `LD (0xD003E0),A`
- This sets BIT 4 of A but BIT 3 must ALREADY be set in A when this executes
- 0x051D52 CLEARS bits 2+3 via RES instructions
- Boot value is 0x00, event loop never writes it
- The function containing 0x04EE3E starts at or near 0x04EE1B

## Task

Build a probe `TI-84_Plus_CE/probe-phase220-04ee1b-bit3-armer.mjs` that:

### Part A — Static disassembly of 0x04EE1B region
1. Read ROM.rom from disk (path: `TI-84_Plus_CE/ROM.rom`)
2. Disassemble bytes from 0x04EE00 to 0x04EF00 (256 bytes) using the eZ80 instruction decoder
3. Look for the function boundary — find RET/JP instructions that mark the end, and find the entry point (look for a RET before 0x04EE1B as boundary)
4. Print each instruction with address, hex bytes, and mnemonic
5. Identify what instructions compute/modify A before the `LD (0xD003E0),A` at 0x04EE3E
6. Look for OR, AND, SET instructions on A that could set BIT 3

### Part B — Find callers of 0x04EE1B (or whatever the actual entry point is)
1. Do a static ROM binary scan for `CALL 0x04EE1B` (CD 1B EE 04), `JP 0x04EE1B` (C3 1B EE 04), `CALL 0x04EE1C` through 0x04EE3E — check several possible entry points
2. Also scan for pointer references (little-endian bytes 1B EE 04 in pointer tables)
3. Report all call sites with their addresses and a few bytes of surrounding context

### Part C — Dynamic trace of 0x04EE1B
1. Set up a runtime using the pattern from existing probes (see `probe-phase219-d003e0-bit3-setters.mjs` for reference)
2. Do a full boot: z80 boot → kernelInit → postInit → memInit (see probe-phase99d-home-verify.mjs for boot sequence)
3. After boot, trace execution starting at 0x04EE1B with A set to various values (0x00, 0x08, 0x0F, 0xFF) for 200 steps each
4. For each trace, record: which blocks are visited, what value A has at 0x04EE3E when the LD (0xD003E0),A executes, what value gets written to 0xD003E0
5. Print the A-value analysis: does the function modify A between entry and 0x04EE3E? Or does A pass through unchanged?

### Part D — Find what calls 0x04EE1B during normal operation
1. After full boot, run 10000 steps of the OS event loop (entry at 0x082BE2)
2. Use a watchpoint on 0xD003E0: before each step, save the value, after each step check if it changed
3. If it changes, report: step number, PC at time of change, old value, new value, A register value
4. This tells us whether the event loop ever arms BIT 3 naturally
