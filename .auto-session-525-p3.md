# Task: DECODE 0x098A13 — Cleanup function called on both success+failure paths

## Context
You are working on TI-84 Plus CE ROM transpilation. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80 binary).

## What we know
- 0x098A13 is called from 0x0987B7 (type-specific initializer) on BOTH success and failure paths
- On the success path: 0x0989E9 (FP save) → 0x09953F (conditional test) → success → 0x099574 → 0x098A13 → cleanup → RET
- On the failure path: 0x0989E9 → 0x09953F → carry (fail) → 0x098A13 → cleanup → JR to 0x0987FB secondary dispatch
- So 0x098A13 is an ALWAYS-RUN cleanup/teardown function for the type-init stack frame
- The stack frame is 15 bytes, allocated via PUSH IX + LD SP adjustment
- 0x0989E9 saves OP1 (D005F8, 11B) to IX-9 and OP2 (D00603, 11B) to IX-18
- 0x098A3D = frame offset calculator, 0x07F978 = 11-byte FP copy
- This function likely restores the FP state and/or deallocates the stack frame

## Your task
1. Create a probe `TI-84_Plus_CE/probe-phase525-decode-098A13-cleanup.mjs` that:
   - Reads ROM from `TI-84_Plus_CE/ROM.rom`
   - Disassembles starting at 0x098A13 for up to 0x400 bytes main, 0x80 bytes per sub-call
   - Full eZ80 decoder covering all instruction types (see other probes for reference)
   - Tracks CALL targets, JP targets, RAM reads/writes (≥0xD00000), carry/zero operations
   - Prints disassembly listing + summary
2. Reference `TI-84_Plus_CE/probe-phase524-decode-08021B-type-op.mjs` for code style
