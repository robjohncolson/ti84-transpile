# Task: RENDER A FULL LINE (26 CHARS) — TEST LINE-WRAP BEHAVIOR

## Context
Session 478 proved character rendering works: 0x0059C6 with A=charcode produces real glyph pixels. 'H' produced 1,472 VRAM bytes, 'I' produced 64, space produced 0. D00596 increments per character (column counter) and the OS compares it to 0x1A (26 chars per line).

The font format is: 28 bytes/glyph, 16 rows high, 12-14 pixels wide. Row stride = 0x280 (640 bytes = 320 pixels × 2 bytes/pixel in 16bpp).

## Task
Create `TI-84_Plus_CE/probe-phase479-full-line-render.mjs` that:

1. Uses the EXACT same pattern as `probe-phase478-char-output-test.mjs` (import createExecutor from cpu-runtime.js, createPeripheralBus from peripherals.js, load ROM.rom and ROM.transpiled.js).
2. After 3-stage boot (0x080000 → 0x0802B2 → 0x08C331, 150K steps each with maxLoopIterations:200000), sets up display state:
   - D0059C = 0xD40000 (VRAM base — start of VRAM)
   - D00595 = 0x00 (cursor row 0)
   - D00596 = 0x00 (column counter reset)
   - D0058C = 0x00, D0058E = 0x00
   - D0058B = 0x70
   - cpu.mbase = 0xD0, cpu._iy = 0xD00080
   - cpu.iff1 = 0, cpu.iff2 = 0, cpu.halted = false
3. Renders 26 characters by calling 0x0059C6 sequentially with "ABCDEFGHIJKLMNOPQRSTUVWXYZ" (0x41 through 0x5A):
   - For each: set cpu._a = (charCode << 24), cpu.sp = 0xD1A87E - 3, push sentinel 0xFFFFFF, run from 0x0059C6 with maxSteps:5000, maxLoopIterations:100
   - After each call, record: D00596 value, D0059C value
4. After all 26 characters, log:
   - D00596 final value (should it wrap to 0 after reaching 0x1A?)
   - D0059C final value  
   - Total VRAM bytes changed from pre-render snapshot
   - Whether D0059C wrapped or overflowed past end-of-row
5. Then render ONE MORE character (0x41 = 'A' again, the 27th character) to test what happens at the line boundary:
   - Does D00596 wrap to 0?
   - Does D0059C jump to the next row?
   - Does D00595 increment (next text row)?
   - Log all state changes

## Key addresses
- 0x0059C6 = character output (A = char code)
- D0059C (3 bytes LE) = VRAM address pointer
- D00595 = rendering row position
- D00596 = column counter (wraps at 0x1A = 26)
- D0058B = display config
- Each character is 12-14 pixels wide in 16bpp = 24-28 bytes per character per row
- Row stride = 0x280 = 640 bytes
- Character height = 16 rows = 16 × 640 = 10,240 bytes per text row

## Template reference
Copy structure from `probe-phase478-char-output-test.mjs`:
- Same imports, boot, helpers
- Same primeDirectCall: cpu._a = (charCode & 0xFF) << 24
- Same snapshotVram/diffVram pattern

## Success criteria
- D00596 should increment from 0 to 25 (0x19) after 26 characters
- The 27th character should trigger line-wrap behavior (D00596 wraps, D00595 increments, D0059C jumps to next row)
- Total VRAM bytes should be substantial (26 × ~1000 = ~26,000+ bytes)
