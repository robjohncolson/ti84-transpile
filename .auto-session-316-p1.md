# Task: Trace scrapMem soft-float usage (57 refs)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). We have a transpiler at `scripts/transpile-ti84-rom.mjs` that lifts ROM to JavaScript.

The soft-float library lives at ROM addresses 0x0034A7–0x003A05. It implements IEEE-754 single-precision operations: _fadd, _fsub, _fmul, _fdiv, _fcmp, _fpunpack, _fppack, _fneg, _ftol, _ultof, sqrtf.

`scrapMem` is RAM address 0xD0065F. Session 314 found 181 total references across the ROM. 57 of those 181 refs are within the soft-float library range (0x0034A7–0x003A05).

A common idiom observed is "high-byte extraction" — using scrapMem as a temporary byte to extract/store high bytes during multi-byte float operations.

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase316-scrapmem-float.mjs` and a report `TI-84_Plus_CE/phase316-scrapmem-float-report.md`.

The probe should:
1. Read `TI-84_Plus_CE/ROM.rom`
2. Scan the range 0x0034A7–0x003A05 for all references to scrapMem (0xD0065F). The eZ80 encoding for this address in little-endian is bytes 0x5F, 0x06, 0xD0.
3. For each reference found, disassemble the instruction (LD A,(scrapMem), LD (scrapMem),A, etc.) and the 2-3 instructions before and after for context.
4. Classify each usage: is it high-byte extraction, temporary storage during normalization, or something else?
5. Report statistics: how many are reads vs writes, which functions they belong to, and whether ALL are the same idiom or if there are distinct usage patterns.

The report should summarize findings and answer: could a dedicated register trick (e.g., using IYL or an unused register) replace all scrapMem usage in the soft-float library?

## Technical details
- eZ80 is little-endian. Address 0xD0065F encodes as bytes 5F 06 D0.
- LD A,(nn) = 0x3A nn_lo nn_mid nn_hi (4 bytes in ADL mode)
- LD (nn),A = 0x32 nn_lo nn_mid nn_hi (4 bytes in ADL mode)
- The soft-float functions start at these addresses (from session 313):
  - _fpunpack: 0x0034A7
  - _fpunpack2: 0x0034CC
  - _fadd: 0x003572
  - _fsub: 0x0035EB
  - _fdiv: 0x0035F4
  - _ftol: 0x003682
  - _fmul: 0x00373D
  - _fcmp: 0x003804
  - sqrtf: 0x003827
  - _fneg: 0x0039F4
  - _fppack: 0x003A05 (end of library region, function itself is ~118 bytes before this)
