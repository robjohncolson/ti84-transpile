# Task: Trace 0x051D89 SET 2,(HL) caller chain — D003E0 bit 2 writer

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript and executed via `cpu-runtime.js`.

Session 239 found a NEW write site for D003E0: address 0x051D89 which does `SET 2,(HL)` where HL=0xD003E0. This was previously unknown. The other writers are:
- 0x04EE3E: `SET 4,A / LD (D003E0),A` (primary writer)
- 0x051D52: `RES 2,(HL) / RES 3,(HL)` (clears bits 2+3)

D003E0 is a critical mode flag that gates the shared post-classification handler at 0x04EDD0. BIT 3 controls whether 0x0850D1 or 0x04E447 branches fire (vs the default 0x09EFDE VRAM fill path).

## Task
Create a probe `TI-84_Plus_CE/probe-phase240-051d89-set2-callers.mjs` that:

1. **Static analysis**: Read ROM.rom and:
   - Disassemble 0x051D89 and surrounding bytes (0x051D80-0x051DA0) to understand the full instruction context
   - Find all CALL/JP references to addresses near 0x051D89 in the entire ROM (scan for CD xx xx 05 and C3 xx xx 05 patterns where the target is within 0x051D70-0x051DA0)
   - Identify the function boundary (find the nearest RET before 0x051D89)
   - Check if 0x051D89 is a function entry or mid-function code

2. **Function identification**: Once you find the containing function:
   - Find ALL call sites to that function in the ROM
   - Classify each caller by region (0x04xxxx=OS core, 0x05xxxx=editor/cxMain, 0x06xxxx=editor2, 0x07xxxx=FP, 0x08xxxx=display, 0x09xxxx=STAT, 0x0Axxxx=apps)
   - Count total callers

3. **Dynamic trace**: Set up the CPU and:
   - Call the function containing 0x051D89 directly
   - Seed HL=0xD003E0 (or whatever HL should be based on disassembly)
   - Trace execution and confirm SET 2,(HL) fires
   - Record what other RAM addresses are modified
   - Record IY flag changes

4. **Cross-reference with 0x051D52**: Note that 0x051D52 does RES 2,(HL) on the SAME byte. Are 0x051D52 and 0x051D89 in the same function? Do they represent SET/RES pairs?

## Reference files
- `TI-84_Plus_CE/ROM.rom` — raw ROM binary (4MB)

## ROM scanning pattern
```javascript
import fs from 'fs';
const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');
// Scan for CALL target: CD LL MM HH where target = HH<<16 | MM<<8 | LL
// Scan for JP target: C3 LL MM HH
for (let i = 0; i < rom.length - 3; i++) {
  if (rom[i] === 0xCD || rom[i] === 0xC3) {
    const target = rom[i+1] | (rom[i+2] << 8) | (rom[i+3] << 16);
    if (target >= 0x051D70 && target <= 0x051DA0) {
      console.log(`${rom[i]===0xCD?'CALL':'JP'} 0x${target.toString(16)} at 0x${i.toString(16).padStart(6,'0')}`);
    }
  }
}
```
