# Task: Decode 0x096CCF (Cursor Show/Erase Subroutine)

## Context
In the TI-84 Plus CE OS ROM transpilation project, the cursor blink architecture has been mapped:
- 0x096BEE is the blink TOGGLE: checks BIT 2,(IY+0x0D) (cursor-currently-drawn flag)
  - If bit=0 (not drawn): JP to 0x096CCF to draw
  - If bit=1 (drawn): RES bit 2, CALL 0x096CCF to erase, SET bit 2
- 0x096BE5 is the entry wrapper (calls 0x07F9FB to set DE=0xD005F8, then falls into 0x096BEE)
- 0x096BC3 is the condition-check wrapper
- 0x096CCF is the DRAW/ERASE SUBROUTINE — called from BOTH paths of the toggle
- 0x061061 is the cursor draw function (loads cursor type from D02575, calls putchar 0x061980)
- 0x061003 is the cursor erase function
- 0x060EF5 is the main-loop orchestrator (8 callers from key processing)
- 0x096B65 is the full cursor display (5 callers: 0x0600D9, 0x0615F6, 0x06161A, 0x06167D, 0x097065)

Key RAM: IY = 0xD00080, so (IY+0x0D) = D0008D. Bit 2 = cursor visible on screen. Bit 1 = cursor blink enabled.

## Task
Create and run a probe that fully decodes 0x096CCF.

### Part 1: Static disassembly
- Load ROM from `TI-84_Plus_CE/ROM.rom`
- Use eZ80 decoder from `TI-84_Plus_CE/ez80-decoder.js` to disassemble starting at 0x096CCF
- Decode until RET (0xC9) or 300 bytes
- Print: address, hex bytes, mnemonic for each instruction
- Identify all CALL/JP targets
- Note references to: 0x061061 (cursor draw), 0x061003 (cursor erase), D02575 (cursor type), D00595/D00596 (cursor pos), (IY+0x0D) (cursor flags)
- Determine: does 0x096CCF call 0x061061 for draw and 0x061003 for erase? Or does it have its own mechanism?

### Part 2: Dynamic test — draw path
- Use cpu-runtime.js to set up execution
- Set cursor at row=5, col=10 (D00595=5, D00596=10, D02505=10)
- Set cursor type D02575=0xE1 (block cursor)
- Set IY=0xD00080
- Clear (IY+0x0D) bit 2 (cursor NOT drawn — so 0x096CCF should DRAW)
- Capture VRAM before, execute from 0x096CCF with maxSteps=50000, capture VRAM after
- Report: steps, pixels changed, bounding box, final state of (IY+0x0D) bit 2

### Part 3: Dynamic test — erase path
- Same setup but SET (IY+0x0D) bit 2 (cursor IS drawn — so 0x096CCF should ERASE)
- Execute from 0x096CCF, compare VRAM
- Report same metrics
