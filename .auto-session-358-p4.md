# Task: Extend Boot Past 0x000D82 - Test Port 0x1F Return Values

## Context
TI-84 Plus CE ROM transpilation project. OS ROM (eZ80) lifted to JS, executed in Node.js. Boot reaches 318 blocks before re-HALTing.

Current boot gate at block 0x000D82:
```
LD A,(0xD02AD9)    ; load A from RAM
IN0 C,(0x1F)       ; read port 0x1F -> currently 0xFF
INC C              ; C = C + 1 (0xFF + 1 = 0x00 wrap)
CP C               ; A - C, sets flags
JP NC,0x0019B5     ; if no carry (A >= C), jump to HALT
```

Currently: port 0x1F=0xFF -> C=0x00 -> CP C always no-carry -> HALT.
To escape: need C > A, meaning (port_0x1F + 1) > mem[0xD02AD9].

## Deliverables

Create `TI-84_Plus_CE/probe-phase358-port1F-bruteforce.mjs` that:

1. Tests port 0x1F returning each of: 0x00, 0x01, 0x02, 0x7E, 0x7F, 0x80, 0xFE, 0xFF. For each value, record:
   - Total unique blocks reached
   - Whether boot escapes past 0x000D82
   - Furthest new block reached (if any beyond 318)
   - Value of A register when gate is hit (from 0xD02AD9)

2. Overrides port 0x1F reads at the probe level (NOT modifying peripherals.js). Check how port reads work in peripherals.js - you need to intercept readPort calls for port 0x1F. Approaches:
   - Wrap bus.readPort: `const orig = bus.readPort.bind(bus); bus.readPort = (p) => p === 0x1F ? testVal : orig(p);`
   - Or check if peripherals.js has a handler registration mechanism you can use

3. Reports which value(s) let boot continue past 0x000D82 and what new blocks appear.

4. Captures A register value at the gate to understand the constraint.
