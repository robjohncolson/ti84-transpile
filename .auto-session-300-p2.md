# Auto-Session 300 P2: Map All 8 Code-Copy Framework Users (0x000D7E)

## Context
The TI-84 Plus CE ROM has a code-copy framework at address 0x000D7E. This routine:
- Takes IX pointing to a parameter block: 2 bytes (little-endian length) followed by the code to copy
- Copies `length` bytes from ROM (source = IX+2) to RAM via LDIR
- Executes the copied code from RAM via `JP (IX)` (IX is updated to point to RAM destination)

Session 299 found that the keyboard scanner at 0x0159C0 is invoked through this framework (caller at 0x01598B does `LD IX,0x0159BD; CALL 0x000D7E`, parameter block has length 0x011A = 282 bytes).

Session 299 also found that 0x000D7E has **8 total callers** (CALL references) in the ROM. We know one of them (0x01598B for the keyboard scanner). The other 7 are unknown.

## Task
Write a probe `TI-84_Plus_CE/probe-phase300-code-copy-users.mjs` that:

1. **Find all 8 CALL 0x000D7E sites** in the ROM. Search for the byte pattern for `CALL 0x000D7E`. In eZ80 ADL mode, CALL is `0xCD` followed by 3-byte little-endian address. So search for bytes `CD 7E 0D 00` in the ROM.

2. **For each call site**, decode the parameter block:
   - Look backwards from the CALL for `LD IX,<addr>` — this gives the parameter block address
   - `LD IX,imm24` in eZ80 is `DD 21 xx xx xx` (5 bytes)
   - Read the parameter block: first 2 bytes = length (little-endian), then `length` bytes of code
   - Report: call site address, IX value (param block address), code length, first few bytes of the code

3. **For each copied routine**, try to identify what it does:
   - Disassemble the first 10-20 instructions of the copied code
   - Look for characteristic patterns (I/O port access, memory reads, loop structures)
   - Cross-reference with known routines

## How to search
Read the entire ROM file (`TI-84_Plus_CE/ROM.rom`, 4MB binary) into a Buffer. Search for byte pattern `0xCD 0x7E 0x0D 0x00` to find CALL 0x000D7E sites.

## Deliverables
- `TI-84_Plus_CE/probe-phase300-code-copy-users.mjs`

## Constraints
- Do NOT modify any existing files
- Output should be a standalone .mjs probe
- Use `import { readFileSync } from 'fs'` for ROM access

## Success criterion
Running the probe prints all 8 call sites with their parameter blocks decoded (lengths, source addresses, brief identification of each copied routine).
