# Task: Investigate 0xD000C6 Initialization — LCD Mode Flag

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is a 4MB eZ80 binary at `TI-84_Plus_CE/ROM.rom`. The runtime is in `TI-84_Plus_CE/cpu-runtime.js`. Session 391 decoded that 0x08C308 tests bit 2 of RAM address 0xD000C6 to determine LCD color depth: bit 2=0 means 16bpp, bit 2=1 means 8bpp. 12 callers use this test across the graphics subsystem.

## What to do
1. Write a Node.js probe at `TI-84_Plus_CE/probe-phase392-D000C6-init.mjs` that:
   - Uses the project's runtime to boot the TI-84 OS and trace when 0xD000C6 is written
   - Boot sequence: use the standard boot pattern from existing probes:
     ```js
     import { createCPU } from './cpu-runtime.js';
     import { createPeripheralBus } from './peripherals.js';
     import fs from 'fs';
     const rom = new Uint8Array(fs.readFileSync('./ROM.rom'));
     const peripherals = createPeripheralBus({ timerInterrupt: false });
     const cpu = createCPU(rom, peripherals);
     ```
   - Hook `cpu.memory` writes: after each step, check if `cpu.memory[0xD000C6]` changed from its previous value. If so, log the step number, PC, and new value.
   - Run boot for 500,000 steps (this covers full OS init)
   - At the end, report the final value of 0xD000C6 and specifically bit 2
   - Also report all addresses that wrote to 0xD000C6 during boot

2. Additionally, do a static ROM search:
   - Search the ROM for all instructions that write to 0xD000C6:
     - `LD (0xD000C6),A` = `32 C6 00 D0` (in ADL mode)
     - SET/RES bit instructions via IY indexing: if IY=0xD00080 (standard), then 0xD000C6 = (IY+0x46). Search for `FD CB 46 xx` patterns where xx encodes SET/RES bit 2
     - Direct LD instructions
   - Print all ROM addresses that reference 0xD000C6

3. Run the probe and print findings
