# Auto-Session 283 P1: Trace 0x040CE6 — STAT event loop event processing

## Context
This is a TI-84 Plus CE ROM transpilation project. We lift eZ80 machine code into JavaScript and trace OS internals.

Session 282 identified that 0x040CE6 is called in the STAT event loop at 0x040C6F. We need to understand what event processing it does — is it a key handler, screen refresh, or something else?

## Task
Write a probe file `TI-84_Plus_CE/probe-phase283-040ce6-event-proc.mjs` that:

1. **Static disassembly** of 0x040CE6 — decode 80+ bytes of instructions starting at this address from ROM.rom. Continue until you hit a RET or unconditional JP that exits the function.
2. **Identify the function signature** — what registers/stack args does it expect? What does it return?
3. **Find all callers** of 0x040CE6 — scan ROM.rom for `CD E6 0C 04` (ADL CALL, little-endian 24-bit: E6 0C 04) and `C3 E6 0C 04` (ADL JP).
4. **Dynamic trace** — set PC=0x040CE6 with reasonable register state (A=1 simulating a key event, HL=0, DE=0). Run 200 steps, log each block visited and any RAM writes. Use `createPeripheralBus({ timerInterrupt: false })`.
5. **Cross-reference with 0x040C6F** — disassemble 20 bytes before the CALL (0x040C5B-0x040C6F) to see what context/args are set up before calling 0x040CE6.
