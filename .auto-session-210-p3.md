# Auto-Session 210 — P3: STAT error check reverse-engineering at 0x058BA9

## Context

In the TI-84 Plus CE ROM transpilation, the STAT pipeline always hits an error condition when entered via 0x058BA9 (cxErrorEP in the context table). Sessions 204-208 tried: list seeding, VAT seeding, PushErrorHandler, full OS boot — ALL produce the same error (OP1=0x032D, "Error" string at 0xD008E6+14). The error occurs within the first ~100 steps.

Session 206 explored all 6 context table entries and found that [4]=0x058BA9 (cxErrorEP) halts at 107 steps, reaches STAT area. The conclusion was that the error is NOT from list/VAT format issues but from missing OS state that only the real menu traversal (2nd→STAT→CALC→1-Var Stats) installs.

**Goal**: Reverse-engineer exactly WHAT state check at the beginning of 0x058BA9's code path triggers the error. If we know the specific RAM location / IY flag / stack frame that's checked, we can seed it.

## What you need to do

Build a probe at `TI-84_Plus_CE/probe-phase210-stat-error-disasm.mjs` that:

1. **Deep static disassembly**: Read ROM.rom bytes from 0x058BA9 to 0x058C00 (the cxErrorEP entry region). Decode ALL eZ80 instructions in ADL mode. Then follow every CALL and JP target for the first 3 levels of calls — i.e., if 0x058BA9 calls 0x0XXXXX, disassemble 0x0XXXXX too, and if THAT calls 0x0YYYYY, disassemble that too. We need to find the instruction that detects "error state" and jumps to the error path.

2. **Execution trace with state logging**: Boot minimal runtime:
   - Load ROM, CPU + peripherals with `timerInterrupt: false`
   - Run standard boot (z80 boot → kernelInit → memInit)
   - Seed list L1={1.0, 2.0, 3.0} at 0xD01600 with proper BCD format (count=3 LE word, then 9-byte BCD floats: 1.0=`00 80 10 00 00 00 00 00 00`, 2.0=`00 80 20 00 00 00 00 00 00`, 3.0=`00 80 30 00 00 00 00 00 00`)
   - VAT entry at 0xD1A800: type=0x01, pointer to 0xD01600, name=L1 (0x5D, 0x00)
   - Set IX = 0xD1A860 (standard)
   - Enter at block closest to 0x058BA9

3. **Step-by-step trace of the first 150 steps**: For EACH step, log:
   - Current PC / block address
   - Key register values (A, F flags, HL, DE, BC, IX, IY, SP)
   - Any RAM reads that look like condition checks (CP, BIT, AND, OR instructions that test RAM values)
   - Any conditional jump outcomes (taken vs not taken)
   
   The goal is to find the EXACT instruction where the error path diverges — the conditional that should go one way (success) but goes the other way (error) because of missing state.

4. **Identify the missing state**: Once you find the divergence point, document:
   - What RAM address or IY flag is being checked
   - What value it has (causing the error)
   - What value it likely SHOULD have (to continue the STAT pipeline)
