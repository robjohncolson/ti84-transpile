# Task: MAP D17744 — Display Phase Counter

## Context
In the TI-84 CE ROM, session 465 decoded 0x0017DD as a ROTATING DISPLAY REFRESH: reads D17744 (2-bit counter, incremented mod 4), indexes into a 4-entry table at 0x17D9 with values {0x7C, 0x2F, 0x2D, 0x5C}, and calls 0x0059C6 (display output) with the table value in A. The 0x0017CE wrapper pushes HL, loads HL=0x0C00, calls 0x0017DD, pops, returns.

Questions to answer:
1. What do the 4 table values mean? (0x7C=H reg, 0x2F=CPL, 0x2D=L reg, 0x5C=H' reg — but these could also be ASCII or display control codes)
2. Who else reads/writes D17744?
3. What are the 4 display phases?

## Deliverable
Create `TI-84_Plus_CE/probe-phase466-map-D17744.mjs` — a probe that:

### Part 1: ROM byte analysis at 0x0017DD
Read 32 bytes starting at 0x0017DD from `romBytes`. Disassemble the function manually. Print the 4-entry table at 0x17D9 with hex values and their possible interpretations:
- As ASCII characters: `String.fromCharCode(0x7C)` = '|', `String.fromCharCode(0x2F)` = '/', etc.
- As eZ80 register encodings
- As display control codes for 0x0059C6

### Part 2: Search for D17744 references
Search the ROM for all references to address D17744 (bytes 0x44, 0x77, 0xD1 in little-endian). For each reference:
- Print the ROM address where it appears
- Read 8 bytes before and 8 bytes after for context
- Determine if it's a read (LD from) or write (LD to)

The search approach: scan `romBytes` from 0x000000 to 0x3FFFFF looking for the 3-byte sequence `0x44 0x77 0xD1`. Note: this will also match false positives — filter by checking if the preceding byte is a valid opcode for a memory access instruction.

### Part 3: Test the display phase cycle
After 3-stage boot, call 0x0017DD four times (PC=0x0017DD, mode='adl', 200 steps each). Before each call, print D17744 value. After each call, print D17744 value and what value was in register A (track via the CALL to 0x0059C6 — monitor PC hitting 0x0059C6 and capture register A at that point).
