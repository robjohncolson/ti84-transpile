# Task: Trace Computed Dispatch for Jump Table 0x0213C0

## Context
In the TI-84 Plus CE ROM transpilation project, we decoded a 40-entry jump table at 0x0213C0 (session 228). Each entry is a 4-byte `JP` instruction (C3 xx xx xx). Entry [12] at 0x0213F0 targets 0x023B67 and has ZERO direct callers — it's only reachable via computed dispatch.

The question: **what code computes the entry index and dispatches through the table?** This explains how mode-registration stubs get invoked at runtime.

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase229-0213c0-dispatch.mjs` that:

1. **Find callers of the table region**: Scan the entire ROM (4MB) for:
   - `CALL 0x0213C0` (CD C0 13 02 in little-endian for ADL CALL)
   - `JP 0x0213C0` (C3 C0 13 02)
   - `LD HL,0x0213C0` or `LD DE,0x0213C0` (potential computed dispatch setup)
   - Any reference to addresses 0x0213C0-0x02145F (the full table range: 40 entries × 4 bytes = 160 bytes)
   - Look for patterns like `ADD HL,HL; ADD HL,HL` (multiply index by 4) followed by `ADD HL,DE` where DE=table base, then `JP (HL)` — this is a common computed dispatch pattern

2. **Search for JP (HL) near table references**: Look for `JP (HL)` opcodes (E9) within 32 bytes of any instruction that loads 0x0213C0 into a register.

3. **Disassemble the dispatch function**: Once found, disassemble the full function that performs the computed dispatch. Show how the index is computed from input (likely a mode ID or key code).

4. **Dynamic trace**: Execute the dispatch function with index=12 to confirm it reaches 0x023B67. Try 2-3 other indices to verify the table indexing math.

## Technical Setup
```javascript
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
import fs from 'fs';

const ROM_PATH = './ROM.rom';
const romData = fs.readFileSync(ROM_PATH);
const pbus = createPeripheralBus({ timerInterrupt: false });
const cpu = createCPU(pbus);
for (let i = 0; i < romData.length; i++) cpu.mem[i] = romData[i];
```

For ROM binary scanning, search `romData` for byte patterns. Remember eZ80 ADL mode uses 3-byte addresses in little-endian. `CALL 0x0213C0` in ADL mode = `CD C0 13 02`. `JP 0x0213C0` = `C3 C0 13 02`. `LD HL,0x0213C0` = `21 C0 13 02`.

For dynamic traces, push sentinel 0x7FFFFE as return address, set registers, set cpu.pc, step and log.
