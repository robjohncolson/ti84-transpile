# Auto-Session 199, Priority 2: STAT Write-Watch on RAM 0xD008E6

## Context

Session 198 discovered that `LD DE,(0x0008E6)` in the STAT handler actually reads RAM address 0xD008E6 (because MBASE=0xD0, and the transpiled code does `cpu.read16(((cpu.mbase << 16) | 0x08e6))`). The value is consistently 0x0017 (23), which after two INC DE instructions becomes 0x0019 (25) — matching session 197's observed DE value for the LDDR byte count.

Key question: **what code writes 0x0017 to RAM 0xD008E6 during STAT init?** Session 198 confirmed via sentinel test that something DOES overwrite 0xD008E6 between entry at 0x058BA9 and the read at 0x092226.

## Task

Build a probe `TI-84_Plus_CE/probe-phase199-stat-write-watch.mjs` that:

1. Sets up standard OS state (memInit, MBASE=0xD0, IX=0xD1A860, timerInterrupt: false)
2. Seeds L1 with 3 elements {1.0, 2.0, 3.0} at 0xD10000 + VAT entry at 0xD1A800 (copy pattern from probe-phase194-stat-seeded-lists.mjs)
3. Places a **write-watch** on address 0xD008E6 by monkey-patching the CPU's write8 method:
   ```javascript
   const origWrite8 = cpu.write8.bind(cpu);
   const writeLog = [];
   cpu.write8 = function(addr, val) {
     if (addr === 0xD008E6 || addr === 0xD008E7) {
       writeLog.push({
         step: stepCount,
         addr: '0x' + addr.toString(16).toUpperCase(),
         val: '0x' + val.toString(16).padStart(2, '0'),
         pc: '0x' + cpu.pc.toString(16).padStart(6, '0'),
         block: currentBlockKey // track which block is executing
       });
     }
     return origWrite8(addr, val);
   };
   ```
4. Enters STAT handler at 0x058BA9 (the cxErrorEP entry — this is where session 194 got 264 unique blocks)
5. Runs for 5000 steps
6. Reports:
   - All write events to 0xD008E6/0xD008E7 (step, PC, block, value)
   - The final value at 0xD008E6 (read16)
   - Total unique blocks visited
   - Whether 0x092226 (the LD DE instruction) was reached
