# Auto-Session 370 — P4: BC31 via Post-Trampoline Entry

## Context
Block 0x00BC31 is a byte-copy loop that we've investigated extensively (sessions 362-369). The standard boot from 0x08C331 never reaches 0x00BC31 — it terminates at 0xD18C22 (flash self-test RAM execution) after only 3,356 steps. The RAM trampoline in cpu-runtime.js handles 0xD18C22 by synthesizing a RET, but the boot path from 0x08C331 still doesn't reach BC31 even with 500K steps (session 369 confirmed this).

The trampoline at 0xD18C22 pops a return address and continues. The caller is 0x000D82 area. We need to find what address execution continues to AFTER the trampoline returns, then start a probe from that post-trampoline point to see if BC31 is eventually reached.

3. Check if 0x00BC31, 0x00BC47, 0x00BC72 are reached in Phase 3.

4. Report:

## Key addresses
- 0xD18C22: flash self-test RAM execution (trampoline intercepts this)
- 0x000D82: area around the caller of the flash self-test
- 0x00BC31: the byte-copy loop we're trying to reach
- 0x00BC47: linked-list pointer follow (LD IX, (IX-30))
- 0x00BC72: epilogue (LD SP,IX → potential SP corruption)
- STACK_RESET_TOP = 0xD1A87E
