# Auto-Session 206, Priority 1: cxMain digit path — why does it return without BufInsert?

## Context

In the TI-84 Plus CE ROM transpilation project, session 205 confirmed that the cxMain (Level 2) digit path at 0x0585E9 successfully reaches 0x0589E5 and avoids 0x09927F entirely. However, **BufInsert (0x05E2A0) is NOT reached** — the path returns cleanly after block 0x058AC9 without inserting any character into the edit buffer.

The path is: 0x0585E9→0x05877A→0x0587E9→0x05899D→0x058D54→0x0589E5→0x0589E9→0x058A0C→0x058A60→0x058AC9→return.

2. **Traces the cxMain digit path with RAM write-watching** on key addresses:

3. **Identify the specific conditional branch** in the 0x058A0C-0x058AC9 range that causes the early return instead of falling through to BufInsert. Look for:

   - Initialize any other flags the disassembly reveals

```javascript
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
import fs from 'fs';

const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');
const transpiled = fs.readFileSync('TI-84_Plus_CE/ROM.transpiled.js', 'utf-8');

const bus = createPeripheralBus({ timerInterrupt: false });
const cpu = createCPU(bus);
// cpu.mbase defaults to 0xD0

// Load ROM
for (let i = 0; i < rom.length; i++) cpu.mem[i] = rom[i];

// Load transpiled
const fn = new Function('cpu', 'mem', 'read8', 'read16', 'read24', 'write8', 'write16', 'write24', transpiled + '\nreturn blockMap;');
const blockMap = fn(cpu, cpu.mem, cpu.read8.bind(cpu), cpu.read16.bind(cpu), cpu.read24.bind(cpu), cpu.write8.bind(cpu), cpu.write16.bind(cpu), cpu.write24.bind(cpu));
```
