# Auto-Session 193 P1: ParseInp Trig Stall — Increase Step Limit to 10000

## Context
In session 192, probe `probe-phase192-parseinp-trig.mjs` showed that trig tokens (sin/cos) enter ParseInp correctly via PushErrorHandler+JError+recovery, but the recovery trace hits a 2000-step limit before evaluation completes. OP1 after recovery holds raw token bytes (`FF 5E 25` for sin, `FF 5E 26` for cos), meaning ParseInp recognized them as two-byte tokens but couldn't finish trig function dispatch.

OP2 = π/180 (degree→radian constant) is consistently loaded — the trig dispatch path is partially working.

## Task
Create a new probe `TI-84_Plus_CE/probe-phase193-trig-extended.mjs` that:

1. **Reuses the same setup** as `probe-phase192-parseinp-trig.mjs` (same memory init, same PushErrorHandler setup, same ParseInp entry) but with a **10000-step limit** on the recovery trace (the trace that runs after JError fires and the z80-mode RET intercept reaches 0x099929).

2. **Tests just sin(0)** — single expression, two-byte token sequence `[0x5E, 0x25]` followed by `[0x30]` (digit 0) in the edit buffer.

3. **Logs every unique block visited** during recovery (like session 192 probe does) and specifically checks:
   - Does execution reach any block in range 0x07C000-0x07D000 (FP math area)?
   - Does execution reach any block in range 0x075000-0x076000 (trig function area — check ROM.transpiled.js for blocks starting with `0x075`)?
   - Does execution hit a `missing_block` call? If so, what address?
   - What is OP1 at steps 2000, 5000, and 10000?

4. **Reports**:
   - Total steps executed in recovery
   - Total unique blocks visited
   - Whether a missing_block was hit (and at what address)
   - OP1 at checkpoints (2000, 5000, 10000 steps)
   - List of all blocks in 0x075xxx-0x07Dxxx range that were visited (trig/FP area)

## Key Addresses

- ParseInp: 0x099914
- JError: 0x061DB2
- Recovery target (hlPayload): 0x099929
- OP1: 0xD005F8 (9 bytes)
- OP2: 0xD00603 (9 bytes, NOT 0xD00601)
- Edit buffer: 0xD00A00
- errSP: 0xD0257A (2 bytes, stores 16-bit value for LD SP,(errSP))

## Constraints
- Do NOT modify any existing files
- Create ONLY `TI-84_Plus_CE/probe-phase193-trig-extended.mjs`
- Use the same probe pattern as `probe-phase192-parseinp-trig.mjs` (import cpu-runtime, load ROM.transpiled.js, etc.)
- The z80-mode RET intercept at block `03e1b1:z80` must hard-code PC=0x03E1CA + set ADL mode (same as session 192 probe)
- Timer interrupt must be disabled: `createPeripheralBus({ timerInterrupt: false })`

## Success Criterion
