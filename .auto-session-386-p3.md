# Task: Investigate the 0x09F79B Table Lookup

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80 binary). Session 385 found that the default key-code path (no 2ND/ALPHA modifier active) in the translation dispatcher falls through to:
```
LD DE, 0x09F79B
CALL 0x022346
```
This is a ROM table lookup. The table at 0x09F79B likely maps raw scan codes to default (unmodified) key tokens.

## Known scan code mapping (from session 378)
OS scan codes are computed as: `scancode = (6-group)*8 + bit + 1`
- GRAPH=0x01, 2ND=0x06, DEL=0x08, ALPHA=0x10, 0=0x11, ENTER=0x29, CLEAR=0x2F

## Your task
Write a Node.js probe at `TI-84_Plus_CE/probe-phase386-table-09F79B.mjs` that:

1. Reads ROM.rom
2. Reads and dumps raw bytes at 0x09F79B for 256 bytes (the table may be shorter — look for a terminator pattern like 0xFF or 0x00)
3. Disassemble the lookup function at 0x022346 (read ~100 bytes starting there). Determine:
   - What format does the table use? (flat array indexed by scan code? key-value pairs? linked entries?)
   - How does 0x022346 use the DE register (table base) and A register (likely the scan code)?
   - What does 0x022346 return? (the translated token in A? in HL? in DE?)
4. Decode the table entries:
   - If it's a flat array: dump entry[scancode] for all known scan codes (0x01-0x38)
   - If it's key-value pairs: parse and list all pairs
   - Cross-reference with known TI-OS key token values (kEnter=0x05, kClear=etc.) if recognizable
5. Check if there are ALPHA and 2ND variants of this table nearby in ROM (e.g., at 0x09F79B + table_size, or referenced from the 0x02FFF6 2ND-mode path)
