# Task: Test port 0x28 returning 0x00 during NMI handler to escape HALT loop

## Context
The TI-84 CE boot sequence currently halts at 0x0019B5 (DI + HALT). NMI wakes execution to 0x000066, which runs a 14-block handler ending back at 0x0019B5. The handler at block 0x001B44 reads port 0x28 and gets 0x04 (PLL locked). Session 356 identified this as the gate — if port 0x28 returned 0x00, the conditional branch would escape to new territory.

## PLL Handler (peripherals.js lines 56-86)
Port 0x28 is the PLL handler. `read()` returns 0x04 when locked, 0x00 when not locked. `write(port, value)` resets the lock countdown only when `value !== state.pll.lastWrite`. After the delay expires, reads return 0x04 (locked) forever.

The NMI handler writes 0xD0 to port 0x28 every cycle. Since the PLL was configured with lastWrite already matching, the write doesn't reset the countdown, so reads keep returning 0x04.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase357-port28-escape.mjs` that:

1. Boots the ROM normally (timerInterrupt: false) for ~5000 steps to reach the HALT at 0x0019B5
2. Then triggers NMI wakes. For the FIRST 2 NMI wakes, let port 0x28 behave normally (return 0x04 when locked).
3. Starting from NMI wake #3, PATCH the PLL state so `state.pll.locked = false` and `state.pll.remainingReads = 999` (so reads return 0x00 instead of 0x04).
4. Run for 10000 more steps after the patch.
5. Record ALL unique blocks visited, especially any new blocks not in the 286-block set from session 356.
6. Log the full block sequence for the first NMI wake after the patch, to see where the escape branch goes.
7. Log any port reads/writes that happen in the new territory.

- Boot with `createPeripheralBus({ timerInterrupt: false })`
- Access PLL state via the peripheral bus state object. The state is at `bus.getState().pll` — you can mutate `bus.getState().pll.locked` and `bus.getState().pll.remainingReads` directly.

- Execution loop: call `run(cpu)` which returns the next PC. HALT (opcode 0x76) stops execution — detect it by checking if PC didn't advance or by checking `cpu.halted`.
