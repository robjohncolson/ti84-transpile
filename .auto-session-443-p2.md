# Task: Map D176FB (Written by D14078/D14079 Consume Sites)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is a 4MB eZ80 binary at `TI-84_Plus_CE/ROM.rom`.

In session 442, we traced D14078 (endpoint-configured flag) and D14079 (deferred-transfer-pending flag). Both have a "consume-and-dispatch" pattern: when set, their consumer sites clear the flag, then write 0x01 to address D176FB before calling function 0x011576. Specifically:
- D14078 consumer at 0x0137A7/0x0138AD: OR A → JR Z, clear D14078, write 0x01 to D176FB, call 0x011576
- D14079 consumer at 0x0137C7/0x0138C3: OR A → JR Z, clear D14079, write 0x01 to D176FB, call 0x011576

D176FB appears to gate something in the USB event processing chain. We need to fully map it.

## Task
Trace ALL references to RAM address 0xD176FB in the ROM:

1. **Find all reads and writes**: Scan the entire 4MB ROM for bytes that encode address D176FB (little-endian: 0xFB 0x76 0xD1). For each hit, determine if it's a read (LD A,(D176FB)) or write (LD (D176FB),A) by checking the surrounding opcodes.

2. **Characterize the byte**: Is it boolean (0/1)? Counter? Enum? What values are written?

3. **Map co-accesses**: What other RAM addresses are accessed in the same functions that access D176FB? Focus on addresses in the D17xxx range.

4. **Determine function**: What does D176FB gate? When it's set to 1 (by D14078/D14079 consumers), what behavior changes? When is it cleared?

5. **Identify the function at 0x011576**: This is called immediately after writing D176FB=1. What does 0x011576 do? Disassemble its first ~80 bytes to understand its role.
