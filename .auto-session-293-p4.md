# Task: Trace 0x0258DA's CP 0x28 Handler at 0x0257CC (CLEAR Key Handler)

## Context
Session 292 mapped the CP cascade at dispatcher 0x0258DA (navigation dispatcher, 10 CPs). One of the CP values is 0x28, which branches to handler address 0x0257CC. Scan code 0x28 = CLEAR key. This is the CLEAR key handler in the main event loop — understanding it reveals how the OS resets state on CLEAR press.

The dispatcher 0x0258DA is in the main navigation event loop. It reads D0058C (the scan code buffer), compares against 10 values (0x09/0x05/0x04/0x03/0x40/0x02/0x28/0x21/0x01), and branches to handlers for each.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase293-clear-key-handler.mjs` that:

1. Disassemble starting at **0x0257CC** (the CLEAR key handler target)
   - Decode instructions sequentially
   - For each instruction: PC address, raw bytes, mnemonic, operands
   - Continue until you hit a RET or JP back to the event loop, or 150 instructions

2. Specifically identify:
   - What RAM addresses are written (state being cleared/reset)
   - Any CALL targets (OS functions invoked during CLEAR handling)
   - Any writes to display RAM or VRAM-related addresses
   - Whether the handler clears D0058C/D0058E (scan code buffer)
   - Whether it calls the home-screen redraw function
   - Any IY-relative flag operations (RES/SET bits)

3. Also disassemble 2-3 other handlers from 0x0258DA for comparison:
   - CP 0x09 handler (whichever key that is)
   - CP 0x40 handler
   This shows the pattern: are all handlers similar in structure or does CLEAR do something special?

4. Print a summary:
   - CLEAR handler: total instructions, RAM writes, CALL targets, purpose summary
   - Comparison handlers: brief summary of what they do
   - Overall: does CLEAR just clear the scan code, or does it do a full state reset?
