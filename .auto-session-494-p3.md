# Task: Map Full BCALL Jump Table (2,178 Entries)

## Context
We are transpiling the TI-84 Plus CE OS ROM (eZ80) to JavaScript. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB). Session 493 discovered the OS BCALL jump table at 0x020104-0x02230B with 2,178 entries. Each entry is a 4-byte `JP` instruction: `C3 xx xx xx` where the 3-byte address is little-endian (24-bit eZ80 address).

## Deliverable
Create `TI-84_Plus_CE/probe-phase494-full-bcall-table.mjs` that:
1. Reads the ROM binary
2. Extracts ALL 2,178 bcall table entries from 0x020104 to 0x02230B
3. For each entry: extract the JP target address
4. Cross-reference targets with known function addresses
5. Identify functional clusters
6. Output a structured report

## Implementation

```javascript
import fs from 'fs';
const rom = fs.readFileSync(new URL('./ROM.rom', import.meta.url));

const TABLE_START = 0x020104;
const ENTRY_SIZE = 4; // C3 xx xx xx
const NUM_ENTRIES = 2178;

const entries = [];
for (let i = 0; i < NUM_ENTRIES; i++) {
  const offset = TABLE_START + i * ENTRY_SIZE;
  const opcode = rom[offset];
  if (opcode !== 0xC3) {
    console.log(`WARNING: Entry ${i} at 0x${offset.toString(16)} is not JP (0x${opcode.toString(16)})`);
    continue;
  }
  const addr = rom[offset + 1] | (rom[offset + 2] << 8) | (rom[offset + 3] << 16);
  entries.push({ index: i, tableOffset: offset, target: addr });
}
```

## Analysis to perform

### 1. Address range distribution
Group entries by ROM region (0x00xxxx, 0x01xxxx, ..., 0x0Bxxxx). Count entries per region.

### 2. Known function cross-reference
Flag entries that match known addresses:
- 0x061003 = cursor erase (entry 832)
- 0x060FEA = cursor draw candidate (entry 831)
- 0x0059C6 = character renderer
- 0x0A23C0 = setLCDWindow
- 0x0A239E = drawPixelBlock
- 0x0A2400 = pixel renderer
- 0x05E386 = validation
- 0x005A48 = VRAM row calculator
- 0x0A2032, 0x0A1CEC, 0x0A22B1 = rendering pipeline functions
- 0x04C979 = idle loop function
- 0x060EF5, 0x060F85, 0x060B8D, 0x060C23, 0x060C39, 0x06118A = cursor cluster entries

### 3. Cluster identification
Identify dense clusters: entries with targets in the same 0x1000 range. Display clusters with 5+ entries. Label obvious functional groups:
- 0x060xxx = display/cursor
- 0x0A2xxx = rendering pipeline
- 0x04xxxx = math/FPU
- 0x05xxxx = text editing
- 0x09xxxx = system/menu
- 0x0Bxxxx = USB/filesystem

### 4. Duplicate target detection
Find any entries that point to the SAME target address (function aliasing).

### 5. Sequential run detection
Find runs of consecutive entries whose targets are also sequential in ROM (suggesting a contiguous function block that was split into bcall entries).

## Output format
Print:
1. Total entries extracted and any non-JP entries
2. Address range distribution histogram
3. Top 20 densest clusters (sorted by entry count)
4. All known function matches
5. Any duplicate targets
6. Notable sequential runs (5+ consecutive)
7. The cursor cluster entries 826-833 with their targets (for verification against session 493)
8. Full entry list as JSON array: `[{index, target_hex}]` — write to `TI-84_Plus_CE/bcall-table.json`

## Important constraints
- This is a PURE ANALYSIS probe — no CPU execution needed, just ROM binary reading
- No peripherals, no stepping, no VRAM
- Write the full table to `TI-84_Plus_CE/bcall-table.json` for future reference

## Probe safety
Run via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase494-full-bcall-table.mjs`
(Though this probe doesn't step the CPU, still use the watchdog for consistency.)
