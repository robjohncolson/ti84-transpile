# Auto-Session 363 P1: Trace SP Corruption Origin

## Goal
Create a probe that instruments the boot sequence to log every SP change, identifying the exact instruction/block that transitions SP from RAM (~0xD1A7E5) to ROM space (~0x014C6F).

## Background
Session 362 found that boot terminates at a fake address 0x4C7B21 because SP has been corrupted into ROM space. At step 2672, SP is in RAM (~0xD1A7E5). By step 2685, SP is in ROM (~0x014C6F). The transition happens inside or after block 0x014C63 (called at step 2673). We need the exact instruction.

The RAM trampoline in `cpu-runtime.js` (line 1146-1156) intercepts missing blocks at RAM addresses >= 0xD00000 and does a synthetic RET: pops 3 bytes from SP, SP += 3. The flash self-test at 0xD18C22 is the primary trampoline target.

## Deliverable
Create file: `TI-84_Plus_CE/probe-phase363-sp-corruption-trace.mjs`

## What the probe must do
1. Boot from 0x000000 in z80 mode with timerInterrupt: false
2. Hook into execution to log SP value at EVERY step (or at minimum, every block entry)
3. Specifically watch for SP transitioning from >= 0xD00000 (RAM) to < 0x400000 (ROM space)
4. When the transition is detected, log:
   - The step number
   - The block address being executed
   - The previous SP value and the new SP value
   - The instruction at that block (use ez80-decoder.js `decodeInstruction`)
   - CPU register dump (A, BC, DE, HL, IX, IY, SP, PC, MBASE, flags)
5. Also log SP at steps 2670-2690 (the known corruption window) with full register dumps
6. Run max 5000 steps, boot entry 0x000000, z80 mode
7. Print a summary at the end: "SP corruption detected at step N, block 0xXXXXXX, instruction: ..."

## How to hook SP tracking
The `run()` method in cpu-runtime.js accepts an `opts` object. Use `opts.onStep` or `opts.onBlock` if available. If not, use `opts.onMissingBlock` won't suffice — you need every step.

Better approach: Use the existing probe pattern from phase362. Create a CPU runtime, load transpiled blocks, then call `cpu.run()` with appropriate callbacks. The `opts` parameter supports:
- `onStep(pc, mode, steps, cpu)` — called every step if present
- `onMissingBlock(pc, mode, steps)` — called on missing blocks
- `maxSteps` — step limit

If `onStep` doesn't exist, instrument by wrapping each compiled block function to log SP before/after execution. Or patch the run loop temporarily.

Actually, the simplest approach: after loading the runtime, monkey-patch `cpu.run()` or create a step-by-step execution loop that checks SP after each block. Look at how probe-phase362-investigate-4C7B21.mjs does its tracing.
