# Task: Trace 0x0005CC JP 0x007B70 boot vector

## Context
This is the TI-84 Plus CE ROM transpilation project. Session 323 classified 5 unreferenced LCD wrappers. One of them — 0x007B70 (read_800C_800D_16bit, reads LCD DMA timing registers) — turned out to NOT be truly dead. It's referenced by a JP instruction at address 0x0005CC, which is part of the boot vector table in the 0x000000-0x000FFF region.

## Goal
Write a probe `TI-84_Plus_CE/probe-phase324-boot-vector-0005CC.mjs` that:

### Part 1: Static analysis of the boot vector table region
1. Disassemble the region around 0x0005CC (from 0x000580 to 0x000600) to see the context — what other vectors are nearby?
2. Check if 0x0005CC is part of a regular vector table pattern (JP every N bytes)
3. Identify all JP targets in this region

### Part 2: Who reaches 0x0005CC?
1. Scan the ROM for all references to 0x0005CC:
   - Search for the 3-byte little-endian encoding: CC 05 00 (since addresses in eZ80 are 24-bit LE)
   - Also search for CALL 0x0005CC and JP 0x0005CC patterns
2. Report all locations that reference this address

### Part 3: What does 0x007B70 do?
1. Disassemble 0x007B70 (first 50 bytes)
2. It's supposedly "read_800C_800D_16bit" — verify it reads ports 0x800C and 0x800D
3. What does it do with the values? Where does it store the result?

### Part 4: Is this vector exercised during normal boot?
1. Run the standard boot sequence (entry 0x000000 → 0x08C331 → 0x0802B2) with a step limit of 100,000
2. Log whether PC ever reaches 0x0005CC or 0x007B70 during boot
3. If yes: what triggered it? If no: it's a dormant vector

## Byte scanning for references
To find references to address 0x0005CC in the ROM:
```javascript
const target = 0x0005CC;
const b0 = target & 0xFF;         // 0xCC
const b1 = (target >> 8) & 0xFF;  // 0x05
const b2 = (target >> 16) & 0xFF; // 0x00
for (let i = 0; i < 0x400000 - 2; i++) {
  if (rom[i] === b0 && rom[i+1] === b1 && rom[i+2] === b2) {
    // potential reference at address i (the target bytes start here)
    // check what instruction is at i-1 or i-3 for CALL/JP opcodes
  }
}
```
Note: JP nn is opcode 0xC3 followed by 3-byte address. CALL nn is 0xCD followed by 3-byte address. The address bytes at i would be preceded by the opcode at i-1 (for 4-byte CALL/JP instructions).
