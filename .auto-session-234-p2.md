# Task: Trace 0x02FFF6 and 0x0300CB pre-cascade exit paths (iii-2)

## Context
You are working on the TI-84 Plus CE ROM transpilation project. We are tracing the OS key-event dispatch pipeline at function 0x02FE89.

Session 233 decoded the CP 0x36/0x30 classification. Before the main CLEAR/MODE/other-key cascade, there are two pre-cascade gates:
- **BIT 3,(IY+18)** → if SET, **JP 0x02FFF6** (skips entire classification)
- **BIT 4,(IY+18)** → if SET, **JP 0x0300CB** (skips classification)

These are exit paths that bypass the normal key-code classification. We need to understand what they do.

IY+18 is at address 0xD00098 (IY = 0xD00080). 
- BIT 3 of IY+18 = bit 3 of (0xD00098)
- BIT 4 of IY+18 = bit 4 of (0xD00098)

From session 233: CLEAR key (0x36) does `SET 3,(IY+18)` and MODE key (0x30) does `SET 4,(IY+18)`. So these gates handle "key pressed WHILE CLEAR or MODE is active" scenarios.

## What to do

Create a probe file `TI-84_Plus_CE/probe-phase234-02fff6-0300cb-exit-paths.mjs` that:

1. **Disassembles 0x02FFF6-0x030100** (at least ~260 bytes from 0x02FFF6 to cover both targets plus surrounding code).

2. **Traces 0x02FFF6 dynamically**:
   - Full boot sequence (same as other probes: z80 boot → kernelInit → memInit → homescreen stages 1-4)
   - Disable timer IRQ: `createPeripheralBus({ timerInterrupt: false })`
   - IX = 0xD1A860 before each homescreen stage
   - After boot: SET BIT 3 of (0xD00098) to arm the gate
   - Set A to a key code (e.g., 0x8F)
   - Jump to 0x02FFF6
   - Trace 200 steps, recording blocks, IY flag changes, CALL/JP targets, RAM writes

3. **Traces 0x0300CB dynamically** — same setup but SET BIT 4 of (0xD00098) instead, and jump to 0x0300CB.

4. **Compare the two paths**: Do they converge? Do they return to the main dispatch loop (JP 0x02FD99)? Do they call different handlers?
