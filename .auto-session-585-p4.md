## Background
Session 584 resolved the event system architecture: 0x0236F9 is the central event posting dispatch (30 bytes, 42 callers). It writes a 3-byte record [type, mode, context] to a stack-local buffer, then reads port 0xDCA0 as an ack/notification.

Among the 27 event types, type 0x09 is the MOST FREQUENT with 8 callers. Some type-0x09 callers also do LDIR copies to D005F8 or D02510 after the event post, suggesting type-0x09 events carry additional context data. We need to trace what these 8 callers are and what type-0x09 means.

## Task
Create a probe `TI-84_Plus_CE/probe-phase585-trace-type09.mjs` that:

1. Reads the ROM file (`TI-84_Plus_CE/ROM.rom`) as a Buffer
2. Uses the decoder at `TI-84_Plus_CE/ez80-decoder.js` (import `{ decodeInstruction }`)
3. Finds all CALL references to 0x0236F9 across the ROM (search for byte pattern `CD F9 36 02` for non-ADL CALL or `ED 9A` followed by `F9 36 02` for ADL CALL — try both patterns).
4. For each caller site found, look backward up to 20 bytes for `LD A,0x09` (opcode `3E 09`) which sets the event type. Collect only those callers where A=0x09.
5. For each type-0x09 caller:
   - Print the caller address and the few instructions before and after the CALL
   - Look for LDIR instructions after the CALL (within 30 bytes) — these copy additional data
   - Identify what function contains the caller (look backward for common function prologues: PUSH IX, LD IX+disp, etc.)
   - Note any RAM addresses referenced (D005F8, D02510, or others)
6. Print a summary table: caller address, parent function (if identifiable), post-call behavior (LDIR destination if any), and a hypothesis about what each type-0x09 event represents.
