# Task: Call 0x005A75 (character renderer) DIRECTLY with proper register setup

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript. We've been tracing the OS display pipeline.

Session 481 found that calling 0x0059C6 with D00595=0, D00596=0 enters a FULL SCREEN INIT PATH (147K VRAM bytes, doesn't return in 50K steps). But session 478 proved that 0x0059C6 WITH D0059C pre-set to 0xD40000 renders individual glyphs correctly.

The key insight: 0x0059C6 calls 0x005A20 (padding) then 0x005A75 (the actual character renderer). 0x005A75 computes the VRAM address from D00595/D00596:
- vram_addr = 0xD40000 + (D00595 × 20 + 37) × 640 + (D00596 × 12 + 2) × 2

## Task
Create a probe `TI-84_Plus_CE/probe-phase482-direct-005A75.mjs` that:

1. Uses the EXACT template pattern from `TI-84_Plus_CE/probe-phase478-char-output-test.mjs` (read it first!)
2. After 3-stage boot, set up display state: D00595=0 (row 0), D00596=0 (col 0), D0058B=0x70, MBASE=0xD0, IY=0xD00080
3. Call 0x005A75 DIRECTLY (bypassing 0x0059C6 entirely) with:
   - A = 0x48 ('H') — set via `cpu._a = (0x48 << 24)`
   - B = 0x10 (16 rows per glyph) — set via `cpu._b = (0x10 << 24) | (cpu._b & 0x00FFFFFF)` or however the register encoding works
   - D0059C pre-computed: For row 0, col 0: vram = 0xD40000 + (0×20+37)×640 + (0×12+2)×2 = 0xD40000 + 23680 + 4 = 0xD45C84
   - Actually compute it: (37)×640 = 23680, + 4 = 23684 = 0x5C84. So D0059C = 0xD45C84
   - Write D0059C: mem[0xD0059C]=0x84, mem[0xD0059D]=0x5C, mem[0xD0059E]=0xD4
   - D005A0 = 37 (computed pixel row): mem[0xD005A0] = 37
4. Run with maxSteps=5000, maxLoopIterations=100
5. Snapshot VRAM before and after, report bytes changed
6. Then try rendering 'H','E','L','L','O' by calling 0x005A75 five times, incrementing D00596 between each call (col 0,1,2,3,4) and recomputing D0059C for each column position
7. Report VRAM changes per character and total

Also try a SECOND experiment: call 0x0059C6 with a 200K step budget (maxSteps=200000) to see if the screen init path COMPLETES when given enough steps. Set D00595=0, D00596=0, D0059C=0 (let it compute). Use a separate VRAM snapshot for this.
