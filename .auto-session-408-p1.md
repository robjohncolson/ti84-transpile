# Task: Trace 0xD141B5 Consumers — Find the Real Key→Action Dispatch Mechanism

## Context
This is a TI-84 Plus CE ROM (eZ80) transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB). We lift eZ80 machine code to JavaScript.

Sessions 402-406 traced what we thought was an "action pipeline" at 0xD005F8, but session 407 proved it's actually the OP1-OP6 floating-point register file (standard TI-OS FP math). The real key→action dispatch mechanism is STILL UNTRACED.

The key lifecycle ends at **0xD141B5** — this is the final key output buffer where processed keys are stored by 0x03FB9A (post-processor). Written only when currently zero (single-slot buffer).

## Your Task
1. **Find all readers of 0xD141B5** in the ROM. The byte pattern for `LD A,(0xD141B5)` is `3A B5 41 D1` (little-endian). Also search for `LD HL,0xD141B5` = `21 B5 41 D1` and any other addressing modes.

2. **For each reader**, disassemble 30-50 bytes of surrounding context to understand:
   - What function is it in?
   - What does it do with the key code after reading it?
   - Does it dispatch to different handlers based on the key code value (CP instructions)?
   - Does it call other functions with the key code?

3. **Identify the dispatch mechanism**: Where do key codes get routed to specific handlers (home screen input, menu navigation, graph mode, etc.)?

4. **Also check 0x08C5D7 (cxSwitch)** — session 397 identified this as a context switch function. Does it read 0xD141B5?

## Deliverables
- Create `TI-84_Plus_CE/probe-phase408-D141B5-consumers.mjs` — a Node.js probe script that:
  - Loads the ROM: `const rom = require('fs').readFileSync('TI-84_Plus_CE/ROM.rom');`
  - Searches for all byte patterns that reference 0xD141B5
