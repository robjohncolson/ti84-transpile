# Auto-Session 405 P2: Map Notification Payload Semantics

## Context
The TI-84 CE OS notification system at 0x049CCA takes a type byte and a payload byte. Session 404 traced 167 callers and found:
- 13 distinct notification types (0x00-0x18)
- Payload bytes vary by type: scan codes (0x80+) for BLOCK types, small indices (0x01-0x11) for ALLOW types
- The notification handler at 0x049D3A has a selector table that dispatches on the type
- All 13 value-store handlers store (IX+6) to 0xD177B8

The question: what does the payload MEAN for each type, and what do the 13 handlers at 0x049D3A's selector table actually DO beyond storing to 0xD177B8?

2. For each handler, disassemble 40 bytes and decode what it does:
   - Does it just store (IX+6) to D177B8 and return?
   - Does it call other subroutines?
   - Does it modify additional RAM locations?
   - Does it check the payload value (in A or on stack)?
3. For the most common notification type (0x11, Stat/List, 27 callers), trace 5 representative callers to see what payload values they pass and what context they're in
4. Build a table: type → handler address → handler behavior → typical payloads

Also write `TI-84_Plus_CE/phase405-notification-payloads-report.md` with findings.

## Technical Details
- ROM file: `TI-84_Plus_CE/ROM.rom` (4 MB, little-endian eZ80)
- eZ80 instructions: CALL nn = 0xCD + 3-byte LE address; JP nn = 0xC3 + 3-byte LE; LD A,n = 0x3E + byte; LD (nn),A = 0x32 + 3-byte LE
- The _seqcase table format (used by TI-OS): each entry is 1-byte match value + 3-byte target address. Default handler follows the last entry.
- 0x049CCA caller pattern: typically LD A,<type> / LD <reg>,<payload> / CALL 0x049CCA
- To find callers of 0x049CCA: scan ROM for bytes CD CA 9C 04
