# Task: Trace 0x09C775 Caller Chain — Sole SET 0,(IY+9) Site

## Context
This is a TI-84 Plus CE ROM transpilation project. ROM: `TI-84_Plus_CE/ROM.rom`. Runtime: `TI-84_Plus_CE/cpu-runtime.js`. Transpiled code: regenerate via `node scripts/transpile-ti84-rom.mjs`.

Session 258 found that **0x09C775 is the ONLY site in the entire ROM that does SET 0,(IY+9)**. IY+9 bit 0 is STAT-specific — it gates D007E0 writes in function 0x09E2EC. Since non-STAT contexts (home screen, Y= editor, graph) must write D007E0 via a DIFFERENT path, understanding 0x09C775's caller chain tells us exactly what OS context activates the STAT write path.

## Task
Create a probe `TI-84_Plus_CE/probe-phase263-09c775-caller-chain.mjs` that:

1. **Statically finds the function containing 0x09C775** — scan backwards from 0x09C775 in the ROM for a RET (0xC9) or other function boundary. The function likely starts right after a RET.

2. **Statically finds ALL callers of that function** — scan the ROM for `CD xx yy zz` (CALL) and `C3 xx yy zz` (JP) and `CA/C2/D2/DA/E2/EA/F2/FA xx yy zz` (conditional JP) where the target is the function entry address. Also check `xx yy zz` patterns for `C4/CC/D4/DC/E4/EC/F4/FC` (conditional CALL).

3. **For each caller found**, decode the 10 bytes before and after the CALL/JP to understand the calling context (what registers are set up, what conditions are checked).

4. **Traces upward** — for each caller, find ITS parent function (scan backward for RET boundary) and search for callers of THAT function. Go 2-3 levels deep.

5. **Documents the call chain** from OS entry points down to 0x09C775, with annotations about what each level does.

## Reference: eZ80 ADL Instruction Encoding
- CALL nn = CD xx yy zz (24-bit target, little-endian)
- JP nn = C3 xx yy zz
- Conditional CALL: C4 (NZ), CC (Z), D4 (NC), DC (C), E4 (PO), EC (PE), F4 (P), FC (M)
- Conditional JP: C2 (NZ), CA (Z), D2 (NC), DA (C), E2 (PO), EA (PE), F2 (P), FA (M)
- RET = C9
- SET 0,(IY+9) = FD CB 09 C6
