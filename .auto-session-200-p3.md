# Auto-Session 200 — P3: Integrate ParseInp arithmetic into browser-shell

## Context

We're transpiling the TI-84 Plus CE OS ROM into JavaScript with a browser shell frontend. Currently the browser shell uses a JavaScript `eval()` bypass (EVAL_TOKEN_MAP + direct JS evaluation) for arithmetic expressions. We have PROVEN that the real ROM ParseInp can evaluate arithmetic:

- Session 190: "2+3"=5, "5"=5, "9-4"=5 all correct via PushErrorHandler→ParseInp→JError recovery→OP1
- Session 191: "3*4"=12, "8/2"=4, "2^3"=8, "2*(3+4)"=14 all correct
- The pattern: BufInsert tokens → PushErrorHandler(0x099929) → ParseInp(0x099914) → JError(errNo=0x8D) → z80-mode RET intercept → recovery at 0x099929 → OP1 contains BCD float result

### Implementation steps:

1. **Add a checkbox or toggle** in the browser shell UI labeled "Use ROM Parser" (default: off).

2. **Implement `evaluateViaParseInp(expression)`** function that:
   a. Tokenizes the expression string using EVAL_TOKEN_MAP (already exists) to get token bytes
   b. Calls BufInsert (0x05E2A0) for each token byte to place them in the edit buffer at 0xD00A00
   c. Sets up PushErrorHandler: write error frame to stack, set errSP, set hlPayload=0x099929
   d. Calls ParseInp at 0x099914
   e. Intercepts the z80-mode RET at 0x03E1B1 (hard-code PC=0x03E1CA + ADL mode when block `03e1b1:z80` fires)
   f. After recovery reaches 0x099929, reads OP1 (0xD005F8, 9 bytes) as BCD float
   g. Converts BCD float to JavaScript number for display

3. **BCD float → JS number conversion**: OP1 format is [sign_type, exponent, mantissa...]. 
   - Byte 0: bit 7 = sign (0=positive, 1=negative), bits 6:0 = type (0x00 = real)
   - Byte 1: exponent + 0x80 bias (so 0x80 = 10^0, 0x81 = 10^1, etc.)
   - Bytes 2-8: BCD mantissa digits (2 digits per byte, implied decimal after first digit)
   - Example: 5.0 = `00 80 50 00 00 00 00 00 00` → sign=+, exp=0, mantissa=5.0

4. **Error handling**: If ParseInp fails or hits a missing block, fall back to the JS eval() path and log a warning.

5. **The z80-mode RET intercept**: The existing probes use this pattern:
   ```javascript

   // Override: set cpu.pc = 0x03E1CA, cpu.madl = 1 (back to ADL mode)
   ```
