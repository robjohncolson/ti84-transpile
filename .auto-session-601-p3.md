# Task: Verify the '2' glyph in VRAM at the expected cursor position

## Context
This is a TI-84 Plus CE ROM transpilation project. Session 600 confirmed that after pressing '2' (internal code 0x90), the OS renders 3,349 non-white pixels to VRAM (0xD40000, BGR565, 320x240, 2 bytes/pixel). The display shows MathPrint-style glyphs in rows 39-132 with 15+ distinct character clusters. But we haven't confirmed which specific character is '2'.

The TI-84 CE home screen in Classic mode shows an 8×10 font at the cursor position. In MathPrint mode the font is larger (~12×14). The cursor starts at the left edge of the entry line (typically row ~220, column ~0 in Classic; varies in MathPrint). After typing '2', the character should appear at the first cursor position.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase601-verify-2-glyph.mjs` that:

1. Uses the EXACT boot sequence from `TI-84_Plus_CE/probe-phase599-wipe-tracker.mjs` (Phase 0 through Phase 2 — cold boot, launch-init 0x09DD62, paint 0x058241). Copy it verbatim.

2. Seeds a key (D0058C=0x90, D0058E=0x90, D0009F|=0x20) and runs the outer loop from 0x08C331 with maxSteps=500_000 and maxLoopIterations=500_000. Push 0x0019b5 return, seed D008E0.

3. After the run completes, analyzes VRAM to find the '2' glyph:

   a. **Scan the ENTIRE body area** (rows 30-239, all 320 columns). For each row, count non-white pixels and identify pixel clusters (contiguous horizontal runs of non-white pixels).
   
   b. **Find all character-sized clusters**: groups of non-white pixels that form ~8-14px wide × 10-14px tall rectangular regions. For each cluster, output its bounding box (row range, column range) and the pixel bitmap within that box.
   
   c. **Dump the raw pixel bitmap** for the FIRST cluster found in the bottom third of the screen (rows 160-239, which is where the entry line typically appears). Format as ASCII art: '#' for non-white, '.' for white, one row per line, with row/col coordinates labeled.
   
   d. **Also dump pixel bitmaps** for any clusters found in rows 39-55 (the first text line where session 600 saw glyphs).
   
   e. **Compare against known '2' shape**: the digit '2' has a characteristic shape — curved top-right, diagonal descent left, horizontal base. Check if any found glyph matches this shape qualitatively.

4. Also read the edit cursor positions D0231A/D0243A after the run — if non-zero, they point to the cursor's buffer position which correlates to screen position.

5. Read D007E0 (display mode) to confirm it's 0x40 (home screen).

## Key constraints
- VRAM layout: base 0xD40000, BGR565, 320 pixels wide × 240 pixels tall, 2 bytes per pixel (little-endian), row-major.
- White = 0xFFFF. Non-white = anything else.
- Import pattern: same as other probes
- NEVER push 0x0019be as return address. Use 0x0019b5.
- Run via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase601-verify-2-glyph.mjs`

## Success criterion
The probe identifies character glyphs in the VRAM body area and dumps their bitmaps as ASCII art. If a '2'-shaped glyph is found, report its location (row, column). If no recognizable '2' is found, report what glyphs ARE present and where.

Run the probe via the watchdog: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase601-verify-2-glyph.mjs`
