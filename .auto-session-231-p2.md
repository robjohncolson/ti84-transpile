# Auto-Session 231 — P2: Verify 0x030100 Transpiled Key Lookup Path

## Context
Session 230 added a transpiler seed at 0x030100, adding 2 new blocks and 107 covered bytes. The function at 0x0300F1-0x030172 is the key code lookup that uses the 09F79B table. The formula is:
- offset = scanCode + (alpha ? 0x70 : 0) + (2nd ? 0x38 : 0)
- Table at 0x09F79B has 4 sections of 56 entries each (224 total)

Session 229 decoded the function but noted block 0x030100 was missing. Now it's transpiled.

## Task
Create a probe `TI-84_Plus_CE/probe-phase231-030100-verify.mjs` that:

1. **Boot the system** (z80 boot → kernelInit → memInit → homescreen render) with timer interrupts disabled.

2. **Test 6 representative scan codes** through the key lookup function at 0x03013A (the CALL entry point used by 0x02FDA8):

   - Scan code 0x80 (+ key, no modifier) — expect key code from no-mod section
   - Scan code 0x9A (first letter key, no modifier) — expect key code from no-mod section
   - Scan code 0x8F with 2nd flag set (IY+0 bit 2 or whatever flag 0x030100 checks for 2nd) — expect key code from 2nd section
   - Scan code 0x8F with alpha flag set — expect key code from alpha section
   - Scan code 0x60 (GRAPH key) — expect key code from no-mod section

3. For each test:
   - Set A = scan code
   - Set appropriate modifier flags if needed (check what 0x030100 reads for alpha/2nd detection — session 229 says the function checks flags to compute offset)
   - Set D0058E to the scan code (the function may read from here)

   - Capture: return value in A (or wherever the key code lands), D0058E after execution, number of steps, blocks visited
   - Check if block 0x030100 was visited (it should be now that it's transpiled)

4. **Verify no missing_block**: Confirm that execution through 0x030100 completes without hitting any missing_block sentinel or unexpected halt.

5. **Cross-reference results** with the phase230-09f79b-full-table.json to verify the looked-up key codes match the expected table values.
