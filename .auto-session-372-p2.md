# Task: Trace Key Dispatch Path (0x003A7B to 0x003C60)

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The OS event loop enters at 0x003A73 and reads the keyboard at 0x003A73-0x003A7B, but only visits that region ~4 times in 500K steps. The dominant execution time is spent in the 0x003D6B idle spin loop. We need to understand the path FROM key detection TO the idle loop — specifically, what is between 0x003A7B and 0x003D6B, and what branch decides whether a key is dispatched or the idle spin resumes.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase372-key-dispatch-path.mjs` that:

1. **Disassembles the range 0x003A73 through 0x003D80** — every block in this range. Use decodeInstruction to decode at least 30 bytes starting from each known block entry point. Known entry points to start with: 0x003A73, 0x003A7B, 0x003A80, 0x003A90, 0x003B00, 0x003B50, 0x003C00, 0x003C50, 0x003C60, 0x003D00, 0x003D28, 0x003D2E, 0x003D5A, 0x003D5C, 0x003D62, 0x003D67, 0x003D6B, 0x003D70, 0x003D73. Also follow any JP/JR/CALL targets you find in the disassembly.
2. **Runs the event loop** with ENTER key injected BEFORE entering the event loop, timerInterrupt:false, maxSteps=50000, maxLoopIterations=100000. Track ALL visited blocks in the 0x003A00-0x003E00 range with visit counts.
3. **Runs the event loop again** WITHOUT a keypress for comparison (same settings). Compare which blocks differ between key-pressed and no-key runs.
4. **Maps the control flow**: For each JP/JR/CALL in the 0x003A73-0x003D80 region, note the target address to build a control flow graph of this region.
