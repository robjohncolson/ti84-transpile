# Task: Map the 6 Crash Stubs (Mega-Table Entries 0-5 + 2022)

## Context

You're working on the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 24-bit addressing).

Session 318 found that mega-table entries 0-4 are crash stubs that chain to 0x0003AC → 0x0019B5 (DI + HALT). Entry 2022 is also reported as a crash stub. RST 28h and RST 30h (entries 3 and 4) are error traps. The mega-table has 2175 entries starting at 0x020110, each 4 bytes (JP + 3-byte target).

The crash chain is:
```
Entry N → JP 0x04ABxx (stub) → JP 0x0003AC → JP 0x0019B5 → DI; LD A,0x10; OUT0(0x00),A; HALT
```

## Task

1. **Verify all 6 crash stubs.** Read entries 0, 1, 2, 3, 4, and 2022 from the mega-table. For each, follow the JP chain to confirm it ends at 0x0019B5 DI+HALT.

2. **Check for more crash entries.** Scan ALL 2175 mega-table entries to find any others that chain to 0x0003AC or 0x0019B5. Are there exactly 6, or are there more?

3. **Disassemble 0x0019B5 fully.** How many bytes? What does `OUT0(0x00), A` do (port 0x00 write)? Is this a hardware reset or just a CPU halt?

4. **Find all paths TO the crash chain.** Besides the mega-table entries, does any other ROM code JP/CALL to 0x0003AC or 0x0019B5? What triggers these crashes?

5. **Determine entry 2022's purpose.** Why is entry 2022 a crash stub when entries 5-2021 are valid? Is it a sentinel marking end-of-table, or a disabled/deprecated entry?

## Deliverables
