# Task: Trace 0x012456 (USB Endpoint Setup)

## Context
You are working on a TI-84 Plus CE ROM reverse-engineering project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). The instruction decoder is at `TI-84_Plus_CE/ez80-decoder.js`.

Session 419 decoded 0x0098D2, the deep USB event dispatcher. During USB connect events, it calls 0x012456 for endpoint setup. We need to understand what endpoints it configures and how it sets up ports 0x3080/0x3010.

## Deliverables

### 1. Probe file: `TI-84_Plus_CE/probe-phase420-trace-012456.mjs`

Write a probe that:
1. Reads ROM.rom
2. Imports and uses `ez80-decoder.js` (use `await import('./ez80-decoder.js')` with `process.emitWarning = () => {}`)
3. Disassembles from 0x012456 forward until finding a RET (estimate ~200-400 bytes)
4. For each instruction, prints: address, raw hex bytes, decoded mnemonic
5. Annotates CALL targets, port I/O (IN/OUT instructions — look for BC register loads followed by IN A,(C) or OUT (C),A), and RAM variable accesses (addresses in D00000-D3FFFF range)
6. Identifies any sub-functions called and their apparent purpose

Use the same probe style as `TI-84_Plus_CE/probe-phase419-trace-014D48.mjs` (read it for reference).

The decoder function signature: `decodeInstruction(romBuffer, pc, 'adl')` returns `{tag, length, nextPc, ...fields}`.

### 2. Report file: `TI-84_Plus_CE/phase420-endpoint-setup-report.md`

After running the probe, write a report with:
- Function boundary (start/end address, byte count)
- What USB endpoints it configures (port 0x3080 = USB controller, 0x3010 = link port)
- What port writes it makes (port address, bit mask, purpose)
- What RAM variables (D00000-D3FFFF) it initializes
- What CALL targets it invokes
- Overall purpose assessment

## Constraints
