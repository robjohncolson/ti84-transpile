**0x0B86AB** is the primary cursor activator (~200 bytes, decoded in session 509). It calls these four functions in sequence:
- 0x0B95E0 — cursor_setup (called early in 0x0B86AB)
- 0x0B968E — cursor_draw (called after post-gate processing)
- 0x0B96B3 — cursor_render (called right after draw)

These are the actual pixel-level cursor operations. We need to decode them to understand how cursor pixels are drawn/erased on the LCD.

## eZ80 Decoding Reference

The eZ80 CPU uses these key patterns:
- `CD xx xx xx` = CALL addr (3-byte address in little-endian)
- `C3 xx xx xx` = JP addr
- `C9` = RET
- `ED` prefix for block ops, IN/OUT, extended arithmetic
- `DD` = IX prefix, `FD` = IY prefix
- `CB` prefix for bit operations (BIT/SET/RES/rotation)
- `52` = .SIS prefix (use 16-bit addresses in 24-bit mode)
- `49` = .LIS prefix
- `FD CB dd xx` = IY+d bit operations (dd = signed displacement, xx = operation)
- Common: `AF` = XOR A, `32 xx xx xx` = LD (addr),A, `3A xx xx xx` = LD A,(addr)
- `21 xx xx xx` = LD HL,addr, `11 xx xx xx` = LD DE,addr
- `E5` = PUSH HL, `E1` = POP HL, `C5` = PUSH BC, `C1` = POP BC
- `18 xx` = JR offset, `20 xx` = JR NZ, `28 xx` = JR Z
- `FE xx` = CP n
- `E7` = RST 28h (BCALL), followed by 2-byte index

## Implementation

```javascript
import { readFileSync } from 'fs';

const rom = readFileSync('TI-84_Plus_CE/ROM.rom');

function readBytes(addr, len) {
  return Array.from(rom.slice(addr, addr + len));
}

function hexByte(b) { return b.toString(16).padStart(2, '0'); }
function hexAddr(a) { return '0x' + a.toString(16).padStart(6, '0'); }
function read24LE(bytes, i) { return bytes[i] | (bytes[i+1] << 8) | (bytes[i+2] << 16); }
```
