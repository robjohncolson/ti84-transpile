# Auto-Session 350, Priority 1: Fix Flash Port 0x06 BIT 2 After PLL Lock

## Context
The TI-84 CE boot code has a secondary polling loop after PLL locks. At address 0x0006F3, it reads port 0x06 (flash status), tests BIT 2,A — if bit 2 is 0, JR Z loops back. Currently `createFlashHandler` always returns 0xD0 (binary 1101_0000, bit 2 = 0), so the loop never exits.

After PLL locks (`state.pll.locked === true`), flash bit 2 should go high. The fix: modify `createFlashHandler` in `peripherals.js` to return 0xD4 (1101_0100) when `state.pll.locked` is true, and 0xD0 otherwise.

## File to modify
`TI-84_Plus_CE/peripherals.js`

## Current code (lines 113-127):
```javascript
function createFlashHandler(state) {
  return {
    read() {
      // Flash controller status register: reads return hardware status (0xD0 = ready).
      // Boot code reads port 0x06 but only to SET bit 2 and write back — never branches
      // on the value. The ISR gate at 0x000704 requires A=0xD0 from IN0 (0x06) for
      // the CP 0xD0 comparison to pass and dispatch to the callback handler at 0x000710.
      return 0xD0;
    },

    write(port, value) {
      state.flash.lastWrite = value;
    },
  };
}
```

## Required change
Replace the `read()` method body. After PLL locks, return 0xD4 (bit 2 set). Before PLL locks, return 0xD0 (unchanged). The state object has `state.pll.locked` (boolean) which is set to `true` by `createPllHandler` once the PLL countdown finishes.

New read() should be:
```javascript
    read() {
      return state.pll.locked ? 0xD4 : 0xD0;
    },
```

Remove the old comments — they were wrong (they said "never branches on the value" but session 349 proved it does branch on bit 2).
