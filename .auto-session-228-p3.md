# Task: Investigate the 09F79B none-mod scan table as alternate key code source

## Context
The function 0x03FC1C is a key code converter with a 56-entry table at 0x03FC41. It reads D0058D (compact keyboard matrix index), looks up a key code, and returns it in HL. However, session 227 found that sub-calls (0x03FA09, 0x0AF8C4) clobber HL, so the dynamic return value is always 0xD00604 instead of the correct key code.

Session 227 also found that the **09F79B "none-mod scan table"** has correct key code mappings (e.g., index 34→0x8F for '1', index 33→0x8E for '0', index 10→0x80 for '+'). This table may be a better path for browser-shell key code conversion than 0x03FC1C.

## Deliverables

Create a probe file `TI-84_Plus_CE/probe-phase228-09f79b-scan-table.mjs` that:

1. **Dump the table at 0x09F79B**: Read ROM.rom bytes starting at 0x09F79B. The table structure isn't known — dump raw bytes for ~200 bytes and look for patterns. Based on session 227, index 34→0x8F and index 33→0x8E, index 10→0x80. Determine:
   - Entry size (1 byte? 2 bytes?)
   - Total number of entries
   - Whether entries are contiguous or separated by row markers (0x00)
   - Full mapping of all entries

2. **Compare with 0x03FC41 table**: The 56-entry table at 0x03FC41 maps compact indices to key codes. Read both tables and compare:
   - Are they the same size?
   - Do corresponding indices map to the same key codes?
   - What are the differences?

3. **Find references to 0x09F79B in ROM**: Search for the 3-byte little-endian pattern 9B F7 09 in the ROM binary. This tells us which functions use this table and how they access it. For each reference, read the surrounding ~20 bytes and identify the access pattern (LD HL,0x09F79B + ADD? Direct indexed access?).

4. **Map the complete table**: Output a human-readable mapping:
   ```
   Index  0x03FC41_keycode  0x09F79B_keycode  Match?
   1      0x22 (DOWN)       ???               ???
   2      0x18 (LEFT)       ???               ???
   ...
   ```

import { readFileSync } from 'fs';

}
