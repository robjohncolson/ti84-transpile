# Auto-Session 192 P2: Disassemble ROM at 0x092263 LDDR successor for STAT path

## Context
Session 191 traced the STAT computation path starting from 0x058BA9 (cxErrorEP). Entry 4 reaches 87 unique blocks in the STAT area (0x091Exx-0x0922xx), penetrating deep into the computation. At step 77, it reaches 0x092263 which contains an LDDR instruction (0xED 0xB8). After the LDDR completes, execution falls to 0x000000 (boot vector) because the successor block is not seeded in the transpiler.

The raw ROM bytes at 0x092260-0x09227F are:
```
092260: c1 28 02 ed b8 11 0b 15 d0 c1 2a 08 15 d0 09 22
092270: 08 15 d0 21 e6 08 d0 ed b0 21 0b 1d d0 34 c9 f5
```

LDDR is at 092263 (ed b8). After LDDR, the successor should be at 0x092265. The bytes there are: `11 0b 15 d0` = LD DE, 0xD0150B. Then continuing: `c1` = POP BC, `2a 08 15 d0` = LD HL,(0xD01508), `09` = ADD HL,BC, `22 08 15 d0` = LD (0xD01508),HL, `21 e6 08 d0` = LD HL,0xD008E6, `ed b0` = LDIR, `21 0b 1d d0` = LD HL,0xD01D0B, `34` = INC (HL), `c9` = RET.

## Task
1. Create a probe `TI-84_Plus_CE/probe-phase192-stat-lddr-successor.mjs` that:
   a. Statically disassembles ROM bytes from 0x092265 to 0x09227F using `ez80-decoder.js` to confirm the instruction sequence
   b. Adds 0x092265 as a new transpiler seed in `TI-84_Plus_CE/phase200-seeds.txt` (append a line: `0x092265`)
   c. After adding the seed, the probe should also trace from 0x058BA9 (STAT entry 4) with a higher step limit (3000 steps) to see what happens after the LDDR successor is seeded

2. Also update `TI-84_Plus_CE/phase200-seeds.txt` to add the new seed address 0x092265.

## How to add seeds to phase200-seeds.txt
Read the file first. It's a simple text file with one hex address per line. Append `0x092265` to the end.

## Retranspile after seeding
After adding the seed, retranspile:
```bash
node scripts/transpile-ti84-rom.mjs
```
This regenerates `ROM.transpiled.js`. Takes ~2 seconds. Check the output for the new block/seed counts.

## Probe structure
Base it on `probe-phase191-stat-extended.mjs`:
- Full boot sequence: 0x000000 → 0x08C331 → 0x0802B2 → 0x09DEE0
- Then trace from 0x058BA9 with step limit 3000
- Log every unique block PC visited
- Log RAM writes in 0xD00000-0xD02000 range
- Specifically watch for blocks in the 0x092265-0x09227F range (the newly seeded successor)
- Report whether execution reaches a RET or another missing block

## Key addresses
- 0x058BA9 = cxErrorEP (STAT context entry 4)
- 0x092263 = LDDR block (currently seeded, 87 blocks reached)
- 0x092265 = LDDR successor (NOT seeded — this is what we're adding)
- 0xD01508 = RAM address used by ADD HL,BC + store (likely list pointer)
- 0xD008E6 = RAM source for LDIR (possibly OS variable area)
- 0xD01D0B = RAM address INC'd (counter/flag)
