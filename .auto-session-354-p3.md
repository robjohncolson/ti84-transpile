# Auto-Session 354 — Priority 3: Investigate Port 0xB020/0xB024 as Potential Loop Cause

## Context
The TI-84 Plus CE boot reaches 270 unique blocks then loops in LCD init. Ports 0xB020 and 0xB024 each receive 23 OUT 0xFF writes during 50K boot steps (once per cycle). These are unknown peripherals. If the init code writes to 0xB020 then reads back to verify, the default 0xFF read might always satisfy the check AND cause a retry.

## Task
Create a probe `TI-84_Plus_CE/probe-phase354-portB020-analysis.mjs` that:

### Part 1: Search ROM for IN instructions reading from 0xB020/0xB024
Scan the ROM binary for eZ80 IN instructions that reference ports 0xB020 or 0xB024. The eZ80 IN instruction patterns to search for:
- `IN A,(C)` = opcode ED 78 (reads from port in BC register)
- `IN0 A,(nn)` = opcode ED 38 nn (reads from direct port nn — but nn is only 8-bit, so this can't reach 0xB020)
- `IN A,(n)` = opcode DB nn (reads from port n, 8-bit only)

Since 0xB020/0xB024 are 16-bit port addresses, they can only be accessed via `IN A,(C)` where BC=0xB020/0xB024. Search for sequences where BC is loaded with 0xB020 or 0xB024 followed by an IN instruction:
- `LD BC, 0xB020` = 01 20 B0 (little-endian)
- `LD BC, 0xB024` = 01 24 B0

Search the ROM (4MB file at `TI-84_Plus_CE/ROM.rom`) for these byte sequences and report the addresses where they appear.

### Part 2: Boot trace with port monitoring
Boot the CPU for 5000 steps and log ALL interactions with ports 0xB020 and 0xB024:
- Every IN (read) — step, PC, port, value returned
- Every OUT (write) — step, PC, port, value written

### Part 3: Test alternate return values
If Part 2 shows any reads from 0xB020/0xB024, test what happens with different return values (0x00, 0x01, 0x80) vs the default 0xFF. Run 10K steps for each and compare unique blocks reached.

## Setup Pattern
```javascript
import fs from 'fs';
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';

const rom = new Uint8Array(fs.readFileSync('./ROM.rom'));
const cpu = createCPU(rom);
const bus = createPeripheralBus({ timerInterrupt: false });
// Intercept reads/writes for monitoring:
const origRead = bus.read.bind(bus);
const origWrite = bus.write.bind(bus);
const portLog = [];
bus.read = (port) => {
  const val = origRead(port);
  if (port === 0xB020 || port === 0xB024) portLog.push({ op: 'IN', port: '0x' + port.toString(16), val: '0x' + val.toString(16), pc: '0x' + cpu.pc.toString(16).padStart(6, '0') });
  return val;
};
bus.write = (port, val) => {
  if (port === 0xB020 || port === 0xB024) portLog.push({ op: 'OUT', port: '0x' + port.toString(16), val: '0x' + val.toString(16), pc: '0x' + cpu.pc.toString(16).padStart(6, '0') });
  origWrite(port, val);
};
cpu.io = bus;
cpu.pc = 0x000000;
```
