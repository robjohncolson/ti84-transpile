# Task: Disassemble 0x09EF44 — Keyboard MMIO Discovery (7th Level)

## Context
We are tracing the TI-84 Plus CE OS keyboard acquisition call chain to find where the actual keyboard hardware reads (IN instructions reading port 0xE009xx) occur. The chain so far:

```
0x02FCB3 (GetCSC) → 0x02FD8F → 0x03013A → 0x04E950 → 0x04E966 → 0x09EF44
```

At 0x04E966, the OS calls `CALL 0x09EF44` with registers BC=0x020F, HL=0x0121, DE=0x012A (these look like port/matrix parameters). None of the previous 6 levels contained any IN instructions or 0xE009xx MMIO reads. 0x09EF44 is where they MUST finally appear.

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase296-09ef44-keyboard-mmio.mjs`

The probe must:
1. Read `TI-84_Plus_CE/ROM.rom` (4MB binary)
2. Starting at offset 0x09EF44, disassemble eZ80 instructions until you hit a RET or JP that ends the function (typically 30-100 bytes for an OS subroutine)
3. For each instruction, output: address, hex bytes, mnemonic
4. Specifically flag any IN instructions (opcodes 0xDB for IN A,(n), or ED-prefixed IN r,(C) variants)
5. Specifically flag any memory reads from 0xE009xx addresses (keyboard MMIO range)
6. Flag any CALL targets for further investigation
7. Report the total function size in bytes

## eZ80 Decoding Reference
- eZ80 is a superset of Z80 with 24-bit addresses
- IN A,(n) = 0xDB nn (2 bytes)  
- IN r,(C) = 0xED 0x40+r*8 (2 bytes) — reads from port in BC
- CALL nn = 0xCD nn nn nn (4 bytes in ADL mode)
- RET = 0xC9
- JP nn = 0xC3 nn nn nn (4 bytes in ADL mode)
- Prefixes: 0x40 = .SIS, 0x49 = .LIS, 0x52 = .SIL, 0x5B = .LIL
- The ROM runs in ADL mode (24-bit) by default, so addresses are 3 bytes

## How to read the ROM
```javascript
import { readFileSync } from 'fs';
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
// Byte at address X: rom[X]
// 24-bit LE value at X: rom[X] | (rom[X+1] << 8) | (rom[X+2] << 16)
```
