# Task: Map all callers of 0x03FA09 and determine ISR reachability

## Context

0x03FA09 is the OS key processor that reads D00587 and writes D141B5. Session 459 found 8 CALL sites plus 1 JP thunk:

CALL sites: 0x02FDBE, 0x03005C, 0x03FC36, 0x040C9D, 0x044FDA, 0x0461C2, 0x056224, 0x09CFA5
JP thunk: 0x02014C (JP 0x03FA09)

The question: which of these 8 callers are reachable from the ISR dispatcher chain (0x03CF7D → ... → 0x03FA09), and which are called from foreground code? This determines whether fixing port 0x03 alone will unblock D141B5 writes.

The ISR dispatcher at 0x03CF7D is a 597-byte function with 3-stage port demux. It calls various handlers. We need to know if any of those handlers eventually call 0x03FA09.

## Deliverables

Write a probe `TI-84_Plus_CE/probe-phase460-callers-03FA09.mjs` that:

1. **For each of the 8 CALL sites**, disassemble the surrounding 64 bytes (32 before, 32 after) to identify:
   - What function the CALL is inside of
   - What the function does (brief description based on instructions)
   - Whether the function appears to be ISR context (checks for interrupt-related patterns: EI/DI, RETI, port reads)

2. **For the JP thunk at 0x02014C**, identify who calls 0x02014C by scanning the ROM for CALL 0x02014C and JP 0x02014C patterns

3. **Cross-reference with the ISR dispatcher**: 
   - Read the ROM bytes at 0x03CF7D (597 bytes) and extract all CALL/JP targets
   - Check if any of those targets match the 8 callers or their containing functions
   - Build a reachability chain: ISR dispatcher → intermediate function → 0x03FA09

4. **Report**: A table showing each caller, its context (ISR vs foreground), and the call chain from 0x03CF7D if ISR-reachable.

## Files to read
- `TI-84_Plus_CE/ROM.rom` — ROM binary for disassembly
- `TI-84_Plus_CE/ez80-decoder.js` — decoder
- `TI-84_Plus_CE/cpu-runtime.js` — for ROM loading

## Constraints
- Read-only probe — do NOT modify runtime files
- Self-contained: `node TI-84_Plus_CE/probe-phase460-callers-03FA09.mjs`
- The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, load with fs.readFileSync)
- eZ80 CALL instruction is 4 bytes: CD LL MM HH (24-bit address, little-endian)
- eZ80 JP instruction is 4 bytes: C3 LL MM HH (24-bit address, little-endian)
- To find CALL 0x03FA09: search for bytes CD 09 FA 03
- To find JP 0x03FA09: search for bytes C3 09 FA 03
