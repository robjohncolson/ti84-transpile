# Task: Decode 0x07EFF0 and 0x07F7FA (Numeric Renderer Exit Paths)

## Context
This is a TI-84 Plus CE ROM transpilation project. In session 515, we decoded 0x07DF6A — the alternate/BCD numeric renderer (292B, 110 instructions). It's a BCD formatting engine that converts binary/BCD values into displayable digit sequences. It has two exit paths:
- JP 0x07F7FA — taken when IY+0x0E bit 6 is clear
- JP 0x07EFF0 — taken when IY+0x0E bit 6 is set

These exit paths reveal how formatted numbers actually reach VRAM for display (e.g., graph coordinates, table values, scientific notation).

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase516-decode-exit-paths.mjs` that:

1. Reads the ROM file (`TI-84_Plus_CE/ROM.rom` via readFileSync)
2. Disassembles BOTH functions by reading raw ROM bytes and decoding eZ80 instructions:

### Function 1: 0x07F7FA
- Start at ROM offset 0x07F7FA
- Decode eZ80 instructions in ADL mode (24-bit addresses)
- Follow control flow: CALLs, JPs, conditional branches, RETs
- Map at least 100 bytes or until a clear exit (RET/JP to known function)
- Document: what subroutines it calls, what RAM it accesses, whether it writes to VRAM

### Function 2: 0x07EFF0
- Start at ROM offset 0x07EFF0
- Same decode approach
- Map at least 100 bytes
- Document same items

3. For each function, identify:
   - Does it call the rasterizer (0x0A1799) or BCD position calc (0x07C8B7)?
   - Does it write to VRAM (0xD40000+ range)?
   - What RAM addresses does it read/write?
   - Does it advance cursor position?
   - Is one a "render and advance" and the other a "render in place" variant?

## eZ80 decoding reference
- eZ80 ADL mode: 24-bit addresses, 24-bit register pairs
- CD lo mid hi = CALL addr (little-endian 3-byte address)
- C3 lo mid hi = JP addr
- C9 = RET
- FE n = CP n
- 3A lo mid hi = LD A,(addr)
- 32 lo mid hi = LD (addr),A
- CB prefix = bit operations
- FD CB offset op = IY bit operations
- DD = IX prefix, FD = IY prefix
- ROM file offset = ROM address (direct mapping)
