# Task: Decode 0x09B9C8 (token fetch mechanism)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript blocks. You need to decode the function at ROM address 0x09B9C8.

Session 521 identified that 0x09B9C8 is called at entry of the 0x09BAFF extended token classifier. Understanding this gives the token reading mechanism before classification.

Related decoded functions:
- 0x09BAFF = extended token classifier (session 521): 34 CP comparisons, 23 unique handler targets, B-register type codes
- 0x09BAB8 (session 520, 7B): reads curPC from D0231A, fetches byte at (curPC), increments curPC — "get next byte from parse stream"
- 0x09BAD1 (session 520, 7B): reads OPS stack pointer from D02593, INC HL, reads byte — "read next byte from OPS stack"
- 0x09BAAF: called before 0x09B9C8 in the classifier entry sequence

Key RAM:
- D0231A = curPC (current parse position)
- D02593 = OPS stack pointer
- D005F8 = descriptor type (B register)
- D005F9, D005FA = written by classifier

## Deliverable
Create a probe file at `TI-84_Plus_CE/probe-phase522-decode-09B9C8-token-fetch.mjs` that:
1. Reads the ROM binary directly
2. Disassembles 0x09B9C8 fully (follow until RET)
3. Also disassemble 0x09BAAF (called before 0x09B9C8) if not already fully known
4. Trace all subroutine calls 1 level deep
5. Report:
   - Full instruction listing with addresses
   - How the token is fetched (which RAM pointer, how many bytes)
   - Whether this handles 1-byte vs 2-byte tokens differently
   - What register the token ends up in (likely A)
   - Any token validation or range checking
   - How curPC (D0231A) is advanced

## Template
Base your probe on existing probes in the `TI-84_Plus_CE/` directory. Key patterns:

## Success criterion
