# Task: USB Init/Reset Caller Trace

## Context
Session 310 mapped USB vector table entries [36-48] — 13 endpoint/FIFO register helpers targeting port block 0x31xx. These are NOT called from the OS event loop. Their callers fall into two groups:

### Vector-slot callers (use the vector table address)
- `0x02A1F2..0x02A22B`: USB init/reset batch (toggles reset/stall for endpoint families)
- `0x02A31E..0x02A32D`: direction-specific stall path (selects IN vs OUT)
- `0x02A9D8..0x02AA23`: USB endpoint sweep/reset loop

### Direct target callers (bypass vector table)
- `0x009E76..0x00A607`: runtime endpoint helpers
- `0x00BD5C..0x00C558`: USB config builders
- `0x00F93A`: runtime transfer helper

The question: WHERE in the boot sequence does USB initialization happen? Is it in the 964-byte boot/wake init block at 0x040892?

## Your Deliverables

1. **Create `TI-84_Plus_CE/probe-phase311-usb-init-trace.mjs`**: A Node.js probe that:
   - Disassembles the USB init/reset batch at 0x02A1F2 (follow until RET, max 60 instructions) to understand its structure
   - Finds all CALL sites that invoke 0x02A1F2 (or the broader batch starting point) — who calls the USB init batch?
   - Traces those callers upward: are they called from the boot sequence at 0x040892?
   - Disassembles the USB config builder region 0x00BD5C-0x00C558 to find the entry point and trace its callers
   - Searches for any USB-related calls from the boot/wake init at 0x040892 — disassemble 0x040892 for ~100 instructions and identify any CALL targets that overlap with the USB caller addresses
   - Prints a call tree showing: boot sequence → USB init → endpoint helpers

2. **Create `TI-84_Plus_CE/phase311-usb-init-trace-report.md`**: A markdown report documenting:
   - The USB initialization call chain from boot to endpoint configuration
   - Whether USB init is in the 0x040892 boot block or elsewhere
   - The relationship between vector-slot callers and direct callers
   - Whether USB init is a one-time boot operation or can be re-triggered at runtime

## Technical Details

- ROM file: `TI-84_Plus_CE/ROM.rom` (4MB, read with `readFileSync`)
- Decoder: `import { decodeInstruction } from './ez80-decoder.js'` — `decodeInstruction(romBuffer, address, 'adl')` returns `{tag, length, target?, ...}`
- Boot/wake init block: starts at 0x040892, approximately 964 bytes (documented in earlier sessions)
- USB vector entries: 0x000608-0x000638 (entries 36-48 in the vector table at 0x000578)
- To find callers of an address: search for CALL pattern CD xx xx xx (3-byte LE target after 0xCD)
