# Task: Trace CoorMon no-key path to find missing blocks

## Context
This is a TI-84 Plus CE ROM transpilation project. The CoorMon event loop at 0x08BF22 calls GetCSC, which returns A=0 (no key). The no-key path then falls into a bytecode interpreter at 0x000310→0x001C55, which eventually hits address 0xFFFFFF (the missing_block sentinel). We need to find exactly which address(es) the bytecode interpreter tries to jump to that are missing, so we can add transpiler seeds for them.

**Key addresses**:
- CoorMon entry: 0x08BF22
- GetCSC entry: 0x042366
- Bytecode interpreter: 0x000310 → 0x001C33 → 0x001C55
- cxMain pointer: 0xD007CA (set to 0x058241 = home handler)
- RETURN_SENTINEL: 0xFFFFFF

## Deliverable
Create `TI-84_Plus_CE/probe-phase337-coormon-nokey.mjs` that:

1. Boots the OS using standard 2-phase sequence:
   - Phase 1: `executor.runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
   - Phase 2: `executor.runFrom(0x08C331, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 })`
   - Post-boot: `cpu.mbase = 0xD0; cpu.iy = 0xD00080; cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;`
   - Stack: `cpu.sp = 0xD1A87E; cpu.sp -= 3; write24(mem, cpu.sp, 0xFFFFFF);`

2. Installs cxMain: `write24(mem, 0xD007CA, 0x058241)`

3. Runs CoorMon from 0x08BF22 with `maxSteps: 100000`, `maxLoopIterations: 100000`.

4. Uses `onBlock(pc, mode, meta, steps)` to:
   - Record ALL block PCs in execution order (full trace, not just unique)
   - Detect when the executor calls `missing_block(addr)` — this is reported as termination='missing_block' with `lastPc` = the missing address
   - Track the call stack by watching SP changes: log each CALL (SP decreases by 3) and RET (SP increases by 3) with the target addresses
   - Record the last 20 blocks before termination

5. After CoorMon terminates:
   - Print the termination reason and lastPc
   - Print the last 20 block PCs in order
   - Print the total unique blocks visited
   - If termination is 'missing_block': the `lastPc` IS the missing address. Print it clearly.
   - Check if the missing address is in ROM (< 0x400000) — if so, disassemble 10 instructions starting there using `decodeInstruction(romBytes, addr, 'adl')` from `ez80-decoder.js`
   - Also check the SP and stack content at termination

6. **TEST B**: If the missing block is found, check if it exists as a transpiler seed. Read `scripts/transpile-ti84-rom.mjs` and search for the missing address. Report whether it's already a seed or needs to be added.

7. **TEST C**: Analyze the return chain. Starting from the last 20 blocks, identify:
   - Which block called into the bytecode interpreter (0x000310/0x001C33/0x001C55)
   - What was on the stack when the interpreter was entered
   - Whether the return address is valid (points to a transpiled block)

## File structure
Same boilerplate as probe-phase336-cxmain-boot.mjs. Import `decodeInstruction` from `ez80-decoder.js`.

## Constraints
- Do NOT modify any existing files
- Console.log output only
- Runnable as: `node TI-84_Plus_CE/probe-phase337-coormon-nokey.mjs`
