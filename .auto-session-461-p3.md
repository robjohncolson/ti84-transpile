# Task: Trace the Reduced ISR Handler at 0x0019BE

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The project lifts eZ80 ROM machine code into runnable JavaScript.

## Background
The ISR dispatch has two paths:
- **Full dispatcher** at 0x03CF7D — 597 bytes, 3-stage port demux, includes KbdScan at 0x03F994
- **Reduced handler** at 0x0019BE — this is where the ISR routes when D177BA is nonzero (normal post-boot operation)

We hypothesize that during normal OS operation, D177BA is nonzero, and the ISR always goes to the reduced handler at 0x0019BE. If so, the reduced handler IS the real keyboard/timer ISR path, and the full dispatcher at 0x03CF7D is boot-only.

## Task
Write a probe file `TI-84_Plus_CE/probe-phase461-reduced-handler.mjs` that:

1. Disassemble the ROM bytes starting at 0x0019BE to trace the reduced handler:
   - Use the decoder: `import { decodeInstruction } from './ez80-decoder.js';`
   - Decode instructions starting at 0x0019BE in ADL mode
   - Follow the control flow (CALL targets, JP targets, conditional branches)
   - Map the function boundaries (find RET/RETI)
   - Decode at least 200 instructions following all non-recursive CALL targets 1 level deep
2. Report:
   - The full disassembly of the reduced handler function (0x0019BE to its RET/RETI)
   - What CALL targets it invokes
   - Whether it accesses any keyboard-related addresses (D00587 key scan code, D0058D internal key, D14091 key enable, D141B5 key buffer)
   - Whether it accesses timer-related addresses (D02658, D02651 countdown timers)
   - Whether it accesses port 0x5008 (timer interrupt acknowledge)
   - What port I/O it does
   - Whether it calls 0x001ACF (the known timer service)
3. Also check the block at 0x0019B5 (5 bytes before 0x0019BE) — session 460 says this is a HALT instruction. Decode 0x0019B5-0x0019BD.
