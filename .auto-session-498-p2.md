# Task: Decode 0x061061 (Cursor Draw Function)

## Context
In the TI-84 Plus CE OS ROM transpilation project, we've mapped the cursor blink architecture:
- 0x096BEE is the blink toggle — checks BIT 2,(IY+0x0D) to decide draw vs erase
- 0x061061 is the CURSOR DRAW function — loads cursor type from D02575, calls putchar (0x061980)
- 0x061003 is the cursor ERASE function (already decoded — 52 bytes, 24 instructions)
- Putchar pipeline: 0x061434 (mode gate) → 0x06002D (flag setter) → 0x0A23E5 (pixel renderer)

Session 497 identified 0x061061 as the cursor draw function but did not fully disassemble it.

## Task
Create and run a probe that:

### Part 1: Static disassembly of 0x061061
- Load the ROM from `TI-84_Plus_CE/ROM.rom`
- Use the eZ80 decoder from `TI-84_Plus_CE/ez80-decoder.js` to disassemble starting at 0x061061
- Decode instructions until you hit a RET (0xC9) or reach 200 bytes
- For each instruction, print: address, hex bytes, mnemonic
- Identify all CALL targets, memory references (especially D02575, D00595, D00596, D008D2)
- Note any cursor glyph codes (0xE1, 0xE2, 0xE3)

### Part 2: Dynamic execution test
- Use the CPU runtime from `TI-84_Plus_CE/cpu-runtime.js`
- Load the ROM and transpiled code
- Set up initial state: cursor at row=5, col=10 (D00595=5, D00596=10, D02505=10)
- Set cursor type at D02575 to 0xE1 (block cursor glyph)
- Set IY to 0xD00080 (standard OS IY value)
- Capture VRAM state before execution
- Execute from 0x061061 with maxSteps=50000
- Capture VRAM state after execution
- Report: steps taken, pixels changed, bounding box of changes, registers modified
