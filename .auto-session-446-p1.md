# Task: Trace 0x00B69E (Display Refresh Function)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is a 4MB eZ80 binary at `TI-84_Plus_CE/ROM.rom`. The transpiler at `scripts/transpile-ti84-rom.mjs` lifts it to JavaScript.

Session 445 discovered that 0x00B69E is the **display refresh function** called by the OS scheduler at 0x0015F7. The scheduler calls it when port 0x0F has both bits 6 and 7 set, after clearing D177B7 (display-dirty flag). This is believed to be the function that updates the LCD from VRAM or renders text to VRAM.

## Task
Disassemble and decode the function at **0x00B69E** in the ROM. Create a trace report.

### How to disassemble
Use `scripts/transpile-ti84-rom.mjs` as reference for the eZ80 instruction encoding. The ROM file is at `TI-84_Plus_CE/ROM.rom`. Read raw bytes from the ROM file using Node.js:

```javascript
const fs = require('fs');
const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');
// Read bytes at offset 0x00B69E
// eZ80 instructions: variable length 1-6 bytes
// Common patterns:
//   CALL nn = 0xCD nn.lo nn.mid nn.hi (4 bytes in ADL mode)
//   JP nn = 0xC3 nn.lo nn.mid nn.hi
//   RET = 0xC9
//   LD A,(nn) = 0x3A nn.lo nn.mid nn.hi
//   LD (nn),A = 0x32 nn.lo nn.mid nn.hi
//   OR A = 0xB7
//   JR Z,offset = 0x28 offset
//   JR NZ,offset = 0x20 offset
```

### Deliverables
Create file `TI-84_Plus_CE/phase446-trace-00B69E-report.md` with:
1. Full disassembly of 0x00B69E (at least the first 200 bytes or until RET)
2. All CALL targets — what functions does it invoke?
3. All memory addresses read/written — especially VRAM region (0xD40000-0xD52C00) or LCD controller ports
4. Function size in bytes
5. Number of callers (grep the transpiled JS for references to 0x00B69E)
6. Key finding: Does this function READ VRAM and push to LCD? Or does it RENDER text/graphics INTO VRAM?

### Constraints
- Do NOT modify `cpu-runtime.js`, `peripherals.js`, `browser-shell.html`, or any probe file
- Do NOT run the transpiler or any probes
- Output is a markdown report only
- Reference existing phase reports in `TI-84_Plus_CE/phase*-report.md` for format examples

### Success criterion
The report identifies what 0x00B69E does: its CALL targets, memory regions accessed, and whether it's a VRAM→LCD push or a render-to-VRAM function.
