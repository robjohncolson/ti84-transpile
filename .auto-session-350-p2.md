# Auto-Session 350, Priority 2: Disassemble Post-Flash-Ready Path (0x0006FA-0x000720)

## Context
The TI-84 CE boot code at 0x0006F3 does:
```
IN0 A,(0x06)   ; read flash status
BIT 2,A        ; test flash ready bit
JR Z,...       ; loop if not ready (currently always loops)
```

When bit 2 is set (flash ready), execution falls through to 0x0006FA. We need to know what's at 0x0006FA-0x000720 to understand the next boot phase.

## Task
Create a probe `TI-84_Plus_CE/probe-phase350-post-flash-disasm.mjs` that:

1. Reads the ROM file at `TI-84_Plus_CE/ROM.rom`
2. Disassembles eZ80 instructions from 0x0006FA to 0x000720 (ADL mode, 3-byte addresses)
3. For each instruction, print: address, hex bytes, mnemonic + operands
4. Also disassemble 0x000704-0x000720 (the CP D0 / MBASE check area mentioned in session 349)

## eZ80 instruction encoding reference (what you need for this range)
- IN0 A,(n): ED 38 nn (3 bytes)
- BIT b,A: CB 47/4F/57/5F/67/6F/77/7F (bit 0-7) — 2 bytes with CB prefix
- JR Z,offset: 28 dd (2 bytes, signed offset from next instruction)
- JR NZ,offset: 20 dd
- CP n: FE nn (2 bytes)
- JP NC,addr: D2 lo mid hi (4 bytes in ADL mode)
- JP addr: C3 lo mid hi (4 bytes in ADL mode)
- CCF: 3F (1 byte)
- LD A,n: 3E nn (2 bytes)
- OUT0 (n),A: ED 39 nn (3 bytes, but check — OUT0 is ED 01/09/11/19/21/29/31/39 for reg A)
- NOP: 00 (1 byte)
- RET: C9 (1 byte)
- CALL addr: CD lo mid hi (4 bytes in ADL mode)
- LD r,r: various single byte
- PUSH/POP: C5/C1 (BC), D5/D1 (DE), E5/E1 (HL), F5/F1 (AF)

Use the existing `TI-84_Plus_CE/ez80-decoder.js` if it exports a decode function. Otherwise, do a raw hex dump with byte-by-byte annotation.

## How to use ez80-decoder.js
Check if it exports something like `decodeInstruction(buffer, offset, adlMode)`. If so, use it. If not, just print raw hex bytes for each address in the range and note what you can identify.
