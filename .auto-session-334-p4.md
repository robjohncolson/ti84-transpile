# Auto-Session 334 — P4: Map Hook Iterator Callers (who calls 0x023D14?)

## Context

This is a TI-84 Plus CE ROM transpilation project. Session 333 fully decoded the hook iterator at 0x023D14:
- 24 slots × 3 bytes each
- Table base at RAM 0xD025D5 (loaded into IY at entry)
- 3-block loop: 023D14→023D2A→023D3E→023D20 repeating 24×
- Uses IX-based frame (LD SP,IX for return)
- After clean boot, ALL hook flag bytes are 0x00 — no hooks installed
- No-match exit: 0x023D49 (POP IX + RET)

Now we need to find WHO CALLS 0x023D14 and what hook types exist.

## Your task

Write a probe file `TI-84_Plus_CE/probe-phase334-hook-callers.mjs` that finds all callers of the hook iterator.

### Steps

1. **Search the ROM for CALL 0x023D14 and JP 0x023D14**:
   
   In eZ80 ADL mode:
   - CALL addr = `0xCD 0x14 0x3D 0x02` (opcode + 3 bytes little-endian)
   - JP addr = `0xC3 0x14 0x3D 0x02`
   
   Also check for the trampoline pattern — there may be a BCALL vector or RST that jumps to 0x023D14. Check:
   - CALL.IS (0x49 0xCD prefix for Z80 mode calls in ADL context)
   - JP.LIL (0x5B 0xC3 prefix)
   
   Load the ROM file and scan all 4MB for these byte patterns. Report every match address.

2. **For each caller found**:
   - Read 32 bytes BEFORE the call instruction to see what registers are set up
   - Particularly look for what value is loaded into A or another register before the call (this likely indicates the hook type/ID being searched for)
   - Read 32 bytes AFTER the call to see how the result is used

3. **Cross-reference with the BCALL table**:
   - The BCALL vector table starts at 0x000000 area. Check if any BCALL vectors (3-byte JP instructions at low addresses) point to 0x023D14 or to a wrapper that calls it.
   - Specifically check if there's a BCALL for "hook execution" — the OS likely exposes hooks via BCALL.

4. **Boot and check the hook table state**:
   ```javascript

   import fs from 'fs';
   const { hex } = helpers;
   const rom = fs.readFileSync(new URL('./ROM.rom', import.meta.url));
   const mem = createMemoryBus(rom);
   const periph = createPeripheralBus({ timerInterrupt: false });
   const executor = createExecutor(mem, periph);
   ```
   Run KERNEL_INIT: `executor.runFrom(0x08C331, { mode: 'adl', maxSteps: 100000 })`
   
   Then read the hook table at 0xD025D5:
   - Read 24 × 3 = 72 bytes (each slot is 3 bytes: flag byte + 2-byte? or 3-byte pointer?)
   - Actually, session 333 said flag bytes at IY+0x30..IY+0x3F and IY = table base 0xD025D5, so flags are at 0xD025D5+0x30=0xD02605 through 0xD02614
   - Read and dump the entire hook table region (0xD025D5 to 0xD025D5 + 128 bytes)

5. **Categorize the callers**: Group them by what hook type they're looking for (the value loaded before the call).
