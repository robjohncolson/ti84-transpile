## Context
You are working on a TI-84 Plus CE ROM (eZ80) transpilation project. The transpiler at `scripts/transpile-ti84-rom.mjs` lifts ROM bytes into JavaScript. Seeds are entry points that the transpiler uses to discover reachable code blocks.

## What to do

1. Open `scripts/transpile-ti84-rom.mjs` and find the `seeds` array (search for `const seeds` or `seeds.push` or the large array of hex addresses).

2. Add 40 new seed addresses. Use these two reliable sources:

   **Source A: OS Export JP Table (20 seeds)**
   The OS export jump table starts around 0x020000. Each entry is a 3-byte JP instruction (0xC3) followed by a 3-byte target address. Find entries in the range 0x0202C4 through 0x020400 that are NOT already in the seeds array. Extract the JP target address (bytes at offset+1, offset+2, offset+3 in little-endian) and add those targets as seeds.
   
   To find JP targets: read ROM at each 4-byte-aligned address in the JP table. If byte[0] == 0xC3, the target is byte[1] | (byte[2] << 8) | (byte[3] << 16).

   **Source B: Function Prologues (20 seeds)**
   Scan the ROM in under-seeded regions for common eZ80 function prologues:
   - `CALL 0x00218A` = bytes CD 8A 21 00 (or with .LIL prefix 49 CD 8A 21 00)
   - `CALL 0x002197` = bytes CD 97 21 00
   - `PUSH IX / LD IX,0 / ADD IX,SP` = bytes DD E5 DD 21 00 00 00 DD 39
   
   Good regions to scan: 0x00A0xx-0x00B0xx, 0x00B0xx-0x00C0xx, 0x010xxx-0x016xxx, 0x04Cxxx-0x050xxx
   
   Add the address of the prologue start (not the CALL target) as the seed.

3. After adding seeds, run the transpiler:
   ```
   node scripts/transpile-ti84-rom.mjs
   ```

4. Check the transpiler output for the new seed count, block count, and covered byte count. Record these numbers.

5. Run the golden regression test:
   ```
   node TI-84_Plus_CE/probe-phase99d-home-verify.mjs
   ```
   Confirm it still passes (26/26 or 5/5 assertions).
