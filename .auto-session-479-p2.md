# Task: REFRESH D00092 BIT 4 IN EVENT LOOP — CONTINUOUS CURSOR RENDERING

## Context
Session 478's probe-phase478-continuous-vram.mjs showed that refreshing D000C6 bit 0 at 0x02FDBE makes 0x030078 fire 31K times in 1M steps (vs 1× without refresh). BUT the pixel-writing branch (0x04E950→0x09EF44) only fires 1× because D00092 bit 4 is consumed by the OS at step 683 (0x16→0x06, bit 4 consumed) and never re-set.

Session 478 also fixed SP drift: resetting cpu.sp to STACK_RESET_TOP-3 at each RET point intercept keeps SP stable at 0xD1A87E for 31K iterations.

## Task
Create `TI-84_Plus_CE/probe-phase479-d00092-refresh.mjs` that:

1. Uses the EXACT same pattern as `probe-phase478-continuous-vram.mjs` (import createExecutor from cpu-runtime.js, createPeripheralBus from peripherals.js, load ROM.rom and ROM.transpiled.js).
2. After 3-stage boot (0x080000 → 0x0802B2 → 0x08C331, 150K steps each with maxLoopIterations:200000), sets up:
   - D00824=0x48, D007E0=0x48 (home mode)
   - D14091=0x01, D00000=0x01 (display enabled)
   - D00092=0x16 (bits 1,2,4 set — cursor active)
   - D00089 |= 0x10 (bit 4, display path enabled)
   - D000C6=0x01 (display setup trigger)
   - D000B4=0x01 (display path enabled)
   - D00080 |= 0x18 (bits 3+4)
   - D0059C = 0xD40000 (VRAM base)
   - D00595 = 0x00 (cursor row 0)
   - D00596 = 0x00 (column 0)
   - D0058B = 0x70
   - cpu.mbase = 0xD0, cpu._iy = 0xD00080
3. In the onBlock handler at 0x02FDBE:
   - Set mem[0xD000C6] |= 0x01 (refresh display trigger — proven in session 478)
   - Set mem[0xD00092] |= 0x10 (refresh bit 4 — cursor active — THIS IS NEW)
   - Reset cpu.sp to 0xD1A87E - 3 (SP drift fix — proven in session 478)
4. RET_POINTS at {0x02FE88, 0x02FDE5, 0x02FE21}: intercept all three, push 0x02FDBE return address and reset SP.
5. Run from 0x02FDBE for 1M steps with maxLoopIterations:200000.
6. Track hit counts for: 0x02FDBE, 0x030078, 0x04E950, 0x09EF44, 0x0059C6, 0x005A75
7. Log: total VRAM bytes changed, first 64 VRAM change addresses, hit counts for all tracked PCs, D00092 final value.

## Key addresses

- 0x04E950 = cursor save/update (needs D00092 bit 4)
- 0x09EF44 = screen fill (58 callers)
- 0x0059C6 = character output
- 0x005A75 = character renderer
- RET points: 0x02FE88, 0x02FDE5, 0x02FE21
