# Task: Seed D007D0=0x06C546 before calling 0x062055 (priority 14aaa)

## Context
In the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, session 261 found that execution crashes at 0x08C69E because D007D0 is uninitialized (reads as 0x000000). Session 262 mapped 12 D007D0 write sites. Session 264 confirmed D007D0 stays at 0x000000 through the ENTIRE boot sequence — none of the 12 write sites fire during boot.

Session 262 identified that 0x06C546 should be a valid home-screen handler address that D007D0 could point to. The function at 0x062055 is the cxMain dispatch (gated by D0230F), and when it calls through the pointer at D007D0, it crashes because D007D0=0x000000.

## Task
Create a probe `TI-84_Plus_CE/probe-phase265-d007d0-seed-test.mjs` that:

1. Boots the CPU through the standard sequence (cold boot → kernelInit → memInit → homescreen stages 1-4), same as `probe-phase99d-home-verify.mjs` does.
2. After boot completes, manually seeds D007D0 with candidate values and calls 0x062055 to see if it proceeds without crashing:
   - Test A: D007D0 = 0x06C546 (hypothesized home-screen handler from session 262)
   - Test B: D007D0 = 0x058241 (cxMain address from session 262)
   - Test C: D007D0 = 0x0AB8D4 (home/editor dispatch from session 232)
   - Test D: D007D0 = 0x000000 (control — should crash/halt quickly)
3. For each test:
   - Set PC = 0x062055, run for 500-2000 steps
   - Track: how many steps before halt/crash/sentinel, which unique blocks are visited, whether 0x08C69E is reached (the crash site), whether execution reaches meaningful OS code
   - Report the last 10 PCs before halt
4. Also check what D0230F contains after boot (this gates cxMain vs graph in 0x062055).
