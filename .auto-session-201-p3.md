# Auto-Session 201 P3: Decode BC=5 at 0xD008F0 for STAT handler

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript.

Session 200 found that block 0x09201E computes the STAT structure size: `LD HL,0xD008F2; LD BC,(0xD008F0); ADD HL,BC` then walks the structure. At entry, BC=0x000005 (read from RAM 0xD008F0). The value 0x0017 (23) is computed as the structure's total size.

We need to understand what the value 5 at 0xD008F0 represents. Is it:
- A stat variable count (number of stat lists)?
- A column count?
- A configuration byte?
- An index into some table?

## Task
Build a probe `TI-84_Plus_CE/probe-phase201-stat-d008f0-decode.mjs` that:

### Part A: ROM binary analysis
Read `TI-84_Plus_CE/ROM.rom` and scan for all references to address 0xD008F0 (or 0x0008F0 with MBASE):
1. Search for byte patterns `F0 08 D0` and `F0 08 00` (little-endian address references)
2. For each hit, dump the surrounding 16 bytes and classify as READ or WRITE instruction
3. Count total references

### Part B: STAT structure layout
Run the runtime and examine the memory region 0xD008E6-0xD00910 after memInit:
1. Standard setup (cold boot + kernelInit + memInit)
2. Dump 0xD008E0-0xD00920 (64 bytes) as hex
3. Note which bytes are non-zero

### Part C: Experiment with different values at 0xD008F0
1. Set 0xD008F0 to values 1, 3, 5, 7, 10
2. For each, run from 0x09201E for 200 steps
3. Record the computed structure size (the value written to 0x0008E6 / 0xD008E6)
4. Check if structure_size = f(BC) follows a linear pattern (e.g., size = 2*BC + 13, or size = 3*BC + 8)

### Part D: Write-watch on 0xD008F0
1. After memInit, install a write-watch on 0xD008F0
2. Run the STAT entry path from 0x058BA9 for 3000 steps
3. Record what block writes to 0xD008F0, what value, and at what step
