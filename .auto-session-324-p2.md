# Task: Trace 0x055191 and 0x055280 — the real LCD hardware init candidates

## Context
This is the TI-84 Plus CE ROM transpilation project. In the 0x05523D LCD init sequence, three functions are called: 0x055743, 0x055191, and 0x055280. Session 323 proved 0x055743 is NOT LCD hardware init — it's a 13-byte config table copier with zero port I/O. The real LCD hardware initialization must be in 0x055191 or 0x055280 (or both).

## Goal
Write a probe `TI-84_Plus_CE/probe-phase324-real-lcd-hw-init.mjs` that:
1. Statically disassembles 0x055191 (first 200 bytes) from the ROM
2. Statically disassembles 0x055280 (first 200 bytes) from the ROM
3. For each function, identifies:
   - All OUT/IN instructions (port I/O) — what ports are accessed?
   - All CALL targets — what sub-functions are invoked?
   - Any references to LCD port ranges (0x8000-0x8041, 0x31xx, 0x40xx)
   - The return point (RET instruction)
4. Then runs each function dynamically (same approach as the 0x055743 probe):
   - Boot to post-init (entry 0x0802B2, SP=0xD1A87E, MBASE=0xD0, IY=0xD00080)
   - Push fake return 0x7FFFFE, set PC to the target
   - Step limit 10,000
   - Log all port I/O
5. Reports for each function: returned or hung, step count, port I/O list, call targets hit

## ROM file
Read the raw ROM from `TI-84_Plus_CE/ROM.rom` (4MB file). The ROM maps directly to addresses 0x000000-0x3FFFFF.

## Disassembly
Use `decodeInstruction(mem, addr)` from `ez80-decoder.js`. It returns an instruction object with fields like `tag`, `target`, `size`, etc. Walk from the entry point, decoding sequentially. Stop at a RET or after 200 bytes, whichever comes first. For each instruction, check:
- tag === 'out' or tag === 'in' → port I/O
- tag === 'call' → sub-function call
- Any immediate values in the 0x8000-0x80FF or 0x3100-0x31FF or 0x4000-0x40FF range

## Boilerplate
Copy structure from `TI-84_Plus_CE/probe-phase323-055743-lcd-hw-init.mjs`:
- Same imports, hex helpers, ensureTranspiledModule pattern
- `createPeripheralBus({ timerInterrupt: false })`
- Wrap bus.read/bus.write for port I/O logging (same as probe-phase323)

## Output
Print two sections (one per function):

