# Auto-Session 183 P2 — ParseInp Inside Home Handler Context

## Context
This is a TI-84 Plus CE ROM transpilation project. ParseInp (0x099914) fails with E_Undefined (errNo=0x8D) when called standalone. Session 182 proved cxErrorEP is irrelevant. The hypothesis: the home handler at 0x0582B8 sets other critical OS state beyond cxErrorEP that ParseInp depends on.

Session 182 fully disassembled the home handler:
- 0x0582B8-0x058348: flag setup + LCD clear (stalls at 0x09EFDE MMIO busy-wait)
- 0x05845D: post-LCD setup, sets cxErrorEP=0x058BA9 at 0x058467
- 0x058467: calls 0x06EDFE (error handler install)
- 0x058483+: key processing loop

The LCD clear at 0x09EFDE is a MMIO busy-wait that stalls the trace. We need to bypass it.

## Task
Build a probe `TI-84_Plus_CE/probe-phase183-parseinp-home-context.mjs` that:

1. Boot the ROM (cold boot + MEM_INIT as in existing probes — copy from probe-phase182-parseinp-state-diff.mjs)
2. **Run the home handler setup portion (0x05845D to ~0x058480)** — skip the LCD clear phase entirely by starting execution at 0x05845D (post-LCD entry). Set up:
   - SP = 0xD1A87E (stack top)  
   - IX = 0xD1A860 (per-stage IX convention from CONTINUATION_PROMPT)
   - IY = 0xD00080 (OS IY convention)
3. Execute from 0x05845D and log every block. This should hit 0x058467 (sets cxErrorEP) and 0x06EDFE (error handler install). Stop when execution reaches 0x058483 or has done 500 steps.
4. **Capture the full OS state** after the home handler setup: dump cxErrorEP, cxPutAway, cxRedisp, cxSizeWind, cxPage, cxCurApp, errSP, errNo, plus any RAM in 0xD02500-0xD025FF (appErr vector area), 0xD007D0-0xD007FF.
5. **Then call ParseInp (0x099914)** with "2+3" tokens in the buffer at 0xD00A00, using the state the home handler just set up.
6. Compare: does ParseInp still jump to 0x1BC300 with errNo=0x8D, or does the home handler context fix it?
7. If it still fails, capture what's different in the error dispatch path compared to the standalone probe.
