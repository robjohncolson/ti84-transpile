# Task: Trace 0x07BF3E (Fixed-Width Font Lookup)

## Context
You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80). The transpiler is at `scripts/transpile-ti84-rom.mjs`. The runtime is `TI-84_Plus_CE/cpu-runtime.js`. Peripherals are in `TI-84_Plus_CE/peripherals.js`.

## What we know
- 0x07BF3E is the fixed-width font lookup function
- Called by the fixed-width text renderer at 0x054E21 with `MLT` stride 28
- This is the Record 1 (sel=1) path in the font descriptor table at 0x0525D4
- Record 1 = fixed-width font: renderer=0x054E21, width=0x054FBC (constant 12px), height=0x054FC1 (constant 15px)
- The variable-width counterpart is 0x0A5424 (stride 25) — a separate task is decoding that one
- We want to compare the two font tables to understand how TI-84 renders text

## Your task
Build a probe script `TI-84_Plus_CE/probe-phase327-fixedfont-lookup.mjs` that:

1. **Disassembles 0x07BF3E** by reading raw bytes from the ROM. Trace from 0x07BF3E until RET or unconditional JP outside the function. Decode eZ80 instructions manually. Document every instruction with address, hex bytes, and mnemonic.

2. **Identifies the font table**:
   - Where is the fixed-width font data in ROM?
   - What is the record size? (Likely 28 bytes per glyph based on MLT stride)
   - How does the character code map to a table index?
   - What format are the glyph entries? (raw bitmap, width+bitmap, etc.)

3. **Compares with variable-width path**: The variable-width font uses stride 25 and 0x0A5424. The fixed-width font uses stride 28 and 0x07BF3E. Why the different strides? Is the extra 3 bytes per glyph due to the fixed width being 12px vs variable-width 13px height?

4. **Dumps sample glyph data**: Read glyph entries for ASCII 'A' (0x41) and '0' (0x30) from the fixed-width font table. Show hex bytes.

5. **Runs a dynamic trace**:
   - Load the transpiled JS
   - Create CPU + peripherals (timerInterrupt: false)
   - Set PC = 0x07BF3E with appropriate register setup
   - Trace up to 100 steps, log block PCs and memory accesses

## Output format
- Part A: Static disassembly of 0x07BF3E
- Part B: Font table location, stride, glyph format
- Part C: Sample glyph dumps
- Part D: Dynamic trace
- Part E: Comparison notes vs variable-width (stride 25 vs 28)

## Constraints
