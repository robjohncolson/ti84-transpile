# Task: Map TRY-BLOCK Mechanism (0x061DEF, 0x061E20, 0x061DB6)

## Context

You are working on a TI-84 Plus CE ROM transpilation project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 machine code). We are reverse-engineering the OS cursor subsystem.

**0x07D5D7** (297 bytes, decoded in session 509) is a post-populator chain function. Its FULL path includes a TRY-BLOCK mechanism:
- Saves SP to D008E0
- CALL 0x061DEF (enter try-block)
- CALL 0x07D610 (the actual work — writes 0x0E to D00D16/D00D1F, iterates cursor types)
- CALL 0x061E20 (exit try-block / teardown)
- Then continues with 0x07DF4B (restore)

This is a structured exception handling mechanism — the OS saves SP, runs code inside a "try" context, then tears down the context. If an error occurs inside, SP is restored from D008E0 and execution jumps to an error handler.

**Related**: 0x061DB6 appears in the broader exception handling region near 0x061DEF/0x061E20.

## eZ80 Decoding Reference

The eZ80 CPU uses these key patterns:
- `CD xx xx xx` = CALL addr (3-byte address in little-endian)
- `C3 xx xx xx` = JP addr
- `C9` = RET
- `ED 73 xx xx xx` = LD (addr),SP — save stack pointer
- `ED 7B xx xx xx` = LD SP,(addr) — restore stack pointer
- `ED` prefix for block ops, IN/OUT, extended arithmetic
- `DD` = IX prefix, `FD` = IY prefix
- `CB` prefix for bit operations
- `52` = .SIS prefix (use 16-bit addresses in 24-bit mode)
- `49` = .LIS prefix
- `FD CB dd xx` = IY+d bit operations
- Common: `AF` = XOR A, `32 xx xx xx` = LD (addr),A, `3A xx xx xx` = LD A,(addr)
- `21 xx xx xx` = LD HL,addr, `11 xx xx xx` = LD DE,addr
- `E3` = EX (SP),HL (swap top-of-stack with HL — used for handler registration)
- `F9` = LD SP,HL (restore SP from HL)
- `E5` = PUSH HL, `E1` = POP HL
- `18 xx` = JR offset, `20 xx` = JR NZ, `28 xx` = JR Z
