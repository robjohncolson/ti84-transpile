# Task: Dynamic probe — call 0x062055 after full boot, trace to cxMain

## Context
This is a TI-84 Plus CE ROM transpilation project. The transpiled ROM is in `TI-84_Plus_CE/ROM.transpiled.js` (regenerate with `node scripts/transpile-ti84-rom.mjs` if needed). The runtime is `TI-84_Plus_CE/cpu-runtime.js`, peripherals in `TI-84_Plus_CE/peripherals.js`.

**Key finding**: 0x062055 is the ONLY function that calls 0x058241 (cxMain pre-handler). It has ZERO static callers — reached via RAM function pointer. We want to see what happens when we call it directly after boot.

**Known D007E0 write sites in 0x0620xx region**:
- 0x0620AE: writes A=0x49 to D007E0
- 0x0620C0: writes A=0x40 to D007E0
- 0x0620C4: CALL 0x058241 (cxMain pre-handler)

## Deliverable
Create `TI-84_Plus_CE/probe-phase260-062055-dynamic.mjs` that:

1. Boots the system using the standard pattern from existing probes (see reference below)
2. After boot (homescreen stages 1-4), sets up state:
   - IX = 0xD1A860 (standard homescreen IX)
   - A = 0x40 (home-screen mode candidate — the value written at 0x0620C0)
   - Key buffer seeded with a digit key (e.g., scan code 0x8F = digit "1")
3. Calls 0x062055 (set PC to block entry for 0x062055)
4. Traces execution for up to 500 steps, logging:
   - Every unique block visited (first visit only)
   - Any writes to D007E0 (value written)
   - Any writes to D00824
   - Whether 0x058241 (cxMain pre-handler) is reached
   - Whether 0x0585E9 (cxMain itself) is reached
   - Whether BufInsert (0x05E2A0) is reached
   - Final PC, step count, unique block count
5. Also try with A = 0x49 (the value written at 0x0620AE)
6. Print comparison of both traces

## Boot Pattern Reference
Look at `TI-84_Plus_CE/probe-phase99d-home-verify.mjs` for the standard boot sequence. Key steps:
```javascript
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
const rom = await import('./ROM.transpiled.js');
const perph = createPeripheralBus({ timerInterrupt: false });
const cpu = createCPU(rom, perph);
// Boot sequence: z80 boot, kernelInit, memInit, homescreen stages
```

The boot helper functions are typically defined inline in probes. Check existing probes for patterns. Key addresses:
- z80 boot entry: block 0x000000 with MADL bit clear
- kernelInit: 0x020328
- memInit: 0x021078  
- Homescreen stage 1: 0x021998
- Homescreen stage 2: 0x0219B8
- Homescreen stage 3: 0x0219D8
- Homescreen stage 4: 0x021A08
- IX for homescreen = 0xD1A860

Each stage runs with `while (cpu.pc !== exitPC) cpu.step()` pattern, with step limits to prevent infinite loops.
