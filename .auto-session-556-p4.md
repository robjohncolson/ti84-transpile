# Task: Decode 0x06CBFA-0x06CC02 Cursor Y Conversion Function

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). Session 555 found that at 0x06CC02 there is a cursor Y → render Y conversion:
```
3D 91 C6 2F 32 D5 08 D0
DEC A; SUB C; ADD A,0x2F; LD (D008D5),A
```
This converts D014FE (cursor Y / row count, 43 refs) to D008D5 (renderer Y coordinate, 265 refs). The function containing this code needs full decoding — what is the complete function, who calls it, and what are its inputs/outputs?

## Target

### Step 1: Find the function boundaries
Starting from 0x06CC02, scan backwards to find the function start. Look for:
- A RET (C9) or JP (C3) instruction that ends the previous function
- The first instruction after that is the start of this function
Scan backwards up to 128 bytes from 0x06CC02.

Also scan forward from 0x06CC02 to find the function end (next RET = C9).

### Step 2: Hex-dump and disassemble the full function
Dump from function start to function end. Disassemble every instruction.

eZ80 ADL mode key opcodes:
- 3A xx xx xx = LD A,(imm24) — reads from RAM address
- 32 xx xx xx = LD (imm24),A — writes to RAM address
- CD xx xx xx = CALL imm24
- C9 = RET
- 3D = DEC A
- 91 = SUB C
- C6 xx = ADD A,imm8
- FD CB dd bb = IY bit operations
- ED 4B xx xx xx = LD BC,(imm24)
- ED 5B xx xx xx = LD DE,(imm24)
- ED 6B xx xx xx = LD HL,(imm24)

### Step 3: Find all callers
Search ROM for:
- CALL to function start address (CD xx xx xx)
- JP to function start address (C3 xx xx xx)

### Step 4: Map all RAM addresses referenced
For every LD A,(addr) or LD (addr),A in the function, list the RAM address and what it means:
- D008D5 = renderer Y coordinate (265 refs, primary y-coord)
- D014FE = cursor Y / row count (43 refs, 1 write)
- Others = identify from prior session notes or mark as new

### Step 5: Cross-reference with 0x06CBFA
Session 555 noted that D014FE + D008D5 appear 8 bytes apart at 0x06CBFA and 0x06CC02. Dump 0x06CBF0-0x06CC20 (48 bytes) and disassemble to see the complete picture — are 0x06CBFA and 0x06CC02 in the same function?

## Deliverables
Create `TI-84_Plus_CE/probe-phase556-cursor-y-conv.mjs` that:
1. Finds function boundaries around 0x06CC02
2. Hex-dumps and shows full disassembly
3. Lists all callers
4. Maps all RAM addresses in the function
5. Shows the 0x06CBFA-0x06CC02 relationship

