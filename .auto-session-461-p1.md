# Task: ISR Dispatch Path Diagnostic Probe

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The project lifts eZ80 ROM machine code into runnable JavaScript.

## Background
The ISR dispatch path after IM1 interrupt is:
- 0x000038 (IM1 vector) → JP 0x0006F3
- At 0x0006F3: flash check → MBASE gate (CP 0xD0)
- If MBASE==0xD0 → CALL 0x001713 (guard function)
- Guard 0x001713: CALL 0x0008BB (ROM sig check) → RET NZ. Then LD A,(D177BA); OR A; RET NZ. Then more checks → eventually may reach 0x03CF7D (full ISR dispatcher)
- If guard returns NZ → JP 0x0019BE (reduced handler)
- If guard returns Z → JP 0x02010C → JP 0x03CF7D (full ISR dispatcher with KbdScan at 0x03F994)

We need to know WHERE the ISR actually routes after a timer interrupt fires during normal operation (after boot completes).

## Task
Write a probe file `TI-84_Plus_CE/probe-phase461-isr-trace.mjs` that:

1. Boots the OS using the standard boot pattern (see `probe-phase99d-home-verify.mjs` for the boot pattern — use `createPeripheralBus({ timerInterrupt: false })` during boot, ~500,000 steps)
2. After boot completes, BEFORE enabling timer interrupts, read and log:
   - `mem[0xD177BA]` (post-init flag)
   - `mem[0xD177B7]` (display dirty flag)  
   - `mem[0xD14091]` (key processing enable)
   - `cpu.mbase` (should be 0xD0)
   - `cpu.iff1` and `cpu.iff2` (interrupt enable flags)
3. Then enable timer interrupts by calling the peripheral bus timer method
4. Set up PC-hit tracing hooks on these critical addresses:
   - 0x000038 (IM1 vector entry)
   - 0x0006F3 (ISR front-end)
   - 0x001713 (guard function)
   - 0x0008BB (ROM signature check)
   - 0x0019B5 (HALT before reduced handler)
   - 0x0019BE (reduced handler)
   - 0x02010C (full dispatcher trampoline)
   - 0x03CF7D (full ISR dispatcher)
   - 0x03F994 (KbdScan)
5. Run 50,000 more steps with timer interrupts enabled
6. Report which addresses were hit and how many times
7. Also report the Z flag state after 0x0008BB returns (hook the RET at 0x0008C7 and check cpu flags)
8. Report D177BA value at the time of the 0x001713 call
