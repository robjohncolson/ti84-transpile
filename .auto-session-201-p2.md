# Auto-Session 201 P2: Find SET 5,(IY+68) site + test 0x08C2AD dispatch

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM (4MB, `TI-84_Plus_CE/ROM.rom`) is lifted to JavaScript blocks.

Session 200 found 77 ROM references to IY+68 (0xD000C4 when IY=0xD00080). The key question is: what sets bit 5 of (IY+68)? Known sites from session 200:
- SET 2 at 0x058406 (sets bit 2, not bit 5)
- OR 0x0C at 0x097F14 (sets bits 2+3, not bit 5)
- RES 5 at 0x079CD8 (CLEARS bit 5)
- BIT 5 test at 0x0584C5 and 0x08C2AD

But NO `SET 5,(IY+68)` site was identified. It might be done via `OR` with a mask that includes bit 5, or via `LD (IY+68),value`, or via a byte write to the absolute address 0xD000C4.

## Task
Build a probe `TI-84_Plus_CE/probe-phase201-bit5-set-finder.mjs` that does TWO things:

### Part A: ROM binary scan for SET 5 sites
Read `TI-84_Plus_CE/ROM.rom` directly (binary) and scan for:
1. `SET 5,(IY+0x44)` — eZ80 encoding: `FD CB 44 EE` (IY+68 = IY+0x44)
2. `OR` instructions that would set bit 5 when applied to (IY+68) — e.g., `OR 0x20`, `OR 0x24`, `OR 0x28`, `OR 0x2C`, `OR 0x30`, `OR 0x38`, `OR 0x3C`, any value with bit 5 set
3. `LD (IY+0x44),immediate` — `FD 36 44 xx` where xx has bit 5 set
4. Direct writes to 0xD000C4 — look for `LD (0xD000C4),A` patterns: `32 C4 00 D0` (8-bit) or `ED 32 C4 00 D0` (eZ80 24-bit addr)

For each match, report the ROM address and the surrounding 8 bytes (hex).

### Part B: Test 0x08C2AD dispatch gate
0x08C2AD also tests BIT 5,(IY+68). Build a trace:
1. Standard runtime setup (cold boot + kernelInit + memInit)
2. Run from 0x08C2AD for 200 steps with bit 5 CLEAR (default)
3. Run from 0x08C2AD for 200 steps with bit 5 SET (mem[0xD000C4] |= 0x20)
4. Compare: unique blocks visited, final registers, any key RAM changes
