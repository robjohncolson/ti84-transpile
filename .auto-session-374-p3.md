# Session 374 P3: Trace 0x003A7D → 0x001937 Dispatch Path

## Context
When ENTER (scan code 0x09) is injected via direct RAM write (mem[0xD00587]=0x09, mem[0xD00080]|=0x08) and the event loop dispatches at 0x003A7D, execution reaches 40 new blocks before halting at 0x001937 after only 52 steps. The dispatch path includes:
- 0x003A7D: CALL 0x001713
- 0x003A81: JP NZ,0x001933
- 0x003A85: JP 0x003A89
- 0x003A89: CALL 0x001853
- 0x003A8D: XOR A
- 0x003A8E: JP 0x000721

The 40 new blocks discovered (from session 373 probe output) include addresses in the 0x001xxx, 0x003xxx, 0x006xxx, and 0x015xxx ranges. We need to disassemble these blocks to understand what the OS does with the ENTER key before halting.

## Task
Create `TI-84_Plus_CE/probe-phase374-dispatch-disasm.mjs` that:

1. Boots phases 1-3, injects ENTER via direct RAM (mem[0xD00587]=0x09, mem[0xD00080]|=0x08)
2. Runs the event loop with timerInterrupt:false, maxSteps=200000
3. Collects ALL unique blocks visited (using onBlock callback)
4. For each block visited that is in the "post-dispatch" set (blocks visited after 0x003A7D is first reached), use `decodeInstruction` from `ez80-decoder.js` to disassemble the first 8 instructions at that address
5. Build a call graph: for each block, record what block it transitions TO (the return value of each compiled block is the next PC). Track the sequence of block transitions for the first 100 steps after dispatch begins.
6. Print:
   - The full sequence of block addresses visited after dispatch (first 100 transitions)
   - For each post-dispatch block, its disassembly (first 8 instructions)
   - A summary: "dispatch path: 0x003A7D → 0x001713 → ... → 0x001937 (HALT)"

```javascript

// inst = { mnemonic: 'LD', operands: 'A, B', length: 1, bytes: [0x78] }
```

Disassemble up to 8 instructions per block by advancing pc by inst.length each time.
