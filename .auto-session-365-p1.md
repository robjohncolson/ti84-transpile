# Task: Integrate SP Clamp into cpu-runtime.js runFrom() Loop

## Context
The TI-84 Plus CE ROM transpilation project boots the OS by executing lifted JavaScript blocks. During boot, at step ~2684, block 0x00BC72 executes `LD SP, IX` where IX has been corrupted to 0x014C7B (ROM space). This crashes boot at 476 blocks.

A probe (`TI-84_Plus_CE/probe-phase364-ix-termination-fix.mjs`) proved that "Fix B" — clamping SP back to the last known-good RAM value when it enters ROM space — extends boot from 476 to 517 blocks. Now we need to integrate this fix permanently into the executor's dispatch loop.

## What to do

Edit `TI-84_Plus_CE/cpu-runtime.js`. In the `createExecutor()` function's `runFrom()` method (starts around line 1092), add SP clamp logic to the main dispatch loop.

### The fix logic (from the probe, lines 360-377):

```javascript
// AFTER each block executes (after `result = fn(cpu)` at ~line 1211):
// Track last good SP before each block runs
// After block returns, check if SP entered ROM space
const spAfter = cpu.sp & 0xFFFFFF;
if (spAfter < 0x400000 && spAfter !== 0 && lastGoodSp !== null) {
    cpu.sp = lastGoodSp;
} else if (spAfter >= 0x400000) {
    lastGoodSp = spAfter;
}
```

### Specific changes:

1. **Add a `lastGoodSp` variable** at the top of `runFrom()` (around line 1098, near the other state variables):
   ```javascript
   let lastGoodSp = null;
   ```

2. **Add SP tracking BEFORE each block executes** (just before `result = fn(cpu)` at ~line 1211):
   ```javascript
   const spBefore = cpu.sp & 0xFFFFFF;
   if (spBefore >= 0x400000) {
       lastGoodSp = spBefore;
   }
   ```

3. **Add SP clamp AFTER each block executes** (after `result = fn(cpu)` and after `steps++` at ~line 1228, before the result checks):
   ```javascript
   // SP safety clamp: if a block corrupted SP into ROM space, restore it.
   // This handles the 0x00BC72 LD SP,IX corruption where IX follows a
   // linked-list pointer into ROM (0x014C7B). See session 364 probe.
   const spAfterBlock = cpu.sp & 0xFFFFFF;
   if (spAfterBlock < 0x400000 && spAfterBlock !== 0 && lastGoodSp !== null) {
       cpu.sp = lastGoodSp;
   }
   ```

### Important constraints:
- Do NOT modify the CPU class's `sp` setter (it already has spWarnings diagnostic from session 364 — leave that in place).
- Do NOT modify probe files or any file other than `cpu-runtime.js`.
- Do NOT change the RAM trampoline logic (lines ~1169-1179).
- Do NOT add comments longer than 2 lines.
- The fix goes in the `runFrom()` method only, not in the CPU class.
- Keep the code style consistent: no semicolons where the file doesn't use them (the file DOES use semicolons — maintain that style).
