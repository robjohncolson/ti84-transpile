# Auto-Session 212 — P3: 0xD01508 write watchpoint during STAT pipeline

## Context

Session 211's STAT late-seed probe traced 10000 steps with 457 unique blocks. Key finding: 0xD01508 (list pointer table base) starts at 0xD01600 (our seed), but reverts to 0x000000 by step 10000. Something in the STAT pipeline clears this value. If InsertMem (0x092226) is called again after the clear, it will re-corrupt RAM with a ~3M LDDR copy. We need to find WHAT instruction writes 0x000000 to 0xD01508.

## Task

Create a probe `TI-84_Plus_CE/probe-phase212-d01508-watchpoint.mjs` that runs the STAT pipeline with the late-seed fix AND a write watchpoint on addresses 0xD01508-0xD0150A (3-byte little-endian pointer). Every time any byte in this range is written, log: step number, PC (block address), the old value, the new value, and what the full 3-byte pointer reads as after the write.

## Implementation

Use `probe-phase211-stat-late-seed.mjs` as your template. Read it in full at `TI-84_Plus_CE/probe-phase211-stat-late-seed.mjs`.

The key modification: intercept writes to 0xD01508-0xD0150A. The runtime's `write8` function in `cpu-runtime.js` handles memory writes. You need to wrap or hook the executor's memory write path.

Approach: After creating the executor via `createExecutor(mem, BLOCKS, peripheralBus)`, wrap the cpu's write functions to detect writes to the watched range:

```javascript
const WATCH_START = 0xD01508;
const WATCH_END = 0xD0150A; // inclusive
const watchLog = [];

const origWrite8 = cpu.write8.bind(cpu);
cpu.write8 = function(addr, val) {
  const a = addr & 0xFFFFFF;
  if (a >= WATCH_START && a <= WATCH_END) {
    const oldVal = mem[a];
    origWrite8(addr, val);
    const newFull = (mem[WATCH_START] | (mem[WATCH_START+1] << 8) | (mem[WATCH_START+2] << 16)) >>> 0;
    watchLog.push({
      step: currentStep,
      pc: cpu.pc,
      byteAddr: a,
      oldByte: oldVal,
      newByte: val & 0xFF,
      fullPointer: newFull
    });
    return;
  }
  origWrite8(addr, val);
};
```

Similarly wrap write16 and write24 if they exist on the cpu object.

Note: `write8` in cpu-runtime.js silently drops writes where addr < 0x400000 (ROM protection). 0xD01508 is in RAM (> 0x400000), so writes go through.
