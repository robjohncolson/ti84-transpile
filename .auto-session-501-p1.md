# Task: Decode 0x097955 — The Actual Cursor Draw Path

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 CPU). We've been tracing the cursor blink architecture.

**Key finding from session 500**: 0x096CCF calls 0x096F56 (a visibility check), and when it returns NZ (cursor IS visible), does `JP NZ,0x097955`. So **0x097955 is where the actual cursor draw/erase logic lives**. We need to decode it.

**Known architecture**:
- 0x096BEE = blink toggle (tests BIT 2,(IY+0x0D) for cursor-currently-drawn flag)
- 0x096CCF = draw/erase subroutine (calls visibility check, then JP NZ,0x097955)
- 0x096F56 = visibility check (3 gates: IY+0x11 bit 7, D007E0==0x49, IY+0x02 bit 7)
- 0x061061 = cursor draw function (164 bytes, dual putchar paths)
- 0x061003 = cursor erase function
- 0x061980 = putchar
- IY = 0xD00080

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase501-decode-097955.mjs` that:

1. **Static disassembly**: Read ROM bytes starting at 0x097955. Decode eZ80 instructions until you hit an unconditional RET (0xC9) or have decoded 200+ bytes. Use the eZ80 instruction set (3-byte addresses, 24-bit mode). Print each instruction with address, hex bytes, and mnemonic.

2. **Identify all CALL/JP targets** — especially look for calls to 0x061061 (cursor draw), 0x061003 (cursor erase), 0x061980 (putchar), or any 0x06xxxx addresses.

3. **Check for references to known RAM addresses**: D00595 (cursor row), D00596 (cursor col), D02575 (cursor type), D007E0 (screen mode), D008D2/D008D5 (VRAM addresses), IY+offset patterns.

4. **Dynamic test** (if static decode looks promising): Set up a minimal executor, load the ROM, set cursor position (D00595=5, D00596=10), set cursor-visible flags (D00091 bit 7 = set, D007E0 = 0x49, D00082 bit 7 = set), call 0x097955 with up to 50000 steps. Capture VRAM changes.

## Technical details
- ROM file: `TI-84_Plus_CE/ROM.rom` — load with `fs.readFileSync`
- eZ80 is little-endian, 24-bit addresses stored as 3 bytes (low, mid, high)
- Common instruction patterns:
  - `CD xx xx xx` = CALL addr
  - `C3 xx xx xx` = JP addr
  - `C9` = RET
  - `3E xx` = LD A,imm8
  - `FD CB xx xx` = IY+offset bit operations
  - `3A xx xx xx` = LD A,(addr)
  - `32 xx xx xx` = LD (addr),A
  - `2A xx xx xx` = LD HL,(addr)
  - `22 xx xx xx` = LD (addr),HL
