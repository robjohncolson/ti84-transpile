# Task: Test D007E0=0x40 (home/editor mode) to see if event loop routes to 0x058322

## Context
In the TI-84 Plus CE ROM transpilation project, the event loop at 0x0582BC has a BIT 2,(IY+21) gate at 0x058322. Session 273's Experiment C showed that with D007E0=0x49 (trace mode), the event loop enters 0x09CE10 → polling at 0x082BE2/0x084711 and NEVER reaches 0x058322 in 5000 steps.

D007E0 is the context/mode ID: 0x40=home/editor, 0x49=trace, 0x48=graph, etc. The home screen context (0x40) might route differently through the event loop and actually reach 0x058322.

## Task
Create a probe `TI-84_Plus_CE/probe-phase274-d007e0-routing.mjs` that:

1. Sets up standard TI-84 CE execution environment (ROM.rom, cpu-runtime.js, peripherals.js)
2. Boots CPU (kernel init 0x000280, 5000 steps)
3. Runs 4 experiments, each starting at PC=0x0582BC (event loop entry) with different D007E0 values:
   - Experiment A: D007E0 = 0x40 (home/editor) 
   - Experiment B: D007E0 = 0x00 (default/uninitialized)
   - Experiment C: D007E0 = 0x48 (graph)
   - Experiment D: D007E0 = 0x43 (Y= editor)
4. For each experiment:
   - Set SP=0xD1A87E, IX=0xD1A860, IY=0xD00080, MBASE=0xD0
   - Set D007E0 to the test value
   - Set D007E8 to a valid handler address (e.g., 0x058241 = cxMain)
   - Set D007D0 to the same handler address
   - Arm IY+21 bit 2 (address 0xD00095, set bit 2): mem[0xD00095] |= 0x04
   - Push return sentinel 0x7FFFFE on stack
   - Run 10,000 steps
   - Track whether 0x058322 was reached
   - Track whether 0x058328 (armed path) or 0x058344 (clear path) was reached
   - Log all unique blocks visited
   - Log any blocks in the 0x058xxx range

5. Report comparison table: which D007E0 values route to 0x058322?

## Key Addresses
- Event loop entry: 0x0582BC
- BIT 2 gate: 0x058322
- Armed path: 0x058328
- Clear path: 0x058344
- D007E0: context/mode ID
- D007E8: handler address (seeded to prevent JP(HL=0) crash)
- D007D0: another handler address
- IY+21 = 0xD00095: bit 2 controls the gate
