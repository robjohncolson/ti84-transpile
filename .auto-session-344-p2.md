# Task: Trace 0x0008BB to Understand Boot Diversion Condition

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The OS ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 binary).

Session 343 found the critical boot diversion:
- At 0x00004F: `JP NZ,0x0019B5` — if NZ flag is set, boot goes to halt loop
- This is reached via RST 0x38 → some path → return NZ
- Session 340 traced: boot at 0x0006C1 calls RST 0x38, RST handler at 0x000038 does EX AF,AF'/EXX/PUSH IX/PUSH IY/LD IY,0x0080/JP 0x0006F3
- The RST 0x38 handler targets 0x0006F3
- The condition at 0x00004F diverts to halt loop 0x0019B5

The hypothesis: 0x0008BB is called somewhere in the RST 0x38 path, and if it returns NZ, boot fails. We need to understand what 0x0008BB checks.

## Task
Create a probe `TI-84_Plus_CE/probe-phase344-boot-diversion.mjs` that:

1. Does a STATIC DISASSEMBLY of ROM bytes at these addresses:
   - 0x0008BB through 0x000950 (the suspected check function — disassemble until RET)
   - 0x0006F3 through 0x000750 (the RST 0x38 handler continuation, which may call 0x0008BB)
   - 0x000038 through 0x000065 (the RST 0x38 entry, for full context)
   - 0x000047 through 0x000060 (NMI/boot early code around the JP NZ 0x0019B5)

2. For the static disassembly, read ROM bytes directly and decode eZ80 instructions. The eZ80 in ADL mode has 24-bit addresses. Key opcodes:
   - JP nn = 0xC3 + 3-byte address
   - CALL nn = 0xCD + 3-byte address  
   - RET = 0xC9
   - JP NZ,nn = 0xC2 + 3-byte address
   - CP n = 0xFE + 1 byte
   - IN0 A,(n) = 0xED 0x38 + 1 byte port
   - OUT0 (n),A = 0xED 0x39 + 1 byte port
   - LD A,(nn) = 0x3A + 3-byte address
   - AND n = 0xE6 + 1 byte
   - OR n = 0xF6 + 1 byte
   - BIT n,r = 0xCB prefix + opcode
   - Use the project's ez80-decoder.js if helpful

3. Also run a DYNAMIC trace: boot from 0x000000 in z80 mode (reset vector), trace per-instruction for up to 200 blocks. Record every block PC and the flag state (Z/NZ) at block boundaries. Identify exactly which instruction sets NZ before the JP NZ 0x0019B5.

4. Analyze: What hardware register or RAM location does 0x0008BB read? What value makes it return Z (boot succeeds) vs NZ (boot fails)? Can we fix this by pre-initializing a RAM location or adding a peripheral stub?
