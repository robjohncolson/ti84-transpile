# Auto-Session 335 — Priority 2: Fix ED 65 Transpiler Misdecoding

## Context
Session 334 found that the "missing block 0xFB65ED" is NOT a real address — it's a transpiler bug. Raw ROM bytes at 0x052508: `ed 65 ec ed 65 fb ed 65 fb cd b2 22 05...`. The `ED 65` bytes are eZ80 ED-prefixed opcodes (like `TST A,(HL)`). The sequence `ed 65 fb` contains literal bytes FB,65,ED which when read as 24-bit little-endian give 0xFB65ED. The transpiler's CFG discovery phase misidentifies these instruction bytes as a jump target.

## Task
1. Read `scripts/transpile-ti84-rom.mjs` and `TI-84_Plus_CE/ez80-decoder.js` 
2. Find where ED-prefix opcodes are decoded. The eZ80 ED prefix map includes:
   - ED 65 = TST A,(HL) (2 bytes total, no operand)
   - Many other ED xx opcodes that are 2 bytes
   - Some ED xx xx that are 3 bytes (with immediate operand)
   - Some ED xx xx xx that are 4 bytes (with address operand)
3. Find specifically how the CFG discovery / seed expansion in `transpile-ti84-rom.mjs` walks instructions. The bug is that when it encounters `ED 65`, it doesn't correctly advance the PC past the 2-byte instruction, so the next byte (e.g., `fb` at offset +2) gets misinterpreted.
4. Fix the decoder so ED 65 (and any other ED-prefix 2-byte opcodes that may be wrong) correctly reports the instruction length.
5. After fixing, run the transpiler: `node scripts/transpile-ti84-rom.mjs` and verify:
   - 0xFB65ED no longer appears as a block target
   - The transpiler report shows the same or higher block count
   - No new errors introduced
