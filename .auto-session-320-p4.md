# Task: Investigate D13FFC USB/Comm Struct

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 binary). Session 319 mapped the D13FD8-D14040 callback region and found D13FFC is the hottest single address at 74 ROM references. It's part of a "USB/Comm Triplet" sub-structure (D13FFC-D14002). Session 319 found these are struct pointers, not callback pointers, and that functions in the 0x00CE-0x00D2 address range manage it.

Key facts from session 319:
- D13FFC = 74 refs (hottest in entire D13FD8-D14040 region)
- D13FFC-D14002 = 7 bytes, a triplet structure
- These are struct pointers, not function callback pointers
- Functions around 0x00CE-0x00D2 in the low-address vector table manage them

## What to do
1. Search the ROM for all references to D13FFC. The byte pattern for the address is `FC 3F D1` (little-endian of 0xD13FFC). Find all LD/ST operations that read or write this address.
2. Categorize the 74 references: how many are reads vs writes? What registers are involved?
3. Read the ROM at the low-address vector entries around 0x00CE-0x00D2. These are 3-byte JP instructions in the 128-entry OS API vector table at 0x000200-0x000400. Each entry is `JP addr24`. Decode where they jump.
4. Follow the jump targets and disassemble the actual functions that manage D13FFC.
5. Determine:
   - What struct does D13FFC point to? What fields are at D13FFD, D13FFE, D13FFF, D14000, D14001, D14002?
   - Is this a USB device descriptor pointer? A communication buffer pointer? A state struct?
   - What subsystem uses this most heavily?

## Deliverables
Create `TI-84_Plus_CE/phase320-d13ffc-usb-struct-report.md` with:
- Reference breakdown: reads vs writes, by subsystem
- The vector table entries that manage D13FFC (addresses + targets)
- Disassembly of the key management functions
- Struct layout of D13FFC-D14002 (field sizes, purposes)
- Classification of what subsystem this serves
