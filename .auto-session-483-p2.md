# Priority (f): MULTI-CHAR RENDERING VIA 0x0059C6 WITH CORRECT BOOT

## Context

This is the TI-84 Plus CE ROM transpilation project. You are working in `C:/Users/rober/Downloads/Projects/school/ti84-transpile`.

Session 478 proved that calling 0x0059C6 with a character code in register A renders actual glyph pixels to VRAM. The key findings:
- 'H' (0x48) → 1,472 VRAM bytes changed, D0059C advanced to 0x0E, D00596 to 1
- 'I' (0x49) → 64 VRAM bytes, D0059C to 0x1A, D00596 to 2
- Space (0x20) → 0 bytes visible

Session 482 decoded the full character output pipeline:
- 0x0059C6: wrapper. CP 0xD6 branches: normal chars (A≠0xD6) → CALL 0x005A75 (renderer), INC D00596, CP 0x1A (check col≥26), CALL NC 0x005A02 (line wrap). Char 0xD6 (newline) → CALL 0x005A20 (fill remaining cols with spaces), CALL 0x005A02 (advance line).
- 0x005A02: line advance. XOR A → LD (D00596),A (reset col to 0), INC D00595 (advance row), CP 0x0A (wrap at 10), XOR A if ≥10.
- VRAM formula: vram_addr = 0xD40000 + (row×20+37)×640 + (col×12+2)×2

Session 478's boot that worked for character rendering used a 3-stage boot:
1. Stage 1: Boot from 0x000000 for ~50K steps (initial hardware setup)
2. Stage 2: Jump to 0x08BF22 (home init) for ~100K steps (sets D0058B=0x70)
3. Stage 3: Set D0059C=0xD40000, D00596=0, D0058B=0x70, then call 0x0059C6

5. **Final analysis**:

   - Expected vs actual D00596 for each character
   - Whether VRAM write addresses match the formula
