# Auto-Session 199, Priority 3: Y= Counter=0x19 Extra 11 Blocks Investigation

## Context

Session 198 probe `probe-phase198-yeq-loop-entry.mjs` discovered that entering the Y= loop at 0x0A1B59 with counter value 0x19 visits **61 unique blocks** while all other counter values (0x15, 0x10, 0x05, 0x00) visit only **50 blocks**. The 11 extra blocks are the "initialization/reset path" triggered when counter 0x19 wraps to 0x1A then 0x00.

Key observations from session 198:
- Counter 0x19 transitions: 0x19→0x1A→0x00 (wraps, triggers init via extra 11 blocks)
- Others simply increment by 1
- All experiments: 384 VRAM writes, return cleanly in ~680-690 steps
- VRAM cursor final varies by counter: 0x19→0xD4525C, 0x00→0xD45004

## Task

Build a probe `TI-84_Plus_CE/probe-phase199-yeq-init-blocks.mjs` that:

### Experiment A: Identify the 11 extra blocks

1. Set up standard OS state (memInit, MBASE=0xD0, IX=0xD1A860, timerInterrupt: false)
2. Run counter=0x19 at 0x0A1B59 for 1000 steps, collect block list
3. Run counter=0x15 at 0x0A1B59 for 1000 steps, collect block list
4. Compute the SET DIFFERENCE: blocks in 0x19 that are NOT in 0x15
5. Report the 11 (or however many) extra block addresses

### Experiment B: Trace what the extra blocks DO

For each extra block identified in Experiment A:
1. Log the block's transpiled code (read from ROM.transpiled.js if accessible, or just log the block key)
2. Log what RAM addresses it writes to
3. Log any CALL/JP targets

### Experiment C: Does counter=0x1A also trigger the init path?

1. Set counter=0x1A at entry (one past the wrap point)
2. Run for 1000 steps
3. Compare block set with 0x19 and 0x15

### Experiment D: RAM diff for init path

1. Snapshot RAM 0xD00590-0xD005B0 (Y= state area) before execution for counter=0x19
2. Snapshot again after execution
3. Report which bytes changed and to what values
4. Compare with counter=0x15 RAM diff
