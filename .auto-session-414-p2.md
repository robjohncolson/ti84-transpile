# Task: Map D176F8 Write Value Semantics

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). The instruction decoder is at `TI-84_Plus_CE/ez80-decoder.js`.

Session 412 found 44 writers and 25 readers of RAM address `D176F8` (protocol type state byte). USB Worker B dispatches on D176F8 values: 0x0A (active), 0x0C (header), 0x0D (complete). But the 44 writers' values are mostly unknown. We need to trace 10+ representative writers to determine what values they write and why.

## What to do
1. Create a probe script `TI-84_Plus_CE/probe-phase414-D176F8-values.mjs` that:
   - Loads the ROM binary
   - Scans the entire ROM (0x000000-0x3FFFFF) for all instructions that write to D176F8
   - For each writer, decode the surrounding context (5-10 instructions before and after) to determine:
     - What value is being written (immediate, register, computed?)
     - What function this writer is in (look for RET/JP boundaries)
   - Categorize writers by value written
   - Print a summary table: address → value written → context

2. Create a report `TI-84_Plus_CE/phase414-D176F8-values-report.md` documenting:
   - All 44 (or however many found) write sites with their values
   - A categorized breakdown: which values are written and by how many sites
   - Cross-reference with known dispatch values (0x0A, 0x0C, 0x0D)
   - Any new values not previously known
   - A proposed state transition diagram if patterns emerge

## How to find writers
Search the ROM for `LD (D176F8),A` patterns. In eZ80 ADL mode:
- `LD (nn),A` = opcode 0x32 followed by 3-byte little-endian address (F8 76 D1)
- Also check `LD (nn),BC` = ED 43 F8 76 D1, `LD (nn),HL` = 22 F8 76 D1

For each writer found, decode backwards from the write instruction to find what value A/BC/HL holds. Common patterns:
- `LD A,imm8` / `LD (D176F8),A` — immediate value
- `XOR A` / `LD (D176F8),A` — writes 0
- `LD A,(other_addr)` / `LD (D176F8),A` — copies from another location
