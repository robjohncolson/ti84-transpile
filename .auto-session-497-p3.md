# Task: Trace Cursor Blink Caller — Find Who Alternates putchar(0xE1) and 0x061003

## Context
This is the TI-84 Plus CE ROM transpilation project. We lift eZ80 machine code from `TI-84_Plus_CE/ROM.rom` into JavaScript and run it in a browser shell.

Session 496 made a paradigm-shifting discovery: cursor draw IS character rendering. The OS draws the cursor by calling putchar (0x061980) with glyph code 0xE1 (insert cursor), 0xE2 (overwrite cursor), or 0xE3 (second overwrite cursor). Cursor erase is via 0x061003 (already known from session 490). Cursor blink = alternating these two calls.

The task is to find the ROM function that orchestrates cursor blink — the one that alternates between drawing (putchar with 0xE1) and erasing (0x061003).

## What to do

Create a probe file `TI-84_Plus_CE/probe-phase497-cursor-blink-caller.mjs` that:

### Part 1: Byte pattern search in ROM
Search the entire 4MB ROM for byte sequences that indicate cursor blink logic:

1. Search for `3E E1 CD 80 19 06` — this is `LD A,0xE1; CALL 0x061980` (load cursor glyph into A, call putchar). The eZ80 CALL encoding for 0x061980 is `CD 80 19 06` (little-endian 24-bit address).

2. Search for `3E E2 CD 80 19 06` — same but with overwrite cursor glyph.

3. Search for `3E E3 CD 80 19 06` — same but with third cursor glyph.

4. Also search for shorter patterns in case the LD A and CALL are not adjacent:
   - Search for `CD 80 19 06` (all CALL 0x061980 sites) and check if A is loaded with 0xE1/0xE2/0xE3 within the previous 10 bytes
   - Search for `CD 03 10 06` (all CALL 0x061003 sites — cursor erase) and note their addresses

5. For each hit, print the surrounding context: 20 bytes before and 20 bytes after, with disassembly.

### Part 2: Cross-reference cursor draw and erase calls
For functions that contain BOTH a CALL 0x061980 (or nearby LD A,0xE1/E2/E3) AND a CALL 0x061003 within 200 bytes of each other — these are the cursor blink candidates. List them.

### Part 3: Decode the blink function
For the most promising blink candidate(s), do a full disassembly from the function entry point. Look for:
- Timer/counter references (blink timing)
- Flag checks (cursor visible vs hidden state, IY+offset bits)
- Loop structure (draw → wait → erase → wait → repeat)
- Who calls this function

### Executor pattern reference

```javascript
import { readFileSync, existsSync } from 'fs';
import { execSync } from 'child_process';

const rom = readFileSync('TI-84_Plus_CE/ROM.rom');

// For byte pattern search, work directly on the ROM buffer
function searchPattern(pattern, label) {
  const results = [];
  for (let i = 0; i < rom.length - pattern.length; i++) {
    let match = true;
    for (let j = 0; j < pattern.length; j++) {
      if (pattern[j] !== null && rom[i + j] !== pattern[j]) { match = false; break; }
    }
    if (match) results.push(i);
  }
  console.log(`${label}: ${results.length} hits`);
  for (const addr of results) {
    const ctx = Buffer.from(rom.slice(Math.max(0, addr - 10), addr + pattern.length + 10));
    console.log(`  0x${addr.toString(16).padStart(6, '0')}: ${ctx.toString('hex')}`);
  }
  return results;
}
```

### Important constraints
- ROM is 4MB: `readFileSync('TI-84_Plus_CE/ROM.rom')`
- eZ80 CALL encoding: `CD` followed by 3-byte little-endian address. CALL 0x061980 = `CD 80 19 06`. CALL 0x061003 = `CD 03 10 06`.
- eZ80 LD A,imm8: `3E xx`
- JP encoding: `C3` followed by 3-byte LE address
- The cursor glyph codes are 0xE1 (insert mode), 0xE2 (overwrite mode 1), 0xE3 (overwrite mode 2)
- IY = 0xD00080. Cursor flags are at various IY+offset positions.
