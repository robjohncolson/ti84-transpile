# Auto-session 340 P3: Map all ROM readers of 0xD007CA (cxMain pointer)

## Context

The TI-84 Plus CE OS stores the current context handler address at RAM location 0xD007CA (3-byte pointer called "cxMain"). Session 339 proved that CoorMon (0x08BF22) does NOT read this pointer — it never dispatches through it. But something in the OS must read 0xD007CA to call the active context handler.

The address 0xD007CA in little-endian is bytes CA 07 D0. In eZ80 ADL mode, loads from absolute 24-bit addresses use patterns like:
- `LD HL,(addr)` = ED 6B CA 07 D0 (or ED 27 CA 07 D0 for .LIL prefix)
- `LD A,(addr)` = 3A CA 07 D0
- `LD BC,(addr)` = ED 4B CA 07 D0
- `LD DE,(addr)` = ED 5B CA 07 D0
- Various IX/IY indexed loads may also appear

## Task

Create a probe `TI-84_Plus_CE/probe-phase340-cxmain-readers.mjs` that:

1. Reads the ROM binary (`TI-84_Plus_CE/ROM.rom`)
2. Scans the entire 4MB ROM for the byte sequence CA 07 D0 (little-endian encoding of address 0xD007CA)
3. For each match, determine context by reading surrounding bytes:
   - Check if the preceding 1-2 bytes form a valid load instruction opcode (3A, ED 4B, ED 5B, ED 6B, ED 27, etc.)
   - Check if the preceding byte is a CALL/JP opcode with 0xD007CA as target (unlikely but check)
   - Classify each hit as: LOAD (reads cxMain), STORE (writes cxMain), CALL/JP target, or DATA/FALSE_POSITIVE
4. For each LOAD hit, also read 20 bytes before and after and do a rough disassembly showing the surrounding instructions
5. Also scan for 0xD007CB and 0xD007CC (the high bytes of the 3-byte pointer — some code may read individual bytes)
6. Print a summary table:
   ```
   Address    Type     Instruction         Context (±10 bytes hex)
   0xNNNNNN   LOAD     LD HL,(0xD007CA)    ...
   ```
7. Also check these specific known locations that write to cxMain:
   - 0x08C8CB (known cxMain writer — sets HOME_HANDLER)
   - Any others found

## Key Facts

- ROM is 4MB (0x000000-0x3FFFFF)
- Most of the ROM above ~0x0C0000 is erased flash (0xFF fill) — but scan everything anyway
- Address 0xD007CA is in RAM space (>= 0xD00000), so it won't appear as a code address in ROM
- The ROM byte sequence CA 07 D0 could appear as data too, so context classification is important
