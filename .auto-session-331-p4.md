# Task: Map the 19 Hook Registration Stubs at 0x023B31-0x023BDC

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The deref helper at 0x025758 reads from D025xx pointer slots. There are 19 registration stubs at 0x023B31-0x023BDC (9 bytes each) covering three IY offset groups:
- IY+52 (6 hooks)
- IY+53 (8 hooks)
- IY+54 (5 hooks)

All 19 slots are NULL at cold boot — they're external hook registration points. The deref helper (0x025758) follows a 3-byte pointer from a D025xx slot, reads a type byte, and dispatches. Type 0x83 triggers "pending uninstall" semantics (increments D0265B, runs hook one final time).

## Key addresses
- **0x023B31 - 0x023BDC** = 19 registration stubs (9 bytes each, ~172 bytes total)
- **0x025758** = deref helper (7 instructions, 10 bytes: LD HL,(HL) → LD A,(HL) → INC HL → PUSH HL/POP IX → CP 0x83 → RET)
- **0x025762** = error/uninstall handler for type 0x83
- **0x0238B2** = sibling helper using DE instead of HL, publishes to D025D2
- **D0265B** = uninstall counter
- **D025xx** = pointer slot region (each 3 bytes)

## What to do
1. Open `TI-84_Plus_CE/ROM.transpiled.js.gz` (gunzip it).
2. For each of the 19 stubs (starting at 0x023B31, 9 bytes apart, ending at 0x023BDC), extract the stub code and determine:
   - Which D025xx slot it registers to
   - Which IY+N offset group it belongs to (52, 53, or 54)
   - What the stub does (likely: store a pointer to a descriptor into the D025xx slot)
3. Find ALL callers of each stub — who calls stub #1 at 0x023B31? Who calls stub #2 at 0x023B3A? Etc.
4. Determine: during normal OS operation (not just cold boot), which hooks get installed? Search for any code that writes non-NULL values to the D025xx slots.
5. Check what the IY+52, IY+53, IY+54 offsets represent in the OS context.

## Deliverable
Create `TI-84_Plus_CE/probe-phase331-hook-stubs.mjs` that:
- Lists all 19 stubs with their addresses, D025xx target slots, and IY group
- Finds all callers of each stub in the transpiled JS
- Identifies any code that writes to D025xx slots during boot or normal operation
- Reports which hooks (if any) are active after booting to home screen (by reading the D025xx slot values post-boot)
