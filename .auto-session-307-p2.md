# Auto-Session 307 P2: Trace Token Descriptor Builder 0x022346

## Context
In the TI-84 Plus CE OS event loop, after looking up the scan-code-to-token table at 0x09F79B, the code at 0x02FF16 calls `CALL 0x022346`. This function takes the token byte read from the table and builds a "token descriptor" that gets passed to CoorMon for key classification. Session 306 identified this call but did not trace what 0x022346 actually does.

We know from session 302 that 0x022346 eventually calls 0x0236F9 (the token buffer writer, which writes 3-byte stack-frame entries). We also know it relates to the token deposit system decoded in session 302 (0x022331 = multi-entry deposit → 0x0236F9 buffer writer).

## Task
1. Read `TI-84_Plus_CE/ROM.rom` and disassemble the function at 0x022346 using the eZ80 decoder at `TI-84_Plus_CE/ez80-decoder.js`.
2. Trace the full control flow from 0x022346 until RET (or tail JP). Document:
   - What registers it reads on entry (especially A = token byte from table?)
   - What memory it reads/writes (especially D0058C = primary token, D0058E = secondary)
   - What subroutines it calls and why
   - How it builds the "token descriptor" — what data structure does it create?
   - How it interacts with 0x0236F9 (the token buffer writer)
3. Compare with the related function 0x022331 (multi-entry deposit, decoded in session 302) — how do they differ?
4. Document the full calling convention: inputs, outputs, side effects.
