# Task: Map the 0x005900-0x005C00 LCD/Display Update Path

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 ADL-mode machine code).

Session 383's trace showed heavy activity in 0x005A48-0x005B92 after key dispatch. This is the post-keypress display update path. We need to map what this region does.

Known context:
- 0x005B96 and 0x005BB1 are CALL targets from handler 0x001853 (session 380)
- The LCD uses an ST7789V controller via SPI (session 382)
- LCD SPI command functions are at 0x0060FA/0x0060F7 (session 354)

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase387-lcd-display-path.mjs` that:

1. Performs static eZ80 ADL-mode disassembly of the range 0x005900-0x005C00
2. Identifies function boundaries (look for RET instructions, CALL targets from other known code)
3. For each identified function, document:
   - Entry point address
   - What it does (LCD commands, RAM reads/writes, port I/O)
   - CALL targets (especially to 0x0060FA/0x0060F7 SPI functions)
   - Any references to LCD-related ports (0xE0xxxx MMIO, SPI ports)
   - References to display RAM (0xD40000+ is the LCD framebuffer)
4. Pay special attention to 0x005B96 and 0x005BB1 as known entry points from 0x001853

## Probe pattern
```js
import { readFileSync } from 'fs';
import { createDecoder } from './ez80-decoder.js';

const rom = readFileSync(new URL('./ROM.rom', import.meta.url));
const decoder = createDecoder(rom);

function disasmRange(start, end) {
  let pc = start;
  const results = [];
  while (pc < end) {
    const instr = decoder.decodeAt(pc);
    results.push(instr);
    pc += instr.length;
  }
  return results;
}

// Disassemble the full range
const instrs = disasmRange(0x005900, 0x005C00);

// Print with hex bytes
for (const i of instrs) {
  const hex = Array.from(i.bytes).map(b => b.toString(16).padStart(2,'0')).join(' ');
  console.log(`0x${i.address.toString(16).padStart(6,'0')}: ${hex.padEnd(20)} ${i.mnemonic} ${i.operands || ''}`);
}
```

After the raw disassembly, add analysis that:
- Groups instructions into functions (separated by RET/JP boundaries)
- Identifies port I/O instructions (IN/OUT)
- Identifies memory references to 0xD40000+ (framebuffer) or 0xE00000+ (LCD MMIO)
- Lists all CALL/JP targets
