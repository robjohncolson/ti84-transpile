Session 519 proved that 0x0A1B5B (the char render wrapper) passes the character code in register A directly to 0x0A1799 (the rasterizer). The font atlas lookup happens INSIDE 0x0A1799, not in the wrapper. 

Session 507 found the font table at ROM address 0x003D6E with 28 bytes per glyph (copied to RAM D005A1 by 0x07BF3E at boot).

Session 515 verified 0x0A1799 end-to-end (668 steps, 312 VRAM bytes written at row 37).

The task: decode the first ~60-80 instructions of 0x0A1799 to find:
1. How it converts char code (A register) to a font table offset (expected: char_code * 28 + font_base)
2. Where the font table base address is read from (RAM pointer? hardcoded?)
3. The VRAM write loop structure (how glyph bytes become pixels)
