## Goal
Create a probe that decodes what 0x05C76C does. It's called every idle loop iteration from 0x02FDAC (CALL Z 0x05C76C) during the pre-loop setup at 0x02FD99. Understanding it reveals what the OS does between key checks in the idle loop.

## Background
- The idle loop path is: 0x02FD99 → CALL 0x03013A → POP IX → 0x02FDAC (CALL Z 0x05C76C) → 0x02FDB6 → CALL 0x03FA09 (key check)
- 0x05C76C is called conditionally (CALL Z) — the Z flag comes from 0x03013A's return path
- Session 474 showed 0x05C76C is reached in the idle loop's repeating pattern
- 0x03013A is the multi-flag cursor/display state machine (fully decoded in session 474)
- After boot with all flags clear, 0x03013A falls through to 0x03015E → CALL 0x030202 → returns Z (D00092 bit 4 clear) → this Z flag may propagate to the CALL Z 0x05C76C
