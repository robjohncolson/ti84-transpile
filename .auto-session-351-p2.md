# Task: Trace Stack at RET PO Point (0x0006A8)

## Context
The TI-84 CE boot is stuck in a 29-block loop. The code at 0x00069A eventually reaches RET PO at 0x0006A8. Even if RET PO DOES fire correctly, if the return address on the stack points back into the loop, that's a different bug class.

The boot sequence starts at 0x000000 and calls into 0x001AFA which CALLs 0x0058A6 (PLL subroutine). The PLL sub eventually reaches 0x00069A. When RET PO fires, it pops the return address from the stack. We need to know what that return address is.

## Your Task

1. **Create a probe** `TI-84_Plus_CE/probe-phase351-stack-trace.mjs` that:
   - Boots the CPU from address 0x000000
   - Uses `createPeripheralBus({ timerInterrupt: false })` 
   - Patches the execution to log SP and stack contents every time address 0x0006A8 is reached
   - Runs for up to 500 blocks or 100k steps
   - Reports: SP value at 0x0006A8, the 2-3 words on top of the stack (return addresses), and where those addresses are in the boot flow

2. **Determine the call chain** leading to 0x0006A8:
   - What CALL instruction put the return address on the stack?
   - Does the return address point to 0x001AFD (after the CALL 0x0058A6 at 0x001AFA)?
   - Or does it point somewhere else (back into the loop)?

3. **Output format**: The probe should print:
   ```
   At 0x0006A8 (RET PO):
     SP = 0x______
     Stack[SP+0] = 0x______ (return addr low)
     Stack[SP+1] = 0x______ (return addr mid)  
     Stack[SP+2] = 0x______ (return addr high)
     Return address: 0x______
     This points to: <description of what's at that address>
   ```

## Key Files
- `TI-84_Plus_CE/cpu-runtime.js` — CPU constructor, `step()`, register access
- `TI-84_Plus_CE/peripherals.js` — `createPeripheralBus()`
- `TI-84_Plus_CE/ROM.transpiled.js` — the transpiled blocks
- `TI-84_Plus_CE/probe-phase349-pll-fix-verify.mjs` — reference probe from session 349 (similar boot trace)
- `TI-84_Plus_CE/probe-phase350-flash-bit2-verify.mjs` — reference probe from session 350

## How to set up the probe
Look at existing probes (e.g., probe-phase349-pll-fix-verify.mjs or probe-phase350-flash-bit2-verify.mjs) for the pattern:
- Import cpu-runtime, peripherals, load ROM.transpiled.js
- Create CPU with peripherals
- Hook into execution (either patch the block function or use cpu.onBlock callback if available)
- Run cpu.run() or step loop

The CPU is eZ80 (24-bit addresses). SP is 24-bit. Stack entries are 3 bytes each (little-endian: low, mid, high). Read mem[SP], mem[SP+1], mem[SP+2] for the return address.

## Constraints
