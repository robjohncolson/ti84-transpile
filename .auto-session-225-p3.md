# Task: Trace 0x02F68A key pipeline with extended step count (2000+ steps)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 binary). The transpiled JS is generated by `scripts/transpile-ti84-rom.mjs` and the runtime is in `TI-84_Plus_CE/cpu-runtime.js`.

0x02F68A is a 334-byte key processing pipeline (0x02F68A-0x02F7D7) that was traced in session 223 but only with 500 steps — not enough for it to return. It's called from 0x04AB91 (inside _GetKey). The function:
- Creates an IX frame via `CALL 0x00012C` (2 local vars at IX-1, IX-2)
- Reads hardware port 0x3082 (USB/keyboard status)
- Calls 0x049E07 TWICE (state-byte reader, returns A from D177B8)
- Does a CP cascade classifying the key code: CP 0x8E, CP 0x91, CP 0xFF, CP 0x01, CP 0x9B, CP 0xFE
- Sub-function 0x02F961 writes to (D0058E) — the key code storage variable
- Has 25 sub-calls, 18 within the function

Session 223 found that 500 steps was insufficient — the function got stuck in heavyweight init via 0x048AC4 (memset-like loops).

## Your Task
Build a probe `TI-84_Plus_CE/probe-phase225-02f68a-extended.mjs` that:

1. **Boot the CPU fully**: z80 boot (0x000200), kernelInit (0x000324), memInit (0x020814). Use `createPeripheralBus({ timerInterrupt: false })`.

2. **Pre-seed keyboard state**: Before calling 0x02F68A, set up realistic keyboard state:
   - Write a scan code to the keyboard matrix (e.g., key '1' = group 3 bit 1, so keyMatrix[4] bit 1 via the SDK mapping)
   - Set D177B8 = 0x8F (a key code value) and D177B9 = 0x00 (case selector for the switch dispatcher at 0x049E07)

3. **Call 0x02F68A with extended steps**: Run for 2000, then 5000, then 10000 steps. For each:
   - Count unique blocks visited
   - Check if the function returns (PC returns past the CALL site)
   - Dump D0058E, D00824, D0059F, D177B8, D177B9 values
   - Record which sub-functions were called (track CALL instructions)

4. **Try with D177B8 = different values**: Test with D177B8 = 0x8F (digit), 0x76 (LOG), 0x2B (comma), 0x00 (no key), 0xFC (2nd modifier). See if the CP cascade at different values produces different behavior.

5. **Identify the return path**: What block/address does the function return to? Does it write to D0058E or D00824 before returning?

**Read existing probes first** to understand the API. Good references:
- `probe-phase223-02f68a-function-trace.mjs` (the previous 500-step trace of this same function)
- `probe-phase224-049e07-switch-dispatch.mjs` (traces the state-byte reader called by 0x02F68A)

Match the coding style exactly.

## Deliverables
- `TI-84_Plus_CE/probe-phase225-02f68a-extended.mjs` — the probe script
- Run it with `node TI-84_Plus_CE/probe-phase225-02f68a-extended.mjs` and include the output
- Report: does the function return? What state does it modify? What's the key code resolution path?
