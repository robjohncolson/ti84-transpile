# Task: Trace full CoorMon entry 0x08C331 → 0x08C449 (undecoded setup region)

## Context
The full CoorMon (Coordinate Monitor) at 0x08C331 is the master OS event loop for the TI-84 Plus CE. Session 338-340 decoded the key dispatch cascade starting at 0x08C449 and the cxMain dispatch at 0x08C72F. However, the ~280 bytes from 0x08C331 to 0x08C449 are undecoded setup — this region runs on every CoorMon iteration before the key dispatch cascade.

Understanding this setup is critical for browser shell integration: we need to know what RAM state, IY flags, and peripheral state the setup assumes/initializes.

## Deliverable: Disassembly probe

Create `TI-84_Plus_CE/probe-phase341-coormon-entry.mjs` that:

1. Reads ROM bytes from 0x08C331 to 0x08C449 (280 bytes) using the ROM file
2. Disassembles each eZ80 instruction in ADL mode using `TI-84_Plus_CE/ez80-decoder.js`
3. For each instruction, prints: `addr: hex_bytes  mnemonic  operands`
4. Annotates known addresses:
   - Any CALL targets — note if they match known functions from prior sessions:
     - 0x08BF22 = narrow CoorMon (GetCSC + VRAM refresh)
     - 0x08C72F = cxMain dispatch wrapper
     - 0x08C745 = JP (HL) trampoline
     - 0x022331 = token deposit
     - 0x04C973 = CP comparison helper
     - 0x0800C2 = status bar related
   - Any LD (IY+offset) — note the offset and whether it's a BIT test, SET, or RES
   - Any LD HL,(<address>) where address is in 0xD007xx range (context handler table)
   - Any JP/JR targets (especially backward jumps = loops, forward jumps = branches)
5. Summarize: how many CALLs, how many IY flag checks, any conditional branches, any RAM reads/writes

```javascript
// ROM byte at address X: rom[X] (ROM is memory-mapped at 0x000000-0x3FFFFF)
```
