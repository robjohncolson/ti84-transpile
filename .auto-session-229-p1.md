# Task: Trace 0x03011C — 09F79B Key Code Lookup Function

## Context
In the TI-84 Plus CE ROM transpilation project, we discovered that ROM address 0x09F79B contains a 3-subtable key code map (none-mod, alpha-mod, 2nd-mod) with OS key codes in the 0x80+ range. There are only 2 ROM references to this table:
- `LD DE,0x09F79B` at 0x02FF11 (ADD HL,DE → CALL 0x022346)
- `LD DE,0x09F79B` at 0x03011C (ADD HL,DE → LD A,(HL) → CP thresholds → writes to D0058E)

0x03011C is the key lookup path — it reads a table entry and writes to D0058E (the primary key code variable with 107 ROM references).

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase229-03011c-key-lookup.mjs` that:

1. **Static disassembly**: Disassemble 0x030100-0x030180 (and surrounding context — find the function boundaries by looking for RET instructions before and after). Show the full instruction sequence.

2. **Find function entry point**: Scan backwards from 0x03011C for a RET/JP/JR instruction to find where the function starts. Also scan ROM for `CALL 0x03XXXX` and `JP 0x03XXXX` patterns that target addresses in this range, to find callers.

3. **Dynamic trace**: Execute starting from the function entry with various keyboard matrix positions to see how HL is computed before the `ADD HL,DE` at 0x03011C. Test at least 4 different inputs. The key question: what register/memory value determines the offset into the 09F79B table?

4. **Map the HL computation**: Document exactly how the function converts a keyboard matrix position (or scan code) into an HL offset that indexes into the 09F79B table. This is the missing link for browser-shell integration.

## Technical Setup
```javascript
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
import fs from 'fs';

const ROM_PATH = './ROM.rom';
// Load ROM
const romData = fs.readFileSync(ROM_PATH);
// Create CPU
const pbus = createPeripheralBus({ timerInterrupt: false });

// Load ROM into memory
for (let i = 0; i < romData.length; i++) cpu.mem[i] = romData[i];
```

For static disassembly, read bytes directly from `romData` and decode eZ80 instructions manually or by reading the transpiled blocks.

For dynamic traces, set registers, set `cpu.pc` to the target address, and step with `cpu.step()` in a loop, logging PC, registers, and memory at each step. Use a sentinel return address: push 0x7FFFFE onto the stack before entry so you can detect when the function returns.
