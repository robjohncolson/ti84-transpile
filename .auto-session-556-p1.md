# Task: Decode 0x055280 LCD Register Setup Function

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). Previous sessions identified a BPP cluster at 0x052A00-0x0554FF (~11KB, ~56 functions) that handles LCD display mode management.

## Target
Fully decode the function at **0x055280** which writes to LCD control registers. Session 555 found that this function:
- Writes to LCD registers at E30018, E30028, E30010, E30020
- Sets VRAM base to D40000 via `LD (E30010),HL`
- Checks BIT 2,(E30028) in a polling loop before returning
- Is part of the BPP cluster that handles 8bpp/16bpp display modes

## Deliverables
Create a probe file `TI-84_Plus_CE/probe-phase556-lcd-regs.mjs` that:

1. **Hex-dumps 0x055280 through 0x0552FF** (128 bytes should be plenty — adjust if you hit RET earlier) from `TI-84_Plus_CE/ROM.rom`. Use `fs.readFileSync` to read the ROM binary.

2. **Disassembles the function manually** using eZ80 opcode tables. The CPU is eZ80 in ADL mode (24-bit addresses, 3-byte immediates for LD rr,imm24). Key opcodes:
   - ED 6F = LD (imm24),HL (stores HL to 24-bit address)
   - DD 21 xx xx xx = LD IX,imm24
   - FD CB dd bb = IY bit operations at displacement dd
   - CB 46 = BIT 0,(HL), CB 4E = BIT 1,(HL), CB 56 = BIT 2,(HL), etc.
   - 20 dd = JR NZ,dd (signed offset)
   - 28 dd = JR Z,dd
   - C9 = RET

3. **Identifies what values are written to each LCD register**:
   - E30018 = ? (likely LCD control)
   - E30028 = ? (status register — polled with BIT 2)
   - E30010 = ? (VRAM base address)
   - E30020 = ? (likely LCD timing/config)

4. **Documents all callers** — search the ROM for bytes that encode `CALL 0x055280` (CD 80 52 05) and `JP 0x055280` (C3 80 52 05). Report each caller address.

5. **Cross-references with known LCD register documentation**: The TI-84 Plus CE uses an LCD controller where:
   - 0xE30000-0xE3FFFF is the LCD register space
   - 0xD40000 is VRAM base (320×240, 16bpp = 153,600 bytes or 8bpp = 76,800 bytes)
