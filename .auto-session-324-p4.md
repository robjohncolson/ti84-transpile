# Task: Investigate 0x000138 — the function called by 0x055743

## Context
This is the TI-84 Plus CE ROM transpilation project. Session 323 decoded 0x055743 as a 13-byte config table copier. It calls 0x000138 with HL as a parameter. We need to understand what 0x000138 does — is it a generic OS utility (memcpy, lookup, validation) or LCD-specific?

## Goal
Write a probe `TI-84_Plus_CE/probe-phase324-function-000138.mjs` that:

### Part 1: Static disassembly
1. Disassemble 0x000138 (first 100 bytes or until RET, whichever comes first)
2. Identify all CALL targets, JP targets, conditional branches
3. Look for patterns: does it do a table lookup? Memory copy? Validation?
4. Check if it accesses any specific RAM addresses or ports

### Part 2: Cross-reference scan
1. Scan the entire ROM for all references to 0x000138:
   - Search for bytes 38 01 00 in little-endian (0x000138 = 0x38, 0x01, 0x00)
   - Check if preceding byte is 0xCD (CALL) or 0xC3 (JP)
2. Count total callers and list the first 20
3. Categorize: is 0x000138 called from many subsystems (generic utility) or only LCD code (specialized)?

### Part 3: Context from the vector table
1. Address 0x000138 is in the 0x000000-0x000FFF region (boot/vector table area)
2. Disassemble the surrounding region (0x000120-0x000160) to see if 0x000138 is part of a vector table pattern
3. Check neighboring addresses (0x000130, 0x000140, etc.) for similar JP patterns

### Part 4: Dynamic trace
1. Boot to post-init (entry 0x0802B2, SP=0xD1A87E, MBASE=0xD0, IY=0xD00080)
2. Set HL to a test value (e.g., the address 0x05550C that 0x055743 passes as one of its two cases)
3. Push fake return 0x7FFFFE, set PC = 0x000138
4. Step limit 5,000
5. Log: what does it read from HL? What does it do with the data? Where does it write?
