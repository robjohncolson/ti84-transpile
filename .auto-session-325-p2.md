# Task: Trace the LCD Refresh Pipeline End-to-End — Who Calls 0x055280?

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM (eZ80 machine code at `TI-84_Plus_CE/ROM.rom`) has been lifted to JavaScript. We're tracing the OS internals.

Session 324 identified:
- 0x010A3C = LCD sync function (wait until DMA idle, polls port 0x8040) — CONFIRMED WORKING
- 0x055280 = LCD DMA transfer trigger (writes 0xE30018 command, sets VRAM base 0xD40000 at 0xE30010, triggers DMA via 0xE30028, polls 0xE30020) — hangs because 0xE300xx MMIO not yet emulated
- 0x055191 = RAM-only config table copier (returns in 11 steps, zero I/O)

## What to do
Create a probe `TI-84_Plus_CE/probe-phase325-lcd-pipeline-callers.mjs` that:

### Part 1: Find all callers of 0x055280 in the ROM
Scan the ROM binary (`TI-84_Plus_CE/ROM.rom`, 4MB) for CALL instructions targeting 0x055280.

eZ80 CALL encoding: `0xCD` followed by 3-byte little-endian address.
So search for bytes: `CD 80 52 05` (0xCD, then 0x055280 in LE = 0x80, 0x52, 0x05).

Also check for JP instructions: `0xC3 80 52 05`.

Report every caller address and the region it's in:
- 0x000000-0x01FFFF = OS Low
- 0x020000-0x03FFFF = OS Mid  
- 0x040000-0x05FFFF = OS High
- 0x060000+ = OS Upper / Apps

### Part 2: For each caller, find THEIR callers (one level up)
For each function that calls 0x055280, search for CALL/JP instructions targeting that function's address. This gives us the call chain.

### Part 3: Trace what sets up the VRAM base at 0xE30010
Before calling 0x055280, the caller should write to 0xE30010/0xE30011/0xE30012 to set the VRAM base pointer. Look at the bytes BEFORE each CALL 0x055280 to see what LD instructions write to those addresses. The IY register is commonly used for MMIO access: `LD (IY+offset), reg`.

### Implementation pattern
Use `TI-84_Plus_CE/probe-phase324-real-lcd-hw-init.mjs` as a template for the probe structure. Key imports:

```javascript
import { readFileSync } from 'fs';
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
```

Then scan the buffer for byte patterns. No need to execute code — this is static analysis of the ROM binary.

### Deliverables
The probe should print a structured report:
1. All CALL/JP sites targeting 0x055280 (address + region)
2. For each caller, their callers (one level up)
3. Any evidence of VRAM base setup (writes to 0xE30010-0xE30012) near call sites
4. A summary of the LCD refresh pipeline call chain

### Constraints
- Read-only analysis — do NOT modify any existing files
- Create only the probe file
- Use the ROM binary directly, not the transpiled JS
- Keep the probe under 300 lines

### Success criteria
- Probe runs without errors: `node TI-84_Plus_CE/probe-phase325-lcd-pipeline-callers.mjs`
- At least 1 caller of 0x055280 is found
- Call chain is traced at least 2 levels deep
- Report clearly shows the LCD refresh pipeline path
