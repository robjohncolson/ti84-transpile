# Auto-Session 246 — P4: Full event loop cycle with key injection

## Context
Sessions 236-245 have decoded the event loop and display pipeline in detail:
- Event loop at 0x02FD99: 127 steps to HALT, reads D0058E for key code
- Key dispatch: 0x02FD8F → CP 0x36/0x30 classification → 0x02FFAE normal dispatch
- Post-key handler: 0x04EDD0 → 0x04ECCE → VRAM fill (0x09EFDE) → display update
- Post-display: 0x08BFCD gate → 0x08BFEC (display table selector) → 0x08C102 → 0x09EF44 → 0x09EFDE
- D02A86 counter: set by 0x0271CD, decremented at 0x08BFE3, zeroed at 0x027112

But nobody has tried running a COMPLETE cycle: inject a key → let the event loop process it → see the full path from HALT wakeup through display update back to HALT.

## Task
Build a probe `TI-84_Plus_CE/probe-phase246-full-event-cycle.mjs` that:

1. **Boot to event loop**: Full boot (z80Boot 0x000000 → kernelInit 0x000292 → memInit 0x020818 → home stages 1-4 with IX=0xD1A860), then run the event loop (entry at 0x02FD99) until it reaches HALT. Record the HALT address and step count.

2. **Inject key "2" (scan code 0x22, key code 0x8F)**: After HALT:
   - Write 0x8F to D0058E (the primary key code variable)
   - Set the keyboard scan result: write 0x22 to the scan buffer at D0058C
   - Set IY+29 bit 0 (the "key available" flag) — SET instruction at 0x02FE9D does `SET 0,(IY+29)`, so write D0009D bit 0
   - Resume execution from the instruction AFTER the HALT

3. **Trace the full cycle (200,000 steps max)**: Let execution run until it either:
   - Reaches HALT again (full cycle complete)
   - Hits 200,000 steps (stuck)
   Log at checkpoints (every 10,000 steps):
   - Current PC and block
   - SP value
   - D0058E value (key code — does it get consumed?)
   - D02A86 value (pending display counter)
   - D007E0 value (display mode)
   - D003E0 value (mode flags)
   - Number of unique blocks so far

4. **Capture the block sequence**: Log every unique block visited during the cycle, in order of first visit. Group them by address range:
   - 0x02xxxx = event loop / key dispatch
   - 0x04xxxx = key handler / housekeeping
   - 0x05xxxx = cxMain / token dispatch
   - 0x07xxxx = display / FP
   - 0x08xxxx = display management
   - 0x09xxxx = VRAM / display
   - 0x0Axxxx = display setup

5. **Report**: Did the full cycle complete (HALT→key→processing→HALT)? If yes, how many steps? If stuck, where?
