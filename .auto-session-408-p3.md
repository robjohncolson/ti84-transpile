# Task: Map OS Syscall/Jump Table Entries at 0x020104

## Context
This is a TI-84 Plus CE ROM (eZ80) transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB).

Session 403 confirmed the OS jump table at 0x020104 contains 2,178 JP instructions (each 4 bytes = 8,712 bytes total, ending at 0x02230C). 4-byte magic header 5A A5 FF FF at 0x020100. Only 12 unique entries are called directly (by hardcoded CALL/JP to specific table slot addresses). Session 69 extracted 957 named entries from `ti84pceg.inc`.

## Your Task
1. **Extract all 2,178 JP targets** from the jump table at 0x020104. Each entry is a 4-byte JP instruction: opcode 0xC3 followed by 3-byte little-endian target address. Verify the pattern holds for all entries.

2. **Find the 12 entries that are called directly**. Search the entire ROM for CALL/JP instructions whose target falls within 0x020104-0x02230C. For each:
   - What is the caller address?
   - Which table slot does it call (compute: (target - 0x020104) / 4)?
   - What is the JP target at that slot?

3. **Cross-reference with ti84pceg.inc names**. The file `TI-84_Plus_CE/ti84pceg.inc` (or check for it) contains SDK-defined names for syscall entries. Match the 12 directly-called slots to their SDK names if available.

4. **Categorize the JP targets**: How many point to flash (0x040000+)? How many to low ROM (0x000000-0x03FFFF)? How many are duplicates (multiple slots pointing to the same target)?

## Deliverables
- Create `TI-84_Plus_CE/probe-phase408-syscall-table.mjs` — a Node.js probe that:
  - Loads the ROM
  - Reads all 2,178 entries from 0x020104
  - Searches the ROM for direct callers of table slots
  - Reports: slot index, JP target, any SDK name, and direct callers
- Create `TI-84_Plus_CE/phase408-syscall-table-report.md` — findings

## Reference Files
- `TI-84_Plus_CE/ez80-decoder.js` — instruction decoder
- `TI-84_Plus_CE/probe-phase403-trampoline-indexer.mjs` — confirmed table structure
- Check for `TI-84_Plus_CE/ti84pceg.inc` or similar SDK include file

## Important Notes
- JP instruction in eZ80 is 0xC3 followed by 3 bytes (24-bit address, little-endian)
- CALL instruction is 0xCD followed by 3 bytes
- RST vectors (0x10, 0x18, 0x20, 0x28, 0x30) jump to entries #3-#7 per session 403
- The table uses DIRECT fixed-address calls, NOT computed indexes
