# Task: Trace the Heap Allocator at 0x00E06D

## Context
The TI-84 Plus CE ROM transpilation project lifts eZ80 ROM machine code into runnable JavaScript. This is a pure investigation/disassembly task — produce a report, do NOT modify any source files.

## Background
Session 320 identified 0x00E06D as a heap allocator used by the USB pipe setup subsystem. The D13FFC pointer (74 refs, USB pipe descriptor heap pointer) is allocated by this function. This priority has been carried from session 320 → 321 → now.

## What to Investigate

### 1. Disassemble 0x00E06D
- Read `TI-84_Plus_CE/ROM.rom` (4MB binary, little-endian eZ80)
- Start at offset 0x00E06D
- Trace until RET or equivalent — heap allocators are typically 50-200 bytes
- Document every instruction with address and purpose
- Key questions:
  - What are the input parameters? (size in HL? block type in A?)
  - What does it return? (pointer in HL?)
  - What RAM addresses does it use for heap metadata?

### 2. Identify the heap region
- What RAM addresses serve as the heap base and heap top pointers?
- Is there a free list? Or is it a simple bump allocator?
- What's the allocation strategy? (first-fit, best-fit, bump, slab?)
- Is there a corresponding free/dealloc function?

### 3. Find all callers of 0x00E06D
- Search ROM for CALL 0x00E06D (opcode CD 6D E0 00) 
- Search ROM for JP 0x00E06D (opcode C3 6D E0 00)
- List all call sites
- For each caller, note what subsystem it belongs to (USB? general OS? app?)

### 4. Related functions
- Is there a dealloc/free counterpart? Check addresses near 0x00E06D (±0x100)
- Are there other heap management functions (heap init, heap check, etc.)?
- What RAM range does the heap occupy?

## Tools Available
- ROM file: `TI-84_Plus_CE/ROM.rom` (read as binary)
- Use `node -e` with `fs.readFileSync` to read ROM bytes
- eZ80 is a Z80 superset with 24-bit addressing. Key opcodes:
  - `CD xx xx xx` = CALL addr24
  - `C9` = RET
  - `DD` = IX prefix
  - `ED 6F` = MLT (multiply)
  - `21 xx xx xx` = LD HL,imm24
  - `11 xx xx xx` = LD DE,imm24

Contents:

2. Allocation algorithm description

4. Complete caller list
5. Related functions (free, init, etc.) if found
6. Heap region boundaries if determinable
