# Auto-Session 306 P1: Find Scan-Code-to-Class Function

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80). The transpiler at `scripts/transpile-ti84-rom.mjs` lifts ROM bytes into JavaScript blocks.

We've been hunting for the function that converts a raw keyboard scan code (0x00-0x3F) into a "key class" value used by the OS event loop. Prior sessions eliminated several candidates:
- 0x069A8D = editor refresh pipeline trigger (18 callers, no A writes) — NOT classifier
- 0x058EC6 = flag-clearing stub (scan code passes through) — NOT classifier
- 0x0800A8 = scan code gate (CP 0x00, JR Z skip) — NOT converter
- 0x058D54 = identity function for classes 0-15 (CP cascade for 2-byte tokens) — handles token classes, not scan codes

## Task
Find the REAL scan-code-to-class function. The OS reads raw scan codes (0x00-0x3F) from D00587 (set by keyboard ISR). Somewhere between GetCSC returning a scan code and CoorMon processing it, the scan code is converted to a "key class" that determines behavior (digit, alpha, function key, arrow, etc.).

### Where to look
1. **Event loop key handler**: 0x02FD8F→0x02FE89 (session 293 disassembled the loop — no HW reads, but may contain the classification). Read blocks in the transpiled JS around this range.
2. **The CP cascade at 0x05877A** (session 206 identified): cascading CP comparisons that route different key classes. This may BE the classifier — it's a computed classification via CP chain, not a table lookup.
3. **0x058xxx region broadly**: grep for CP cascades on values in 0x00-0x3F range (scan code values). The classifier may be inline in the key dispatch chain.
4. **0x04Exxx region**: also mentioned as a possible location.

### Method
1. Read `TI-84_Plus_CE/ROM.rom` binary data at these addresses and disassemble the eZ80 instructions
2. Look for patterns: LD A,(D00587) or LD A,(IY+offset) followed by CP cascades that compare against scan code values
3. The classifier likely takes A=scan_code and either returns A=class or branches to class-specific handlers
4. Create a probe script that traces execution from GetCSC return through the classification

### Deliverables
1. Create `TI-84_Plus_CE/probe-phase306-scan-class-find.mjs` — a probe that:
   - Seeds D00587 with a known scan code (e.g., 0x31 = ENTER)
   - Runs from 0x02FD8F (event loop) or wherever the classification starts
   - Logs every CP instruction and its operand, plus every conditional branch taken
   - Reports which address range performs the classification
2. Write findings as comments at top of probe file

### Constraints
- Do NOT modify `cpu-runtime.js`, `peripherals.js`, `browser-shell.html`, or `scripts/transpile-ti84-rom.mjs`
- The probe should use the same pattern as existing probes (import from cpu-runtime.js, create CPU, load ROM, etc.)
- Look at `TI-84_Plus_CE/probe-phase305-scan-class-hunt.mjs` for the probe pattern used in prior sessions
