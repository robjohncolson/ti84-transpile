# Auto-Session 359 P2: Trace Caller Chain of 0x000D82 + Disassemble 0x000D7E Entry

## Context

The TI-84 Plus CE boot hits `missing_block` at RAM address 0xD18C22 because block 0x000D82 copies code from ROM 0x000EBB to RAM and jumps there. We need to understand the full call chain that leads to this copy — specifically, what block CALLS or JUMPS to 0x000D82 (actually 0x000D7E, the real entry point), and what the caller does with the return value.

### Known facts from sessions 289, 299, 300, 358:
- 0x000D7E is the real entry point (CALL target); 0x000D82 is 4 bytes into it
- The routine takes IX pointing to a parameter block (2-byte length + code)
- 8 total callers of CALL 0x000D7E found by session 300
- The specific caller during boot is at 0x000E94: `LD IX, 0x000EB9; CALL 0x000D7E` (at 0x000E99)
- After the RAM code executes and RETs, control returns to 0x000E9D (instruction after the CALL)

### What we DON'T know:
1. What code calls 0x000E94? What is the block that reaches this address?
2. What does 0x000E9D do after the flash test returns? Does it check a flag? Does it loop?
3. What are the bytes at 0x000D7E-0x000D81 (the 4-byte entry prefix before 0x000D82)?

## Task

Create a probe `TI-84_Plus_CE/probe-phase359-caller-chain.mjs` that:

1. **Disassemble 0x000D7E-0x000D81** (4 bytes). These are the entry point bytes before the known code at 0x000D82. Use raw ROM bytes and an eZ80 disassembler. Expected: likely PUSH AF or similar prologue.

2. **Disassemble 0x000E9D-0x000ED0** (the code AFTER the CALL 0x000D7E at 0x000E99). This is what executes after the flash self-test returns. Does it check a register? Does it branch? Does it call another copy routine?

3. **Trace the dynamic call stack during boot** up to the point where 0x000D82 executes. Run the boot with `createPeripheralBus({ timerInterrupt: false })` and track all CALL/RET/JP transfers. When execution reaches 0x000D82 (or 0x000D7E), dump the call stack: what sequence of CALLs led here? This tells us the full caller chain.

4. **Disassemble 0x000E80-0x000E99** — the code block that contains the LD IX + CALL sequence. What is this function? Where does it start? What conditional logic (if any) guards the CALL?

5. **Cross-reference with the 0x001D37 NMI path**. Session 358 found that block 0x001D37 also calls 0x000D7E (specifically at 0x001D51 via `CALL 0x000D7E`). With GPIO bit 4=1, IX=0x001008 (the E008xx MMIO routine, 591 bytes). Does the boot path go through 0x001D37 or directly through 0x000E94?
