# Task: Trace 0x03FBFD key pipeline function

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 binary). The transpiled JS is generated by `scripts/transpile-ti84-rom.mjs` and the runtime is in `TI-84_Plus_CE/cpu-runtime.js`.

Function 0x084E98 (362 bytes, decoded in session 224) handles key codes after they arrive in the A register. It has 3 callers:
- 0x084D34 (after CALL 0x084ADF)
- **0x084D4F (after CALL 0x03FBFD)** ← this is our target
- 0x084D6E (hardcodes A=0x4A)

0x03FBFD is called as part of the key processing pipeline BEFORE the D00824 writer at 0x084E98. We need to understand what 0x03FBFD does.

## Your Task
Build a probe `TI-84_Plus_CE/probe-phase225-03fbfd-key-pipeline.mjs` that:

1. **Static disassembly**: Read ROM.rom and disassemble starting at 0x03FBFD. Decode eZ80 instructions (ADL mode, 24-bit addresses). Continue until you hit a RET or have decoded 200 bytes. Look for:
   - What registers it reads/writes
   - What memory addresses it accesses
   - What sub-functions it CALLs
   - Key state variables (D0058E = key code, D00824 = processed key, D0059F = mode)

2. **Find function boundaries**: Scan backward from 0x03FBFD looking for a RET/JP/JR instruction to find the function start. Scan forward to find the RET that ends it.

3. **Find ALL callers**: Scan the entire ROM (0x000000-0x0BFFFF) for:
   - `CALL 0x03FBFD` → byte pattern `CD FD FB 03` (or with ADL prefix)
   - `JP 0x03FBFD` → byte pattern `C3 FD FB 03`

4. **Dynamic trace**: Boot the CPU (z80 boot 0x000200, kernelInit 0x000324, memInit 0x020814), then:
   - Set up for a key press: write a key code (e.g., 0x8F = digit '1') to D0058E
   - Call 0x03FBFD directly with A=0x8F
   - Trace for 500 steps, recording all unique blocks visited
   - Check what D0058E, D00824, D0059F contain after the call
   - Also try with A=0x2B (comma key) and A=0x00 (no key)

**Read an existing probe first** to understand the exact API. Good references:
- `probe-phase224-084e9c-caller-chain.mjs` (similar function tracing)
- `probe-phase223-02f68a-function-trace.mjs` (similar pipeline analysis)

Match the coding style exactly — imports, CPU/peripheral creation, boot sequence, step counting.

## Deliverables

- Run it with `node TI-84_Plus_CE/probe-phase225-03fbfd-key-pipeline.mjs` and include the output
- Report: function boundaries, what it does, all callers, dynamic behavior
