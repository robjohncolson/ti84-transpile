# Task: Decode 0x099F49 (CLEAR key handler) and 0x099F68 ((-) key handler)

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The OS event loop command dispatcher at 0x099921 has been fully mapped (session 514). It routes key codes via CP/JP cascades. Two important handlers:
- 0x099F49 = CLEAR key handler (key code 0x07)
- 0x099F68 = (-) key handler (key code 0x09)

These are among the most common home-screen keys. CLEAR is critical for understanding screen reset flow.

## Your task
Create a probe file `TI-84_Plus_CE/probe-phase515-decode-key-handlers.mjs` that:

1. Loads the ROM and disassembles starting at 0x099F49 (at least 128 bytes)
2. Also disassembles starting at 0x099F68 (at least 128 bytes)
3. For each, identify:
   - All CALL targets and JP targets
   - RAM addresses read/written
   - Which rendering or system functions are invoked
   - Where each function returns or jumps to next
4. Print the full disassembly and analysis

## Technical details
- ROM file: `TI-84_Plus_CE/ROM.rom` (4MB, load with `fs.readFileSync`)
- Use the decoder from `TI-84_Plus_CE/ez80-decoder.js` — import with:
  ```js
  import { createDecoder } from './ez80-decoder.js';
  ```
  Then: `const decoder = createDecoder(romBuffer);` and `decoder.decode(address)` returns `{mnemonic, operands, length, ...}`
- The ROM is eZ80 ADL mode (24-bit addresses). All addresses are 24-bit.
- Known function references from session 514:
  - 0x099921 = event loop command dispatcher
  - 0x09BBAD = get keycode
  - 0x09BF37 = setup function
  - 0x09BAB8 = setup function
  - 0x082961 = system lock
  - 0x0828D1 = system unlock
  - 0x06868A = descriptor-type dispatcher
  - 0x07D583 = populator
  - 0x0A1799 = glyph-to-VRAM rasterizer

## Constraints
- Do NOT modify any existing files
- Do NOT import from cpu-runtime.js — use ez80-decoder.js directly with the ROM buffer
- File must be a standalone .mjs with `import` at top
- Run the probe via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase515-decode-key-handlers.mjs`

## Success criteria
- Probe runs cleanly and prints disassembly of both functions
- Each function's purpose, call targets, and RAM accesses are identified
- Output clearly labels which function is which
