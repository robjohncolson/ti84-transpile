# Task: Implement browser-shell font rendering with corrected base 0x003D6E

## Context
This is a TI-84 Plus CE ROM transpilation project with a browser shell at `TI-84_Plus_CE/browser-shell.html`. The font architecture has been fully decoded:

- **Font base address**: 0x003D6E in ROM (NOT 0x004000 — that was a prior incorrect finding)
- **Glyph size**: 28 bytes per glyph (0x1C)
- **Format**: 1bpp bitmap, 2 bytes per row × 14 rows = 28 bytes
- **Glyph dimensions**: 14 rows tall, up to 16 pixels wide (2 bytes per row)
- **ROM copies glyphs to RAM staging**: 0xD005A5 (28 bytes), then returns pointer to 0xD005A1

The OS function at 0x00596E computes: `ROM[0x003D6E + glyphOffset]`, copies 28 bytes to 0xD005A5, and returns HL=0xD005A1.

## What to do

Modify `TI-84_Plus_CE/browser-shell.html` to add a JavaScript font renderer that can decode and display ROM font glyphs. Specifically:

1. **Add a `renderGlyph(romData, charCode, ctx, x, y, fgColor, bgColor)` function** that:
   - Reads 28 bytes from ROM at offset `0x003D6E + charCode * 0x1C`
   - Decodes the 1bpp bitmap: 2 bytes per row, 14 rows
   - For each bit: if 1, draw foreground pixel; if 0, draw background (or transparent)
   - Renders to a canvas 2D context at position (x, y)

2. **Add a `renderText(romData, text, ctx, x, y, fgColor, bgColor)` function** that:
   - Iterates through characters in the text string
   - Calls renderGlyph for each character
   - Advances x position by glyph width (likely 8 or 10 pixels — check the actual glyph data to determine effective width)

3. **Add a test/demo**: Add a button or automatic display that renders "HELLO WORLD" or similar test text using the ROM font, so we can visually verify the font rendering works.

4. **Integration note**: The ROM data is available as `romData` (Uint8Array) after the ROM is loaded. The LCD canvas already exists. Place the font rendering functions in a clearly labeled section.

## Important details

- The charCode used in the glyph offset calculation is the TI-OS character code, NOT ASCII. For basic uppercase letters and digits, TI-OS codes may differ from ASCII. Start with direct charCode indexing and we'll map ASCII→TI later.
- The glyph format is likely: MSB first per byte, row 0 at offset 0, row 13 at offset 26.
- 2 bytes per row = 16 pixels wide maximum, but many glyphs may only use 7-8 pixels (the rightmost bits might be padding).
