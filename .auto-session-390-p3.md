# Task: Investigate the 0x005A75 character renderer font data

## Context
You are working on TI-84 Plus CE ROM transpilation. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary).

0x005A75 is a character rendering function in the TI-84 CE OS. Understanding where its font data comes from and what format it uses is needed for browser-shell text rendering.

## Deliverable
Create `TI-84_Plus_CE/probe-phase390-font-data.mjs` — a Node.js probe that:

1. Reads the ROM from `TI-84_Plus_CE/ROM.rom`
2. Statically disassembles starting at 0x005A75 using BFS (follow branches, calls, jumps)
3. Looks for:
   - Where IX register is loaded/used (IX often points to font data)
   - Any LD instructions that reference addresses in the 0x3Bxxxx-0x3Fffff range (flash data) or 0x000000-0x010000 range (low ROM)
   - Indexed memory reads like (IX+d), (IY+d), (HL), (DE), (BC) that could be font bitmap reads
   - Loop structures that iterate over pixel rows (e.g., a counter of 8 or 16 for row height)
   - Any multiplication or shift operations that compute glyph offsets (e.g., char_code * glyph_size)
4. Reports:
   - Full instruction listing with addresses and hex bytes
   - All CALL/JP targets found
   - Font data pointer(s) if found — the base address of the font bitmap table
   - Glyph dimensions if determinable (width x height in pixels, likely 8x16 or 6x8)
   - Font format if determinable (1bpp bitmap, packed, proportional, etc.)
   - All RAM reads/writes

## eZ80 Encoding Reference
- ADL mode: all addresses are 24-bit (3 bytes, little-endian)
- LD r,nn = 1-byte opcode + 3-byte immediate (ADL mode)
- CALL nn = 0xCD + 3-byte address
- JP nn = 0xC3 + 3-byte address
- IX prefix = 0xDD: LD IX,nn = 0xDD 0x21 + 3-byte; LD r,(IX+d) = 0xDD 0x46+r*8 + 1-byte offset
- IY prefix = 0xFD
- RET = 0xC9
- SLA/SRL/RLC/RRC for bit manipulation (font rendering often uses shifts)
- BIT/SET/RES for pixel testing
- ADD HL,DE / ADD IX,DE for pointer arithmetic
