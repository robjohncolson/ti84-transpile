# Task: Decode 0x061D02 — Error Longjmp Target

## Context
0x061D02 is an error/overflow longjmp target in the TI-84 Plus CE OS ROM. Known references:
- 0x07FE20 (4B): `JP 0x061D02` — standalone overflow longjmp (decoded session 538)
- 0x07CA73 area: `JP 0x061D02` on exponent overflow in FP right-shift normalizer
- 0x07FE1A: exponent increment overflow dispatches here

Related longjmp targets already seen:
- 0x061D0E — longjmp from 0x080173 validation guard (session 535)
- 0x061D22 — longjmp from 0x07FF59 calling context
- 0x061D46 — longjmp from session 519

These are all in the 0x061Dxx range, likely a table of error handler entry points.

## Task
Write a probe script that:

1. Reads raw ROM bytes from 0x061D00 to 0x061D60 and hex-dumps them
2. Manually disassembles starting at 0x061D02, 0x061D0E, 0x061D22, and 0x061D46
3. Look for patterns like:
   - LD A,imm8 (error code loading)
   - JP addr (forwarding to shared error handler)
   - RST 0x28 or RST 0x08 (TI-OS system calls)
   - CALL addr (error dispatch)
4. Map the 0x061D00-0x061D60 region to identify all entry points and whether they share a common error handler

## eZ80 instruction reference (key opcodes for this task)
- 3E xx = LD A,imm8
- C3 xx xx xx = JP addr [4 bytes ADL mode]
- CD xx xx xx = CALL addr [4 bytes ADL]
- C9 = RET
- CF = RST 0x08, D7 = RST 0x10, DF = RST 0x18, E7 = RST 0x20, EF = RST 0x28
- 21 xx xx xx = LD HL,imm24
- 11 xx xx xx = LD DE,imm24
- F5 = PUSH AF, C5 = PUSH BC
- 18 xx = JR offset
