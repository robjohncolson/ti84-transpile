# Task: Decode 0x07DF6A (alternate renderer from 0x07D233)

## Context
You are working on the TI-84 Plus CE ROM transpilation project. Session 514 decoded 0x07D233 as a descriptor filter/router. It has three exit paths:
- Primary: JP 0x07CFA7 (standard text renderer) — the main path
- Alternate 1: JP 0x07FE9C (reached when 0x07FD4A returns Z)
- Alternate 2: JP 0x07DF6A (reached via alternate entry at 0x07D276)

0x07CFA7 and 0x07FE9C are partially known, but 0x07DF6A is completely unknown. Understanding it reveals what descriptor types get special rendering treatment — possibly graphs, equations, or formatted math expressions.

## Your task
Create a probe file `TI-84_Plus_CE/probe-phase515-decode-07DF6A.mjs` that:

1. Disassembles starting at 0x07DF6A (at least 256 bytes to capture the full function)
2. Also disassemble 0x07FE9C briefly (64 bytes) to compare the two alternate paths
3. For each, identify:
   - All CALL and JP targets
   - RAM addresses read/written (especially D005F8/D005F9/D00595/D00596)
   - Whether it calls the rasterizer 0x0A1799 or BCD calc 0x07C8B7
   - How it differs from the standard 0x07CFA7 path
   - Where it returns or chains to
4. Print the full disassembly and analysis

## Technical details
- ROM file: `TI-84_Plus_CE/ROM.rom` (4MB, load with `fs.readFileSync`)
- Use the decoder from `TI-84_Plus_CE/ez80-decoder.js` — import with:
  ```js
  import { createDecoder } from './ez80-decoder.js';
  ```
  Then: `const decoder = createDecoder(romBuffer);` and `decoder.decode(address)` returns `{mnemonic, operands, length, ...}`
- The ROM is eZ80 ADL mode (24-bit addresses).
- Known functions for cross-reference:
  - 0x07CFA7 = standard text renderer
  - 0x07C8B7 = BCD position calculator
  - 0x0A1799 = glyph-to-VRAM rasterizer
  - 0x07D1B4 = descriptor list walker
  - 0x07D233 = descriptor filter/router
  - 0x07F7BD = read D005F8 type
  - 0x0801E9 = type test
  - 0x07F9FB = copy descriptor to D005F8

## Constraints

- File must be a standalone .mjs with `import` at top
