# Task: Re-investigate Key Handler Table Format at 0x07DD00

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80 binary).

Session 410 found that key dispatch at 0x05D593 reads a table base from RAM address D1441D and indexes it by key code. The installer at 0x05D5C9 does `LD BC,(IX+6)` — reads table base from a stack parameter. Session 410 corrected that 0x07DD00 was a false positive as a hardcoded ROM table base.

However, the DISPATCH mechanism at 0x05D58F is confirmed: it reads key code from D141B5, multiplies by 4 (key_code × 4), adds to table base from D1441D, and calls via CALL 0x0000A4.

## Task
Write a probe `TI-84_Plus_CE/probe-phase411-key-handler-format.mjs` that:

1. Reads the ROM binary directly to disassemble the dispatch code at 0x05D58F-0x05D5E0 (about 80 bytes). Show exact byte-by-byte disassembly with eZ80 opcodes.

2. Find ALL callers of the table installer at 0x05D5C2 (the syscall trampoline entry). Search the entire ROM for CALL 0x05D5C2 and JP 0x05D5C2 patterns. For each caller, disassemble the surrounding 20 bytes to see what value they pass as the table base parameter (what's in BC before the call).

3. Also search for the JP table entry at 0x021E78 that jumps to 0x05D5C2. Find all CALL 0x021E78 patterns in the ROM.

4. For any ROM addresses found as table bases, dump the first 64 bytes of that table and try to interpret them as 4-byte entries (3-byte address + 1 byte flags). Report which entries point to valid ROM addresses (< 0x400000) vs garbage.

## eZ80 Encoding Reference
- CALL nn = 0xCD followed by 3 bytes (little-endian 24-bit address)
- JP nn = 0xC3 followed by 3 bytes (little-endian 24-bit address)
- LD BC,nn = 0x01 followed by 3 bytes (little-endian 24-bit)
- LD HL,(nn) = 0x2A followed by 3 bytes (address, little-endian)
- LD BC,(IX+d) = 0xDD 0x07 0x4E 0x06 (prefix varies - just show raw bytes)
