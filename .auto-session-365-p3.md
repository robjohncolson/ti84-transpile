# Task: Disassemble ROM at 0x006D57 (Fix B Boot Endpoint)

## Context
The TI-84 Plus CE ROM transpilation project boots the OS by executing lifted JavaScript blocks. In session 364, Fix B (SP clamp) reached 517 unique blocks over 10,000 steps, with the last PC at 0x006D57 in ADL mode. We need to disassemble this area to understand what the OS is doing at this point — is it entering the main event loop, continuing hardware init, or in a subroutine?

## What to do

Write a probe script at `TI-84_Plus_CE/probe-phase365-disasm-006D57.mjs` that:

1. **Reads ROM.rom** and disassembles bytes starting at 0x006D57 for ~128 bytes (through 0x006DD7). Use the eZ80 ADL instruction set.

2. **For the disassembly**, read the raw ROM bytes and decode them manually. The eZ80 instruction set in ADL mode uses 24-bit addresses. Key opcodes:
   - Standard Z80 opcodes (single byte) with 24-bit immediates where applicable
   - `0xED` prefix for extended instructions
   - `0xCB` prefix for bit operations
   - `0xDD` prefix for IX instructions
   - `0xFD` prefix for IY instructions
   - In ADL mode, immediate addresses and stack operations are 24-bit (3 bytes)

3. **Also disassemble surrounding context**: 0x006D40 through 0x006DF0 to see if 0x006D57 is mid-function or a function entry.

4. **Static analysis**: Check if any of these patterns appear:
   - `CALL` targets (what functions does this code call?)
   - `JP` targets (where does control flow go?)
   - `RET` instructions (is this a leaf function?)
   - Port I/O (`IN`/`OUT` instructions)
   - Memory references (what RAM/MMIO addresses are accessed?)

5. **Print a clean disassembly listing** with address, hex bytes, and mnemonic for each instruction.
