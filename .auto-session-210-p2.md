# Auto-Session 210 — P2: Why cxMain digit path returns without BufInsert

## Context

In the TI-84 Plus CE ROM transpilation, the cxMain digit dispatch path goes:
0x0585E9 → 0x05877A → 0x0587E9 → 0x05899D → 0x058D54 → 0x0589E5 → 0x0589E9 → 0x058A0C → 0x058A60 → 0x058AC9 → return

At 0x058AC9, `CALL 0x0802C4` does `CP 0x5A; RET C`. Since digit class A=0x00 < 0x5A, carry is set, and RET C fires — BufInsert is never reached.

But there are THREE earlier CP branches in the cascade that digits fall through:
- **0x058A0C**: `CP 0x09` — class 0 ≠ 9, falls through  
- **0x058A60**: `CP 0x0C` — class 0 ≠ 12, falls through
- **0x058AC9**: the final gate (CP 0x5A rejects all class < 90)

Session 205's probe showed the digit path returns cleanly after 0x058AC9 without inserting. The question is: **what happens at the CP 0x09, CP 0x0C, and CP 0x0D branches when the class DOES match?** These might be the actual digit insertion paths (if digits are reclassified to class 9/12/13 under certain OS state conditions).
