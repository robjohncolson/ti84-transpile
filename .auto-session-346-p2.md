## Task

Create a probe that disassembles the first 32 bytes of each of the 32 syscall targets to identify what they do. Cross-reference with known TI-84 CE SDK bcall numbers:

Standard TI-84 CE bcall mapping (RST 0x28 + 2-byte index):
- The RST 0x28 vector is at ROM address 0x000028. Each bcall is RST 0x28 followed by a 16-bit index.
- But this table at 0x000080 uses RST 0x38 (8-byte stride entries). These are the system RST vectors, not bcalls.
- RST 0x00 = 0x000000 (reset)
- RST 0x08 = 0x000008
- RST 0x10 = 0x000010
- RST 0x18 = 0x000018
- RST 0x20 = 0x000020
- RST 0x28 = 0x000028 (bcall dispatcher)
- RST 0x30 = 0x000030
- RST 0x38 = 0x000038 (ISR/system call)

The table at 0x000080 is jumped to from the RST 0x38 handler. It's the OS system service table. Each entry is a different system service.

For each of the 32 targets:
1. Read the first 32 bytes from the ROM binary directly
2. Decode as eZ80 instructions (use the existing decoder if possible, or manually decode common patterns)
3. Identify the function's purpose from its prologue pattern:
   - PUSH IY / LD IY,+3 → stack-frame syscall (most common)
   - LD A,imm / LD B,imm / RET → simple register-return service
   - JP addr → redirect/alias
   - CALL addr + complex setup → dispatcher
