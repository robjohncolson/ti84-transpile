# Task: Fix Port 0x03 GPIO Value for Key Dispatch

## Context

This is the TI-84 Plus CE ROM transpilation project. The OS ROM is lifted to JavaScript and runs in a browser shell. We've discovered that the key dispatch path is blocked by a GPIO port check at ROM address 0x0067F8.

## The Problem

The function at 0x0067F8 is a "system capabilities checker." It:
1. Loads a table pointer from 0x020000
2. Searches for a type-0x80C0 entry (finds it at ROM offset 0x020014)
3. Reads GPIO port 0x03 via `IN0 A,(0x03)`
4. ANDs with the first payload byte at ROM[0x020016] = 0x01
5. Compares against the second payload byte at ROM[0x020017] = 0x00
6. If `(port03 & 0x01) == 0x00` → returns HL=1 (success)
7. If `(port03 & 0x01) != 0x00` → returns HL=0 (fail)

Current emulation: port 0x03 defaults to `gpioValue ?? 0xef` in `peripherals.js`. The value 0xEF has bit 0 SET, so the check FAILS → HL=0 → caller falls through to DI+HALT.

## What to Do

1. In `TI-84_Plus_CE/peripherals.js`, change the default GPIO value so bit 0 is CLEAR. Change line ~264:
   ```
   readValue: normalizeValue(options.gpioValue ?? 0xef),
   ```
   to:
   ```
   readValue: normalizeValue(options.gpioValue ?? 0xee),
   ```
   This changes 0xEF (11101111) to 0xEE (11101110) — only bit 0 flipped to 0. All other bits stay the same.

2. Write a verification probe `TI-84_Plus_CE/probe-phase377-gpio-fix.mjs` that:
   - Boots through all 3 phases (Phase 1 at 0x000000 in z80 mode, Phase 2 at 0x08C331, Phase 3 at 0x0802B2)
   - Seeds flash signature at 0x020100 = [0x5A, 0xA5, 0x00]
   - Seeds system flag at 0xD177BA = 0x00
   - Injects key: mem[0xD00587] = 0x09 (ENTER), mem[0xD00080] |= 0x08
   - Runs the event loop from 0x003A73 with 1M steps
   - Tracks whether 0x0067F8 is reached and whether the function returns HL=1
   - Tracks whether execution passes BEYOND the old halt point at 0x001933/0x001937
   - Reports what new blocks are reached with the GPIO fix vs without
   - Runs TWO scenarios: (A) with gpioValue=0xEE (fixed), (B) with gpioValue=0xEF (current default, control)
   - Compares the two and prints which blocks are newly reachable

3. Run the golden regression to make sure nothing breaks:
   ```bash
   node TI-84_Plus_CE/probe-phase99d-home-verify.mjs
   ```

Use the EXACT boot pattern from `TI-84_Plus_CE/probe-phase375-both-seeds-test.mjs` as your template — it has the correct 3-phase boot, CPU snapshot/restore, peripheral rebuild, and event loop entry. Copy its structure.
