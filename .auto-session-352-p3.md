# Task: Verify Browser Shell Boot After GPIO Fix

## Context
Session 351 changed GPIO port 0x03 default from 0xFF to 0xEF (bit 4 cleared) in `TI-84_Plus_CE/peripherals.js`. This fixed the boot loop in probe-based testing. We need to verify the browser shell also benefits — its boot path may differ slightly from the probes.

## Deliverable
Create `TI-84_Plus_CE/probe-phase352-browser-shell-boot-verify.mjs` that:
1. Simulates what the browser shell does: boots from 0x000000 in z80 mode
2. Uses the SAME peripheral configuration the browser shell uses (check `browser-shell.html` for how it calls `createPeripheralBus` — it may use different options than the probes)
3. Runs for 5000 steps
4. Reports:
   - Does boot progress past 142 blocks? (session 351 reached 142 in 1000 steps)
   - Termination reason
   - Unique block count
   - Furthest PC reached
   - Any missing blocks encountered

Also:
5. Read `TI-84_Plus_CE/browser-shell.html` and check:
   - How does it configure `createPeripheralBus`? (look for the options object)
   - Does it pass `timerInterrupt: false`? Or is timer enabled?
   - Does it set `pllDelay`?
   - What mode does it boot in? (z80 or adl?)
   - Report any differences between the browser shell's boot config and the probe's config

## Reference Files
- `TI-84_Plus_CE/browser-shell.html` — the browser frontend; search for `createPeripheralBus` and `runFrom` calls
- `TI-84_Plus_CE/peripherals.js` — peripheral bus factory
- `TI-84_Plus_CE/probe-phase351-gpio-boot-fix.mjs` — template for probe structure

## Constraints
- Do NOT modify any existing files — only CREATE the new probe file
- The probe must be runnable with: `node TI-84_Plus_CE/probe-phase352-browser-shell-boot-verify.mjs`
- If browser-shell.html uses timer interrupts enabled, replicate that in the probe (even though it may cause different behavior)

## Success Criterion
The probe runs, reports whether the browser shell's boot configuration also benefits from the GPIO fix, and identifies any configuration differences that might cause divergent behavior. No crashes.
