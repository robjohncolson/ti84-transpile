# Auto-Session 221 P1: Trace callers of function containing 0x04E9FD

## Context

We are reverse-engineering the TI-84 Plus CE OS ROM (eZ80, 4MB at `TI-84_Plus_CE/ROM.rom`). Session 220 found that the D003E0 writer entry is at 0x04EE33, called from 0x04E9FD. The caller code at 0x04E9E0-0x04EA0D does:
- RST 0x20 → CP 0xFF (clamp A to 0xFE) → LD B,A → LD A,(0xD0058E) → LD C,A → LD A,B → CALL 0x051B2B → RET C → LD A,B → CALL 0x04EE33

BIT 3 in the value written to 0xD003E0 comes from whatever A value the caller's parent function receives. We need to trace UP the call chain to find who calls this function and what A value they pass.

## Task

Build a probe `TI-84_Plus_CE/probe-phase221-04e9fd-caller-trace.mjs` that:

1. **Find the function entry point**: Scan ROM backwards from 0x04E9E0 looking for a RET instruction (0xC9, or 0xED 0x45/0x4D for RETI/RETN). The byte before that RET is the end of the preceding function, and the byte after is our function's entry point. Also check for unconditional JP/JR that could be function boundaries.

2. **Static call-site scan**: Search the entire ROM (0x000000-0x3FFFFF) for:
   - `CD xx xx xx` (CALL addr) where addr matches the function entry point (3-byte little-endian, ADL mode)
   - `C3 xx xx xx` (JP addr) where addr matches the function entry point
   - `C2/CA/D2/DA/E2/EA/F2/FA xx xx xx` (conditional JP) where addr matches
   - `CC/C4/D4/DC/E4/EC/F4/FC xx xx xx` (conditional CALL) where addr matches
   Report all sites found with their ROM offsets and instruction bytes.

3. **Disassemble caller context**: For each call site found, disassemble 32 bytes before and 16 bytes after the call instruction using the eZ80 decoder (`ez80-decoder.js`). Report the full disassembly with addresses.

4. **Check pointer tables**: Search ROM for the 3-byte little-endian encoding of the entry point address. Report any hits that aren't already identified as CALL/JP instructions (these would be pointer table entries).

## Key constraint

The function entry point is UNKNOWN — that's what you're finding. Start scanning backwards from 0x04E9DF byte by byte. In eZ80 ADL mode, RET = 0xC9, RETI = 0xED 0x4D, RETN = 0xED 0x45. Also look for JP nn (0xC3 xx xx xx) or JR d (0x18 xx) as potential boundaries.
