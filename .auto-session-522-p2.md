# Task: Decode 0x09EF20 (LCD rectangle operation)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript blocks. You need to decode the function at ROM address 0x09EF20.

Session 521 identified that 0x09EF20 is called by 0x0A321D (edit-buffer scroll) with HL=0, DE=0x013F=319 (full LCD width). Understanding this completes the display scroll pipeline.

Related decoded functions:
- 0x0A321D = edit-buffer scroll: 26-col LDDR + space fill
- 0x0A3126 = display scroll: dual-layer pixel LDIR/LDDR at D40000 + text buffer at D006BF
- 0x09EF44 = VRAM fill (decoded in earlier sessions)

## Deliverable
Create a probe file at `TI-84_Plus_CE/probe-phase522-decode-09EF20-lcd-rect.mjs` that:
1. Reads the ROM binary directly (no boot needed for pure disassembly)
2. Disassembles the function at 0x09EF20 by reading ROM bytes and decoding eZ80 instructions
3. Follows the function until RET, tracking all branches
4. Also disassembles any subroutines called (1 level deep)
5. Reports:
   - Full instruction listing with addresses
   - The rectangle parameters: how HL, DE, BC map to x, y, width, height
   - Any LCD hardware port I/O (ports 0x0800-0x0FFF are LCD-related)
   - VRAM address calculations
   - Whether this draws, fills, or scrolls a rectangle

## Template
Base your probe on existing probes in the `TI-84_Plus_CE/` directory. Key patterns:
- `import fs from 'fs'` and `import path from 'path'`
- Read ROM: `const rom = new Uint8Array(fs.readFileSync(path.join(import.meta.dirname, 'ROM.rom')).buffer)`
- Decode eZ80 instructions manually by reading opcode bytes
- eZ80 is little-endian, 24-bit addresses. Common patterns:
  - LD rr,imm24 = 3-byte immediate loads
  - LDIR = block copy (HL→DE, BC bytes)
  - OUT (C),A / IN A,(C) = port I/O
  - MLT rr = 8×8 multiply (upper×lower of register pair)

## Constraints
- Do NOT modify any existing files
- Do NOT touch cpu-runtime.js, peripherals.js, browser-shell.html, or the transpiler
- The probe should be self-contained
- Focus on static disassembly — no boot/execution needed

## Success criterion
The probe runs without error and produces a clear disassembly of 0x09EF20 showing:
- Whether this is a rectangle draw, fill, clear, or scroll operation
- How the parameters (HL, DE) map to LCD coordinates
- Any VRAM address math (base D40000, stride 640 bytes = 320 pixels × 2 bytes/pixel)
- Port I/O if any
