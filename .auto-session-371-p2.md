# Task: Keypress Probe with Higher Loop Limit

## Context
Session 370's `probe-phase370-keypress-event-loop.mjs` showed that keypresses ARE detected (0x003A79 visited 255 times) but `maxLoopIterations:10` forces the scan loop to exit before key dispatch can process the scan code. The scan loop runs 13,260 full cycles and falls through to the idle path. The key insight: the scan code in A is lost because the loop is forcibly exited.

We need to try `maxLoopIterations:100000` (or higher) to let the scan loop complete naturally and trace the key dispatch path after `_GetCSC` returns a scan code.

## Deliverable
Create `TI-84_Plus_CE/probe-phase371-keypress-highloop.mjs` that:

1. **Boot phases 1-3** (identical to probe-phase370-keypress-event-loop.mjs):
   - Phase 1: `runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
   - Phase 2: `runFrom(0x08C331, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 })`
   - Phase 3: `runFrom(0x0802B2, 'adl', { maxSteps: 100, maxLoopIterations: 32 })`
   - Between phases: reset stack (`cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.sp = STACK_RESET_TOP - 3; mem.fill(0xFF, cpu.sp, cpu.sp + 3);`)
   - Phase 2 setup: set `cpu.mbase = 0xD0; cpu._iy = 0xD00080; cpu._hl = 0;`

2. **Event loop with ENTER key, HIGH loop limit**:
   - Reset event loop state: `cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.f = 0x40; cpu._ix = 0xD1A860; cpu._iy = 0xD00080; cpu.sp = STACK_RESET_TOP - 12; mem.fill(0xFF, cpu.sp, cpu.sp + 12);`
   - Reset keyboard: `keyMatrix.fill(0xFF); groupSelect = 0xFF;`
   - Set ENTER key: `keyboardState.keyMatrix[1] &= ~(1 << 0);` (scan code 0x10)
   - Run: `executor.runFrom(0x003A73, 'adl', { maxSteps: 500000, maxLoopIterations: 100000 })`

3. **Event loop with NO key, HIGH loop limit** (control comparison):
   - Same setup but no keypress (keyboard stays all 0xFF)
   - Run: `executor.runFrom(0x003A73, 'adl', { maxSteps: 500000, maxLoopIterations: 100000 })`

4. **Report for each phase**:
   - Total steps, termination reason, lastPc
   - Unique blocks discovered
   - NEW blocks vs cold-boot baseline (phases 1-3)
   - Top 30 hottest blocks
   - Visit counts for watched addresses: `0x001713, 0x001933, 0x001853, 0x000721, 0x003A77` (key detect block)
   - Missing blocks
   - Loops forced count

5. **Comparison summary**: Compare ENTER vs no-key — do they reach different blocks? Does the ENTER key path proceed further into dispatch?

## Key constants
- `STACK_RESET_TOP = 0xD1A87E` (check probe-phase370-keypress-event-loop.mjs line 13 — it may use 0xD1A87E or 0xD1A87B)
- Event loop entry: `0x003A73`
- Key detect block: `0x003A77`, instruction at `0x003A79`
- Peripherals: `createPeripheralBus({ pllDelay: 2, timerInterrupt: false })`
