# Auto-Session 335 — Priority 3: Investigate cxMain Initialization

## Context
The TI-84 Plus CE OS stores the "current context main handler" pointer at RAM address 0xD007CA (called cxMain). After our staged boot sequence, this is NULL (0x000000). The real OS boot must set it to the home-screen handler (believed to be around 0x058241). Finding where cxMain gets populated is key to making the event loop dispatch to the correct app handler.

Session 334 confirmed the OS event loop is at 0x08BF22. The event loop likely reads cxMain to decide which app handler to call for key events.

## Task
Write a probe `TI-84_Plus_CE/probe-phase335-cxmain.mjs` that:

1. Boots using the standard staged-boot pattern (see `probe-phase334-event-loop.mjs` for reference)
2. Instruments writes to 0xD007CA (3 bytes, since it's a 24-bit pointer). Log every write: the PC that wrote it, and the value written.
3. Runs the full boot sequence from 0x000000 with a generous step limit (~500000 steps) to see if cxMain ever gets set during normal boot
4. If cxMain remains NULL after boot, search the ROM for references to 0xD007CA:
   - Disassemble/scan for `LD (0xD007CA),` patterns — look for the bytes CA 07 D0 in the ROM (little-endian address)
   - Report all ROM locations that reference this address
5. For each reference found, classify it: is it a read or a write? What function is it in? What value does it write?
6. Specifically check if 0x058241 appears as a value being written to 0xD007CA — that would confirm it's the home-screen handler

## Technical Details
- To instrument memory writes: the cpu-runtime.js `write8/write16/write24` functions handle all writes. You can wrap write24 or monitor the specific address.
- Address 0xD007CA is 3 bytes (24-bit eZ80 pointer). The OS likely writes it with a 24-bit store instruction like `LD (nn),HL` where nn=0xD007CA.
- To search ROM bytes: read ROM.rom as a Buffer and search for byte pattern CA 07 D0 (little-endian encoding of 0xD007CA)
- Import pattern: `import { createCPU } from './cpu-runtime.js'` etc.
- Use `createPeripheralBus({ timerInterrupt: false })`
