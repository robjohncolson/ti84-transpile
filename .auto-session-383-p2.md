# Session 383 P2: Model SPI LCD ports 0xD018 and 0xD008 in peripherals.js

## Context
Session 382 identified the TI-84 CE LCD controller as an ST7789V, communicating via SPI bit-banging through these ports:
- **0xD018** — SPI command register (528 writes during boot)
- **0xD008** — SPI data register (352 writes during boot)
- **0xD00D** — SPI busy status (174 reads during boot) — ALREADY registered (returns 0x00)
- **0xD00C** — SPI read-back (174 reads during boot) — ALREADY registered (returns 0x02)

Ports 0xD018 and 0xD008 are NOT registered in peripherals.js. They currently return 0xFF (the default for unregistered ports), which may cause issues. They need simple read/write store handlers.

## Task
1. Read `TI-84_Plus_CE/peripherals.js` to understand the port registration pattern
2. Add handlers for ports 0xD018 and 0xD008 near the existing 0xD00C/0xD00D handlers (around line 552)
3. Use the same simple pattern as the backlight ports (lines 642-648):
   ```js
   register(0xD018, {
     read() { return state.spiLcd.command; },
     write(port, value) { state.spiLcd.command = value; },
   });
   register(0xD008, {
     read() { return state.spiLcd.data; },
     write(port, value) { state.spiLcd.data = value; },
   });
   ```
4. Add `spiLcd: { command: 0x00, data: 0x00 }` to the `state` object initialization (around line 287, after `csBase`)
5. Also add `spiLcd` to the `getState()` return (around line 359, after `keyboardController`)
6. Run the golden regression to verify no breakage: `node TI-84_Plus_CE/probe-phase99d-home-verify.mjs`
