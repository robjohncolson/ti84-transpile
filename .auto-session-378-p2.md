# Task: Find the OS Scan Code Lookup Table (0x29 for ENTER)

## Context
Session 377 discovered that the natural keyboard scan at 0x003C63 produces OS scan code **0x29** for ENTER, not the raw matrix code 0x09 or the positional code 0x10 ((group<<4)|bit). This means there's a lookup table somewhere in ROM that maps (group, bit) → OS scan code. The keyboard-matrix.md documents the matrix positions but not the OS-internal scan codes.

The scan routine at 0x003C63:
- Reads keyboard ports 0xA000-0xA01E (8 groups)
- Detects which group has a keypress
- Detects which bit in that group is pressed
- **Somewhere** translates (group, bit) → OS scan code
- Writes the scan code to 0xD00587

ENTER is in group 1 (port 0xA014), bit 0. The raw matrix value is 0x10 = (1<<4)|0. But the OS stores 0x29 at 0xD00587.

## Deliverable
Create `TI-84_Plus_CE/probe-phase378-scancode-table.mjs` that:

1. **Static ROM scan for the lookup table**: Search ROM bytes for the scan code table. The table likely has 56 entries (7 groups × 8 bits, or 8 groups × 8 bits = 64). Look for:
   - A region where byte at offset corresponding to group 1, bit 0 = 0x29
   - Known TI-84 CE scan codes: ENTER=0x09 in SDK docs, but OS may use different internal codes
   - The table is likely within the 0x003C63-0x003E00 region or nearby
   - Search for 0x29 appearing at regular intervals in potential table regions

2. **Dynamic trace approach**: Boot through phases 1-3, set ENTER key in matrix, run the event loop, and trace exactly which ROM address is read to produce the 0x29 value. Hook memory reads in the 0x003C63-0x003D60 region during execution to find the table access.

3. **If table found**: Dump all entries (group 0-7, bit 0-7 → scan code). Map at least these keys:
   - ENTER (group 1, bit 0) → expected 0x29
   - CLEAR (group 6, bit 6) → ?
   - 2ND (group 1, bit 5) → ?
   - ALPHA (group 2, bit 7) → ?
   - Y= (group 3, bit 4) → ?

4. **Report the table's ROM address** and format.
