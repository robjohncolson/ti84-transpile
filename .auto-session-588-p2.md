# Task: Decode 0x09D49A — NZ Branch from Type-0x5F Validator

## Context
0x09D454 is the TYPE-0x5F SEARCH KEY VALIDATOR (31B, decoded session 587). When the search key type at D005F9 is NOT 0x5F, it takes JR NZ to 0x09D49A. Since 0x0843B3 writes type 0x72 to D005F9 before calling 0x09D454, the CP 0x5F test ALWAYS fails for type-0x72 → JR 0x09D49A. So 0x09D49A is the ACTUAL code path for type-0x72 lookups.

## Deliverable
Create `TI-84_Plus_CE/probe-phase588-decode-09D49A.mjs` that:
1. Reads `TI-84_Plus_CE/ROM.rom` (path relative to repo root)
2. Disassembles starting at 0x09D49A for up to 300 bytes
3. Follows all branch/call targets within the function
4. Identifies all RAM references (0xD00000-0xD3FFFF range), IY-relative refs, port I/O
5. Cross-references all CALL targets and JP targets
6. Prints a formatted disassembly with hex addresses, raw bytes, and mnemonics
7. Prints a summary: function boundaries, purpose hypothesis, all call targets, all RAM refs

## Decoder API
Use a HAND-ROLLED inline decoder. Do NOT import from ez80-decoder.js. The working pattern:
- `const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');`
- Read bytes directly: `rom[offset]`, `rom[offset] | (rom[offset+1] << 8)` for 16-bit, add `| (rom[offset+2] << 16)` for 24-bit
- Handle eZ80 prefixes: 0xDD=IX, 0xFD=IY, 0xED=extended, 0xCB=bit ops
- Handle .SIS prefix 0x40 (forces 16-bit operands in ADL mode)
- Key opcodes:
  - 0xFE = CP n (immediate compare), NOT a prefix
  - 0xCD = CALL nn (3-byte address in ADL mode)
  - 0xC3 = JP nn, 0x18 = JR d, 0x20/0x28/0x30/0x38 = JR cc,d
  - 0xC9 = RET
  - 0x3E = LD A,n
  - 0xED prefix for block ops and IN/OUT

## Known context
- 0x09D454: TYPE-0x5F validator (31B). CP 0x5F at start, JR NZ → 0x09D49A
- 0x09D50D: another branch target from 0x09D454 (subfield/mode mismatch)
- Called from 0x0843B3 (type-0x72 lookup setup) which also calls 0x0992C3
- D005F9 = search key type, D005FA = subfield, D007E0 = mode byte

## Constraints
- Do NOT modify any existing files
- Do NOT import from ez80-decoder.js
- ROM path is 'TI-84_Plus_CE/ROM.rom' (relative to repo root)
- Run via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase588-decode-09D49A.mjs`
- NEVER run bare `node TI-84_Plus_CE/probe-*.mjs`

## Success criterion
Probe runs via watchdog (exit 0), prints full disassembly of 0x09D49A and its continuation, identifies function boundaries, all CALL/JP targets, RAM refs, and provides a hypothesis about what this type≠0x5F code path does.
