# Task: Map D14085-D14089 — Callback State Group Co-Accessed with D14075

## Context
The TI-84 Plus CE ROM transpilation project traced D14075 as a USB callback-pending flag (6 refs). D14085 appeared at 4/6 D14075 sites (67% co-access rate). D14089 appeared at teardown sites. We need to trace ALL references to D14085, D14086, D14087, D14088, and D14089 to map this callback state group.

## What to do

1. **Create a probe script** `TI-84_Plus_CE/probe-phase442-trace-D14085.mjs` that:
   - Loads the ROM from `TI-84_Plus_CE/ROM.rom` (4MB, raw binary)
   - Scans ALL 4MB for any instruction that reads or writes addresses D14085, D14086, D14087, D14088, or D14089
   - For eZ80 memory access patterns, search for these byte sequences (little-endian 3-byte addresses):
     - `85 40 D1` for D14085
     - `86 40 D1` for D14086
     - `87 40 D1` for D14087
     - `88 40 D1` for D14088
     - `89 40 D1` for D14089
   - For each reference found, extract:
     - ROM address of the instruction
     - The instruction type (read/write) — look at the opcode before the address bytes
     - Which of the 5 addresses is referenced
     - Surrounding context (8 bytes before and after)
     - What other D140xx addresses are accessed within ±40 bytes (co-access pattern)
     - The containing function (scan backward for prologues)

2. **Create a report** `TI-84_Plus_CE/phase442-trace-D14085-report.md` with:
   - Per-address reference counts (D14085 through D14089)
   - Read vs write breakdown for each
   - Value analysis: boolean (0x00/0x01) or multi-value?
   - Co-access matrix: which bytes appear together?
   - Containing functions list
   - Group assessment: what is this 5-byte block? Callback function pointer (3 bytes for eZ80 address)? Callback argument? State flags?

## Reference files
- `TI-84_Plus_CE/probe-phase441-trace-D14075.mjs` — probe for D14075 which co-accesses this group, use as template
- `TI-84_Plus_CE/ROM.rom` — the 4MB ROM file to scan

## Known facts
- D14085 co-accessed with D14075 (callback-pending) at 4/6 sites = 67%
- D14089 co-accessed at teardown (0x0085B5 + mirror 0x04984D)
- D14075's read sites at 0x009ACF (mirror 0x0494C0) are in USB event loop function 0x0094C4
- D14075's read uses OR A → JR NZ gate pattern, co-reading D14044/D14082/D14085
- In eZ80, a 24-bit function pointer needs 3 bytes — D14085/D14086/D14087 could be a callback address
