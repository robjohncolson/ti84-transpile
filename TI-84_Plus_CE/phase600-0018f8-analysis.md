## Interpretation

The sequence at 0x001881 sets up a massive LDIR clear:
1. LD HL, 0xD00000 (source/first byte)
2. LD DE, 0xD00001 (destination = source + 1)
3. LD BC, 0x013FD7 (length = 81,879 bytes)
4. LD (HL), 0x00 (seed the first byte with zero)
5. LDIR (copy forward: each byte copies the zero from the previous byte)

This zeroes the entire range D00000-D13FD7 (~82KB), which includes:
- D007CA (cxMain dispatch vector)
- D0231A (edit cursor descriptor)
- D0243A (edit cursor descriptor)
- D0058C/D0058E (key scan code / translated key)

A second clear at 0x001891 targets D1787C-D19880 (VRAM area, 0x2001 = 8193 bytes).
A third sequence at 0x0018A1 targets D3FEFF-D3FFFF (high RAM, 255 bytes, written downward via LDIR from FF end).

- XOR A; LD (0xD177B7),A -- clears a flag byte
- LD A,0x95; LD (0xD0058F),A -- sets a status byte

The 0x0019BE "wipe trap" is the start of a new function that re-runs the full init (192K steps).
