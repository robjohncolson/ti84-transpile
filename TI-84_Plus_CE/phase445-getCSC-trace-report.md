## Analysis

### _GetCSC (0x003D5A) — High-level flow

1. **LD B, 0x34** — Load debounce counter (52 iterations)
2. **BIT 3, (IY+0x00)** — Test "key ready" flag in IY system flags
3. If flag SET (key ready):
   - Jump to 0x003D75: read scan code from D00587, clear it, clear flag, return
4. If flag CLEAR (no key):
   - CALL 0x003C63 (scan dispatcher — performs one hardware scan)
   - Delay loop: LD BC, 0x000800; DEC BC; loop until BC=0
   - DJNZ back to step 2 (repeat up to 52 times)
   - If all 52 iterations pass with no key: XOR A (return 0)

### Hardware scan routine (0x003CC0-0x003D59)

The hardware scan reads the keyboard via **I/O ports** (not MMIO):

#### Port usage (B=0xA0, port address = B:C = 0xA0xx):
- **Port 0xA000 (C=0x00):** keyboard controller enable/mode
- **Port 0xA008 (C=0x08):** keyboard data register (IN/OUT for scan-all)
- **Port 0xA00C (C=0x0C):** keyboard group/mode select
- **Ports 0xA012-0xA01E (C=0x12-0x1E, step 2):** individual group scan ports
  - Group scan starts at C=0x10, increments by 2 each iteration

- **Initialization (0x003CC6-0x003CF8):**
  1. .SIS LD BC, 0xA000 — B=0xA0 (port base), C=0x00
  2. LD A, 0x01; OUT (C), A — write 0x01 to port 0xA000 (enable)
  3. CP 0xA0 — verify B is still 0xA0 (RST 0x08 = error if not)
  4. C=0x0C; LD A, 0x04; OUT (C), A — write 0x04 to port 0xA00C (mode)
  5. C=0x08; .SIS LD HL, 0xFF00; OUT (C), H — write 0xFF to port 0xA008 (scan all groups)
  6. Wait: CP 0x08 loop on C until C=0x08 (port ready check)
  7. XOR A; IN A, (C) — read port 0xA008; RET Z if 0 (no keys pressed)

- **Single-group re-scan (0x003CF7-0x003D20):**
  1. C=0x00; LD A, 0x03; OUT (C), A — write 0x03 to port 0xA000 (scan mode)
  2. C=0x0C; LD A, 0x01; OUT (C), A — write 0x01 to port 0xA00C
  3. C=0x08; OUT (C), H; IN A, (C) loop — scan + wait
  4. C=0x00; XOR A; OUT (C), A — write 0x00 to port 0xA000 (reset)

- **Group scan loop (0x003D21-0x003D33):**
  1. D=8 (7 groups to scan + 1 for exit), C=0x10 (base scan port)
  2. DEC D; if D=0 → done (jump to 0x003D34)
  3. INC C; INC C — advance port by 2 (groups at ports 0xA012-0xA01E)
  4. IN E, (C) — read group bits into E
  5. If E=0 (no key in group) → JR back to step 2
  6. INC H — increment group counter (first found key)
  7. If H≠0 (second key found): JR to 0x003D47 → SCF; A=0xFF; RET (multi-key rejection)
  8. ADD HL, DE — accumulate key bits
  9. JR back to step 2 — continue scanning remaining groups

- **Bit extraction + scan code computation (0x003D34-0x003D4A):**
  1. OR L — if L=0, RET Z (no key bits found)
  2. LD A, H; DEC A — A = group counter - 1
  3. BIT 0, (IY+0x2C) — check modifier flag
  4. If set: RET NZ (return with carry clear = modifier handled separately)
  5. RLA; RLA; RLA — A = (group-1) * 8
  6. Loop at 0x003D40: INC A; RR L; JR NC → loop
     - Rotates L right through carry, incrementing A each time
     - When carry is set, the lowest set bit in L was found
     - A = (group-1)*8 + bit_position + 1 = OS scan code
  7. CCF; RET Z — complement carry; if was single-bit, return with A=scan code
  8. 0x003D47: SCF; LD A, 0xFF; RET — multi-key or error: return 0xFF with carry set

- **Store result (0x003D4B-0x003D59):**
  1. LD (D00587), A — store OS scan code
  2. SET 3, (IY+0x00) — set "key ready" flag
  3. OR A; RET Z — if scan code is 0, just return
  4. LD (D0058D), A — store to "last key" location
  5. RET

### Return value

- **A = OS scan code** (0x01-0x38, or 0x00 for no key)
- OS scan codes use the formula: (6 - group) * 8 + bit + 1
- The scan loop iterates groups in reverse (group 6 first → lowest codes)

### Debounce mechanism (0x003C63)

The scan dispatcher at 0x003C63 implements debounce:
1. Calls hardware scan (0x003CC2) which returns carry+A if key found
2. If carry set (key found):
   - Compares new key (A) with D00589 (last debounced key)
   - If different: stores to D00589, resets repeat delay to 5
   - If same: checks D00588 (previous key match)
     - If matches AND non-zero: checks if key is 0x38 (special)
     - Decrements D0058A (debounce timer)
     - When timer reaches 0: reloads to 10 (0x0A) and stores via 0x003D4B
3. Implements key-repeat: after initial delay, auto-repeats at rate 10

### Calling convention

- **Input:** None
- **Output:** A = OS scan code (0 = no key)
- **Flags:** Z set if no key, NZ if key found
- **Destroys:** A, B, C, D, E, H, L, flags
- **Preserves:** IY (system flags pointer)

### Does it write to D141B5?

No. _GetCSC does NOT write to D141B5. It writes scan codes to:
- D00587 (primary scan code location)
- D0058D (last non-zero key backup)
D141B5 is likely written by a higher-level key processing routine.
