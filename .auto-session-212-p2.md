# Auto-Session 212 — P2: What sets BIT 4,(IY+5) in the ROM?

## Context

Session 211 confirmed that BIT 4,(IY+5) at address 0xD00085 is the gate that routes digit tokens to BufInsert. When BIT 4 is SET, ConvKeyToTok at 0x05E630 routes through 0x05E6A4 → BufInsert. When CLEAR, it takes an alternate path. We need to find what instructions in the ROM SET this bit — this tells us what "edit mode active" means and when it's armed.

## Task

Create a probe `TI-84_Plus_CE/probe-phase212-bit4-iy5-setters.mjs` that does a static binary scan of ROM.rom to find ALL instructions that SET or RES bit 4 of (IY+5).

## eZ80 instruction encoding

IY-indexed CB-prefix bit operations in eZ80:
- `SET 4,(IY+d)` = FD CB dd E6 (where dd = displacement = 0x05)
- `RES 4,(IY+d)` = FD CB dd A6 (where dd = displacement = 0x05)
- `BIT 4,(IY+d)` = FD CB dd 66 (where dd = displacement = 0x05, for reference)

So scan ROM.rom for:
- SET 4,(IY+5): bytes FD CB 05 E6
- RES 4,(IY+5): bytes FD CB 05 A6
- BIT 4,(IY+5): bytes FD CB 05 66 (for context — these are the testers)

## Implementation

1. Read ROM.rom as a Buffer
2. Scan for all occurrences of each 4-byte pattern
3. For each match, record the ROM address
4. Try to identify what region each address is in (using rough boundaries):
   - 0x000000-0x00FFFF: Boot/reset vectors
   - 0x010000-0x04FFFF: OS core/services
   - 0x050000-0x06FFFF: cxMain/editor/keyboard
   - 0x070000-0x08FFFF: FP/math/display
   - 0x090000-0x0AFFFF: STAT/apps/upper OS
5. For each SET/RES match, read the surrounding 16 bytes before and 16 bytes after and disassemble the context (or just hex dump if disassembly is complex)
6. Report a summary:
   - All SET 4,(IY+5) addresses with region labels
   - All RES 4,(IY+5) addresses with region labels
   - All BIT 4,(IY+5) addresses with region labels (the testers)

## Key question to answer

Which ROM routines arm "edit mode" (SET bit 4) and which disarm it (RES bit 4)? The SET sites tell us the entry points into edit mode. The RES sites tell us the exit points.
