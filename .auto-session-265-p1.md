# Task: Investigate D007E0 write sites for non-STAT contexts (priority 13ccc)

## Context
In the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, we've established that IY+9 bit 0 (SET at 0x09C775) is STAT-specific. But D007E0 is the OS "context/mode ID" variable used on the home screen (D007E0=0x00), in graph mode (D007E0=0x40), and other contexts. We need to find how D007E0 gets written for NON-STAT contexts.

## Task
1. Create a probe file `TI-84_Plus_CE/probe-phase265-d007e0-write-sites.mjs` that:
   a. Reads the ROM binary from `TI-84_Plus_CE/ROM.rom` (4MB, little-endian eZ80)
   b. Scans the entire ROM for ALL `LD (D007E0),A` instructions. In eZ80 ADL mode, this is the byte sequence `32 E0 07 D0` (LD (addr),A with 3-byte address). Also check for the `ED 39 xx E0 07 D0` pattern (LD (addr),rr variants) though less likely for single-byte writes.
   c. For each site found, print the address, the preceding 16 bytes (for context on what A contains), and the following 8 bytes.
   d. Also scan for `ED` prefix stores to D007E0 (ED 43/53/63/73 with address E0 07 D0).
   e. Classify each site: is it inside the 0x09xxxx STAT region, 0x04xxxx OS core, 0x05xxxx editor, 0x06xxxx graph, 0x08xxxx display, or other?

2. Additionally, dynamically test 3-5 of the non-STAT write sites by running them in the transpiled JS environment:
   - Load the transpiled ROM: `const { createCPU } = require('./cpu-runtime.js');` and `const { createPeripheralBus } = require('./peripherals.js');`
   - Create CPU with timer disabled: `const bus = createPeripheralBus({ timerInterrupt: false }); const cpu = createCPU(bus);`
   - Load ROM: `const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom'); cpu.loadROM(rom);`
   - Load transpiled code: `require('./ROM.transpiled.js')(cpu);`
   - Set IX=0xD1A860, SP=0xD1A860 (standard init values)
   - For each site: set PC to the write instruction address, run for 50-200 steps, check what value D007E0 received.
