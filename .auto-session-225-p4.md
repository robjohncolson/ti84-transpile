# Task: End-to-end 2-byte token insertion via D0059F=0xFC + ConvKeyToTok

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 binary). The transpiled JS is generated by `scripts/transpile-ti84-rom.mjs` and the runtime is in `TI-84_Plus_CE/cpu-runtime.js`.

We've decoded the full token table architecture:
- ConvKeyToTok at 0x05E630 calls KeyClassifier at 0x05C52C as its FIRST instruction
- KeyClassifier uses magic A values for secondary tables: 0xFA=AlphaLock, 0xFB=Alpha, 0xFC=2nd, 0xFE=Fn
- When A is a magic value, the REAL key code is loaded from memory at **D0058E**
- D0059F is the key state variable that the primary ConvKeyToTok caller (0x04EA26) loads into A

Session 223 verified that A=0xFC + D0058E=0x76 (LOG key) → DE=0x6228 (correct 2nd-mode token for LOG = "10^"). But that was testing the classifier alone. We need to test the FULL insertion path:
1. Set D0059F = 0xFC (2nd mode)
2. Set D0058E = key code
3. Arm edit mode: BIT 4,(IY+5) SET, editCursor=0xD00A00, editTail=0xD00B00
4. Call ConvKeyToTok at 0x05E630 (which reads A from caller context)
5. Verify: correct 2-byte token written to edit buffer at 0xD00A00

## Your Task
Build a probe `TI-84_Plus_CE/probe-phase225-2byte-e2e.mjs` that:

1. **Boot the CPU**: z80 boot (0x000200), kernelInit (0x000324), memInit (0x020814). Use `createPeripheralBus({ timerInterrupt: false })`.

2. **Set up edit mode context**:
   - IY+5 bit 4 SET: `cpu.mem[0xD00085] |= 0x10` (IY=0xD00080, offset 5)
   - editTop (0xD02437) = 0xD00A00
   - editCursor (0xD0243A) = 0xD00A00
   - editTail (0xD0243D) = 0xD00B00
   - editBtm (0xD02440) = 0xD00B00
   - Zero edit buffer: fill 0xD00A00-0xD00AFF with 0x00

3. **Test 2nd-mode tokens (A=0xFC via D0059F)**:
   Test these key codes in D0058E with A=0xFC (loaded from D0059F by the caller, but we set A directly at entry to ConvKeyToTok):
   - 0x76 (LOG → expected 2nd token: 10^, DE=0x6228 from session 223)
   - 0x69 (COS → expected 2nd token: cos⁻¹)
   - 0x5B (x⁻¹ → expected 2nd token)
   
   For each test:
   - Write key code to D0058E
   - Set A = 0xFC
   - Call 0x05E630 (ConvKeyToTok)
   - Run for 200 steps
   - Read edit buffer at 0xD00A00 (should have 2-byte token)
   - Read cursor position at 0xD0243A (should advance by 2)
   - Reset cursor and buffer between tests

4. **Test Fn-mode tokens (A=0xFE)**:
   - D0058E=0x76 (LOG → expected Fn token: DE=0x7E0D from session 223)
   - D0058E=0x33 (another key)
   
5. **Test Alpha-mode (A=0xFB)**:
   - D0058E=0x76 → expected DE=0xEF5B from session 223
   
6. **Compare with primary table (A=0x8F, digit '1')**:
   - Should produce 1-byte token 0x31 as baseline
