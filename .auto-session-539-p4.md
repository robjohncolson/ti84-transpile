# Task: Decode 0x07FAC2 — Zero OP1 Handler

## Context
0x07FAC2 is a heavily referenced "zero OP1" handler in the TI-84 Plus CE FPU. Known callers:
- 0x07FF03: `JP Z,0x07FAC2` when OP1 mantissa is zero
- 0x07C9BD (normalization loop): `JP Z,0x07FAC2` overflow → zero OP1
- 0x07C9D0 (exponent adjust): `JP C,0x07FAC2` underflow → zero
- 0x07CA5D area: `JR 0x07CAA1 → JP 0x07FAC2` out-of-range → reinitialize as zero BCD
- 0x07CAA0: `POP BC; JP 0x07FAC2` alternate exit with stack cleanup
- 0x07DF66 area (BCD division post-loop): `CALL 0x07F8FA + 0x07FAC2` 
- Known from BCD division context

This function appears to zero-out OP1 (set mantissa to all zeros, possibly set exponent to 0x80 or 0x00). It's called whenever an FP operation detects underflow, overflow, or zero result.

## Task
Write a probe script that reads raw ROM bytes starting at 0x07FAC2 and disassembles them. The function likely:
- Clears D005FA through D00602 (9 mantissa bytes of OP1)
- May set D005F9 (exponent) to 0x00 or 0x80
- May set D005F8 (type/sign) to 0x00
- Ends with RET

Check nearby context: 0x07FAE7 is at offset +37 from 0x07FAC2 and is "generic B-count zero fill" (5B). 0x07FADB is at offset +25 and is "clear 3 bytes at D0060E". So 0x07FAC2 through 0x07FAE6 is the region of interest (~37 bytes).
