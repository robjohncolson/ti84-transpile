# Task: Trace D141E6 Config/Mode Source — Who Writes This RAM Address?

## Context

## What We Know
- D141E6 is a config/mode source byte in RAM.
- It is read 4 times by 0x00DE8B (the 232-byte post-bootstrap field initializer at 0x00DE8B-0x00DF72).
- In 0x00DE8B, D141E6 is shifted left 4 bits and OR'd with bit 6 to produce the descriptor +5 mode byte.
- D141E6's source is unknown — likely set during USB enumeration or Link setup.
- The ROM is 4MB (0x000000-0x3FFFFF). All code is in the ROM image.

## Deliverables
1. Create `TI-84_Plus_CE/probe-phase429-trace-D141E6.mjs` — a Node.js probe that:
   - Reads the entire ROM binary
   - Scans all 4MB for any instruction that writes to absolute address 0xD141E6
   - This means scanning for patterns like:
     - `LD (0xD141E6), A` — opcode pattern for store-A-to-absolute-24bit
     - `LD (0xD141E6), HL` or similar multi-byte stores
     - Any indirect store via a register that could point to D141E6
   - For eZ80 ADL mode, the absolute address encoding is 3 bytes little-endian: E6 41 D1
   - Search the raw ROM bytes for the byte sequence E6 41 D1 (little-endian encoding of 0xD141E6)
   - For each match, decode the instruction at that address to confirm it's a write (not a read or immediate)
   - Also search for D141E5 and D141E7 (adjacent bytes) to find block writes
   - Print all writer sites with: address, full instruction, surrounding context (a few instructions before/after)

   - Assessment: when is D141E6 set? During boot? During USB enumeration? During Link setup?
   - What value(s) get written to D141E6?

## Approach
The simplest approach: scan all 4,194,304 bytes for the 3-byte sequence E6 41 D1. For each occurrence, look at the opcode byte(s) before it to determine if it's a write instruction (LD (nn), A = 0x32 E6 41 D1; LD (nn), HL = 0x22 E6 41 D1; etc.) or a read instruction (LD A, (nn) = 0x3A E6 41 D1; LD HL, (nn) = 0x2A E6 41 D1; etc.) or something else (immediate data, etc.).
