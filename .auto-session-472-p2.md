# Task: Find Who Writes D00824 in the TI-84 CE ROM

## Context

You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`.

Session 471 discovered that at address 0x02FFAE, the FIRST instruction is `LD A,(D00824)` which OVERWRITES register A with the D00824 content. This means the translated key code in A is lost — D00824 must be set BEFORE entering 0x02FFAE. We need to find which ROM code writes to D00824.

## Deliverable

Create a NEW file: `TI-84_Plus_CE/probe-phase472-d00824-writers.mjs`

This probe should:

### 1. Search ROM binary for writes to D00824

The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB, loaded at address 0x000000).

Search for these byte patterns in the ROM:
- `32 24 08 D0` — LD (0xD00824),A (z80/adl encoding)
- `ED 53 24 08 D0` — LD (0xD00824),DE (extended)
- `ED 43 24 08 D0` — LD (0xD00824),BC (extended)
- `ED 63 24 08 D0` — LD (0xD00824),HL (extended)
- `22 24 08 D0` — LD (0xD00824),HL (non-prefix)
- Also search for `24 08 D0` as a 3-byte address subsequence and filter for store-type opcodes preceding it

### 2. Also search the transpiled code

Read `TI-84_Plus_CE/ROM.transpiled.js` (decompress from .gz first if needed — actually it may already exist uncompressed). Search for references to address `0xD00824` or decimal `13632548` in the transpiled JS. Look for patterns like:
- `mem[0xD00824]` or `mem[13632548]`
- `write8(0xD00824` or `write8(13632548`
- `D00824` in any form

Actually, the transpiled JS is ~214MB and may not be practical to search directly. Instead:

### 3. Use ROM binary search approach

```js

import path from 'path';

// Target address bytes: D00824 in little-endian = 24 08 D0
// But for LD (nn),A the format is: opcode + addr_low + addr_mid + addr_high
// In eZ80 ADL mode: LD (0xD00824),A = 0x32 0x24 0x08 0xD0

const patterns = [
  { name: 'LD (D00824),A', bytes: [0x32, 0x24, 0x08, 0xD0] },
  { name: 'LD (D00824),HL [22]', bytes: [0x22, 0x24, 0x08, 0xD0] },
  { name: 'LD (D00824),HL [ED 63]', bytes: [0xED, 0x63, 0x24, 0x08, 0xD0] },
  { name: 'LD (D00824),DE [ED 53]', bytes: [0xED, 0x53, 0x24, 0x08, 0xD0] },
  { name: 'LD (D00824),BC [ED 43]', bytes: [0xED, 0x43, 0x24, 0x08, 0xD0] },
  { name: 'LD (D00824),SP [ED 73]', bytes: [0xED, 0x73, 0x24, 0x08, 0xD0] },
  { name: 'LD (D00824),IX [DD 22]', bytes: [0xDD, 0x22, 0x24, 0x08, 0xD0] },
  { name: 'LD (D00824),IY [FD 22]', bytes: [0xFD, 0x22, 0x24, 0x08, 0xD0] },

// Also search for any 3-byte address 24 08 D0 to catch indirect writes
```

For each match, report:
- ROM address where the pattern was found
- The preceding 4 bytes (context)
- The following 4 bytes (context)
- A label like "potential LD (D00824),A at 0x0302EB"

### 4. Also search for IY-relative writes

D00824 = D00080 + 0x7A4 — BUT IY-relative only works for offsets 0-127 (signed byte), so 0x7A4 is too large. Skip IY-relative.

However, code might compute the address differently:
- LD HL, 0xD00824; LD (HL), A — search for `21 24 08 D0` (LD HL, 0xD00824)
- LD DE, 0xD00824 — search for `11 24 08 D0`
- LD BC, 0xD00824 — search for `01 24 08 D0`

Add these to the pattern list too.

### 5. Output format

Print all matches sorted by ROM address. For each, print:
```
[match] <pattern_name> at 0x<addr>  context: <hex bytes before> [MATCH] <hex bytes after>
```

At the end, print a summary count of total matches per pattern.
