## Key question
The inline case dispatcher likely works like this:
1. Caller does `CALL 0x00211B`
2. The dispatcher pops the return address from the stack — this points to the inline table
3. It reads a case count byte (or scans for a sentinel)
4. It compares A (the selector value) against each case byte
5. On match, it jumps to the 3-byte target address
6. On no match, it advances past the table and returns to the code after the table

This is a common eZ80/Z80 pattern. Verify this hypothesis against the actual bytes at 0x00211B.
