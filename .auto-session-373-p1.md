# Task: Disassemble 0x003C63 Keyboard Scan Subroutine

## Context
You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`.

The OS function `_GetCSC` lives at 0x003D5A. It calls 0x003C63 to scan the keyboard matrix. 0x003C63 reads physical keyboard ports 0xA000-0xA014. We need to understand what 0x003C63 does with the scan result — specifically, does it write the scan code to 0xD00587? Does it set bit 3 of 0xD00080?

## What to do
Write a Node.js probe at `TI-84_Plus_CE/probe-phase373-disasm-003C63.mjs` that:

1. Loads the ROM from `TI-84_Plus_CE/ROM.rom` (4MB file)
2. Imports the eZ80 decoder from `TI-84_Plus_CE/ez80-decoder.js`
3. Disassembles the region 0x003C63 through 0x003D59 (the full keyboard scan subroutine, up to where _GetCSC starts)
4. For each instruction, print: address (hex), raw bytes (hex), mnemonic, operands
5. Specifically flag any instructions that:
   - Write to memory addresses 0xD00080-0xD000FF (IY-relative writes where IY=0xD00080)
   - Write to memory address 0xD00587 (the scan code storage location)
   - Read from ports 0xA000-0xA014 (keyboard matrix ports)
   - Do any `BIT`, `SET`, or `RES` instructions on IY-relative offsets
6. After the static disassembly, run a DYNAMIC trace:
   - Boot the OS through phases 1-3 using the standard 4-phase boot pattern (see existing probe files for the pattern)
   - In the event loop phase, intercept calls to 0x003C63 and log all memory writes to addresses 0xD00000-0xD00FFF
   - Press a key by setting keyMatrix[6] = 0xFE (ENTER key: group 6, bit 0) BEFORE the event loop starts
   - Run 200,000 steps and report what 0x003C63 writes and where
