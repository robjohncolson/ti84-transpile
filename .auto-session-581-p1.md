# Task: DECODE 0x03D1C3 — Real Key Scan Function

## Context
This is part of TI-84 Plus CE ROM transpilation. The OS event loop at 0x08C331 calls 0x0A27DD for key input. Session 579-580 decoded 0x0A27DD: it's a 33-byte init-guarded wrapper that does `BIT 6 IY+0x1B` guard → `LD (D005F5),1` → `CALL 0x03D1C3` → `EI` → `SET 0 IY+0x12` → tail-call `JP 0x0A1A36`. The `CALL 0x03D1C3` is where the actual key scan happens — it reads the keyboard hardware and returns the scan code. This function has NOT been decoded yet.

## Your Task
Write a probe at `TI-84_Plus_CE/probe-phase581-decode-03D1C3.mjs` that statically disassembles the function at ROM address 0x03D1C3 and writes a report to `TI-84_Plus_CE/phase581-decode-03D1C3-report.md`.

### What to do
1. Read ROM bytes starting at 0x03D1C3 using the existing ROM loading pattern (see any `probe-phase5*.mjs` for the pattern — load ROM via `fs.readFileSync`, read bytes with `rom[addr - baseAddr]`). The ROM base address is 0x000000 and it's at `TI-84_Plus_CE/ROM.rom`.
2. Decode eZ80 instructions manually from the raw bytes. The eZ80 is a Z80 superset with ADL mode (24-bit addresses). Key instruction patterns:
   - `0xCD nn nn nn` = CALL addr (3-byte little-endian address in ADL mode)
   - `0xC3 nn nn nn` = JP addr
   - `0xC9` = RET
   - `0x18 dd` = JR dd (signed relative)
   - `0x20 dd` = JR NZ, dd
   - `0x28 dd` = JR Z, dd
   - `0xCB` prefix = bit operations
   - `0xFD` prefix = IY operations
   - `0xDD` prefix = IX operations
   - `0xED` prefix = extended operations (IN, OUT, LDIR, etc.)
   - `0x40` prefix (SIS) = force 16-bit operand in ADL mode
   - Loads: `0x3E` = LD A,n; `0x21 nn nn nn` = LD HL,addr; `0x01 nn nn nn` = LD BC,addr
   - `0xDB nn` = IN A,(n); `0xED 78` = IN A,(C)
3. Decode at least 100 bytes (or until you hit a clear RET/JP that ends the function).
4. Look for:
   - Keyboard I/O port reads (IN instructions, port 0x01 = key group select, port 0x02 = key data)
   - RAM references (addresses in 0xD00000-0xD3FFFF range)
   - IY+offset flag operations
   - Subroutine calls (CALL instructions)
   - Loop structures (JR/JP back to earlier addresses)
5. Count callers: grep the ROM for bytes that encode `CALL 0x03D1C3` (bytes `CD C3 D1 03`) and `JP 0x03D1C3` (bytes `C3 C3 D1 03`).

### Report format
Write `phase581-decode-03D1C3-report.md` with:
- Function address, size in bytes, number of instructions
- Full annotated disassembly (address | hex bytes | mnemonic | comment)
- RAM addresses referenced (list with read/write/address classification)
- IY+offset flags touched
- Subroutine calls made (CALL targets)
- Caller count and addresses
- Architectural summary: what does this function do? Is it _GetCSC? Does it scan the keyboard matrix? How does it return the scan code (in A? in a RAM location?)
