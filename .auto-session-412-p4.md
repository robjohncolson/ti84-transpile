# Task: Add 20 New Seeds to the Transpiler

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The transpiler at `scripts/transpile-ti84-rom.mjs` lifts the TI-84 Plus CE ROM (eZ80 machine code) into JavaScript. It uses a "seed" list of known code entry points to start disassembly. More seeds = more coverage.

Current state: 145,279 transpiled blocks, 710,483 covered bytes. The ROM is 4 MB (0x000000–0x3FFFFF).

## What to do

1. Read `scripts/transpile-ti84-rom.mjs` and find the `seeds` array (search for `const seeds` or `seeds = [`).

2. Run `node TI-84_Plus_CE/audit-true-uncovered.mjs` to find the largest uncovered ROM gaps.

3. For each gap, examine the ROM bytes at the gap start address to determine if it's likely code (look for common eZ80 instruction patterns) or data (look for ASCII strings, repetitive bytes, 0xFF fills).

4. Add 20 new seed addresses that are LIKELY CODE entry points. Good indicators:
   - Starts with a common function prologue: PUSH IX (DD E5), CALL (CD xx xx xx), LD SP,HL, DI (F3)
   - Referenced by CALL/JP instructions from already-covered code
   - NOT in the middle of a data table (no long runs of ASCII, 0x00, 0xFF)

5. After adding seeds, run:
   ```
   node scripts/transpile-ti84-rom.mjs
   node TI-84_Plus_CE/probe-phase99d-home-verify.mjs
   ```
   The transpiler MUST complete without errors and the golden regression MUST pass (look for "Normal Float Radian" in output and all 26 cells passing).

6. Record the before/after block count and covered byte count.

## Seed format
Seeds are added to the array like:
```javascript
0x0XXXXX,  // description of what's at this address
```

## Constraints
- ONLY modify `scripts/transpile-ti84-rom.mjs` (to add seeds)
- Do NOT modify any other files
- Do NOT add seeds in the range 0x400000+ (that's RAM, not ROM)
- Do NOT add seeds that are already in the seeds array
- Verify the golden regression passes AFTER adding seeds
- If the golden regression FAILS, revert your seed additions and try different addresses
