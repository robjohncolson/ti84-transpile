# Task: Map the 6-Slot Action Pipeline Data Flow

## Context
You are working on a TI-84 Plus CE ROM (eZ80) reverse-engineering project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`.

Session 403 decoded the action byte interpreter at 0x07FDD6. Key findings:
- 0x07FDD6 is NOT a dispatch table — it's a simple 2-way branch
- After AND 0x3F, only TWO action codes get special handling: CP 0x1C and CP 0x1D trigger CALL 0x07F95E (pipeline shift)
- 0x07F95E promotes slot 1 into slot 0, archives old slot 0 to slot 3 via LDI chain
- Four entry points: 0x07FDC3/0x07FDC9/0x07FDD0/0x07FDD6 handle slot 0 vs slot 1
- 119 TOTAL CALLERS (57 for slot 0, 52 for bit 7 test, 10 for slot 1)
- Bit 7 of the action byte is a ONE-SHOT MODIFIER FLAG (cleared in-place via RES 7,(HL))

## Task
Create a probe `TI-84_Plus_CE/probe-phase404-action-pipeline.mjs` that:

1. **Find the pipeline slot RAM addresses**: 0x07F95E does an LDI chain to shift slots. Disassemble 0x07F95E from ROM bytes to find the RAM addresses used for slots 0-5. Each slot likely has a fixed-size action record at a known RAM address.

2. **Categorize the 119 callers by action code**: From the ROM, find 10-15 representative callers of 0x07FDD6 (slot 0 reader). For each, disassemble the bytes AFTER the CALL to see what action code they compare against (CP xx instructions). Group callers by which action code they handle.

3. **Trace what each pipeline stage does**: Starting from 0x07F95E (the pipeline shift), trace what happens to each slot:
   - Slot 0: current action being processed
   - Slot 1: next action queued
   - Slots 2-5: what are they? Archive? History?

4. **Output a structured report** with:
   - All slot RAM addresses and their sizes
   - A table of action codes → number of callers → representative caller addresses
   - The pipeline shift mechanics (what LDI copies where)
