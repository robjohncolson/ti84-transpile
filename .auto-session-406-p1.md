# Task: Trace Into Top Action Dispatch Subroutines

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80 binary). We've been tracing the OS key/action dispatch system.

Session 405 found that the action byte readers at 0x07FDD6/0x07FDD0 are pure data fetchers — callers read the action byte from the 6-slot pipeline at 0xD005F8 and then PASS it to subroutine targets rather than using CP (compare) directly. The real action dispatch logic lives INSIDE these subroutines.

The top 5 most-called subroutine targets that receive the action byte are:
- **0x07FA74** (4 callers — most popular)
- **0x07F954** (3 callers)
- **0x07F8CC** (3 callers)
- **0x07F8FA** (3 callers)
- **0x07C74F** (3 callers)

## Task
Create a probe script `TI-84_Plus_CE/probe-phase406-action-subroutines.mjs` that:

1. Reads the ROM binary directly (use `fs.readFileSync('TI-84_Plus_CE/ROM.rom')`)
2. For each of the 5 subroutine targets above, disassemble 80-120 bytes starting at each address
3. For each subroutine, identify:
   - Any CP (compare) instructions and what values they compare against (looking for action codes like 0x08, 0x09, 0x0C, 0x0D, 0x1C, 0x1D, 0x1F, 0x1E, 0x1B)
   - Any CALL/JP targets (what functions they delegate to)
   - Any RAM addresses they read/write
   - Whether they contain a dispatch table (JP (HL) or similar computed jump)
4. Print a structured summary for each subroutine

Also create `TI-84_Plus_CE/phase406-action-subroutines-report.md` with findings.

## eZ80 Instruction Reference
- CP n = 0xFE nn (compare A with immediate)
- CP (HL) = 0xBE
- CALL nn = 0xCD lo mid hi (3-byte address in eZ80 ADL mode)
- JP nn = 0xC3 lo mid hi
- JP cc,nn = 0xC2/0xCA/0xD2/0xDA lo mid hi (NZ/Z/NC/C)
- JP (HL) = 0xE9
- RET = 0xC9
- LD A,(nn) = 0x3A lo mid hi (ADL mode, 3 bytes)
- LD (nn),A = 0x32 lo mid hi
- LD A,n = 0x3E nn
- JR cc,e = 0x20/0x28/0x30/0x38 offset (NZ/Z/NC/C)

eZ80 ADL mode: addresses are 3 bytes (24-bit). CALL/JP use 3-byte targets.
