# Session 467 P2: Trace 0x003A0F Key-Found Path (ROM Disassembly)

## Context
Session 466 decoded 0x003D5A as a key polling function that reads D00587, clears it, and returns NZ with scan code in A when a key is found. The caller at 0x003A0F calls 0x003D5A in a loop (B=100, DJNZ). After 0x003D5A returns NZ (key found), execution does `OR A → JR NZ` to jump somewhere. We need to decode what ROM bytes are at the JR NZ target — that's where the scan code in A gets processed.

## Task
Create a probe `TI-84_Plus_CE/probe-phase467-key-found-path.mjs` that disassembles the ROM bytes at and around 0x003A0F to trace the key-found path.

1. **Read the ROM file** `TI-84_Plus_CE/ROM.rom` directly (binary).
2. **Disassemble bytes starting at 0x003A0F** through 0x003A90 (about 130 bytes). Use a simple eZ80 disassembler that handles at minimum:
   - CALL nn (0xCD + 3-byte address)
   - JP nn (0xC3 + 3-byte address)
   - JR cc,offset (0x20/0x28/0x30/0x38 + signed byte)
   - JR offset (0x18 + signed byte)
   - LD A,(nn) (0x3A + 3-byte address)
   - LD (nn),A (0x32 + 3-byte address)
   - OR A (0xB7)
   - CP n (0xFE + byte)
   - DJNZ offset (0x10 + signed byte)
   - RET (0xC9), RET cc (0xC0/0xC8/0xD0/0xD8/0xE0/0xE8/0xF0/0xF8)
   - LD r,n / LD rr,nn basics
   - BIT/SET/RES via CB prefix
   - IN0 A,(n) via ED prefix (0xED 0x38 n)
   - OUT0 (n),A via ED prefix (0xED 0x39 n)
   - The IY+d instructions via FD prefix (0xFD + opcode + displacement)
   - For unknowns, print hex bytes

3. **For each CALL/JP/JR target**, note whether it's within the 0x003A0F-0x003A90 range (local) or external.

4. **Specifically identify**:
   - The `OR A → JR NZ` instruction pair after the DJNZ loop — compute the JR NZ target address
   - What code runs at that target address (disassemble 30+ bytes there)
   - Any CALL targets that could be the key processor (0x03FA09) or display functions (0x0059C6, 0x005B96, 0x0059E9)

5. **Also disassemble 0x003D5A through 0x003D90** to show the key polling function's structure for cross-reference.

## Reference
The probe at `TI-84_Plus_CE/probe-phase466-decode-0x003D5A.mjs` has a good disassembler template you can reference for the hex→mnemonic approach.

Running `node TI-84_Plus_CE/probe-phase467-key-found-path.mjs` prints a clear disassembly showing the JR NZ target address and what code executes when 0x003D5A returns with a key found.
