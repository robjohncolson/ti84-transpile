# Task: Decode the LDIR Source Blocks at ROM 0x05550C and 0x055519

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80).

Session 331 mapped the 0x055743 mode-switch function. It found:
- When BPP flag (IY+70 bit 2) is clear → 16bpp path at 0x05550C
- When BPP flag is set → 8bpp path at 0x055519
- Both paths use LDIR to copy 13 bytes to destination D02FD9

The LDIR instruction copies BC bytes from (HL) to (DE). In this case BC=13, DE=D02FD9, and HL points to a ROM source address (0x05550C for 16bpp, 0x055519 for 8bpp).

These 13 bytes are a configuration record that controls LCD/VRAM behavior. Session 331 also found that the scaling kernel at 0x053573 uses records of similar format (12-byte records indexed by scale level).

## Your Task
1. **Hex-dump both 13-byte blocks** from the ROM:
   - 16bpp block: ROM[0x05550C .. 0x05550C+12] (13 bytes)
   - 8bpp block: ROM[0x055519 .. 0x055519+12] (13 bytes)

2. **Annotate each byte/field**. Based on context from session 331:
   - The record likely contains: width, height, stride, VRAM base address, BPP indicator, and possibly pixel format flags
   - The destination D02FD9 is read by multiple subsystems (text, pixel, graph, LCD)
   - Compare the two blocks field-by-field: what changes between 16bpp and 8bpp?

3. **Cross-reference with readers of D02FD9**. Search the transpiled JS for reads of addresses D02FD9 through D02FE5 (13 bytes). How is each field used? This tells you what each byte means.

4. **Compare with the scaling kernel records** at 0x05320F (4 records × 12 bytes each, indexed by scale level). Are these the same format? Or a different structure?

## Method
- Read ROM bytes: `node -e "const rom = require('fs').readFileSync('TI-84_Plus_CE/ROM.rom'); console.log('16bpp:', rom.slice(0x05550C, 0x05550C+13).toString('hex')); console.log('8bpp:', rom.slice(0x055519, 0x055519+13).toString('hex'));"`
- Also dump the scaling records: `rom.slice(0x05320F, 0x05320F+48).toString('hex')` (4×12 bytes)
- Search transpiled JS for D02FD9-D02FE5 reads
- Gunzip transpiled JS first if needed

## Deliverables
Create `TI-84_Plus_CE/probe-phase332-ldir-blocks.mjs` that:
- Reads both 13-byte blocks from the ROM
- Hex-dumps them with byte-by-byte annotation
- Reads the 4 scaling kernel records for comparison
- Searches for D02FD9-D02FE5 reader patterns in the transpiled JS (or ROM)
- Outputs a field-by-field comparison table

Also create `TI-84_Plus_CE/phase332-ldir-blocks-report.md` with the annotated field map.
