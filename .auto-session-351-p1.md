# Task: Inspect Transpiled Block 0x00069A — BIT 2,A → RET PO Flag Bug

## Context
The TI-84 CE boot loop is stuck because RET PO at address 0x0006A8 never fires after BIT 2,A succeeds. The boot code at 0x00069A does:
- OUT (0x28), 4   (write PLL)
- IN A, (0x28)    (read PLL — now returns 0x04 after session 349 fix)
- BIT 2, A        (test bit 2 — sets PV=0 when bit is 1, meaning "parity odd" = PO condition true)
- LD IX, 0x0800   (load IX — does NOT affect flags)
- RET PO          (return if P/V flag = 0, i.e., PO condition)

After session 349's PLL fix + session 350's flash fix, port 0x28 returns 0x04 (bit 2 set). So BIT 2,A should set Z=0 and PV=0 (bit is set → NOT zero → P/V reflects bit state). Then RET PO (P/V=0) should return. But it doesn't.

## Your Task

1. **Find the transpiled block at address 0x00069A** in `TI-84_Plus_CE/ROM.transpiled.js`. Search for `block_0x00069A` or `0x00069A` or the function that handles this address. The file is ~210MB so use grep/search, don't read the whole thing.

2. **Check the block boundary**: Does the block at 0x00069A contain ALL of these instructions: OUT, IN, BIT 2,A, LD IX, RET PO? Or does it end before RET PO? If RET PO is in a DIFFERENT block (e.g., block_0x0006A9), then flag state from BIT 2,A is lost at the block boundary — that's the bug.

3. **Check flag semantics**: In the transpiled JS for this block:
   - Does BIT 2,A correctly set `cpu.flags.pv` (or equivalent P/V flag variable)?
   - Does LD IX,nn preserve the flags (it should NOT modify any flags)?
   - Does RET PO correctly check the P/V flag (`if (!cpu.flags.pv)` or equivalent)?
   - Is there any flag clobbering between BIT and RET PO?

4. **Check block_0x0006A9**: If this block exists, what's its first instruction? Does it start at the byte AFTER RET PO, or does it contain RET PO?

5. **Write findings to `TI-84_Plus_CE/probe-phase351-ret-po-analysis.mjs`** as a Node.js script that:
   - Reads the transpiled JS and extracts the relevant block(s)
   - Reports: block boundaries, flag handling code, whether RET PO is in the same block as BIT 2,A
   - Outputs a clear diagnosis: "BUG FOUND: <description>" or "NO BUG IN BLOCK — issue is elsewhere"
