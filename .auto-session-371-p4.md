# Task: Investigate Timer ISR Blocks 0x0019BE-0x001A32

## Context
Session 370 discovered 6 NEW blocks in the timer interrupt path that execute ~994 times each in 200K steps: 0x0019BE, 0x0019EF, 0x001A17, 0x001A23, 0x001A2D, 0x001A32. These blocks are part of what the timer ISR actually does between the RST 38h dispatch and the 0x001713 idle check. We need to disassemble them to understand the timer's processing.

## Deliverable
Create `TI-84_Plus_CE/probe-phase371-timer-isr-blocks.mjs` that:

1. **Boot phases 1-3** (standard):
   - Phase 1: `runFrom(0x000000, 'z80', { maxSteps: 20000, maxLoopIterations: 32 })`
   - Phase 2: `runFrom(0x08C331, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 })`
   - Phase 3: `runFrom(0x0802B2, 'adl', { maxSteps: 100, maxLoopIterations: 32 })`
   - Standard stack resets between phases

2. **Static disassembly** of each block — read ROM bytes directly and decode using the eZ80 instruction decoder:
   - **0x0019BE**: Decode 40 bytes starting from 0x0019BE
   - **0x0019EF**: Decode 40 bytes starting from 0x0019EF
   - **0x001A17**: Decode 20 bytes starting from 0x001A17
   - **0x001A23**: Decode 20 bytes starting from 0x001A23
   - **0x001A2D**: Decode 10 bytes starting from 0x001A2D
   - **0x001A32**: Decode 20 bytes starting from 0x001A32

   For each instruction: print address, hex bytes, and mnemonic/operands.

3. **Dynamic trace with timer** — Run the event loop with `timerInterrupt:true` and `iff1=1` for 10K steps:
   - Record visit counts for ALL blocks in the timer path: 0x000038, 0x0006F3, 0x000704, 0x000710, 0x000719, 0x001713, 0x001717, 0x0019BE, 0x0019EF, 0x001A17, 0x001A23, 0x001A2D, 0x001A32
   - Record the execution ORDER of these blocks for the FIRST 3 timer interrupts (capture block sequence)
   - Check what RAM addresses these blocks read/write (if any writes to LCD buffer 0xD40000-0xD53F00, report them)

4. **RAM state analysis** — After the 10K-step run:
   - Read and print key RAM locations that these blocks might reference:
     - 0xD00080-0xD000C0 (IY-relative system flags area, 64 bytes)
     - 0xD177BA (the ROM magic check address from session 370 — stays non-zero)
   - Print cpu.iff1, cpu.iff2, cpu.im after the run

5. **Report**: Full disassembly of each block with annotations, dynamic visit counts, execution sequence, and RAM state analysis.

## How to decode instructions
Import the decoder from `TI-84_Plus_CE/ez80-decoder.js`. It exports a decode function — read the first 30 lines of the file to find the export name and calling convention. It takes (memory_buffer, pc_address, adl_mode) and returns instruction details.

## Key setup for timer event loop
```javascript
const peripherals = createPeripheralBus({ pllDelay: 2, timerInterrupt: true });
const executor = createExecutor(BLOCKS, mem, { peripherals });
// After boot phases:
cpu.halted = false;
cpu.iff1 = 1;  // MUST be 1 for timer to fire
cpu.iff2 = 1;
cpu.f = 0x40;
cpu._ix = 0xD1A860;
cpu._iy = 0xD00080;
cpu.sp = 0xD1A87B - 12;  // approximate; use STACK_RESET_TOP - 12
mem.fill(0xFF, cpu.sp, cpu.sp + 12);
// Run event loop:
executor.runFrom(0x003A73, 'adl', { maxSteps: 10000, maxLoopIterations: 10 });
```
