# Task: Trace 0x03FB9A Key Processing Path

## Context
You are working on a TI-84 Plus CE ROM (eZ80) transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 ADL mode).

Session 397 found that 0x03FA09 is the "result fetch" function in the OS event loop. When the key result (read from 0xD00587) is non-zero, it jumps to 0x03FB9A for key processing. When zero, it checks auto-power-down/USB/link-port flags.

**0x03FB9A is the "key accepted" path — what the OS does when a key has been processed and a result is ready.** Understanding this completes the key lifecycle from press to effect.

## Your Task
Create a probe file `TI-84_Plus_CE/probe-phase398-trace-03FB9A.mjs` that:

1. Reads ROM.rom from disk
2. Uses the eZ80 decoder at `TI-84_Plus_CE/ez80-decoder.js` (import `decodeInstruction`)
3. Performs static disassembly starting at 0x03FB9A in ADL mode
4. Traces forward for up to 256 instructions or until RET/HALT, following both branches at conditional jumps
5. For each instruction, logs: address (hex), raw bytes (hex), mnemonic + operands
6. Identifies:
   - What 0x03FB9A does with the key result in A
   - Any writes to display buffer, input buffer, or key state RAM
   - CALL/JP targets (annotate known: 0x02237E, 0x0301F6, 0x02FD99, 0x030300, 0x02FE73, 0x02FECF)
   - RAM reads/writes (especially 0xD0058C kbdKey, 0xD0058E kbdToken, 0xD00587 kbdGetKy result)
   - IY+offset bit operations (IY base = 0xD00080)
   - Whether it loops back into the event loop or returns to caller
7. Also searches the entire ROM for CALL/JP references TO 0x03FB9A to find all callers
8. Prints a summary section

## Reference Format

## Key Known Addresses
- 0xD00587 = kbdGetKy result register (read by 0x03FA09)
- 0xD0058C = kbdKey, 0xD0058E = kbdToken
- 0xD007E0 = mode byte (cxCurApp)
- 0xD14091, 0xD141B2, 0xD141BA, 0xD00589 = power/USB/link flags (checked by 0x03FA09 on zero result)
- IY = 0xD00080
