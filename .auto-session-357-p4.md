# Task: Trace post-HALT code at 0x0019BE — what happens after HALT on real hardware

## Context
The TI-84 CE boot HALTs at 0x0019B5. The bytes at this location are:
```
0x0019B5: F3 3E 10 ED 39 00 00 00 76
         (DI, LD A,0x10, OUT0 (0x00),A, HALT)
```

After HALT at 0x0019BE, the bytes are:
```
0x0019BE: 40 01 15 50 ED 78 28 29
         (LD B,B, LD BC,0x5015, IN A,(C), JR Z,+0x29)
```

On real eZ80 hardware, when NMI fires during HALT, execution resumes at the NMI vector (0x000066) BUT the return address pushed is the instruction AFTER HALT (0x0019BE), not the HALT itself. So when the NMI handler executes RETN, it should return to 0x0019BE, not 0x0019B5.

Our transpiler dispatches NMI to 0x000066 but the NMI handler path ends at 0x000DED → 0x0019B5. If 0x000DED has a JP 0x0019B5 instead of RETN, we're bypassing the post-HALT code entirely.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase357-post-halt-trace.mjs` that:

1. Reads ROM.rom binary and disassembles 0x0019B5 through 0x001A20 (~107 bytes) in eZ80 ADL mode. Show the full disassembly of the post-HALT region.

2. Also disassemble 0x000DED through 0x000E10 to check for RETN (ED 45) / RETI (ED 4D) / JP instructions.

3. Boot the ROM (timerInterrupt: false) for ~5000 steps to reach HALT.

4. When HALT is reached, instead of triggering NMI, directly set PC to 0x0019BE (the post-HALT address) and continue execution for 5000 steps.

5. Record all unique blocks visited starting from 0x0019BE. This tells us what code would run if RETN returned to the correct post-HALT address.

6. Also record all port reads and writes from 0x0019BE onward. The post-HALT code at 0x0019BE reads port 0x5015 (IN A,(C) with BC=0x5015) and branches on Z flag. What value does port 0x5015 return? What happens on the JR Z branch?

7. Additionally: check what port 0x50 maps to in peripherals.js (port 0x5015 would be accessed as port (C) where C=0x15 and B=0x50 — but in eZ80, IN A,(C) uses the full 16-bit BC as the port address). Check if the peripheral bus handles 16-bit port addresses or just 8-bit.

## eZ80 ADL-mode decoding notes
- IN A,(C) = ED 78 — reads port BC (16-bit in ADL mode: all 16 bits of BC used)
- JR Z,e = 28 ee — relative jump if Z flag set. Offset is signed: +0x29 = jump forward 41 bytes from the NEXT instruction
- LD B,B = 40 (NOP-like)
- LD BC,nn in ADL = 01 + 3-byte immediate (but this is 0x5015 which is 2-byte — check if this is z80-mode prefix or ADL)
