# Task: Decode 0x0BD00D (Bulk Descriptor Initializer)

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary, little-endian).

## Background
Session 507 identified 0x0BD00D as a bulk descriptor initializer:
- Loads DE=D01EB1
- Sets B=6
- Loops calling 0x07FA0D 6 times

This may be the boot-time or editor-init routine that first populates all cursor descriptors. The descriptors at D01EB1-D01EF9 are all zeros at boot (confirmed session 506), so this initializer runs later during event loop setup.

Related functions:
- 0x07FA0D = called 6 times with DE=D01EB1 (purpose unknown — decode this too)
- D01EB1/D01EBA/D01EDE = three cursor type descriptor blocks (9-byte primary + 21-byte secondary each)
- 0x07F978 = 9× LDI + RET (copies 9-byte descriptor)
- 0x07F9FB = copies 9-byte descriptor to active slot D005F8-D00600

## Task
Create a probe that disassembles 0x0BD00D and its key callee 0x07FA0D:

1. **0x0BD00D**: Read ~128 bytes starting at this address. Decode all eZ80 instructions. Find the loop structure (B=6, DJNZ or conditional JR back). Determine how DE advances between iterations (by 9 bytes for each descriptor? by some other stride?). Find what values are passed to 0x07FA0D.

2. **0x07FA0D**: Read ~64 bytes starting at this address. Decode all instructions. This is called with DE pointing to a descriptor block. Does it initialize/zero the block? Copy from a template? Compute values?

3. Also decode any functions called by 0x07FA0D that are short enough to inline (< 32 bytes).

Key eZ80 notes:
- 24-bit address space, ADL mode
- `ED 27` = LD HL,(HL)
- `40` prefix = .SIS (16-bit MBASE addressing)
- `DD`/`FD` = IX/IY prefixes
- `ED 4C/5C/6C` = MLT BC/DE/HL
- DJNZ = `10 xx` (decrement B, jump if not zero)

## Deliverable

- Prints instruction-by-instruction: address, hex bytes, mnemonic
- Summarizes: what the loop does, what 0x07FA0D does to each descriptor, what stride DE uses
