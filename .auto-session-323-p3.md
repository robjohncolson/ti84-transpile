# Task: Trace 0x055743 (LCD Hardware Init Function)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. Function 0x055743 is called by 0x05523D (LCD init sequence) BEFORE `SET 2,(IY+0x46)` which arms the D000C6 bit 2 flag that enables VRAM writes. This function configures LCD hardware. We need to know what it does — what ports it writes, what state it sets up, and whether it needs to run before LCD VRAM writes can succeed.

Reference: Session 256 found 0x022264 vector table with entry[0]=JP 0x05523D. The function body at 0x05523D calls 0x055191, does LDIR (VRAM fill D40000), calls 0x055280, calls **0x055743** (LCD HW init), then SET 2,(IY+70). D000C6 bit 2 is the sole gate for LCD column/row drawing (traced in session 247).

## What to do
Write a probe at `TI-84_Plus_CE/probe-phase323-055743-lcd-hw-init.mjs` that:

1. **Boots the CPU** to get a reasonable initial state (use the standard boot pattern from other probes in this repo — import from `cpu-runtime.js`, create CPU with `createPeripheralBus({ timerInterrupt: false })`, run kernelInit/memInit as other probes do).

2. **Traces function 0x055743** by setting PC to 0x055743, SP to a safe stack (e.g., 0xD1A87E), and running for up to 5000 steps. Collect:
   - All OUT instructions (port writes) — what ports and what values
   - All IN instructions (port reads) — what ports and what values returned
   - All unique block addresses visited
   - Total step count
   - Whether it returns (hits RET) or gets stuck

3. **Also try a static disassembly** of the first 64 bytes starting at ROM address 0x055743. Read from the ROM buffer. Print the hex bytes and any obvious instruction patterns.

4. Print a structured report:
   ```

   Port writes: [list of {port, value}]

   ```
