# Task: Map LCD Synchronization Function 0x010A3C

## Context
You are analyzing the TI-84 Plus CE OS ROM (eZ80, file `TI-84_Plus_CE/ROM.rom`, 4 MB). The transpiler is at `scripts/transpile-ti84-rom.mjs`. The lifted JS is generated into `TI-84_Plus_CE/ROM.transpiled.js` (gunzip from `.gz` if needed).

## Background
Function 0x010A3C is called by 12 display vectors in the OS. It is the central LCD synchronization point — it busy-loops on an LCD status register waiting for the display controller to be ready. Session 319 identified it as "central LCD sync" used by the 26-vector display subsystem.

The TI-84 Plus CE uses an SPI-connected LCD controller. Key LCD-related ports from `TI-84_Plus_CE/peripherals.js`:
- Port range 0x4000-0x401F is LCD controller territory
- The LCD SPI handler is at 0x03CF7D

2. **Port identification** — which I/O port(s) does it read (IN/IN0 instructions)? Which bit(s) does it test?
3. **Loop structure** — how does the busy-wait loop work? Is there a timeout/counter? What's the exit condition?
4. **Caller analysis** — list the 12 display vector callers. For each, note the address and what display operation it performs (if identifiable from surrounding context).
5. **Peripheral implications** — what value should `peripherals.js` return for the polled port to allow the function to proceed without infinite looping?

## Method
1. Read `TI-84_Plus_CE/ROM.rom` as a binary buffer
2. Disassemble starting at offset 0x010A3C (ROM is mapped at address 0x000000, so file offset = address)
3. Use the eZ80 instruction set — this is a 24-bit CPU (ADL mode). Instructions may have .LIL/.SIS/.LIS/.SIL suffixes
4. Look for IN/IN0 instructions (reads from I/O ports), CP/BIT/AND instructions (bit testing), JR/JP conditional branches (loop)
5. Search the ROM for CALL 0x010A3C to find all callers
