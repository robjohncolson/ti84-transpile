# Auto-Session 349 — P1: Identify Boot Loop Condition (IN/OUT Trace)

## Context
After session 348's port 0x3D fix, boot now reaches 35 unique blocks and runs 50k steps without missing blocks. But it loops indefinitely through: 0x001AFA→0x0058A6→...→0x005998→0x001AFD→...→0x000043→0x0006F3→0x000704→0x00070F→0x00080B.

The loop likely polls a hardware register (IN instruction) waiting for a condition (PLL lock, flash ready, etc.) that never resolves in the emulator.

## Task
Create a probe `TI-84_Plus_CE/probe-phase349-boot-loop-io.mjs` that:

1. Boots from PC=0x000000 with `timerInterrupt: false`
2. Instruments ALL IN and OUT instructions by patching the CPU's `in8`/`out8` methods to log: `{step, pc, port, value, direction: 'IN'|'OUT'}`
3. Runs for 5000 steps (enough to capture several loop iterations)
4. Prints a summary: unique ports read/written, how many times each port is read, what values are returned
5. Specifically identifies any port that is read repeatedly (>5 times) with the same value — this is the polled condition

## Key Files
- `TI-84_Plus_CE/cpu-runtime.js` — has `in8(port)` and `out8(port, val)` methods
- `TI-84_Plus_CE/peripherals.js` — peripheral bus, port handlers
