# Task: Find OS main loop caller of 0x0584A3 and test dispatch with proper stack

## Context
In the TI-84 Plus CE ROM transpilation project, block 0x0584A3 is the key classification entry point (Copy9 → KeyClassifier → dispatch). Session 197 proved that entering 0x0584A3 directly causes RST 0 (stack underflow at step 49) because the RET at 0x03E1B1 pops 0x000000 — the probe's bare stack lacks the return addresses the real OS event loop provides.

The dispatch chain is: 0x0584A3→Copy9→KeyClassifier(0x07F7BD)→0x09927F→0x082C50→0x0846EA→0x061D3A→0x03E1B4→0x03E1B1→0x000000(RST 0)

## Goal
1. **Find the CALL site** that invokes 0x0584A3 (or whatever calls the block containing 0x0584A3). Search the transpiled ROM blocks for any block containing `call(0x0584A3)` or `call(0x05849F)` or a JP to that area. The caller is likely in the CoorMon/main event loop area.

2. **Build a probe** that enters from the caller level (or enters 0x0584A3 with the correct stack frame pre-loaded). The stack needs return addresses that 0x03E1B1's RET will pop correctly — based on session 197, the chain goes through 0x03E1B4 and 0x03E1B1. The RET at 0x03E1B1 needs to return to somewhere in the event loop (not 0x000000).

3. **Approach A (preferred)**: Find the caller block, enter from there with a key pre-loaded in the appropriate register/RAM.
   **Approach B (fallback)**: Enter 0x0584A3 but pre-push correct return addresses on the stack. Based on the chain: 0x03E1B4 is called by 0x061D3A, so 0x03E1B1's RET should return to... wherever called 0x03E1B4. Look at what address should be on the stack.
