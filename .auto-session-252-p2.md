# Task: Trace 0x08C8CF — handler pointer store for 0x058241

## Context
In the TI-84 Plus CE ROM transpilation project, session 251 found that at ROM address **0x08C8CF** there is a `LD HL,0x058241` instruction — this stores the cxMain pre-handler address as a function pointer. Additionally, at **0x08C958**, after a RET instruction, the raw bytes `41 82 05` appear (the address 0x058241 as a data table entry).

We need to understand:
1. What function contains 0x08C8CF?
2. Where does it store the pointer (what RAM address)?
3. What is the data table at 0x08C958, and how is it indexed?
4. Who calls this function?

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase252-08c8cf-handler-store.mjs`

## What the probe must do

1. **Disassemble around 0x08C8CF**: Read ROM bytes from 0x08C8A0 to 0x08C980. Decode eZ80 ADL instructions manually. Look for:
   - The LD HL,0x058241 at 0x08C8CF (should be bytes `21 41 82 05`)
   - What instruction follows it — likely `LD (addr),HL` which stores the pointer to RAM
   - Find the function boundary by scanning backwards for RET (0xC9) or unconditional JP

2. **Disassemble the data table at 0x08C958**: Read bytes 0x08C950-0x08C9A0. The `41 82 05` at 0x08C958 is likely one entry in a pointer table. Look for:
   - Other 3-byte address entries (patterns that look like ROM addresses in range 0x000000-0x0BFFFF)
   - Table boundaries (repeated patterns, zeroes, or other delimiters)
   - How many entries the table has

3. **Static ROM scan for callers**: Search the entire ROM for:
   - CALL/JP to the function entry address (found in step 1)
   - Any LD instructions that reference the RAM address where the pointer is stored (found in step 1)

4. **Cross-reference with known addresses**:
   - 0x058241 = cxMain pre-handler entry
   - 0x0585D3 = cxMain dispatch table (JP (HL))
   - 0x0585E9 = cxMain direct entry
   - 0x0582BC = home body entry
   - Check if any of these appear in the data table at 0x08C958

## Technical details
- ROM file: `TI-84_Plus_CE/ROM.rom` (4,194,304 bytes)
- Use `import { readFileSync } from 'fs'` and Buffer operations
- eZ80 ADL mode: addresses are 3 bytes (24-bit), little-endian
- Key eZ80 opcodes:
  - 0x21 = LD HL,nn (4 bytes: 21 + 3-byte LE addr)
  - 0x22 = LD (nn),HL (4 bytes: 22 + 3-byte LE addr) 
  - 0xCD = CALL nn (4 bytes)
  - 0xC9 = RET
  - 0xC3 = JP nn (4 bytes)
  - 0xED 0x63 = LD (nn),HL (alternate encoding, but 0x22 is more common in ADL)
