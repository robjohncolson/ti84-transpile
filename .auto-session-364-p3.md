# Auto-Session 364 — Priority 3: Add SP < 0x400000 Diagnostic Warning to cpu-runtime.js

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The eZ80 CPU runtime is in `TI-84_Plus_CE/cpu-runtime.js`. Boot currently crashes because SP gets set to a ROM address (0x014C7B) via `LD SP, IX` in block 0x00BC72.

On real TI-84 hardware, SP pointing into ROM (< 0x400000) would cause writes to fail silently (flash is read-only without unlock sequences). Our runtime already write-protects ROM addresses in `write8`/`write16`/`write24` (silently dropping writes where addr < 0x400000), but PUSH/CALL operations that decrement SP and write to the stack don't trigger a visible warning.

## Your Task
Add a lightweight diagnostic to `cpu-runtime.js` that warns when SP enters ROM space. This helps future debugging by catching SP corruption early.

### What to Add

1. In the `createCPU` function (or wherever the CPU state object is created), add a `spWarnings` array to the CPU object: `cpu.spWarnings = []`

2. Find the `setSP` or direct `cpu.sp = ...` assignments. There is likely a pattern where SP is set. Add a check:
   ```javascript
   // After any SP assignment:
   if (cpu.sp < 0x400000 && cpu.sp !== 0) {
     const warning = { step: cpu.stepCount || 0, sp: cpu.sp, pc: cpu.pc };
     cpu.spWarnings.push(warning);
     if (cpu.spWarnings.length <= 5) {
       console.warn(`[SP WARNING] SP=${cpu.sp.toString(16)} (ROM space) at PC=${cpu.pc.toString(16)} step=${cpu.stepCount || '?'}`);
     }
   }
   ```

3. The warning should:
   - Only print the first 5 warnings (avoid spam in boot loops)
   - Store all warnings in the array for programmatic access
   - NOT change any behavior (don't clamp SP, don't throw, don't halt)
   - Be zero-cost when SP is in valid RAM range (just an integer comparison)

### Where to Look

- The PUSH helper function (PUSH decrements SP by 3 in ADL mode, then writes)
- The CALL helper (similar to PUSH — decrements SP and writes return address)

If SP is set via a JavaScript setter (Object.defineProperty with set), add the check inside the setter. If it's a plain property, you'll need to convert it to a setter or add the check at call sites.
