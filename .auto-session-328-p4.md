# Task: Trace 0x055316 Config Table Selector in Full

## Context
You are working on the TI-84 Plus CE ROM transpilation project. Session 325 partially decoded 0x055316 as a "config table selector" — it's called by the slow path of the LCD sync gate function 0x055191. Session 327 showed that the slow path of 0x055191 calls 0x055316 after setting up state (bit 1 of D000C6, etc.).

From session 327: the slow path sets bit 1 at D000C6, pushes 0, calls 0x055316 (which re-enters 0x055191 — fast-returns since bit is now set), then initializes D005EC=0x00, D005F4=0xFF, D005F0→0x05320F, D005ED from ROM 0x05323F, D02FD6=conditional, copies 13 bytes ROM 0x05550C→D02FD9 via LDIR.

Session 325 noted: 0x055316 has IX frame setup and recursive 0x055191 call. We need the FULL function body.

## Target
Function at **0x055316** — config table selector, part of LCD initialization.

## Deliverables
Create a probe file `TI-84_Plus_CE/probe-phase328-config-selector.mjs` that:

1. Disassembles 0x055316 completely — follow all basic blocks until RET/JP instructions
2. Answers these specific questions:
   - How many instructions / basic blocks does the full function have?
   - What does the IX frame look like? What local variables are on the stack?
   - What does it do AFTER the recursive 0x055191 call returns?
   - What config tables does it reference? (Look for LD HL,imm pointing into ROM)
   - What RAM addresses does it write to? (D005xx, D02Fxx regions)
   - What MMIO ports does it access? (0x80xx LCD, 0x31xx SPI, 0xE3xxxx DMA)
   - What conditional branches exist and what do they test?

3. Dynamic trace:
   - Set up minimal state (bit 1 of D000C6 already set so 0x055191 fast-returns)
   - Execute 0x055316 and log all RAM writes and port accesses
   - Track the call depth to identify how deep the recursion goes

4. Produces an annotated disassembly listing with basic block boundaries marked
