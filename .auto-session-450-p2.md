# Task: Investigate Crash at 0xD18C22 (RAM-space function pointer)

## Context
When the TI-84 OS event loop processes a key with the D177BA gate cleared, execution reaches 0x0067F8 (the real key handler), runs 170,329 steps through 405 unique blocks, VRAM changes, but then CRASHES at PC=0xD18C22 with:

```
TypeError: Cannot read properties of undefined (reading '13740110')
```

0xD18C22 is in RAM space (above 0xD00000). The transpiled ROM only has blocks for ROM addresses (< 0x400000). When execution jumps to a RAM address that has no transpiled block, it crashes.

## Your task
Create a probe file `TI-84_Plus_CE/probe-phase450-d18c22-crash-investigation.mjs` that:

1. **Boots the OS** using the standard boot sequence (copy from `probe-workflow-arithmetic.mjs` — BOOT_ENTRY → KERNEL_INIT → POST_INIT → 4 stages → set D14091=1, D177B7=0x55, D177BA=0)

2. **Injects key "1"** (scan code 0x12, idx=4, bit=1) and runs from EVENT_LOOP_ENTRY (0x003A73) with maxSteps=200000

3. **Tracks execution** to find:
   - What was the PC BEFORE the jump to 0xD18C22? (The last ROM-space PC)
   - What instruction at that PC caused the jump? (Read the bytes from ROM)
   - What value is stored at RAM address 0xD18C22? (Read mem[0xD18C22] through mem[0xD18C24])
   - Who wrote to 0xD18C22 during boot? (Check if the value was there after boot, before key processing)

4. **Reports findings** to `TI-84_Plus_CE/phase450-d18c22-crash-investigation-report.md`
