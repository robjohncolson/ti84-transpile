# Auto-Session 395 P3: Implement 8bpp Rendering in Browser Shell

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The browser shell is at `TI-84_Plus_CE/browser-shell.html`.

The LCD palette register at 0xE30200 was modeled in session 394 in `TI-84_Plus_CE/peripherals.js`. The peripheral bus now exposes:
- `bus.getState().lcdSpiDma.palette` — Uint8Array(512), the 256-entry RGB565 palette (2 bytes per entry, little-endian)
- `bus.lcdSpiDma.palette` — direct reference

The LCD mode flag is at RAM address 0xD000C6 bit 2:
- bit 2 = 0 → 16bpp mode (current rendering, each pixel is 2 bytes in VRAM)
- bit 2 = 1 → 8bpp mode (each pixel is 1 byte = palette index)

VRAM starts at 0xD40000. Screen is 320×240. In 16bpp mode, stride = 640 bytes/row. In 8bpp mode, stride = 320 bytes/row.

## Task
Edit `TI-84_Plus_CE/browser-shell.html` to add 8bpp palette rendering support:

1. In the LCD rendering function (look for `renderLCD` or the function that reads VRAM and draws to the canvas), add a check for 8bpp mode by reading byte at 0xD000C6 and testing bit 2.

2. When in 8bpp mode:
   - Read each VRAM byte as a palette index (0-255)
   - Look up the RGB565 color from the palette: `palette[index*2] | (palette[index*2+1] << 8)`
   - Convert RGB565 to RGB888: R = (rgb565 >> 11) * 255/31, G = ((rgb565 >> 5) & 0x3F) * 255/63, B = (rgb565 & 0x1F) * 255/31
   - Write to the canvas ImageData

3. When in 16bpp mode (existing behavior), keep the current rendering unchanged.

4. Make sure the palette data is accessible. The peripheral bus should already expose it. Look for how `peripherals.js` is used in browser-shell.html — find the `bus` or `peripheralBus` variable and access `.lcdSpiDma.palette` or `.getState().lcdSpiDma.palette`.
