# Task: Map D014FE — Cursor Y Position References and Writers

## Context
The TI-84 Plus CE ROM at `TI-84_Plus_CE/ROM.rom` has been partially reverse-engineered. D014FE is a RAM address confirmed as "cursor Y position / row count". It appears in:
- **0x07B75F Entry A**: `LD A,(D014FE)` — used as row count/height for 8bpp y-flip calculation
- **0x0A1B1C**: `LD A,(D014FE); SUB C` — adjusted row in 4bpp mode dispatcher
- D014FE is a 16-bit value at D014FE (low byte) + D014FF (high byte), or may be used as 8-bit only

There's also **D008D5** — a separate y-coordinate used by the character renderer at 0x0A23E5. The relationship between D014FE and D008D5 is unknown.

Additionally, **D01501** is "display width (16-bit)" read via SIS prefix at 0x07B75F. Map its refs too.

## Task
1. **Search the entire ROM for all references to D014FE**. The byte pattern for `LD A,(D014FE)` in eZ80 is `3A FE 14 D0` (opcode 0x3A + 24-bit little-endian address). Also search for:
   - `(D014FE)` as destination: `32 FE 14 D0` (LD (nn),A)
   - 16-bit loads: `2A FE 14 D0` (LD HL,(nn)), `22 FE 14 D0` (LD (nn),HL)
   - `ED 4B FE 14 D0` (LD BC,(nn)), `ED 5B FE 14 D0` (LD DE,(nn))
   - Any occurrence of bytes FE 14 D0 in sequence

2. **For each reference found**, disassemble ~20 bytes around it to understand the context — is it reading or writing? What function is it in?

3. **Search for D01501 references** using the same patterns (bytes `01 15 D0`).

4. **Search for D008D5 references** (bytes `D5 08 D0`) and compare — how many refs does each y-coordinate have? Are they ever cross-referenced (one function reads both)?
