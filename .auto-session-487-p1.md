# Auto-Session 487 P1: Identify the Real Text Cursor Position Source

## Context

This is a TI-84 Plus CE ROM transpilation project. The OS ROM (eZ80 machine code) has been lifted to JavaScript. We run "probes" — Node.js scripts that boot the lifted ROM, step the CPU, and observe memory/VRAM changes.

Session 486 proved that the cursor blink function at 0x030173 renders at a FIXED position (row=2, col=289) regardless of D0059C, D00595, or D00596 values. D0059C is overwritten to 0x0742 in all cases. The cursor blink path sets LCD window registers D008D2 and D008D5 before rendering. Session 486 concluded this is likely a STATUS INDICATOR blink, not the text cursor blink.

## Task

Create a probe that investigates what D008D2 and D008D5 contain when 0x030173 fires, and search the ROM for other code that writes to D008D2/D008D5 near cursor-related paths.

### Specific investigations:

1. **LCD window register values during cursor blink**: Boot the ROM, run the idle loop (D00000=0x00), and at the first hit of 0x030173, capture the values of D008D2 and D008D5 BEFORE and AFTER 0x030173 executes. The function itself sets D008D2=0x0121 and D008D5=0x02 (hardcoded). Log these values.

2. **Search for D008D2/D008D5 writes in ROM**: Scan the ROM binary for writes to addresses 0xD008D2 and 0xD008D5. The eZ80 instruction patterns to search for:
   - `LD (0x08D2),A` in .LIL mode: bytes `32 D2 08 D0` (but the prefix byte varies)
   - `LD (addr),HL` patterns near 0xD008D2
   - Any 3-byte address reference containing `D2 08 D0` or `D5 08 D0`
   
   For each write site found, report the surrounding ROM address and disassembly context.

3. **Test with full event loop**: Boot the ROM, run with D00000=0x01 (display path) for 500 iterations to let the OS set up state, then switch to D00000=0x00 (idle) and capture what D008D2/D008D5 contain at the next 0x030173 hit. Compare to the cold-boot idle values.
