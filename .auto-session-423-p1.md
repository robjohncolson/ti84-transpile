# Task: Trace 0x00DB66 (TX send-byte) + 0x00DC0E (RX receive-byte) — TI-Link serial I/O drain primitives

## Context

You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). The transpiler is at `scripts/transpile-ti84-rom.mjs`. Probes run via Node.js and use `TI-84_Plus_CE/cpu-runtime.js` + `TI-84_Plus_CE/peripherals.js`.

## What we know

- **0x00DA8C** is a bidirectional link-state toggle (218 bytes, 0x00DA8C-0x00DB65). Fully decoded in session 422.
- When arg=0 (deactivate), 0x00DA8C checks port 0x3010:
  - bit 5 (TX ready) → CALL 0x00DB66 to drain pending TX (~168 bytes estimated)
  - bit 4 (RX ready) → CALL 0x00DC0E to drain pending RX (~168 bytes estimated)
- These are the TI-Link serial I/O primitives for forced disconnect cleanup.
- Port 0x3010 bits: 0=link active, 4=RX ready, 5=TX ready.
- The TI-Link ISR at 0x0094C0 (523 bytes) handles the legacy serial protocol.

## Your task

1. **Disassemble 0x00DB66 through ~0x00DC0D** (TX send-byte drain). Use the ROM file directly — read bytes starting at file offset 0x00DB66 and decode eZ80 ADL-mode instructions. Document:
   - Exact byte range (start-end)
   - All port I/O (IN/OUT instructions — expect port 0x30xx range)
   - All RAM reads/writes (absolute addresses in 0xD00000+ range)
   - All CALL targets
   - Control flow (loops, conditionals)
   - What "draining TX" means — does it send buffered data? Does it flush? Does it just wait?

2. **Disassemble 0x00DC0E through ~0x00DCB0** (RX receive-byte drain). Same analysis as above.

3. **Write a probe** at `TI-84_Plus_CE/probe-phase423-trace-link-io.mjs` that:
   - Reads the ROM binary
   - Extracts bytes for both functions
   - Validates instruction boundaries
   - Identifies all CALL targets, port I/O, and RAM addresses
   - Prints a structured report

   Use this template for the probe:
   ```javascript
   import { readFileSync } from 'fs';
   const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
   // ... analysis code ...
   ```

4. **Write a report** at `TI-84_Plus_CE/phase423-link-io-report.md` summarizing findings.

## Constraints

- Do NOT modify `cpu-runtime.js`, `peripherals.js`, `browser-shell.html`, or the transpiler
- Do NOT modify any existing probe files

- eZ80 is in ADL mode (24-bit addresses, 3-byte pointers)
