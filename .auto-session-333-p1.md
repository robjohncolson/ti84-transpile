# Task: Fix the Workflow Probe Event Loop (Priority A — ★★★)

## Context
The workflow probe (`TI-84_Plus_CE/probe-workflow-arithmetic.mjs`) is the student-facing forcing function. It boots the TI-84 CE home screen, then injects keypresses (1 + 1 ENTER) and checks if "2" appears on screen.

**Root cause identified in session 332**: After `bootToHomeScreen()` runs, the probe calls `findResumePc(cpu)` which checks `cpu.pc` — but that property DOES NOT EXIST. The `runFrom()` method in `cpu-runtime.js` uses a LOCAL variable `pc`, never stored on the cpu object. So `findResumePc` returns `null`, the probe falls back to `POST_INIT_ENTRY` (0x0802B2), which is a short init ending in `ret`. The stack has 0xFF fill → pops 0xFFFFFF → instant `missing_block` termination.

## What runFrom() returns
```js
return {
  steps,
  lastPc: pc,        // ← THIS is the resume PC
  lastMode: mode,
  halted: cpu.halted,
  termination,
  ...
};
```

## The Fix
Modify `TI-84_Plus_CE/probe-workflow-arithmetic.mjs` (NOT cpu-runtime.js):

1. **`bootToHomeScreen` must return the last `lastPc` and `lastMode`** from the final stage's runFrom call. Change the function signature to return `{ lastPc, lastMode }`.

2. **`findResumePc` should be removed** — it's a broken pattern. Instead, capture the return value.

3. **In `main()`, after `bootToHomeScreen()`**: use the returned `lastPc` as the resume PC for key injection, NOT `cpu.pc` or `POST_INIT_ENTRY`.

4. **For each key in the SEQUENCE loop**: use `lastPc` from the PREVIOUS runFrom result (not findResumePc). The first iteration uses the PC from bootToHomeScreen. Each subsequent iteration uses `pressResult.lastPc` from the previous press.

5. **For _GetCSC integration**: After pressing a key in the matrix, the OS event loop polls _GetCSC (0x03FA09). Instead of blindly running from `lastPc`, consider this pattern used in the missing-blocks probe:
   - Push a sentinel return address (e.g., 0xFEFEFE) on the stack
   - Call _GetCSC directly at 0x03FA09
   - When it returns to 0xFEFEFE (missing_block termination), the scan code is in register A
   - Then call the OS dispatch with the scan code loaded

   However, the SIMPLEST first fix is just to capture lastPc properly and see how far that gets us. Don't over-engineer.
