# Auto-Session 394 P1: Trace 0x030353 Key Dispatch Entry from Event Loop

## Context
We are tracing the TI-84 Plus CE OS key dispatch chain. Session 393 found that 0x030353 contains `JP 0x02FE73`, which is one of 3 callers of the key dispatcher function at 0x02FE84 (the multi-block function spanning 0x02FE84-0x030102, 639 bytes, 31 reachable blocks).

The key dispatch chain so far:
- Event loop at 0x003A73 calls _GetCSC at 0x003D5A
- Dispatch at 0x003A7D → 0x001713 → 0x001853 → 0x0158DE → ... → 0x030300 (event consumption)
- 0x030300 normal key path at 0x03032C writes kbdKey/kbdToken to RAM, then JP 0x02FE73
- 0x02FE73 reads kbdKey from D0058C and enters the dispatch chain

Three callers of 0x02FE73/0x02FE84:
1. 0x02FFEE — JP NZ 0x02FE84 (internal re-entry)  
2. 0x030130 — JP 0x02FE84
3. 0x030353 — JP 0x02FE73

We need to know: what function CONTAINS 0x030353? This connects the event loop to the key translation chain.

## Task
Write a Node.js probe at `TI-84_Plus_CE/probe-phase394-trace-030353.mjs` that:

1. Reads the ROM file at `TI-84_Plus_CE/ROM.rom` (4MB binary)
2. Does a BACKWARD scan from 0x030353 to find the start of the containing function/block. Look for common function prologue patterns (PUSH AF, PUSH BC, PUSH IX, DI, etc.) or a preceding RET/JP/JR that would indicate the previous function ended.
3. Does a FORWARD scan from 0x030353 to find what comes after the JP instruction (is it dead code? is there a fall-through from somewhere else?).
4. Disassembles the region 0x030300-0x030400 (256 bytes) instruction by instruction using the eZ80 encoding:
   - 0xC3 = JP nn (3 bytes for address in ADL mode)
   - 0xC2/CA/D2/DA/E2/EA/F2/FA = JP cc,nn (conditional JP)
   - 0xCD = CALL nn
   - 0xC9 = RET
   - 0xCB prefix = bit operations
   - 0xDD/FD prefix = IX/IY operations
   - 0xED prefix = extended ops
   - 0x18 = JR e
   - 0x20/28/30/38 = JR cc,e
   - Standard 8080-like opcodes otherwise
   
   **IMPORTANT**: This is eZ80 in ADL mode. All addresses are 3 bytes (24-bit), not 2 bytes. JP nn = opcode + 3 address bytes = 4 bytes total. CALL nn = opcode + 3 address bytes = 4 bytes total.

5. Find ALL references to 0x030353 in the ROM (search for bytes pattern for JP/CALL to 0x030353: the address in little-endian is 0x53 0x03 0x03).
6. Find what calls 0x030300 — search for CALL/JP to 0x030300 (bytes: 0x00 0x03 0x03 with preceding C3/CD/C2/CA/etc).
