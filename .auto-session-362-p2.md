# Auto-Session 362 — P2: Trace 0x00BC31↔0x00BC47 Pattern

## Context

TI-84 Plus CE ROM transpilation project. Boot currently reaches 476 unique blocks. The last 10 blocks before termination show repeated visits to addresses in the 0x00BCxx range:

```
0x00BC31 → 0x00BC47 → 0x00BC31 → 0x00BC3C → 0x00BC6C → 0x00BC72 → 0x006500 → 0x006CC6 → 0x006D5D → 0x0021C2 → missing_block at 0x4C7B21
```

We need to understand what the 0x00BC31–0x00BC72 blocks are doing. Are they a loop? A search routine? An initialization sequence?

## Task

Write a probe script `TI-84_Plus_CE/probe-phase362-trace-BC-blocks.mjs` that:

1. **Boots the OS** with:
   - Timer interrupts disabled: `createPeripheralBus({ timerInterrupt: false })`
   - GPIO = 0xEF
   - RAM trampoline enabled (already in cpu-runtime.js)
   - Run for 5000 steps

2. **Counts how many times each 0x00BCxx block is visited** during the full boot. Record visit counts for at least: 0x00BC31, 0x00BC47, 0x00BC3C, 0x00BC6C, 0x00BC72.

3. **Records the full transition sequence** for the last 50 blocks before termination (not just the last 10).

4. **Disassembles ALL blocks in the 0x00BC00–0x00BD00 range** that are visited during boot. Use the decoder:
   ```js
   import { decodeInstruction } from './ez80-decoder.js';
   // decodeInstruction(romBuffer, offset, adlMode) returns {mnemonic, operands, length}
   ```
   For each block, disassemble until RET/JP/JR or 64 bytes.

5. **Identifies the calling context** — what block calls into 0x00BC31 the first time? What does 0x00BC72 jump to when it exits the BC-block cluster?

6. **Checks for port I/O** in the BC blocks — do any of them do IN or OUT instructions? This would indicate hardware polling.
