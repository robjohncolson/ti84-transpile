# Task: Cross-Reference Key-to-Token Table with _GetCSC Scan Codes

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`.

The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 binary).

## What We Know

### The OS Event Loop Dispatcher (0x099921)
Session 514 fully mapped 0x099921 — it has 38 dispatch entries. The dispatcher calls 0x09BBAD to get a keycode into register A, then does a CP/JP cascade:
- 19 exact key handlers (CP val / JP Z,handler)
- 19 range handlers (CP val / JP C,handler)
- Default fallthrough: JP 0x061D1A (unhandled keys -> key-to-token table)

Key exact handlers from session 514:
- 0x04=MUL, 0x07=CLEAR, 0x09=(-), 0x11=DECIMAL, 0x29=GRAPH, 0x2B=ZOOM
- 0x2C=WINDOW, 0x2D=Y=, 0x3E=TABLESET, 0x40=QUIT, 0x72=SOLVE, 0x73=SIMUL_EQ
- 0xAA=OFF, 0xB0=TOKEN_SEL, 0xBB=ANGLE_CMD, 0xE6=RESET, 0xEF=SELF_TEST, 0xFF=TEST_MODE

### The Key-to-Token Table (0x061CFA-0x061DB1)
Session 517 extracted 45 entries. Each is LD A,<token>; JR <offset to 0x061DB2>.
Notable tokens: 0x81-0x88 (control), 0x89=DEL, 0x8A=INS, 0x2D='-', 0x2E='.', 0x30='0', 0x31='1', etc.
All converge on 0x061DB2 -> store token -> CALL 0x03E1B4 -> clear flags -> longjmp.

### The Keyboard Matrix
File: `TI-84_Plus_CE/keyboard-matrix.md`
Maps physical keys to _GetCSC scan codes.

### The Missing Link
Keys NOT handled by exact/range matches in 0x099921 fall through to JP 0x061D1A. We need to trace which scan codes ultimately reach which entries in the key-to-token table at 0x061CFA. The code at 0x061D1A (decoded in session 516) does a longjmp then routes to the token table — decode HOW it indexes into the table.

## Your Task
Create a probe `TI-84_Plus_CE/probe-phase518-scancode-token-map.mjs` that:

1. **Read keyboard-matrix.md** to extract all _GetCSC scan codes and their key names.

2. **Read the 0x099921 dispatcher** from ROM bytes. Re-extract the CP/JP cascade. For each scan code 0x00-0xFF, determine which handler it routes to.

3. **Identify which scan codes reach 0x061D1A** (the fallthrough path to the key-to-token table).

4. **Decode the indexing mechanism at 0x061D1A**: Read ROM bytes at 0x061D1A and following. How does it compute which entry in the 0x061CFA-0x061DB1 table to jump to? Is it a direct jump table indexed by scan code? A subtraction + multiply? Decode the code.

5. **Build the complete map**: For every physical key on the TI-84 CE keyboard, show:
   - Key name
   - _GetCSC scan code (hex)
   - Dispatcher route (exact handler / range handler / fallthrough)
   - If routed to token table: which token byte it produces

6. **Output**: Print a formatted table of all mappings.
