# Task: Decode 0x06023E — Screen Region Fill

## Context
This is the TI-84 Plus CE ROM transpilation project. Session 491 found that 0x06023E writes 1404 black pixels across rows 0-26 — a large region. It could be screen-clear, region fill, or possibly the actual cursor draw if the large pixel count was due to test setup. We need to understand what this function actually does.

## What to do

Create a probe `TI-84_Plus_CE/probe-phase492-decode-06023E.mjs` that:

### Part 1: Static disassembly of 0x06023E
Read the ROM bytes at 0x06023E and disassemble instruction-by-instruction. Print each instruction with address, raw bytes, and mnemonic. Continue until you hit a RET or reach 150 bytes. Look for:
- References to D00595 (cursor row) and D00596 (cursor col)
- References to D0059C (VRAM pointer)
- References to D008D2/D008D5 (LCD window registers)
- CALL/JP instructions (note targets)
- LDIR/LDDR (block copy)
- Loop structures (DJNZ, JR, conditional JP back)
- Any immediate values suggesting screen dimensions (320, 240, 12, 16)

Note: eZ80 mode prefixes are 0x40 (SIS), 0x49 (LIS), 0x52 (SIL), 0x5B (LIL). Check for these before decoding the next opcode.

### Part 2: Find all callers of 0x06023E
Scan the entire ROM (0x000000-0x3FFFFF) for:
- CALL 0x06023E: bytes CD 3E 02 06
- JP 0x06023E: bytes C3 3E 02 06
- Also check with mode prefixes (0x40/0x49/0x52/0x5B before CD/C3)
Report all call sites with their addresses.

### Part 3: Dynamic test with 3 cursor positions
Boot the CPU (120,000 steps, timer IRQ disabled). Then test 0x06023E with:
- Test A: D00595=0, D00596=0 (row 0, col 0)
- Test B: D00595=5, D00596=13 (row 5, col 13)  
- Test C: D00595=9, D00596=25 (row 9, col 25)

For each test:
1. Fill VRAM (0xD40000, 76800 bytes) with 0xFF (white) before the call to get clean baseline
2. Set PC=0x06023E, SP=0xD1A87E, push return sentinel 0x064910
3. Run up to 50,000 steps or until PC reaches return sentinel
4. Count non-0xFF bytes in VRAM after
5. Find bounding box of all non-0xFF writes (row=offset/320, col=offset%320)
6. Report if the write region changes with cursor position

### Part 4: Relationship to 0x06029D and 0x061000
Print the address distance between these three functions. Check if 0x06023E calls either 0x06029D or 0x061000 (or vice versa) in its disassembly. These three functions are in the same 0x060000 range and may be related parts of the text editing / cursor system.

## API

```js
import fs from 'node:fs';
import { execFileSync } from 'node:child_process';
import { fileURLToPath } from 'node:url';
import zlib from 'node:zlib';

function ensureTranspiledRom() {
  const transpiled = new URL('./ROM.transpiled.js', import.meta.url);
  const gz = new URL('./ROM.transpiled.js.gz', import.meta.url);
  if (fs.existsSync(transpiled) || !fs.existsSync(gz)) return;
  console.log('ROM.transpiled.js missing; expanding ROM.transpiled.js.gz');
  try {
    execFileSync('gzip', ['-dk', fileURLToPath(gz)], {
      cwd: fileURLToPath(new URL('.', import.meta.url)),
      stdio: 'inherit',
    });
  } catch (error) {
    console.log(`gzip failed (${error.message}); falling back to node:zlib`);
    fs.writeFileSync(transpiled, zlib.gunzipSync(fs.readFileSync(gz)));
  }
}

ensureTranspiledRom();

const { createCPU } = await import('./cpu-runtime.js');
const { createPeripheralBus } = await import('./peripherals.js');
```

- Look at existing probes (e.g., `TI-84_Plus_CE/probe-phase491-decode-061000.mjs`) for the exact CPU creation pattern. The API is either `createCPU(bus)` or `createCPU()` followed by `bus.install(cpu)`.
- `cpu.mem[addr]` for memory access. ROM (< 0x400000) is read-only.
- `cpu.step()` executes one instruction. `cpu.pc`, `cpu.sp` are register accessors.
- Push return sentinel: `cpu.sp -= 3; cpu.mem[cpu.sp] = addr & 0xFF; cpu.mem[cpu.sp+1] = (addr >> 8) & 0xFF; cpu.mem[cpu.sp+2] = (addr >> 16) & 0xFF;`

The probe runs and prints: (1) full disassembly, (2) all callers, (3) whether writes move with cursor position, (4) relationship to 0x06029D and 0x061000. This determines if 0x06023E is screen-clear, region fill, or an alternate cursor draw.
