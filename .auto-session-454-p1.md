# Task: VRAM Write Intercept Probe — Determine If Subsequent Key Rendering Is Idempotent

## Context
In auto-session 453, we discovered that only key "1" (the first injected key) produces 6,078 VRAM byte changes (0x00→0xFF). Keys "+", "1"(second), and "ENTER" show ZERO VRAM diff despite D177B7 being consumed (0x55→0x00) for ALL keys. The question: are subsequent keys writing the SAME values to the SAME VRAM addresses (idempotent repaint), or are they truly not writing at all?

## Deliverable
Create `TI-84_Plus_CE/probe-phase454-vram-write-intercept.mjs` — a probe that intercepts ALL writes to the VRAM address range (0xD40000–0xD40000+320*240*2) during each key's processing, counting:
1. Total VRAM write operations per key
2. How many of those writes changed the value (before != after)
3. How many wrote the same value that was already there (idempotent)

## Implementation approach
Use the existing probe `probe-phase453-rearm-d177b7.mjs` as your template (copy its boot sequence, key injection, re-arming logic). The key modification: **monkey-patch `mem.write8` and `mem.write16`** (or whatever the memory write path is) to intercept writes in the D40000 range.

Look at `cpu-runtime.js` to find how memory writes work. The runtime uses a `mem` Uint8Array. The transpiled code writes via `write8(addr, val)`, `write16(addr, val)`, `write24(addr, val)` functions. You need to wrap these to count VRAM-range writes.

### Boot sequence (copy from probe-phase453-rearm-d177b7.mjs):
1. Create executor with `createPeripheralBus({ timerInterrupt: false })`
2. Boot: run BOOT_ENTRY (0x000000) for 50 steps, then KERNEL_INIT_ENTRY (0x08C331), POST_INIT_ENTRY (0x0802B2), stages [0x0A2B72, 0x0A3301, 0x0A29EC, 0x0A2854]
3. Copy flash self-test at 0x0802C5 (16 bytes from ROM to RAM at 0xD18C22)
4. Set D14091=1, D177B7=0x55, D177BA gate

### Per-key injection (same as 453 probe):
- Clear D141B5, set D00587=scanCode, set bit 3 of D00080
- Re-arm D177B7=0x55 and clear D141B5=0x00 before EACH key
- Run event loop at 0x003A73 with HALT bypass

### VRAM write tracking:
Before each key injection, install counters:
```javascript
let vramWriteCount = 0;
let vramChangedCount = 0;
let vramIdempotentCount = 0;

const origWrite8 = cpu.write8.bind(cpu); // or however write8 is accessed
cpu.write8 = function(addr, val) {
  if (addr >= 0xD40000 && addr < 0xD40000 + 320*240*2) {
    vramWriteCount++;
    if (cpu.mem[addr] !== val) vramChangedCount++;
    else vramIdempotentCount++;
  }
  return origWrite8(addr, val);
};
```
