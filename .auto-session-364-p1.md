# Auto-Session 364 — Priority 1: Trace What Initializes the Linked-List Data at 0xD14095

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The OS ROM (eZ80 machine code) has been lifted into JavaScript. Boot reaches 476 blocks then crashes because of SP corruption.

**The SP corruption chain (found in session 363)**:
1. Block 0x00BC47 at instruction 0x00BC4D does `LD IX, (IX-30)` — a linked-list pointer follow
2. On iteration 1, IX=0xD140B3, so (IX-30) = memory at 0xD14095
3. The value at 0xD14095 is 0x014C7B (a ROM address, NOT a valid RAM pointer)
4. IX becomes 0x014C7B → all subsequent IX-relative accesses read ROM
5. Block 0x00BC72 does `LD SP, IX` → SP=0x014C7B (ROM) → crash

## Your Task
Create a probe that traces ALL writes to RAM address 0xD14095 (and nearby ±16 bytes: 0xD14085–0xD140A5) during boot. We need to know:

1. **Who writes 0x014C7B to 0xD14095?** Is it the LDIR block-copy at 0x000D82, OS init code, or is it uninitialized RAM (default 0x00 bytes that happen to look like 0x014C7B)?
2. **What step number does the write happen at?** (relative to the 2688-step boot)
3. **What block is executing when the write occurs?**
4. **Is the value 0x014C7B written as a single 24-bit value, or assembled from separate byte writes?**
