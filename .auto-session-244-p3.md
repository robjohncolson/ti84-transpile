# Task: Trace 0x088772 — second sub-call from 0x051ADC (xxxx)

## Context
Session 243 decoded 0x051ADC as a mode filter function. It showed 0x051ADC calls 0x088772 as a second sub-function. Its NZ return causes 0x051ADC to take the "pass through" path (Z=clear). We need to understand what 0x088772 does.

The mode filter at 0x051ADC:
- Reads D007E0, cascades CP comparisons
- Calls 0x09D06B (sub-function 1)
- Calls 0x088772 (sub-function 2) — THIS TASK
- Its NZ return → 0x051ADC returns Z=clear (pass through, NOT filtered)
- Home screen: Z=set (filtered out) in 11 steps

1. **Hex dump** ROM bytes at 0x088772-0x0887E0 (110 bytes)
2. **Static disassembly** of 0x088772-0x0887E0 using the eZ80 decoder
3. **RUN 1**: Call 0x088772 directly with home-screen state:
   - D007E0 = 0x00, D00824 = 0x00
   - IX = 0xD1A860, IY = 0xD00080, SP = 0xD1987E
   - Timer interrupts disabled
   - 200 steps, trace:
     - All unique blocks visited
     - All RAM reads and writes
     - Return value (A register, flags Z/NZ)
     - All CALL destinations
4. **RUN 2**: Call 0x088772 with D007E0 = 0x40
5. **RUN 3**: Call 0x088772 with D007E0 = 0x5B
6. **RUN 4**: Call 0x088772 with D00824 = 0x4A (the special value 0x051ADC checks)

**Report**: What does 0x088772 do? What determines its Z/NZ return? How does it relate to display/mode state?
