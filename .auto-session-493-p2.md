# Auto-Session 493 P2: Timer IRQ Cursor Trace

## Context
We are reverse-engineering the TI-84 Plus CE OS ROM. The text cursor blink on real hardware is timer-driven. All probes so far have run with `timerInterrupt: false`, which means the timer ISR path that drives cursor blinking has never been exercised for cursor-specific functions. Session 492 confirmed that the idle loop at 0x03030E does NOT reach any cursor functions (0x060000-0x062000) within 30K steps — the cursor blink path likely requires the timer IRQ to be active.

Key addresses:
- 0x061000/0x061003: cursor erase (clear-to-screen-bottom), zero direct callers (called via indirect dispatch)
- 0x060000-0x062000: text editing system range
- Timer ISR: 0x0019BE (reduced handler), reaches 0x001ACF (timer service)
- D00595/D00596: cursor row/col
- IY = 0xD00080

## Task
Create a probe `TI-84_Plus_CE/probe-phase493-timer-cursor-trace.mjs` that:

1. **Boot the OS** using the standard 3-stage init (see existing probes for the pattern):
   - Stage 1: PC=0x000000, ~12K steps
   - Stage 2: PC=0x0002B0, ~5K steps  
   - Stage 3: PC=0x020000, ~35K steps

2. **Enable timer IRQ** after boot:
   - Use `bus.setTimerEnabled(true)` if available, OR set `timerInterrupt: true` in createPeripheralBus options
   - The timer fires every `timerInterval` ticks (default ~200). This may need to be higher (500-1000) to avoid the ISR consuming all CPU time.

3. **Set up cursor state**:
   - Set D00595=5, D00596=13 (cursor at row 5, col 13)
   - Set D00092 (IY+0x12, cursor flags) to various values that might enable cursor blink

4. **Instrument and trace**: Hook or monitor execution to detect when ANY address in 0x060000-0x062000 is reached. Specifically:
   - Set PC to the idle loop entry (0x03030E or the main scheduler at 0x0015F7)
   - Run for 100K-200K steps with timer IRQ enabled
   - After every N steps (e.g., every 1000), check if PC has entered 0x060000-0x062000
   - Log every unique address in that range that gets hit
   - Also log timer ISR fire count and which functions the ISR dispatches to

5. **Try multiple cursor flag values**: Run the trace with D00092 set to: 0x00, 0x01, 0x02, 0x04, 0x08, 0x10, 0x20, 0x40, 0x80, 0xFF. The cursor blink enable flag is unknown — one of these may activate it.

## Important Safety Notes
- Timer-enabled probes CAN infinite-loop. The watchdog (`scripts/run-probe.mjs --max-time 180`) is the only enforced cap.
- Keep step limits strict: 200K max per trace run, 2M total across all flag values
- If execution enters a tight loop (same PC range for >10K steps), break out and report

## How to detect function entry
The simplest approach: after each cpu.step() call, check if `cpu.pc >= 0x060000 && cpu.pc < 0x062000`. Log the PC value when this condition is first met and each time it enters a new 0x100-aligned region.
