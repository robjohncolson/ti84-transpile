# Task: Map 0x001853 Internal Behavior (Key Handler)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. When a key is pressed and dispatched through the event loop, the OS calls handler 0x001853. From session 379 traces: the dispatch path is 0x003A7D → 0x001713 → 0x001853 → 0x0158DE (post-handler).

We know 0x001853:
- Sets 0xD177BA = 0x7F
- Does port 0x09 I/O operations
- Calls 0x0158DE (post-key-action dispatcher)

But we don't know what the port 0x09 operations do, what other RAM locations it modifies, or what the overall purpose of 0x001853 is.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase380-handler-001853.mjs` that:

1. Reads `TI-84_Plus_CE/ROM.rom` as a binary buffer
2. Statically disassembles 0x001853 through all its internal branches until RET or known external calls
3. For each instruction, document:
   - Any RAM writes (LD (addr), reg)
   - Any port I/O (IN/OUT to port 0x09 or others)
   - Any CALL targets
   - Any conditional branches and what they test
4. Also run a dynamic trace: boot the ROM using `cpu-runtime.js`, inject ENTER key (scan code 0x29 via `peripherals.setKeyPressed`), and run until 0x001853 is reached, then trace all instructions within 0x001853 until it returns

## Reference files
- `TI-84_Plus_CE/ez80-decoder.js` — `decodeInstruction(rom, pc)` for static disassembly
- `TI-84_Plus_CE/cpu-runtime.js` — `createCPU()`, `runFrom()` for dynamic execution

## Key addresses
- 0x001853: The key handler we're investigating
- 0x0158DE: Post-key-action dispatcher (called by 0x001853)
- 0x001713: Intermediate dispatcher between event loop and handler
- 0xD177BA: RAM location set to 0x7F by this handler
- Port 0x09: Unknown purpose — this is what we want to understand
