# Auto-Session 216 — P3: Display-result loop token destinations (BufInsert cursor tracking)

## Context

We're reverse-engineering the TI-84 Plus CE OS ROM (eZ80). The display-result loop at 0x080CFE copies characters from the format buffer at 0xD0060E into the edit buffer via BufInsert (0x05E2A0).

Session 215 found:
- Loop at 0x080CFE iterates correctly with editCursor 0xD0243A seeded to 0xD00A00
- With "42.5\0" in format buffer, **4 BufInsert calls fire** (correct for 4 characters)
- BUT: edit buffer at 0xD00A00 is **empty (all zeros)** after the loop completes
- Hypothesis: BufInsert writes the first token, then the cursor advances past 0xD00A00, so subsequent tokens go elsewhere. Or a post-loop memcpy/LDIR overwrites the buffer.

## Task

Build a probe `TI-84_Plus_CE/probe-phase216-bufinsert-cursor-tracking.mjs` that:

### Part A: Track editCursor after each BufInsert call
1. Set up standard runtime
2. Seed: format buffer at 0xD0060E = "42.5\0" (bytes: 0x34, 0x32, 0x2E, 0x35, 0x00)
3. Seed: editCursor 0xD0243A = 0xD00A00 (3-byte little-endian pointer)
4. Seed: IY = 0xD00080, BIT 4,(IY+5) = SET
5. Enter at 0x080CFE
6. Run step-by-step (up to 500 steps), and after EVERY step:
   - Read editCursor at 0xD0243A (3 bytes LE)
   - Read edit buffer 0xD00A00-0xD00A0F (16 bytes)
   - If the current block is 0x05E2A0 (BufInsert entry) or we just returned from BufInsert, log:
     - Step number
     - editCursor value
     - DE register value (the token being inserted)
     - Edit buffer contents (first 16 bytes at 0xD00A00)
7. After loop completes (JR Z at block 0x080CFE when A=0x00):
   - Dump final editCursor value
   - Dump edit buffer 0xD00A00-0xD00A1F (32 bytes)
   - Dump any memory that editCursor points to (16 bytes from cursor address)

### Part B: Check for post-loop overwrites
1. After the loop exits (JR Z to 0x080D14), continue execution for 200 more steps
2. The post-loop code calls 0x05E3AE then `RES 5,(IY+5)` then RET
3. Log: every block visited, and after each step check if edit buffer 0xD00A00-0xD00A0F changed
4. Specifically watch for LDIR/LDDR instructions that might clear the buffer

### Part C: Single-character test
Same as Part A but with format buffer = "5\0" (just one character: 0x35, 0x00). This isolates the simplest case:
- Does the single character appear at 0xD00A00?
- Where does editCursor point after?
