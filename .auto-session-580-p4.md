# Task: Map D0146D — Pending Key Code Buffer (Full Reference Scan)

## Context
This is the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80).

Session 579 discovered D0146D is a "pending key code" buffer, DISTINCT from D0058E ("previous key"). The key dispatch pre-processor at 0x06CE7F reads from D0146D to get the current key, while the main dispatch cascade at 0x08C3C3+ uses D0058E for catalog sub-dispatch context. Understanding who WRITES to D0146D vs who READS from it maps the key delivery pipeline.

Known D0146D context:
- READ at 0x06CE7F (key pre-processor, session 579)
- D0058E is the "previous key" buffer used in the 0x08C3C3+ cascade for catalog dispatch

## Deliverable
Create `TI-84_Plus_CE/probe-phase580-map-D0146D.mjs` that:

1. Reads ROM.rom from disk (`fs.readFileSync('./TI-84_Plus_CE/ROM.rom')` — returns a Buffer)
2. Scans the ENTIRE ROM (0x000000–0x3FFFFF) for all references to D0146D:
   - 3-byte LE address pattern: bytes 6D 14 D0 (little-endian for 0xD0146D)
   - For each hit, decode the instruction AT that address to determine if it's a READ (LD A,(D0146D), LD reg,(D0146D)) or a WRITE (LD (D0146D),A, LD (D0146D),reg) or an ADDRESS-OF (LD HL,D0146D etc.)
   - Use the decoder: `import { decodeInstruction } from './ez80-decoder.js';` — call as `decodeInstruction(romBuffer, offset, 'adl')` which returns `{ mnem, op_str, length }`
3. Also scan for D0146E and D0146F (adjacent bytes — often part of the same key buffer structure)
4. For each reference, try to decode 2 instructions before and 2 after for context
5. Categorize: WRITE refs (who sets the key code?), READ refs (who consumes it?), ADDRESS refs (who passes a pointer?)
6. Also scan D0058E (6D 05 D0... wait — 0xD0058E = 8E 05 D0) for comparison — how many refs does the "previous key" buffer have?
7. Print: total ref count per variable, categorized READ/WRITE/ADDRESS breakdown, sorted by address

## Important constraints
- The decoder API is `decodeInstruction(buffer, offset, 'adl')` → `{ mnem, op_str, length }`. The third param MUST be the string `'adl'`, not boolean `true`.
- ROM is a Node.js Buffer, NOT a DataView/ArrayBuffer. Read bytes with `rom[offset]` or `rom.readUInt8(offset)`.
- D0146D in little-endian bytes = 0x6D, 0x14, 0xD0. Scan for this 3-byte pattern.
- D0058E in little-endian bytes = 0x8E, 0x05, 0xD0.
- For hex formatting: `'0x' + val.toString(16).toUpperCase().padStart(6, '0')`.
- File must be an ES module (`.mjs` extension, use `import` not `require`).
- Do NOT modify any existing files. Only create the new probe file.

## Success criterion
Running `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase580-map-D0146D.mjs` exits 0 and prints categorized ref counts for D0146D and D0058E with READ/WRITE/ADDRESS breakdown.
