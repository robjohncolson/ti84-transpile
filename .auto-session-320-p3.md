# Task: Decode the 0x0401E9 and 0x048E7B Crash Paths

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 binary). Session 319 found that 0x0003AC is the crash entry in the OS mega-table (JP 0x0019B5 → DI; OUT0 0x10; HALT). The mega-table has exactly 6 crash entries (0, 1, 2, 3, 4, 2022), but 2 additional sites reference 0x0003AC OUTSIDE the mega-table:
- JP at 0x0401E9
- CALL at 0x048E7B

These are runtime integrity checks that fail to the crash handler.

## What to do
1. Read the ROM at offsets 0x0401C0-0x040280 (~192 bytes around 0x0401E9) and 0x048E50-0x048EE0 (~144 bytes around 0x048E7B).
2. Disassemble as eZ80 ADL-mode code. Key opcodes:
   - `LD A,(addr24)` = 3A xx xx xx
   - `CP imm8` = FE xx
   - `JP Z/NZ/C/NC,addr24` = CA/C2/DA/D2 xx xx xx
   - `CALL addr24` = CD xx xx xx
   - `JP addr24` = C3 xx xx xx
   - `RET` = C9
   - `BIT n,reg` = CB xx (bit test)
3. For each crash path:
   - What function contains this reference?
   - What condition leads to the crash? (What test fails?)
   - What is the function's normal (non-crash) path?
   - Who calls this function? Search for `CALL 0x0401xx` and `CALL 0x048Exx` patterns in ROM.
4. Determine what runtime integrity checks these represent — are they stack overflow checks, memory corruption checks, hardware fault checks, etc.?

## Deliverables
Create `TI-84_Plus_CE/phase320-crash-paths-report.md` with:
- Full disassembly of both functions (or at least the crash-path portion)
- The condition that triggers each crash
- Normal vs crash control flow for each function
- Caller analysis
- Classification of what kind of integrity check each represents
