# Auto-Session 491 — P2: Find the Cursor Draw Companion to 0x061000

## Context

Session 490 confirmed that 0x061000 is the text cursor ERASE function — it writes 0xFF (white) pixels in a 12×16 rectangle at the cursor position (D00595/D00596). The cursor blink mechanism requires a complementary DRAW function that writes cursor glyph pixels (not 0xFF) at the same position. The draw+erase pair constitutes the complete cursor blink.

Three hypotheses for the draw companion:
1. A nearby function in the 0x060000-0x062000 range that writes non-0xFF values to VRAM at cursor position
2. A function that calls 0x0059C6 (the character renderer) with cursor glyph codes 0xE1, 0xE2, or 0xE3
3. The OS event loop alternates: call 0x0059C6 with cursor glyph to DRAW, call 0x061000 to ERASE

## Task

Create a probe `TI-84_Plus_CE/probe-phase491-cursor-draw-search.mjs` that searches for the cursor draw companion:

### Part 1: Scan 0x060000-0x062000 for D00595/D00596 readers

Read ROM.rom bytes from 0x060000 to 0x062000. Search for byte patterns that reference D00595 and D00596:
- LD A,(D00595) = 3A 95 05 D0 (or FA 95 05 for SIS prefix)
- LD A,(D00596) = 3A 96 05 D0 (or FA 96 05 for SIS prefix)
- Also check for HL/DE/BC loads from these addresses

List every function entry in this range that reads either variable. For each, note what other references are nearby (VRAM writes, calls to 0x0059C6, glyph codes 0xE1-0xE3).

### Part 2: Find all callers of 0x061000

Search the entire ROM (0x000000-0x3FFFFF) for:
- CALL 0x061000: CD 00 10 06
- JP 0x061000: C3 00 10 06
- CALL.SIS variants if applicable

For each caller, check what ELSE that caller calls — especially look for calls to 0x0059C6 nearby (within 100 bytes), which would suggest the caller alternates cursor draw and erase.

### Part 3: Dynamic test of nearby functions

For any function found in Part 1 that reads D00595/D00596 (other than 0x061000 itself), run a dynamic test:
- Boot CPU, run 120000 steps to idle
- Set D00595=0, D00596=0, set cursor style flags
- Snapshot VRAM
- Call the function (set PC, push return address, run up to 5000 steps)
- Diff VRAM — look for non-0xFF writes at cursor position

### Part 4: Check if 0x0059C6 is the draw mechanism

The character renderer 0x0059C6 draws any glyph at the current cursor position. The OS may simply call 0x0059C6 with glyph code 0xE1/0xE2/0xE3 (the cursor glyphs discovered in session 486) to DRAW the cursor, then call 0x061000 to ERASE it. To test this:
- Search ROM for sequences where both 0x0059C6 and 0x061000 are called within 200 bytes of each other
- Search for LD A, 0xE1 (3E E1) or LD A, 0xE2 (3E E2) or LD A, 0xE3 (3E E3) near calls to 0x0059C6

## Key addresses

- ROM file: `TI-84_Plus_CE/ROM.rom` (4MB flat binary)
- 0x061000 = confirmed cursor erase (writes 0xFF to 12×16 cell at cursor pos)
- 0x0059C6 = character renderer (draws glyph at cursor position)
- D00595 = cursor row, D00596 = cursor column
- D00092 = cursor flags (bit patterns for cursor style)
- Cursor glyph codes: 0xE1 (block cursor), 0xE2 (underline), 0xE3 (insert bar)
- VRAM: 0xD40000-0xD52BFF
