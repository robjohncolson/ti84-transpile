# Task: Decode Idle Cursor Pixel Write Mechanism

## Context
We're transpiling the TI-84 Plus CE ROM (eZ80) to JavaScript. Session 480 proved that the idle cursor path (D00000=0x00) produces 72 VRAM bytes via the 0x03013A→0x030202 chain. However, 0x04E950=0 hits, 0x0059C6=0 hits, 0x005A75=0 hits — so the cursor blink writes VRAM through a DIFFERENT mechanism than the character renderer.

The idle path flow is: 0x03013A→0x03013F→0x030145→0x03015E→0x030173→0x030202→0x03020A→0x030177→0x02FDAC→0x05C76C.

0x030202 is the cursor glyph selector: returns cursor character A=0xE1/0xE2/0xE3 based on D00092 bits 3/4/5. After 0x030202 returns, something writes to VRAM. We need to find WHAT.

Key: 0x03013A decoded in session 474: At 0x03015E it tests D00095 bit 1 → CALL 0x030202 → JR NZ → CALL 0x04E950. But session 480 showed 0x04E950=0 hits! So either the JR NZ path is taken (skipping 0x04E950), or the VRAM write happens inside 0x030202 itself or in a function called between 0x030202 and 0x04E950.

## Deliverable
Create `TI-84_Plus_CE/probe-phase481-cursor-write-mechanism.mjs` that:

1. Does 3-stage boot (0x080000, 0x0802B2, 0x08C331, each 150K steps)
2. Sets up idle mode state (D00000=0x00, D00092=0x16, etc.)
3. Refreshes D00092 and D000C6 at each 0x02FDBE iteration (like session 480's probe)
4. Tracks a WIDE set of PCs in the 0x030100-0x030400 range (every ~16 bytes) to find which sub-functions fire
5. Also tracks: 0x04E950, 0x03FBF9, 0x04C979, 0x0059C6, 0x005A75, 0x030202, 0x03020A, 0x030177
6. Captures VRAM before and after, reports byte diff
7. CRITICAL: Also does a ROM hex dump of bytes at 0x030170-0x0301F0 (128 bytes) and 0x030200-0x030280 (128 bytes) to identify the VRAM write instructions in the cursor path

The hex dump should show raw ROM bytes in the format: `ADDR: XX XX XX XX ...` (16 bytes per line).

## Template Pattern (MUST follow exactly)
```javascript
import { readFileSync } from "node:fs";
import { createExecutor } from "./cpu-runtime.js";
import { createPeripheralBus } from "./peripherals.js";
import { PRELIFTED_BLOCKS } from "./ROM.transpiled.js";

const MEM_SIZE = 0x1000000;
const VRAM_BASE = 0xd40000;
const VRAM_SIZE = 320 * 240 * 2;
const STACK_RESET_TOP = 0xd1a87e;
const EVENT_LOOP_HEAD = 0x02fdbe;
const RET_POINTS = new Set([0x02fe88, 0x02fde5, 0x02fe21]);

const mem = new Uint8Array(MEM_SIZE);
const rom = readFileSync(new URL("./ROM.rom", import.meta.url));
mem.set(rom.subarray(0, MEM_SIZE), 0);
const peripherals = createPeripheralBus();
const executor = createExecutor(PRELIFTED_BLOCKS, mem, { peripherals });

function runFrom(pc, steps, onBlock) {
  return executor.runFrom(pc, "adl", { maxSteps: steps, maxLoopIterations: 200000, onBlock });
}
function hex(v, w = 6) { return "0x" + (v >>> 0).toString(16).toUpperCase().padStart(w, "0"); }

// 3-stage boot
runFrom(0x080000, 150000);
runFrom(0x0802b2, 150000);
runFrom(0x08c331, 150000);

// Set state
mem[0xd00824] = 0x48;
mem[0xd007e0] = 0x48;
mem[0xd14091] = 0x01;
mem[0xd00000] = 0x00;  // IDLE path
mem[0xd00092] = 0x16;
mem[0xd00089] |= 0x10;
mem[0xd000c6] = 0x01;
mem[0xd000b4] = 0x01;

executor.cpu.sp = STACK_RESET_TOP;
```

- At EVENT_LOOP_HEAD: refresh D00092 (|= 0x16) and D000C6 (|= 0x01), reset SP
- At RET_POINTS entries: return "stop" to intercept returns back to event loop head

Run for 500K steps.
