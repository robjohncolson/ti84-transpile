# Task: Trace 0x05622E — A+keyExtend Pack Helper

## Context
In the TI-84 Plus CE OS token pipeline, function 0x022331 calls `CALL 0x05622E` before building the token descriptor. From session 294's analysis of 0x0AF408, we know this helper checks values 0xFE and 0xFC. The question is: what does it actually do with the token code in register A?

Hypothesis: it may pack A (the token code) together with the keyExtend value, possibly into a 16-bit pair, for the subsequent descriptor builder at 0x022359.

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase296-05622e-pack-helper.mjs`

The probe must:
1. Read `TI-84_Plus_CE/ROM.rom` (4MB binary)
2. Starting at offset 0x05622E, disassemble eZ80 instructions until function end (RET/JP)
3. For each instruction: address, hex bytes, mnemonic
4. Look for:
   - CP 0xFE and CP 0xFC comparisons (known from 0x0AF408 analysis)
   - How register A is combined with other values (LD H,A / LD L,A patterns for 16-bit packing)
   - Reads from D0058E (keyExtend) or D0058C (scan code)
   - Any CALL targets
   - Return value setup (what's in A or HL on exit)
5. Report function size and what the "packing" operation actually does

## eZ80 Decoding Reference
- ADL mode, 24-bit addresses (3 bytes LE)
- CALL nn = 0xCD nn nn nn (4 bytes)
- RET = 0xC9
- CP n = 0xFE nn (2 bytes) — note: CP 0xFE is FE FE (the opcode IS 0xFE)
- LD A,(nn) = 0x3A nn nn nn (4 bytes ADL)
- LD (nn),A = 0x32 nn nn nn (4 bytes ADL)
- LD H,A = 0x67, LD L,A = 0x6F
- LD A,H = 0x7C, LD A,L = 0x7D
