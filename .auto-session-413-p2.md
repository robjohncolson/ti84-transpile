# Task: Trace All D17795 Protocol State Transitions

## Context
You are working on a TI-84 Plus CE ROM (eZ80) transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB). RAM address D17795 is a protocol state byte used by the USB/Link receive workers:
- Worker A (0x013250) sets D17795=4 (ready)
- Handler 2 sets D17795=5 (mode 4→5 transition)
- Extended Worker (0x0135CF) checks D17795 on mismatch

We need to find ALL writes to D17795 across the entire ROM and map the complete state machine.

## Deliverables
1. Create `TI-84_Plus_CE/probe-phase413-D17795-states.mjs` — a Node.js probe that:
   - Reads `TI-84_Plus_CE/ROM.rom`
   - Scans the entire ROM (0x000000–0x3FFFFF) for all instructions that reference address D17795 (little-endian bytes: 0x95 0x77 0xD1)
   - For each reference, determine if it's a READ or WRITE by checking the opcode:
     * LD (D17795),A = 0x32 0x95 0x77 0xD1 → WRITE (value in A, check preceding instruction for value)
     * LD A,(D17795) = 0x3A 0x95 0x77 0xD1 → READ
     * LD (D17795),BC / LD (D17795),HL etc. for 16/24-bit stores
   - For writes, look backward up to 10 bytes to find what value is being written:
     * LD A,n (3E n) before LD (addr),A → value is n
     * XOR A (AF) before LD (addr),A → value is 0
     * OR A (B7) → value unknown (register)
   - For reads, look forward up to 10 bytes to find CP n comparisons to determine what values are checked
   - Output a structured state machine: which addresses write which values, which addresses read and compare which values

2. Create `TI-84_Plus_CE/phase413-D17795-states-report.md` summarizing the protocol state machine

## eZ80 Encoding Reference
- LD (nn),A = 32 nn[0] nn[1] nn[2] (4 bytes, nn is 24-bit little-endian)
- LD A,(nn) = 3A nn[0] nn[1] nn[2] (4 bytes)
- LD A,n = 3E n (2 bytes)
- XOR A = AF (1 byte, sets A=0)
- CP n = FE n (2 bytes)
- Address D17795 in little-endian = 95 77 D1

## Constraints
- Do NOT modify any existing files
- The probe must be runnable with `node TI-84_Plus_CE/probe-phase413-D17795-states.mjs`
- Use `fs.readFileSync` to read the ROM
- ROM address 0x000000 = file offset 0x000000
