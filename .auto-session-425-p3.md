# Task: Map D13FD8/D13FDE Descriptor Table Bases

## Context
You are working on a TI-84 Plus CE ROM (eZ80) transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 machine code). The transpiler lifts ROM bytes into JavaScript. You write probes (Node.js scripts) that scan ROM bytes for references to specific RAM addresses.

## Background
D13FD8 and D13FDE are descriptor table base addresses:
- Caller A (0x00CD7B, 1394 bytes) uses D13FD8 for its 5-entry descriptor table
- Caller B (0x00EB31, 582 bytes) uses D13FDE for its 1-entry descriptor table
- These are likely separate regions of the same descriptor pool, partitioned for different transfer types

Related RAM variables in the same region:
- D13FED: 5-slot connection table (35 ROM refs, fully mapped in session 423)
- D13FE7: active descriptor (27 refs)
- D14014: live context (13 refs)
- D141E2: latched context (21 refs)

## What to do

1. Create a probe script `TI-84_Plus_CE/probe-phase425-map-D13FD8.mjs` that:
   - Reads `TI-84_Plus_CE/ROM.rom` as a binary buffer
   - Scans all 4 MB for every reference to D13FD8 (bytes 0xD8, 0x3F, 0xD1 in little-endian at any 3-byte address operand position)
   - Scans all 4 MB for every reference to D13FDE (bytes 0xDE, 0x3F, 0xD1)
   - Also scan for D13FD9 through D13FDD (the bytes between the two bases) to check for field accesses
   - For each reference found, print:
     - ROM address where the reference occurs
     - The instruction opcode context (a few bytes before and after)
     - Whether it's a read (LD reg,(addr)) or write (LD (addr),reg)
   - Group references by function (cluster nearby addresses)
   - Count total references for each address

2. Create a report `TI-84_Plus_CE/phase425-D13FD8-map-report.md` summarizing:
   - Total reference count for D13FD8 and D13FDE
   - Who initializes/populates these bases
   - How D13FD8 and D13FDE relate to each other (offset, shared pool?)
   - How they relate to D13FED connection table
   - What the descriptor table entry format looks like based on indexed accesses

## Reference: scanning pattern
The scan should look for 3-byte little-endian address patterns. For D13FD8:
```javascript
const target = [0xD8, 0x3F, 0xD1]; // D13FD8 in little-endian
for (let i = 0; i < rom.length - 2; i++) {
  if (rom[i] === target[0] && rom[i+1] === target[1] && rom[i+2] === target[2]) {
    // Found reference at offset i
  }
}
```

Check the opcode byte(s) before the 3-byte address to determine instruction type (LD, CALL, JP, etc.).
