# Task: Decode 0x0A1A8F — Pixel Renderer Utility

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). We decode ROM functions by reading raw bytes, disassembling them as eZ80 instructions, and documenting their behavior.

Session 560 fully decoded the pixel rendering loop at 0x0A1799 (220B from 0x0A1819). That loop calls two helpers:
- **0x0A1A8F** — utility function (this task)
- 0x0A1A83 — conditional helper (called when D02A71 is nonzero)

The pixel loop context:
- B = 16/18 rows per glyph
- Stride = 0x0280 (640 bytes) for 16bpp framebuffer
- IX walks glyph data byte-by-byte
- D0059C = framebuffer write pointer
- D02A62-D02A75 = pixel renderer workspace (glyph ptr, write ptr, mask, counters)

## What to do

1. Read 150 bytes starting at ROM offset 0x0A1A83 from `TI-84_Plus_CE/ROM.rom` (start a bit before 0x0A1A8F to also catch the conditional helper at 0x0A1A83)
2. Disassemble as eZ80 ADL-mode instructions (24-bit addresses, 3-byte pointers)
3. Document: registers used, RAM addresses read/written, CALL targets, function boundaries
4. Look for: framebuffer pixel manipulation, mask operations, color table lookups

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase561-decode-0A1A8F.mjs`

Use this template structure:
```javascript
import { readFileSync } from 'fs';

const rom = readFileSync('TI-84_Plus_CE/ROM.rom');

const startAddr = 0x0A1A83;
const bytes = rom.slice(startAddr, startAddr + 150);

console.log(`=== Decoding 0x0A1A83-0x0A1A8F region: Pixel Renderer Utilities ===`);
console.log(`Bytes at 0x${startAddr.toString(16)}:`);

for (let i = 0; i < bytes.length; i += 16) {
    const addr = startAddr + i;
    const hex = Array.from(bytes.slice(i, Math.min(i + 16, bytes.length)))
        .map(b => b.toString(16).padStart(2, '0')).join(' ');
    console.log(`  ${addr.toString(16).padStart(6, '0')}: ${hex}`);
}

console.log(`\n=== Disassembly ===`);
// Full eZ80 ADL-mode disassembly, instruction by instruction
// Cover: LD, PUSH/POP, CALL/RET, JP/JR, CP/OR/AND/XOR, ADD/SUB, INC/DEC
// CB prefix (BIT/SET/RES), DD/FD prefix (IX/IY), ED prefix
// Stop at clear function boundaries

console.log(`\n=== Summary ===`);
// RAM addresses, CALL targets, function size, architectural interpretation
```

Implement a FULL eZ80 disassembly — decode each instruction byte-by-byte. Cover at minimum:
- LD r,r / LD r,n / LD r,(addr) / LD (addr),r patterns
- PUSH/POP, CALL nn (3-byte ADL), RET/RET cc
- JP nn / JR e / JR cc,e
- CP / OR / AND / XOR / ADD / SUB / INC / DEC
- BIT/SET/RES (CB prefix, including IY+d DD/FD CB prefix)
- IX/IY prefix instructions (DD/FD)
- ED prefix group (LDIR, LDI, etc.)

Stop disassembling when you hit clear function boundaries for both 0x0A1A83 and 0x0A1A8F.
