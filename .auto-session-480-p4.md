# Task: FIND VRAM ROW BASE VARIABLE

## Context
This is a TI-84 Plus CE ROM transpilation project. ROM at `TI-84_Plus_CE/ROM.rom` (4MB eZ80).

Session 479 discovered that D0059C is a RELATIVE column pixel offset, NOT an absolute VRAM pointer. The character renderer at 0x005A75 computes the VRAM write address internally. There must be a separate variable holding the VRAM ROW base address.

Known facts:
- D0059C = column pixel offset (14 per character, wraps/corrupts after 2 chars)
- D00595 = cursor row (127 write sites, read by 0x005A8E in renderer)
- D00596 = cursor column counter (incremented per character)
- VRAM base = 0xD40000, row stride = 640 bytes (320px × 2 bytes/pixel @ 16bpp)
- Characters rendered at VRAM row 119, not row 0, despite D00595=0

Session 476 found 22 "LD HL,(D0059C)" sites. But D0059C is just the column offset. The VRAM ROW BASE must come from somewhere else.

## What to do
Create `TI-84_Plus_CE/probe-phase480-vram-row-base.mjs` that:

1. Reads the ROM binary directly
2. Searches the ENTIRE ROM (0x000000-0x3FFFFF) for LD HL references to RAM variables near D0059x:
   - LD HL,(D0059A) — pattern: 2A 9A 05 D0 (or ED 27 variant with 9A 05 D0)
   - LD HL,(D00598) — pattern: 2A 98 05 D0
   - LD HL,(D0059E) — pattern: 2A 9E 05 D0
   - LD (D0059A),HL — pattern: 22 9A 05 D0
   - LD (D00598),HL — pattern: 22 98 05 D0
   - LD (D0059E),HL — pattern: 22 9E 05 D0
3. Also search for any instruction that loads 0xD40000 and stores it near D005xx:
   - Search for bytes D4 00 00 (VRAM base fragments) within 10 bytes of any D005xx reference
4. Search for LD HL,(D00599) through LD HL,(D005A0) — all cursor-area variables:
   - For each address D00599 through D005A0, search for 2A pattern with matching bytes
5. Dump ROM bytes around 0x005A8E (where D00595 is read by renderer) — 0x005A80 through 0x005AB0 (48 bytes) with raw hex
6. Also dump 0x09EFB0-0x09F000 where D0059C is written (session 476 found stores at 0x09EFC8, 0x09F09D, 0x09F139)
7. For each found reference, print: address, opcode, direction (read/write), target RAM address

## Template (MUST follow)
```javascript
import { readFileSync } from "node:fs";

const rom = readFileSync(new URL("./ROM.rom", import.meta.url));
const hex = (v, w=6) => `0x${(v>>>0).toString(16).toUpperCase().padStart(w,'0')}`;

function searchLdHlFromAddr(ramAddr, label) {
  const lo = ramAddr & 0xff;
  const mid = (ramAddr >> 8) & 0xff;
  const hi = (ramAddr >> 16) & 0xff;
  console.log(`\n=== LD HL,(${label}) and LD (${label}),HL references ===`);
  let count = 0;
  for (let i = 0; i < 0x400000 - 4; i++) {
    // LD HL,(addr) = 2A lo mid hi in ADL mode
    if (rom[i] === 0x2A && rom[i+1] === lo && rom[i+2] === mid && rom[i+3] === hi) {
      console.log(`  ${hex(i)}: LD HL,(${label})`);
      count++;
    }
    // LD (addr),HL = 22 lo mid hi
    if (rom[i] === 0x22 && rom[i+1] === lo && rom[i+2] === mid && rom[i+3] === hi) {
      console.log(`  ${hex(i)}: LD (${label}),HL`);
      count++;
    }
    // ED 27 variant (SIS prefix LD in mixed mode)
    // ED 6B variant LD SP,(addr) — less likely but check
  }
  console.log(`  Total: ${count} references`);
}

// Search cursor-area variables D00598-D005A0
for (let addr = 0xD00598; addr <= 0xD005A0; addr++) {
  searchLdHlFromAddr(addr, hex(addr));
}

console.log("\n=== 0x005A80-0x005AB0 (renderer at D00595 read site) ===");
// ...raw hex dump...

console.log("\n=== 0x09EFB0-0x09F000 (D0059C write sites) ===");
// ...raw hex dump...
```
