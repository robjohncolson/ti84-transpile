# Auto-Session 495 — P2: Search Text Editing Cluster (0x05F000 BCALL entries)

## Context

You are working on a TI-84 Plus CE ROM transpilation project. The OS ROM is lifted to JavaScript and run in a CPU emulator. We are searching for the **cursor draw** function.

The BCALL jump table at 0x020104 has 2,178 entries. Session 494 mapped the full table to `TI-84_Plus_CE/bcall-table.json`. The cursor ERASE is at 0x061003 (entry 832). We've been searching the nearby cursor cluster (entries 826-833) but the cursor draw may be elsewhere.

The **text editing cluster at 0x05F000 has 66 BCALL entries** and is the likeliest alternate location for cursor draw. Hypothesis: the draw function lives in a different BCALL cluster from the erase function.

Key RAM addresses:
- D00595 = cursor row, D00596 = cursor column  
- D00080 = IY base (OS system flags)
- D40000 = VRAM base (320×240, 16bpp, 153,600 bytes)
- 0x0059C6 = charRenderer function
- Cursor glyph codes: 0xE1 (insert block), 0xE2 (overwrite underline), 0xE3 (second cursor)

## Task

Create ONE probe file: `TI-84_Plus_CE/probe-phase495-text-cluster-scan.mjs`

### Step 1: Extract 0x05F000 cluster entries from bcall-table.json

Read `TI-84_Plus_CE/bcall-table.json` and filter all entries whose target address is in range 0x05F000-0x05FFFF. Print the list (entry index, target address).

### Step 2: Static scan for D00595/D00596 references

For each extracted entry, read the ROM bytes starting at the target address and scan the next 200 bytes for the byte sequences:
- `95 05 D0` (little-endian encoding of 0xD00595 in a 24-bit operand)
- `96 05 D0` (little-endian encoding of 0xD00596)
- `C6 59 00` (little-endian encoding of CALL 0x0059C6 — charRenderer)

Print which entries reference cursor position or the charRenderer.

### Step 3: Dynamic test of entries that reference D00595/D00596

For each entry that references cursor position RAM, run a dynamic test:
1. Cold boot CPU (same pattern as probe-phase494-bcall-neighbor-dynamic.mjs — copy the coldBoot, snapshotVram, compareVram, purgeRamBlocks functions)
2. Snapshot VRAM (pre-filled with 0xFF white)
3. Set D00595=3, D00596=10, IY=0xD00080
4. Run from the target address with maxSteps=50000, maxLoopIterations=500
5. Compare VRAM: count pixel changes and bounding box
6. If VRAM changed, repeat with D00595=7, D00596=20 to test position-dependence

For entries that DON'T reference D00595/D00596, just print "no cursor refs, skipped."

### Step 4: Summary

Print a ranked list of candidates:
- Did VRAM change?
- Is the change area consistent with cursor-cell size (roughly 12-16 pixels wide, 14-16 pixels tall)?
- Does the change position move with cursor row/col?
