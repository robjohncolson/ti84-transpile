# Auto-Session 361 P3: Trace the 0x002126↔0x002136 Loop

## Context
TI-84 Plus CE ROM transpilation project. Boot reaches 323 unique blocks (session 360). Before termination, boot enters a tight loop between blocks 0x002126 and 0x002136. Understanding what these blocks do (peripheral polling? flag checking?) will help identify what condition breaks the loop and what the boot is waiting for.

## Task
1. Create a probe `TI-84_Plus_CE/probe-phase361-loop-trace.mjs` that:
   a. **Static disassembly**: Decode 64 bytes of eZ80 at 0x002120-0x002160 (covering both loop blocks and surrounding context). Use the ROM binary directly for disassembly.
   b. **Dynamic trace**: Boot from 0x000000 in z80 mode with 50000 max steps, using RAM trampoline (built into cpu-runtime.js). Count how many times each of 0x002126 and 0x002136 are visited. Record the first 5 visits to each with full CPU register state (A, F, BC, DE, HL, IX, IY, SP, PC, MBASE, flags).
   c. **Port I/O tracking**: If any IN or OUT instructions are in these blocks, record what ports are read/written and what values.
   d. **Exit analysis**: What block is visited AFTER the last visit to the 0x002126/0x002136 pair? What condition caused the loop to exit (or did it exhaust max steps)?
2. Run the probe and report findings

## Key files
- `TI-84_Plus_CE/ROM.rom` — 4MB ROM binary
- `TI-84_Plus_CE/probe-phase360-disasm-frontier.mjs` — template for disassembly probes
- `TI-84_Plus_CE/probe-phase360-new-seeds.mjs` — template for boot probes with register tracking
- `TI-84_Plus_CE/cpu-runtime.js` — runtime with RAM trampoline
- `TI-84_Plus_CE/peripherals.js` — peripheral bus
- `TI-84_Plus_CE/ez80-decoder.js` — instruction decoder (import `decodeInstruction`)

## Constraints
- Do NOT modify cpu-runtime.js, peripherals.js, ez80-decoder.js, or browser-shell.html
- Do NOT modify any existing probe files
- Use `createPeripheralBus({ timerInterrupt: false })`
- Boot entry is 0x000000 in z80 mode
- MAX_LOOP_ITERATIONS = 50000

## Success criteria
- Probe runs successfully
- Disassembly of the loop blocks is printed
- Visit counts for both blocks are reported
- Register state for first 5 visits shown
- Loop exit condition identified (or "loop exhausted max steps" if it never exits)
- Any port I/O in the loop blocks is documented
