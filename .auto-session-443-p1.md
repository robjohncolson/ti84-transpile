# Task: Trace 0x001937 ISR Dispatch Context

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is a 4MB eZ80 binary at `TI-84_Plus_CE/ROM.rom`. The transpiled JS is regenerated via `node scripts/transpile-ti84-rom.mjs`.

The workflow arithmetic probe (`TI-84_Plus_CE/probe-workflow-arithmetic.mjs`) successfully boots the OS and processes key '1' through the event loop (entry at 0x003A73), but after processing the first key, the CPU enters DI+HALT at address 0x001937 and stays there. Subsequent keys get 1 step (immediate re-HALT). This is the ISR dispatch gate — the OS expects a timer interrupt to wake from HALT and re-enter the event loop.

## Task
Create a trace report that maps the 0x001937 HALT barrier:

1. **What function contains 0x001937?** Read ROM bytes around 0x001937 (±200 bytes) to find function boundaries (look for RET instructions, prologue patterns like PUSH IX / CALL __frameset). Name the containing function.

2. **What is the ISR vector for the timer interrupt?** The eZ80 ISR vector table is at 0x000000-0x00007F. Each vector is 8 bytes: DI (0xF3) + STMIX (0xED 0x7D) + JP addr (0xC3 + 3-byte LE address). Read the vector table and identify:
   - Vector 0 (address 0x000000) — timer/system tick
   - Vector 1 (address 0x000008)
   - Vector 2 (address 0x000010)
   List all vectors and their targets.

3. **What does the timer ISR do?** Follow the timer ISR vector target. Disassemble the first ~100 bytes. Does it eventually route back to the event loop at 0x003A73? Or does it just increment a counter and RTI?

4. **Map the HALT → wake → event-loop path**: After the timer ISR fires, what instruction does the CPU return to? (Answer: the instruction after HALT at 0x001937+1 = 0x001938). What code runs at 0x001938 and beyond? Does it loop back to 0x003A73?

## Deliverables
- Create `TI-84_Plus_CE/phase443-trace-001937-report.md` with your findings
- Create `TI-84_Plus_CE/probe-phase443-trace-001937.mjs` — a Node.js probe that:
  - Reads ROM.rom bytes
  - Extracts and prints the ISR vector table (all vectors with targets)
  - Disassembles bytes around 0x001937 (±100 bytes) showing the containing function
  - Disassembles the timer ISR handler (first 100 bytes of the target)
