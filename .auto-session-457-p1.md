# Session 457 P1: Fix Key Injection — Write to D0058D Instead of D00587

## Context
You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The OS ROM is lifted to JavaScript and executed in Node.js probes.

## Discovery from Session 456
The `_GetCSC` → `GetK` path at 0x03FC1C reads key scan codes from **D0058D**, NOT D00587. Current probes inject scan codes to D00587, which is the keyboard ISR output. But the event loop's GetK function does:
```
LD HL, D0058D
LD A, (HL)
OR A
; if zero → return HL=0 (no key)
; if nonzero → use as index into 64-byte table at 0x03FC41
```

The table at 0x03FC41 maps OS scan codes to key codes. Key '1' has OS scan code 0x12, which maps to key code 0x66 in the table.

## Task
Create a new probe file `TI-84_Plus_CE/probe-phase457-d0058d-inject.mjs` that:

1. Boots to home screen using the standard boot sequence (copy from `probe-phase456-irq-frontend-trace.mjs` lines 57-100 — the `bootToHomeScreen` function and all constants)
2. After boot, sets:
   - `mem[0xD14091] = 1` (key processing enable)
   - `mem[0xD177B7] = 0x55` (display dirty flag)
   - `mem[0xD177BA] = 0` (per-event gate cleared)
3. Injects key '1' via **D0058D** (not D00587):
   - `mem[0xD0058D] = 0x12` (OS scan code for '1')
   - Also set `mem[0xD00080] |= 0x08` (bit 3 = key available flag for IY+0)
4. Runs the event loop from 0x003A73 in 'adl' mode with `maxSteps: 500000, maxLoopIterations: 10000, diHaltBypass: true`
5. After execution, checks and prints:
   - Value of `mem[0xD141B5]` — should be 0x66 (key code for '1') if GetK's table lookup worked
   - Value of `mem[0xD0058D]` — should be 0x00 (consumed by GetK)
   - Value of `mem[0xD00587]` — for comparison
   - VRAM hash change (use SHA-256 of VRAM region 0xD40000 to 0xD40000 + 320*240*2)
   - Count of VRAM changes from baseline (count non-0xAA pixels after init, or diff before/after)
   - Execution termination reason, step count, and final PC

6. Also does a SECOND injection test: inject to D00587 only (NOT D0058D) as a control:
   - Reset state, boot again (or just reset the key-related memory)
   - `mem[0xD00587] = 0x12`, `mem[0xD0058D] = 0x00`, `mem[0xD00080] |= 0x08`
   - Run event loop again
   - Check D141B5 — should remain 0x00 if GetK only reads D0058D

7. Print a JSON summary at the end with both test results.
