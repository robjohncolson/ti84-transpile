# Task: Investigate 0x04EDDD BIT 0 with 100K+ steps (kkkk)

## Context
Session 240 found that 0x04EDD9 is actually `LD HL,0xD003E0` (3-byte instruction), and the real BIT 0,(HL) is at 0x04EDDD. This gate controls whether execution goes to 0x04E447 (alternate computation) vs 0x0850D1 (display-update path).

Session 240's dynamic comparison was inconclusive — both BIT 0 CLEAR and BIT 0 SET produced identical 72-block traces because 5000 steps doesn't get past the preceding VRAM fill (0x09EFDE) to reach the branch point. The VRAM fill takes 80K+ steps.

We need to run 100K+ steps to get past the VRAM fill and actually observe the branch divergence.

## What to do
Create a new probe file `TI-84_Plus_CE/probe-phase241-04eddd-bit0-100k.mjs` that:

1. Runs TWO scenarios with 120000 steps each:
   - **Scenario A**: D003E0 = 0x00 (BIT 0 CLEAR — default home screen)
   - **Scenario B**: D003E0 = 0x01 (BIT 0 SET)
2. Both scenarios enter at 0x04EDD0 (the shared handler, which calls 0x04ECCE first, then returns and checks D003E0)
3. Track:
   - Whether 0x04E447 is visited (alternate computation path)
   - Whether 0x0850D1 is visited (display-update path)
   - What happens AFTER the VRAM fill completes — which blocks diverge
   - Total unique blocks in each scenario
   - Block visit counts for key blocks: 0x04E447, 0x0850D1, 0x04EDDD, 0x09EFDE
4. Compare the two scenarios: identify the first block where they diverge AFTER the VRAM fill

## Setup (per scenario)
- Standard boot: z80 boot → kernelInit(0x08C331) → memInit(0x0802B2)
- SP=0xD1A87E, IX=0xD1A860, IY=0xD00080, MBASE=0xD0

- Entry PC: 0x04EDD0
