# Auto-Session 405 P1: Trace Action Code Dispatch at 137 Caller Sites

## Context
The TI-84 CE OS has an action pipeline at 0xD005F8 (6 slots × 11 bytes). The action byte reader at 0x07FDD6 has 137 total callers across 4 entry points:
- 0x07FDD6: 57 callers (read slot 0 action byte)
- 0x07FDD0: 10 callers (read slot 1 action byte)
- 0x07FDC9: 52 callers (test slot 0 bit 7)
- 0x07FDC3: 18 callers (test slot 1 bit 7)

Session 404 found that most callers do NOT use CP (compare) immediately after the call — they pass the returned byte to other functions. Only 4 CP instructions were found among slot-0 callers (codes 0x08, 0x09, 0x0C, 0x0D at 0x0678A8).

## Task
Write a probe at `TI-84_Plus_CE/probe-phase405-action-dispatch.mjs` that:
1. For each of the 57 callers of 0x07FDD6 (slot 0 reader), disassemble 20 bytes AFTER the CALL instruction
2. Categorize what each caller does with the returned action byte (in register A):
   - CP <imm> → direct comparison (record the value)
   - CALL/JP <addr> → passes to subroutine (record the target)
   - LD (nn),A → stores to RAM (record the address)
   - AND/OR/XOR → bitwise operation
   - Other pattern
3. For the "passes to subroutine" cases, trace one level deeper — what does THAT subroutine do with A?
4. Produce a summary of all action codes that are checked and their handler addresses

Also write `TI-84_Plus_CE/phase405-action-dispatch-report.md` with findings.

## Technical Details
- ROM file: `TI-84_Plus_CE/ROM.rom` (4 MB, little-endian eZ80)
- The ROM is raw binary, load with `fs.readFileSync`
- eZ80 instructions: CALL nn = 0xCD + 3-byte LE address; JP nn = 0xC3 + 3-byte LE; CP n = 0xFE + byte; LD (nn),A = 0x32 + 3-byte LE
- To find callers of 0x07FDD6: scan ROM for bytes CD D6 FD 07 (CALL 0x07FDD6)
- After each CALL (4 bytes), the next instruction starts at offset+4
