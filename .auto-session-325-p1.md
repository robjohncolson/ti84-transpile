# Task: Register 0xE300xx LCD Controller DMA/SPI MMIO in cpu-runtime.js

## Context
The TI-84 Plus CE has an LCD controller DMA/SPI engine at memory-mapped addresses 0xE30000-0xE3002F. This is a DIFFERENT hardware block from the LCD panel timing registers at port 0x80xx (which are already emulated in peripherals.js). The 0xE300xx region is accessed via memory reads/writes (LD instructions), not IN/OUT port instructions.

Session 324 discovered that ROM function 0x055280 (LCD DMA transfer trigger) writes to 0xE30018 (command), 0xE30010 (VRAM base = 0xD40000), 0xE30028 (DMA trigger, SET bit 2), then polls 0xE30020 in a tight loop waiting for a completion bit — and HANGS because 0xE300xx is not emulated.

## What to do
Edit `TI-84_Plus_CE/cpu-runtime.js` to add MMIO intercepts for the 0xE30000-0xE3002F address range in the `read8`/`write8` hooks.

### Where to edit
In `cpu-runtime.js`, around line 903, inside the `if (options.peripherals && options.peripherals.keyboard)` block, the `cpu.read8` function already intercepts:
- 0xE00000-0xE0002F (LCD controller registers via `getLcdMmioReg`)
- 0xF80000-0xF8002F (mirror of above)
- 0xE00800-0xE0091F (keyboard MMIO)

Add a NEW intercept block for 0xE30000-0xE3002F BEFORE the `origRead8(addr)` fallthrough at line 927.

Similarly, in `cpu.write8` (around line 932), add the write intercept before the `origWrite8` fallthrough.

### Behavior specification
Create a state object (similar to `lcdMmio` at line 845):

```javascript
const lcdSpiDma = {
  vramBase: 0xD40000,  // 0xE30010-0xE30012: 3-byte VRAM base pointer
  command: 0x00,        // 0xE30018: command register
  status: 0x00,         // 0xE30020: DMA status (read-only to OS)
  trigger: 0x00,        // 0xE30028: DMA trigger control
};
```

**Read behavior** (addr 0xE30000-0xE3002F):
- 0xE30010: return `lcdSpiDma.vramBase & 0xFF`
- 0xE30011: return `(lcdSpiDma.vramBase >> 8) & 0xFF`
- 0xE30012: return `(lcdSpiDma.vramBase >> 16) & 0xFF`
- 0xE30018: return `lcdSpiDma.command`
- 0xE30020: return `lcdSpiDma.status` — THIS IS THE KEY ONE. After a DMA trigger, the OS polls this waiting for non-zero.
- 0xE30028: return `lcdSpiDma.trigger`
- All others in range: return 0x00

**Write behavior** (addr 0xE30000-0xE3002F):
- 0xE30010: set low byte of vramBase
- 0xE30011: set mid byte of vramBase
- 0xE30012: set high byte of vramBase
- 0xE30018: set command register
- 0xE30028: set trigger register. **CRITICAL**: When bit 2 is set (value & 0x04), immediately set `lcdSpiDma.status = 0x01` to simulate instant DMA completion. This prevents the polling loop at 0x055280 from hanging.
- 0xE30020: ignore writes (status is read-only from OS perspective)
- All others in range: ignore
