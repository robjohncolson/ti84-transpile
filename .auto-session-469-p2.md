# Task: Decode 0x030078 fully — the real key wait loop

## Context
This is a TI-84 Plus CE ROM transpilation project. ROM is at `TI-84_Plus_CE/ROM.rom`. We need to fully disassemble the function at 0x030078, which is the **real key wait loop** in the TI-84 CE OS. Prior sessions claimed it contains "CALL 0x040D40; BIT 3,(IY+0)=D00080; JR Z loop; CALL 0x03FA09" but the actual ROM bytes don't match that description. The bytes start with LD A,(D0058F), SET 0,(IY+0x46), etc.

Two jump table entries at 0x021AB8 and 0x021ABC both point here, suggesting this is a primary mode handler entry point.

## Deliverable
Create a probe file at `TI-84_Plus_CE/probe-phase469-decode-030078.mjs` that:

1. Reads ROM.rom and disassembles starting at 0x030078 through at least 0x030200 (384+ bytes). Use the eZ80 decoder at `TI-84_Plus_CE/ez80-decoder.js`.

2. For each instruction, print: address (hex), hex bytes, mnemonic, and operands.

3. Annotate known addresses:
   - D0058F = unknown OS variable (figure out from context)
   - D00080 = IY base (OS flags byte 0)
   - IY+0x46 = D000C6
   - 0x040D40 = unknown helper (if referenced)
   - 0x03FA09 = key processor
   - 0x003D5A = _GetCSC

4. Also disassemble ROM bytes from 0x030040 to 0x030078 (the 56 bytes before the entry point) to check if the function actually starts earlier.

5. Continue disassembly until you hit a RET or JP that exits, or reach 0x030200.

6. Identify: where is the key polling loop? Where does it call 0x03FA09? What variable holds the mode/state? Print a summary of the function structure at the end.

## Technical details for using ez80-decoder.js
The decoder file is at `TI-84_Plus_CE/ez80-decoder.js`. Read the first ~50 lines to understand how to import/use it. It should export a `decodeInstruction(buffer, offset)` function. The buffer is the full ROM as a Buffer/Uint8Array. The offset is the ROM address. It returns an object with mnemonic, operands, length, etc.

The probe must be a standalone Node.js ES module (.mjs). Use dynamic import or read the file and eval if the decoder uses CommonJS.
