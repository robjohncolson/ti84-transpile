# Task: Implement 0x006202 Delay Stub in Transpiler

## Context
This is a TI-84 Plus CE ROM transpilation project. The transpiler is at `scripts/transpile-ti84-rom.mjs`. It lifts eZ80 ROM machine code to JavaScript functions.

Session 248 proved that function 0x006202 is a **pure delay loop** with NO side effects. It reads port 0x03 bit 4 for speed select, then loops ~35K iterations (at 48MHz). The function ends with `POP HL / POP DE / RET` at 0x00620A-0x00620C. It has 15 callers in the ROM, including 0x0003B0 which calls it 6 times (~215K wasted steps). Stubbing it saves massive step counts when tracing through screen-redraw routines (0x027111/0x027123).

Session 248 also found sibling 0x0003B4 = JP 0x0061E3 (delay only).

## Task
Modify `scripts/transpile-ti84-rom.mjs` to add a **transpiler seed** that emits an immediate-return stub for the delay function. The stub should:

1. Pop HL and DE from the stack (matching the function's epilogue at 0x00620A-0x00620C)
2. Return immediately (no delay loop)

Look at how existing seeds/stubs are implemented in the transpiler. The transpiler already has a seed mechanism — search for `seed` or `stub` or `manualSeeds` or similar patterns in `scripts/transpile-ti84-rom.mjs`. Follow the existing pattern.

**IMPORTANT**: The delay function entry is at **0x006202**. The function does:
- At entry: already has HL and DE pushed by caller (or by function prologue)
- Body: reads port 0x03, loops
- Epilogue: `POP HL` (0x00620A) / `POP DE` (0x00620B-ish) / `RET` (0x00620C)

The stub should replace the BODY with a no-op, keeping the epilogue (POP HL, POP DE, RET). Or if the transpiler seed mechanism works by providing a JavaScript function body, emit the equivalent JS: `const hl = stack.pop(); const de = stack.pop(); return;` (check how other stubs handle register pops).
