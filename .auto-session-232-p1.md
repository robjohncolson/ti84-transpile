# Auto-Session 232 — P1: Investigate 10 BIT 0,(IY+29) test sites

## Task
Build a probe that investigates ALL 10 `BIT 0,(IY+29)` test sites found in session 231. Group them by parent function and determine what each function does.

## Background
Session 231 mapped `IY+29` bit 0 completely:
- **1 SET site**: 0x02FE9D (sole armer in entire ROM)
- **2 RES sites**: 0x02FEA7 (same function), 0x040276 (bulk clearer)
- **10 BIT test sites**: 0x030300, 0x03DDC4, 0x03DEE9, 0x06CCA0, 0x085AFB, 0x085BEB, 0x0AB8D4, 0x0ABB19, 0x0ABCA2, 0x0B63AE

IY base = 0xD00080 (TI-OS convention), so IY+29 = 0xD0009D. Bit 0 of this byte is the key repeat timer gate.

## Deliverables
Create `TI-84_Plus_CE/probe-phase232-iy29-bit0-test-sites.mjs` that:

1. For each of the 10 BIT test addresses, read the surrounding bytes from ROM.rom (±32 bytes around each address) and disassemble them using the eZ80 decoder to find the parent function boundary (look for RET instructions as boundaries).

2. For each site, determine:
   - What the parent function does (based on what other instructions are nearby — CALLs, memory accesses, CP comparisons)
   - Whether the BIT 0 test gates (JR Z/JR NZ after it) or just checks
   - What other IY flags or RAM addresses the parent function accesses

3. Group the 10 sites into clusters:
   - 0x03DDC4 + 0x03DEE9 (125 bytes apart — likely same function or related)
   - 0x085AFB + 0x085BEB (240 bytes apart — likely same function)
   - 0x0AB8D4 + 0x0ABB19 + 0x0ABCA2 (3-site cluster)
   - 0x030300 (standalone — already known as key timer gate)
   - 0x06CCA0 (standalone)
   - 0x0B63AE (standalone)

4. Output a structured JSON summary with fields: `address`, `parentFunctionStart`, `parentFunctionEnd`, `gateType` ("JR Z"/"JR NZ"/"other"), `surroundingCalls`, `otherIYFlags`, `ramAddresses`, `cluster`, `hypothesis`.
