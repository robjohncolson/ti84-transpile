# Task: Trace D1407E (USB Pipe/Buffer State Byte)

## Context
This is part of the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 machine code). We're tracing RAM byte D1407E which is part of a 16-byte USB state block at D14070-D1407F.

From session 437: D1407E has 28 refs (23 writes / 5 reads) — making it extremely write-heavy and the most active byte in the USB state block after D14073 (52 refs). It's likely a pipe/buffer state byte.

## Task
Write a probe script at `TI-84_Plus_CE/probe-phase438-trace-D1407E.mjs` AND a report at `TI-84_Plus_CE/phase438-D1407E-report.md`.

The probe must:
1. Open `TI-84_Plus_CE/ROM.rom` (raw binary, 4,194,304 bytes)
2. Scan the entire ROM for all references to address 0xD1407E:
   - Pattern for LD (addr),A or LD (addr),reg: look for 3-byte address 0x7E, 0x40, 0xD1 (little-endian) in instruction contexts
   - Pattern for LD A,(addr) or LD reg,(addr): same address bytes
   - Also check for LEA/ADL addressing modes that compute D1407E
3. For each reference found, determine:
   - The containing function (scan backwards for a common prologue: PUSH IX / PUSH AF / DI, or look for the nearest CALL target)
   - Whether it's a read or write
   - What value is written (if determinable — constants like XOR A → 0, LD A,imm → that value, etc.)
   - What the read gates (the instruction(s) following the read — typically CP/JR/JP branches)

## Approach for finding references
The eZ80 in ADL mode uses 3-byte addresses. The address 0xD1407E in little-endian is bytes: 0x7E 0x40 0xD1.

Common instruction patterns:
- `LD A,(D1407E)` = 0x3A 0x7E 0x40 0xD1 (4 bytes)
- `LD (D1407E),A` = 0x32 0x7E 0x40 0xD1 (4 bytes)  
- `LD r,(D1407E)` uses extended opcodes
- Indexed access via IX/IY+offset if a base register points near D14070

Also check for:
- References via IX+offset where IX is loaded with a base near D14070 (offset would be +0x0E for D1407E from D14070 base)
- HL-based indirect: LD HL,D1407E then LD A,(HL) or LD (HL),value
