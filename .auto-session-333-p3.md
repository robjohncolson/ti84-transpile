# Task: Trace the Glyph Bitmap-to-RGB565 No-Scale Path (Priority C — ★★)

## Context
Session 332 decoded the glyph format: FIXED 28 bytes/glyph, 16px wide × 14 rows, 1 bit/pixel, 2 bytes/row, MSB-first. Main font at ROM 0x0040EE. The glyph scaler at 0x0533BD handles scaled rendering.

Now we need to trace the **no-scale path** at **0x0536A0** — the routine that converts 1bpp glyph bitmaps directly to RGB565 pixels in VRAM. Questions:
1. Where does it get fg/bg colors?
2. How does it iterate bitmap bits?
3. How does it compute VRAM write addresses?

## Key addresses
- **0x0536A0** — no-scale glyph renderer (target of this trace)
- **0x0040EE** — main font base in ROM (glyph for char 0x20 starts here, each glyph = 28 bytes)
- **0xD40000** — VRAM base (16bpp RGB565 mode)
- **640** — VRAM stride (320 pixels × 2 bytes/pixel)
- **D02FD9** — LCD geometry descriptor (13 bytes: width, height, bpp, stride, vram_base)
- **D005E9** — DrawChar vtable area
- **ROM file**: `TI-84_Plus_CE/ROM.rom`

## eZ80 hints for the renderer
The no-scale 1bpp→RGB565 renderer likely:
- Loads 2 bytes per glyph row (16 bits = 16 pixels)
- Tests each bit MSB-first (BIT 7, BIT 6, ... or shift-left + test carry)
- If bit=1: write fg color (2 bytes) to VRAM; if bit=0: write bg color or skip
- Advances VRAM pointer by 2 after each pixel
- After 16 pixels (one row), advances VRAM pointer by stride-32 (640-32=608) to reach next row
- Repeats for 14 rows

Color sources to look for:
- Foreground color might be in a register pair (DE or BC) or at a fixed RAM address
- Background color might be at another address or might be "transparent" (no write)
- Look for `LD (HL),E / LD (HL+1),D` or similar 16-bit VRAM write patterns

## What to do

1. **Dump raw ROM bytes** at 0x0536A0 (at least 200 bytes) and manually disassemble the first ~50 instructions.

2. **Create a probe** `TI-84_Plus_CE/probe-phase333-glyph-renderer.mjs` that:
   - Boots to home screen (standard sequence)
   - Sets up to render character 'A' (char 0x41): glyph address = 0x0040EE + (0x41 - 0x20) * 28 = 0x0040EE + 0x024C = 0x00433A
   - Traces 0x0536A0 with `onBlock` callback logging every block
   - Before calling: set up registers/memory as the caller would (check what 0x0533BD or its callers pass). At minimum:
     - IX likely points to a rendering context struct
     - HL or DE likely has the glyph data pointer
     - VRAM destination likely in another register or at (IX+offset)
   - If you can't determine exact register setup, trace FROM a known caller instead: boot, then call 0x052569 (one of the 5 glyph_add_bias callers) with a known character
   - Log: every memory read from the glyph area, every VRAM write, final pixel pattern

3. **Also**: dump the glyph bitmap for 'A' from ROM (28 bytes at 0x00433A) and decode it as a 16×14 1bpp image. Print the bitmap as ASCII art (# for set bits, . for clear bits).
