# Task: Cross-reference 593-entry token table with browser-shell direct-eval token map

## Context
We're reverse-engineering the TI-84 Plus CE OS ROM. Session 287 dumped the token name table at ROM address 0x0A0806 — 593 entries spanning 0x0A0806-0x0A1799 (3,987 bytes). Format: (token_id: u8, strlen: u8, chars[strlen]). 254 unique token IDs with 216 duplicates (2-byte token prefixes).

The browser-shell (`TI-84_Plus_CE/browser-shell.html`) has a hand-rolled `EVAL_TOKEN_MAP` that maps token bytes to JavaScript string representations for direct-eval execution. We need to find tokens that exist in the ROM table but are MISSING from browser-shell's token map — these are coverage gaps.

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase288-token-coverage-gaps.mjs`

## What to do
1. Read ROM.rom and parse the token table at 0x0A0806 the same way `probe-phase287-0a0806-token-table.mjs` does (format: token_id u8, strlen u8, chars[strlen]). Extract all token IDs and their string names.
2. Read `browser-shell.html` and extract the `EVAL_TOKEN_MAP` object (it's a JS object literal mapping hex token values to string representations). Parse out all token IDs that browser-shell currently handles.
3. Compare: which token IDs from the ROM table are NOT in browser-shell's EVAL_TOKEN_MAP?
4. Categorize the gaps:
   - Math functions (sin, cos, ln, etc.) — high priority for calculator functionality
   - Statistical functions (1-Var Stats, LinReg, etc.)
   - System commands (ClrHome, Disp, etc.)
   - Variables/constants (pi, e, Ans, etc.)
   - Other (graph modes, colors, etc.)
5. Print a summary: total ROM tokens, total browser-shell tokens, gap count, and the categorized gap list.

## Technical details
- ROM file: `ROM.rom` in the same directory
- Browser shell: `browser-shell.html` in the same directory
- The EVAL_TOKEN_MAP in browser-shell.html is a JavaScript object with numeric keys (token bytes) mapped to string values
- Some tokens are 2-byte sequences (prefix + id) — check how browser-shell handles these vs the ROM table format
- Reference: `probe-phase287-0a0806-token-table.mjs` already parses the ROM table — reuse that parsing logic

## Constraints
- Do NOT modify any existing files (especially NOT browser-shell.html)
- Do NOT run the transpiler
- Output should be a self-contained Node.js ESM script
- Use the same boilerplate style as other probe-phase*.mjs files

## Success criterion
The probe prints a clear gap analysis showing which calculator-relevant tokens are missing from browser-shell's direct-eval implementation, prioritized by user-facing importance.
