# Auto-Session 381 — P2: Trace 0x005B96 and 0x005BB1 Subroutines

## Context
The TI-84 Plus CE OS key handler at 0x001853 calls two subroutines — 0x005B96 and 0x005BB1 — BEFORE calling the post-key dispatcher 0x0158DE. Session 380 mapped 0x001853's full 76-instruction body (0x001853-0x001932) and identified these calls but did not trace what they do. They may be the actual key-processing routines (screen update, cursor movement) while 0x001853 is just the keyboard hardware handler.

## Task
Write a Node.js probe script `TI-84_Plus_CE/probe-phase381-subroutines-5B96-5BB1.mjs` that:

1. Loads the ROM and performs static BFS disassembly from BOTH entry points:
   - 0x005B96 — trace all reachable instructions
   - 0x005BB1 — trace all reachable instructions

2. For each subroutine, report:
   - Total instruction count
   - Address range covered
   - All CALL targets (direct calls to other subroutines)
   - All port I/O (IN/OUT instructions — what ports they access)
   - All RAM writes (LD to addresses in 0xD00000-0xD1FFFF range)
   - All RST instructions (system call dispatchers)
   - Whether the subroutine itself calls 0x0158DE or 0x001853 (recursion check)
   - How it returns (RET, RETI, JP to known address)

3. Use the eZ80 decoder at `TI-84_Plus_CE/ez80-decoder.js`:
   ```js
   import { decodeInstruction } from './ez80-decoder.js';
   // decodeInstruction(romBuffer, offset) returns { mnemonic, operands, length, bytes }
   ```

4. Static BFS: maintain a work queue + visited set. For each instruction:
   - If unconditional JP/JR: add target to queue, do NOT fall through
   - If conditional JP/JR: add target AND fall-through to queue
   - If CALL: add target to queue, also fall through (CALL returns)
   - If RET/RETI/HALT: do not fall through
   - Skip targets outside ROM (>= 0x400000 is RAM, skip)
   - Limit to 500 instructions per subroutine to avoid runaway
