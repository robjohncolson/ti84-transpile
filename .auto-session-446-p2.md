# Task: Trace 0x00846E (Main OS Dispatch Function)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is a 4MB eZ80 binary at `TI-84_Plus_CE/ROM.rom`. 

Session 445 discovered that 0x00846E is the **main OS dispatch handler** called by the scheduler at 0x0015F7 every loop iteration when port 0x0F bit 7 is set. It reads D14080 (pending flags) and D177BB (mode state). This is believed to be the entry point for mode-specific key handling.

## Task
Disassemble and decode the function at **0x00846E** in the ROM. Create a trace report.

### How to disassemble
Read raw bytes from `TI-84_Plus_CE/ROM.rom` using Node.js:

```javascript
const fs = require('fs');
const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');
// Read bytes starting at offset 0x00846E
// eZ80 ADL mode instructions (24-bit addresses):
//   CALL nn = 0xCD lo mid hi (4 bytes)
//   JP nn = 0xC3 lo mid hi
//   RET = 0xC9
//   LD A,(nn) = 0x3A lo mid hi
//   LD (nn),A = 0x32 lo mid hi
//   CP n = 0xFE n
//   BIT b,(HL) = 0xCB 0x46+8*b
//   PUSH/POP = standard Z80
```

### Deliverables
Create file `TI-84_Plus_CE/phase446-trace-00846E-report.md` with:
1. Full disassembly of 0x00846E (first 300 bytes or until you find the function boundary via RET/JP patterns)
2. All CALL targets — what sub-functions does it invoke?
3. What RAM addresses does it read? Especially D14080, D177BB, D141B5 (processed key), D1441D (handler table pointer)
4. Does it reference D141B5 (the processed key byte)?
5. Does it reference D1441D (the mode-specific handler table pointer)?
6. How does it dispatch to mode-specific handlers?
7. Function size and caller count

### Constraints
- Do NOT modify `cpu-runtime.js`, `peripherals.js`, `browser-shell.html`, or any probe file
- Do NOT run the transpiler or any probes
- Output is a markdown report only

### Success criterion
The report explains how 0x00846E routes from "bit 7 set in port 0x0F" to mode-specific key handler dispatch, and identifies whether it reads D141B5 or D1441D.
