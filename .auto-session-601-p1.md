# Task: D007CA re-arm tracking during FIRST keypress (276K-step path)

## Context
This is a TI-84 Plus CE ROM transpilation project. The OS runs via lifted JavaScript blocks from an eZ80 ROM. We drive a keypress ('2', internal code 0x90) through the OS outer event loop at 0x08C331, which dispatches through cxMain at 0x0585E9. The full key processing runs 276K steps and ends at HALT 0x0019B5.

Session 600 found that D007CA (the cxMain dispatch vector) is zeroed during key processing (at step ~84,825 by bulk mem-clear 0x0018F8) and is NOT re-armed by the outer loop's second pass. BUT session 600 only checked D007CA re-arm during a SECOND keypress (when D007CA was already 0). We need to check whether D007CA is re-armed during the FIRST keypress's 276K-step path — between the wipe at step ~84,825 and halt at step ~276,537.

## Known D007CA writer addresses (all LD (D007CA),HL)
19 addresses found via static ROM scan:
0x05CC31, 0x0601B4, 0x06B432, 0x080EB7, 0x081018, 0x081100, 0x0813E0,
0x09D327, 0x09D33D, 0x09D353, 0x0AB767, 0x0AB8E7, 0x0ABA7D, 0x0ABB09,
0x0ABE84, 0x0ACC8A, 0x0B1D4D, 0x0B48EC, 0x0B6170

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase601-d007ca-rearm-firstkey.mjs` that:

1. Uses the EXACT boot sequence from `TI-84_Plus_CE/probe-phase599-wipe-tracker.mjs` (Phase 0 through Phase 2 — cold boot, launch-init 0x09DD62, paint 0x058241). Copy it verbatim.

2. Seeds the FIRST key (D0058C=0x90, D0058E=0x90, D0009F|=0x20) and runs the outer loop from 0x08C331 with maxSteps=500_000 and maxLoopIterations=500_000.

3. Uses `onBlock(pc)` to track:
   - Whether ANY of the 19 D007CA writer addresses are hit as blocks during the run
   - The step number and PC when D007CA transitions from 0→non-zero (re-arm) or non-zero→0 (wipe)
   - The actual value written to D007CA at each transition

4. Also tracks the current value of D007CA by reading `read24(mem, 0xD007CA)` on each onBlock call and comparing to previous.

5. Reports:
   - Which of the 19 writer addresses were hit (if any), at which step
   - All D007CA transition events (value changes with step and PC)
   - Whether D007CA is non-zero at the end of the first keypress (meaning it was re-armed)
   - Final state: D007CA, D0231A, D0243A, VRAM non-white pixel count

## Key constraints
- Import pattern: `import { createExecutor } from './cpu-runtime.js'; import { createPeripheralBus } from './peripherals.js';`
- ROM loading: `const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));` then dynamic import of `ROM.transpiled.js`
- NEVER push 0x0019be as return address (wipe trap). Use 0x0019b5 (halt).
- write24/read24/hex/countVramNonWhite helper functions — copy from probe-phase599-wipe-tracker.mjs
- The probe runs via `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase601-d007ca-rearm-firstkey.mjs`

## Success criterion
Probe runs to completion and reports whether D007CA is re-armed during the first keypress path. If it IS re-armed, identify which of the 19 writer addresses did it. If NOT, confirm it stays 0 throughout.

Run the probe via the watchdog: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase601-d007ca-rearm-firstkey.mjs`
