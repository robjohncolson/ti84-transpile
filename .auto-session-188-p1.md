# Auto-Session 188 P1: Lift PushErrorHandler (0x07C88B) + Probe ParseInp Error Recovery

## Goal
Add 0x07C88B as a transpiler seed so PushErrorHandler becomes a lifted block, then build a probe that calls PushErrorHandler properly before ParseInp to set up an error frame targeting 0x099929. Verify that ParseInp's JError now reaches 0x099929 (the intended error recovery point).

## Background
- PushErrorHandler lives at 0x07C88B (JT entry 0x0201C4 → JP 0x07C88B)
- Session 187 proved JError's `LD SP,(errSP)` at 0x061DCA fires when we intercept the broken z80-mode RET at 0x03E1B1
- But 0x099929 is NOT reached because the error frame was set up via fallback JT 0x020798→0x061DEF, not the real PushErrorHandler
- The real PushErrorHandler at 0x07C88B was never a lifted block — so it can't execute
- Session 187 probe `probe-phase187-jerror-intercept.mjs` has all the infrastructure

## Deliverables

### 1. Add seed to `TI-84_Plus_CE/phase200-seeds.txt`
Append this line at the end:

```
0x07C88B
```

### 2. Regenerate ROM.transpiled.js

Verify the new seed count is 50,061 (was 50,060). Check that block `07c88b` appears in the output.

### 3. Create `TI-84_Plus_CE/probe-phase188-pusherrorhandler.mjs`
Build a probe based on `probe-phase187-jerror-intercept.mjs` that:
1. Sets up memory identically to the session 187 probe (edit buffer with "2+3" tokens, BegPC/CurPC/EndPC, FPS/OPS, etc.)
2. **Before calling ParseInp**, calls PushErrorHandler at 0x07C88B with:
   - HL = 0x099929 (the error recovery target — hlPayload)
   - Stack has a proper return address
   This should write an error frame to the stack area at (errSP), so when JError fires, `LD SP,(errSP)` loads the frame and JP (HL) goes to 0x099929
3. Then calls ParseInp at 0x099914 as before
4. Still applies the z80-mode RET intercept at block `03e1b1:z80` → PC=0x03E1CA, ADL mode
5. Traces execution and reports:
   - Whether PushErrorHandler completes (how many steps, what it wrote to errSP area)
   - Whether ParseInp fires JError
   - Whether 0x099929 is reached after JError
   - If reached: what's in OP1 and the error registers

**Key addresses from session 187 probe** (copy these):

- EDIT_TOP = 0xD02437, EDIT_CURSOR = 0xD0243A, EDIT_TAIL = 0xD0243D, EDIT_BTM = 0xD02440

- BUF_START = 0xD00A00

**PushErrorHandler calling convention** (from JT entry 0x0201C4):
- Input: HL = error handler address (hlPayload)
- It pushes a frame onto the error handler stack (at errSP)
- The frame contains: hlPayload, saved SP, saved PC
- After return, errSP points to the new frame
