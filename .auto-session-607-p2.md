# Auto-Session 607 — P2: DECODE 0x04E07B (Memory Management Function)

## Goal
Static-decode the function at ROM address 0x04E07B. This is the actual function called by `CALL 0x04E07B` at 0x048BF7 (session 606 showed 0x048BFB is just the return address, not a function entry). 0x04E07B calls 0x000130. Understanding this function reveals part of the memory management subsystem that runs during key1's one-time init pass.

## Background
- Session 606 decoded the 0x048B07-0x048DFC range as a MASSIVE memory management function that does seven distinct RAM region initializations via LDIR-style block copies, then calls 0x04E07B.
- 0x04E07B is one of several functions called in the memory init sequence: 0x0457B2, 0x04E07B, 0x049CCA.
- 0x000130 is a very low-ROM routine called by 0x04E07B.

## What to Build
Create `TI-84_Plus_CE/probe-phase607-decode-04e07b.mjs`:

1. **Read ROM bytes** starting at 0x04E07B. Decode eZ80 instructions in ADL mode until you find a RET or JP that clearly ends the function (or decode 256 bytes, whichever comes first).

2. **For each instruction**, print:
   - Address (hex)
   - Raw bytes (hex)
   - Mnemonic + operands
   - Any interesting observations (CALL targets, memory addresses referenced, I/O ports)

3. **Also decode 0x000130** — the function called by 0x04E07B. Same format, up to 128 bytes or first RET.

4. **Count callers** of 0x04E07B in the entire ROM: scan all bytes 0x000000-0x3FFFFF for the 4-byte pattern `CD 7B E0 04` (CALL 0x04E07B in ADL mode — little-endian 3-byte address after CD opcode). Report count and addresses.

5. **Count callers** of 0x000130 similarly: scan for `CD 30 01 00`.

6. **Write a report** to `TI-84_Plus_CE/phase607-decode-04e07b.md` with:
   - Full disassembly of 0x04E07B
   - Full disassembly of 0x000130
   - Caller lists for both
   - Analysis: what does this function do? Is it a memory allocator? Integrity checker? Block copy? What RAM regions does it touch?

## eZ80 Decode Notes
- ADL mode (24-bit addressing) is the default
- CALL = 0xCD followed by 3-byte little-endian address
- RET = 0xC9
- JP = 0xC3 followed by 3-byte address
- LD A,(addr) = 0x3A + 3-byte addr
- LD (addr),A = 0x32 + 3-byte addr
- Use the decoder in `TI-84_Plus_CE/ez80-decoder.js` if available, or do raw byte decode
