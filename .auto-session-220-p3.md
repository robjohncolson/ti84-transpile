# Auto-Session 220 — P3: _GetCSC Scan Code → Key Name Complete Mapping

## Context

The TI-84 Plus CE keyboard matrix maps physical keys to scan codes via `keyMatrix[N] = SDK Group(7-N)`. Scan code = `(idx << 4) | bit`. 63 active keys, 64th (DOWN = 0x00) collides with no-key sentinel.

The OS function `_GetCSC` (at jump table entry 0x020118, resolves to a ROM function) reads the keyboard hardware and returns a scan code in A. This scan code is the input to ConvKeyToTok (0x05E630) for token conversion.

Session 186 dumped the ConvKeyToTok tables and mapped scan codes to tokens. But there is NO complete reference mapping scan codes to human-readable key names (e.g., 0x8F = "1", 0x80 = "+", 0x9A = "ALPHA-A"). The keyboard-matrix.md file has the matrix layout but not a clean code-to-name table.

## Task

Build a probe `TI-84_Plus_CE/probe-phase220-getCSC-scancode-map.mjs` that:

### Part A — Build complete scan code → key name map
1. Read `TI-84_Plus_CE/keyboard-matrix.md` for the matrix layout
2. Using the SDK keyboard group definitions (Group 1-7, 8 bits each), build a complete mapping:
   - keyMatrix[0] = SDK Group 7 (row 0)
   - keyMatrix[1] = SDK Group 6 (row 1)
   - ...
   - keyMatrix[6] = SDK Group 1 (row 6)
3. Scan code formula: `scanCode = (row << 4) | bitPosition` where bitPosition is 0-7

The TI-84 Plus CE keyboard layout (from SDK/hardware docs):
```
Group 1 (keyMatrix[6], row 6): GRAPH, TRACE, ZOOM, WINDOW, Y=, 2nd, MODE, DEL
Group 2 (keyMatrix[5], row 5): (reserved), STO, LN, LOG, x², x⁻¹, MATH, ALPHA
Group 3 (keyMatrix[4], row 4): 0, 1, 4, 7, COMMA, SIN, APPS, X,T,θ,n
Group 4 (keyMatrix[3], row 3): ., 2, 5, 8, ), COS, PRGM, STAT
Group 5 (keyMatrix[2], row 2): (-), 3, 6, 9, (, TAN, VARS, (reserved)
Group 6 (keyMatrix[1], row 1): ENTER, +, -, ×, ÷, ^, CLEAR, (reserved)
Group 7 (keyMatrix[0], row 0): DOWN, LEFT, RIGHT, UP, (reserved), (reserved), (reserved), (reserved)
```

4. For each scan code 0x00-0x6F, output: scan code hex, key name, token (from ConvKeyToTok primary table at 0x05BF84)

### Part B — Verify against ROM ConvKeyToTok table
1. Read the primary ConvKeyToTok table at ROM offset 0x05BF84 (166 entries × 2 bytes)
2. For each scan code that has a non-zero token entry, verify the key name matches the token meaning
3. Flag any mismatches or unexpected mappings

### Part C — Print formatted reference table
Output a clean reference table suitable for documentation:
```
Scan Code | Key Name    | Token (hex) | Token (char/name)
----------|-------------|-------------|------------------
0x00      | DOWN        | -           | (no token - arrow key)
0x01      | LEFT        | -           | (no token - arrow key)
...
0x8F      | 1           | 0x31        | '1'
0x80      | +           | 0x70        | '+'
```

### Part D — Verify _GetCSC jump table resolution
1. Read the jump table entry for _GetCSC at ROM address 0x020118 (3 bytes, little-endian, gives target address)
2. Disassemble the first 20 bytes at the target to confirm it's the keyboard scan function
3. Report the resolved address
