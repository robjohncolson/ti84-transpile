# Auto-Session 359 P3: GPIO Bit 4 Path Analysis — Test GPIO=0xFF Boot Path

## Context

The TI-84 Plus CE boot sequence reaches block 0x001D37 (NMI handler path). This block branches on GPIO port 0x03 bit 4:
- If bit 4=0 (GPIO=0xEF): `LD IX, 0x001259; CALL 0x000D7E` — copies/runs a different ROM routine
- If bit 4=1 (GPIO=0xFF, current default): `LD IX, 0x001008; CALL 0x000D7E` — copies/runs the E008xx MMIO routine (591 bytes)

Session 358 noted that with GPIO=0xFF (bit 4=1), boot reaches 3147 steps vs 2206 baseline — significantly more exploration. This suggests the GPIO=0xFF path might be a better/longer boot path.

However, 0x001D37 is in the **NMI handler path**, not the main boot path. The main boot currently goes through 0x000E94 → 0x000D7E (flash self-test, 90 bytes). The question is: does the NMI path eventually reach the same code-copy framework but with different parameters?

## Task

Create a probe `TI-84_Plus_CE/probe-phase359-gpio-path.mjs` that:

1. **Run boot with GPIO=0xFF (default) for 10,000 steps** with `createPeripheralBus({ timerInterrupt: false })`. Record:
   - Total unique blocks
   - Whether block 0x001D37 is reached
   - Whether block 0x000E94 is reached
   - All `missing_block` addresses encountered
   - The sequence of blocks from step 2000-2500 (around where the paths diverge)

2. **Run boot with GPIO=0xEF (bit 4 cleared) for 10,000 steps**. Record the same metrics. Compare block counts and paths.

3. **For each GPIO value, trace the code-copy calls**. When execution enters block 0x000D82 (or 0x000D7E), log: which caller site invoked it, what IX value was passed, what the parameter block length is, and what RAM destination the code will be copied to.

4. **Disassemble the IX=0x001259 parameter block** (the GPIO bit 4=0 path). Read ROM at 0x001259: first 2 bytes = length (little-endian), then the code. Disassemble the first 20 instructions of the copied code to identify what it does. Compare with the IX=0x001008 path (E008xx MMIO routine, already known from session 300).

5. **Report which GPIO value reaches more boot territory** and whether either path avoids the RAM execution wall at 0xD18C22.
