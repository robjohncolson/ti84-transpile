# Task: Decode 0x0979C6 and 0x0979E4 — Cursor Position Check + Character Output

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). We are investigating the cursor blink system.

**Key finding**: 0x096B65 (137-byte cursor display formatter) calls:
- 0x0979C6 FIRST (cursor position check) — if Z, skips to 0x096B7B
- 0x0979E4 FOUR times with ASCII values: A=0x20 (space), A=0x28 ('('), A=0x29 (')'), and one more

These are in the 0x0979xx region which also contains 0x097955 (LCD refresh trigger, 55 bytes decoded in session 501) and 0x0979A1 (VRAM writer setup called from 0x097955).

   - **0x0979C6** — decode ~40 bytes (until RET or unconditional JP). This is a cursor position check that returns Z/NZ.
   - **0x0979E4** — decode ~40 bytes. This is called with A = ASCII character code. It likely outputs a character to some display buffer or status area.
3. Also decode **0x09798C** — ~40 bytes. Called with D=0x5E and E=cursor_type.
4. For each instruction, print: address, hex bytes, mnemonic
5. Use proper eZ80 decoding (see reference below)
6. Flag any CALL/JP targets and note if they're in known ranges:
   - 0x060xxx-0x061xxx = cursor/draw region
   - 0x097xxx = LCD refresh region  
   - 0x0A2xxx = pixel renderer region

7. Print summaries for each function: size, call targets, what it appears to do

## eZ80 Instruction Reference
- In ADL mode, CALL nn = CD xx xx xx (4 bytes), JP nn = C3 xx xx xx (4 bytes)
- JR e = 18 xx (2 bytes, signed offset), JR cc,e = 20/28/30/38 xx
- LD A,(nn) = 3A xx xx xx (4 bytes), LD (nn),A = 32 xx xx xx
- LD HL,(nn) = 2A xx xx xx, LD (nn),HL = 22 xx xx xx
- LD HL,nn = 21 xx xx xx, LD A,n = 3E xx
- RET = C9, RET cc = C0/C8/D0/D8/E0/E8/F0/F8
- CP n = FE xx, CP (HL) = BE, CP r = B8-BF
- .SIS prefix = 0x40 (16-bit operands with MBASE)
- BIT/SET/RES via IY: FD CB dd xx
- PUSH/POP: C5/D5/E5/F5 / C1/D1/E1/F1
- RST 28h = E7 (BCALL, followed by 2-byte index)
