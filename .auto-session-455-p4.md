# Auto-Session 455 P4: Map the Two CP 0x01 Sites Checking D177B7

## Context
The TI-84 Plus CE ROM transpilation project. Session 454 fully mapped the D177B7 four-state protocol:
- 0x00 = clean
- 0x01 = busy/hardware-lock  
- 0x55 = dirty/needs-refresh
- 0xAA = consumed/refresh-in-progress

Two ROM sites explicitly `CP 0x01` against D177B7:
- 0x0128E5
- 0x0414B5

The question: What do these sites do when D177B7 equals 0x01 (busy)? Do they spin-wait? Branch differently? Skip display operations?

## Task
Create a probe file `TI-84_Plus_CE/probe-phase455-d177b7-cp01-sites.mjs` that:

1. Reads the ROM binary (`TI-84_Plus_CE/ROM.rom`)
2. For EACH of the two CP 0x01 sites (0x0128E5 and 0x0414B5):
   a. Read 64 bytes BEFORE the site and 64 bytes AFTER (total 128 + instruction bytes)
   b. Print the raw hex dump with offsets
   c. Identify the instruction sequence:
      - How is D177B7 loaded? (LD A,(D177B7) = 3A B7 77 D1 in ADL mode)
      - What follows CP 0x01? (JR Z? JR NZ? JP Z? JP NZ?)
      - Where does the branch go?
      - What happens on the taken vs not-taken path?
   d. Identify which function contains this site:
      - Scan backwards from the site for common function prologue patterns (PUSH AF/BC/DE/HL/IX/IY)
      - Scan forward for RET (0xC9)
      - Estimate function bounds
   e. Check if the function also compares D177B7 against 0x55 (CP 0x55 = FE 55) or 0xAA (CP 0xAA = FE AA)
3. For each site, determine:
   - Is this a spin-wait loop? (Does the branch target loop back to the CP instruction?)
   - Is this a gate/skip? (Does the branch skip a section of code?)
   - Is this a state-machine dispatch? (Does it branch to different handlers for different values?)

## How to find the LD A,(D177B7) instruction
In eZ80 ADL mode: LD A,(nn) = 3A followed by 3-byte LE address
D177B7 in LE = B7 77 D1
So pattern: 3A B7 77 D1

Search for this pattern near each CP site (within 16 bytes before) to confirm the load.
