# Auto-Session 262 P2 — Find all ROM writes to D007D0 (handler pointer)

## Context

Session 261 found that address D007D0 is a handler pointer used at 0x08C69E: `LD HL,(D007D0)` then `CALL 0x08C745` which does `JP (HL)`. After boot, D007D0 = 0x000000 (uninitialized), causing a crash to the cold boot vector.

We need to find what OS code WRITES to D007D0 so we can either:
- Pre-seed it with the correct value, or  
- Understand which OS initialization path populates it

## Task

Create a probe `TI-84_Plus_CE/probe-phase262-d007d0-write-sites.mjs` that:

1. Reads the ROM file (`TI-84_Plus_CE/ROM.rom`, 4MB) as a Buffer
2. Searches for all byte patterns that could write to address 0xD007D0:
   - `LD (0xD007D0),HL` = `0x22 0xD0 0x07 0xD0` (in ADL mode, 3-byte address: little-endian 0xD007D0 = bytes D0 07 D0)
   - `LD (0xD007D0),A` = `0x32 0xD0 0x07 0xD0`
   - Any 3-byte store instructions targeting this address
   - Also search for the 2-byte address pattern `D0 07` near store opcodes as a broader sweep
3. For each match, report:
   - ROM offset (hex)
   - Surrounding bytes (16 bytes before, 16 after) as hex dump
   - Decoded instruction if recognizable
4. Also search for writes to nearby addresses D007CE-D007D5 (the handler pointer might be part of a struct)
5. Count total matches

## Important eZ80 encoding notes

In ADL mode (24-bit), `LD (imm24),HL` = `0x22` followed by 3 address bytes in little-endian.
So `LD (0xD007D0),HL` = `22 D0 07 D0`.
`LD (0xD007D0),A` = `32 D0 07 D0`.

The address 0xD007D0 in little-endian bytes is: `D0 07 D0`.
