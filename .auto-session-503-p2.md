# Auto-Session 503 — P2: Decode 0x096B65 Fully (137 bytes to 0x096BEE)

## Task
Perform a complete instruction-by-instruction static disassembly of 0x096B65 through 0x096BEE (137 bytes) from the TI-84 Plus CE ROM. This is the "full cursor display" function with 5 callers: 0x0600D9, 0x0615F6, 0x06161A, 0x06167D, 0x097065.

## Context
The cursor rendering architecture uses a display invalidation model (NOT direct draw):
- 0x096B65 is called from the main editor loop
- It contains calls to 0x0979C6, 0x0979E4, 0x09798C, 0x093625, 0x0A0BA2
- It eventually reaches 0x096BEE (blink toggle) which flows to 0x096CCF → 0x096F56 → 0x097955 (invalidation)
- Session 502 proved ZERO direct CALL/JP to draw/erase functions in 0x096000-0x09A000
- The draw/erase may happen through BCALL (RST 28h, opcode 0xE7) or through the callers at 0x0600D9

## eZ80 instruction encoding reference
- Standard Z80 opcodes apply but addresses are 24-bit (3 bytes) in .LIL mode (default for TI-84 CE)
- LD r,(nn) uses 4-byte address encoding in ADL mode: opcode + 3 address bytes (LE)
- CALL nn = CD xx xx xx (4 bytes), JP nn = C3 xx xx xx (4 bytes)
- JR e = 18/20/28/30/38 + signed offset byte
- RST 28h = E7 (single byte), followed by 2-byte BCALL index
- BIT/SET/RES via CB prefix: FD CB dd bb for (IY+d)
- .SIS prefix (0x40) makes next instruction use 16-bit addresses composed with MBASE
