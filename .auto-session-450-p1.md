# Task: Fix Scan Codes + D177BA=0 in Workflow Probe

## Context
File: `TI-84_Plus_CE/probe-workflow-arithmetic.mjs`

This probe tests "1 + 1 ENTER → expect 2 on screen" by injecting key scan codes into the TI-84 OS event loop. Session 449 discovered that the scan code formula was wrong — the probe used `(idx << 4) | bit` but the OS uses `((7-idx)-1)*8 + bit + 1`. Dynamic verification via `_GetCSC` confirmed the correct values.

Session 449 also discovered that after boot, `D177BA` = 0x7F which blocks key processing at address 0x001713. Setting `D177BA = 0` after boot allows key processing to reach 0x0067F8 (the real key handler), which causes VRAM changes.

## What to change

In `TI-84_Plus_CE/probe-workflow-arithmetic.mjs`:

### 1. Fix scan code values (lines 35-37)

const KEY_PLUS  = { idx: 1, bit: 1, label: '+',     scan: 0x11 };
const KEY_ENTER = { idx: 1, bit: 0, label: 'ENTER', scan: 0x10 };
