# Task: Decode the Tight Loop Path at 0x02FDD8

## Context
We're investigating the TI-84 Plus CE OS event loop. In session 472, we discovered that after the first key is processed, the event loop enters a tight 2-block spin between 0x03FA09 (key processor) and 0x02FDD8 (main handler) — WITHOUT ever reaching 0x02FE88 (the RET where the stack is restored to loop back to 0x02FDBE).

The event loop head is at 0x02FDBE: `CALL 0x03FA09`. After key processing, execution reaches 0x02FE88 (RET) on the first iteration, but on subsequent iterations the path 0x02FDD8→...→0x03FA09→0x02FDD8 repeats endlessly.

## Task
Create a probe `TI-84_Plus_CE/probe-phase473-tight-loop-decode.mjs` that:

1. **Disassembles 0x02FDD8 through 0x02FE88** by reading raw ROM bytes and decoding them manually (print hex bytes + instruction mnemonics). The key question: what instruction at or near 0x02FDD8 causes a CALL or JP to 0x03FA09?

2. **Traces the tight loop** by entering at 0x02FDBE after boot with:
   - D00587=0x09 (ENTER key scan code)
   - D00080 bit 3 set
   - D14091=1 (key processing enable)
   - D00824=0x48 (home screen mode)
   - D177B7=0x00, D177BA=0x7F
   - Stack set with return address 0x02FDBE
   - onBlock callback that tracks EVERY block PC for the first 200 blocks (not just selected addresses)

3. **Logs the full block-by-block trace** for iterations 1 and 2 so we can see EXACTLY where the path diverges (why iteration 1 reaches 0x02FE88 but iteration 2 does not).
