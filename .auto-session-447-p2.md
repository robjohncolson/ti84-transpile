# Task: Trace 0x049087 (Display Refresh Function)

## Context
This is the TI-84 Plus CE ROM transpilation project. The ROM is a 4MB eZ80 binary at `TI-84_Plus_CE/ROM.rom`. The transpiled JavaScript is at `TI-84_Plus_CE/ROM.transpiled.js` (gunzip from `.gz` if needed, but you can also read the ROM binary directly).

0x049087 is the **display refresh function** for the home screen. It is called from the key processor 0x03FA09 at address 0x03FB03 when:
- D177B7 = 0x55 (display needs refresh)
- Port 0x0F bit 6 is set AND bit 7 is clear

After 0x049087 returns successfully, 0x049E07 (token dispatch) is called.

## What to do
Create a trace report at `TI-84_Plus_CE/phase447-trace-049087-report.md` that answers:

1. **Function boundaries**: Start address 0x049087, find the end (look for RET/JP instructions). How many bytes?
2. **What it does**: Disassemble using the ROM bytes. What memory regions does it read/write? Does it access VRAM (0xD40000-0xD52BFF)? Does it access LCD MMIO ports (0x4000-0x401F)? Does it read the font table?
3. **CALL targets**: What functions does it call? List all CALL/JP instructions with their targets.
4. **Key state variables**: Does it read D141B5 (key buffer)? D177B7? D1441D? Other D1xxxx state?
5. **Register usage at entry**: What does it expect in registers when called from 0x03FB03?

## How to disassemble
Read the ROM binary at `TI-84_Plus_CE/ROM.rom` starting at offset 0x049087. eZ80 ADL mode instructions (24-bit addresses). Key instruction encodings:
- CALL nn: 0xCD followed by 3-byte little-endian address
- JP nn: 0xC3 followed by 3-byte little-endian address
- JP cc,nn: 0xC2/0xCA/0xD2/0xDA followed by 3-byte address
- RET: 0xC9
- LD A,(nn): 0x3A followed by 3-byte address
- LD (nn),A: 0x32 followed by 3-byte address
- LD HL,nn: 0x21 followed by 3-byte value
- LD BC,nn: 0x01 followed by 3-byte value
- CP n: 0xFE followed by 1-byte
- IN A,(n): 0xDB followed by 1-byte port (short I/O)
- IN0 A,(n): 0xED 0x38 followed by 1-byte port (eZ80 I/O)
- OUT0 (n),A: 0xED 0x39 followed by 1-byte port

You can write a small Node.js script to read and decode the ROM bytes if that helps. Place it in the project root as a temporary file.
