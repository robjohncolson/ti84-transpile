# Task: Investigate 0x08C8CB context setup — how HOME context is installed

## Context
From session 340: 0x08C8CF loads HL=0x058241 (HOME_HANDLER), then calls 0x08C900 which does BIT 6,(IY+0x36), CALL NZ 0x023A02, sets IY+0x01 bits, calls JP (HL) trampoline. This is the context SWITCH mechanism — how the HOME context gets installed into cxMain (0xD007CA).

Understanding this is critical for browser shell integration: we need to know how to properly install a context handler so the OS event loop dispatches to it.

## Deliverable: Disassembly probe

Create `TI-84_Plus_CE/probe-phase341-context-setup.mjs` that:

1. Disassembles ROM bytes from 0x08C8CB to 0x08C960 (~150 bytes, covering 0x08C8CB entry + 0x08C900 subroutine)
2. Uses the same ROM reading + ez80-decoder pattern as other probes
3. For each instruction, prints: `addr: hex_bytes  mnemonic  operands`
4. Annotates:
   - All writes to 0xD007xx range (context handler table writes) — especially stores to 0xD007CA (cxMain)
   - All IY flag operations (BIT/SET/RES with offset)
   - All CALL/JP targets
   - Any LD HL,0x058241 or similar handler address loads
5. Then searches the ENTIRE ROM for all callers of 0x08C8CB and 0x08C900:
   - Pattern: `CD CB C8 08` (CALL 0x08C8CB in ADL mode, little-endian) 
   - Pattern: `CD 00 C9 08` (CALL 0x08C900)
   - For each caller, read the 3-6 bytes before the CALL to see what HL was loaded with (the handler being installed)
6. Produces a summary table: `caller_address → handler_address_loaded → which_context_slot_written`

## How to search ROM for byte patterns
```javascript
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
for (let i = 0; i < rom.length - 3; i++) {
  if (rom[i] === 0xCD && rom[i+1] === 0xCB && rom[i+2] === 0xC8 && rom[i+3] === 0x08) {
    // Found CALL 0x08C8CB at address i
  }
}
```
Note: eZ80 ADL CALL is 4-byte instruction: CD ll mm hh (little-endian 24-bit address).
