# Auto-Session 246 — P1: Trace 0x0271CD (D02A86 counter setter)

## Context
Session 245 mapped the D02A86 "pending-display counter" lifecycle:
- 0x0271CD: SETS the counter (LD HL,D02A86 → CP (HL) → conditional LD (HL),A when A≥2 after CP 0x02/JP C gate)
- 0x08BFE3: DECREMENTS the counter (DEC A → LD (D02A86),A)
- 0x027112: ZEROS the counter (XOR A → LD (D02A86),A — "display done")

We need to understand WHO calls 0x0271CD and WHAT determines the counter value (register A at entry).

## Task
Build a probe `TI-84_Plus_CE/probe-phase246-0271cd-caller-trace.mjs` that:

1. **Static scan**: Search the entire ROM (4MB at `TI-84_Plus_CE/ROM.rom`) for all CALL/JP instructions targeting 0x0271CD. eZ80 CALL nn = `CD xx xx xx` (3-byte address, little-endian). JP nn = `C3 xx xx xx`. Also check for RST vectors or jump table entries. Report all call sites with their addresses.

2. **Static disassembly of the parent function**: 0x0271CD is inside a function that starts somewhere before it. Disassemble backwards from 0x0271CD to find the function entry (look for a RET or unconditional JP before the function). Then disassemble forward from that entry through 0x0271CD to the next RET, documenting every instruction.

3. **Dynamic trace from 0x0271CD entry**: Using the transpiled ROM, set up a warm home-screen state (full boot: z80Boot 0x000000 → kernelInit 0x000292 → memInit 0x020818 → home-screen stages 1-4 with IX=0xD1A860), then execute starting at 0x0271CD with A=0x03 (a plausible counter value). Track:
   - All blocks visited (first 500 steps)
   - All memory writes (address, old value, new value)
   - All CALL/RET pairs
   - Where it returns to

4. **Cross-reference callers dynamically**: For each static call site found in step 1, set PC to that caller's address and run 50 steps to see what A value it passes.
