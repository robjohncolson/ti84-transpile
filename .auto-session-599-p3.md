# Auto-session 599 P3: Decode 0x05899d (command handler entry) + trace GRAPH through it

## Context

In auto-session 598, we found that GRAPH key (translated code 0x44) goes through the same cxMain path as character keys: cxMain → 0x05877A → convergence 0x0587E9 → CALL 0x058b73 (type ≥ 5) → JR NC 0x05884c → catalog check (0x058EDA) → JP NZ 0x05899d (command handler entry). 0x099921 was NOT hit during the GRAPH key run (428K steps, 2983 blocks). We need to understand what 0x05899d does and whether it eventually reaches 0x099921.

## Task

Create a probe `TI-84_Plus_CE/probe-phase599-command-handler.mjs` that does TWO things:

### Part A: Static decode of 0x05899d

Use the same static decode pattern from `TI-84_Plus_CE/probe-phase598-decode-058EDA.mjs`:
- Decode 512 bytes starting from 0x05899d
- Print address, raw bytes, decoded instruction
- Highlight all CALL/JP/JR targets (especially any reference to 0x099921)
- Note any CP instructions (dispatch comparisons)

### Part B: Dynamic trace of GRAPH key through 0x05899d

Use the same boot sequence as `TI-84_Plus_CE/probe-phase598-command-key.mjs` (copy its boot/init phases exactly):
1. Cold boot → launch-init (0x09DD62) → paint (0x058241)
2. Seed GRAPH key: D0058C=0x44, D0058E=0x44, D0009F |= 0x20
3. Run outer loop from 0x08C331 with maxSteps 600_000 and maxLoopIterations 600_000

But add instrumentation to trace the command handler path:
- Use onBlock to record EVERY block PC that's in range [0x058900, 0x05A000] — this captures the command handler region
- Also specifically watch for hits at: 0x05899d, 0x099921, 0x05884c, 0x058854, 0x0587E9, 0x058b73
- Record the ORDERED sequence of blocks hit in the command handler region (first 200 entries, to see the flow)

Output:
- The static decode listing
- The dynamic trace: ordered block sequence in the command handler region
- Whether 0x099921 was reached from 0x05899d
- Any CALL targets from 0x05899d that were dynamically hit
