# Task: Decode 0x055228 and 0x055261 — LCD Register Setup Callers

## Context
This is the TI-84 Plus CE ROM transpilation project. We disassemble eZ80 machine code from `TI-84_Plus_CE/ROM.rom` (4MB).

Session 556 decoded **0x055280** (27B, LCD register setup function). It writes a mode value from register A to LCD control register E30018, sets bit 2 of E30028, writes VRAM base D40000 to E30010, then polls E30020 bit 2 until ready. It has exactly 2 callers: **0x055228** and **0x055261**.

We need to decode these two callers to understand what mode values they pass in A and what context they set up before calling the LCD register function.

## What To Do

1. Create a probe script `TI-84_Plus_CE/probe-phase557-lcd-callers.mjs` that:
   - Loads the ROM from `TI-84_Plus_CE/ROM.rom`
   - Disassembles **0x055228** — start reading backwards from the CALL at this address to find the function start (look for the previous RET or function boundary), then disassemble forward through the CALL 0x055280 and beyond to the function's RET
   - Disassembles **0x055261** — same approach
   - For each caller, identifies: what value is loaded into A before the CALL, what other setup is done, what the function does after the CALL returns

2. Output:
   - Function boundaries for both callers
   - What A value each passes to 0x055280 (the LCD mode)
   - Any BPP/mode flag tests (BIT 2,(D000C6) or similar)
   - What each function does overall (LCD 8bpp init? LCD 16bpp init? Mode switch?)

## Technical Reference

- ROM file: `TI-84_Plus_CE/ROM.rom` (4,194,304 bytes, flat binary)
- BPP cluster context: 0x052A00-0x0554FF contains ~56 display mode functions
- D000C6 bit 2 = BPP mode flag (set=8bpp, clear=16bpp)
- D52C00 = 8bpp back buffer, D40000 = VRAM
- 0x055280 = LCD register setup (27B): writes A→E30018, SET 2,(E30028), D40000→E30010, polls E30020
- The CALL instruction is at the address given (0x055228 and 0x055261 are where the CALL opcode is located)
- CALL opcode = `CD 80 52 05` (little-endian 0x055280)
