# Task: Trace 0x049E07 (Token Dispatch Function)

## Context
This is the TI-84 Plus CE ROM transpilation project. The ROM is a 4MB eZ80 binary at `TI-84_Plus_CE/ROM.rom`.

0x049E07 is the **token dispatch function** for the home screen. It is called from the key processor 0x03FA09 AFTER 0x049087 (display refresh) succeeds. This function converts key codes into actions (text entry, cursor movement, command execution).

## What to do
Create a trace report at `TI-84_Plus_CE/phase447-trace-049E07-report.md` that answers:

1. **Function boundaries**: Start address 0x049E07, find the end (RET/JP). How many bytes?
2. **What it does**: Disassemble using ROM bytes. Does it read D141B5 (the key buffer)? Does it use a lookup table to convert key codes to token IDs? Does it dispatch to per-key handlers?
3. **CALL targets**: List all CALL/JP instructions with their target addresses.
4. **Key state variables**: What D1xxxx memory does it access? Does it write to VRAM? Does it modify D177B7?
5. **Dispatch mechanism**: Is it a table dispatch (computed jump)? A switch/case chain (sequential CP tests)? A bitmask test?
6. **Register usage at entry**: What does it expect in registers?

## How to disassemble
Read the ROM binary at `TI-84_Plus_CE/ROM.rom` starting at offset 0x049E07. eZ80 ADL mode instructions (24-bit addresses). Key instruction encodings:
- CALL nn: 0xCD followed by 3-byte little-endian address
- JP nn: 0xC3 followed by 3-byte little-endian address
- JP cc,nn: 0xC2/0xCA/0xD2/0xDA followed by 3-byte address
- CALL cc,nn: 0xC4/0xCC/0xD4/0xDC followed by 3-byte address
- RET: 0xC9
- LD A,(nn): 0x3A followed by 3-byte address
- LD (nn),A: 0x32 followed by 3-byte address
- CP n: 0xFE followed by 1-byte immediate
- IN0 A,(n): 0xED 0x38 followed by 1-byte port
- IY-indexed: 0xFD prefix, then (IY+d) ops

You can write a small Node.js script to decode the ROM bytes. Place temporary scripts in the project root.
