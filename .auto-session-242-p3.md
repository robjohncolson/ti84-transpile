# Task: Investigate D010F8 — map write sites and boot value

## Context
In the TI-84 Plus CE ROM transpilation project, session 241 decoded the BIT 4 guard at 0x051B84. The function 0x051B7C has a cascading guard where BIT 4,(D003E0) SET + D010F8==0x01 causes a bail (skip). D010F8 is a newly discovered variable. We need to understand:
- What writes D010F8?
- What are its possible values?
- What is its boot value?
- Is it a sub-mode indicator?

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase242-d010f8-investigation.mjs`

## What the probe must do
1. **Static ROM scan**: Read the ROM binary (`TI-84_Plus_CE/ROM.rom`, 4MB) and scan for all references to address 0xD010F8. Search patterns:
   - 3-byte LE address bytes: `F8 10 D0` in LD/ST instructions
   - Also search for `F8 10` (partial, in case of relative addressing via IY or IX)
   - Classify each reference as READ (LD A,(addr)), WRITE (LD (addr),A / LD (addr),value), BIT test, SET, RES, or POINTER
   - For each reference, dump the surrounding 16 bytes and decode the instruction

2. **Boot value**: After full boot (z80 boot → kernelInit → memInit → homescreen stages 1-4), read mem[0xD010F8] and report its value.

3. **Event loop value**: After the boot + running 10000 event loop steps, read mem[0xD010F8] again.

4. **Key press value**: After triggering key press (0x8F digit), run 5000 steps, read mem[0xD010F8].

## Key files to reference

The probe runs and reports:
- Total number of D010F8 references in ROM
- Classification of each reference (READ/WRITE/BIT/SET/RES/POINTER) with ROM address
- Surrounding instruction context (hex dump + rough decode)
- Boot value, event-loop value, and post-key-press value
