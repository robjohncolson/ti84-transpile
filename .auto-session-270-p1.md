# Task: Seed event loop dispatch table with correct 9-byte entry, test if event loop exits

## Context
The TI-84 CE OS event loop (5-block polling: 0x082BE2→0x084716→0x08471B→0x084723→0x084711) searches a dispatch table downward from D3FFFF. Session 269 decoded the table format:

- 9-byte entries, scanned downward from D3FFFF
- Entry format: [key2][key1][key0][handlerB2][handlerB1][handlerB0][?][?][flag]
- key bytes at positions 0-2 (lowest address first), handler at positions 3-5
- Loop compares against D005F9/D005FA/D005FB
- After boot + event loop entry: D005F9=0x40, D005FA=0x00, D005FB=0x00
- Table base: D0259D. Table currently EMPTY (D0259D=0x000000, all zeros at D3FFFF)
- Session 269's manual seed at D3FFFA failed because entry position was wrong (9-byte stride)

## What to do

Create a probe `TI-84_Plus_CE/probe-phase270-dispatch-table-seed.mjs` that:

1. Performs a full boot sequence (cold boot → kernelInit → memInit → homescreen stages 1-4) using the same boot pattern as `probe-phase269-event-loop-exit-condition.mjs` or `probe-phase268-d007e8-fix.mjs`. Look at those files for reference.

2. After boot, seeds the dispatch table with a CORRECT 9-byte entry. Since entries are scanned downward from D3FFFF:
   - Entry starts at D3FFF7 (= D3FFFF - 8, since last byte is at D3FFFF)
   - D3FFF7 = key[0] = 0x40 (matches D005F9)
   - D3FFF8 = key[1] = 0x00 (matches D005FA)
   - D3FFF9 = key[2] = 0x00 (matches D005FB)
   - D3FFFA = handler byte 0 = 0x41 (low byte of 0x058241)
   - D3FFFB = handler byte 1 = 0x82 (mid byte of 0x058241)
   - D3FFFC = handler byte 2 = 0x05 (high byte of 0x058241)
   - D3FFFD = 0x00 (unknown field)
   - D3FFFE = 0x00 (unknown field)
   - D3FFFF = 0x01 (flag — nonzero to indicate active entry)

   Also set D0259D = address of the first valid entry (D3FFF7) so the loop knows the table isn't empty. Actually, re-check: D0259D might be the table BASE (lowest entry). If the loop scans downward from D3FFFF and stops at D0259D, then D0259D should be set to something ≤ D3FFF7.
   
   **IMPORTANT**: Try TWO experiments:
   - Exp A: D0259D = 0xD3FFF7 (exact entry address)
   - Exp B: D0259D = 0xD3FFF0 (slightly below, in case base means "stop scanning here")

3. Also seed D007E8 = 0x06C546 (session 268 fix — prevents 0x08C69E crash)

4. Enter the event loop at PC=0x082BE2 (or use the home body bypass at PC=0x0582BC which reaches event loop at step 21).

5. Run for 5000 steps. Check:
   - Does the loop EXIT (visit blocks outside the 5-block polling set)?
   - What PC does execution reach after the table match?
   - Does it reach cxMain (0x058241 or 0x0585E9)?
   - Report unique blocks visited, step count, final PC

6. If neither experiment works, try the REVERSE byte order for the key: D3FFF7=0x00, D3FFF8=0x00, D3FFF9=0x40 (big-endian vs little-endian uncertainty).
