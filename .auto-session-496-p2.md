# Auto-session 496 P2 — Decode 0x061980 (Putchar Function)

## Goal
Statically disassemble and dynamically test 0x061980, the "putchar" function that outputs a single character at the current cursor position. Understanding this function reveals how the OS renders characters at cursor position — and whether cursor drawing is simply a putchar call with a cursor glyph code (0xE1/0xE2/0xE3).

## Context
- Session 495 discovered that BCALL entry 833 (0x06118A, a text formatter) calls 0x061980 SIX times with different ASCII codes. This is the OS "putchar" — it outputs one character at the current cursor position.
- 0x061980 likely reads D00595 (cursor row) and D00596 (cursor column) to compute the VRAM address for rendering.
- The cursor draw may simply be a call to 0x061980 with cursor glyph code 0xE1 (normal cursor), 0xE2 (insert cursor), or 0xE3 (second cursor). If so, there is no dedicated "cursor draw" function — cursor drawing IS character rendering.
- Key addresses:
  - D00595 = cursor row, D00596 = cursor column
  - 0x0059C6 = charRenderer (internal, not in BCALL table)
  - 0x005A48 = VRAM row calculator
  - 0x0A2400 = pixel renderer
  - VRAM base = 0xD40000, 320×240×2 bytes (16-bit RGB565)

## Deliverable
Create `TI-84_Plus_CE/probe-phase496-decode-061980.mjs` that:

### Part 1: Static disassembly
1. Load ROM.rom
2. Read bytes starting at 0x061980 (at least 300 bytes — this may be a complex function)
3. Use the eZ80 decoder (`TI-84_Plus_CE/ez80-decoder.js`) to disassemble instruction by instruction until RET or 300 bytes
4. Report: total instruction count, byte range, all CALL/JP targets, all LD references to D00xxx addresses, any references to VRAM (D40000), any cursor glyph codes (0xE1, 0xE2, 0xE3)

### Part 2: Dynamic test
1. Load ROM.transpiled.js and boot the CPU (see reference probe for exact boot sequence)
2. After boot, set cursor position: D00595=5, D00596=10
3. Set register A = 0x41 (character 'A') — or whatever register 0x061980 expects its character argument in (check the static disassembly first — it may read from A, from (HL), or from a memory location)
4. Set PC = 0x061980, SP = 0xD1A87E
5. Snapshot VRAM, then run up to 50,000 steps
6. Compare VRAM: report changed pixel count, bounding box, whether the changes are at the cursor position

### Part 3: Cursor glyph test
1. Same setup but with A = 0xE1 (cursor glyph code)
2. Run and capture VRAM diff
3. If it draws a cursor-shaped region (roughly 10×14 pixels) at the cursor position, this confirms the "putchar IS cursor draw" hypothesis

```javascript

// decode returns { mnemonic, length, ... }
let offset = 0x061980;
for (let i = 0; i < 100 && offset < 0x061980 + 300; i++) {

  offset += inst.length;
  if (inst.mnemonic.startsWith('RET') && !inst.mnemonic.includes(',')) break;
}
```
