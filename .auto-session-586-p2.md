# Task: Decode 0x0843B3 — called between type-0x09 LDIR event posts

## Context
You are working on a TI-84 Plus CE ROM reverse-engineering project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary, little-endian, ADL mode = 24-bit addresses).

Session 585 traced type-0x09 event callers. The first two callers at 0x02262C and 0x02265D share a function starting ~0x0225DB. Between them, at approximately 0x02264C, there's a CALL 0x0843B3. This sits between:
- The first LDIR that saves 9B from D005F8 and 65B from D02510
- The event post itself
- The second LDIR that restores those buffers

We need to know what 0x0843B3 does with the D005F8/D02510 buffers.

## Deliverable
Create `TI-84_Plus_CE/probe-phase586-decode-0843B3.mjs` — a static disassembly probe that:
1. Reads `TI-84_Plus_CE/ROM.rom` directly with `readFileSync`
2. Disassembles starting at 0x0843B3 until RET or unconditional JP (max ~200 bytes)
3. Tracks all CALL targets, JP/JR targets, RAM references (0xD0xxxx), IY+offset refs, and port I/O
4. Prints a formatted analysis

## Decoder API
The probe must use a HAND-ROLLED eZ80 decoder reading raw bytes from the ROM buffer. Do NOT import from `ez80-decoder.js` — it does not export `decodeAt` or similar.

```js
import { readFileSync } from 'fs';
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
function b(addr) { return rom[addr] ?? 0; }
function u16(addr) { return b(addr) | (b(addr + 1) << 8); }
function u24(addr) { return b(addr) | (b(addr + 1) << 8) | (b(addr + 2) << 16); }
```

Then decode eZ80 instructions manually by reading opcodes. See `TI-84_Plus_CE/probe-phase585-decode-08011F.mjs` for a complete working example.

## Key RAM addresses to annotate
- D005F8: descriptor buffer (9-byte search key area)
- D005F9: search key type byte
- D02510: expression buffer (65 bytes)
- D02590: symbol table start
- D0259D: symbol table current pointer
- D02AD7-D02AD9: last-match buffer

## Constraints
- Do NOT modify any existing files
- Do NOT import from cpu-runtime.js, ez80-decoder.js, or peripherals.js
- The probe is STATIC analysis only — reads ROM bytes, does NOT execute the CPU
- Run the probe via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase586-decode-0843B3.mjs`

## Success criterion
The probe runs (exit 0) and prints: function boundaries, instruction-by-instruction disassembly, all CALL/JP/JR targets, RAM references, and a summary of what the function does.
