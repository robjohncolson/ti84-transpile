# Task: SET D00595=0 + RENDER MULTI-CHAR STRING "HOME" AT TOP OF SCREEN

## Context
Session 478 proved that calling 0x0059C6 directly with A=charcode produces real glyph pixels in VRAM. Character 'H' produced 1,472 VRAM bytes at row 119 — NOT at (0,0) as expected. Session 478 discovered that D00595 (127 write sites, read at 0x005A8E in the renderer) controls the ACTUAL rendering position, while D0058C/D0058E are logical cursor positions.

## Task
Create `TI-84_Plus_CE/probe-phase479-multi-char-string.mjs` that:

1. Uses the EXACT same pattern as `probe-phase478-char-output-test.mjs` (import createExecutor from cpu-runtime.js, createPeripheralBus from peripherals.js, load ROM.rom and ROM.transpiled.js).
2. After 3-stage boot (0x080000 → 0x0802B2 → 0x08C331, 150K steps each with maxLoopIterations:200000), sets up display state:
   - D0059C = 0xD40000 (VRAM base — row 0, col 0)
   - D00595 = 0x00 (cursor row 0 — THIS IS THE KEY DIFFERENCE from session 478)
   - D00596 = 0x00 (column counter reset)
   - D0058C = 0x00, D0058E = 0x00 (logical cursor)
   - D0058B = 0x70 (display config)
   - cpu.mbase = 0xD0, cpu._iy = 0xD00080
   - cpu.iff1 = 0, cpu.iff2 = 0, cpu.halted = false
3. Calls 0x0059C6 with each character of "HOME" (0x48, 0x4F, 0x4D, 0x45) sequentially:
   - For each: set cpu._a = (charCode << 24), cpu.sp = 0xD1A87E - 3, push sentinel 0xFFFFFF on stack, run from 0x0059C6 with maxSteps:5000, maxLoopIterations:100
   - After each call, log: VRAM bytes changed, D0059C value, D00596 value, first 16 changed addresses
4. After all 4 characters, take a final VRAM diff from the pre-render snapshot and log total bytes changed.
5. Check if VRAM changes are near 0xD40000 (row 0) rather than deep in VRAM (row 119+).

## Key addresses
- 0x0059C6 = character output function (takes A = character code)
- D0059C (3 bytes LE) = VRAM address pointer
- D00595 = rendering row position (read at 0x005A8E)
- D00596 = column counter (increments per char, wraps at 0x1A=26)
- D0058B = display config byte
- VRAM_START = 0xD40000, VRAM_END = 0xD65800

## Template reference
Copy the structure from `probe-phase478-char-output-test.mjs`:
- Same imports, same boot stages, same snapshotVram/diffVram/displayState helpers
- Same primeDirectCall pattern: cpu._a = (charCode & 0xFF) << 24; cpu.sp = STACK_RESET_TOP - 3; sentinel on stack
- Same runFrom('adl') call

## Success criteria
- VRAM changes should be near 0xD40000 (early VRAM = top of screen), not at 0xD5299C+ (row 119)
- D00596 should increment from 0 to 4 after rendering "HOME"
- Each character should produce non-zero VRAM bytes changed
- Total VRAM change count should be substantial (>500 bytes for 4 characters)
