# Task: Decode the 0x003D6B polling loop exit condition

## Context
In the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, all keys end stuck in a tight loop at 0x003D6B during event loop processing. The loop is `DEC BC / OR B / JR NZ` — a classic countdown loop polling the keyboard hardware ports. This is `_GetCSC` waiting for a key release/debounce.

The question: what is the EXIT CONDITION for this loop? The CPU runs 500,000 steps and still ends at 0x003D6B. Either:
1. The loop counter BC is enormous (millions of iterations), OR
2. The loop is re-armed by something (BC reloaded), OR
3. The exit depends on a hardware port read that our emulation doesn't provide

## Your Task
Create a probe file `TI-84_Plus_CE/probe-phase452-polling-loop.mjs` that:

1. Boots the OS (same as probe-phase451-enhanced-workflow.mjs — boot entry, kernel init, post init, stage entries, ROM pre-copy).

2. Injects key "1" (scan=0x12) and enters the event loop at 0x003A73.

3. When PC reaches 0x003D6B (or nearby in the _GetCSC function 0x003D5A-0x003D80 range), dumps:
   - Register BC value (the loop counter)
   - Register A value
   - Current flags
   - Any port reads that happened recently

4. Tracks how many times PC visits 0x003D6B across the 500k steps.

5. Also disassembles the area around 0x003D6B by reading ROM bytes. Show bytes at 0x003D60-0x003D80 with hex dump and eZ80 instruction decode.

6. Specifically check: does the loop at 0x003D6B read any I/O ports (IN instructions)? If so, which ports? The _GetCSC function polls keyboard ports 0xA000-0xA01E. If the exit depends on a port read returning a specific value, document what value is needed.

7. After the loop, what PC does execution reach if BC reaches 0? Trace the fallthrough path.

## Approach
One useful technique: run in small step chunks (e.g., 1000 steps at a time), check PC after each chunk. When PC is in the 0x003D5A-0x003D80 range, dump registers. Count how many chunks land in this range vs. elsewhere to understand the time split.

Also: manually decode the bytes at 0x003D60-0x003D80 from the ROM. The eZ80 instructions are:
- DEC BC = 0x0B (1 byte)
- OR B = 0xB0 (1 byte)  — actually this might be `LD A,B / OR A` or `OR A,B`
- JR NZ,xx = 0x20 xx (2 bytes)

Read the actual bytes and decode them to confirm the exact loop structure.
