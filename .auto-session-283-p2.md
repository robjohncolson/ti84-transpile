# Auto-Session 283 P2: Trace 0x09E2AE — where do STAT CALC menu item strings come from?

## Context
This is a TI-84 Plus CE ROM transpilation project. We lift eZ80 machine code into JavaScript and trace OS internals.

Session 282 discovered that 0x09E11B is a null-terminated string renderer (not a menu renderer). It reads a string pointer from HL and renders character-by-character via CALL 0x0A1B5B. At 0x09E2AE there is a `JP 0x09E11B` in the STAT CALC path. We need to trace what HL contains when execution reaches 0x09E2AE — this tells us where the actual STAT CALC menu item strings live in ROM.

Also: session 282 clarified that 0x09E140 contains ASCII strings ("MEM Cleared\0RAM Cleared\0Defaults...") — OS status messages, NOT menu descriptors. So the real STAT CALC menu items must come from elsewhere.

## Task
Write a probe file `TI-84_Plus_CE/probe-phase283-09e2ae-calc-strings.mjs` that:

1. **Static disassembly of 0x09E280-0x09E2AE** (46 bytes before the JP) — decode each instruction. Focus on what loads HL before the JP 0x09E11B. It likely does `LD HL,<address>` pointing to a string table.
2. **Identify the string table address** — whatever address gets loaded into HL, dump 128 bytes from that ROM address as ASCII to see the menu item strings.
3. **Context: disassemble 0x09E296-0x09E2B0** — session 281 identified 0x09E296 as "STAT CALC menu setup". Show what happens between 0x09E296 and the JP at 0x09E2AE.
4. **Find other JP/CALL 0x09E11B sites** — scan ROM.rom for `C3 1B E1 09` (JP) and `CD 1B E1 09` (CALL) to see all callers of the string renderer. For each caller, disassemble 6 bytes before it to see what HL is loaded with.
5. **Dump strings from discovered addresses** — for each HL value found in step 4, dump 64 bytes as ASCII.

## Pattern for probes
```javascript
import { readFileSync } from 'fs';

const rom = readFileSync(new URL('ROM.rom', import.meta.url));

function disasm(addr, len) {
  // Read bytes from ROM and decode eZ80 instructions
  // eZ80 ADL mode: 3-byte addresses, 24-bit operands
  // LD HL,nn = 0x21 followed by 3 bytes (little-endian 24-bit)
  // CALL nn = 0xCD followed by 3 bytes
  // JP nn = 0xC3 followed by 3 bytes
}

function dumpAscii(addr, len) {
  const bytes = rom.slice(addr, addr + len);
  return [...bytes].map(b => b >= 0x20 && b < 0x7F ? String.fromCharCode(b) : '.').join('');
}

// Scan for patterns
function findPattern(pattern) {
  const results = [];
  for (let i = 0; i < rom.length - pattern.length; i++) {
    if (pattern.every((b, j) => rom[i + j] === b)) results.push(i);
  }
  return results;
}
```
