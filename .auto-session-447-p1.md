# Task: Update Workflow Probe — Set D14091=1 + D177B7=0x55 After Boot

## Context
The TI-84 CE ROM transpilation project has a workflow probe at `TI-84_Plus_CE/probe-workflow-arithmetic.mjs` that tests key injection (pressing 1+1 ENTER and expecting "2" on screen). The probe currently boots the OS, then injects keys into the event loop at 0x003A73 — but keys never reach D141B5 (the key buffer) because:

1. **D14091 = 0 after boot** — The key processor at 0x03FA09 checks D14091 at 0x03FBC7 and SKIPS writing to D141B5 if D14091 is zero. D14091 is the master key-processing enable flag.
2. **D177B7 state unknown** — The key processor at 0x03FB03 checks D177B7: if 0x55, it calls 0x049087 (display refresh). D177B7=0x55 means "display needs refresh" in home screen mode.

## What to do
Edit `TI-84_Plus_CE/probe-workflow-arithmetic.mjs` to add two memory writes AFTER the `bootToHomeScreen()` call completes but BEFORE the key injection loop begins. Specifically, in the `main()` function, after line 119 (`const bootState = bootToHomeScreen(executor, cpu, mem);`), add:

```javascript
mem[0xD14091] = 1;    // enable key processing (master gate for 0x03FA09)
mem[0xD177B7] = 0x55; // display needs refresh (home screen mode flag)
```

Also add diagnostic logging right after these writes:
```javascript
console.log(`  D14091=${hex(mem[0xD14091], 2)} (key processing enabled)`);
console.log(`  D177B7=${hex(mem[0xD177B7], 2)} (display refresh mode)`);
console.log(`  D141B5=${hex(mem[0xD141B5], 2)} (key buffer, should be 0x00)`);
```

Also add per-key diagnostics INSIDE the key injection loop. After each key press+release cycle (after the `releaseResult` block and before the hash comparison), add:
```javascript
console.log(`    D141B5=${hex(mem[0xD141B5], 2)} D14091=${hex(mem[0xD14091], 2)} D177B7=${hex(mem[0xD177B7], 2)} D00587=${hex(mem[0xD00587], 2)} D1441D=${hex(mem[0xD1441D] | (mem[0xD1441E] << 8) | (mem[0xD1441F] << 16), 6)}`);
```
