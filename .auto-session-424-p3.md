## Background

Session 423 proved that 0x00DB66 and 0x00DC0E are NOT payload I/O functions — they are control-line arm/drain wrappers that only manipulate direction bits on port 0x3010 and poll status bits on port 0x3015. They never touch data ports (0x3030/0x3031).

The question remains: where does actual per-byte serial TI-Link data transfer happen?

Known TI-Link functions that do NOT do byte-level I/O:
- 0x0094C0: Legacy TI-Link ISR (523 bytes) — dispatches to handlers but doesn't read/write data bytes itself
- 0x00FE10: Transfer engine (638 bytes) — walks block list, produces result codes, but doesn't do per-byte I/O
- 0x00DB66/0x00DC0E: Control-line arm/drain only (168 bytes each)
- 0x00DA8C: Link-state toggle (218 bytes) — activate/deactivate control

The actual byte-level I/O likely reads/writes port 0x3030 (data port, confirmed by multiple functions checking bit 0 for busy) or port 0x3031. It may be in:
- Functions called by the ISR at 0x0094C0 that we haven't traced
- Hardware-triggered paths
- Functions in the 0x00D0xx-0x00DAxx range (between known functions)
