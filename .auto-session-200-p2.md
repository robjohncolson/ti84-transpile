# Auto-Session 200 — P2: Disassemble block 0x09201E to understand the 0x0017 constant (STAT)

## Context

We're transpiling the TI-84 Plus CE OS ROM into JavaScript. In the STAT 1-Var Stats handler, RAM address 0xD008E6 receives the value 0x0017 (23 decimal). This value is later read at 0x092226 (`LD DE,(0x0008E6)` which with MBASE=0xD0 reads 0xD008E6), incremented twice to 0x0019 (25), and used as the byte count for an LDDR copy.

Session 199 found THREE blocks write to 0xD008E6:
1. Block 0x0921AD at step 15 writes 0x0B (11) via write8
2. Block **0x09201E** at step 79 writes **0x0017** (23) via write16 — this is the DEFINITIVE value
3. Block 0x092FCB at step 125 writes 0x0017 again via write8

The value 0x0017 is LIST-SIZE-INDEPENDENT (identical for L1 with 1, 3, or 5 elements).

## Task

Build a probe `TI-84_Plus_CE/probe-phase200-stat-09201e-disasm.mjs` that:

1. **Static disassembly of block 0x09201E**: Read ROM.transpiled.js, find the block entry `09201e:adl`, extract and display all instructions. Identify what computation or constant load produces the value 0x0017 for the write16 to 0xD008E6.

2. **Static disassembly of block 0x0921AD**: Same — understand what writes 0x0B.

3. **Static disassembly of block 0x092FCB**: Same — understand what writes 0x0017.

4. **Register trace through 0x09201E**: Run from the STAT entry point 0x058BA9 with seeded list data:
   - L1 = {1.0, 2.0, 3.0} at 0xD10000
   - VAT entry at 0xD1A800 pointing to L1
   - Set a breakpoint/sentinel when PC enters block 0x09201E
   - Dump all registers (A, BC, DE, HL, IX, IY, SP) at entry to 0x09201E
   - Track what value ends up being written to 0xD008E6 and from which register

5. **Determine if 0x0017 is a constant or computed**: Is it loaded from ROM via `LD reg, imm16`? Or computed from something (number of STAT variables, structure size, etc.)?
