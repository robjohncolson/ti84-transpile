# Task: Analyze VRAM diff pixel pattern from key "1"

## Context
In the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, session 451 found that pressing key "1" produces 6,078 VRAM byte changes from 0x00→0xFF across rows 119-128 starting at column 14. This should be the "1" character glyph rendered to the LCD.

The TI-84 Plus CE LCD is 320×240 pixels at 16bpp (RGB565), so VRAM is 320*240*2 = 153,600 bytes starting at 0xD40000. Each row is 320*2 = 640 bytes. Each pixel is 2 bytes (little-endian RGB565).

## Your Task
Create a probe file `TI-84_Plus_CE/probe-phase452-vram-pattern.mjs` that:

1. Boots the OS (same boot sequence as probe-phase451-enhanced-workflow.mjs).

2. Takes a VRAM snapshot BEFORE key injection.

3. Injects key "1" (scan=0x12) and processes 500k steps.

4. Takes a VRAM snapshot AFTER.

5. Computes the full diff:
   - Total bytes changed
   - Row-by-row breakdown: for each LCD row (0-239), how many bytes changed?
   - For the rows with changes, show the column range (in pixels) where changes occurred
   - Show the actual byte values: what changed from what to what?

6. Interprets the pixel data:
   - Since it's 16bpp RGB565, every 2 bytes = 1 pixel
   - 0x0000 = black pixel, 0xFFFF = white pixel
   - If bytes went 0x00→0xFF, that means pixels went from black (0x0000) to white (0xFFFF)
   - Extract the glyph shape: for each row of the changed region, show which pixel columns are "on" (non-black)
   - Print an ASCII art representation of the glyph (use '#' for white/on pixels, '.' for black/off)

7. Also check: does the changed region match TI-84 CE font dimensions?
   - The TI-84 CE uses a variable-width font, typically 7-12 pixels wide and ~12 pixels tall for the home screen
   - Large font characters are about 12×16 pixels
   - The home screen has a 26×10 grid of character cells

8. Compare the rendered glyph shape against what a "1" digit should look like.
