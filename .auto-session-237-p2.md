# Task (uuu): Investigate 0x02FE73→0x02FD99 housekeeping loop blocks

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript. You write Node.js probes that boot the transpiled ROM and trace execution paths.

## Background
Session 236 decoded the event loop re-entry at 0x02FD99. The self-loop path is:
0x02FD99→0x02FDA6→0x03013A(key scan)→0x05C76C→0x03FA09(key delivery)→0x02FDC2→housekeeping→0x03030E→0x03034F→0x02FE73→0x02FD99

The housekeeping section visits blocks 0x03030E, 0x04C979, and 0x03034F before reaching 0x02FE73 which jumps back to 0x02FD99. **Question**: What do these housekeeping blocks perform? Are they cursor blink, display refresh, battery check, or something else?

## What to do
Create `TI-84_Plus_CE/probe-phase237-housekeeping-blocks.mjs` that:

1. Boots the transpiled ROM (full boot sequence — see existing probes for pattern)
2. For each housekeeping block (0x03030E, 0x04C979, 0x03034F, 0x02FE73), trace execution starting at that block
3. Record all unique blocks visited from each entry, max 200 steps each
4. Capture key RAM reads/writes at each block:
   - IY flags (byte reads from IY+offset)
   - D00824 (mode byte)
   - VRAM area (0xD40000-0xD52C00) — any writes?
   - Timer-related: D00590, D00591
   - Cursor-related: D0243A, D0243D
   - Display-related: D005F0-D005F8
5. Disassemble the first 10-20 bytes at each block address by reading ROM.rom directly
6. Determine what each block's PURPOSE is

## Reference files
- `TI-84_Plus_CE/probe-phase236-02fd99-event-loop-reentry.mjs` — session 236's event loop probe (use as template for boot + init pattern)
- `TI-84_Plus_CE/ROM.rom` — raw ROM binary for disassembly
- `TI-84_Plus_CE/cpu-runtime.js` — eZ80 runtime

## Constraints
- Do NOT modify any existing files
- Create ONLY `TI-84_Plus_CE/probe-phase237-housekeeping-blocks.mjs`
- Use `createPeripheralBus({ timerInterrupt: false })` — timer IRQ causes infinite loops
- Output results to stdout as structured text
- Max 200 steps per individual block trace

## Success criteria
- Probe runs without error: `node TI-84_Plus_CE/probe-phase237-housekeeping-blocks.mjs`
- Reports what each of the 4 housekeeping blocks does
- Identifies whether any block touches VRAM, cursor state, timer state, or IY flags
- Classifies each block (e.g., "cursor blink timer", "display refresh", "battery monitor", "key repeat handler", etc.)
