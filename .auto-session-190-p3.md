# Auto-Session 190 P3: Y= Key Dispatch Trace

## Context
Priority #4 in the continuation prompt: "Y= editor → graph pipeline end-to-end". This is the first step: trace what happens when the Y= key is pressed from the home screen. Session 139 validated GraphPars renders in isolation, session 140 added graph mode to browser-shell. The gap is connecting the Y= key → editor → VAT-slot store.

The home handler is at 0x0582B8-0x058700 (disassembled in session 182). Key classification via `call 0x07F7BD` at 0x0584A7. The home handler's JP (HL) dispatch table at 0x0585D3 dispatches based on key type.

## Task
Build `TI-84_Plus_CE/probe-phase190-yeq-key-dispatch.mjs` that traces the Y= key through the home handler dispatch.

### What to do

1. **Determine the Y= key's scan code and key code**:
   - Read `TI-84_Plus_CE/keyboard-matrix.md` for the Y= key's physical position
   - Y= key is typically scan code 0x37 → _GetCSC 0x22 → home key code (look up in ROM table at 0x09F7BB)
   - Actually, use the ROM's ConvKeyToTok table or key dispatch tables to find the correct code. The Y= key may have a special handling path since it's not a character key.

2. **Boot + MemInit** (same as other probes — boot, kernelInit, memInit, CreateReal(Ans) to set up Ans variable)

3. **Trace the home handler with Y= key code**:
   - Look up the Y= home key code. The TI-84 CE SDK defines: `kYequ = 0x8A` (key code for Y=). But also check if the home handler expects a different encoding.
   - Set register A = key code for Y=
   - Set IX = 0xD1A860 (home screen stage convention from CONTINUATION_PROMPT)
   - Set IY = 0xD00080
   - Set TOKEN_STAGING (0xD0230E) = 0x00
   - Push return sentinel on stack
   - Enter at 0x058460 (home handler key entry, used in session 185 probe)
   - Run max 2000 steps with block-level PC logging

4. **Record**:
   - Every block PC hit (first 100 blocks)
   - Where execution terminates or loops
   - Registers at exit: A, HL, DE, BC, IX, IY, SP
   - Whether any of these known Y= editor addresses are reached:
     - 0x06B300-0x06B400 (typical Y= editor area)
     - 0x059xxx range (app context switches)
     - 0x0582BC (cxRedisp from context table)
   - TOKEN_STAGING value at exit
   - Any writes to the Y-variable VAT area (0xD02xxx range)

5. **Also do a static disassembly** of the Y= key code's expected dispatch path:
   - Read ROM bytes at 0x058460-0x058500 (home handler entry)
   - Disassemble to find the key classification and dispatch for non-character keys
   - Keys like Y= are "app switch" keys — they likely go through the context table dispatch, not the BufInsert path

### Key addresses
- Home handler entry: 0x058460
- Key classification: 0x07F7BD (reads OP1[0] type byte, AND 0x3F)
- Copy helper 0x07F9FB (copies 9 bytes from token staging to OP1)
- Context table: 0x0585D3
- BufInsert: 0x05E2A0
- TOKEN_STAGING: 0xD0230E
- kYequ key code: 0x8A (verify this from ROM data)
- ConvKeyToTok primary table: 0x05BF84
