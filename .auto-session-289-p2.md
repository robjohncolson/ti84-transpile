# Auto-Session 289 — Priority P2: Trace CALL sites to 0x0059E9

## Context

This is the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). The instruction decoder is at `TI-84_Plus_CE/ez80-decoder.js`.

Previous session (288) established that 0x0059E9 is the "scan buffer processor" — it loops 10 times reading D17731 and converting scan codes to key codes. One known caller is at 0x0149B4.

**Key question**: Is 0x0059E9 called from the keyboard ISR directly, or from a foreground polling loop? The answer tells us whether key processing is interrupt-driven or cooperative.

## Task

Write a probe script `TI-84_Plus_CE/probe-phase289-0059E9-callers.mjs` that:

1. Scans the entire ROM (0x000000 through 0x0BFFFF) for CALL 0x0059E9 instructions
   - CALL nn in eZ80 ADL mode is opcode 0xCD followed by 3-byte LE address
   - So search for bytes: 0xCD, 0xE9, 0x59, 0x00
   - Also search for JP 0x0059E9: 0xC3, 0xE9, 0x59, 0x00

2. For each call site found:
   - Print the address
   - Disassemble 10 instructions BEFORE the CALL (context)
   - Disassemble 5 instructions AFTER the CALL (what happens to the return value)
   - Look for patterns indicating ISR context: DI/EI instructions, RETI, push/pop of all registers, references to interrupt vectors

3. Specifically check known ISR entry points:
   - The main keyboard ISR dispatcher was identified at 0x040CE6 (session 283)
   - Check if 0x040CE6's code path reaches 0x0059E9 (search for CALLs in the 0x040C00-0x041000 range)

4. For each caller, classify it as:
   - "ISR" — if within known ISR code or surrounded by DI/EI/RETI
   - "FOREGROUND" — if in normal subroutine flow
   - "UNKNOWN" — if unclear
