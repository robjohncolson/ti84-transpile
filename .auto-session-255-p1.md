# Task: Trace 0x08C33D — the CoorMon/context dispatch convergence point

## Goal
Disassemble and trace the function at/around 0x08C33D to determine HOW it dispatches to context handlers. Specifically:
1. Does 0x08C33D contain a JP (HL), CALL (HL), or PUSH HL + RET trampoline?
2. Does it read a function pointer from RAM? If so, from what address?
3. How does control flow reach 0x062055 (the parent of the sole cxMain caller 0x0620C4)?

## Background
- The OS event loop at 0x02FD99 processes keys but does NOT route to cxMain (0x058241) directly.
- cxMain's sole caller is 0x0620C4 (inside function 0x062055). 0x062055 has ZERO static callers — it's reached via computed dispatch (function pointer in RAM).
- The handler table at 0x08C958 has 20 entries: [0]=0x058241(cxMain), [1]=0x03D755, [2]=0x080CA7, etc. The lookup function at 0x08C94B does: LD E,A / LD D,3 / MLT DE / LD HL,0x08C958 / ADD HL,DE / LD HL,(HL) / RET.
- 0x08C33D was identified as a convergence point with 11 callers (session 252). It likely contains the mechanism that stores or dispatches through the handler pointer.
- 0x08C79F (parent of interior label 0x08C808) has 12 static callers including 0x062050 (inside 0x062055). Entry compares A with (D007E0) mode byte.

## Deliverables
Create probe file: `TI-84_Plus_CE/probe-phase255-08c33d-dispatch-trace.mjs`

The probe should:
1. Read ROM.rom binary and disassemble bytes starting at 0x08C33D for ~100 bytes (use the eZ80 decoder at `TI-84_Plus_CE/ez80-decoder.js`).
2. Also disassemble 0x08C308 (nearby caller/gate block) for context (~60 bytes).
3. Search ROM for all CALL/JP to 0x08C33D (3-byte LE search for `3D C3 08` preceded by CD/C3/C4-CC/D4-DC/E4/EC/F4/FC opcode bytes, and also `JP (HL)` is E9 — but just search for the address pattern).
4. Boot the CPU (use cold_boot + kernelInit pattern from existing probes like `probe-phase254-d007e0-boot-trace.mjs`), then set D007E0=0x00 (home mode) and instrument execution to log when PC enters 0x08C33D, 0x08C308, 0x062055, 0x08C79F. Run for 2000 steps post-boot to see if any of these are reached during idle event loop.
5. Print disassembly + caller list + execution trace results.
