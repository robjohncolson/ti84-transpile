# Task: MAP D025D2 USAGE — Function Pointer for Indirect Dispatch

You are working on a TI-84 Plus CE ROM transpilation project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary, little-endian, ADL mode = 24-bit addresses by default).

## Context

Session 548 decoded 0x023970 (7B), an indirect dispatch function:
- `LD HL,(0xD025D2)` → `EX (SP),HL` → `RET`
- This loads a function pointer from RAM address D025D2 and jumps to it.

We need to know: who WRITES to D025D2? What function addresses get stored there? This maps the indirect dispatch mechanism.

## What to do

1. **Search the full ROM for all references to address 0xD025D2**. In eZ80 ADL mode, D025D2 appears as bytes `D2 25 D0` (little-endian). Search patterns:
   - `21 D2 25 D0` = LD HL,0xD025D2 (load address into HL for indirect access)
   - `22 D2 25 D0` = LD (0xD025D2),HL (direct write, 24-bit)
   - `ED 23 D2 25 D0` = LD (0xD025D2),HL (alternate encoding)
   - `3A D2 25 D0` = LD A,(0xD025D2) (byte read)
   - `32 D2 25 D0` = LD (0xD025D2),A (byte write)
   - `2A D2 25 D0` = LD HL,(0xD025D2) (24-bit read, this is what 0x023970 does)
   - Also search for the raw bytes `D2 25 D0` to catch any pattern

2. **For each write site**: read surrounding bytes (±20 bytes) to determine what value is being written. If it's `LD HL,<addr>` followed by `LD (D025D2),HL`, the addr is a dispatch target.

3. **Classify each reference** as READ, WRITE, or POINTER (LEA/address-of).

4. **Map the dispatch targets**: What functions get called indirectly through D025D2?

## Deliverables

Create file: `TI-84_Plus_CE/probe-phase549-map-D025D2.mjs`

The probe should:
- Scan the full ROM (0x000000-0x3FFFFF) for all references to D025D2
- For each reference, print: address, instruction type (READ/WRITE/POINTER), surrounding context
- For WRITE sites, identify the value being written if possible
- Print total counts by type
- Print a summary of the dispatch mechanism
