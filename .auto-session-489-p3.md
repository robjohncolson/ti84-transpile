# Task: Coverage Push — Add New Seeds from Uncovered CODE? Ranges

## Context
The TI-84 Plus CE ROM transpiler (`scripts/transpile-ti84-rom.mjs`) lifts eZ80 machine code to JavaScript. Coverage is currently at 713,057 bytes with 145,815 blocks and 51,564 seeds. There are ~2,513 uncovered CODE? bytes remaining (reduced from 3,912 in session 488's push). The seeds list is in `knownEntryAnchors` in the transpiler and in `TI-84_Plus_CE/phase24b-seeds.txt`.

## What to do

1. **Run the coverage audit** to find remaining uncovered ranges:
   ```
   node TI-84_Plus_CE/audit-true-uncovered.mjs
   ```
   This produces a list of uncovered byte ranges with classifications (CODE?, DATA, ERASED, etc.)

2. **Identify CODE? ranges** from the audit output. These are ranges that look like valid eZ80 code but aren't yet reached by any seed.

3. **Verify each CODE? range** is real eZ80 code (not data masquerading as code):
   - Read the first few bytes from ROM.rom at each range start
   - Check if they decode as valid eZ80 instructions (common opcode prefixes: 0xCD=CALL, 0xC3=JP, 0x21=LD HL, 0x3E=LD A, 0xED=prefix, 0xDD=IX prefix, 0xFD=IY prefix, 0x01=LD BC, 0x11=LD DE, 0xC9=RET, 0x18=JR, 0x20=JR NZ, etc.)
   - Exclude ranges that start with unlikely opcodes or are clearly data (repeated patterns, ASCII text, etc.)

4. **Add verified seeds** to BOTH:
   - `TI-84_Plus_CE/phase24b-seeds.txt` (one hex address per line, e.g., `0x05E400`)
   - `scripts/transpile-ti84-rom.mjs` in the `knownEntryAnchors` array

5. **Re-run the transpiler** to regenerate ROM.transpiled.js:
   ```
   node scripts/transpile-ti84-rom.mjs
   ```

6. **Re-run the coverage audit** to verify improvement:
   ```
   node TI-84_Plus_CE/audit-true-uncovered.mjs
   ```

7. **Run the golden regression** to verify nothing broke:
   ```
   node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase99d-home-verify.mjs
   ```
