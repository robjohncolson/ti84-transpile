## How seeds work

The transpiler reads `ROM.rom` and lifts eZ80 machine code to JavaScript. It needs "seed" addresses — known function entry points — to begin disassembly. From each seed, it follows control flow (branches, calls) to discover reachable code blocks. Adding more seeds discovers more code.

Seeds are added in `scripts/transpile-ti84-rom.mjs` in a large array. Each seed is just a hex address like `0x012345`. Add yours at the end of the array.

## Finding good seeds

The coverage analyzer outputs gap regions. For each gap:
- Read the first few bytes at the gap start from `ROM.rom`
- If they look like a function prologue (CD 8A 21 00, DD E5, etc.), it's a good seed
- If they're 0xFF (erased flash), skip
- If they look like data (repeating patterns, ASCII strings), skip
- JP table entries (C3 xx xx xx) at addresses in the 0x020xxx-0x021xxx range are OS export stubs — good seeds
