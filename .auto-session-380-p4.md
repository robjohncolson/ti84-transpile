# Task: Test Key-Specific Dispatch Behavior (CLEAR vs ENTER vs 2ND)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. Session 379 confirmed that the 0x3B0001 flash-app table search finds no matching handlers for ENTER — so ENTER takes the Z-return path through 0x0158DE. But different keys may produce different behavior in the dispatch chain: 0x003A7D → 0x001713 → 0x001853 → 0x0158DE.

The question: does the OS perform different actions for different keys, or does every key take the same path at the home screen?

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase380-key-dispatch-compare.mjs` that:

1. Tests 3 keys via the natural keyboard scan path:
   - ENTER (scan code 0x29) — keyMatrix[1] bit 0
   - CLEAR (scan code 0x2F) — keyMatrix[1] bit 6
   - 2ND (scan code 0x06) — keyMatrix[6] bit 5

2. For each key:
   - Boot through standard phases (use `createPeripheralBus({ timerInterrupt: false })`)
   - Set up the CPU with `diHaltBypass: true, diHaltBypassEntry: 0x003A73`
   - Inject the key via `peripherals.setKeyPressed(cpu.memory, scanCode)` where scanCode is the OS scan code
   - Run the event loop from 0x003A73 with enough steps to reach the DI+HALT bypass point
   - Track ALL unique blocks visited
   - Track the value of register A when 0x001853 is entered (this is the scan code the handler receives)
   - Track any RAM writes that differ between keys
   - Track the return path from 0x0158DE — does it take the Z or NZ path?

3. Compare the three runs:
   - Which blocks are visited by all three keys? (common path)
   - Which blocks are unique to specific keys? (key-specific behavior)
   - Do any keys trigger the NZ (action found) path in 0x0158DE?

## Key matrix mappings (for natural scan — use setKeyPressed with OS scan codes)
- ENTER: OS scan code 0x29 (keyMatrix[1] bit 0, H=6 in scan loop)
- CLEAR: OS scan code 0x2F (keyMatrix[1] bit 6, H=6 in scan loop)  
- 2ND: OS scan code 0x06 (keyMatrix[6] bit 5, H=1 in scan loop)

## Key addresses
- 0x003A73: Event loop entry
- 0x003A7D: Key dispatch (CALL 0x001713)
- 0x001713: Intermediate dispatcher
- 0x001853: Normal key handler
- 0x0158DE: Post-key-action dispatcher
- 0x0158BC: Flash-app table search (called by 0x0158DE)
- 0x0019B5: DI+HALT (sleep mode)
