# Task: Investigate Port 0xDCA0

## Context

Session 388 found that the universal key event builder at 0x0236F9 reads port 0xDCA0 (`IN A,(0xDCA0)`) just before returning. The question is: what is port 0xDCA0? Is it a status register? Does the value affect event processing?

The TI-84 Plus CE uses an eZ80 CPU with memory-mapped I/O. Known port ranges:
- 0x0000-0x00FF: CPU control registers
- 0x5000-0x501F: Interrupt controller (FTINTC010)
- 0xA000-0xA01E: Keyboard matrix
- 0xB000-0xB0FF: LCD controller
- 0xB020-0xB024: Backlight
- 0xE000-0xE0FF: USB controller
- 0xD000xx: Might be RAM-mapped (D0xxxx is OS RAM at 0xD00000+)

Note: 0xDCA0 is in the range 0xDC00-0xDCFF. This could be a peripheral port OR it could be a direct memory read disguised as a port read (the eZ80's I/O space is separate from memory space, so IN A,(0xDCA0) reads I/O port 0xDCA0, not memory address 0x00DCA0).

## eZ80 I/O instruction encoding
- `IN A,(n)` = 0xDB n (2 bytes, reads port n — but in ADL mode, full 16-bit port from BC)
- `IN0 A,(n)` = 0xED 0x38 n (3 bytes, reads 8-bit internal I/O port n)
- `IN r,(C)` = 0xED 0x40+r*8 (2 bytes, reads port addressed by BC/C)
- `OUT (n),A` = 0xD3 n
- `OUT0 (n),A` = 0xED 0x39 n (internal I/O)
- `OUT (C),r` = 0xED 0x41+r*8

For the key event builder at 0x0236F9: check the exact instruction encoding at the IN A,(0xDCA0). Is it `IN A,(n)` with n=0xA0? Or `IN r,(C)` with BC=0xDCA0?
