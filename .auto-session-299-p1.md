# Task: Trace GetCSC Caller Chain — Who Calls 0x0159C0?

## Context
The TI-84 Plus CE primary keyboard scanner routine lives at 0x0159C0-0x015AD8 (281 bytes, fully disassembled in session 298). It reads MMIO at 0xE00900 via IY=0xE00800, does a two-phase scan, and returns via tail-call JP 0x000DB6.

We need to find WHO CALLS 0x0159C0. This will reveal how the OS event loop invokes the keyboard scanner.

## What to do
Create a probe at `TI-84_Plus_CE/probe-phase299-getCSC-callers.mjs` that:

1. **Static scan**: Search the entire ROM binary (`TI-84_Plus_CE/ROM.rom`, 4MB) for all CALL and JP instructions targeting 0x0159C0.
   - eZ80 ADL CALL = `CD C0 59 01` (little-endian 24-bit address)
   - eZ80 ADL JP = `C3 C0 59 01`
   - Z80-suffix CALL = `CD C0 59` (but only if preceded by `49` SIS prefix or `52` LIS prefix)
   - Also check for 3-byte address stored as data pointer: `C0 59 01` anywhere (could be in a jump table)
   
2. **For each hit**: Print the ROM offset, the full instruction, and the surrounding context (decode 5 instructions before and after using the ROM bytes).

3. **Dynamic trace**: Boot the OS using the standard transpiled runtime and trace execution. Set up instrumented memory reads:
   - Import `{ createCPU }` from `./cpu-runtime.js` and the transpiled ROM
   - Boot from 0x000000 in Z80 mode
   - Run through cold boot + kernel init + home screen render (use the stage sequence from probe-phase99d-home-verify.mjs as reference)
   - Log every time PC enters the range 0x0159C0-0x015AD8
   - For each entry, capture: the return address on the stack (read SP, then read24 at SP), and the caller's PC

4. **Output**: Print all static call sites and all dynamic callers observed during boot + home screen.
