# Task: Decode 0x0A1CAC — Text Output / String Rendering Function

## Context
This is the TI-84 Plus CE ROM transpilation project. We disassemble eZ80 machine code from `TI-84_Plus_CE/ROM.rom` (4MB) to understand the OS.

Session 556 established that **0x0A1CAC** is the primary text output / string rendering function. It is called 7+ times from the 0x045xxx-0x046xxx region, always bracketed by `SET 4,(IY+0x4A)` before the call and `RES 4,(IY+0x4A)` after (re-entrancy guard). The renderer at 0x0A22DA also references it.

## What To Do

1. Create a probe script `TI-84_Plus_CE/probe-phase557-decode-0A1CAC.mjs` that:
   - Loads the ROM from `TI-84_Plus_CE/ROM.rom`
   - Reads bytes starting at 0x0A1CAC and disassembles them (manually decode eZ80 opcodes or just dump hex + interpret)
   - Determines the function's size (find the RET or unconditional JP that ends it)
   - Identifies what subroutines it calls (CALL instructions)
   - Identifies what RAM addresses it reads/writes (LD instructions with addresses >= 0xD00000)
   - Identifies what IY-relative flags it tests/sets

2. The probe should output structured findings:
   - Function start: 0x0A1CAC
   - Function end/size
   - All CALL targets within the function
   - All RAM address references (LD from/to D0xxxx addresses)
   - All IY+offset references
   - Any conditional branches (JR/JP with conditions)

## Technical Reference

- ROM file: `TI-84_Plus_CE/ROM.rom` (4,194,304 bytes, flat binary, load address 0x000000)
- eZ80 is Z80-compatible with 24-bit addressing. Key prefixes: 0xDD=IX, 0xFD=IY, 0xED=extended
- Common instruction patterns:
  - `CD xx xx xx` = CALL addr (3-byte address, little-endian)
  - `C3 xx xx xx` = JP addr
  - `C9` = RET
  - `FD CB ofs op` = IY+offset bit operations
  - `32 xx xx xx` = LD (addr),A; `3A xx xx xx` = LD A,(addr)
  - `22 xx xx xx` = LD (addr),HL; `2A xx xx xx` = LD HL,(addr)
  - `ED 63 xx xx xx` = LD (addr),SP (and similar ED-prefix stores)
