# Task: Trace 0x0236F9 — Token Descriptor Sink

## Context
In the TI-84 Plus CE OS, when a key is pressed and processed through the token pipeline, function 0x022331 builds a 6-byte token descriptor on the stack via 0x022359 and hands it to `CALL 0x0236F9`. This is the "descriptor sink" — where token descriptors get queued or processed for actual execution. Understanding this function reveals the OS token queue mechanism.

The 6-byte descriptor structure (built by 0x022359) is:
- Byte 0: L (low byte of some value)
- Byte 1: H (high byte)
- Byte 2: IY+0x12 (flags byte)
- Byte 3: 0x01 (constant)
- Byte 4: cxCurApp (current app context)
- Byte 5: (unknown)

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase296-0236f9-descriptor-sink.mjs`

The probe must:
1. Read `TI-84_Plus_CE/ROM.rom` (4MB binary)
2. Starting at offset 0x0236F9, disassemble eZ80 instructions until function end (RET/JP tail call)
3. For each instruction: address, hex bytes, mnemonic
4. Look for:
   - Stack reads (POP, LD r,(SP+offset)) that consume the 6-byte descriptor
   - Memory writes that store the descriptor to a queue/buffer
   - Any CP (compare) instructions that filter on token values
   - CALL targets for further tracing
   - Any references to known OS addresses: D0058C (scan code), D0058E (keyExtend), D02500-D02510 (token table pointers)
5. Report function size and key findings

## eZ80 Decoding Reference
- eZ80 runs in ADL mode (24-bit addresses), addresses are 3 bytes LE
- CALL nn = 0xCD nn nn nn (4 bytes)
- RET = 0xC9
- JP nn = 0xC3 nn nn nn (4 bytes)
- POP rr = 0xC1/D1/E1/F1 (BC/DE/HL/AF)
- LD A,(nn) = 0x3A nn nn nn (4 bytes ADL)
- LD (nn),A = 0x32 nn nn nn (4 bytes ADL)
- CP n = 0xFE nn (2 bytes)
- IY prefix = 0xFD

