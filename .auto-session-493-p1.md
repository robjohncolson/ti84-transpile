# Auto-Session 493 P1: Decode Callers of 0x061003 (Cursor Erase Function)

## Context
We are reverse-engineering the TI-84 Plus CE OS ROM. The function at 0x061003 is the confirmed cursor ERASE function (clears from current row to screen bottom). We need to find the cursor DRAW function. The best approach is to decode the CALLERS of 0x061003, because the parent function that calls erase likely also calls draw.

Known callers of 0x061003:
- 0x05EE3E (CALL)
- 0x060F51 (CALL)
- 0x060FC3 (mid-function entry, ZERO direct callers)
- 0x06104E (mid-function entry, ZERO direct callers)
- 0x020E04 (JP)

Known callers of 0x06029D (eliminated as cursor draw — it's a screen init/clearing routine):
- 0x093258 (JP)
- 0x0B1C84 (JP)
- 0x0932C2 (CALL)

## Task
Create a probe `TI-84_Plus_CE/probe-phase493-decode-061003-callers.mjs` that:

1. **Static disassembly** of each caller function. For each of the 5 callers (0x05EE3E, 0x060F51, 0x060FC3, 0x06104E, 0x020E04):
   - Read ROM bytes starting from a reasonable function entry (back up to find the function prologue — look for PUSH AF/IX/IY patterns before the address)
   - Disassemble at least 100 bytes of each function
   - Log all CALL and JP targets found
   - Look specifically for: (i) companion CALL/JP to addresses near 0x061000-0x062000 (the draw function is likely nearby), (ii) flag-based branching (BIT/SET/RES instructions on IY offsets — these control draw vs erase), (iii) references to D00595/D00596 (cursor row/col), (iv) timer/counter references (D02658, D02505)

2. **Cross-reference search**: For each CALL/JP target found in step 1, check if any of them:
   - Fall in the 0x060000-0x062000 range (text editing system)
   - Are NOT 0x061000/0x061003/0x06029D (already known)
   - These are cursor draw candidates

3. **Dynamic test of 0x05EE3E and 0x060F51**: These have direct callers, so they're reachable. Set up:
   - Boot state from the standard 3-stage init (see existing probes for pattern)
   - Set D00595=5 (row), D00596=13 (col) for cursor position
   - Call each function and capture VRAM changes
   - Report: which addresses were called, what VRAM writes occurred, were any non-0xFF (non-white) pixels written?
