# Task: TRACE 0x001296 — What happens when interrupt status check returns Z

## Context
In the TI-84 CE ROM, the event handler at 0x001794 calls 0x001296 at address 0x00179A. If 0x001296 returns Z (zero flag set), the event handler takes JR Z to cleanup at 0x0017BC.

Session 465 decoded 0x001296: "Reads port 0x500C (FTINTC010 interrupt status) via IN A,(C) with BC=0x500C. Manipulates bit 0 of the port value (clear bit, write back, read again, AND 0x01, compare). Saves/restores the original value. Returns Z/NZ based on whether bit 0 was set — this is an INTERRUPT STATUS CHECK."

## Deliverable
Create `TI-84_Plus_CE/probe-phase466-0x001296-z-path.mjs` — a probe that:

1. **Disassembles 0x001296** using ROM bytes. Read bytes from the ROM file at offset 0x001296 (first 64 bytes should be enough). Print each instruction's hex bytes and a human-readable decode (use the eZ80 decoder in `ez80-decoder.js` if available, or manual decode).

2. **Disassembles the cleanup path at 0x0017BC** (the JR Z target). Read bytes starting at 0x0017BC (32 bytes should be enough). This is what happens when the interrupt status check returns Z (no interrupt pending). Decode and print.

3. **Traces what 0x0017BC does**: The cleanup at 0x0017BC does `LD (D00595),0x000000` then `JP 0x003A0F`. Document:
   - What D00595 is (24-bit word, cleared to 0)
   - Where 0x003A0F leads (event loop re-entry, already decoded in session 465)

4. **Tests the Z path** by running the event handler with port 0x500C returning 0 (so bit 0 is clear → Z). Boot the OS (3-stage boot as in other probes), inject a key, enter scheduler at 0x0015F7, and monitor whether 0x0017BC is hit.

## ROM Byte Reading
The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB raw binary). To read bytes at address X: `romBytes[X]`. The ROM occupies addresses 0x000000-0x3FFFFF.

## Output Format

1. Full disassembly of 0x001296 (until RET)
2. Full disassembly of 0x0017BC cleanup path (until JP)
3. What D00595 stores / who reads it
4. Analysis: under what conditions does 0x001296 return Z vs NZ?
5. Hit counts for 0x001296, 0x0017BC, 0x003A0F during the test run
