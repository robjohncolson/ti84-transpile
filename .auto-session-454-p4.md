# Task: Investigate 0x040852 — The D177B7=0x01 Outlier Writer

## Context
In auto-session 453, we mapped all 91 ROM references to D177B7. The display-dirty flag uses a THREE-STATE PROTOCOL: 0x00 (clean), 0x55 (dirty/needs-refresh), 0xAA (consumed/in-progress). But there is ONE OUTLIER: address 0x040852 writes 0x01 to D177B7. This doesn't fit the three-state model. What does 0x01 mean?

## Deliverable
Create `TI-84_Plus_CE/probe-phase454-d177b7-outlier.mjs` — a ROM analysis probe that investigates the 0x040852 site:

1. Hex dump the surrounding ROM region (0x040800-0x040900) to see the instruction context
2. Identify what instruction writes 0x01 to D177B7 at 0x040852. Is it `LD A,0x01; LD (D177B7),A`? Or `LD (D177B7),0x01`? Or something else?
3. Find the function containing 0x040852 — scan backward/forward for function boundaries
4. List all CALL instructions within the function (what it calls)
5. Search the ROM for all callers of this function
6. Determine: what is the function's purpose? Is it related to display? USB? Mode switching?
7. Check if the function also accesses D177B7 with other values (0x00, 0x55, 0xAA) or only 0x01
8. Check what other RAM addresses the function accesses — especially D141B5, D14091, VRAM range, LCD ports

## Implementation
ROM analysis probe — read the ROM binary directly.

```javascript
import fs from 'node:fs';
import path from 'node:path';
import { fileURLToPath } from 'node:url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));
```

### Key analysis steps:

1. **Hex dump 0x040800-0x040900**:
```javascript
for (let addr = 0x040800; addr < 0x040900; addr += 16) {
  const bytes = Array.from(romBytes.subarray(addr, addr + 16));
  const hex = bytes.map(b => b.toString(16).padStart(2, '0')).join(' ');
  console.log(`  ${addr.toString(16).padStart(6, '0')}: ${hex}`);
}
```

2. **Identify the instruction at 0x040852**: Read the bytes at that address. The write to D177B7 involves the byte pattern for `LD (D177B7),A` which would be `32 B7 77 D1` (STA abs24) or via a register indirect. The value 0x01 is loaded into A first: `3E 01` (LD A,0x01).

3. **Find function boundaries**: Scan backward from 0x040852 looking for RET (0xC9), JP (0xC3), or the start of a code block. Scan forward to the next RET.

4. **Search for callers**: Look for `CD xx 08 04` patterns in the ROM (CALL to 0x0408xx range). Also check for JP patterns.

5. **Check for other D177B7 access patterns within the same function**: Search for byte sequence `B7 77 D1` (the address D177B7 in little-endian) within the function.
