# Task: Trace Notification Payload CP Cascade at Page 0x012xxx

## Context
This is a TI-84 Plus CE ROM (eZ80) transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB).

Session 407 mapped 212 notification readers (200 for D177B8 payload, 12 for D177B9 type). The dominant access pattern is "payload discriminator": read D177B8, CP against a constant, branch. Page 0x012xxx was identified as having a LONG CP CASCADE checking ~10 payload values (0x0B, 0x0D, 0x96-0x9B, 0x01, 0xFF) all jumping to the same handler.

The notification system uses two RAM bytes:
- **0xD177B8** = notification payload (what happened)
- **0xD177B9** = notification type (which context)

## Your Task
1. **Find all references to 0xD177B8 in the 0x012000-0x012FFF range** (page 0x012xxx). Search for byte patterns:
   - `LD A,(0xD177B8)` = `3A B8 77 D1` (or with eZ80 prefixes)
   - `LD HL,0xD177B8` = `21 B8 77 D1`

2. **Disassemble the full CP cascade** at each hit site. For each comparison:
   - What payload value is being tested (the CP operand)?
   - Where does the branch go (JR/JP target)?
   - Do multiple comparisons branch to the same handler?

3. **Identify what each payload value triggers** — follow the branch targets to understand what OS action each notification payload value causes.

4. **Cross-reference with known notification types** from session 407:
   - Type 0x11 (Stat/List) = payloads 0x83-0x86 (scan codes)
   - Type 0x03 (Window/Format) = payloads 0x06-0x11 (indices)
   - Type 0x00 (switch/generic) = payloads 0x01-0x05

## Deliverables
- Create `TI-84_Plus_CE/probe-phase408-notification-cascade.mjs` — a Node.js probe that:
  - Loads the ROM
  - Finds all D177B8 references in page 0x012xxx
  - Disassembles the CP cascade at each site
  - Reports each comparison value and branch target
- Create `TI-84_Plus_CE/phase408-notification-cascade-report.md` — findings
