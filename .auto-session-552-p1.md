# Task: Decode 0x04C979 — Character Width Computation / Clipping

## Context
You are working on a TI-84 Plus CE ROM (eZ80) transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 machine code). We decode ROM functions by reading raw bytes from the ROM and disassembling them manually (eZ80 instruction set).

0x04C979 is called by 0x0A23E5 (the ~300B character renderer mega-function) at offset 0x0A244D. The call sequence is:
```
CALL 0x04C979    ; character width computation/clipping
POP DE
CCF
JP C,0x0A26D6    ; if carry → overflow → scroll/newline
```

The DE register at entry holds the pixel width limit for the current font mode:
- 0x000140 = 320px (full width, fixed-width mode)
- 0x0000A0 = 160px (large font)
- 0x0000BD = 189px (small font, proportional)
- 0x000061 = 97px (small font, fixed)
- 0x000124 = 292px (another mode)

After the call, carry flag indicates whether the character fits (NC) or overflows (C, but CCF inverts it so JP C means overflow).

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase552-decode-04C979.mjs` that:

1. Reads raw bytes from ROM at 0x04C979 for ~120 bytes
2. Disassembles them as eZ80 instructions (ADL mode, 24-bit addresses)
3. Looks for: what registers it reads (DE = width limit, A or B = character?), what RAM it accesses, what it returns in carry flag, any sub-calls
4. Prints a clear disassembly with annotations

## eZ80 Decoding Reference
- The ROM file is a flat binary. Address 0x04C979 = file offset 0x04C979.
- eZ80 ADL mode: default 24-bit addresses and 24-bit registers.
- Common opcodes: CB = bit ops, ED = extended ops, DD = IX prefix, FD = IY prefix, 40 52 = SIS prefix (16-bit override)
- LD instructions, CALL (CD xx xx xx = 4 bytes in ADL), JP (C3 xx xx xx), JR (18/20/28/30/38 xx), RET (C9)
- CP = compare (FE xx), BIT = test bit (CB xx), SET/RES = set/reset bit
- Key: 0x40 0x52 prefix = SIS (short instruction suffix — 16-bit operand override in ADL mode)
