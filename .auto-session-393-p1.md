# Task: Trace 0x02FEDB caller — what function contains it?

## Context
This is a TI-84 Plus CE ROM transpilation project. We're tracing the OS key-processing chain.

0x02FEDB is the sole caller of the 2ND-mode table reader function at 0x0300CB (via JP NZ from 0x02FEDB). We need to know what function 0x02FEDB belongs to — this is the top-level key dispatch that decides normal vs 2ND-mode translation.

## What to do

Create a probe file `TI-84_Plus_CE/probe-phase393-trace-02FEDB.mjs` that:

1. **Static disassembly**: Read the ROM bytes around 0x02FEDB to find the function boundaries. Scan backward from 0x02FEDB to find the function entry point (look for a known entry pattern or a CALL/JP target). Scan forward to find the RET/JP that ends the function.

2. **Cross-reference search**: Search the ROM for all CALL/JP instructions that target the function entry point you find. List all callers.

3. **Instruction decode**: Decode ALL instructions from function entry to function end. Document the control flow — what decisions does this function make? What RAM locations does it read/write?

4. **Key questions to answer**:
   - What function does 0x02FEDB belong to? (entry address and size)
   - How many callers does this function have?
   - What is the decision logic at 0x02FEDB that leads to calling 0x0300CB vs taking another path?
   - Does this function reference kbdKey (0xD0058C), kbdToken (0xD0058E), or the translation table (0x09F79B)?

## Known context from prior sessions
- 0x02FEDB contains: JP NZ,0x0300CB (calls the 2ND-mode table reader)
- 0x02FE73 is a known entry into the key dispatch chain: LD A,(D0058C) / OR A / JP Z,0x02FD99 / RES 2,(IY+0x43) / RES 5,(IY+0x1F) / CALL 0x030300 / RET

- The function 0x02FF8A-0x030078 is a large key-processing dispatcher with 13 callers

## ROM file
Read from: `TI-84_Plus_CE/ROM.rom` (4MB binary, little-endian eZ80)

## eZ80 instruction reference
- CALL nn = 0xCD nn(3 bytes LE) — 4 bytes total
- JP nn = 0xC3 nn(3 bytes LE) — 4 bytes total  
- JP cc,nn = condition codes: NZ=0xC2, Z=0xCA, NC=0xD2, C=0xDA
- RET = 0xC9
- LD A,(nn) = 0x3A nn(3 bytes LE)
- LD (nn),A = 0x32 nn(3 bytes LE)
- CP n = 0xFE n
- JR n = 0x18 offset (signed byte)
- JR NZ,n = 0x20 offset; JR Z,n = 0x28 offset
- BIT b,(IY+d) = 0xFD 0xCB d 0x46+(b*8)
- SET b,(IY+d) = 0xFD 0xCB d 0xC6+(b*8)
- RES b,(IY+d) = 0xFD 0xCB d 0x86+(b*8)
- In ADL mode (default), addresses are 3 bytes. LD r,nn for 16-bit regs loads 3 bytes.
