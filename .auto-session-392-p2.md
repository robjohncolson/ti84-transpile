# Task: Disassemble the 0x030117 Table Reader

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is a 4MB eZ80 binary at `TI-84_Plus_CE/ROM.rom`. Session 391 found a second reference to the translation table base 0x09F79B at address 0x03011D. This path does `ADD A,0x38` before table access and then `CP 0xE2` on the result. This is a different path from GetCSC (0x02FF0B).

## What to do
1. Write a Node.js probe at `TI-84_Plus_CE/probe-phase392-disasm-030117.mjs` that:
   - Reads `TI-84_Plus_CE/ROM.rom` (4MB binary, `fs.readFileSync`)
   - Statically disassembles from 0x0300F0 to 0x030180 (covering the area around 0x03011D)
   - Finds the function boundaries: search backward from 0x03011D for RET/RETI and forward for the next RET
   - Decodes key instructions: CALL, JP, JR, RET, ADD A, CP, LD, BIT/SET/RES
   - Searches the ENTIRE ROM for CALL/JP to addresses in the function range found
   - Identifies what the CP 0xE2 comparison means in context (what follows it? JR Z? JR NZ? What branch is taken?)

2. For eZ80 ADL-mode disassembly:
   - Most instructions use 3-byte addresses (CALL/JP = 4 bytes total)
   - `C3 xx xx xx` = JP, `CD xx xx xx` = CALL, `C9` = RET
   - `C6 xx` = ADD A,imm8, `FE xx` = CP imm8
   - `18 xx` = JR, `20/28/30/38 xx` = conditional JR
   - `CB xx` = bit ops, `DD/FD` = IX/IY prefix, `ED xx` = extended
   - Print raw hex for complex instructions you can't fully decode

3. Also check: what value is 0xE2 in the TI-84 token system? (0xE2 could be a sentinel or boundary marker in the translation table)

4. Run the probe and print all findings

- All callers identified
