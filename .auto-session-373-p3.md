# Task: Fix setKeyboardIRQ in peripherals.js

## Context
You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`.

Session 372 confirmed a bug in `peripherals.js`: the `setKeyboardIRQ` function uses bit 19 of the FTINTC010 interrupt controller raw status register. But bit 19 maps to port 0x5016 bit 3, which is the USB handler (0x001A5D), NOT the keyboard handler. The comment in the code says "bit 10 = keyboard" which would be port 0x5015 bit 2 (handler 0x001ABB — a simple acknowledge, also not keyboard).

**Critical finding from session 372**: NONE of the 7 ISR handlers in the FTINTC010 access keyboard ports (0xA000) or write to 0xD00587 or set bit 3 of 0xD00080. The TI-84 CE keyboard is ENTIRELY POLL-DRIVEN, not interrupt-driven.

The correct approach to inject keyboard input is:
1. When a key is pressed: write the scan code to mem[0xD00587] and set bit 3 of mem[0xD00080] (IY+0 flag)
2. When a key is released: clear the scan code and the flag
3. The `setKeyboardIRQ` function should be replaced with a `setKeyPressed(scanCode)` / `clearKeyPressed()` API that does direct RAM writes

## What to do
Edit `TI-84_Plus_CE/peripherals.js` to:

1. **Replace `setKeyboardIRQ`** with two new functions:
   ```javascript
   function setKeyPressed(mem, scanCode) {
     mem[0xD00587] = scanCode & 0xFF;
     mem[0xD00080] |= 0x08;  // Set bit 3 of (IY+0) = key available flag
   }
   
   function clearKeyPressed(mem) {
     mem[0xD00587] = 0x00;
     mem[0xD00080] &= ~0x08;  // Clear bit 3
   }
   ```

2. **Keep `setKeyboardIRQ` as a deprecated alias** that calls the new function (for backwards compat with browser-shell.html):

   ```javascript
     // This is a no-op now. Use setKeyPressed/clearKeyPressed instead.
   }
   ```
