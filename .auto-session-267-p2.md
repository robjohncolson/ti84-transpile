# Auto-Session 267 — P2: cxMain bypass probe — skip 0x08C69E, jump directly to cxMain

## Context

The boot path from 0x062055 reaches 0x08C69E, which eventually does JP(HL) at 0x08C745. But HL gets zeroed in that call chain, causing a reset-vector jump. Session 262 found that BIT 5,(IY+0x25) at 0x062055 is a gate — if bit 5 is set, execution takes a different path.

cxMain is at 0x058241. The pointer table at 0x0585D3 has [0]=0x0585E9 (cxMain). The home screen body is at [3]=0x0582BC.

## Task

Create a probe `TI-84_Plus_CE/probe-phase267-cxmain-bypass.mjs` that tests 3 experiments:

### Experiment 1: Direct entry to cxMain (0x058241)
- Standard setup: `createPeripheralBus({ timerInterrupt: false })`, load ROM.transpiled.js
- Set ADL=true, MBASE=0xD0
- Set IX=0xD1A860 (per-stage IX convention from CONTINUATION_PROMPT)
- Set IY=0xD00080 (standard OS IY base)
- Seed D0230F=0x3F (boot flags)
- PC = 0x058241
- Run 500 steps
- Log: unique blocks visited, final PC, whether 0x082BE2 (event loop) was reached, whether 0x0585E9 (cxMain dispatch) was reached

### Experiment 2: Direct entry to cxMain body (0x0585E9)
- Same setup as Exp1
- PC = 0x0585E9
- Run 500 steps
- Same logging

### Experiment 3: Direct entry to home body (0x0582BC)
- Same setup as Exp1
- PC = 0x0582BC  
- Run 500 steps
- Same logging

### Experiment 4: Boot from 0x062055 but SET bit 5 of (IY+0x25) to force alternate path
- Same setup as Exp1 but also seed D007D0=0x06C546, B=3
- Set IY+0x25 = D00080+0x25 = D000A5. Read current value, SET bit 5 (OR 0x20)
- PC = 0x062055
- Run 500 steps
- Same logging — does the alternate gate path reach cxMain?

For all experiments, track:
- Every unique block address visited
- Count of steps
- Whether key addresses were hit: 0x058241, 0x0585E9, 0x0582BC, 0x082BE2, 0x08C69E, 0x08C745, 0x000000
- Final PC and registers (A, HL, BC, DE)
