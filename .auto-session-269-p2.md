# Auto-Session 269 P2: Timer ISR + Event Loop — Does ISR Break Polling?

## Context
The TI-84 CE OS event loop is a tight 5-block polling loop at 0x082BE2→0x084716→0x08471B→0x084723→0x084711. It never exits in 50K steps with timerInterrupt:false.

The timer ISR fires every 200 ticks when timerInterrupt:true, dispatching via 0x1713→0x67F8→0x1C33. Previous sessions disabled it during boot to avoid an infinite ISR loop, but the event loop may NEED the ISR to break out.

Session 268 confirmed the path: boot with timerInterrupt:false, seed D007E8=0x06C546, call 0x062055(B=3, D0230F=0x3F) → reaches event loop at 0x082BE2.

## Task
Create a probe `TI-84_Plus_CE/probe-phase269-isr-event-loop.mjs` that:

1. **Boot with timer OFF** (timerInterrupt:false) through full init:
   - cold_boot: 20 steps
   - kernel_init: 2000 steps  
   - mem_init: 500000 steps (timerInterrupt:false)
   - Seed D007E8=0x06C546

2. **Enter event loop**: Call 0x062055 with B=3, D0230F=0x3F, run 200 steps to confirm we're in the polling loop.

3. **Enable timer ISR**: Set `peripherals.timerInterrupt = true` (or however the peripheral bus exposes it — check cpu-runtime.js). Then run 5000 more steps.

4. **Trace what happens**: Log unique block addresses visited after enabling the ISR. Did execution leave the 5-block polling set? Did it reach:
   - 0x0159C0 (keyboard scan)?
   - 0x06EDFE (CoorMon)?
   - 0x058241 (cxMain)?
   - Any new blocks not in the 5-block set?

5. **Alternative**: If timer ISR can't be toggled mid-run, try a different approach: inject a key scancode into the keyboard buffer at D0058E (the kbdScanCode address) and see if the polling loop detects it.
   - Write `mem[0xD0058E] = 0x8F` (scan code for key "2", from keyboard-matrix.md: group 3 bit 7 = idx=4,bit=7 → (4<<4)|7 = 0x4F... actually check the matrix)
   - OR write to whatever RAM address the loop condition checks (from P1's findings)

6. Report:
   - Did the ISR fire? (check if PC visited 0x001713 or 0x0067F8)
   - Did execution escape the 5-block loop?
   - What blocks were reached after ISR/injection?
   - If still stuck, what's the bottleneck?

## How to boot and run
```js
import { createRuntime, createPeripheralBus } from './cpu-runtime.js';
const peripherals = createPeripheralBus({ timerInterrupt: false });
const { cpu, mem } = createRuntime(peripherals);

// Boot sequence
cpu.pc = cpu.entryPoint; // cold_boot
for (let i = 0; i < 20; i++) cpu.step();
cpu.pc = 0x0002B0; // kernel_init
for (let i = 0; i < 2000; i++) cpu.step();
cpu.pc = 0x000324; // mem_init  
for (let i = 0; i < 500000; i++) cpu.step();

// Seed and enter event loop
mem[0xD007E8] = 0x46; mem[0xD007E9] = 0xC5; mem[0xD007EA] = 0x06; // 0x06C546 LE
mem[0xD0230F] = 0x3F;
cpu.registers.B = 3;
cpu.pc = 0x062055;
```

Note: The exact boot API may differ — check how probe-phase268 probes do it.
