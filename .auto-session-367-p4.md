# Task: Add Port 0xA000 Keyboard Controller Model to peripherals.js

## Context
The TI-84 CE ROM transpilation project has confirmed the OS reaches the main event loop and calls _GetCSC (keyboard scan routine) at 0x003D31. Session 366 found that _GetCSC uses port range 0xA000-0xA010:
- **0xA000**: Keyboard control register (write: select scan mode/group)
- **0xA008**: Keyboard data register (read: key status)
- **0xA010**: Keyboard data register (read: key data)

Currently these ports return 0xFF (default for unhandled ports), which means "no keys pressed." The OS scan routine polls keyboard groups with DJNZ 0x34 (52 iterations with delay). RAM state at 0xD00587-0xD0058D tracks keyboard debounce/repeat/scan codes.

The existing keyboard model at port 0x01 is the legacy Z80 keyboard matrix. Port 0xA000 is the CE-specific keyboard controller.

## Your task
Add a `createKeyboardControllerHandler` function to `TI-84_Plus_CE/peripherals.js` and register it for ports 0xA000-0xA010.

### Requirements

1. **Create the handler function** near the other handler functions in peripherals.js. It should:
   - Accept `state` and `keyboardState` parameters (reuse the existing `keyboardState` object)
   - Track the currently selected keyboard group/mode via writes to 0xA000
   - Return key status from `keyboardState.keyMatrix` on reads from 0xA008/0xA010
   - The CE keyboard controller uses 16-bit group selection (vs 8-bit on port 0x01)

2. **Port behavior**:
   - **Write to 0xA000**: Sets the keyboard scan group mask. The CE controller uses a 16-bit value where each bit selects a group (active low, same as port 0x01).
   - **Read from 0xA000**: Returns the last written scan group mask.
   - **Read from 0xA008**: Returns the combined key status for all selected groups (AND of all selected groups' keyMatrix entries). Same logic as port 0x01 read but accessed via memory-mapped I/O.
   - **Read from 0xA010**: Returns the same as 0xA008 (keyboard data).
   - **Other ports in 0xA000-0xA010**: Return 0x00 (status OK).

3. **Register the handler** after the existing keyboard port 0x01 registration. Use:
   ```javascript
   register({ start: 0xa000, end: 0xa010 }, createKeyboardControllerHandler(state, keyboardState));
   ```

4. **Expose in the returned state object**: Add `keyboardController` to the returned state (or reuse the existing `keyboard` property since both share `keyboardState`).

### Reference: Existing port 0x01 keyboard handler (lines 414-429 of peripherals.js)
```javascript
const keyboardState = { groupSelect: 0xFF, keyMatrix: new Uint8Array(8).fill(0xFF) };

register(0x01, {
  read() {
    let result = 0xFF;
    for (let g = 0; g < 8; g++) {
      if (((keyboardState.groupSelect >> g) & 1) === 0) {
        result &= keyboardState.keyMatrix[g];
      }
    }
    return result;
  },
  write(port, value) {
    keyboardState.groupSelect = value;
  },
});
```

### Reference: Handler registration pattern (from createFlashControllerHandler)
```javascript
function createFlashControllerHandler(state) {
  return {
    read(port) {
      if (port === 0x2001) {
        return 0x00;
      }
      return 0xFF;
    },
    write(port, value) {
      state.flashController.lastCommand = port === 0x2000 ? value : state.flashController.lastCommand;
      state.flashController.writes.set(port, value);
    },
  };
}
```
