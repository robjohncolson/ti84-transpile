# Auto-Session 202 P1: Digit Token Dispatch Path — Which BufInsert Call Site Handles Digits?

## Context
In the TI-84 Plus CE ROM transpilation project, we've been tracing how digit keypresses flow through the OS event loop to reach BufInsert (0x05E2A0). Session 201 proved that the CP 0x5D gate at 0x08011F rejects digit tokens (OP1[1] < 0x5D), so the 0x0584A3→Copy9→KeyClassifier→0x082C50 path is for **non-digit tokens only** (function keys with type ≥ 0x5D).

Session 182 disassembled the home handler (0x0582B8-0x058700) and found **5 direct BufInsert (0x05E2A0) call sites**:
- 0x058520
- 0x05852A
- 0x05853C
- 0x0585AD
- 0x0585CA

The key classification at 0x0584A7 calls 0x07F7BD which does: `LD A,(0xD005F8); AND 0x3F; RET` — reads OP1[0] type byte. CP 0x06/0x05 dispatch follows. Digit tokens have type 0x00, which falls through to the "else" branch.

## Task
Build a probe `TI-84_Plus_CE/probe-phase202-digit-bufinsert-path.mjs` that:

1. **Static disassembly of the 5 BufInsert call sites**: For each address (0x058520, 0x05852A, 0x05853C, 0x0585AD, 0x0585CA), disassemble the surrounding block (±30 bytes) to understand the control flow leading to each CALL 0x05E2A0. What condition gates each call? What's in the registers at each call site?

2. **Trace from 0x0584A7 (KeyClassifier call) with a digit-type token**: Set up:
   - OP1 = digit-4 token: `[0x00, 0x34, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]` at 0xD005F8
   - TOKEN_STAGING (0xD0230E) = same digit-4 bytes (Copy9 source)
   - IY = 0xD00080
   - IX = 0xD1A860
   - SP = 0xD1A87E
   - Edit buffer at 0xD00A00 initialized (cursor at 0xD00A00, empty buffer)
   - Entry at 0x0584A7 (the CALL 0x07F7BD instruction — key classifier)
   
   Run for 500 steps. Log every block visited, every CALL instruction, and check if any of the 5 BufInsert addresses are reached. Also log writes to the edit buffer area (0xD00A00-0xD00AFF).

3. **If BufInsert not reached at 0x0584A7**: Try entry at 0x058514 (the address after the BIT 5 JR Z branch, where bit-5-CLEAR path goes). Set same OP1/TOKEN_STAGING state. Run 500 steps. This is the path session 198 identified as the bit-5-CLEAR branch.

4. **If BufInsert not reached at 0x058514**: Try each of these entry points with the digit token state:
   - 0x058518 (instruction after 0x058514)
   - 0x05851C (another candidate — falls through from 0x058518)
   
   Run 200 steps each.
