# Task: STAT dispatch — investigate RAM state and CoorMon-level entry

## Context

Session 188 extended the STAT key trace to 3000 steps but found the handler at 0x0585E9 (cxMain/HomeContext entry) returns in only 47 steps WITHOUT reaching 0x059xxx (STAT app area). The handler compares against 0x05, 0x07, 0x0A-0x0F, 0x21, 0x5A, 0xFA — but NEVER against 0x31 (STAT key code). 

Key insight: the handler uses table lookup / indirect jump, NOT a sequential CP chain. The key code 0x31 is likely consumed by an earlier stage of the state machine (CoorMon/GetKey layer) that sets up context variables in RAM before entering cxMain. Entering cxMain directly with A=0x31 bypasses that setup.

## Your Task

Create `TI-84_Plus_CE/probe-phase189-stat-coormon-entry.mjs` that:

### Part A: Identify what RAM the handler reads

1. Set up standard OS init (MemInit at 0x09DEE0)
2. Enter the home context handler at 0x0585E9 with A=0x31 (STAT scan code) as session 188 did
3. But this time, **instrument memory reads** in the first 47 steps — log every memory READ from the D0xxxx/D1xxxx range (RAM). Focus especially on:
   - 0xD00587 (rawKeyStatus / kbdScanCode)
   - 0xD0058C (keyCode)
   - 0xD0058D (kbdGetKy / getKy)
   - 0xD0058E (getCSCscan)
   - 0xD00080-0xD000FF (IY-relative flags area)
   - Any address in 0xD00500-0xD00600 range
4. Report which RAM addresses the handler reads and what values it finds there

### Part B: Try GetKey-level entry

The CoorMon dispatcher (around 0x080xxx) handles the key-to-context routing. Try:

1. Same OS init setup
2. Write 0x31 to 0xD0058D (getKy RAM variable) — this is where GetKey stores its output
3. Also write 0x31 to 0xD0058C (keyCode)
4. Set IX=0xD1A860, IY=0xD00080, SP=0xD1A87E
5. Try entering at 0x0802B2 (POST_INIT_ENTRY / CoorMon main loop) with step limit 500
6. Log the execution trace — does it read the key code from RAM? Does it dispatch to 0x059xxx?

### Part C: Check the context table at 0x0585D3

The probe from session 188 defines HOME_CONTEXT_TABLE = 0x0585D3. Read the ROM bytes at this address (it's likely a jump table indexed by key code). Dump the first 128 bytes and see if there's an entry for key code 0x31. Report what the table structure looks like.

## Key Addresses

- Home context entry (cxMain): 0x0585E9
- Home context table: 0x0585D3
- CoorMon/PostInit entry: 0x0802B2
- GetCSC translation table: 0x09F79B
- RAM key variables: 0xD00587 (rawScan), 0xD0058C (keyCode), 0xD0058D (getKy), 0xD0058E (getCSCscan)
- IY base: 0xD00080
- IX: 0xD1A860
- Stack top: 0xD1A87E
- STAT app area: 0x059000-0x05A000
- MemInit entry: 0x09DEE0, ret stub: 0x7FFFF6
