# Task: Investigate JP Table Entries at 0x020104+

## Context

This is the TI-84 Plus CE ROM transpilation project. The OS ROM is lifted to JavaScript. Session 376 discovered that ROM region 0x020104+ contains a JP (jump) table — sequential `C3 xx xx xx` entries that are JP instructions to various ROM addresses.

The ROM region 0x020000-0x020200 was partially decoded in session 376:
- 0x020000-0x020027: structured table entries with 0x80 prefix (type/payload format)
- 0x020028-0x0200F9: zeros
- 0x0200FA-0x020103: flash-test magic bytes (5A A5 ...)
- 0x020104+: JP table (C3 xx xx xx entries)

## What to Do

Write a probe `TI-84_Plus_CE/probe-phase377-jp-table.mjs` that:

1. **Dump and decode the JP table at 0x020104-0x020200**:
   - Read ROM bytes from 0x020104 onwards
   - For each 4-byte group starting with 0xC3 (JP opcode in eZ80 ADL mode): decode the 3-byte target address (little-endian: byte1 + byte2<<8 + byte3<<16)
   - Print each entry as: `0x020104: JP 0xXXXXXX`
   - Stop when you hit a non-C3 byte or reach 0x020200
   - Count total entries

2. **Cross-reference each JP target**:
   - For each target address, read the first few bytes at that address from ROM
   - Decode the first instruction at the target using `ez80-decoder.js`
   - Classify: is the target a function entry (PUSH IX/AF, LD pair, etc.)? A trampoline (another JP)? A data region?
   - Print the first instruction at each target

3. **Check if any JP targets are known addresses**:
   - Compare against known key addresses:
     - 0x003A73 (event loop), 0x003A7D (dispatch), 0x003D5A (_GetCSC)
     - 0x001713, 0x001853, 0x001933, 0x000721
     - 0x003C63 (keyboard scan), 0x0067F8 (GPIO checker)
     - 0x001C33, 0x001C4F, 0x001CA6 (table parsers)
   - Report any matches

4. **Check the region before the JP table (0x0200FA-0x020103)**:
   - Dump the bytes in hex
   - The flash-test magic 5A A5 was found here — decode the full structure

5. **Investigate connectivity**: Does any code in the boot path or event loop reference addresses in the 0x020104+ range? Search the ROM for references:
   - Grep the ROM binary for any 3-byte little-endian address sequences that point into 0x020100-0x020200
   - Check if 0x020104 (or nearby addresses) appear as CALL/JP targets anywhere in the first 0x100000 bytes of ROM
