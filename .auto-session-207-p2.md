# Auto-Session 207 P2: PushErrorHandler before STAT entry

## Context
In the TI-84 Plus CE ROM transpilation project, the STAT (1-Var Stats) pipeline hits an error condition at step <100 and enters an infinite event/redraw loop waiting for user dismiss (which never comes in headless mode). OP1=0x032D after error. Session 206 confirmed the error is NOT caused by list format or VAT format — 4 experiments all produce identical error.

Session 188-200 proved that **PushErrorHandler** works for ParseInp: install error frame at 0x07C88B with HL=recovery address, then when JError fires, execution jumps to the recovery address instead of entering the infinite dismiss loop.

## Task
Build a probe `TI-84_Plus_CE/probe-phase207-stat-pusherror.mjs` that:

1. Sets up a cold-boot runtime with properly seeded list data
2. Installs PushErrorHandler (0x07C88B) with a recovery address BEFORE entering the STAT pipeline
3. Enters the STAT pipeline at 0x058BA9 (cxErrorEP / STAT entry, context table entry [4])
4. Traces execution to see if:
   - The error handler catches the error instead of entering the infinite loop
   - Any STAT computation results appear in RAM before the error
   - The recovery continuation can be used to extract partial results

## Setup details (from sessions 194-206)

### List seeding (session 202 fix: seed NEAR 0xD01600, not far at 0xD10000)
```javascript
// L1 = {1.0, 2.0, 3.0} at 0xD01600
const listBase = 0xD01600;
// List header: count = 3 (little-endian 16-bit)
mem[listBase] = 0x03; mem[listBase+1] = 0x00;
// Element 1: 1.0 in BCD = 00 80 10 00 00 00 00 00 00
const e1 = listBase + 2;
mem[e1+0]=0x00; mem[e1+1]=0x80; mem[e1+2]=0x10;
// Element 2: 2.0 = 00 80 20 00 00 00 00 00 00
const e2 = e1 + 9;
mem[e2+0]=0x00; mem[e2+1]=0x80; mem[e2+2]=0x20;
// Element 3: 3.0 = 00 80 30 00 00 00 00 00 00
const e3 = e2 + 9;
mem[e3+0]=0x00; mem[e3+1]=0x80; mem[e3+2]=0x30;

// VAT entry at 0xD1A800
const vatBase = 0xD1A800;
mem[vatBase] = 0x01;  // type = real list
// pointer to list data (little-endian 24-bit)
mem[vatBase+1] = 0x00; mem[vatBase+2] = 0x16; mem[vatBase+3] = 0xD0;
// name: L1 = 0x5D 0x00
mem[vatBase+4] = 0x5D; mem[vatBase+5] = 0x00;
```

### PushErrorHandler pattern (from session 188/200)
```javascript
// PushErrorHandler: CALL 0x07C88B with HL = recovery address
// It pushes an error frame onto errSP so JError jumps to HL instead of the dismiss loop
// Set HL to a known address (e.g., 0x082BE2 which is the OS event loop, or better: 
// a custom recovery point)
cpu.registers.hl = RECOVERY_ADDRESS;
// Execute block 0x07C88B
```

### STAT entry
- Entry point: 0x058BA9 (cxErrorEP, context table entry [4])
- Session 190: Entry 4 reaches STAT area 0x091Exx, then hit missing block at 0x092263 (later seeded)
- Session 191: Entry 4 reaches 87 unique blocks, gets to 0x092263 (LDDR)
- Session 204-206: Error loop at 0x082BE2, 264 blocks, "Error" string at 0xD008E6+14
