# Task: Trace 0x051ADC in post-computation path

## Context
Session 242 showed the post-0x04EE06 path goes: 0x04E447→0x04E459→0x04E25B→0x051ADC→...→0x0A1B5B (computation + display refresh). We need to trace what 0x051ADC does and its sub-calls to understand the path between computation and display refresh.

## What to do

1. Create a probe `TI-84_Plus_CE/probe-phase243-051adc-post-computation.mjs` that:
   - Uses the same boilerplate as `probe-phase242-04ee00-return-path.mjs` (cold boot + kernel init + state setup)
   - Sets up the same state as the session 242 probes (D003E0=0x00, edit buffer seeded, gap buffer initialized)
   - Calls 0x051ADC directly (set up SP with return sentinel 0x7FFFFE, push sentinel to stack)
   - Traces 500 steps with detailed logging:
     - All unique blocks visited
     - All CALL destinations (to identify sub-functions)
     - All RAM writes (especially D003xx, D005xx, D00Axx regions)
     - IY flag changes
     - Register state at entry and every 50 steps
   - Also does a SECOND run entering from 0x04E447 (the computation path entry) with 2000 steps to show the full 0x04E447→0x051ADC→0x0A1B5B chain
   - Reports: function structure of 0x051ADC, sub-call targets, what it modifies, how it connects to the display refresh at 0x0A1B5B

2. Additionally, dump the raw ROM bytes at 0x051ADC-0x051B30 (80 bytes) for manual eZ80 disassembly context.

3. Run the probe:
   ```bash
   node TI-84_Plus_CE/probe-phase243-051adc-post-computation.mjs
   ```

## Key addresses
- 0x051ADC: target function to trace
- 0x04E447: computation path entry (runs before 0x051ADC)
- 0x04E459: intermediate block between 0x04E447 and 0x04E25B
- 0x04E25B: block that calls/jumps to 0x051ADC
- 0x0A1B5B: display refresh entry (expected downstream)
- D003E0: mode flag byte (should be 0x00 for home screen)
- D0059F: key state variable
- 0xD00A00: edit buffer start
- 0xD0243A: edit cursor pointer

## Constraints
- Do NOT modify `cpu-runtime.js`, `peripherals.js`, `ez80-decoder.js`, or `browser-shell.html`
- Use `createPeripheralBus({ timerInterrupt: false })`
- Do NOT re-run the transpiler
- If ROM.transpiled.js doesn't exist, generate it: `node scripts/transpile-ti84-rom.mjs`

## Success criteria
- We know the function structure of 0x051ADC (entry, sub-calls, exit)
- We know what 0x051ADC modifies (RAM writes, IY flags)
- We can trace the full path from 0x04E447 through 0x051ADC to 0x0A1B5B
