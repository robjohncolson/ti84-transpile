# Auto-Session 298 — Priority 2: Fix Missing 0xE00900 Write Handler

## Task
Add a write handler for keyboard MMIO address 0xE00900 (group select) in `cpu-runtime.js`. Currently, writes to 0xE00900 silently fall through.

## Context
The TI-84 CE primary keyboard scanner at 0x0159C0 writes group select values to 0xE00900 via `LD (0xE00900),A` before reading key state back. The write handler in `cpu-runtime.js` handles the keyboard controller range 0xE00800-0xE00920 (line 945) but does NOT handle reg === 0x100 (which corresponds to address 0xE00900).

The read handler (line 915) already handles reg === 0x100 correctly — it scans the key matrix for pressed keys and returns a scan code.

The port-based keyboard handler in `peripherals.js` (line 365-380) has `keyboardState.groupSelect` which is set on port 0x01 writes. But the MMIO keyboard controller in `cpu-runtime.js` (line 853) uses `kbdMmio` which has NO groupSelect field.

## What to Change

```javascript
if (reg === 0x100) {
  // 0xE00900: keyboard group select — OS writes group mask before reading key state
  // The read handler at reg 0x100 should use this to return only the selected group's keys
  kbdMmio.groupSelect = value;
  return;
}
```

Also add `groupSelect: 0xFF` to the `kbdMmio` object initialization (around line 853).

Then update the READ handler for reg === 0x100 (around line 915-927) to use `kbdMmio.groupSelect` instead of scanning all groups. The read should return the combined key state for only the groups selected by the group select mask (active-low: bit 0 clear = group 0 selected):

```javascript
if (reg === 0x100) {
  let result = 0xFF;
  for (let g = 0; g < 8; g++) {
    if (((kbdMmio.groupSelect >> g) & 1) === 0) {
      result &= kbd.keyMatrix[g];
    }
  }
  return result;
}
```

This mirrors the logic already in `peripherals.js` port 0x01 read handler (lines 368-375).
