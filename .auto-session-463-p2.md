# Auto-session 463 P2: Decode 0x0067F8 port 0x03 check function

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The function at 0x0067F8 is called from 0x001723 as part of the ISR guard at 0x001713. It reads eZ80 port 0x03 (the MBASE/GPIO register) and returns HL=1 (pass) or HL=0 (fail). The return value determines whether keys route to processing or sleep.

## Task
Create a probe `TI-84_Plus_CE/probe-phase463-port03-decode.mjs` that:

1. Boots the OS using the standard 3-stage boot
2. Sets D177BA=0x00 (clear event gate so 0x001713 falls through to 0x0067F8)
3. Runs the event loop from 0x003A73 with port-0x03 I/O tracing enabled
4. Captures EVERY port read/write during the run, especially port 0x03
5. Tracks the return value of 0x0067F8 (HL register after the function returns)
6. Tests multiple gpioValue settings: 0x00, 0x01, 0xEE (default), 0xFF
7. For each gpioValue, reports: did 0x0067F8 return HL=1 or HL=0? Did execution reach 0x001853 (key processing)?

## ROM bytes at 0x0067F8 (56 bytes)
```
dd e5 dd 21 00 00 00 dd 39 dd 27 06 cd 4f 1c 00
11 c0 80 00 cd 33 1c 00 20 12 cd 4f 1c 00 ed 38
03 a6 23 be 20 06 21 01 00 00 18 04 21 00 00 00
dd e1 c9
```

Key instructions in the function:
- `IN0 A,(0x03)` at some point (ed 38 03 = IN0 A,(0x03))
- `AND (HL)` — mask the port value
- `INC HL` — advance to expected value
- `CP (HL)` — compare masked port value against expected
- If match: LD HL, 0x000001 (pass)
- If no match: LD HL, 0x000000 (fail)

The mask and expected value come from data pointed to by HL (set up by CALL 0x001C4F).

## What to discover
1. What is the mask byte AND'd with port 0x03's value?
2. What is the expected value after masking?
3. What gpioValue (port 0x03 return) makes the check pass?
4. What do 0x001C4F and 0x001C33 do? (helper functions called in the body)

## Peripherals
Port 0x03 is the GPIO handler in peripherals.js. It returns `state.gpio.readValue` which defaults to `options.gpioValue ?? 0xee`. You can pass different values:
```javascript
createPeripheralBus({ pllDelay: 2, timerInterrupt: false, gpioValue: 0x01 })
```

## Implementation approach
- Run the test 4 times with different gpioValue settings
- For each run: boot, set D177BA=0x00, inject key (0xD00587=0x29, 0xD00080|=0x08), run event loop

- Track whether PC reaches 0x001853 (key processing) or 0x001933 (sleep)
- After each run, report the gpioValue, port 0x03 reads, and verdict
