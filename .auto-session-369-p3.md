# Task: Disassemble Post-Scan Handler Blocks

## Context
The TI-84 Plus CE OS event loop polls _GetCSC 100 times, then falls through to a chain of handlers:
- 0x003A7D: `CALL 0x001713` (cursor/timer handler)
- 0x003A81: `JP NZ, 0x001933`
- 0x003A85: `JP 0x003A89`
- 0x003A89: `CALL 0x001853`
- 0x003A8D: `XOR A`
- 0x003A8E: `JP 0x000721`

We need to disassemble the ROM at these 4 handler entry points to understand what they do.

## Deliverable
Create `TI-84_Plus_CE/probe-phase369-disasm-post-scan.mjs` that:

1. Reads ROM.rom directly (no transpiled blocks needed)
2. For each of these 4 addresses: 0x001713, 0x001933, 0x001853, 0x000721
   - Disassemble 64 bytes starting at each address using the eZ80 decoder
   - Print the raw hex bytes + decoded mnemonic for each instruction
   - Note any CALL/JP/JR targets and RET instructions
   - Identify what peripheral ports are accessed (IN/OUT instructions)
3. For any CALL/JP targets discovered in step 2 that are within 0x000000-0x00FFFF range, disassemble an additional 32 bytes at those targets (one level of call depth)

## Reference: How to use the eZ80 decoder
The decoder is at `TI-84_Plus_CE/ez80-decoder.js`. Usage pattern:
```javascript
import { decodeInstruction } from './ez80-decoder.js';

// Read ROM bytes
const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));

function disassembleAt(addr, maxBytes = 64) {
  let pc = addr;
  const end = addr + maxBytes;
  while (pc < end) {
    const result = decodeInstruction(romBytes, pc, true); // true = ADL mode
    // result has: { mnemonic, length, bytes }
    // Format output with hex address, raw bytes, mnemonic
    const rawHex = Array.from(romBytes.slice(pc, pc + result.length), b => b.toString(16).padStart(2, '0')).join(' ');
    console.log(`  ${hex(pc)}: ${rawHex.padEnd(20)} ${result.mnemonic}`);
    pc += result.length;
  }
}
```

Note: The decoder's exact API may vary — check the export from `ez80-decoder.js`. The function might be `decode` or `decodeInstruction`. The result object likely has `mnemonic` and `length` (or `size`). Read the first ~50 lines of `ez80-decoder.js` to confirm the API before using it.

## Key questions this probe should answer
- What does 0x001713 do? (Suspected cursor blink / timer tick)
- What does 0x001933 do? (Post-cursor dispatch)
- What does 0x001853 do? (Secondary handler)
- What does 0x000721 do? (Event loop re-entry? Or different function?)
- Do any of these handlers write to the LCD buffer (0xD40000+)?
- Do any reference timer ports (0xF20000+)?
- Do any reference keyboard ports (0xA000+)?
