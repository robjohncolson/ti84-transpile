# Auto-Session 456 — P2: Investigate D141B5=0x60 Key Code Mapping

## Context

This is a TI-84 Plus CE ROM transpilation project. The ROM at `TI-84_Plus_CE/ROM.rom` is a 4MB eZ80 binary.

**Key finding from session 455**: After injecting scan code 0x12 into D00587 and running the event loop, D141B5 ends up containing 0x60. The key processor at 0x03FA09 is supposedly pass-through (copies D00587 → D141B5 directly), yet D141B5=0x60 ≠ 0x12.

**Keyboard matrix**: Per `keyboard-matrix.md`, scan code 0x12 = "-" key (group 1, bit 2). Key "1" is actually at scan code 0x41 (group 4, bit 1). The _GetCSC scan code table at 0x03FC41 is 64 bytes (8x8 matrix).

## Task

Create a probe `TI-84_Plus_CE/probe-phase456-getCSC-table-dump.mjs` that:

1. Reads the ROM file directly (`ROM.rom`)
2. Dumps the 64-byte _GetCSC scan code table at ROM offset 0x03FC41 (this is within the first 4MB so it's a direct file offset)
3. Formats the table as an 8x8 grid showing the key code at each position
4. Cross-references: if the table maps index 0x12 → 0x60, that explains the D141B5 value
5. Also dumps the surrounding bytes (0x03FC00 - 0x03FC80) to see the full context of the key code translation function

Additionally:

6. Disassemble ROM bytes at 0x03FC1C-0x03FC40 (the GetK function that reads D0058D and does the table lookup). Use raw byte interpretation — the CPU is eZ80 in ADL mode (24-bit addresses). Key opcodes:
   - `LD A,(nnnnnn)` = 0x3A nn nn nn
   - `LD HL,nnnnnn` = 0x21 nn nn nn  
   - `ADD A,L` / `ADD A,H` etc. for table indexing
   - `LD L,A` + `LD H,0` for 8→16 bit extension
   - `LD A,(HL)` = 0x7E for table read
   - `CALL nnnnnn` = 0xCD nn nn nn
   - `JP nnnnnn` = 0xC3 nn nn nn
   - `RET` = 0xC9

7. Print the full scan code → key code mapping: for each scan code 0x00-0x3F, show what key code the table yields, and label known keys from the keyboard matrix

## Deliverables
- `TI-84_Plus_CE/probe-phase456-getCSC-table-dump.mjs`
- Console output: 8x8 table dump, disassembly of 0x03FC1C-0x03FC40, full scan-to-keycode map

## Constraints

- This is a pure ROM analysis probe — no CPU execution needed, just read the ROM file
