# Task: Trace 0x07A627 — called from 0x051B7C when D003DD matches 0x4A/0x48/0x49

## Context
In the TI-84 Plus CE ROM transpilation project, session 241 decoded the BIT 4 guard at 0x051B84 inside parent function 0x051B7C-0x051BD9. The function has a CP cascade on D003DD: when the value matches 0x4A, 0x48, or 0x49, it calls 0x07A627. These key codes suggest graph (0x48)/table (0x49)/stat (0x4A) context. We need to understand what 0x07A627 does.

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase242-07a627-trace.mjs`

## What the probe must do
1. **Static analysis**: Dump ROM bytes at 0x07A627-0x07A700 (hex + instruction decode) to understand the function structure.

2. **Dynamic trace with D003DD=0x4A (STAT context)**:
   - Set up warm state: full boot + homescreen stages, IX=0xD1A860, timer IRQ disabled
   - Set mem[0xD003DD] = 0x4A
   - Set up minimal call frame (push return sentinel, set PC=0x07A627)
   - Run up to 500 steps
   - Log: every unique block visited, register state at entry, RAM writes, return value (A register at RET)

3. **Dynamic trace with D003DD=0x48 (graph context)**:
   - Same setup but D003DD=0x48
   - Run up to 500 steps, compare path

4. **Dynamic trace with D003DD=0x49 (table context)**:
   - Same setup but D003DD=0x49
   - Run up to 500 steps, compare path

5. **Also trace from the actual caller 0x051B7C**:
   - Set D003DD=0x4A, D0059F to a non-0x80 value, D003E0 BIT 4 CLEAR, D010F8=0x00
   - Call 0x051B7C with return sentinel
   - Run up to 200 steps
   - Verify the CP cascade reaches CALL 0x07A627
