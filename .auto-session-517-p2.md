# Auto-Session 517 — P2: Decode 0x03E1B4 (Token Processor)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary).

Session 516 decoded 0x061D1A as a LONGJMP-style key-to-token handler. The common handler at 0x061DB2 does:
- `LD (D008DF),A` — stores the token code
- `CALL 0x03E1B4` — processes the token
- Clears 4 flags: IY+4B bit 7, IY+12 bit 2, IY+24 bit 4, IY+49 bit 1
- `LD SP,(D008E0)` → `POP AF` → `RET` — longjmp back to event loop

0x03E1B4 is the function that ACTUALLY processes token/command codes after a key press. The token byte is stored in D008DF before this call. Understanding 0x03E1B4 reveals what each key token actually does (screen clear for 0x88, character insert, etc.).

- Each instruction with address, hex bytes, and mnemonic
- All CALL/JP/JR targets

- All conditional branches and what they test
- Where the function returns (RET / RET Z / RET NZ / etc.)

### Part 2: Dynamic trace (if safe)
