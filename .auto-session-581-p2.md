# Task: DECODE 0x06ADC9/0x06ADD1 — MODE Handler Pair

## Context
This is part of TI-84 Plus CE ROM transpilation. Session 580 decoded the multi-key dispatcher at 0x06CF41 (271 bytes, 85 instructions). It handles 9+ key codes. Keys 0x89 and 0x8B share a JP target at 0x06ADC9, and key 0x8D (MODE) dispatches to 0x06ADD1. Neither has been decoded yet.

The key dispatch flow: event loop 0x08C331 → key pre-processor 0x06CE73 → inner worker 0x06CE7F filters CLEAR/DEL/MODE/GRAPH → multi-key dispatcher 0x06CF41 → for MODE 0x8D → JP 0x06ADD1.

## Your Task
Write a probe at `TI-84_Plus_CE/probe-phase581-decode-06ADC9.mjs` that statically disassembles BOTH functions starting at 0x06ADC9 and 0x06ADD1, and write a report to `TI-84_Plus_CE/phase581-decode-06ADC9-report.md`.

### What to do
1. Read ROM bytes starting at 0x06ADC9 using the pattern: `import fs from 'fs'; const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');` then `rom[addr]` for any address.
2. Decode eZ80 instructions manually from raw bytes. The eZ80 is a Z80 superset with ADL mode (24-bit addresses). Key patterns:
   - `0xCD nn nn nn` = CALL addr (3-byte LE in ADL mode)
   - `0xC3 nn nn nn` = JP addr
   - `0xC9` = RET
   - `0x18 dd` = JR dd (signed); `0x20 dd` = JR NZ; `0x28 dd` = JR Z
   - `0xCB` = bit ops prefix; `0xFD` = IY prefix; `0xDD` = IX prefix; `0xED` = extended
   - `0x3E` = LD A,n; `0x21 nn nn nn` = LD HL,addr; `0x32 nn nn nn` = LD (addr),A
3. Note that 0x06ADC9 and 0x06ADD1 may be part of the same contiguous function, or 0x06ADC9 may be a short stub that falls through to 0x06ADD1. Decode both.
4. Decode at least 150 bytes from 0x06ADC9 (or until you hit terminal RET/JP).
5. Look for:
   - RAM references (0xD00000-0xD3FFFF)
   - IY+offset operations
   - CALL targets — what subroutines does the MODE handler call?
   - Screen-mode bit testers (known: 0x06C72D BIT 4 IY+2, 0x06C732 BIT 5 IY+2, 0x06C737 BIT 6 IY+2, 0x06C73C BIT 7 IY+2)
   - D007E0 (current OS mode variable, values: 0x40=main, 0x49=alternate, 0x43/0x48/0x44/0x4A/0x4B=other modes)
   - Exit paths (JP 0x08C331 = event loop return, JP 0x08C33D = cleanup, JP 0x06AB29/0x06AB15/0x06AABF = known exits from 0x06CF41)
6. Count callers: grep ROM for `CD C9 AD 06` (CALL 0x06ADC9) and `CD D1 AD 06` (CALL 0x06ADD1) and JP variants.

### Report format
Write `phase581-decode-06ADC9-report.md` with:
- Function addresses, sizes, instruction counts
- Full annotated disassembly for both entry points
- RAM addresses referenced
- IY+offset flags touched
- CALL targets
- Caller list
- Architectural summary: what do keys 0x89/0x8B do? What does MODE (0x8D) do? How does the handler change the current OS mode?

### Constraints
- Do NOT modify any existing file except to CREATE the two new files
- Do NOT run any probes
- Static analysis only

### Success Criterion
Report accurately decodes both entry points and explains what the MODE key handler does.
