# Task: Trace the real OS scheduler at 0x001612

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM (eZ80 machine code) has been lifted to JavaScript. We're tracing the OS event loop to understand how keys get processed.

**Key finding from session 444**: The scheduler at 0x001612 is the outer caller that re-enters the event loop after HALT wake. It calls 0x001794, which via error-detection logic eventually JP 0x003A0F (error display + key poll at 0x003A05-0x003A8E). After HALT wake, RET returns to ~0x001612, which loops. The error handler function at 0x003A05-0x003A8E displays "ERROR! Press any key to turn unit OFF" then polls keyboard via CALL 0x003D5A up to 100x.

## Task
Write a probe script `TI-84_Plus_CE/probe-phase445-scheduler-trace.mjs` that:

1. Reads the ROM binary at `TI-84_Plus_CE/ROM.rom`
2. Disassembles the function at 0x001612 and surrounding context (0x001600-0x001700) using raw byte decoding. The ROM is eZ80 machine code.
3. For each instruction, decode the opcode and operands. Key eZ80 opcodes to handle:
   - CALL nn (0xCD + 3-byte address in ADL mode)
   - JP nn (0xC3 + 3-byte address in ADL mode)
   - JP cc,nn (0xC2/CA/D2/DA + 3-byte address)
   - RET (0xC9)
   - HALT (0x76)
   - LD r,n / LD r,(HL) etc
   - DI (0xF3), EI (0xFB)
   - JR e (0x18), JR cc,e (0x20/28/30/38)
   - RST n (0xC7/CF/D7/DF/E7/EF/F7/FF)
   - CP n (0xFE)
   - OR A (0xB7)
   - AND n (0xE6)
4. Identify what 0x001612 does between its calls. Does it call 0x001794? Does it have a loop structure? Does it handle display refresh?
5. Look at what 0x001794 does (disassemble 0x001794-0x001850).
6. Check if there's a display refresh call in the scheduler loop.

Also write a report file `TI-84_Plus_CE/phase445-scheduler-trace-report.md` with:
- Full disassembly of 0x001600-0x001700
- Full disassembly of 0x001794-0x001850
- Analysis of the scheduler's loop structure
- Whether display refresh is called from the scheduler
- Call graph from 0x001612
