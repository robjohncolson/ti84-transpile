# Task: Decode 0x0A1A9D + 0x0A1B1C — Framebuffer Address Computation

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 binary).

## What we know
- 0x0A1A9D and 0x0A1B1C are called during the blit loop setup (0x0A24C8-0x0A2536) in the character renderer.
- They compute a framebuffer row start address from x,y coordinates.
- The framebuffer pointer is stored at D0059C.
- Row strides are 0x140 (320 bytes = half-row) or 0x280 (640 bytes = full 320px row at 16bpp).
- The TI-84 Plus CE LCD is 320×240 at 16bpp (RGB565), so full framebuffer = 320×240×2 = 153,600 bytes.
- The framebuffer base is typically at D40000 (VRAM mapped region).

## Your task
1. Create a probe file `TI-84_Plus_CE/probe-phase553-decode-0A1A9D.mjs` that:
   - Reads ROM.rom bytes starting at offset 0x0A1A9D and disassembles 128+ bytes
   - Also reads and disassembles from 0x0A1B1C for 128+ bytes
   - For each function: identify parameters (input registers), return value (output registers), and what RAM addresses they read/write
   - Look for multiplication patterns (MLT, repeated ADD, shift) that would convert x,y to a linear offset
   - Identify any constants that reveal framebuffer geometry (320, 640, 0x140, 0x280)

2. Use the standard probe format (reference `TI-84_Plus_CE/probe-phase552-decode-04C979.mjs`).

3. Report findings in stdout as structured analysis.

## eZ80 reference
- MLT rr = ED 4C (BC), ED 5C (DE), ED 6C (HL) — 8×8 multiply within register pair
- ADD HL,rr = 09 (BC), 19 (DE), 29 (HL), 39 (SP)
- SLA r = CB 20+r (shift left arithmetic)
- SRL r = CB 38+r (shift right logical)
- LD HL,(nn) = ED 27 nn nn nn (eZ80 24-bit indirect)
- LD (nn),HL = ED 37 nn nn nn
