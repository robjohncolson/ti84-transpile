# Auto-Session 455 P3: Trace 0x048AC4 Callers in Key Processor Path

## Context
The TI-84 Plus CE ROM transpilation project lifts eZ80 machine code into runnable JS. Session 454 identified 0x048AC4 as the APP-LEVEL DISPLAY REFRESH function (894 bytes, 4 callers). One caller is 0x03FAED in the key processor at 0x03FA09.

The key processor (0x03FA09-0x03FC1B, 531 bytes) processes keys from D00587 → D141B5. At 0x03FAED it calls 0x048AC4. Session 454 found 0x048AC4 has 44 outgoing CALLs including 13× to 0x05202F (peripheral config) and 7× to 0x0000B0 (system primitive).

The question: What CONDITION at 0x03FAED triggers the call to 0x048AC4? Is it gated by D177B7? What does 0x048AC4 actually do — is it truly display refresh or something else?

## Task
Create a probe file `TI-84_Plus_CE/probe-phase455-048ac4-trace.mjs` that:

1. Reads the ROM binary directly (`TI-84_Plus_CE/ROM.rom`) to disassemble the key processor around the call site
2. Starting at ROM offset 0x03FAE0 (16 bytes before the call at 0x03FAED), read ~40 bytes of raw hex and print them
3. Identify the instruction sequence leading to the CALL at 0x03FAED:
   - What conditional test precedes it? (CP, BIT, JR, JP?)
   - Is D177B7 loaded before the call?
   - What register holds the target?
4. Read the FIRST 64 bytes of function 0x048AC4 from ROM and print raw hex
5. Identify:
   - What does 0x048AC4 do in its first ~20 instructions?
   - Does it read D177B7? If so, what value does it check?
   - Does it access VRAM (0xD40000-0xD65400)?
   - Does it do port I/O?
6. List all 4 callers of 0x048AC4 with their addresses and the surrounding context (read 16 bytes before each CALL instruction from ROM)

## How to find callers
Search the ROM for the byte sequence that encodes `CALL 0x048AC4` in eZ80 ADL mode:
- eZ80 CALL nn = 0xCD followed by 3-byte little-endian address
- 0x048AC4 in little-endian = C4 8A 04
- So search for bytes: CD C4 8A 04

Read the ROM file, scan for this 4-byte pattern, and report all match offsets.
