# Auto-session 609 P1 — TEST D000A3 BIT 3 FIX FOR MULTI-KEY INTERACTIVE USE

## Context

This is the TI-84 Plus CE ROM transpilation project. The OS ROM is lifted to JavaScript and executed via `cpu-runtime.js`. We have a working single-key round-trip (key '2' renders to VRAM). The blocker for MULTI-key interactive use is that keys 2-3 run away in an infinite walker loop at 0x090917.

**Root cause (session 608)**: The walker loop at 0x090917 calls `BIT 3,(IY+35); RET` at 0x08F3DC. This tests D000A3 bit 3. When SET, the walker continues; when CLEAR, it exits (RET Z). The post-paint snapshot has D000A3 bit 3 SET, so the walker never exits for subsequent keys.

**The fix**: Restore the post-paint snapshot, zero edit pointers, AND clear D000A3 bit 3 (`mem[0xD000A3] &= ~0x08`).

## Task

Create `TI-84_Plus_CE/probe-phase609-d000a3-fix.mjs` that:

1. Boots the OS exactly like `probe-phase608-selective-zero.mjs` (read that file for reference — it's in `TI-84_Plus_CE/`):
   - Fresh state: sp=0xD1A87E-24, push 0x0019b5 as return, write24(D008E0, sp), adl mode
   - Run 0x09DD62 (full OS init) with maxSteps=300000, maxLoopIterations=30000, timerInterrupt:false
   - Enable timer: `peripherals.setTimerEnabled(true)`
   - Drive home repaint: push 0x0019b5, runFrom(0x058241) with maxSteps=350000
   - Capture post-paint snapshot (D007CA 21B, D0008D, D0231A, D0243A, D02434 32B, D0009F, IY 128B at D00080-D000FF)

2. Process KEY 1 ('2', scan code 0x90):
   - Seed key: setMatrixKey(3,1), D00587=0x1A, D0058E=0x90, D0058C=0x90, D00080|=0x08, D0009F|=0x20
   - Run outer loop: push 0x0019b5, runFrom(0x08C331) with maxSteps=350000
   - Log: steps, cxMain hit (watch 0x0585E9), wipe count (watch 0x0018F8), VRAM non-white px, final D007CA

3. Process KEY 2 ('3', scan code 0x91) — THE CRITICAL TEST:
   - Restore post-paint snapshot (D007CA 21B from ROM 0x0585D3, D0008D, D0231A, D0243A, D02434, D0009F, IY flags)
   - **SELECTIVELY ZERO** edit pointers: D0243A=0, D0243D=0, D02317-D0231F=0, D02440-D02448=0
   - **CLEAR D000A3 BIT 3**: `cpu.mem[0xD000A3] &= ~0x08` ← THIS IS THE NEW FIX
   - Re-arm longjmp: push 0x0019b5, write24(D008E0, sp)
   - Seed key: setMatrixKey(3,1), D00587=0x1B, D0058E=0x91, D0058C=0x91, D00080|=0x08, D0009F|=0x20
   - Run outer loop: push 0x0019b5, runFrom(0x08C331) with maxSteps=350000
   - Log: steps, cxMain hit, wipe count, VRAM, D007CA, D000A3 value

4. Process KEY 3 ('+', scan code 0x70):
   - Same restore as key 2
   - Same selective zeroing + D000A3 bit 3 clear
   - Seed: D00587 appropriate for '+', D0058E=0x70, D0058C=0x70
   - Run and log same metrics

5. **SUCCESS CRITERIA**: ALL THREE keys must:
   - Dispatch through cxMain (0x0585E9 hit)
   - Complete in under 350K steps (no runaway)
   - Halt at 0x0019B5
   - Log clear results
