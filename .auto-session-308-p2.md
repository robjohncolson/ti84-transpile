# Task: Map the 2ND-modified token table (gap entries 0x39-0x6F)

## Context
Session 307 discovered that the scan-code-to-token table at ROM address 0x09F79B is 112 bytes. Entries 0x00-0x38 map primary scan codes to tokens. Entries 0x39-0x6F contain 2ND-modified key tokens (the table extends beyond the 57 primary keys for shifted mappings).

The probe `TI-84_Plus_CE/probe-phase307-scancode-token-table.mjs` already dumps all 112 entries. Your job is to:

## What to do

1. Read `TI-84_Plus_CE/probe-phase307-scancode-token-table.mjs` to understand the table dump format and see the raw data.
2. Read the ROM binary at 0x09F79B for 112 bytes using the probe infrastructure (or create a new probe).
3. For entries 0x39 through 0x6F (indices 57-111), cross-reference each non-zero token value against the TI CE SDK `sk2nd*` scan code definitions. The SDK defines 2nd-function scan codes like:
   - sk2ndDown, sk2ndLeft, sk2ndRight, sk2ndUp (2nd + arrow keys)
   - sk2ndEnter (2nd + ENTER → ENTRY recall)
   - sk2ndClear (2nd + CLEAR → ???)
   - sk2ndMath (2nd + MATH → TEST menu)
   - sk2ndApps (2nd + APPS → ANGLE menu)
   - etc.
4. The SDK sk2nd prefix scan codes start at 0x39 in the scan code numbering. So:
   - Index 0x39 in the table = 2nd+something → identify which key
   - The offset from primary key can be computed: sk2nd base starts at scan code 0x39, so 0x39 = 2nd+DOWN(?), 0x3A = 2nd+LEFT(?), etc.
   
5. Create a probe file `TI-84_Plus_CE/probe-phase308-2nd-token-table.mjs` that:
   - Reads all 112 bytes from ROM at 0x09F79B
   - For entries 0x39-0x6F, prints the index, the token value, and an SDK name assignment
   - Cross-references against the TI CE SDK `keypadc.h` sk2nd definitions
