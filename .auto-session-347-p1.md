# Auto-Session 347 — P1: Diagnose 0x0019B5 HALT + Post-HALT Continuation

## Context

The TI-84 Plus CE ROM boot sequence now passes the former diversion point at 0x0008BB (ALU fix from session 345 working). However, boot terminates at 0x0019B5 in z80 mode with a HALT instruction after writing port 0x0000=0x10.

Boot path (from session 346 probe): 0x000000->0x000003->0x000658->...->0x00069A->0x0006A9->0x000038->0x000080->0x001768->0x000800->0x000804->0x000066->0x000047->0x0008BB->0x00004C->0x0019B5(HALT)

Port 0x0000 on the eZ80 is the CPU speed/control register. Writing 0x10 likely sets a PLL/clock configuration bit, then HALT waits for an interrupt to fire once the hardware stabilizes.

## Task

1. **Disassemble 0x0019B5 and surrounding code (0x001980-0x001A20)**. Read the ROM bytes directly from `TI-84_Plus_CE/ROM.rom` at those offsets. The code is z80-mode (3-byte addresses, but opcodes are standard z80). Show the full disassembly with annotations.

2. **Determine what happens AFTER the HALT**. On real hardware, HALT waits for any enabled interrupt (EI must have been called before HALT). After the interrupt handler returns, execution resumes at PC+1 (the byte after HALT). Identify:
   - Was EI called before this HALT? (Check bytes before 0x0019B5)
   - What is at PC+1 (0x0019B6)? Disassemble the continuation.
   - What interrupt would fire? (IM mode, interrupt vector)

3. **Write a probe** at `TI-84_Plus_CE/probe-phase347-halt-continuation.mjs` that:
   - Boots from 0x000000 in z80 mode with timer interrupt ENABLED (timerInterrupt: true)
   - Traces execution past the HALT at 0x0019B5
   - Records what happens after the interrupt fires and execution resumes
   - Reports the full boot path for 100+ steps past the HALT
   - Uses the same probe boilerplate as `TI-84_Plus_CE/probe-phase346-boot-alu-fix-trace.mjs`

4. **If the probe shows boot continuing past the HALT**, document the continuation path. If it gets stuck in a timer ISR loop (the known 0x1713->0x67F8->0x1c33 loop), note that and suggest what peripheral response would let boot continue naturally.
