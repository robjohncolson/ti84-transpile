# Task: Find the REAL scan-code-to-class translation function

## Context
We are reverse-engineering the TI-84 Plus CE OS ROM. Session 304 proved that 0x069A8D is NOT the scan-code-to-class dispatch — it's a 6-instruction side-effect orchestrator with 17 callers (CALL 0x08CA64, conditional CALL 0x0562DE, CALL 0x09747C). Zero CP cascades, zero table lookups, zero writes to A.

The real scan-code-to-class function must be either:
1. UPSTREAM of the 17 callers of 0x069A8D
2. Inside one of the deeper sub-calls: 0x0917BE (called from 0x08CA64), 0x07FF8D, 0x0846EA, 0x08267D (called from 0x09747C)

## What to do

Create a probe file `TI-84_Plus_CE/probe-phase305-scan-class-hunt.mjs` that:

1. **Disassemble each candidate** (0x0917BE, 0x07FF8D, 0x0846EA, 0x08267D) by running them in a cold-boot CPU context and tracing what they do. For each:
   - Boot the CPU via the standard pattern (see existing probes for reference)
   - Execute from the candidate address for 200-500 steps
   - Log: instruction count, unique blocks visited, what RAM addresses are written, whether A is modified, whether there are CP cascades or table lookups
   
2. **Check upstream**: Find the 17 callers of 0x069A8D by grepping `ROM.transpiled.js` for `rom_069A8D` call references. For the most common caller patterns, trace what happens BEFORE the call — does A get loaded from a table or CP cascade before 0x069A8D is called?

3. **Report**: For each candidate, classify as:
   - "HAS CP CASCADE" (contains CP instructions comparing A against multiple values)
   - "HAS TABLE LOOKUP" (indexes into a ROM table to get a class value)
   - "IDENTITY/PASSTHROUGH" (A unchanged)
   - "SIDE EFFECTS ONLY" (modifies flags/RAM but not A)
