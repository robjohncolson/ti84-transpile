# Task: Decode 0x0820CD — alternate symbol table path for type-0x5D symbols

## Context
You are working on a TI-84 Plus CE ROM reverse-engineering project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary, little-endian, ADL mode = 24-bit addresses).

Session 585 decoded 0x08011F (7B type-check guard): it loads A from D005F9, compares with 0x5D, returns with Z flag. When type==0x5D, the caller 0x0846EA (symbol table searcher) jumps to 0x083833, which does:
- LD A,0x01
- PUSH AF
- CALL 0x0820CD   ← THIS IS YOUR TARGET
- INC A
- JR to 0x083856 which does LD DE,(D0259A)

This is the alternate symbol table path that bypasses normal backward search for type-0x5D symbols (likely "program" type). We need to know what 0x0820CD does.

## Deliverable
Create `TI-84_Plus_CE/probe-phase586-decode-0820CD.mjs` — a static disassembly probe that:
1. Reads `TI-84_Plus_CE/ROM.rom` directly with `readFileSync`
2. Disassembles starting at 0x0820CD until RET or unconditional JP (max ~200 bytes)
3. Tracks all CALL targets, JP/JR targets, RAM references (0xD0xxxx), IY+offset refs, and port I/O
4. Prints a formatted analysis

## Decoder API
The probe must use a HAND-ROLLED eZ80 decoder reading raw bytes from the ROM buffer. Do NOT import from `ez80-decoder.js` — it does not export `decodeAt` or similar. Look at existing probes for the pattern:

```js
import { readFileSync } from 'fs';
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
function b(addr) { return rom[addr] ?? 0; }
function u16(addr) { return b(addr) | (b(addr + 1) << 8); }
function u24(addr) { return b(addr) | (b(addr + 1) << 8) | (b(addr + 2) << 16); }
```

Then decode eZ80 instructions manually by reading opcodes. See `TI-84_Plus_CE/probe-phase585-decode-08011F.mjs` for a complete working example of this pattern.

## Key RAM addresses to annotate
- D005F8: descriptor buffer (9-byte)
- D005F9: search key type byte
- D02590: symbol table start
- D0259A: symbol table alt pointer
- D0259D: symbol table current pointer
- D02AD7-D02AD9: last-match buffer
- D3FFFF: symbol table end

## Constraints
- Do NOT modify any existing files

- The probe is STATIC analysis only — it reads ROM bytes, it does NOT execute the CPU
- Run the probe via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase586-decode-0820CD.mjs`

## Success criterion
The probe runs (exit 0) and prints: function boundaries, instruction-by-instruction disassembly, all CALL/JP/JR targets, RAM references, and a summary of what the function does.
