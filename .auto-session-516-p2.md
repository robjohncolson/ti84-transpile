# Task: Decode 0x061D1A (Main CLEAR Action / Unhandled Key Path)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM (4MB eZ80 machine code) is lifted to JavaScript. We've fully mapped the OS event loop command dispatcher at 0x099921 (38 entries, session 514). Multiple handlers route to 0x061D1A:
- CLEAR key handler (0x099F49) jumps to 0x061D1A for full clear
- Both range dispatchers (0x099BB0 and 0x09AF4E) route mismatches to 0x061D1A
- The default fallthrough from 0x099921 is JP 0x061D1A

So 0x061D1A is BOTH the screen-clear/reset function AND the unhandled-key-code catch-all. Understanding it reveals the full screen-clear flow.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase516-decode-061D1A.mjs` that:

1. Boots the transpiled ROM (copy the import/boot pattern from an existing probe like `TI-84_Plus_CE/probe-phase515-rendering-chain.mjs` — do NOT use `import { createDecoder } from './ez80-decoder.js'`, that export doesn't exist)
2. Disassembles 0x061D1A using raw ROM bytes (read ROM.rom via readFileSync, decode eZ80 instructions manually or use the inline disassembler pattern from other probes)
3. Traces the function by:
   - Reading ROM bytes starting at 0x061D1A
   - Decoding eZ80 instructions (the ROM is eZ80 ADL mode — 24-bit addresses)
   - Following the control flow: identify CALLs, JPs, conditional branches, RETs
   - Document each instruction with address, opcode, operands
4. Map at least 200 bytes of the function or until you hit a clear RET/JP-exit pattern
5. Identify:
   - What subroutines it calls
   - What RAM addresses it reads/writes
   - Whether it clears VRAM or edit buffers
   - How it handles the "unhandled key" case vs the "CLEAR key" case (or if they're the same path)

## eZ80 decoding reference
- eZ80 ADL mode: 24-bit addresses, 24-bit register pairs
- Common opcodes: CD=CALL nn, C3=JP nn, C9=RET, CB prefix=bit ops, FD CB=IY bit ops, DD=IX prefix, FD=IY prefix
- LD A,(addr) = 3A lo mid hi
- CALL addr = CD lo mid hi (3-byte address in little-endian)
- JP addr = C3 lo mid hi
- CP n = FE n
- JR cc,offset = 20/28/30/38 + signed offset
- The ROM file maps directly: ROM address 0x061D1A = file offset 0x061D1A

A clear disassembly of 0x061D1A showing its structure, subroutine calls, RAM accesses, and purpose. At minimum 150 bytes decoded.
