# Auto-Session 362 — P1: Investigate 0x4C7B21 Boot Terminator + Extended Flash Trampoline

## Context

This is a TI-84 Plus CE ROM transpilation project. We lift eZ80 machine code from a 4MB ROM (0x000000–0x3FFFFF) into JavaScript blocks. Boot currently reaches 476 unique blocks then terminates at `missing_block` for address **0x4C7B21:adl**.

0x4C7B21 is OUTSIDE the 4MB ROM (0x4C7B21 > 0x400000). The ROM is only 4MB. This address is in "extended flash" or OS application space.

The last blocks before termination (from session 361 probe) are:
```
0x00BC31 → 0x00BC47 → 0x00BC31 → 0x00BC3C → 0x00BC6C → 0x00BC72 → 0x006500 → 0x006CC6 → 0x006D5D → 0x0021C2 → missing_block at 0x4C7B21
```

The project already has a **RAM trampoline** in `TI-84_Plus_CE/cpu-runtime.js` that intercepts execution at RAM addresses (0xD00000+) and redirects to ROM-source blocks. A similar mechanism may be needed for extended flash addresses.

## Task

Write a probe script `TI-84_Plus_CE/probe-phase362-investigate-4C7B21.mjs` that:

1. **Boots the OS** with the standard configuration:
   - Timer interrupts disabled: `createPeripheralBus({ timerInterrupt: false })`
   - GPIO = 0xEF (the standard boot path)
   - Use the RAM trampoline (already in cpu-runtime.js)
   - Run for enough steps to reach termination (try 5000 steps)

2. **Traces the last 20 blocks** before the missing_block termination at 0x4C7B21. Record the full block addresses and the instruction that causes the jump to 0x4C7B21.

3. **Disassembles blocks 0x0021C2 and 0x006D5D** (the last two blocks before termination) using raw ROM bytes from `TI-84_Plus_CE/ROM.rom`. Show the full disassembly of each block (all instructions until the next RET/JP/JR or 64 bytes, whichever comes first). The eZ80 is in ADL mode. Use the project's `TI-84_Plus_CE/ez80-decoder.js` decoder:
   ```js
   import { decodeInstruction } from './ez80-decoder.js';
   // decodeInstruction(romBuffer, offset, adlMode) returns {mnemonic, operands, length}
   ```

4. **Checks if 0x4C7B21 is a computed jump target** — specifically:
   - Does block 0x0021C2 contain a JP (HL), JP (IX), JP (IY), CALL (HL), or similar indirect jump?
   - What register values would produce 0x4C7B21? (e.g., if JP (HL), what was HL?)
   - Is there a flash bank register (port 0x06, 0x07, or memory-mapped at 0xE00000+) that maps a logical address to physical flash?

5. **Checks the memory at 0x4C7B21** — read mem[0x4C7B21] through mem[0x4C7B40] and report the byte values. Are they all 0x00/0xFF (unmapped) or do they contain valid code?

6. **Proposes a fix**: If 0x4C7B21 is outside ROM and the memory is empty, this is likely a flash bank mapping issue. The eZ80 on the TI-84 CE uses memory-mapped flash with bank registers. The real question: what ROM address does 0x4C7B21 map to? Check if there's a pattern like `physical = (bank_register << 16) | (addr & 0xFFFF)` or `physical = addr - offset`.
