# Task: Implement repeated NMI wake boot probe

## Context
TI-84 Plus CE ROM transpilation project. Boot sequence runs in ADL mode, reaching 273 blocks before DI+HALT at 0x0019B5. A single NMI wake (PC→0x000066) extends to 286 blocks then HALTs again. We need to know: if we keep waking from HALT with repeated NMIs, how far does boot get? Does it eventually stop halting and proceed to OS init?

## What to do

Create `TI-84_Plus_CE/probe-phase356-repeated-nmi-wake.mjs` that:

1. **Boots from 0x000000** in z80 mode, `timerInterrupt: false`, `pllDelay: 2`
2. **Runs blocks** via `executor.runFrom(cpu.pc, mode)` in a loop, up to MAX_STEPS = 100000
3. **On every HALT** (result === -1):
   - Record: halt number, step count, PC, unique blocks so far, registers (A, BC, DE, HL, SP)
   - Automatically trigger NMI: set `cpu.pc = 0x000066` (NMI vector)
   - Increment halt counter
4. **On missing_block**: Record the address and continue (don't crash)
5. **Track metrics**:
   - Total HALTs encountered
   - Unique blocks after each HALT wake
   - New blocks discovered per HALT cycle (blocks seen for the first time in that cycle)
   - Max unique blocks reached
6. **Print summary**:
   - Table: HALT#, step, blocks_total, blocks_new_this_cycle, PC_at_halt
   - Whether boot ever escapes the HALT loop (i.e., runs >500 steps without halting)
   - Any missing_block addresses encountered
   - Final register state

## Key constraints
- Do NOT use `cpu.step()` — it doesn't exist. Use `executor.runFrom()`.
- Do NOT use `wakeFromHalt` option on peripherals — handle HALT manually.
- Do NOT enable timer interrupts (they hijack init via 0x1713).
- Set initial `cpu.adl = false` (z80 mode) — the ROM switches to ADL itself.
- Cap at 100K steps OR 50 HALTs, whichever comes first.
