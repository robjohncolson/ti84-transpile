# Task: Trace 0x08237A parent function — VAT table population trigger

## Context
In the TI-84 Plus CE ROM transpilation project, we discovered that 0x0820ED (an entry writer for the VAT/dispatch table at D3Fxxx) has exactly ONE caller in the entire 4MB ROM: address 0x08237A.

The call site setup at 0x08236B is:
- LDDR copies 3 bytes from stack into D005FB
- XOR A clears A
- Stores 0x00 into D005F9 and D005FA
- Then CALL 0x0820ED

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase278-08237a-parent.mjs` that:

1. **Static disassembly**: Scan backwards from 0x08237A to find the function entry point. Look for common entry patterns: PUSH IX / LD IX,0 / ADD IX,SP, or just the first address that no other instruction jumps INTO from outside (i.e., find the function boundary). Scan ROM bytes from ~0x082300 backwards to ~0x0822xx looking for a RET/JP/JR that would end the previous function. The byte AFTER that RET is likely the entry point of the function containing 0x08237A.

2. **Caller scan**: Once you find the entry point of the function containing 0x08237A, scan the entire ROM (0x000000-0x3FFFFF) for CALL/JP instructions targeting that entry point. Report how many callers exist and their addresses. Use the eZ80 ADL CALL opcode patterns:
   - `CD xx xx xx` = CALL addr24 (4 bytes)  
   - `C3 xx xx xx` = JP addr24 (4 bytes)
   - `C4/CC/D4/DC/E4/EC/F4/FC xx xx xx` = conditional CALL (4 bytes)

3. **Dynamic trace**: Boot the emulator (cold boot with timer IRQ disabled), run to a stable state, then set PC to the entry point found in step 1. Trace 200 steps, logging each block visited, any writes to D3Fxxx range, and any CALLs to known functions (0x0820ED, 0x08267D, 0x0846EA, 0x082BE2).

For static disassembly, read ROM bytes directly from the ROM buffer. For CALL scanning, search for the 4-byte pattern `CD <low> <mid> <high>` where the 24-bit address is in little-endian.
