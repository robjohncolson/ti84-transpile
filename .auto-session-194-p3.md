# Session 194 P3 — Trace ConvKeyToTok Register E → OP1 Path

## Task
Build a probe `TI-84_Plus_CE/probe-phase194-convkey-e-to-op1.mjs` that traces how the token in register E (output of ConvKeyToTok at 0x05C52C) gets transferred into OP1 (0xD005F8) before the Copy9 call that writes it to TOKEN_STAGING (0xD0230E).

## Context
Session 187 findings established:
- TOKEN_STAGING (0xD0230E) is populated via Copy9 path: OP1 → TOKEN_STAGING (not by direct store from ConvKeyToTok)
- ConvKeyToTok outputs token in register E
- At the two known call sites (0x05E630, 0x05E91A), token E is preserved via PUSH DE / POP DE around intermediate calls
- Two Copy9-based writes to TOKEN_STAGING: 0x06214C and 0x099AF1 via `LD DE,0xD0230E; CALL/JP 0x07FA0D` (0x07FA0D = LD HL,OP1; JR Copy9)
- 11 total ConvKeyToTok call sites in ROM

The gap: we know E comes out of ConvKeyToTok and eventually OP1 contains the token. We don't know the intermediate steps.

## What to build
Use `probe-phase193-yeq-extended.mjs` as a template for boilerplate.

### Experiment A: Trace from 0x05E630 context (call site 1)
Session 187 found ConvKeyToTok called at 0x05E630. The surrounding code has PUSH DE / POP DE to preserve E.
1. Boot + kernel init + mem init
2. resetCpuForOsCall
3. Set up a plausible key context: write scan code 0x92 (digit '2', maps to token 0x32) into the key buffer. Set register A=0x92 (the key code).
4. Push return sentinel 0x7FFFFE
5. Enter at 0x05E620 (a few instructions before the ConvKeyToTok call at 0x05E630) in ADL mode
6. Use onBlock callback to snapshot OP1 (0xD005F8, 9 bytes) and register E at key blocks
7. Max 3000 steps. Log every unique block visited.
8. Check: at what block does OP1 first change to contain the token byte?

### Experiment B: Trace from 0x05E91A context (call site 2)
Same as A but enter at 0x05E910 (before ConvKeyToTok call at 0x05E91A).

### Experiment C: Trace the 0x099AF1 Copy9 path backward
0x099AF1 does `LD DE,0xD0230E; JP 0x07FA0D`. What sets up OP1 before reaching 0x099AF1?
1. Disassemble ROM bytes at 0x099AE0-0x099B00 (16-32 bytes before 0x099AF1) to find what CALL or operation puts data into OP1
2. Enter at 0x099AE0 with OP1 pre-cleared, A=0x92, max 1000 steps
3. Check: does OP1 get populated? What block writes to it?

### Experiment D: Trace the 0x06214C Copy9 path backward
0x06214C does `LD DE,0xD0230E; CALL 0x07FA0D`. Same approach as C:
1. Disassemble 0x062130-0x062160 
2. Enter at 0x062130 with OP1 cleared, max 1000 steps
3. Check OP1 contents
