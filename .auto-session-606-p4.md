# Task: Investigate why first key takes 276K steps but subsequent keys take ~196K

## Context
In the TI-84 Plus CE ROM transpilation project, session 605 confirmed multi-key dispatch with state restoration. Step counts: key1 ('2')=276,820 steps, key2 ('3')=196,488 steps, key3 ('+')=196,813 steps. The first key runs ~80K MORE steps than subsequent keys. Understanding this difference will reveal whether the first key follows a different code path (init+render vs update-only).

## Task
Create a probe at `TI-84_Plus_CE/probe-phase606-step-analysis.mjs` that:

1. **Boots the OS** using the established recipe:
   ```javascript
   import { createCPU } from './cpu-runtime.js';
   import { createPeripheralBus } from './peripherals.js';
   const peripherals = createPeripheralBus({ timerInterrupt: false });
   const cpu = createCPU(peripherals);
   cpu.sp = 0xD1A87E - 24;
   cpu.write24(cpu.sp, 0x0019b5);
   cpu.write24(0xD008E0, cpu.sp);
   cpu.adl = 1;
   ```

2. **Runs init** `cpu.runFrom(0x09DD62, { maxSteps: 300000, maxLoopIterations: 30000 })`

3. **Runs paint** with timer on, pushed return 0x0019b5.

4. **Snapshots full state** after paint (D007CA 21B, D0008D, D0231A, D0243A, D02434 32B, D0009F, D00080-D000FF 128B, D008E0 SP anchor).

5. **Processes key1 ('2'=0x90) through outer loop 0x08C331** with block-level instrumentation:
   - Track unique blocks visited
   - At 196K steps (where key2/3 would halt), record the current PC and what blocks are being executed
   - Track VRAM non-white pixel count at 196K and at completion
   - Track when specific milestones hit: cxMain (0x0585E9), wipe #1 (0x0018F8), wipe #2 (0x0018F8 second time), halt (0x0019B5)

6. **Restores state, processes key2 ('3'=0x91) through outer loop** with same instrumentation.

7. **Compares the two runs**:
   - Which blocks appear in key1 but NOT in key2?
   - Which blocks appear in key2 but NOT in key1?
   - At what step does key1 diverge from key2's pattern?
   - Does the first wipe happen at the same step in both runs?
   - Does key1 have MORE wipe events than key2?

8. **Reports**:
   - Milestone timing for both keys (cxMain entry step, wipe #1 step, wipe #2 step, halt step)
   - Unique block counts for both
   - The set of blocks unique to key1 (the "extra 80K steps" path)
   - VRAM at 196K steps for key1 vs VRAM at halt for key2

## State Restoration Between Keys
After key1 completes, restore the snapshot from step 4:
```javascript
// Restore D007CA 21-byte descriptor
for (let i = 0; i < 21; i++) cpu.write8(0xD007CA + i, snapshot.d007ca[i]);
cpu.write8(0xD0008D, snapshot.d0008d);
cpu.write24(0xD0231A, snapshot.d0231a);
cpu.write24(0xD0243A, snapshot.d0243a);
// ... restore all snapshot fields
// Re-arm longjmp
cpu.sp = 0xD1A87E - 24;
cpu.write24(cpu.sp, 0x0019b5);
cpu.write24(0xD008E0, cpu.sp);
```
