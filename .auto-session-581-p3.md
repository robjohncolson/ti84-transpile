# Task: DECODE 0x07BF19 — QUIT Handler

## Context
This is part of TI-84 Plus CE ROM transpilation. The OS event loop key dispatch cascade at 0x08C3C3 handles key code 0xB4 (QUIT) with a conditional call: `CP 0xB4; CALL Z 0x07BF19`. This function has NOT been decoded yet.

The event loop flow: 0x08C331 (loop top) → cleanup 0x08C33D → display refresh → key input 0x0A27DD → key dispatch 0x08C3C3 → first check: `CP 0xB4; CALL Z 0x07BF19` (QUIT handler).

## Your Task
Write a probe at `TI-84_Plus_CE/probe-phase581-decode-07BF19.mjs` that statically disassembles the function at 0x07BF19 and write a report to `TI-84_Plus_CE/phase581-decode-07BF19-report.md`.

### What to do
1. Read ROM bytes: `import fs from 'fs'; const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');` then `rom[addr]`.
2. Decode eZ80 instructions from raw bytes. eZ80 = Z80 superset, ADL mode (24-bit addresses):
   - `0xCD nn nn nn` = CALL addr (3-byte LE)
   - `0xC3 nn nn nn` = JP addr
   - `0xC9` = RET
   - `0x18 dd` = JR dd; `0x20 dd` = JR NZ; `0x28 dd` = JR Z
   - `0xCB` = bit ops; `0xFD` = IY; `0xDD` = IX; `0xED` = extended
   - `0x3E` = LD A,n; `0x21 nn nn nn` = LD HL,addr
3. Decode at least 100 bytes from 0x07BF19 (or until terminal RET/JP).
4. Look for:
   - What QUIT does: does it reset state? Change D007E0 (mode variable)? Call the init trampoline 0x063033?
   - RAM references (0xD00000-0xD3FFFF)
   - IY+offset operations
   - CALL targets
   - Screen-mode bit testers (0x06C72D/0x06C732/0x06C737/0x06C73C)
   - Exit paths back to event loop
5. Count callers: grep ROM for `CD 19 BF 07` (CALL 0x07BF19) and `C3 19 BF 07` (JP 0x07BF19).

### Report format
`phase581-decode-07BF19-report.md`:
- Function address, size, instruction count
- Full annotated disassembly
- RAM refs, IY flags, CALL targets, callers
- What does QUIT do? Does it return to the event loop or does it jump elsewhere?
