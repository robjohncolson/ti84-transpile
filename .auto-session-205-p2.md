# Auto-Session 205 — P2: Determine what sets BIT 7,(IY+12) — Level 1 vs Level 2 gate

## Context

In the TI-84 Plus CE ROM transpilation project, we found that `BIT 7,(IY+12)` at address 0x058297 gates which dispatch level handles keypresses:
- If BIT 7 is SET → JP to 0x058483 (Level 1: Copy9→KeyClassifier→0x09927F→crash)
- If BIT 7 is CLEAR → execution continues to Level 2 (cxMain at 0x0585E9, which routes digits without crashing)

IY base = 0xD00080, so IY+12 = 0xD0008C. BIT 7 of that byte is the gate.

We need to find what ROM code SETS bit 7 of (IY+12) and what CLEARS it, to understand when the OS uses Level 1 vs Level 2.

## Task

Build a probe `TI-84_Plus_CE/probe-phase205-bit7-iy12-setter.mjs` that:

1. **Static ROM scan**: Read `TI-84_Plus_CE/ROM.rom` directly (Buffer, fs.readFileSync) and search for:
   - `SET 7,(IY+0x0C)` — opcode bytes: `FD CB 0C FE` (FD prefix, CB prefix, displacement 0x0C, SET 7 opcode FE)
   - `RES 7,(IY+0x0C)` — opcode bytes: `FD CB 0C BE` (FD prefix, CB prefix, displacement 0x0C, RES 7 opcode BE)
   - `BIT 7,(IY+0x0C)` — opcode bytes: `FD CB 0C 7E` — to find all test sites
   - Also scan for direct writes to 0xD0008C: `LD (0xD0008C),A` patterns and `OR`/`AND` patterns that modify the byte

2. **Report all addresses** where SET 7 and RES 7 occur, with 5 instructions of context before/after each site (disassemble from ROM bytes using basic eZ80 decoding — at minimum show the raw hex + known mnemonics for common instructions)

3. **Cross-reference with known addresses**:
   - 0x058297 (the BIT 7 test we already know about)
   - 0x0584A3 (the seeded entry point)
   - 0x0585E9 (cxMain)
   - Does the SET happen during OS init? During mode switches? During specific key handlers?

4. **Count statistics**: How many SET vs RES sites? Is BIT 7 predominantly SET (Level 1 is default) or predominantly CLEAR (Level 2 is default)?
