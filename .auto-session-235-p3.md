# Task: Investigate key code 0x44 and BIT 4,(IY+0x4B) (nnn)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript and executed via `cpu-runtime.js`.

Session 234 decoded 0x0302EB as a gate that checks for key code 0x44:
- `LD A,(HL)` — loads key code from table
- `CP 0x44` — compare with 0x44
- non-0x44 → `CP A` (sets Z=1) → RET (normal processing)
- 0x44 + BIT 4,(IY+0x4B) SET → `LD A,0x1D` → RET NZ (special handling via JP NZ,0x02FFED)
- 0x44 + BIT 4 CLEAR → RET Z (treated as normal)

We need to know: (1) What key does 0x44 represent? (2) What does BIT 4,(IY+0x4B) control? (3) What is 0x1D (the replacement code)?

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase235-key44-investigation.mjs` that:

1. Imports from `./cpu-runtime.js` and loads ROM from `./ROM.rom`
2. Standard setup: `{ timerInterrupt: false }`, `cpu.mbase = 0xD0`, IY = 0xD00080

### Part A: Identify key code 0x44 in the 09F79B table
The 09F79B key code table was fully mapped in session 230 (file `TI-84_Plus_CE/phase230-09f79b-full-table.json`). Read this JSON file and find which scan code(s) produce key code 0x44. The table has 4 sections of 56 entries each (no-mod, 2nd, alpha, alpha+2nd). Offset = scanCode + (alpha?0x70:0) + (2nd?0x38:0).

Also check: Does 0x44 appear in the primary ConvKeyToTok table at 0x05BF84 (166 entries)? Read ROM bytes at 0x05BF84 and scan for value 0x44.

### Part B: Map BIT 4,(IY+0x4B) — what sets/clears it?
IY+0x4B = 0xD000CB (IY base 0xD00080 + 0x4B = 0xD000CB).
- Scan ROM binary for all instructions that reference (IY+0x4B): SET 4, RES 4, BIT 4, LD (IY+0x4B), and LD A,(IY+0x4B).
- The eZ80 encoding for IY+0x4B operations: FD prefix + CB + 4B + opcode byte. SET 4 = E1, RES 4 = A1, BIT 4 = 61.
- Also check for direct memory writes to 0xD000CB: scan for `21 CB 00 D0` (LD HL,0xD000CB) or `3A CB 00 D0` (LD A,(0xD000CB)) patterns.
- Classify each site: SET (armer), RES (clearer), BIT (tester), LD (reader/writer).
- For SET sites, note the surrounding context (what function, what conditions).

### Part C: Identify key code 0x1D
0x1D (decimal 29) is the replacement value when 0x44 triggers the special path. Check:
- Is 0x1D a known TI-OS key code? Check the 09F79B table for any entry with value 0x1D.
- Is 0x1D a token? Check ConvKeyToTok primary table at 0x05BF84.
- Search ROM for `CP 0x1D` (FE 1D) to see how the OS handles this value elsewhere.

### Part D: Print results
For each part, print structured results showing:
- Part A: Which scan code(s) map to 0x44, under which modifier state
- Part B: All (IY+0x4B) BIT 4 reference sites with classification
- Part C: What 0x1D means in the OS context
