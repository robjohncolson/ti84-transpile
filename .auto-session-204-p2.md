# Auto-Session 204 P2: STAT LDDR Successor Wiring Investigation

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript blocks. We're tracing the STAT (1-Var Stats) execution path.

**Problem**: The LDDR instruction at block 0x092263 completes (BC decrements to 0) but execution never reaches the successor block 0x092265. Session 203 confirmed this with near-seed (BC=245) — both near and far experiments reach blocks 0x09224B and 0x092263 but neither progresses to 0x092265 in 10000 steps. The question is: where does PC go after LDDR completes?

**Background from sessions 195-203**:
- Block 0x092263 contains: LDDR (first instruction) → LD DE,0xD0150B → POP BC → LD HL,(0xD01508) → ADD HL,BC → ... → RET
- BC comes from the stack (POP BC), not from RAM
- Near-seed (list at 0xD01600): BC=0xF5 (245) — manageable iteration count
- Far-seed (list at 0xD10000): BC=0xEAF5 (60,149) — huge iteration count
- STAT structure at 0xD008E6 value = 0x0017 (23), formula: size = BC + 18 where BC = column count
- SBC at 0x09224B: near HL=0x070B, DE=0x0019; far HL=0xFF1D0B, DE=0x0019

## What to build
Create `TI-84_Plus_CE/probe-phase204-stat-lddr-exit.mjs`.

## Approach
1. **Inspect the TRANSPILED block 0x092263**: Read `ROM.transpiled.js` (generate it first with `node scripts/transpile-ti84-rom.mjs` if needed, or read the .gz). Find the JavaScript function for block `092263:adl`. Check:
   - What is the block's successor/exit target?
   - Does the LDDR implementation loop internally or delegate to a runtime helper?
   - Is the successor wired as direct fallthrough, conditional branch, or return?
   - Could the block be terminating via RET before reaching the LDDR successor?

2. **Trace execution with near-seed and small BC**: Set up L1={1.0,2.0,3.0} at 0xD01600 (near seed, session 203 pattern). But this time:
   - Use step-by-step logging at EACH step after entering block 0x092263
   - Log PC, SP, BC, FLAGS after every block transition
   - Specifically watch for: does 0x092263 call another block? Does it RET? Does it fall through to 0x092265?
   
3. **Check if LDDR is the block terminator**: In the transpiler, LDDR (EDBB) might terminate the block (it's a repeating instruction). If so, the block might only execute ONE iteration of LDDR per invocation, with the successor being either:
   - 0x092263 again (self-loop until BC=0), then 0x092265 when BC=0
   - OR 0x092265 always (wrong — LDDR should loop)
   
4. **Alternative**: Check `scripts/transpile-ti84-rom.mjs` for how LDDR is handled. Search for "LDDR" or opcode 0xED 0xB8. Does the transpiler emit a loop? Or does it emit a single decrement + conditional branch?
