# Task: Map Deferred Callback System (0x0A27DD)

## Context
Session 342 traced 0x0A27DD as a deferred callback ticker. Its flow:
- PUSH AF/BC/DE/HL
- BIT 6,(IY+27) — check if callbacks enabled
- If clear: clear 0xD005F6 (callback pointer), set 0xD005F5=1 (countdown)
- CALL 0x03D1C3 (countdown decrement + optional callback invoke via 0x0A32F9)
- EI, SET 0,(IY+18)
- JP 0x0A1A36 (POP HL/DE/BC/AF + RET)

The OS uses this as a deferred-event mechanism. We need to understand:
- Who WRITES to 0xD005F6 (the callback pointer)?
- What functions get registered as callbacks?
- When does 0x0A32F9 actually get called (the callback invocation)?

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase343-deferred-callbacks.mjs` that:

1. Reads the ROM file at `TI-84_Plus_CE/ROM.rom` (4MB binary)
2. Scans the entire ROM for any instruction that writes to address 0xD005F6:
   - LD (0xD005F6),A — opcode pattern: 0x32 followed by 0xF6 0x05 0xD0 (little-endian 24-bit address for eZ80 ADL mode)
   - LD (0xD005F6),HL — opcode: 0x22 followed by 0xF6 0x05 0xD0
   - Also check for indirect writes: LD HL,0xD005F6 / LD (HL),<reg> patterns
3. For each write site found, disassembles 20 bytes BEFORE the write (to see what value is being written — usually loaded into A or HL first) and 10 bytes AFTER
4. Also scans for references to 0x0A32F9 (the callback invocation function) — who calls it besides 0x03D1C3?
5. Scans for writes to 0xD005F5 (the countdown byte) to understand what countdown values are used

## Technical Details
- ROM is at `TI-84_Plus_CE/ROM.rom` (4MB raw binary, Uint8Array)
- For scanning, do byte-pattern search across the full 4MB
- eZ80 ADL mode uses 3-byte addresses in LE format
- LD (nn),A in eZ80 ADL = 0x32 + 3-byte LE address
- LD (nn),HL in eZ80 ADL = 0x22 + 3-byte LE address  
- For disassembly context, use `import { decodeInstruction } from './ez80-decoder.js'`
- The decoder: `decodeInstruction(buffer, offset)` returns `{mnemonic, operands, length}` or similar

## Constraints

- Only create the single probe file listed above
- The probe must be self-contained and runnable with just `node`

## Success Criterion
The probe identifies all ROM locations that write to 0xD005F6 (callback pointer) and 0xD005F5 (countdown), shows what values they write, and identifies all callers of 0x0A32F9. This maps the complete deferred callback registration and invocation system.
