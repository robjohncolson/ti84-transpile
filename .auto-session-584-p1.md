# Auto-Session 584 — P1: Decode the Event Consumer (trace 0x0236F9 caller buffer addresses)

## Context
0x0236F9 is a 30-byte leaf function ("EVENT POSTING CENTRAL DISPATCH") that writes a 3-byte event record to a buffer pointed by HL:
- byte[0] = A (event type)
- byte[1] = contents of RAM D007E0 (mode byte)
- byte[2] = contents of RAM D0058E (context byte) if mode==0x4E, else 0x00

It has 42 callers, all in the 0x022xxx-0x0236xx range (the key processor suite at 0x022331). The buffer address comes from HL at each call site.

## Task
Create a probe `TI-84_Plus_CE/probe-phase584-event-consumer.mjs` that:

1. **Scans all 42 CALL sites targeting 0x0236F9** in the ROM binary. For each call site, disassemble backwards ~20 bytes to find what value HL was loaded with (LD HL,nnnn). Collect the set of unique buffer addresses.

2. **For each unique buffer address**, scan the ROM for all READ references (LD A,(HL) / LD A,(nn) / LDIR / CP / etc.) that access those addresses — i.e., find who READS the event records that 0x0236F9 writes.

3. **Report**: For each buffer address: (a) which caller sites use it, (b) what event types (A values) are posted to it, (c) who reads it, (d) what they do with the data.

## Files
- ROM binary: `TI-84_Plus_CE/ROM.rom` (4MB, read with `fs.readFileSync`)
- Decoder: `import { decodeInstruction } from './ez80-decoder.js'`
  - API: `decodeInstruction(buffer, offset, mode)` where buffer is a Buffer/Uint8Array, offset is the byte position in the buffer, mode is `'adl'` (24-bit) or `'z80'` (16-bit). Returns object with `.length` (bytes), `.asm` (string like "LD HL,0x123456"), `.opcode` (string).
- Runtime: NOT needed (static analysis only).

## Decoder usage pattern
```js
import { decodeInstruction } from './ez80-decoder.js';
import fs from 'fs';
const rom = fs.readFileSync('TI-84_Plus_CE/ROM.rom');
// Decode at offset in ADL mode:
const insn = decodeInstruction(rom, 0x0236F9, 'adl');
// insn.asm = "LD (HL),A" or similar, insn.length = byte count, insn.opcode = mnemonic
```
