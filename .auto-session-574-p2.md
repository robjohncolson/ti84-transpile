# Task: DECODE 0x0BA57E — function after LCD window reset

## Context

Session 572 decoded 0x0BA561-0x0BA57D (29B LCD window reset). The function immediately after it at 0x0BA57E is known to write D02A76/D02A7C and call 0x0A89F2 (the LCD parameter wrapper that clears IY+0x51 bit 3 then calls 0x0A89FE).

D02A76 and D02A7C are in the pixel renderer workspace region (D02A62-D02A75 was mapped in session 571, so D02A76+ extends it).

## Deliverable

Create a probe at `TI-84_Plus_CE/probe-phase574-decode-0BA57E.mjs` that:

1. Boots the TI-84 CPU to idle (use the same boot pattern as the golden regression probe `probe-phase99d-home-verify.mjs` — copy its boot/factory setup exactly)
2. Reads and disassembles ROM bytes starting at 0x0BA57E until the next RET/JP/JR unconditional (or ~64 bytes, whichever comes first)
3. For disassembly, use the eZ80 decoder: `import { decodeInstruction } from './ez80-decoder.js'` — call `decodeInstruction(cpu, address)` which returns `{mnemonic, operands, length}`. Step through by incrementing address by `length`.
4. Print each instruction with address, hex bytes, mnemonic+operands
5. Identify:
   - All RAM addresses written (LD (nnnn),reg patterns) — especially D02A76, D02A7C
   - All CALL targets
   - Function boundaries (RET, JP unconditional)
6. Cross-reference D02A76 and D02A7C: scan the ROM for all references to these addresses (bytes `76 2A D0` and `7C 2A D0` in little-endian) and count them

## Boot pattern (copy from golden regression)

```javascript
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';

const rom = fs.readFileSync(path.join(__dirname, 'ROM.rom'));
const peripherals = createPeripheralBus({ timerInterrupt: false });
const cpu = createCPU(rom, peripherals);

// Boot to idle
let steps = 0;
while (steps < 500000) {
    cpu.step();
    steps++;
    if (cpu.halted) break;
}
```

Then use `decodeInstruction(cpu, 0x0BA57E)` to disassemble.
