# Auto-Session 285 P2: Find the Real Keyboard Matrix Reader (MMIO 0xE00810-0xE00817)

## Context
Session 284 proved that 0x027111 is NOT the keyboard scanner — it's USB/power polling with 0 I/O instructions touching port 0x01 (keyboard). The TI-84 Plus CE keyboard matrix is read through MMIO at addresses 0xE00810-0xE00817 (8 bytes, one per keyboard row). We need to find which ROM routine(s) actually read from this MMIO range.

The keyboard matrix hardware: writing a row-select value to 0xE00810-0xE00817 range and reading back gives the column bitmask of pressed keys. The SDK maps keyMatrix[N] = SDK Group(7-N). 

## Task
Create a probe file `TI-84_Plus_CE/probe-phase285-mmio-kbd-reader.mjs` that:

1. **Binary scan for MMIO loads** — scan the entire ROM (0x000000-0x3FFFFF) for instructions that load from the 0xE00810-0xE00817 range. Look for:
   - `LD A,(0xE008xx)` — opcode pattern: `3A xx 08 E0` (ADL mode) where xx is 0x10-0x17
   - `LD HL,(0xE008xx)` — opcode pattern: `2A xx 08 E0`
   - Any register load from that range
   - Also check for `IN A,(0x01)` — opcode `DB 01` — which is the legacy Z80 port-mapped keyboard I/O (port 0x01 is the keyboard scan port on older TI models; on CE it may still work)
   - Check for `LD HL,0xE00810` or `LD DE,0xE00810` — setting up a pointer to the MMIO base (pattern: `21 10 08 E0` for HL, `11 10 08 E0` for DE)

2. **For each hit**: decode the surrounding ~20 bytes to show context (what function is this in?). Use the eZ80 decoder.

3. **Also search for port 0x01 I/O** — `IN A,(C)` with prior `LD C,0x01` or `LD BC,0x0001`. Pattern for IN A,(C): `ED 78` (or `ED 40` etc). Search for `0E 01` near `ED` bytes.

4. **Cross-reference with known functions**: 
   - 0x027111 — confirmed NOT keyboard (USB/power)
   - 0x02FCB3 — blocking key wait (being traced in P1)
   - 0x04AB65 — _GetCSC
   - 0x02F68A — key processing pipeline
   - 0x003D55 — ISR keyboard writer

5. **Report**: Which routine(s) physically read the keyboard matrix? How many sites? Is it one central scanner called by the ISR, or distributed?

- The MMIO range 0xE00810-0xE00817 is in the peripheral address space, NOT in ROM. We're searching ROM code for instructions that REFERENCE those addresses.
- eZ80 ADL mode uses 3-byte addresses, so look for 4-byte sequences with the address in little-endian
- The ROM is 4MB (0x000000-0x3FFFFF), but actual code is mostly in 0x000000-0x0BFFFF
