# Task: Check code immediately before 0x0159C0 for fall-through entry

## Context
We're reverse-engineering the TI-84 Plus CE OS ROM (eZ80, 4MB at `TI-84_Plus_CE/ROM.rom`). Address 0x0159C0 is the foreground keyboard scanner — a 201-byte function that reads MMIO at 0xE00900 and produces scan codes. Session 287 proved that 0x0159C0 is NEVER stored as a literal anywhere in the ROM (no CALL/JP/LD instructions reference it directly). This means it's invoked via one of:
- (a) Runtime-computed address (base+offset)
- (b) RAM-based vector table populated during OS init
- (c) Fall-through from the preceding function (the function at 0x0159BF or earlier simply falls into 0x0159C0)

This task investigates option (c).

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase288-0159c0-fallthrough.mjs`

## What to do
1. Use the `ez80-decoder.js` decoder to statically disassemble backwards from 0x0159C0. Start at ~0x015980 (64 bytes before) and decode forward until you reach 0x0159C0. Identify the last instruction before 0x0159C0.
2. Determine if that instruction is a block terminator (RET, RETI, RETN, JP, RST) or if it could fall through into 0x0159C0.
3. If it's NOT a terminator (i.e., fall-through is possible), decode further backwards to find the entry point of the preceding function. Look for patterns like: a RET/JP that ends the function before it, then the start of a new function that leads to 0x0159C0.
4. If it IS a terminator, check if the code before it has any CALL/JP references to nearby addresses — maybe 0x0159C0 is actually the continuation of a larger function (the function entry is earlier).
5. Also check: is there a vector table or pointer array in the ROM that contains addresses near 0x0159C0? Scan 0x015900-0x015A00 for 3-byte aligned address patterns.

## Technical details
- Import the decoder: `import { decodeInstruction } from './ez80-decoder.js';`
- ROM file: `ROM.rom` in the same directory
- eZ80 ADL mode (24-bit addressing), `decodeInstruction(romBuffer, offset)` returns `{mnemonic, length, operands, ...}`
- Print results clearly: hex addresses, mnemonics, whether fall-through is possible
- The decoder may not perfectly decode every byte — if you hit garbage, note it and skip

## Constraints

- Output should be a self-contained Node.js ESM script that reads ROM.rom and prints analysis to stdout
- Use the same boilerplate style as `probe-phase287-0159c0-indirect-callers.mjs` (already in the directory)

## Success criterion
The probe prints whether 0x0159C0 is reachable via fall-through from the preceding code, and if so, what function/address falls into it.
