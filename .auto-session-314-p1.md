# Task: Trace scrapMem (0xD02AD7) Usage Beyond Utility Family

## Context
The TI-84 Plus CE ROM transpilation project has identified 12 utility functions in the 0x04C800-0x04CA40 region that use RAM address 0xD02AD7 ("scrapMem") as a scratch buffer. We need to know how many OTHER callers outside the utility family reference this address, whether it's safe as a scratch area, or whether it can be clobbered mid-use by interrupts or nested calls.

## What to do

1. **Search the transpiled ROM for all references to 0xD02AD7** (and nearby addresses 0xD02AD8-0xD02ADF in case of multi-byte accesses). The transpiled JS is at `TI-84_Plus_CE/ROM.transpiled.js.gz` — gunzip it first (`gunzip -kf TI-84_Plus_CE/ROM.transpiled.js.gz`), then grep for `d02ad` (case-insensitive) in the resulting `ROM.transpiled.js`.

2. **Categorize each reference** as:
   - Utility family (0x04C800-0x04CA40 region) — already known, just count
   - Other ROM functions — list address, read/write, and what the function appears to do
   - ISR context — any reference from interrupt handlers (0x000038, 0x000066, 0x001401, etc.)

3. **Assess safety**: Can scrapMem be clobbered if an ISR fires while a utility function is using it? Are there any nested call chains where two scrapMem users call each other?

4. **Write results** to `TI-84_Plus_CE/phase314-scrapmem-report.md` with:
   - Total reference count (reads vs writes)
   - Categorized list of all non-utility references
   - Safety assessment
   - Any interesting patterns (e.g., "always saved/restored before use")

5. **Write a probe** at `TI-84_Plus_CE/probe-phase314-scrapmem.mjs` that:
   - Loads the ROM (`fs.readFileSync('TI-84_Plus_CE/ROM.rom')`)
   - Scans for all instructions referencing 0xD02AD7-0xD02ADF
   - Prints a summary matching your report

## Key files
- `TI-84_Plus_CE/ROM.rom` — raw 4MB ROM binary
- `TI-84_Plus_CE/ROM.transpiled.js.gz` — transpiled JS (gunzip first)
- `TI-84_Plus_CE/cpu-runtime.js` — eZ80 runtime (for understanding memory model)
- `TI-84_Plus_CE/phase313-entry49-callback-report.md` — recent report for format reference

## Constraints
- Do NOT modify any existing files except creating the two new files listed above
- Do NOT touch browser-shell.html, peripherals.js, cpu-runtime.js, or the transpiler
- The ROM is little-endian eZ80 (24-bit addresses, 3-byte LD instructions)
- Search for the byte pattern D7 2A D0 (little-endian 0xD02AD7) in the raw ROM as well as string "0xd02ad" in the transpiled JS

## Success criterion
Report exists with a definitive count of all scrapMem references, categorized by caller region, with a clear safety verdict.
