# Task: Investigate 10-byte vs 9-byte stride discrepancy in dispatch table

## Context
In the TI-84 Plus CE ROM dispatch table system:

- **Session 271** decoded the polling loop at 0x084711: it uses a **10-byte stride** — CALL 0x082BE2 does DEC HL × 6 (subtracts 6), then after the 3-byte key comparison and skip of 3 more bytes on mismatch, the total skip is 6 + 3 + 1 = 10 bytes per entry.
- **Session 277** decoded the recursive VAT cache builder at 0x08267D: it loads BC=9 (entry size), and 0x08262B shifts existing D3Fxxx entries DOWN by 7 bytes to make room.
- **Session 275** confirmed D0259A is a 24-bit table-top pointer, and table size = (D3FFFF - D0259A) / 9.

So we have conflicting stride values: the SEARCH uses 10 bytes per entry, but the INSERTION uses 9 bytes (BC=9) and shifts by 7 bytes.

## Deliverable
Create a probe file `TI-84_Plus_CE/probe-phase278-stride-discrepancy.mjs` that:

1. **Re-disassemble 0x082BE2** (the DEC helper): Read ROM bytes at 0x082BE2 and decode. Session 271 says "DEC HL × 6" but verify: is it exactly 6 DECs, or could it be 7? Count the exact number of DEC HL instructions before the RET.

2. **Re-disassemble the polling loop at 0x084711-0x084740** (~50 bytes): Decode each instruction. Map out exactly how HL moves through the table:
   - Start position (from D0259A or D0259D?)
   - After CALL 0x082BE2: HL -= N (verify N)
   - After key comparison (CP (HL) etc.): how many more bytes does HL skip on mismatch?
   - Total stride = N + skip bytes

3. **Re-disassemble the insertion at 0x08267D** around the BC=9 load and the LDIR/LDDR at 0x08262B: Verify the 7-byte shift. What are the 7 bytes? What are the remaining 2 bytes of the 9-byte entry? Or is it 9 bytes total with 7 data + 2 overhead?

4. **Entry format hypothesis**: Based on the disassembly, propose the actual byte layout of one dispatch table entry:
   - Which bytes are the 3-byte key (matched against D005F9/FA/FB)?
   - Which bytes are the handler/data (read by 0x04C885)?
   - Is there a flag byte, length byte, or padding?
   - Why does search use stride 10 but insertion uses size 9?

5. **Dynamic verification**: 
   - Boot emulator, run 0x08267D with a seeded FindSym result to populate one entry
   - Dump the D3Fxxx region (D3FFF0-D3FFFF) to see the actual bytes written
   - Then run the polling loop at 0x084711 with matching D005F9 key and trace HL movement step by step
