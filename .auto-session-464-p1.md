# Session 464 P1: Read and Decode ROM Table at 0x3B0001 Used by 0x0066FF

## Context

The function at 0x0066FF is the #1 blocker for key detection in the TI-84 CE OS scheduler. It is called from the scheduler at 0x0015DF with BC=0x000F13. It searches ROM tables starting at 0x3B0001 with multiple search stages (DE values: 0x000300, 0x000700, 0x000710, 0x000730). It returns Z (fail) every iteration, so the scheduler never reaches key detection code at 0x0015E1.

## Task

Create a Node.js probe at `TI-84_Plus_CE/probe-phase464-rom-table-decode.mjs` that:

1. Reads the ROM file at `TI-84_Plus_CE/ROM.rom` (4MB binary, little-endian eZ80)
2. Starting at offset 0x3B0001, reads and decodes the table structure
3. The table is used by a function that does table-search with DE as a key parameter. The search stages use DE=0x000300, 0x000700, 0x000710, 0x000730.
4. Dump the first 256 bytes at 0x3B0001 as hex
5. Try to identify the table entry format. Common TI OS table formats:
   - Length-prefixed entries: first byte = entry length, then data
   - Fixed-size entries with a terminator byte (0x00 or 0xFF)
   - Two-byte key + N-byte value entries
6. The search function at 0x0066FF uses parameter BC=0x000F13. Try to find if 0x0F13 appears anywhere in the table data near 0x3B0001 (within 0x3B0001-0x3B1000).
7. Also check what's at 0x3B0000 (the byte before the table start — might be a table count or type byte)
8. Print all findings to stdout
