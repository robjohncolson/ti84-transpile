# Auto-Session 355 — P1: Trace 0x00D33B → RST 38h Transition

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM (eZ80 CPU, 4MB at `TI-84_Plus_CE/ROM.rom`) has been lifted to JavaScript. Boot currently loops in a 2203-step cycle through 270 blocks. At the end of each cycle, execution reaches 0x00D33B which somehow triggers RST 38h (address 0x000038), restarting boot init.

## Task
Create a probe that:
1. **Disassembles ROM bytes at 0x00D330-0x00D370** (64 bytes) using the ROM file directly. Print each instruction with address, hex bytes, and mnemonic.
2. **Determines whether 0x00D33B contains opcode 0xFF** (RST 38h instruction) or some other mechanism that leads to 0x000038.
3. **Traces execution dynamically** from 0x00D7BE (the z80-mode seed that enters the cycle) for 3000 steps with `createPeripheralBus({ timerInterrupt: false })`. Log every instruction that executes in the address range 0x00D330-0x00D360, printing: step number, PC, opcode bytes, SP, and the instruction at that PC.
4. **Specifically captures the transition** from 0x00D33B to 0x000038 — what is the last instruction before PC becomes 0x000038? What are the register values (A, F, SP, IY) at that moment?

## Deliverables
- Create file: `TI-84_Plus_CE/probe-phase355-rst38h-transition.mjs`
- The probe must be runnable with `node TI-84_Plus_CE/probe-phase355-rst38h-transition.mjs`
- Print clear labeled output

## Technical Details
- ROM file: `TI-84_Plus_CE/ROM.rom` (4MB, load with `fs.readFileSync`)
- Runtime: `import { createCPU } from './cpu-runtime.js'; import { createPeripheralBus } from './peripherals.js';`
- CPU creation pattern:
```js
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';
import fs from 'fs';

const rom = new Uint8Array(fs.readFileSync('TI-84_Plus_CE/ROM.rom'));
const mem = new Uint8Array(0x1000000);
mem.set(rom);
const bus = createPeripheralBus({ timerInterrupt: false });
const cpu = createCPU(mem, bus);
```
- To step: `cpu.step()` returns number of cycles. Check `cpu.pc` for current PC, `cpu.sp` for stack pointer.
- Registers: `cpu.a`, `cpu.f`, `cpu.b`, `cpu.c`, `cpu.d`, `cpu.e`, `cpu.h`, `cpu.l`, `cpu.ix`, `cpu.iy`, `cpu.sp`, `cpu.pc`
- The transpiled ROM is loaded via: after creating cpu+mem, do `const mod = await import('./ROM.transpiled.js'); mod.default(cpu, mem, bus);` — this registers all block functions.
- Actually, use dynamic import and the blocks are registered on the cpu object. The pattern from existing probes:
```js
const { createCPU } = await import('./cpu-runtime.js');
const { createPeripheralBus } = await import('./peripherals.js');
// ... setup mem, bus, cpu ...
// Load transpiled blocks
const transpiled = await import('./ROM.transpiled.js');
```
- To read ROM bytes for disassembly, just index into `rom[addr]` for addresses < 0x400000.
- eZ80 RST 38h = opcode 0xFF. It pushes PC+1 onto stack (3 bytes in ADL mode) and jumps to 0x000038.
