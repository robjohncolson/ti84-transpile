# Task: Build onBlock wipe hook for automatic state restoration

## Context
In the TI-84 Plus CE ROM transpilation project, the OS bulk RAM wipe at address 0x0018F8 fires TWICE during every key processing cycle. It zeroes 82KB of RAM (D00000-D13FD7) including critical OS state: D007CA (cxMain context pointer), D0231A/D0243A (edit cursors), D0008D (mode flag), and IY flag area. Session 605 confirmed that state restoration after each wipe enables 3/3 multi-key dispatch. The wipe is STRUCTURAL — part of normal OS key processing — and cannot be prevented.

**Goal**: Instead of manually restoring state before each key, use an `onBlock` hook on address 0x0018F8 to automatically snapshot and restore state after each wipe fires. This should enable processing 3+ keys with just key-seeding, no manual state restoration between keys.

## Task
Create a probe at `TI-84_Plus_CE/probe-phase606-wipe-hook.mjs` that:

1. **Boots the OS** using the established recipe:
   ```javascript
   import { createCPU } from './cpu-runtime.js';
   import { createPeripheralBus } from './peripherals.js';
   const peripherals = createPeripheralBus({ timerInterrupt: false });
   const cpu = createCPU(peripherals);
   // Standard shortcut boot
   cpu.sp = 0xD1A87E - 24;
   const retAddr = 0x0019b5; // HALT idle, NOT 0x0019be (wipe trap!)
   cpu.write24(cpu.sp, retAddr);
   cpu.write24(0xD008E0, cpu.sp);
   cpu.adl = 1;
   ```

2. **Runs the real init** `cpu.runFrom(0x09DD62, { maxSteps: 300000, maxLoopIterations: 30000 })` to initialize VAT/RAM/system vars properly.

3. **Runs the paint** `cpu.runFrom(0x058241, ...)` with timer on and pushed return 0x0019b5 to build the initial display + edit context.

4. **Snapshots the critical state** after paint:
   - D007CA-D007DE (21-byte context descriptor)
   - D0008D (mode flag)
   - D0231A (3 bytes, edit cursor)
   - D0243A (3 bytes, edit cursor)
   - D02434 (32 bytes, descriptor block)
   - D0009F (1 byte, event flags)
   - D00080-D000FF (128 bytes, IY flag area)

5. **Installs an onBlock hook** on 0x0018F8 that, AFTER the wipe executes, restores the snapshot:
   ```javascript
   let wipeCount = 0;
   cpu.onBlock(0x0018F8, () => {
     // Let the wipe run first (it will execute when the block runs)
     // We need to restore AFTER the block completes
     wipeCount++;
   });
   // Actually, onBlock fires BEFORE the block runs. 
   // We need a POST-block hook or to restore at the next block after 0x0018F8.
   // Alternative: use onBlock on the RETURN address after the CALL to 0x0018F8.
   // From session 603: the call is 0x001872→0x001879→0x0018F8
   // After 0x0018F8 completes, execution returns to after the CALL in 0x001879.
   // 
   // BETTER APPROACH: hook the block AFTER 0x0018F8 in the execution flow.
   // The wipe block at 0x0018F8 does LDIR clears then CALLs 0x005B96 + 0x005BB1.
   // After those, it RETs. Hook 0x005B96 or use a step-counting approach:
   // just run a fixed number of steps per key and restore state between keys.
   //
   // SIMPLEST APPROACH: Use onBlock(0x0019b5) — the HALT idle block that 
   // each key dispatch ends at — to restore state for the next key.
   ```

   **Recommended approach**: Hook `onBlock(0x0019b5)` (the HALT idle block where each key dispatch terminates). When it fires after a key dispatch, restore the full state snapshot, seed the next key, and re-arm the longjmp anchor. This way each key starts with clean state.

6. **Processes 3 keys** ('2'=0x90, '3'=0x91, '+'=0x70) sequentially via the outer loop at 0x08C331:
   - For each key: set D0058C=scancode, set D0009F bit 5, re-arm D008E0 with sp frame pushing 0x0019b5
   - Run `cpu.runFrom(0x08C331, { maxSteps: 500000, maxLoopIterations: 50000 })`
   - After halt, check VRAM pixel count, check D007CA, check if wipe fired

7. **Reports** for each key:
   - Steps taken
   - Whether cxMain (0x0585E9) was dispatched (use onBlock watch)
   - Wipe count (how many times 0x0018F8 fired)
   - Peak VRAM pixel count during processing
   - Final D007CA value
   - Final D0231A/D0243A values

## Key Setup Functions (from existing probes)
```javascript
function pressKey(cpu, scanCode) {
  // Set the key in the OS key buffer
  cpu.write8(0xD0058C, scanCode);    // pending key scan code
  cpu.write8(0xD0058E, scanCode);    // internal scan code
  cpu.write8(0xD00587, scanCode);    // raw scan code
  const flags = cpu.read8(0xD0009F);
  cpu.write8(0xD0009F, flags | 0x20); // set bit 5 = key pending for outer loop
  cpu.write8(0xD00080, cpu.read8(0xD00080) | 0x08); // set bit 3 = key available
}

function countVRAM(cpu) {
  let count = 0;
  for (let i = 0xD40000; i < 0xD52C00; i += 2) {
    const px = cpu.read8(i) | (cpu.read8(i+1) << 8);
    if (px !== 0xFFFF) count++; // count non-white pixels
  }
  return count;
}
```
