# Task: Decode 0x04E5FE — Token rendering helper called by 0x0A2A68

## Context
In the TI-84 Plus CE ROM (eZ80, `TI-84_Plus_CE/ROM.rom`, 4MB), session 549 decoded 0x0A2A68 as the TOKEN PAGE DISPATCHER (235B, 27 callers). Near the end of 0x0A2A68's rendering path, it calls 0x04E5FE (after loading the first byte of the token string into D026B8). We need to know what 0x04E5FE does.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase550-decode-04E5FE.mjs` that:

1. Reads the ROM binary from `TI-84_Plus_CE/ROM.rom`
2. Dumps raw hex bytes starting at 0x04E5FE for ~256 bytes (0x100)
3. Disassembles the eZ80 instructions starting at 0x04E5FE until you hit a RET (0xC9) or unconditional JP, or ~80 instructions
4. Identifies what the function does: register usage, RAM reads/writes, subroutine calls, loops
5. Scans the entire ROM for all CALL/JP references to 0x04E5FE to count callers
6. Prints a structured summary

Use the same probe structure as `TI-84_Plus_CE/probe-phase549-decode-0A2A68.mjs` (read it for reference). The probe is a standalone Node.js ESM file that reads the ROM binary directly and prints analysis to stdout.

## eZ80 notes
- eZ80 is like Z80 but with 24-bit addresses. Default mode is ADL (24-bit).
- 3-byte addresses in LD instructions (e.g., LD HL,imm24 = 0x21 + 3 bytes LE)
- CALL nn = 0xCD + 3 bytes LE address
- JP nn = 0xC3 + 3 bytes LE address  
- JP cc,nn = 0xC2/CA/D2/DA/E2/EA/F2/FA + 3 bytes LE
- RET = 0xC9
- Prefix 0x40 = SIS mode (16-bit operands in 24-bit mode)
- Prefix 0x52 = SIS+IX, 0x62 = SIS+IY (but these are also LD D,D / LD H,D — context matters)
- CP n = 0xFE + 1 byte
- JR cc,e = 0x20/28/30/38 + signed 8-bit offset
- DJNZ e = 0x10 + signed 8-bit offset
- BIT/SET/RES via 0xCB prefix
- IX prefix = 0xDD, IY prefix = 0xFD
- ED prefix for extended ops (ED 27 = LD HL,(HL) in eZ80)

## Caller scan
Search the full 4MB ROM (0x000000-0x3FFFFF) for bytes CD FE E5 04 (CALL 0x04E5FE) and C3 FE E5 04 (JP 0x04E5FE). Print each caller address.
