# Session 250 P3: Investigate D007E0 mode flags — what values enable cxMain key routing

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript blocks.

Session 249's event loop trace found that when a key is injected, the dispatch at 0x02FFAE reads D007E0 (mode flags) and gets value 0x40. The dispatch path then goes through 0x022346→0x000578→0x0158A6 and loops back WITHOUT reaching cxMain (the home screen key handler).

The hypothesis: D007E0=0x40 is not the right mode for cxMain dispatch. The OS may need a different D007E0 value (or additional flags) to route keys to the home screen key handler.

## Task
Write a probe `TI-84_Plus_CE/probe-phase250-d007e0-mode-sweep.mjs` that:

1. Boots the OS (copy boot sequence from `probe-phase249-event-loop-digit-trace.mjs`)
2. Reaches the idle HALT at 0x040D40
3. For EACH of these D007E0 values: 0x00, 0x01, 0x02, 0x04, 0x08, 0x10, 0x20, 0x40, 0x80, 0xFF:
   a. Save CPU state + memory snapshot (at least D007E0 through D007FF, D003E0, D0058E, D0059F, IY area)
   b. Set D007E0 to the test value
   c. Inject key "2" (D0058E = 0x8F)
   d. Run up to 200 steps
   e. Record: which blocks were visited, whether any of these were reached:
      - 0x0585D3 (JP (HL) dispatch table)
      - 0x0585E9 (cxMain entry)
      - 0x05877A (cascading CP chain)
      - 0x058AC9 (BufInsert gate)
      - 0x05E2A0 (BufInsert)
      - 0x04EDD0 (post-key handler)
   f. Restore CPU state + memory to pre-test snapshot
4. Print a summary table: D007E0 value → which watched addresses were hit (YES/NO for each)

Also investigate:
5. Read ROM bytes at 0x02FFAE-0x02FFD0 and disassemble (just hex dump the raw bytes)
6. Read ROM bytes at 0x022346-0x022380 and hex dump
7. Check what writes D007E0 during boot — trace which block last wrote to D007E0 before HALT
