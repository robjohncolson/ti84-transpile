# Auto-Session 192 P3: TOKEN_STAGING format experiments for Y= key

## Context
Session 191 built `probe-phase191-yeq-bypass.mjs` which tested entry at 0x05849F and 0x05848F for Y= key dispatch. Key findings:
- Entry at 0x05849F: Copy9 copies TOKEN_STAGING (9 bytes at 0xD0230E) → OP1. Then classifier at 0x07F7BD reads OP1[0] & 0x3F. With TOKEN_STAGING[0]=0x8D (raw ConvKeyToTok output), classifier sees type=0x0D → falls through to general insertion. But the 9-byte structure was `[0x8D, 0, 0, 0, 0, 0, 0, 0, 0]` which is wrong.
- Entry at 0x05848F: classValue=0x03, hits 19 blocks in 0x058Cxx-0x058Dxx handler area.

The KEY INSIGHT from session 191: TOKEN_STAGING must contain a properly formatted 9-byte OP1-format token object (type byte at [0], token data at [1-2]), not just the raw key code byte. The OP1 format for tokens is: `[type, token_byte_1, token_byte_2, 0, 0, 0, 0, 0, 0]`.

## Task
Create `TI-84_Plus_CE/probe-phase192-token-staging-format.mjs` that tests multiple TOKEN_STAGING format hypotheses at entry point 0x05849F:

### Hypothesis A: type=0x05 (special token type), token=0x8D (Y= token)
```
TOKEN_STAGING = [0x05, 0x8D, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]
```
Type 0x05 is the "special" type per session 184's key classifier decode (cp 0x05 branch at 0x0584B1 in the home handler).

### Hypothesis B: type=0x00 (variable type), token=0x8D
```
TOKEN_STAGING = [0x00, 0x8D, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]
```

### Hypothesis C: type=0x0D (raw token type from ConvKeyToTok)
```
TOKEN_STAGING = [0x0D, 0x8D, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]
```

### Hypothesis D: type=0x06 (error type → should trigger error handler path)
```
TOKEN_STAGING = [0x06, 0x8D, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]
```

### Hypothesis E: Y= is a two-byte token with prefix
The Y= key might use a two-byte token format: `[type, prefix, token]`. Try:
```
TOKEN_STAGING = [0x05, 0x5E, 0x8D, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]
```

## Probe structure
Base on `probe-phase191-yeq-bypass.mjs`. For each hypothesis:
1. Full boot + MemInit (same as probe-phase191)
2. Set TOKEN_STAGING at 0xD0230E with the 9-byte hypothesis value
3. Enter at 0x05849F (the Copy9 TOKEN_STAGING→OP1 point)
4. Set up: SP=STACK_TOP(0xD1A87E), IX=0xD1A860, IY=0xD00080, stack has return sentinel
5. Trace up to 2000 steps
6. Record:
   - classValue = what the classifier returns (OP1[0] & 0x3F after Copy9)
   - Which branch is taken (cp 0x06, cp 0x05, or fall-through)
   - All unique block PCs visited
   - Final PC and termination reason
   - Whether BufInsert (0x05E2A0) is reached
   - Whether any Y= editor blocks in 0x09C000-0x09D000 range are reached
   - OP1 state after execution
7. Also test each hypothesis at entry 0x05848F (the earlier entry that hit classValue=0x03 in session 191)

## Key addresses
