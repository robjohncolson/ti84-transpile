# Task (vvv): Trace the no-key HALT path

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript. You write Node.js probes that boot the transpiled ROM and trace execution paths.

## Background
Session 236's home-screen key event e2e map (probe-phase236-home-key-e2e.mjs) showed that when NO key is pressed, the event loop takes a different path: 19 steps from 0x02FD99 to HALT at 0x040D40. The path goes through:
0x02FDEB→0x02FDF4→0x02FE02→0x03D1BE→0x02FE06→0x02FE23→0x02FE2F→0x040D40

**Questions**:
1. What does each block do on this path?
2. 0x040D40 is HALT — does the ISR restart the event loop? How does execution resume after HALT?
3. What conditions does each block test to decide "no key → go to HALT"?

## What to do
Create `TI-84_Plus_CE/probe-phase237-nokey-halt-path.mjs` that:

1. Boots the transpiled ROM (full boot sequence — see existing probes for pattern)
2. Disassembles ROM bytes at each block in the no-key path:
   - 0x02FDEB, 0x02FDF4, 0x02FE02, 0x03D1BE, 0x02FE06, 0x02FE23, 0x02FE2F, 0x040D40
3. Traces execution from 0x02FD99 with NO key pressed (D0058E=0x00, keyboard matrix empty)
4. Records step-by-step block transitions with register snapshots (A, F, HL, BC, DE, IY)
5. At each block, captures what condition/flag test causes the branch toward HALT
6. When execution reaches 0x040D40 (HALT), check:
   - What is the HALT instruction doing? (power save? wait for interrupt?)
   - If ISR were enabled, where would execution resume? (PC after HALT = 0x040D41?)
   - What does block 0x040D41 or the ISR vector do?
7. Also trace what happens if we simulate ISR firing at HALT:
   - Set PC to the ISR handler address and trace a few blocks
   - Does it eventually return to the event loop at 0x02FD99?

- Output results to stdout as structured text
- Max 300 steps per trace

## Success criteria
- Probe runs without error: `node TI-84_Plus_CE/probe-phase237-nokey-halt-path.mjs`
- Reports disassembly and purpose of each block on the no-key path
- Identifies what condition at each block routes execution toward HALT
- Documents what happens at/after the HALT instruction
- Explains how the event loop would resume after HALT (ISR mechanism)
