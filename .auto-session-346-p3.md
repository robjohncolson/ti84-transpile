# Auto-Session 346 — Priority 3: Map Synthetic Scan Code Generators

## Context

Session 345 mapped D0058E as the "cooked" scan code register. It found that D0058E receives virtual key events from addresses 0x0869A9-0x0869FF with hardcoded values 0x82, 0x01, 0xFD. These bypass D0058C (raw scan code register) — they're OS-generated synthetic key events.

The probe `probe-phase345-scancode-d0058e.mjs` identified these write sites but didn't trace what triggers them or what the values mean.

## Task

Create a probe that:

1. **Disassembles the region 0x0869A9-0x086A20** (about 120 bytes) to understand the full context of the synthetic scan code writes. Look for:
   - What conditional branches guard each write
   - What IY flags or other state is checked before writing 0x82, 0x01, 0xFD to D0058E
   - Whether these are part of a larger state machine

2. **Identifies what 0x82, 0x01, 0xFD mean** in the scan code system:
   - Cross-reference with `TI-84_Plus_CE/keyboard-matrix.md` (the scan code map)
   - 0x01 likely = a virtual "enter" or "start" signal
   - 0x82, 0xFD are > 0x7F, so they're NOT raw keyboard scan codes (those are 0x00-0x38 range)
   - These are likely "meta" scan codes that trigger special handler behavior

3. **Traces callers of the region** — who calls into the 0x0869xx area? Is it called from the CoorMon loop, from an interrupt, or from a specific handler?

4. **Cross-references with the context handler CP cascades** from session 342:
   - Handler 0x06B4E8 has CP cascade: 0x27, 0x17, 0x19, 0x15, 0x18, 0x20, 0x09
   - Do any handlers check for 0x82, 0x01, or 0xFD in their CP cascades?
