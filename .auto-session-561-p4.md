# Task: Decode 0x0B4EE2 — Partial-Clip Blit Function

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). We decode ROM functions by reading raw bytes, disassembling them as eZ80 instructions, and documenting their behavior.

Session 560 decoded 0x025C33 (Quick Newline, 96B) which calls 0x0B4EE2 in its partial-clip path:
- When width clipping (via 0x04C979) returns carry: `SRL A` on L, DJNZ loop calling 0x0B4EE2
- Also called once more after the DJNZ loop with a decrement of (0x08D2)
- Likely a single-column pixel fill or partial blit operation

Related functions:
- 0x0A23E5 = full blit loop (decoded session 552, called with A=6 mode in the no-carry path)
- 0x04C979 = width clipping (decoded session 552)
- 0x025C33 = quick newline (decoded session 560)
- D0059C = framebuffer write pointer
- (0x08D2) = clip X / cursor column position (accessed via .SIS 16-bit mode)
- (0x017F) = width limit

## What to do

1. Read 150 bytes starting at ROM offset 0x0B4EE2 from `TI-84_Plus_CE/ROM.rom`
2. Disassemble as eZ80 ADL-mode instructions (24-bit addresses, 3-byte pointers)
3. Document: registers used, RAM addresses read/written, CALL targets, function boundary
4. Look for: framebuffer writes, column-based operations, pixel fill patterns, interaction with D0059C

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase561-decode-0B4EE2.mjs`

Use this template structure:
```javascript

const rom = readFileSync('TI-84_Plus_CE/ROM.rom');

const startAddr = 0x0B4EE2;
const bytes = rom.slice(startAddr, startAddr + 150);

console.log(`=== Decoding 0x0B4EE2: Partial-Clip Blit ===`);
console.log(`Bytes at 0x${startAddr.toString(16)}:`);

for (let i = 0; i < bytes.length; i += 16) {
    const addr = startAddr + i;
    const hex = Array.from(bytes.slice(i, Math.min(i + 16, bytes.length)))
        .map(b => b.toString(16).padStart(2, '0')).join(' ');
    console.log(`  ${addr.toString(16).padStart(6, '0')}: ${hex}`);
}

console.log(`\n=== Disassembly ===`);
// Full eZ80 ADL-mode disassembly, instruction by instruction
// Cover all standard eZ80 instruction groups
// Watch for framebuffer stride patterns (0x0280 = 640B for 16bpp)
// Watch for LDIR/LDI block copies

// RAM addresses, CALL targets, function size, architectural interpretation
```

Implement a FULL eZ80 disassembly. Cover at minimum:
- LD r,r / LD r,n / LD r,(addr) / LD (addr),r
- PUSH/POP, CALL nn (3-byte ADL), RET/RET cc
- JP nn / JR e / JR cc,e
- CP / OR / AND / XOR / ADD / SUB / INC / DEC
- BIT/SET/RES (CB prefix), IX/IY (DD/FD prefix)
- ED prefix: LDIR/LDI, block operations
- .SIS prefix (0x40) for 16-bit mode

Stop at clear function boundary.
