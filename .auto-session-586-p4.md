# Task: Decode 0x092F87 and 0x092F95 — math/computation helpers called before type-0x09 event posting

## Context
You are working on a TI-84 Plus CE ROM reverse-engineering project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary, little-endian, ADL mode = 24-bit addresses).

Session 585 traced type-0x09 event callers. Two callers (at 0x022878 and 0x0228CC) call 0x092F87 and 0x092F95 respectively before posting the type-0x09 event. These are hypothesized to be math or computation helpers. Note that 0x092F95 is only 14 bytes after 0x092F87 — they may be entry points into the same function or closely related functions.

## Deliverable
Create `TI-84_Plus_CE/probe-phase586-decode-092F87.mjs` — a static disassembly probe that:
1. Reads `TI-84_Plus_CE/ROM.rom` directly with `readFileSync`
2. Disassembles BOTH functions:
   - Starting at 0x092F87 until RET or unconditional JP (max ~200 bytes)
   - Starting at 0x092F95 until RET or unconditional JP (max ~200 bytes)
3. Notes whether they overlap (0x092F95 might be a mid-function entry into the 0x092F87 body)
4. Tracks all CALL targets, JP/JR targets, RAM references (0xD0xxxx), IY+offset refs, and port I/O
5. Prints a formatted analysis of both

## Decoder API
The probe must use a HAND-ROLLED eZ80 decoder reading raw bytes from the ROM buffer. Do NOT import from `ez80-decoder.js` — it does not export `decodeAt` or similar.

```js
import { readFileSync } from 'fs';
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
function b(addr) { return rom[addr] ?? 0; }
function u16(addr) { return b(addr) | (b(addr + 1) << 8); }
function u24(addr) { return b(addr) | (b(addr + 1) << 8) | (b(addr + 2) << 16); }
```

Then decode eZ80 instructions manually by reading opcodes. See `TI-84_Plus_CE/probe-phase585-decode-08011F.mjs` for a complete working example.
