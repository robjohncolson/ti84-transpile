# Auto-Session 456 — P1: Trace IRQ Front-End Dispatch at 0x0006F3

## Context

This is a TI-84 Plus CE ROM transpilation project. The OS ROM is lifted to JavaScript and executed via `cpu-runtime.js`. We're investigating why the timer IRQ service routine at 0x001ACF never gets called despite the IRQ front-end at 0x0006F3 being visited 8,952 times.

**Key finding from session 455**: With `timerInterrupt: true`, the IRQ vector at 0x000038 fires 8,952 times, jumps to 0x0006F3 (the generic IRQ front-end) all 8,952 times, but 0x001ACF (the timer-specific service) gets ZERO visits. The front-end dispatches somewhere else.

## Task

Create a probe `TI-84_Plus_CE/probe-phase456-irq-frontend-trace.mjs` that:

1. Boots to home screen using the standard boot sequence (copy from `probe-phase455-timer-irq-exit.mjs` lines 56-106)
2. Enables `timerInterrupt: true` in createPeripheralBus
3. Injects key "1" (scan code 0x12 to D00587, set bit 3 of D00080)
4. Runs from EVENT_LOOP_ENTRY (0x003A73) with a 2M step budget
5. **Traces the IRQ front-end dispatch path**: For the FIRST 10 IRQ entries (when PC hits 0x000038), record the next 50 unique PCs visited after 0x0006F3. This shows us WHERE the front-end dispatches to.
6. Also record which PORT READS happen in the 0x0006F3 function — it likely reads a status port to decide which interrupt source to service. Capture all `portIn` calls between 0x0006F3 and 0x000FFF (the front-end is in the low ROM vector area).

**Key addresses**:
- 0x000038: IM 1 IRQ entry vector
- 0x0006F3: Generic IRQ front-end (saves registers, loads IY=0xD00080, dispatches)
- 0x001ACF: Timer-specific ISR (acknowledges FTINTC byte0 bit4 via port 0x5008, decrements D02658+D02651)
- 0x003A73: Event loop entry
- 0xD00587: Key scan code injection address
- 0xD00080: Key available flag (bit 3)

**What to instrument**: Add a `portInLog` array to track port reads. Intercept the `portIn` function in the peripheral bus to log port address and value returned during IRQ front-end execution. Track the first 10 IRQ entries and for each one, record the dispatch chain of PCs after 0x0006F3.

## Deliverables
- `TI-84_Plus_CE/probe-phase456-irq-frontend-trace.mjs`
- Console output showing: which PCs the front-end visits, which ports it reads, and where it dispatches (the first JP/CALL after reading the status port)

## Constraints
- Do NOT modify `cpu-runtime.js`, `peripherals.js`, `ez80-decoder.js`, or any other shared file
- Base your probe on the boot sequence in `probe-phase455-timer-irq-exit.mjs`
- Use `createPeripheralBus({ pllDelay: 2, timerInterrupt: true })`
- Use `createExecutor(BLOCKS, mem, peripherals)` — the executor takes (blocks, mem, peripherals)
- The `runFrom` method signature is: `executor.runFrom(address, mode, { maxSteps, maxLoopIterations, onStep, onPortIn, onPortOut })`
- `onStep(pc, steps)` callback receives current PC and step count
- `onPortIn(port, value)` callback receives the port address and value read
- `onPortOut(port, value)` callback receives the port address and value written
