# Session 374 P1: Investigate Halt at 0x001937 After Key Dispatch

## Context
In session 373, direct RAM injection was confirmed: writing scan code 0x09 (ENTER) to mem[0xD00587] and setting bit 3 of mem[0xD00080] before the event loop at 0x003A73 makes _GetCSC return the key. The event loop dispatches to 0x003A7D, and execution proceeds through 40 new blocks. But after only 52 steps, execution HALTS at 0x001937.

The question: is 0x001937 a HALT instruction waiting for a timer interrupt? If timerInterrupt is enabled, does execution continue past 0x001937? What new blocks are reached?

## Task
Create `TI-84_Plus_CE/probe-phase374-halt-investigation.mjs` that:

1. Boots phases 1-3 (same pattern as `probe-phase373-direct-ram-inject.mjs` — use that file as your template)
2. Runs TWO scenarios with direct RAM injection (mem[0xD00587]=0x09, mem[0xD00080]|=0x08):
   - **Scenario A**: `timerInterrupt: false` — expect halt at 0x001937 after ~52 steps
   - **Scenario B**: `timerInterrupt: true` — does the timer ISR fire and resume past the HALT?
3. For each scenario, track:
   - Total steps executed
   - Termination reason and lastPc
   - Whether 0x001937 is visited (and how many times)
   - All unique blocks visited (sorted)
   - cpu.halted state at end
   - Whether execution continues past 0x001937 (new blocks reached after it)
4. Run Scenario B with maxSteps=500000 and maxLoopIterations=200000 to give the timer time to fire
5. Compare the block sets between scenarios A and B
6. Read ROM byte at 0x001937 and disassemble it (use `decodeInstruction` from `ez80-decoder.js`) to confirm it's actually a HALT instruction
