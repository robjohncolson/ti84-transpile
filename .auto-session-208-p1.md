# Auto-Session 208 P1: Find ALL BufInsert (0x05E2A0) call sites in ROM

## Context
We're investigating how digit tokens get inserted into the TI-84 CE edit buffer. The cxMain path at 0x058AC9 has a gate (CP 0x5A at 0x0802C4) that rejects all token classes < 90 — digits (class 0) can NEVER reach BufInsert through that path. We need to find ALTERNATIVE call sites for BufInsert.

## Task
Build a probe `TI-84_Plus_CE/probe-phase208-bufinsert-callsites.mjs` that:

1. **Scans the ROM binary** (`TI-84_Plus_CE/ROM.rom`, 4MB) for ALL `CALL 0x05E2A0` instructions in eZ80 ADL mode.
   - eZ80 ADL CALL encoding: `CD A0 E2 05` (opcode CD, then 24-bit little-endian address 0x05E2A0)
   - Also check for `JP 0x05E2A0`: `C3 A0 E2 05`
   - Also check z80 mode CALL (non-ADL): the encoding would be `CD A0 E2` (16-bit, but within MBASE page — less likely, still check)

2. **For each call site found**, report:
   - Address of the CALL/JP instruction
   - Which region it's in (classify by address range: 0x000000-0x010000=vectors, 0x010000-0x050000=OS core, 0x050000-0x060000=cxMain/editor, 0x060000-0x080000=display/error, 0x080000-0x0A0000=FP/validation, 0x0A0000-0x0C0000=apps/Y=)
   - The 16 bytes before and after the CALL for context

3. **Specifically highlight** any call sites OUTSIDE the 0x058000-0x058FFF range (the cxMain area we already know about).

4. **Cross-reference with known patterns**: Do any of the non-cxMain call sites have a CP 0x5A gate before them? Or do they call BufInsert unconditionally?
