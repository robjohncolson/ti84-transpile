# Task: Trace who calls 0x046500 (the full keyboard matrix scanner)

## Context
We're reverse-engineering the TI-84 Plus CE OS ROM (eZ80, 4MB at `TI-84_Plus_CE/ROM.rom`). Session 287 identified 0x046500 as the "FULL KEYBOARD MATRIX SCANNER" — a 185-step function that does multi-pass scanning of the keyboard hardware via MMIO at 0xE00800-0xE0090F, storing 10 scan results into RAM buffer D17731-D1773A. This is likely called from the ISR (interrupt service routine) level keyboard handler.

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase288-046500-callers.mjs`

## What to do
1. Search the entire ROM (0x000000-0x0BFFFF, the non-erased code region) for CALL and JP instructions targeting 0x046500.
   - eZ80 CALL nn in ADL mode: opcode 0xCD followed by 3 bytes (little-endian target). So search for: `CD 00 65 04`
   - eZ80 JP nn in ADL mode: opcode 0xC3 followed by 3 bytes. Search for: `C3 00 65 04`
   - Also check JP cc,nn variants: 0xC2/CA/D2/DA/E2/EA/F2/FA followed by `00 65 04`
2. For each call site found, decode the surrounding context (16 bytes before, 16 bytes after) to understand what function contains the call.
3. Also check: is 0x046500 reachable via fall-through from 0x0464FF? Decode the instruction at/before 0x046500.
4. For the most promising caller (likely in the ISR region 0x000000-0x001000 or the keyboard handler region 0x040000-0x047000), do a deeper decode of the calling function to understand when/how 0x046500 is invoked.

## Technical details
- Import the decoder: `import { decodeInstruction } from './ez80-decoder.js';`
- ROM file: `ROM.rom` in the same directory
- eZ80 ADL mode (24-bit addressing)
- The ISR vector table starts at 0x000000. Timer ISR enters at ~0x000038 or via a vector.
- Previous sessions identified 0x040CE6 as a "keyboard dispatcher" and 0x040F0E as a "scan-engine programmer"

## Constraints
- Do NOT modify any existing files
- Do NOT run the transpiler
- Output should be a self-contained Node.js ESM script
- Use the same boilerplate style as other probe-phase*.mjs files in the directory

## Success criterion
The probe identifies all ROM sites that call/jump to 0x046500, and for the primary caller, explains the calling context (is it the ISR? a polling loop? a specific OS function?).
