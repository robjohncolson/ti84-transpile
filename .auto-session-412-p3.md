# Task: Map 0x01567C (Notification Delivery Wrapper)

## Context
You are working on a TI-84 Plus CE ROM (eZ80) transpilation project. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 machine code).

Session 411 decoded USB Worker A at 0x013250, which calls 0x01567C for notification delivery via the 0x00F5B0 syscall. We also know that 0x02B373 is a post-dispatch notification initializer that builds a 28-byte parameter block at D143E7 and calls syscall 0x0004A0 → 0x00F5B0.

We need to understand how 0x01567C wraps the 0x00F5B0 notification delivery syscall:
- Does it build a different parameter block than 0x02B373?
- Does it call 0x00F5B0 directly or via the syscall table?
- What additional setup/teardown does it perform?

2. **Trace all subroutine calls** within 0x01567C — especially calls to:
   - 0x00F5B0 (notification delivery handler)
   - 0x0004A0 (syscall that resolves to 0x00F5B0)
   - 0x014E3F (notification state installer)

3. **Identify RAM addresses accessed** — look for references to:
   - D143E7-D14402 (the 28-byte notification parameter block)

4. **Find all callers** of 0x01567C in the ROM:
   - `CALL 0x01567C` = bytes CD 7C 56 01
   - `JP 0x01567C` = bytes C3 7C 56 01

5. **Compare with 0x02B373**: The known wrapper builds a 28-byte block with 7 fields at D143E7. Does 0x01567C use the same block or a different one?

## eZ80 Encoding Reference
- CALL nn = CD nn24 (4 bytes total)
- JP nn = C3 nn24 (4 bytes total)
- LD A,(nn) = 3A nn24 (4 bytes)
- LD (nn),A = 32 nn24 (4 bytes)
- LD HL,(nn) = 2A nn24 (4 bytes)
- LD (nn),HL = 22 nn24 (4 bytes)
- LD BC,(nn) = ED 4B nn24 (5 bytes)
- LD (nn),BC = ED 43 nn24 (5 bytes)
- LD DE,(nn) = ED 5B nn24 (5 bytes)
- LD (nn),DE = ED 53 nn24 (5 bytes)
- RET = C9
- DI = F3, EI = FB
- PUSH IX = DD E5, POP IX = DD E1
- LD (IX+d),n = DD 36 d n

Addresses are 24-bit little-endian in the ROM.
