# Auto-Session 366 — P3: Trace Linked-List Init for 0xD14095-0xD14097

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The OS ROM is lifted to JavaScript and executed block-by-block.

### The problem
At ROM address 0x00BC47, the OS reads bytes at (IX-30) as a 24-bit pointer for a linked-list traversal. When IX points to the flag region 0xD14091-0xD14098, the bytes at 0xD14095-0xD14097 are read as a 3-byte pointer, producing 0x010000 (because 0xD14095=0x00, 0xD14096=0x00, 0xD14097=0x01 — set by init code at 0x00B71B).

This pointer 0x010000 is in ROM space, and when loaded into SP at 0x00BC72 (`LD SP,IX` where IX=pointer from linked list), it corrupts the stack pointer. The SP clamp in cpu-runtime.js catches and fixes this, but the root cause is either:
1. A missing init routine that should write a REAL 3-byte linked-list pointer to 0xD14095-0xD14097 before 0x00BC47 runs
2. IX at 0x00BC47 is offset wrong (pointing to flags instead of the actual struct)

## Task
Create a probe script `TI-84_Plus_CE/probe-phase366-linked-list-init.mjs` that searches the ROM for:

1. **24-bit writes to 0xD14095** — Look for:
   - `LD (0xD14095), HL` = opcode patterns that store HL to absolute address 0xD14095
   - `LD (nn), HL` where nn = 0xD14095 (opcode 0x22 followed by 0x95 0x40 0xD1 in ADL mode, or ED 63 for non-ADL)
   - LDIR/LDDR block copies that cover this address range
   
2. **All ROM references to 0xD14095, 0xD14096, 0xD14097** — Search for the byte pattern 0x95 0x40 0xD1 (little-endian 0xD14095) in the ROM:
   ```javascript
   for (let i = 0; i < rom.length - 2; i++) {
     if (rom[i] === 0x95 && rom[i+1] === 0x40 && rom[i+2] === 0xD1) {
       // Found reference to 0xD14095
     }
   }
   ```
   Similarly for 0xD14096 (0x96,0x40,0xD1) and 0xD14097 (0x97,0x40,0xD1).

3. **Cross-reference with 0x05D4BB** — Session 365 noted that 0xD14096 has only 1 reference in the entire ROM at 0x05D4BB. Disassemble 10-20 instructions around 0x05D4BB to understand what it does. Is it the missing pointer initializer?

4. **Check if 0x00BC47 block is in the seed list** — Read `TI-84_Plus_CE/phase200-seeds.txt` and check whether 0x00BC47 is seeded. Also check if 0x05D4BB is seeded.

5. **Analyze the IX context at 0x00BC47** — What value should IX have? If IX = 0xD1A860 (home-screen stage entry from handoff notes), then (IX-30) = 0xD1A842, NOT 0xD14095. So either IX changes between init and when 0x00BC47 runs, or there are multiple call sites for the linked-list walker with different IX values.
