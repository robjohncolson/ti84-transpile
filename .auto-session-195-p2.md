# Auto-Session 195 P2: STAT BC Backward Trace + Extended Steps

## Context
In the TI-84 Plus CE ROM transpilation project, we're tracing the STAT 1-Var Stats handler. Session 194 found that with seeded list data (L1={1.0,2.0,3.0}), STAT execution reaches 264 unique blocks in 5000 steps (3× improvement over unseeded). The LDDR at 0x092263 has BC=0x00EAF5 (60,149) — still garbage, but the low bytes 0xEAF5 are identical between seeded and unseeded runs, suggesting a specific OS variable sets the count.

The LDDR block itself works perfectly (BC=3 bypass confirmed in session 194). The problem is BC initialization before LDDR.

## Task
Build a probe file `TI-84_Plus_CE/probe-phase195-stat-bc-trace.mjs` with three experiments:

### Experiment A: Backward trace from LDDR — find the LD BC instruction
Trace execution from 0x058BA9 (STAT entry) with seeded list data (same seeding as session 194). At EVERY step, log the BC register value. When BC changes, record:
- The block PC where the change happened
- The instruction that changed it (if identifiable from block address)
- Previous and new BC value

Seeding (copy from session 194 pattern):
- L1 data at 0xD10000: three FP reals {1.0, 2.0, 3.0} in TI BCD format (9 bytes each)
  - 1.0 = [0x00, 0x80, 0x10, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]
  - 2.0 = [0x00, 0x80, 0x20, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]
  - 3.0 = [0x00, 0x80, 0x30, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]
- VAT entry at 0xD1A800: type=0x01 (real list), name bytes for L1
- Allocator pointers: seed the same way session 194 did (check `probe-phase194-stat-seeded-lists.mjs` for exact addresses)

Step limit: 5000. Log BC at every step.

### Experiment B: Extended step limit (10000 steps)
Same seeded setup as A but run for 10000 steps. Record:
- Total unique blocks
- Whether any blocks in the STAT calculation area (0x091E00-0x092FFF) are reached beyond what 5000 steps showed
- Final state: BC, DE, HL, SP, PC, OP1, OP2

### Experiment C: Trace backward from 0x092263 statically
Read the transpiled blocks database. Starting from block 0x092263, find all blocks that JUMP/CALL to it. For each predecessor block, check if it contains a `LD BC,<value>` instruction. This is a static analysis — no CPU execution needed. List all predecessor blocks and whether they set BC.
