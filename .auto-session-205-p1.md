# Auto-Session 205 — P1: Trace cxMain digit path (class=0) to BufInsert

## Context

In the TI-84 Plus CE ROM transpilation project, we've decoded a TWO-LEVEL key dispatch architecture:
- **Level 1** (Copy9/KeyClassifier at 0x058483): routes ALL keys including digits through 0x09927F which crashes via JError
- **Level 2** (cxMain at 0x0585E9): reached via JP (HL) at 0x0585D3. Does `CP 0x05` → class≠5 → `JP 0x05877A` → cascading CP 3/4/2/1 → class 0 (digits) falls through ALL comparisons to 0x0587E0 → `JP NZ,0x0589E5`

The hypothesis is that Level 2 (cxMain) is the REAL digit path that reaches BufInsert(0x05E2A0) without touching 0x09927F. We need to trace it.

## Task

Build a probe `TI-84_Plus_CE/probe-phase205-cxmain-digit-trace.mjs` that:

1. Boots the transpiled runtime (same pattern as existing probes — see `probe-phase204-coormon-digit-classify.mjs` for reference)
2. Sets up entry at **0x0585E9** (cxMain) with:
   - A = 0x00 (class value for digits, returned by KeyClassifier as OP1[0]&0x3F)
   - Set OP1 at 0xD005F8 to a digit-4 token structure: `[0x00, 0x34, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]`
   - IX = 0xD1A860 (standard home-screen IX)
   - IY = 0xD00080 (standard IY base for flag bytes)
   - SP = 0xD1A860
   - Set BIT 7,(IY+12) CLEAR (so we're testing Level 2 path)
   - Set the edit buffer cursor at 0xD00A00 (standard edit buffer start), with cursor pointer at appropriate RAM address
3. Traces execution for up to **5000 steps**, logging:
   - Every unique block visited (address)
   - Whether 0x05877A is reached (the class-0 handler)
   - Whether 0x0587E0 is reached (the fall-through point)
   - Whether 0x0589E5 is reached (the JP NZ target for digits)
   - Whether **0x05E2A0** (BufInsert) is reached — THIS IS THE KEY QUESTION
   - Whether 0x09927F is reached (should NOT be reached in Level 2)
   - The final state of the edit buffer at 0xD00A00-0xD00A10
4. Also run a second experiment with A = 0x01 (class 1 = operators like +) to compare paths
