# Task: Trace D14017 Master Pool Source

## Context
In the TI-84 CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, session 425 discovered that D14017 is the master source for descriptor table bases:
- 0x00E383 copies D14017 → D13FD8 (direct copy)
- 0x00E383 copies D14017 + 0x80 → D13FDE (offset copy)
- D14017 has the most references among descriptor-related RAM variables

We need to trace who WRITES to D14017 — is it set during USB init? During slab pool init at 0x00CB29? During boot?

## What to do
1. Create a Node.js probe script `TI-84_Plus_CE/probe-phase426-trace-D14017.mjs` that:
   - Reads the ROM binary at `TI-84_Plus_CE/ROM.rom`.
   - Scans ALL 4MB of ROM for references to address 0xD14017:
     - Direct loads: `LD (0xD14017), A/HL/etc` — look for opcodes with the 3-byte address D14017 (bytes 17 40 D1 in little-endian)
     - Indirect loads via HL: patterns like `LD HL, 0xD14017` (bytes 21 17 40 D1) followed by `LD (HL), <reg>`
     - Increment/shift through nearby addresses D14014-D1401D
   - For each reference found, classify as READ or WRITE.
   - Output: address (hex), instruction type, read/write classification.
2. Also scan for references to D14014 (live context, 13 refs from session 423), D14011 (primary walk target from sibling walker, 22 refs), and D1401A/D1401D/D14020 (slab pool config from 0x00CB29).
3. Identify the WRITE sites — these tell us who initializes D14017. Focus on:
   - Boot-time initialization (addresses < 0x002000)
   - USB init code (0x006E00-0x007700, 0x00C900-0x00CC00)
   - Slab pool init at 0x00CB29
   - Descriptor init at 0x00E383
4. Write a report `TI-84_Plus_CE/phase426-D14017-trace-report.md` summarizing:
   - Total READ vs WRITE reference counts for D14017
   - Which functions write D14017 (the initialization chain)
   - The initialization order: does D14017 get written before or after slab pool init?
   - Connection to the slab allocator: does the alloc function (0x00E06D) write D14017?
