# Task (ppp): Trace 0x02FD99 — Event Loop Re-entry Point

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM (eZ80 machine code) has been lifted to JavaScript. You write probes that execute lifted ROM blocks and trace execution paths.

The OS key event dispatcher lives at 0x02FD8F. When a key is processed, the final convergence gate at 0x02FFED does `OR A; JP NZ,0x02FE84; JP 0x02FD99`. When A=0x00 (no key / key consumed), execution jumps to 0x02FD99 — the event loop re-entry point.

**Session 233** decoded 0x02FD8F as the key-event dispatcher entry. It does: RES 3,(IY+40), LD A,0xCC→(D00000), LD A,0x1A, BIT 0,(IY+52) gate→CALL 0x02390A, CALL 0x03013A (key scan), CALL 0x05C76C, CALL 0x03FA09. Then OR A tests key code, JP NZ→0x02FE89 (key processing).

**Question**: What happens between 0x02FD99 and 0x02FD8F? Is 0x02FD99 == 0x02FD8F (direct loop-back)? Or are there intermediate blocks that do housekeeping (display update, cursor blink, timer check) before re-entering the dispatcher?

## Deliverables
Create `TI-84_Plus_CE/probe-phase236-02fd99-event-loop-reentry.mjs` that:

1. Boots the system (ROM load, transpiled JS load, memory init, MBASE=0xD0, IY=0xD00080, timer IRQ disabled)
2. Seeds: SP=0xD1A87E, return sentinel=0x7FFFFE on stack
3. Enters at 0x02FD99 with A=0x00 (simulating "no key" return from 0x02FFED)
4. Steps up to 500 steps, recording every unique block visited
5. Checks: does execution reach 0x02FD8F? If so, how many blocks between 0x02FD99 and 0x02FD8F?
6. Records any RAM writes (especially IY flag changes, D0058E, D00000)
7. Dumps the block chain from 0x02FD99 back to 0x02FD8F (or wherever it ends up)
8. Reports: is 0x02FD99 the SAME block as 0x02FD8F, or a different entry?

Also: disassemble ROM bytes at 0x02FD8F-0x02FDA0 and 0x02FD99-0x02FDA0 to check if 0x02FD99 is mid-block or a distinct block entry.
