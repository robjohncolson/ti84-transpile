# Session 457 P3: Investigate Why Timer Service 0x001ACF Gets 0 Visits

## Context
You are working on a TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The OS ROM is lifted to JavaScript and executed in Node.js probes.

## Problem
Session 456 fixed the ED 6D/6E/7D/7E decoder bug. Now the IRQ dispatch path is correct:
```
0x000038 → 0x0006F3 (reads port 0x06=0xD0 MBASE)
→ 0x000704 (SET 6,(IY+0x1B))
→ 0x000710 (LD HL,(D02AD7))
→ 0x001713 (_GetCSC)
→ 0x0008BB → 0x0067F8 → timer area 0x001C4F-0x001CE5
→ 0x006810-0x006828 → 0x001727 → returns to 0x000719
→ 0x02010C → key processing area 0x03CF7D-0x03D054
```

But the timer service at 0x001ACF STILL gets 0 visits despite 8997 IRQ vector visits. The IRQ goes through _GetCSC → event loop code but never branches to 0x001ACF.

Session 443 mapped the timer service: it acknowledges FTINTC byte0 bit4 via port 0x5008 and decrements D02658+D02651. The question is: what condition would cause the IRQ handler to branch to 0x001ACF?
