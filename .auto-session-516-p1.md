# Task: Trace 0x07CFA7 Standard Text Renderer End-to-End

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is lifted to JavaScript. We've verified the rasterizer at 0x0A1799 works (668 steps, 312 VRAM bytes for glyph 'A'). Now we need to test the HIGHER-LEVEL renderer 0x07CFA7 which calls through 0x07C8B7 (BCD position calc) → 0x0A1799 (rasterizer).

The rendering chain is: 0x07D1B4 (walker) → 0x07D233 (filter) → 0x07CFA7 (standard text) → 0x07C8B7 (BCD calc) → 0x0A1799 (rasterizer).

Session 515's probe-phase515-rendering-chain.mjs tested 0x0A1799 directly. This task tests 0x07CFA7, one level up.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase516-trace-07CFA7.mjs` that:

1. Boots the transpiled ROM (same pattern as existing probes — see `TI-84_Plus_CE/probe-phase515-rendering-chain.mjs` for the import/boot pattern)
2. Seeds the descriptor area at D005F8 with a valid text descriptor (type byte + glyph code for 'A' = 0x41)
3. Seeds cursor position state: curRow and curCol at known RAM locations (check probe-phase515 for what it used — it set curRow=0, curCol=0 at specific RAM addrs)
4. Calls 0x07CFA7 via `cpu.callFunction(0x07CFA7)` or equivalent stepping
5. Checks:
   - Did it return cleanly (not infinite loop)?
   - How many steps did it take?
   - Are there non-zero VRAM bytes? Where?
   - Were curRow/curCol updated (cursor advancement is caller's job per session 515, but 0x07CFA7 might advance them since it's higher-level)?

## Key addresses from prior sessions
- D005F8 = descriptor type byte
- D005F9 = glyph code (or part of descriptor)
- 0x07CFA7 = standard text renderer entry
- 0x07C8B7 = BCD position calculator (called by 0x07CFA7)
- 0x0A1799 = rasterizer (called by 0x07C8B7)
- VRAM base = 0xD40000 (320×240×2 bytes, 16-bit color)
- Font atlas at ROM ~0x000400 region (28 bytes per glyph, 16×14 bitmap)
