# Task: Test 0x027111/0x027123 with delay stub active (priority 14ccc)

## Context
In the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`, session 263 added a delay stub for 0x006202 (a pure delay loop that takes ~35K iterations / ~215K steps per call). The screen-redraw routines at 0x027111 and 0x027123 call 0x0003B0 which calls 0x006202 up to 6 times. Previously these routines were effectively untestable because they'd burn hundreds of thousands of steps in pure delays.

Session 245 traced 0x027111/0x027123 and found:
- 0x027111: clears D02A86 to 0, calls 0x0003B0 + 0x0270F3, BIT 6,(IY+27) → RET NZ, else falls into 0x027123
- 0x027123: saves display state (D026AC/D02AC0), DI, selects timer constant (0xFC64/0xC618/0xF800) → stores to D026AC, calls 0x02672F (LCD drawing) 3+ times, restores state, RET at 0x0271C2

Now that 0x006202 is stubbed (it should complete in very few steps instead of 35K), we can trace these routines to completion and understand what they actually do to VRAM and display state.

## Task
Create a probe `TI-84_Plus_CE/probe-phase265-redraw-delay-stubbed.mjs` that:

1. Sets up the CPU with standard boot state (or minimal state sufficient for these routines).
2. Verifies that the delay stub at 0x006202 is active by running PC=0x006202 for 100 steps and confirming it returns quickly (should be <50 steps with stub, vs ~35K without).
3. Tests 0x027111:
   - Set PC = 0x027111, appropriate SP, IX=0xD1A860
   - Seed D02A86 = 0x02 (non-zero, so the routine has work to do)
   - Set IY+27 bit 6 = 0 (CLEAR, so it falls through to 0x027123 instead of early-returning)
   - Run for up to 20,000 steps (should be feasible now with delay stub)
   - Track: total steps to RET, unique blocks visited, VRAM changes (sample D40000-D40100 before/after), display state changes (D026AC, D02AC0, D02A86), IY flag changes
4. Tests 0x027123 standalone:
   - Same setup but PC = 0x027123
   - Run for up to 20,000 steps
   - Track same metrics
5. Tests 0x027111 with IY+27 bit 6 SET (should RET NZ early, confirm)
6. Report whether these routines complete successfully, what display state they modify, and how many steps they take with the delay stub vs the previous estimate of 215K+.
