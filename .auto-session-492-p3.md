# Task: Trace Cursor Blink End-to-End in OS Event Loop

## Context
This is the TI-84 Plus CE ROM transpilation project. We've decoded the cursor ERASE mechanism (0x061000 = clear-to-screen-bottom) and found a cursor DRAW candidate (0x06029D = writes 182 black pixels in cursor-sized region). But we haven't traced the full cursor blink path from the OS event loop.

The OS idle loop enters cursor blink at 0x03030E. From session 487: the call chain is 0x03030E → 0x03031A → ... → 0x03013A → 0x030173 → 0x030202 → 0x0A23C0 → 0x0A239E. But that chain was confirmed as the STATUS BAR indicator, not text cursor.

The text cursor must be triggered from a DIFFERENT branch of the event loop (possibly different flag bits at 0x03030E), or from a different entry point entirely.

## What to do

Create a probe `TI-84_Plus_CE/probe-phase492-trace-cursor-blink.mjs` that:

### Part 1: Trace from 0x03030E with cursor flags set for "draw cursor"
The OS event loop at 0x03030E reads flag bytes to decide what to render. We need to find which flag combination triggers the text cursor draw (as opposed to status bar).

Key memory locations:
- D00080 / D00082: OS flags (various display modes)
- D00092: cursor flags
- D00595: cursor row
- D00596: cursor col
- IY typically points to D00080 or nearby flag block

Strategy: Boot the CPU (120,000 steps, timer disabled). Then:
1. Set D00595=3, D00596=10 (cursor in middle of screen)
2. Set D00092 to various cursor flag values (try 0x01, 0x02, 0x04, 0x08, 0x0F, 0xFF) 
3. For each flag value, set PC=0x03030E, SP=0xD1A87E, push return sentinel
4. Run up to 30,000 steps
5. Log which addresses in 0x060000-0x062000 range are visited (track unique PCs)
6. Check if 0x06029D or 0x061000 is reached
7. Snapshot VRAM before/after and check for cursor-position-dependent writes

### Part 2: Direct trace of the call chain from 0x03030E
Instead of just checking endpoints, trace the FULL call chain. For each step, if PC is a CALL instruction, log the target. Build a call tree (up to depth 10) showing which functions get called from 0x03030E.

Specifically look for branches: the first few instructions at 0x03030E likely test flag bits (BIT n,(IY+d) or BIT n,(HL)) and branch to different handlers. Map out which bit/flag leads to which handler.

### Part 3: Search for alternate event loop entries
The cursor blink might not come from 0x03030E at all. Search the ROM for:
- Direct calls to 0x06029D (CD 9D 02 06, or with mode prefix)
- Direct calls to 0x061000 (CD 00 10 06, or with mode prefix)  
- Direct calls to 0x061003 (CD 03 10 06 — session 491 says 0x061003 is called from 0x060FC3 and 0x06104E)

Report all callers. Then trace one level up: who calls THOSE callers? This builds the path from the event loop down to the cursor functions.

### Part 4: Disassemble 0x03030E entry
Read ROM bytes at 0x03030E and disassemble the first 30-40 instructions. Look for:
- BIT tests on IY+offset (cursor visibility flags)
- Conditional jumps to different rendering handlers
- References to 0x060xxx range (text cursor functions)
- References to 0x030xxx range (status bar — already known)

## API

```js
import fs from 'node:fs';
import { execFileSync } from 'node:child_process';
import { fileURLToPath } from 'node:url';
import zlib from 'node:zlib';

function ensureTranspiledRom() {
  const transpiled = new URL('./ROM.transpiled.js', import.meta.url);
  const gz = new URL('./ROM.transpiled.js.gz', import.meta.url);
  if (fs.existsSync(transpiled) || !fs.existsSync(gz)) return;
  console.log('ROM.transpiled.js missing; expanding ROM.transpiled.js.gz');
  try {
    execFileSync('gzip', ['-dk', fileURLToPath(gz)], {
      cwd: fileURLToPath(new URL('.', import.meta.url)),
      stdio: 'inherit',
    });
  } catch (error) {
    console.log(`gzip failed (${error.message}); falling back to node:zlib`);
    fs.writeFileSync(transpiled, zlib.gunzipSync(fs.readFileSync(gz)));
  }
}

ensureTranspiledRom();

const { createCPU } = await import('./cpu-runtime.js');
const { createPeripheralBus } = await import('./peripherals.js');
```

## Constraints
- Do NOT modify any existing files. Create ONLY `TI-84_Plus_CE/probe-phase492-trace-cursor-blink.mjs`.
- Must be runnable via `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase492-trace-cursor-blink.mjs`
- Print all findings to stdout.
- Use `process.exit(0)` at the end.
- Boot steps: 120,000 with timer disabled. Per-test max: 30,000 steps.

## Success criterion
The probe identifies: (1) which flag bits at 0x03030E trigger cursor draw vs status bar, (2) the full call chain from event loop to cursor functions, (3) whether 0x06029D and 0x061000 are reachable from the event loop and through what path. This maps the complete cursor blink mechanism.
