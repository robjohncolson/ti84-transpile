# Task: Trace D1407B (most co-accessed USB state byte)

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). We are tracing USB state variables in the D14070-D1407F USB state block.

D1407B is the **most co-accessed variable** in the pipe state group:
- 10/17 D1407C (pipe-pending) references co-access D1407B
- 5/28 D1407E (pipe-active) references co-access D1407B
- Session 439 noted: at 0x0097BC, "If D1407C is clear, the code sets D1407B=1, zeroes D14038, and then acknowledges port 0x313D"
- Session 439 noted: at 0x009892, "If D1407B is already set or D1407C is set, the fall-through clears D1407E, D17796, and D140B2"

Already mapped nearby:
- D1407C: pipe-pending flag (boolean, 17 refs)
- D1407D: co-written with D1407C at pipe-initiation
- D1407E: pipe-active flag (boolean, 28 refs)
- D14038: co-accessed with D1407B (threshold/counter?)

## Your task
Create a probe script at `TI-84_Plus_CE/probe-phase440-trace-D1407B.mjs` and a report at `TI-84_Plus_CE/phase440-trace-D1407B-report.md`.

### Methodology (follow exactly — see `TI-84_Plus_CE/probe-phase439-trace-D1407C.mjs` for the template)

1. **Find all ROM references** to address D1407B by scanning for the 3-byte little-endian pattern `[0x7B, 0x40, 0xD1]` in the ROM.
2. **For each reference site**, decode:
   - What instruction accesses D1407B (LD A,(D1407B), LD (D1407B),A, XOR A + LD (D1407B),A, etc.)
   - Whether it's a READ or WRITE
   - What value is written (if write): 0x00 via XOR A? 0x01 via LD A,0x01? Something else?
   - What condition gates the access (CP/JR Z/JR NZ before or after)
   - What nearby D140xx bytes are co-accessed within ±20 bytes
   - What nearby port I/O (IN/OUT with 0x30xx/0x31xx ports) happens within ±32 bytes
3. **Classify the variable**: boolean (0/1)? enum (multi-value)? counter? bitmask?
4. **Identify the containing function** for each site (scan backward for function prologue: PUSH AF/IX/IY or `__frameset` CALL 0x00218A/0x002197)
5. **Note dual-banking**: references in 0x00xxxx, 0x02xxxx, 0x04xxxx, 0x0Bxxxx are mirrors of the same logical function

### Output format
The probe script should:
- Read ROM.rom
- Scan for all `[0x7B, 0x40, 0xD1]` occurrences
- For each site: print address, read/write, value, nearby co-accessed D140xx bytes, nearby port I/O
- Print summary statistics (total refs, read count, write count, unique values written)
- Write a markdown report to `phase440-trace-D1407B-report.md`

The report should contain:
- Total reference count (reads vs writes)
- Classification (boolean/enum/counter/bitmask)
- All write values observed
- All read patterns (how reads are used — OR A + JR Z? CP N? etc.)
- Co-access summary (which D140xx bytes appear most often nearby)
- Port I/O summary
- Relationship to pipe-pending (D1407C) and pipe-active (D1407E) state machines
- Suggested semantic name (e.g., `usb_PipeXxx`)

### Constraints
- Do NOT modify any existing files
- Do NOT run the transpiler or modify ROM.transpiled.js
- The probe is a standalone Node.js ESM script (import fs, path, url)
- Use `#!/usr/bin/env node` shebang
- The ROM is raw binary — no headers, byte 0 = address 0x000000
- eZ80 uses 3-byte (24-bit) addresses in little-endian format
- Watch for eZ80 mode prefixes before instructions: 0x40=SIS, 0x49=LIS, 0x52=SIL, 0x5B=LIL
