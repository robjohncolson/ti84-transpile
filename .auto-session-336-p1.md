# Auto-session 336 — Priority (a): Populate cxMain during boot

## Goal
Trace the code path from kernel init (0x08C331) to the site at 0x08C8D0 that loads 0x058241 (home handler) into HL. Determine what branch condition prevents this path from executing during our staged boot. Then create a probe that either:
1. Patches the branch so the natural boot path populates cxMain, OR
2. Manually writes cxMain (0xD007CA) = 0x058241 after boot but before the event loop

## Context
- cxMain is a 3-byte pointer at RAM address 0xD007CA
- The home-screen handler is at ROM address 0x058241
- cxPPG is at 0xD007D0 (paired handler — find what value goes there from the same code site)
- Kernel init entry: 0x08C331
- The site 0x08C8D0 was found by session 335's cxMain probe — it does `LD HL, 0x058241` near kernel init, but on an untaken path
- Event loop entry (CoorMon): 0x08BF22 — this reads cxMain to dispatch
- ROM file: `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary, little-endian)

## Existing probe to reference
Read `TI-84_Plus_CE/probe-phase335-cxmain.mjs` for the boot harness pattern, memory layout, executor creation, and how probes are structured in this project.

## Deliverables
Create `TI-84_Plus_CE/probe-phase336-cxmain-boot.mjs` that:
1. Boots normally (0x000000 → kernel init 0x08C331) with timerInterrupt: false
2. Disassembles the code around 0x08C8D0 (±50 bytes) to find the branch that gates it
3. Traces backwards from 0x08C8D0 to find the conditional jump that skips this path
4. Reports: the branch instruction address, what condition it checks, what RAM/flag state would take the branch
5. Tests approach: after boot completes, manually write cxMain = 0x058241 at 0xD007CA, then run ONE iteration of CoorMon (0x08BF22) and check if it dispatches to the home handler (PC reaches 0x058241 or vicinity)
6. Also check what value should go at cxPPG (0xD007D0) — look at the data table near 0x08C8D0 for paired entries

## Key files

## Constraints
- Do NOT modify cpu-runtime.js, peripherals.js, ez80-decoder.js, or the transpiler
- Do NOT modify any existing probe files
- Create ONLY the new probe file
- Use `createPeripheralBus({ timerInterrupt: false })` — timer IRQ causes infinite loops
- The probe must be runnable with `node TI-84_Plus_CE/probe-phase336-cxmain-boot.mjs`
- Use ES module syntax (import/export), not require()
- Follow the exact boilerplate pattern from probe-phase335-cxmain.mjs

## Success criterion
The probe runs without errors and reports:
- The disassembly around 0x08C8D0 showing the branch
- Whether manually writing cxMain=0x058241 causes CoorMon to dispatch to the home handler
- What value cxPPG should hold
