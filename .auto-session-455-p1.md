# Auto-Session 455 P1: Enable Timer Interrupt for Polling Loop Exit

## Context
The TI-84 Plus CE ROM transpilation project lifts eZ80 machine code into runnable JavaScript. The OS event loop at 0x003A73 calls _GetCSC which enters a polling loop at 0x003D6B. Session 454 proved definitively that this polling loop is INFINITE without timer interrupts — 1.2M steps still stuck at 0x003D6B with 1,001,306 visits.

The timer ISR path is fully mapped:
- IM 1 mode: ALL maskable interrupts enter at 0x000038
- 0x000038 → saves shadow regs + IX/IY, loads IY=0xD00080, JP 0x0006F3
- 0x0006F3 → generic front-end → timer service at 0x001ACF
- 0x001ACF → acknowledges FTINTC byte0 bit4 via port 0x5008, decrements D02658 (24-bit) + D02651 (8-bit), EI + RETI
- RETI returns to wherever execution was interrupted (the polling loop)

The DI+HALT barrier is at 0x001933-0x001942 in the event loop wrapper.

## Task
Create a probe file `TI-84_Plus_CE/probe-phase455-timer-irq-exit.mjs` that:

1. Boots to home screen using the EXACT same boot sequence as `probe-phase454-1200k-budget.mjs` (copy it verbatim — boot entry, kernel init, post init, 4 stages, flash routine pre-copy, CPU state reset)
2. Creates the peripheral bus WITH `timerInterrupt: true` (this is the key change)
3. Sets up key processing: `mem[0xD14091] = 1` (key processing enable), `mem[0xD177B7] = 0x55` (display dirty)
4. Injects key "1" (scan code 0x12) via `mem[0xD00587] = 0x12; mem[0xD00080] |= 0x08`
5. Runs from EVENT_LOOP_ENTRY (0x003A73) with a generous step budget (2,000,000 steps), `maxLoopIterations: 50000`
6. Uses `onBlock` callback to track:
   - Whether 0x000038 (IRQ vector) is visited
   - Whether 0x0006F3 (IRQ front-end) is visited
   - Whether 0x001ACF (timer service) is visited
   - Whether 0x003D6B (polling loop) visit count
   - Whether HALT at 0x001933-0x001942 is reached
   - Whether execution returns PAST the polling loop (PC > 0x003D80)
   - The final PC and step count
7. Prints a structured report showing: IRQ fired (yes/no), polling loop exited (yes/no), HALT reached (yes/no), final PC, total steps, polling loop visits

## Important
- Use `createPeripheralBus({ timerInterrupt: true })` — this is the ONLY change from previous probes that used `timerInterrupt: false`
- Use `diHaltBypass: true` in runFrom options (existing pattern)
- Import pattern: `import { createExecutor } from './cpu-runtime.js'; import { createPeripheralBus } from './peripherals.js';`
- ROM load: `const romBytes = fs.readFileSync(path.join(__dirname, 'ROM.rom'));`
- Transpiled load: `const romModule = await import(pathToFileURL(path.join(__dirname, 'ROM.transpiled.js')).href); const BLOCKS = romModule.PRELIFTED_BLOCKS;`
- The executor is created with: `const { executor, cpu, mem } = createExecutor(romBytes, BLOCKS, { mem: new Uint8Array(MEM_SIZE), peripherals: createPeripheralBus({ timerInterrupt: true }) });`

## Success criteria
- Probe runs without crashing
- Report clearly shows whether the timer IRQ fires and whether the polling loop exits
- If the polling loop exits, shows where execution goes next
