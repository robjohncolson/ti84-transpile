# Task: Trace 0x084E9C→0x084EA7 caller chain

## Context
In the TI-84 Plus CE ROM transpilation project, 0x084EA7 was decoded as a D00824 writer (key code storage). It's reached via `JR Z,0x084EA7` from 0x084E9C — NOT a direct CALL target. We need to find the containing function and understand how register B (the key code) arrives.

Session 223 found: Entry at 0x084EA6 (`LD A,B`), writes `LD (D00824),A` then CP cascade: 0x2B(comma)/0x4A. BIT 7 check on IY+89 (0xD000D9). 16 total D00824 writers found.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase224-084e9c-caller-chain.mjs` that:

1. **Find function boundary**: Read ROM.rom (fs.readFileSync). Scan backward from 0x084E9C looking for a RET/JP/JR boundary to find the function's entry point. Also scan forward from 0x084EA7 past the CP cascade to find where the function ends (RET).

2. **Static disassembly**: Disassemble the full function. Show the complete instruction sequence from entry to all RET points. Focus on:
   - How B is loaded before JR Z to 0x084EA7
   - What the JR Z condition tests (what sets Z flag)
   - All CP branches after D00824 write
   - Sub-calls made within the function

3. **Find callers**: Scan the entire ROM (0x000000-0x0BFFFF) for:
   - `CALL <function_entry>` (CD xx xx xx pattern)
   - `JP <function_entry>` (C3 xx xx xx pattern)
   - `JP cc,<function_entry>` (C2/CA/D2/DA/E2/EA/F2/FA xx xx xx)
   For each caller found, disassemble 20 bytes before the CALL to see how B is set.

4. **Dynamic trace**: Boot runtime with timerInterrupt:false. Set B to various key codes (0x8F for digit-1, 0x70 for +, 0x41 for A) and call the function entry. Trace 100 steps. Log D00824 value after each, and which CP branches are taken.
