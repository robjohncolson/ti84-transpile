# Auto-Session 334 — P3: Verify Font Base Address 0x0040EE vs 0x003D6E

## Context

This is a TI-84 Plus CE ROM transpilation project. Two different font base addresses have been reported:
- **0x0040EE** — found in session 332, confirmed in session 333 ('A' glyph at 0x00448A = 0x0040EE + (0x41-0x20)*28 renders correctly as letter A in 16×14 1bpp)
- **0x003D6E** — earlier assumption from prior sessions

We need to definitively confirm which is the authoritative main font table base, or whether both exist as different font tables (e.g., small font vs large font, or homescreen font vs graph font).

## Your task

Write a probe file `TI-84_Plus_CE/probe-phase334-font-verify.mjs` that compares both font tables.

### Steps

1. **Boot normally**:
   ```javascript
   import { createExecutor, createMemoryBus, createPeripheralBus, helpers } from './cpu-runtime.js';
   import fs from 'fs';
   const { hex } = helpers;
   const rom = fs.readFileSync(new URL('./ROM.rom', import.meta.url));
   const mem = createMemoryBus(rom);
   const periph = createPeripheralBus({ timerInterrupt: false });
   const executor = createExecutor(mem, periph);
   ```
   Run KERNEL_INIT: `executor.runFrom(0x08C331, { mode: 'adl', maxSteps: 100000 })`

2. **Dump both font tables for printable ASCII (0x20-0x7E)**:
   
   For **base 0x0040EE** (28 bytes per glyph, session 332/333 finding):
   - For characters 0x20 (space), 0x30 ('0'), 0x41 ('A'), 0x42 ('B'), 0x61 ('a'), 0x7E ('~'):
     - Address = 0x0040EE + (charCode - 0x20) * 28
     - Read 28 bytes at that address from ROM
     - Render as a 16×14 1bpp bitmap (2 bytes per row × 14 rows = 28 bytes, MSB-first)
     - Print the bitmap to stdout using '#' for set pixels and '.' for unset

   For **base 0x003D6E** (try both 28 bytes/glyph and other sizes):
   - Same characters
   - Try stride 28: address = 0x003D6E + (charCode - 0x20) * 28
   - Read 28 bytes, render as 16×14 1bpp
   - ALSO try stride 12 (8×12 font): address = 0x003D6E + (charCode - 0x20) * 12, render as 8×12 (1 byte per row × 12 rows)
   - ALSO try stride 16 (8×16 font): similar

3. **Check font descriptor tables**:
   - Session 330 decoded a font descriptor table. Read memory at these addresses after boot to see what the OS thinks the font base is:
     - 0xD005E9 + offsets (DrawChar vtable)
     - Any RAM location that stores font table pointers
   - Read 16 bytes at 0xD02680-0xD0268F (font/draw state area) and log them

4. **Verify 'A' explicitly at both bases**:
   - 0x0040EE + (0x41 - 0x20) * 28 = 0x0040EE + 33 * 28 = 0x0040EE + 924 = 0x00448A
   - 0x003D6E + (0x41 - 0x20) * 28 = 0x003D6E + 924 = 0x00410A
   - Dump both and compare visually

5. **Report conclusion**: Which base produces recognizable ASCII glyphs? Are they different font sizes? Is one for the home screen and the other for menus/graph?
