# Task: Decode 0x0987B5 and 0x0987B7 — Type-Specific Initializers

## Context
In the TI-84 Plus CE OS ROM (`TI-84_Plus_CE/ROM.rom`), address 0x0987B5 is called by the type-dispatch cascade at 0x097AC8 (session 522). Specifically:
- Type 0x20 (appvar) at 0x097B33: `CALL 0x0987B5`
- Type 0x21 (group) at 0x097B3F: `CALL 0x0987B5`
- Type 0x1C (prot program) at 0x097B4B: `LD A,0x1A` then `CALL 0x0987B7` (entry +2 bytes)

0x0987B5 and 0x0987B7 are type-specific initializers for the edit-buffer system. We need to decode what they do.

## Deliverable
Create `TI-84_Plus_CE/probe-phase523-decode-0987B5-type-init.mjs` that:
1. Reads ROM bytes starting at 0x0987B5 for ~200 bytes
2. Disassembles the eZ80 instructions (ADL mode, 24-bit addresses)
3. Documents what 0x0987B5 does (entry point) and what 0x0987B7 does (alternate entry +2)
4. Identifies all CALLs, JPs, memory reads/writes (especially RAM addresses D0xxxx)
5. Prints a structured analysis

## How to read ROM bytes
```javascript
import { readFileSync } from 'fs';
const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
// Read byte at address: rom[address]
// Read 24-bit LE value: rom[addr] | (rom[addr+1] << 8) | (rom[addr+2] << 16)
```

## eZ80 ADL mode reference
- All addresses are 24-bit (3 bytes LE) in ADL mode
- CALL nn = 0xCD nn[2:0] (3-byte address)
- JP nn = 0xC3 nn[2:0]
- LD r,(nn) / LD (nn),r use 3-byte addresses
- RET = 0xC9, RET Z = 0xC8, RET NZ = 0xC0, RET C = 0xD8, RET NC = 0xD0
- JR e = 0x18 e (signed offset from PC+2)
- JR Z,e = 0x28 e, JR NZ,e = 0x20 e, JR C,e = 0x38 e, JR NC,e = 0x30 e
- CP n = 0xFE n
- LD A,n = 0x3E n
- LD HL,nn = 0x21 nn[2:0], LD DE,nn = 0x11 nn[2:0], LD BC,nn = 0x01 nn[2:0]
- PUSH AF = 0xF5, POP AF = 0xF1
- OR A = 0xB7, XOR A = 0xAF
- BIT b,r uses CB prefix
- LD A,(HL) = 0x7E, LD (HL),A = 0x77
- INC HL = 0x23, DEC HL = 0x2B
- RST 0x28 = 0xEF (used for bcall)
