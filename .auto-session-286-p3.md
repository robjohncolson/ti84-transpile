# Auto-Session 286 — P3: Investigate 0x048AC4 Keyboard RAM Initializer

## Context
Session 285 found that 0x02FCB3 (the deep event-service wrapper) calls into a chain that reaches 0x048AC4, identified as a "keyboard RAM initializer." We need to understand what RAM it zeroes/inits and how it fits into the keyboard subsystem.

## Task
Create a probe `TI-84_Plus_CE/probe-phase286-048ac4-kbd-ram-init.mjs` that:

1. **Static disassembly** of 0x048AC4 — decode at least 100 bytes. Look for:
   - XOR A / LD (addr),A patterns (zeroing RAM)
   - LD HL,addr / LD BC,count / LDIR patterns (block zero/copy)
   - What RAM addresses are written (D0xxxx range = OS RAM)
   - Any keyboard-related constants (matrix addresses, scan codes)

2. **Dynamic trace** — Set PC=0x048AC4, SP=0xD1A87E (normal OS stack). Run 150 steps. Log ALL memory writes (address + value). This is the key output — we want to see which RAM locations get initialized.

3. **RAM write summary** — After the trace, categorize all written addresses:
   - Group by address range (D005xx, D006xx, D007xx, etc.)
   - Count writes per range
   - Identify which addresses match known keyboard RAM (D0058C, D0058E from session 285's event-service analysis)

4. **Cross-reference** — Find all callers of 0x048AC4 in the ROM. Search for CALL 0x048AC4 pattern (CD C4 8A 04 in little-endian, or search ROM.transpiled.js for references to 048AC4).
