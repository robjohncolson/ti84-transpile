# Task: Decode D0059C Usage in Cursor Blink Event Loop Path

## Context

The TI-84 Plus CE ROM transpilation project has proven that D0059C is a 16-bit scratch variable used by the character renderer at 0x005A75 to store the column pixel value. The `.SIS LD (0x059C),HL` at 0x005AB0 stores only 16 bits (column pixel).

However, session 480 found 46 ROM references to D0059C (22 reads, 24 writes). The cursor blink path at 0x030173 also uses D0059C. The question: does 0x030173's rendering pipeline compute cursor position from D00595/D00596 (like the character renderer), or does it read D0059C as a pre-set input for cursor VRAM location?

## Goal

Create a probe that answers: **How does the cursor blink path at 0x030173 determine cursor VRAM position?**

Two hypotheses:
1. It reads D0059C as the VRAM address for cursor position (set by the last character render)
2. It independently computes VRAM address from D00595/D00596

## Implementation

Create file: `TI-84_Plus_CE/probe-phase486-d0059c-cursor-usage.mjs`

The probe should run 4 experiments to distinguish between the hypotheses:

### Experiment 1: Default cursor position
- 3-stage boot (same as reference probes)
- Set D00000=0x00 (idle), D00092=0x16, D000C6|=0x01, D00089|=0x10
- Set D00595=0, D00596=0 (row 0, col 0)
- Set D0059C to expectedVramAddress(0,0) = 0xD40000 + 37*640 + 2*2 = 0xD40000 + 23680 + 4 = 0xD45C84
  - Actually compute: (0*20+37)*640 + (0*12+2)*2 = 37*640 + 4 = 23684 = 0x5C84, so VRAM addr = 0xD45C84
- Run idle loop (5 iterations at 0x02FDBE, intercept at 0x02FE21)
- Record VRAM changes + first/last addresses

### Experiment 2: Move cursor via D00595/D00596 ONLY (keep D0059C at row 0 col 0)
- Re-initialize VRAM to 0xFF
- Set D00595=5, D00596=13 (row 5, col 13)
- Set D0059C to expectedVramAddress(0,0) = 0xD45C84 (WRONG for row 5 col 13)
- Set D00092=0x16, D000C6|=0x01, D00089|=0x10, D00000=0x00
- Run idle loop
- Record VRAM changes

### Experiment 3: Move cursor via D0059C ONLY (keep D00595/D00596 at 0,0)
- Re-initialize VRAM to 0xFF
- Set D00595=0, D00596=0
- Set D0059C to expectedVramAddress(5,13) = 0xD40000 + (5*20+37)*640 + (13*12+2)*2 = 0xD40000 + 137*640 + 158*2 = 0xD40000 + 87680 + 316 = 0xD55C7C (compute exactly)
  - (5*20+37) = 137; 137*640 = 87680 = 0x15680; (13*12+2)*2 = 158*2 = 316 = 0x13C; 0xD40000+0x15680+0x13C = 0xD556BC... let the probe compute this dynamically.
- Set D00092=0x16, D000C6|=0x01, D00089|=0x10, D00000=0x00
- Run idle loop
- Record VRAM changes

### Experiment 4: Both D00595/D00596 and D0059C at row 5 col 13
- Re-initialize VRAM to 0xFF
- Set D00595=5, D00596=13
- Set D0059C to expectedVramAddress(5,13)
- Same flags
- Run idle loop
- Record VRAM changes

### Analysis

Compare VRAM write locations across experiments:
- If Exp 2 cursor appears at row 5 col 13 (matching D00595/D00596, ignoring D0059C) → hypothesis 2 (independent compute)
- If Exp 3 cursor appears at row 5 col 13 (matching D0059C, ignoring D00595/D00596) → hypothesis 1 (reads D0059C)
- If Exp 4 matches Exp 2 → D00595/D00596 are authoritative
- If Exp 4 matches Exp 3 → D0059C is authoritative

### Output

For each experiment print:
- D00595, D00596, D0059C values (before/after)
- VRAM bytes changed
- First changed VRAM address → compute the pixel row/col: `row = (addr - 0xD40000) / 640`, `col = ((addr - 0xD40000) % 640) / 2`
- Whether cursor appeared at (0,0) or (5,13) position

Final: print which hypothesis is confirmed.
