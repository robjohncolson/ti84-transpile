# Task: Trace 0x04EE00 return path — D003E0 writer tail

## Context
In the TI-84 Plus CE ROM transpilation project, the 0x04EDD0 handler returns through 0x04EE0A→0x04EE1B→0x04EE00 at step ~102,297 (session 241). This tail sequence is part of the D003E0 writer function. We need to know:
- Does 0x04EE00 update D003E0 on the way out?
- What does the tail block sequence do?
- Where does execution go after 0x04EE00?

Previous findings (session 220):
- 0x04EE1B is just `JR 0x04EE00` → dead end
- 0x04EE33 is the real D003E0 writer entry: `PUSH AF / CALL 0x052004 / POP BC / LD A,B / JR Z,0x04EE3E / SET 4,A / LD (0xD003E0),A`
- 0x04EE3E writes D003E0

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase242-04ee00-return-path.mjs`

## What the probe must do
1. Import cpu-runtime, peripherals, ROM loader (see existing probes for patterns)
2. Set up warm state with full boot + homescreen stages, IX=0xD1A860, timer IRQ disabled
3. Trigger key press (0x8F) to enter 0x04EDD0 handler
4. Run enough steps to reach the return path (~102K+ steps, or use a targeted breakpoint)
5. When execution enters 0x04EE00-0x04EE3E range, capture:
   - Hex dump of ROM bytes at 0x04EE00-0x04EE40 (disassembly)
   - Register state (A, BC, DE, HL, SP, F flags) at each block entry
   - D003E0 value BEFORE and AFTER passing through this range
   - The final RET destination (where does SP pop to?)
   - Any other RAM writes in this tail sequence
6. Also capture D003E0 value at 5 checkpoints: before key press, after entering 0x04EDD0, mid-fill, at 0x04EE00 entry, after 0x04EE00 exits
