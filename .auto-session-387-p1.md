# Task: Disassemble 0x0301F6 (2ND-Mode Translation Subroutine)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 ADL-mode machine code). We have a static disassembly approach using probes that read ROM bytes and decode eZ80 instructions.

Session 386 found that the 2ND mode key-processing path at 0x02FFF6 calls 0x0301F6 as a dedicated 2ND translation subroutine. This is distinct from the default path's 0x022346 flat table lookup. We need to understand what 0x0301F6 does.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase387-disasm-0301F6.mjs` that:

1. Reads ROM bytes starting at 0x0301F6 and performs static eZ80 ADL-mode disassembly
2. Disassemble at least 0x0301F6 through 0x0302EA (the function before 0x0302EB which is another known entry)
3. Follow all CALL targets within the function to identify sub-calls
4. Identify:
   - Does it use the +56 sub-table at 0x09F7D3 (the 2ND sub-table discovered in session 386)?
   - Does it do a computed lookup or branch on individual scan codes?
   - What special 2ND functions does it handle (2ND+Y= = STAT PLOT, 2ND+0 = CATALOG, etc.)?
   - What RAM addresses does it read/write?

## Reference: probe pattern
Look at existing probes for the pattern. Example structure:
```js
import { readFileSync } from 'fs';
import { createDecoder } from './ez80-decoder.js';

const rom = readFileSync(new URL('./ROM.rom', import.meta.url));
const decoder = createDecoder(rom);

// Linear disassembly from start address
function disasmRange(start, end) {
  let pc = start;
  const results = [];
  while (pc < end) {
    const instr = decoder.decodeAt(pc);
    results.push(instr);
    pc += instr.length;
  }
  return results;
}

const instrs = disasmRange(0x0301F6, 0x0302EA);
for (const i of instrs) {
  const hex = Array.from(i.bytes).map(b => b.toString(16).padStart(2,'0')).join(' ');
  console.log(`0x${i.address.toString(16).padStart(6,'0')}: ${hex.padEnd(20)} ${i.mnemonic} ${i.operands || ''}`);
}
```
