You're working on the TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB, eZ80 24-bit addressing).

Session 318 identified a 26-vector display subsystem cluster spanning vectors 224-252 in the OS mega-table at 0x020110. Each vector entry is 4 bytes (a JP instruction: opcode 0xC3 + 3-byte target address). Vector N is at address `0x020110 + N * 4`.

The 4 already-decoded API vectors are:

4. Categorize the function: LCD port operation, display parameter, callback-related, status query, mode handler, etc.

- The mega-table starts at 0x020110. Each entry is `C3 xx xx xx` (JP followed by 3-byte LE address).
- Vector stub addresses: vec N has a stub at `0x020110 + N * 4` in the mega-table.
- The OS API stubs in low ROM are at `0x000200 + (N - 128) * 4` for vectors >= 128. So vec 224 = `0x000200 + 96*4 = 0x000380`. Wait — let me recalculate. From the report: vec 224 = address 0x000580. So the mapping is `0x000200 + vec_num * 4`? No, 224 * 4 = 896 = 0x380, and 0x000200 + 0x380 = 0x000580. Yes: **stub address = 0x000200 + vec_num * 4**. Alternatively, just read 4 bytes at `0x020110 + vec_num * 4` from the ROM to get the JP target directly.
