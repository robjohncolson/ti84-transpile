# Task: Trace 0x09196F — sole D010F8 writer in STAT region

## Context
Session 242 mapped D010F8: 9 total refs, 1 WRITE at 0x09196F (STAT region), 8 READ. All readers do `LD A,(D010F8); CP 0x01` — it's a binary flag. D010F8 is a STAT sub-mode indicator. We need to trace what function 0x09196F is in, what sets the value to 0x01, and what callers reach it.

## What to do

1. Create a probe `TI-84_Plus_CE/probe-phase243-09196f-d010f8-writer.mjs` that:
   - Uses the same boilerplate as `probe-phase242-d010f8-investigation.mjs` (cold boot + kernel init)
   - Dumps raw ROM bytes at 0x091960-0x0919B0 (80 bytes) for eZ80 disassembly context
   - Finds the function boundary containing 0x09196F by scanning backward for RET (0xC9) or block boundaries
   - Calls 0x09196F directly with various A values (0x00, 0x01, 0x02, 0xFF) to see what gets written to D010F8
   - Traces 200 steps from 0x09196F for each A value
   - Logs: all unique blocks, RAM writes (especially D010F8), register state, sub-calls
   - Does a static ROM scan for CALL/JP to addresses in 0x091960-0x091980 range to find callers
   - Also scans for CALL/JP to the function entry (once identified from disassembly)
   - Reports: function structure, what A value produces D010F8=0x01, caller sites

2. Run the probe:
   ```bash
   node TI-84_Plus_CE/probe-phase243-09196f-d010f8-writer.mjs
   ```
