# Auto-Session 272 P1: Disassemble 0x09EFDE — the stall point in context registration

## Context
Session 271 found that calling 0x09E2EC (context registration) stalls at address 0x09EFDE. The probe `probe-phase271-context-reg-init.mjs` showed 0x09EFDE is a tight self-loop — the function never reaches table initialization code. We need to understand WHAT condition it's waiting for (hardware register? memory flag? interrupt?).

## Task
Create a probe file `TI-84_Plus_CE/probe-phase272-09EFDE-stall-disasm.mjs` that:

1. **Disassemble 0x09EFDE and surrounding bytes** (0x09EFD0 to 0x09F010) using the eZ80 decoder at `TI-84_Plus_CE/ez80-decoder.js`. Import `decodeInstruction` from it. Read the ROM file at `TI-84_Plus_CE/ROM.rom` and decode instructions starting at each address in ADL mode. Print each instruction's address, hex bytes, and mnemonic.

2. **Identify the self-loop mechanism**: Is it a `JR $-2` (backward jump to self)? A `DJNZ` loop? A `HALT`? Something checking a memory address or port? Print the exact loop structure.

3. **If the loop checks a memory address**: Note what address it reads and what condition makes it exit (e.g., "loops while bit 3 of (0xD0XXXX) is clear"). If it checks an I/O port, note the port number.

4. **Run a dynamic trace**: Boot the system (z80 boot → kernelInit → memInit → home stages 1-4), then call 0x09E2EC with A=0x49 (same as session 271). Trace execution with a write-tracking wrapper that logs ALL memory reads in the 0x09EFD0-0x09F010 range. Limit to 5000 steps. Show which addresses are read, what values are found, and where the loop gets stuck.

5. **Test bypassing the stall**: After booting, instead of calling 0x09E2EC naturally, patch past the stall. If the loop checks address X, try pre-seeding that address with the "exit" value and see if execution continues past 0x09EFDE. Report what blocks follow.
