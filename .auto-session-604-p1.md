# Auto-session 604 P1: Decode 0x0158xx chain and 0x001872 (immediate callers of bulk wipe 0x0018F8)

## Context

In the TI-84 Plus CE ROM transpilation project, the OS has a bulk RAM wipe at PC 0x0018F8 that fires during key processing inside cxMain. Session 603 traced the full 233-frame call chain and found the final approach to the wipe is:

```
0x0158D2 → 0x0158DA → 0x0158EC → 0x0158EE → 0x0158F8 → 0x001872 → 0x001879 → 0x0018F8
```

This is NOT the normal MEM_INIT path (0x09DD62/0x09DEE0). It comes from the memory management/flash subsystem.

## Task

Create a probe that statically decodes the ROM bytes at these addresses to understand what each function does:

1. **0x001872** — the immediate caller of 0x0018F8. Decode from 0x001872 through at least 0x001900. What does it check before calling 0x0018F8? Is there a flag or condition guard?
2. **0x0158D2 through 0x0158F8** — the chain leading to 0x001872. Decode each entry point. What triggers the chain? Is there a conditional branch that could be used to prevent the wipe?
3. **0x0018F8 itself** — the wipe function. Session 600 already decoded it as a multi-stage RAM init (82KB+8KB+255B+37B with integrity check). But decode the ENTRY of 0x0018F8 specifically — does it check any flag/condition before wiping?

## Deliverables

1. A probe file: `TI-84_Plus_CE/probe-phase604-0158xx-decode.mjs`
2. A report file: `TI-84_Plus_CE/phase604-0158xx-decode.md`

The probe should:
- Load the ROM binary from `TI-84_Plus_CE/ROM.rom`
- Read raw bytes and disassemble them (use the eZ80 instruction encoding — it's ADL mode, 24-bit addresses)
- Print the disassembly for each address range
- Look for conditional branches (JR NZ, JR Z, CALL NZ, CALL Z, RET NZ, RET Z, CP, BIT, etc.) that could serve as guard gates

The report should summarize findings with hex addresses and instruction bytes.

## eZ80 instruction reference (ADL mode)

Key encodings for disassembly:
- `CD xx xx xx` = CALL addr24
- `C3 xx xx xx` = JP addr24
- `18 xx` = JR offset8
- `20 xx` = JR NZ, offset8
- `28 xx` = JR Z, offset8
- `C4 xx xx xx` = CALL NZ, addr24
- `CC xx xx xx` = CALL Z, addr24
- `FE xx` = CP A, imm8
- `CB 46+8*bit` = BIT bit,(HL)
- `FD CB dd 46+8*bit` = BIT bit,(IY+dd)
- `3E xx` = LD A, imm8
- `ED B0` = LDIR
- `C9` = RET
- `C0` = RET NZ
- `C8` = RET Z
- Addresses are little-endian 24-bit in ADL mode
