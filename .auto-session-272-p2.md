# Auto-Session 272 P2: Trace 0x09CE10 and 0x058322 in the event loop

## Context
Session 271 ExpC found that booting with D007E0=0x49 + D007E8=0x06C546 + calling 0x09E2EC then 0x0582BC reaches the event loop (0x082BE2) with 37 non-polling unique blocks (39 total, minus 5 known polling blocks). Among the interesting non-polling blocks reached: 0x09CE10, 0x0A1FB5, 0x058322, 0x058344, 0x0A2854. The event loop eventually gets trapped at 0x0A28B7/0x0A28BF.

We need to understand what 0x09CE10 and 0x058322 do — these are event loop dispatch targets that could be key handlers or screen update routines.

   - Set PC = 0x0582BC (home body entry, the best path from session 269)
   - Set SP = STACK_TOP, IX = IX_BASE

     (a) Every time PC enters 0x09CE10: log step number, CPU registers (A, HL, DE, BC), and first 16 bytes of RAM at address HL

Check if 0x09CE10 or 0x058322 appear as handler addresses in the table.
