# Auto-Session 379 — P1: Implement DI+HALT Bypass in Coldboot Mode

## Context

The TI-84 Plus CE ROM transpilation project lifts eZ80 machine code to JavaScript. The "coldboot" runtime mode in `TI-84_Plus_CE/browser-shell.html` boots the OS and enters the event loop at 0x003A73. When the user presses a key, the OS processes it and then executes DI + HALT at address 0x0019B5 (power-down/sleep mode). Since DI disables all maskable interrupts, the timer cannot wake the CPU, and execution stops permanently.

Session 378 confirmed:
- 0x0019B5 = DI instruction
- 0x0019B6 = LD A, 0x10
- 0x0019B8 = OUT0 (0x00), A
- 0x0019BB-BC = NOP
- 0x0019BD = HALT
- After HALT, if NMI woke CPU, wake path at 0x0019BE reads port 0x5015 to determine wake reason

## Task

Modify `TI-84_Plus_CE/cpu-runtime.js` to add a DI+HALT bypass for coldboot mode. When the runtime detects that:
1. A HALT instruction is executed (check `cpu.halted === true` or equivalent)
2. Interrupts are disabled (`cpu.iff1 === 0` or `cpu.iff1 === false`)

...it should restart the event loop instead of staying halted forever.

### Implementation approach

In the `executeBlock` function or the main execution loop in `cpu-runtime.js`, after a block executes and the CPU is halted with interrupts disabled:

```javascript
// After block execution, check for DI+HALT (sleep mode)
if (cpu.halted && !cpu.iff1) {
  // OS entered sleep mode — restart event loop
  cpu.halted = false;
  cpu.iff1 = 1;  // Re-enable interrupts (simulates ON-key wake)
  cpu.iff2 = 1;
  cpu.pc = 0x003A73;  // Event loop entry point
}
```

This goes in the main step/run loop, NOT inside individual transpiled blocks.

### Where to look

- `TI-84_Plus_CE/cpu-runtime.js` — find the main execution loop (the `step()` or `run()` function that dispatches transpiled blocks). Look for where `cpu.halted` is checked.
- Search for existing HALT handling — there should already be code that sets `cpu.halted = true` when a HALT instruction is encountered.
- The `coldboot` mode flag may be accessible via a configuration option or could be checked via `cpu.coldboot` or similar. If no such flag exists, make the DI+HALT bypass unconditional (it's safe — real boot with timer enabled would never hit DI+HALT because the timer ISR fires first).
