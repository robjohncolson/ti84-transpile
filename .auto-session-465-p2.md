# Task: Fix Port 0x0F in peripherals.js

## Problem
In `TI-84_Plus_CE/peripherals.js`, port 0x0F is hardcoded at line 885 to always return `0x80` (bit 7 = USB power present). The OS scheduler at 0x0015FB does:
```
IN0 A,(0x0F)
BIT 7,A → JR NZ 0x001644   (USB path — always taken with 0x80)
BIT 6,A → JR NZ → CALL 0x001794  (event handler — never reached)
```

With 0x80, bit 7 is always set, so the scheduler ALWAYS takes the USB state handler path and NEVER reaches the keyboard event handler at 0x001794. Session 464 proved that with port 0x0F=0x40, the scheduler correctly reaches the event handler.

## Current Code (line 885-888)
```js
register(0x0f, {
    read() { return 0x80; }, // bit 7 = USB power present
    write() {},
});
```

## Required Fix
Change port 0x0F to return a dynamic value based on keyboard state:
- Return `0x40` (bit 6 = keyboard event pending) when ANY key in the keyboard matrix is pressed
- Return `0x00` when no keys are pressed
- Do NOT set bit 7 (USB power) — this routes to the USB path which blocks key processing

The keyboard matrix state is accessible via `keyboardState.keyMatrix` (a Uint8Array of 8 bytes, each 0xFF when no keys pressed in that group, bits cleared when keys pressed). A key is "down" when any group has a value != 0xFF.

Replace the port 0x0F registration (lines 885-888) with:
```js
register(0x0f, {
    read() {
        for (let g = 0; g < keyboardState.keyMatrix.length; g++) {
            if (keyboardState.keyMatrix[g] !== 0xFF) {
                return 0x40; // bit 6 = keyboard event pending
            }
        }
        return 0x00;
    },
    write() {},
});
```

## IMPORTANT: Scope of keyboardState
The `keyboardState` variable is defined at line 672:
```js
const keyboardState = { groupSelect: 0xFF, keyMatrix: new Uint8Array(8).fill(0xFF) };
```

Port 0x0F is registered at line 885. The `keyboardState` variable IS in scope at line 885 because both are inside the same `createPeripheralBus` function. You can directly reference `keyboardState.keyMatrix` in the port 0x0F handler.

## Constraints
- Do NOT modify any other port handlers
- Do NOT add new state variables — use the existing keyboardState.keyMatrix
- Do NOT set bit 7 (0x80) — this must stay clear to avoid the USB path
- Keep the existing write() handler as a no-op
- Keep the comment above the register block ("USB controller ports...")

## Success Criteria
- Port 0x0F returns 0x40 when any key is pressed in the matrix
- Port 0x0F returns 0x00 when no keys are pressed
- The scheduler at 0x0015FB can now reach the event handler at 0x001794 when a key is down
- No other port behavior is changed
