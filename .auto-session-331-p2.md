# Task: Map the 0x055743 Mode-Switch Function

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM (eZ80 machine code) has been lifted to JavaScript. Address 0x055743 is a "config copier" that selects between 16bpp and 8bpp VRAM modes based on (IY+70) bit 2.

## Key addresses from prior sessions
- **0x055743** = mode-switch / config copier function. Selects 16bpp vs 8bpp.
- When bit 2 of (IY+70) is clear → uses ROM source at **0x05550C** (16bpp: stride=640, vbase=0xD40000)
- When bit 2 of (IY+70) is set → uses ROM source at **0x055519** (8bpp: stride=320, vbase=0xD52C00)
- Writes 13-byte LDIR block to D02FD9-D02FE5 (VRAM descriptor)
- Also sets D02FDF = bpp indicator (0x10 for 16bpp, 0x08 for 8bpp)
- **0x0551EA** = init function that also writes VRAM descriptor from 0x05550C
- **0x08C6D5** = full reset that writes via 0x0551EF

## What to do
1. Open `TI-84_Plus_CE/ROM.transpiled.js.gz` (gunzip it), find block_0x055743 and disassemble it fully.
2. Find ALL callers of block_0x055743 in the transpiled JS (search for calls/jumps to 0x055743).
3. For each caller, determine: what triggers the mode switch? Is it user-initiated (menu), OS-initiated (boot), or app-initiated?
4. Trace what other state 0x055743 updates beyond the VRAM descriptor (check all memory writes in the block).
5. Check if there are any other references to (IY+70) bit 2 in the ROM — who else reads/writes this flag?

## Deliverable
Create `TI-84_Plus_CE/probe-phase331-mode-switch.mjs` that:
- Statically disassembles block_0x055743 from the transpiled JS (extract the function body)
- Finds all callers of 0x055743
- Finds all references to (IY+70) bit 2 (search for patterns like `bit 2` near IY+70 or address 0xD00046+70=0xD0008C... actually IY is typically 0xD00080 so IY+70=0xD000C6... search the transpiled JS for reads/writes involving the bpp flag)
- Boots to home screen and logs when/if 0x055743 is called during boot
- Reports all callers, all state changes, and the bpp flag references
