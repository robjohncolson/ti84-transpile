# Task: Map the 12 D0058D write sites — complete ISR scan-code-to-key-code pipeline

## Context
This is a TI-84 Plus CE ROM transpilation project. ROM at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80).
Runtime: `TI-84_Plus_CE/cpu-runtime.js`.

## What we know
- D0058D is a RAM variable that holds a sequential matrix index written by the ISR/keyboard handler
- 0x03FC1C reads D0058D, looks it up in a 56-entry table at 0x03FC41, returns the TI-OS key code in HL
- D0058D has 15 total ROM references: 12 WRITE, 1 READ at 0x09CF72, 1 POINTER, 1 UNKNOWN
- D0058D is zeroed after reading (read-and-clear pattern at 0x03FC1C)
- The 56-entry table at 0x03FC41 maps sequential indices to key codes, grouped by keyboard row:
  - arrows[4]: 0x22/0x18/0x1A/0x19
  - row6[7]: 0x69-0x2D  
  - row5[7]: 0x68-0x2C
  - row4[8]: 0x67-0x21
  - row3[8]: 0x66-0x20
  - row2[7]: 0x5B-0x1F
  - modifiers[8]: 0x0F-0x17
- The keyboard matrix uses `keyMatrix[N] = SDK Group(7-N)`, scan code = `(idx << 4) | bit`

## Task
Build a probe `TI-84_Plus_CE/probe-phase227-d0058d-write-sites.mjs` that:

1. **Static ROM scan**: Search the entire ROM (0x000000-0x0BFFFF) for all instructions that write to D0058D (absolute address 0xD0058D). Look for:
   - `LD (0xD0058D),A` patterns: `32 8D 05 D0` (SIS) or with ADL prefix
   - `LD (HL),A` where HL=0xD0058D (indirect — look for LD HL,0xD0058D = `21 8D 05 D0` near stores)
   - Any other store patterns (INC (addr), DEC (addr), etc.)
   
   For each write site found, disassemble ±30 bytes of context to understand:
   - What value is being written (immediate, register, computed?)
   - What function it's inside (find RET boundary)
   - Is it in ISR context or normal code?

2. **Dump the 0x03FC41 table**: Read all 56 bytes from ROM at 0x03FC41 and format as a complete mapping:
   - table_index → key_code (hex)
   - Group by keyboard row (separated by 0x00 entries)
   - Cross-reference with the keyboard matrix from `TI-84_Plus_CE/keyboard-matrix.md`

3. **Build the complete mapping**: For each D0058D write site, determine:
   - What scan code / matrix position produces the write
   - What value gets written to D0058D
   - What key code 0x03FC41[value] returns
   - What the physical key name is

4. **Cross-reference summary**: Print a table showing:
   ```
   Physical Key | Scan Code | D0058D Index | Key Code (from table) | Write Site Address
   ```
