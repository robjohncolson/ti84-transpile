# Task: Identify OS context handler table entries (20 entries at 0x08C958)

## Goal
Map each of the 20 handler table entries at ROM address 0x08C958 to known OS contexts by cross-referencing the entry point addresses with known functions/labels.

## Background
Session 252 decoded the handler table at 0x08C958. The table has 20 3-byte entries (little-endian 24-bit addresses). The lookup function at 0x08C94B: `LD E,A / LD D,3 / MLT DE / LD HL,0x08C958 / ADD HL,DE / LD HL,(HL) / RET` — indexes by A (0-19), returns handler address in HL.

Known entry: [0] = 0x058241 = cxMain (home screen key handler).

The context selector is stored at D007E0 and D00824 is the "app context" byte.

## Deliverables
Create probe file: `TI-84_Plus_CE/probe-phase255-handler-table-map.mjs`

The probe should:
1. Read ROM.rom binary directly (fs.readFileSync).
2. Extract all 20 3-byte LE entries from ROM offset 0x08C958 (20 entries × 3 bytes = 60 bytes).
3. For each entry address, disassemble the first ~30 bytes at that address using the eZ80 decoder to identify what the function does.
4. Cross-reference each entry address against known labels. Search the ROM binary for patterns that reference these addresses:
   - D00824 values: 0x00=home, 0x46=UI/menu, 0x48/0x49/0x4A=editor modes, 0x01=STAT (from session 236 D00824 writer map)
   - Check if any entry matches known function starts: 0x03D755, 0x080CA7, 0x0AB667, 0x06C748, etc.
5. For each handler, classify as: home/editor/graph/stat/table/program/matrix/list/unknown based on the disassembly (look for what RAM addresses they load, what they CP against, what subroutines they call).
6. Also dump D007E0 values 0-19 and note which ones correspond to which handler (since the context selector A = index into the table).
7. Print a formatted table: `[index] address = classification (first few instructions)`.

## Reference files

## Constraints

- This is a READ-ONLY analysis probe — it reads ROM.rom and disassembles, no CPU execution needed.
- The probe must be runnable via `node TI-84_Plus_CE/probe-phase255-handler-table-map.mjs`.

## Success criteria
- All 20 handler addresses extracted and printed
- Each handler has first ~30 bytes disassembled
- At least cxMain ([0]=0x058241) is correctly identified
- A classification attempt for each handler based on disassembly context
