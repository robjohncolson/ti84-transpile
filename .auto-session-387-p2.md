# Task: Disassemble 0x0302EB (Token Validation Subroutine)

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 ADL-mode machine code).

Session 386 found that after the default key translation table lookup at 0x022346, the code calls 0x0302EB for token validation before accepting the token via JP NZ,0x02FFED. We need to understand what 0x0302EB validates.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase387-disasm-0302EB.mjs` that:

1. Reads ROM bytes starting at 0x0302EB and performs static eZ80 ADL-mode disassembly
2. Disassemble from 0x0302EB until you hit a clear RET or JP that ends the function (likely around 0x030350 based on 0x030353 being another known entry, but go further if needed)
3. Identify:
   - What does it check/validate about the token?
   - Does it filter invalid tokens? Check context flags?
   - What RAM addresses does it read (especially 0xD007E0 context byte, IY-indexed flags)?
   - What are the return conditions (Z/NZ flag meaning)?
   - Any CALL targets within the function

## Probe pattern
```js
import { readFileSync } from 'fs';
import { createDecoder } from './ez80-decoder.js';

const rom = readFileSync(new URL('./ROM.rom', import.meta.url));
const decoder = createDecoder(rom);

function disasmRange(start, end) {
  let pc = start;
  const results = [];
  while (pc < end) {
    const instr = decoder.decodeAt(pc);
    results.push(instr);
    pc += instr.length;
  }
  return results;
}

const instrs = disasmRange(0x0302EB, 0x030388);
for (const i of instrs) {
  const hex = Array.from(i.bytes).map(b => b.toString(16).padStart(2,'0')).join(' ');
  console.log(`0x${i.address.toString(16).padStart(6,'0')}: ${hex.padEnd(20)} ${i.mnemonic} ${i.operands || ''}`);
}
```
