# Task: Test 0x03FC1C with D0058D values — verify scan-code-to-key-code end-to-end

## Context
This is a TI-84 Plus CE ROM transpilation project. ROM at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80).
Runtime: `TI-84_Plus_CE/cpu-runtime.js`, decoder: `TI-84_Plus_CE/ez80-decoder.js`, peripherals: `TI-84_Plus_CE/peripherals.js`.
Transpiled ROM: regenerate via `node scripts/transpile-ti84-rom.mjs`, then load from `TI-84_Plus_CE/ROM.transpiled.js`.

## What we know
- 0x03FC1C is a key code converter function
- It reads D0058D (sequential matrix index), looks up in 56-entry table at 0x03FC41, returns TI-OS key code in HL
- Read-and-clear pattern: reads D0058D, then zeroes it
- Table at 0x03FC41 has 56 entries grouped by keyboard row (arrows, row6, row5, row4, row3, row2, modifiers), separated by 0x00 bytes
- 2 callers: CALL at 0x099CEB, JP at 0x020AA8
- Known table entries: index 1→0x22(DOWN?), index 2→0x18, index 3→0x1A, index 4→0x19

## Task
Build a probe `TI-84_Plus_CE/probe-phase227-03fc1c-e2e-test.mjs` that:

1. **Boot the CPU**: Use the standard boot sequence from existing probes:
   ```javascript
   const { createCPU } = require('./TI-84_Plus_CE/cpu-runtime.js');
   // ... load transpiled ROM, create CPU, run boot
   ```
   Look at `probe-phase226-03fc1c-table-reader.mjs` or `probe-phase225-2byte-e2e.mjs` for the exact boot pattern.

2. **Test 0x03FC1C with every valid D0058D index (1-55)**:
   For each index value from 1 to 55:
   - Set D0058D to the index value: `cpu.mem[0xD0058D] = index`
   - Set PC to 0x03FC1C
   - Run for 100 steps max (function should complete quickly)
   - Read HL register after return (this is the key code)
   - Verify D0058D was cleared to 0 (read-and-clear pattern)
   - Record: index → HL value

3. **Test D0058D=0 (no key)**: Verify it returns HL=0 without table lookup

4. **Cross-reference with known scan codes**:
   Known scan code → key mappings from `keyboard-matrix.md`:
   - 0x8F = digit '1' → should map to key code that ConvKeyToTok converts to token 0x31
   - 0x8E = digit '0' → token 0x30
   - 0x80 = '+' → token 0x70
   
   Print which D0058D indices produce key codes matching these known scan codes.

5. **Build complete mapping table**: Print:
   ```
   D0058D Index | Key Code (HL) | Hex | Known Key Name (if identifiable)
   ```

6. **Verify read-and-clear**: After each test, confirm D0058D = 0x00

## Important
- Between each test, you MUST reset the CPU state or at minimum restore D0058D and any modified flags
- The function also calls 0x03FA09 and 0x0AF8C4 as side effects — those should complete normally after boot
- If the function doesn't return within 100 steps for any index, note it and move on
