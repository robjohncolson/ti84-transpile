# Task: Trace the type code origin before convergence 0x0587E9

## Context
This is a TI-84 Plus CE ROM transpilation project. The OS general key handler at 0x05877A processes all non-special keys. It converges at 0x0587E9 where a type code in register A determines character vs command routing:
- `CALL 0x058b73` (type-7 check)
- `CP 0x05` at 0x0587F3 splits chars (type < 5) from commands (type >= 5)
- `CALL 0x058d54` is called from 0x05899d (command path) and presumably somewhere before convergence (character path)

Session 599 INCORRECTLY claimed 0x058d54 is "the REAL type classifier". Session 600 CORRECTED this: 0x058d54 is a 58-byte key action processor with PUSH/POP AF that preserves the caller's type. The type in A must be set by an EARLIER function.

## What to do
Create a probe file `TI-84_Plus_CE/probe-phase601-type-code-trace.mjs` that:

1. Uses the EXACT boot sequence from `TI-84_Plus_CE/probe-phase599-wipe-tracker.mjs` (Phase 0 through Phase 2 — cold boot, launch-init 0x09DD62, paint 0x058241). Copy it verbatim.

2. Seeds a key (D0058C=0x90 for '2', D0058E=0x90, D0009F|=0x20) and runs the outer loop from 0x08C331.

3. Uses `onBlock(pc)` to capture a detailed register trace at key addresses in the call chain leading to convergence. Track register A (via `cpu._a` or equivalent — check `cpu-runtime.js` for the register accessor) at these blocks:
   - 0x0585E9 (cxMain entry)
   - 0x05877A (general key handler entry)
   - 0x058b73 (type-7 check)
   - 0x058d54 (key action processor)
   - 0x0587E9 (convergence point)
   - 0x0587F3 (CP 0x05 split — capture A here to see the type code)
   - 0x080259 (descriptor check, called before convergence)
   - 0x058EDA (catalog check)
   
   For each: log the step number, PC, and the value of register A.

4. **ALSO do static decode**: Read ROM bytes around the convergence point 0x0587E9 backward (~50 bytes, from 0x0587B0 to 0x058810) and forward. List every CALL/JP/RET instruction and its target. We need to find which CALL before 0x0587E9 sets A to the type code.

5. Check `cpu-runtime.js` for how to access register A. Look for `cpu._a`, `cpu.a`, or `cpu.registers` — read the source to find the correct accessor. Also check cpu._f for flags.

## Key constraints
- Import pattern: same as other probes in the directory
- The probe must run in under 180s via the watchdog
- NEVER push 0x0019be as return address (wipe trap). Use 0x0019b5 (halt).
- Run via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase601-type-code-trace.mjs`

## Success criterion
Identify which function in the call chain sets the type code in register A before the convergence point 0x0587E9. The output should show the value of A at each tracked block, making it clear where it transitions from the raw key code (0x90) to the type code.

Run the probe via the watchdog: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase601-type-code-trace.mjs`
