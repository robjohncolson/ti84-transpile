# Task: Decode 0x000380 — Font Base Address Provider

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 binary).

## What we know
- 0x000380 is called by the glyph table lookup function at 0x07BF3E (session 552 finding).
- After the call, HL = font table base address in ROM.
- The caller then does ADD HL,DE where DE = 28 × char_code, giving the glyph data pointer.
- Each glyph is 28 bytes.
- The function is in the very low ROM area (0x000380) — this is the OS jump table / vector region.

## Your task

   - Disassembles 64+ bytes of eZ80 code at that address
   - Identifies what address it returns in HL (the font base)
   - Traces any JP/CALL targets it references
   - Check if 0x000380 is actually a jump vector (JP xxxx) to the real function
   - If it's a vector, follow the target and decode that too

2. The probe should use the project's standard pattern. Reference `TI-84_Plus_CE/probe-phase552-decode-04C979.mjs` for the format.

3. Report findings in stdout as structured analysis.

## eZ80 reference
- JP nn = ED C3 nn nn nn (4 bytes) or C3 nn nn (3 bytes in short mode)
- CALL nn = ED CD nn nn nn (4 bytes) or CD nn nn (3 bytes)
- LD HL,nn = 21 nn nn nn (4 bytes eZ80) or 21 nn nn (3 bytes short)
- RET = C9
- The OS vector table at 0x000000-0x000FFF typically contains JP instructions to actual implementations
