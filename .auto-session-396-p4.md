# Task: Coverage Push — Add Seeds for Uncovered CODE? Regions

## Context
TI-84 Plus CE ROM transpilation project. The transpiler lifts eZ80 ROM to JavaScript.
- Transpiler: `scripts/transpile-ti84-rom.mjs`
- ROM: `TI-84_Plus_CE/ROM.rom` (4MB)
- Current state: 144,379 blocks, 705,551 covered bytes

The coverage audit identifies uncovered non-erased ranges. Ranges with verdict "CODE?" are the most likely to be actual executable code that just needs a seed address to be discovered by the transpiler's CFG walker.

## Deliverable
1. Run `node TI-84_Plus_CE/audit-true-uncovered.mjs` and capture the output
2. From the output, identify ranges with verdict "CODE?" — these are the best candidates for new seeds
3. For each CODE? range, examine the first few bytes at that address in ROM.rom to verify they look like valid eZ80 instructions (not data). Good signs:
   - Starts with a common instruction prefix (PUSH = C5/D5/E5/F5, LD = 3E/21/11/01, etc.)
   - Contains CALL (CD) or JP (C3) or RET (C9) patterns within the range
   - Does NOT start with 00 00 00 or FF FF FF (erased/padding)
4. Add validated seed addresses to `scripts/transpile-ti84-rom.mjs` in the `SEED_ADDRESSES` array
   - Find the array in the file (search for `SEED_ADDRESSES` or the existing seed list)
   - Add new addresses at the end of the array with a comment like `// session 396 coverage push`
5. Re-run the transpiler: `node scripts/transpile-ti84-rom.mjs`
6. Re-run the coverage audit: `node TI-84_Plus_CE/audit-true-uncovered.mjs`
7. Report the before/after block count and covered byte count

## Constraints
- Only add seeds that genuinely look like code entry points (not data)
- Add at least 10 seeds, up to 20 if that many valid CODE? ranges exist
- Do NOT modify any file other than `scripts/transpile-ti84-rom.mjs`
- Do NOT touch `TI-84_Plus_CE/ROM.transpiled.js` — it's gitignored and will be regenerated
- Verify golden regression still passes after adding seeds: `node TI-84_Plus_CE/probe-phase99d-home-verify.mjs`
- The transpiler takes ~2 seconds to run

## Success criteria
- New seeds added to transpiler
- Transpiler runs successfully with new seeds
- Block count increased
- Golden regression (probe-phase99d-home-verify.mjs) still passes
