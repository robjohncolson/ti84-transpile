# Task: Decode 0x061434 — Character Preprocessor

## Context
This is the TI-84 Plus CE ROM transpilation project. We lift eZ80 machine code from `TI-84_Plus_CE/ROM.rom` into JavaScript and run it in a browser shell.

Session 496 decoded putchar (0x061980) and found it calls 0x061434 as the first step in the character rendering pipeline. The preprocessor's result determines whether the normal render path or an alternate path at 0x0619B3 is taken (JR NZ at offset+4 from the CALL site). Understanding this function reveals how the OS handles special characters, control codes, newlines, etc.

The full putchar pipeline: 0x061434 (preprocessor) → 0x06002D (cursor-to-VRAM) → 0x0A23E5 (pixel renderer).

## What to do

Create a probe file `TI-84_Plus_CE/probe-phase497-decode-061434.mjs` that:

### Part 1: Static disassembly
1. Load the ROM from `TI-84_Plus_CE/ROM.rom`
2. Disassemble 0x061434 instruction-by-instruction using the eZ80 decoder at `TI-84_Plus_CE/ez80-decoder.js`
3. Follow the code until RET (or until 200 bytes), tracking all branches
4. Print each instruction with address, hex bytes, and mnemonic
5. Note: what register holds the character code on entry (likely A)? What flag does it set for the JR NZ decision? What special characters cause the NZ path?
6. Note all CALL/JP targets and any references to known addresses (D00595, D00596, cursor glyphs 0xE1/0xE2/0xE3, etc.)

### Part 2: Dynamic tests
1. Use the executor pattern (see below for reference)
2. Test with these character codes in register A:
   - 0x41 ('A') — normal printable character
   - 0x0D (carriage return)
   - 0x0A (line feed)
   - 0x08 (backspace)
   - 0x00 (null)
   - 0xE1 (cursor glyph — insert mode)
   - 0xE2 (cursor glyph — overwrite mode)
   - 0x20 (space)
   - 0x7F (DEL or special)
   
3. For each test:
   - Set IY=0xD00080, PC=0x061434, SP=0xD1A87E
   - Load character code into register A
   - Set D00595=3, D00596=10 (fixed cursor position)
   - Step until RET or 1000 steps
   - Capture: Z flag state on return, register A value on return, step count, any memory writes
   - The Z/NZ flag after 0x061434 returns determines whether putchar takes the normal path or the alternate path at 0x0619B3

4. Print a table showing: input char → Z/NZ flag → meaning (normal render vs special handling)

### Executor pattern reference

```javascript
import { readFileSync, existsSync } from 'fs';
import { execSync } from 'child_process';
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';

const rom = readFileSync('TI-84_Plus_CE/ROM.rom');
const peripherals = createPeripheralBus({ timerInterrupt: false });
const cpu = createCPU(peripherals);

for (let i = 0; i < rom.length; i++) cpu.mem[i] = rom[i];

const transpiledPath = 'TI-84_Plus_CE/ROM.transpiled.js';
if (!existsSync(transpiledPath)) {
  execSync('gzip -dk TI-84_Plus_CE/ROM.transpiled.js.gz');
}
const transpiledCode = readFileSync(transpiledPath, 'utf-8');
new Function('cpu', transpiledCode)(cpu);
```

### Important constraints
- Use `import` syntax (ES modules, .mjs file)
- ROM is 4MB at cpu.mem[0..0x3FFFFF]
- IY is always 0xD00080
- `createPeripheralBus({ timerInterrupt: false })` — always disable timer IRQ
- The decoder is at `TI-84_Plus_CE/ez80-decoder.js`, import as `import { decodeInstruction } from './ez80-decoder.js';`
