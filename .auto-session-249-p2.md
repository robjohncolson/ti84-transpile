# Auto-Session 249 P2: Trace OS Event Loop Digit Processing (Real Path)

## Context
Session 246 P4 achieved a **full event loop cycle**: HALT → key injection → processing → HALT, in 72 block steps (67 unique blocks). The probe `TI-84_Plus_CE/probe-phase246-full-event-cycle.mjs` demonstrates the pattern.

Key findings from session 246:
- Idle HALT at 0x040D40 (25 steps from 0x02FD8F dispatcher entry)
- Key "2" (scan code 0x22, key code 0x8F) injected at D0058E
- Key-present path: 0x02FE89 → 0x02FFAE (normal dispatch) → 0x02FE84 → 0x02FD99 (re-enter) → 0x040D40 (HALT)
- Stubs: 0x049656 (USB/timer HALT bypass) and 0x03FA09 (key delivery, loads A from D0058E and RETs)
- D00000=0xCC needed for HALT gate

Session 214 and earlier traced the cxMain digit path extensively but found that **NO table entry reaches BufInsert for digits**. The missing piece is: what happens between the event loop's "normal dispatch" at 0x02FFAE and the eventual digit processing? The event loop cycle from session 246 used only 72 steps — it may be exiting too early.

## Task
Create a probe `TI-84_Plus_CE/probe-phase249-event-loop-digit-trace.mjs` that:

1. **Full boots** the OS (same pattern as probe-phase246-full-event-cycle.mjs: z80 boot → kernelInit at 0x08C331 → memInit at 0x09DEE0 → home-screen stages 1-4 at 0x0A2B72/0x0A3301/0x0A29EC/0x0A2854)
2. **Enters the event loop** at dispatcher 0x02FD8F with the same setup (D00000=0xCC, stack at 0xD1A87E, IX=0xD1A860, IY=0xD00080)
3. **Waits for first HALT** (idle state)
4. **Injects key "2"** (scan code 0x22 at D0058C, key code 0x8F at D0058E) 
5. **Resumes from HALT** and traces execution with a **MUCH higher step limit** (50000 steps instead of the 200 used in session 246)
6. **Logs every block visited** with its address, tracking the FULL path from key injection to wherever execution settles (next HALT or step limit)
7. **Specifically watches** for these key addresses:
   - 0x0585D3 (JP (HL) dispatch table)
   - 0x0585E9 (cxMain entry)
   - 0x05877A (cascading CP chain)
   - 0x058AC9 (BufInsert gate, CP 0x5A)
   - 0x0589E5 (class comparison chain)
   - 0x05E2A0 (BufInsert itself)
   - 0x05E620 / 0x05E6A4 (ConvKeyToTok)
   - 0x058D54 (token class lookup)
   - 0x09927F (key handler)
8. **Dumps RAM state** at key addresses after processing: D0058E (key consumed?), D00A00-D00A10 (edit buffer), D007E0 (mode flags)
9. Uses the same stubs as session 246: 0x049656 (ret) and 0x03FA09 (load-key-ret)
