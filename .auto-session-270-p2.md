# Task: Enable IFF1=1 + test ISR delivery during event loop

## Context
Session 269 probe `probe-phase269-isr-event-loop.mjs` found that:
- The event loop's no-key HALT path (decoded session 237) does EI+HALT at 0x040D40
- Timer IRQ is generated but MASKED because IFF1=0 (interrupts disabled after boot)
- D0058E key injection also fails — the event loop checks the dispatch table only, not D0058E directly
- The ISR chain (when enabled) would deliver key events via 0x02F68A → 0x02F961 → writes D0058E
- The event loop at 0x02FD8F reads D0058E via CALL 0x03013A (key scan)

The no-key HALT path (session 237): OR A(Z)→checks→SET 0,(IY+22)→CALL 0x040D40(EI+HALT). On HALT, CPU waits for interrupt. ISR resume at 0x040D42.

## What to do

Create a probe `TI-84_Plus_CE/probe-phase270-iff1-isr-test.mjs` with multiple experiments:

### Experiment 1: EI before event loop entry
- Full boot (cold boot → kernelInit → memInit → homescreen stages 1-4), same pattern as other phase 269/268 probes
- After boot, set `cpu.iff1 = 1` and `cpu.iff2 = 1` (enable interrupts)
- Enable timer interrupt: `createPeripheralBus({ timerInterrupt: true })` — actually you need to create the peripheral bus with timer enabled for this test (unlike other probes that disable it)
- Enter event loop at PC=0x0582BC (home body bypass, reaches event loop at step 21 per session 267)
- Run for 10000 steps
- Report: Does the ISR fire? Which blocks are visited? Does execution reach 0x02F68A (key processing pipeline)? Does it reach HALT at 0x040D40?

### Experiment 2: EI + key injection
- Same setup as Exp 1
- After boot, also inject a key: `mem.write8(0xD0058E, 0x8F)` (digit "1" key code)
- Also set `mem.write8(0xD0058C, 0x01)` (pending-event flag — session 237: D0058C==0→loop back; nonzero→clear IY flags + CALL 0x030300)
- Run for 10000 steps
- Report: Does the key get processed? Does execution reach 0x02FE89 (key-event handler)? Does it reach ConvKeyToTok? BufInsert?

### Experiment 3: EI + timer BUT boot with timerInterrupt:false, then enable mid-run
- Boot with `timerInterrupt: false` as usual
- After boot, enable IFF1=1 and IFF2=1
- Then reconfigure the peripheral bus to enable timer (if possible — check if the peripheral bus object has a method to enable timer, or if you need to write the timer MMIO registers directly at port 0x30-0x37)
- Enter event loop, run 10000 steps
- This tests whether enabling interrupts post-boot (after all init is done) allows the ISR to fire without hijacking boot

### For ALL experiments, report:
- Total steps taken
- Unique blocks visited
- Whether blocks 0x003D55 (ISR keyboard writer), 0x02F68A (key pipeline), 0x040D40 (HALT) were visited
- IFF1/IFF2 values at end
- D0058E value at end
- Any crashes or resets (PC=0x000000)
