# Task: Add 20 Coverage Seeds to the Transpiler

## Context
This is a TI-84 Plus CE ROM (eZ80) transpilation project. The transpiler at `scripts/transpile-ti84-rom.mjs` lifts eZ80 machine code from `TI-84_Plus_CE/ROM.rom` into JavaScript. It uses "seeds" — known entry point addresses — to discover code blocks via control flow analysis.

Current state: 145,031 blocks, 709,088 covered bytes (~95.92% of non-erased ROM).

## Your Task
1. **Run the coverage analyzer** to find gaps:
   ```bash
   node TI-84_Plus_CE/coverage-analyzer.mjs
   ```
   This outputs uncovered regions.

2. **Find 20 new seed addresses** in uncovered regions. For each candidate:
   - Read the ROM bytes at that address
   - Verify the first byte is a valid eZ80 opcode (not data)
   - Look for function prologue patterns: `PUSH IX` (0xDD 0xE5), `PUSH AF` (0xF5), `PUSH HL` (0xE5), `LD IX,nn` (0xDD 0x21), `DI` (0xF3), or any valid instruction sequence
   - Avoid addresses that are clearly data (ASCII strings, lookup tables, zero-filled regions)

3. **Add the seeds** to `scripts/transpile-ti84-rom.mjs`. Find the `seeds` array and append your 20 new addresses with brief comments.

4. **Re-run the transpiler** and verify:
   ```bash
   node scripts/transpile-ti84-rom.mjs
   ```
   Check the output for new block count and covered bytes.

5. **Run the golden regression** to verify nothing broke:
   ```bash
   node TI-84_Plus_CE/probe-phase99d-home-verify.mjs
   ```
   Must still pass 26/26.

## Deliverables
- Modified `scripts/transpile-ti84-rom.mjs` with 20 new seeds added
- Console output showing new block/byte counts
- Golden regression pass confirmation

## Constraints
- ONLY modify `scripts/transpile-ti84-rom.mjs` (the seeds array)
- Do NOT modify `cpu-runtime.js`, `peripherals.js`, `browser-shell.html`, `ez80-decoder.js`
- Do NOT modify any probe files
- Seeds must be in ROM range 0x000000-0x3FFFFF
- Each seed must start at a valid instruction (verify before adding)
- Golden regression MUST still pass after adding seeds
