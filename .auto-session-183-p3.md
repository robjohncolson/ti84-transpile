# Auto-Session 183 P3 — Key Classifier 0x07F7BD Trace with Digit Keys

## Context
This is a TI-84 Plus CE ROM transpilation project. The home handler at 0x0582B8 has been fully disassembled (session 182). The key processing loop at 0x058483+ calls `0x07F7BD` at address 0x0584A7 — this is the key classifier that returns a type value in register A. The home handler then dispatches:
- CP 0x06 → JP 0x061D42
- CP 0x05 → special handling
- Otherwise → falls through to character insertion (which calls BufInsert)

We need to know: what does 0x07F7BD return for digit keys (0-9) and operator keys (+, -, *, /)?

Session 181 found that 0x058D49 and 0x058BA3 are NOT key classifiers (they're flag-clearing routines). The REAL key classifier is 0x07F7BD. Session 182 confirmed it's called at 0x0584A7.

## Task
Build a probe `TI-84_Plus_CE/probe-phase183-key-classifier.mjs` that:

1. Boot the ROM (cold boot + MEM_INIT — copy boot pattern from probe-phase182-parseinp-state-diff.mjs)
2. For each test key scan code, set up the home handler's key processing context:
   - Start execution from 0x058483 (after LCD clear, in the key processing loop)
   - SP = 0xD1A87E, IX = 0xD1A860, IY = 0xD00080
   - Set the scan code in the appropriate RAM location. The TI-84 CE keyboard convention: _GetCSC returns scan code in A. The home handler likely reads the scan code from a RAM buffer (check 0xD0008E area — kbdScanCode, or the key may already be in register A at 0x058483 entry)
3. Execute from 0x058483 and trace blocks until either:
   - The CALL 0x07F7BD at 0x0584A7 is reached and returns, giving us the return value in A
   - Or 500 steps are reached
4. Do a static disassembly of 0x07F7BD (first 100 bytes) to understand what it does — is it a table lookup? Does it read from kbdKey RAM?
5. Test with these scan codes (from keyboard-matrix.md):
   - k1 (digit 1): 0x9A
   - k2 (digit 2): 0x92
   - k5 (digit 5): 0x8A
   - k0 (digit 0): 0x82
   - kAdd (+): 0x8B
   - kEnter: 0x09
6. For each key, report: the return value in A after 0x07F7BD returns, and which dispatch path is taken (CP 0x06 branch, CP 0x05 branch, or fall-through)
