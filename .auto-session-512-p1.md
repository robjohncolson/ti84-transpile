## What we know
- 0x07C8B7 is called by BOTH 0x07CFA7 (standard text render) and 0x07CF1A (special render)
- 0x07CFA7 calls: 0x07CF9D, 0x07FE9C, 0x07F7A4, 0x07FE5A, 0x07F16C(A=4), **0x07C8B7**, 0x07F7D6, 0x07CF8E
- 0x07CF1A calls 0x07C8B7 at least twice in its 130B body
- 0x06868A is a descriptor-type dispatcher that routes to 0x07CFA7 (types 0x20/0x21) or 0x07CF1A (type 0x1C)
- The glyph rasterizer is at 0x0A1799 (38 call sites in ROM)
- The column wrapper is at 0x0A1B5B (110 call sites)
- D005F8 is the active descriptor (9 bytes). D005F9 holds the glyph code.
- Font table at ROM 0x003D6E, 28 bytes/glyph → RAM D005A1

## Your task
Create a probe file `TI-84_Plus_CE/probe-phase512-decode-07C8B7.mjs` that:

1. Reads ROM bytes starting at 0x07C8B7 (read ~200 bytes to capture the full function)

3. Identifies all CALL targets, JP targets, and RET instructions
4. Specifically checks whether 0x0A1799 (rasterizer) or 0x07D583 (populator) appear as call targets anywhere in the function body
5. Documents the function's purpose based on the instruction sequence

Read bytes directly from the `rom` buffer: `rom[addr]` for addresses < 0x400000. For eZ80 instructions:
- CALL nn = 0xCD followed by 3-byte little-endian address
- JP nn = 0xC3 followed by 3-byte address
- JP cc,nn = 0xC2/0xCA/0xD2/0xDA followed by 3-byte address
- CALL cc,nn = 0xC4/0xCC/0xD4/0xDC followed by 3-byte address
- RET = 0xC9
- RET cc = 0xC0/0xC8/0xD0/0xD8/0xE0/0xE8/0xF0/0xF8
- JR e = 0x18 followed by signed byte offset
- JR cc,e = 0x20/0x28/0x30/0x38 followed by signed byte offset
- RST n = 0xC7/0xCF/0xD7/0xDF/0xE7/0xEF/0xF7/0xFF
- DD/FD prefix = IX/IY instructions
- ED prefix = extended instructions (ED 4B = LD rr,(nn) etc.)
- CB prefix = bit operations

Print a hex dump of the first ~200 bytes, then list every CALL/JP target found, noting if any match 0x0A1799 or 0x07D583. Print a summary of the function structure.
