# Task: Decode 0x052Axx-0x0554xx BPP-Switching Cluster

## Context
The TI-84 Plus CE ROM at `TI-84_Plus_CE/ROM.rom` has been partially reverse-engineered. Session 554 fully mapped D000C6 — a single-purpose BPP flag where only bit 2 is ever tested. 6 of 7 references to D000C6 live in the 0x052Axx-0x0554xx range:

| ROM address | Instruction | Pattern |
|-------------|-------------|---------|
| 0x052ADE | LD A,(D000C6); BIT 2,A; JR Z,+9 | Z=16bpp jumps, NZ=8bpp falls through |
| 0x052BFB | LD A,(D000C6); BIT 2,A; JR NZ,+1 | NZ=8bpp jumps, Z=16bpp doubling loop |
| 0x052CE9 | LD A,(D000C6); BIT 2,A; JR NZ,+98 | NZ=8bpp jumps far forward |
| 0x052D82 | LD A,(D000C6); BIT 2,A; JR NZ,+81 | NZ=8bpp jumps forward |
| 0x05440B | LD A,(D000C6); BIT 2,A; JR NZ,+1 | Doubling loop pattern |
| 0x05529C | LD A,(D000C6); BIT 2,A; JR Z,+14 | Z=16bpp jumps |

This cluster is likely the main pixel-blitting / stride-doubling logic for the LCD driver.

## Task
1. **Find function boundaries** in the 0x052A00-0x055500 range. Look for RET instructions (0xC9), JP/CALL targets, and the standard eZ80 function prologue patterns. The goal is to identify how many functions exist in this ~2.7KB region and what each does.

2. **For each D000C6 reference**, disassemble ~30 bytes before and ~60 bytes after to understand the surrounding logic. Focus on:
   - What data they operate on (framebuffer pointers, pixel data, stride values)
   - Whether they're doing row-doubling (16bpp stride = 640B = 2× the 8bpp stride of 320B)
   - What other functions they CALL
   - What RAM addresses they read/write

3. **Identify the "doubling loop" pattern** at 0x052BFB and 0x05440B — these have `JR NZ,+1` which skips exactly one byte (likely a stride doubling). Decode what the +1 skip means in each case.

4. **Look for LDIR/LDI/LDDR instructions** in this region — these would indicate block copy operations (common in framebuffer blitting).

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase555-bpp-cluster.mjs`

The probe should:
- Import from `./cpu-runtime.js` and read ROM bytes
- For each of the 6 D000C6 references, hex-dump and annotate 30B before + 60B after
- Scan 0x052A00-0x055500 for RET (0xC9) to estimate function boundaries
- Scan for LDIR (0xED 0xB0), LDI (0xED 0xA0), CALL (0xCD) patterns
- Print annotated results

Use this pattern:
```javascript

```

Run the probe via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase555-bpp-cluster.mjs`
