# Task: Decode BCALL Entry 831 (0x060FEA) — Strongest Cursor Draw Candidate

## Context
We are transpiling the TI-84 Plus CE OS ROM (eZ80) to JavaScript. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB). We discovered the OS BCALL jump table at 0x020104 with 2,178 entries. Entry 831 at 0x060FEA is the STRONGEST cursor draw candidate because:
- It's immediately adjacent to entry 832 (0x061003 = cursor erase) in the bcall table
- It's called from 4 sites: 0x022D8A, 0x060F4D, 0x060FBF, 0x0B53E0
- The 0x060Fxx region contains cursor management code

## Deliverable
Create `TI-84_Plus_CE/probe-phase494-decode-060FEA.mjs` that:
1. Statically disassembles 0x060FEA from the ROM binary
2. Dynamically traces it with cursor position set

## Static disassembly
Read the ROM file and decode eZ80 instructions starting at 0x060FEA. Use the eZ80 decoder at `TI-84_Plus_CE/ez80-decoder.js`:

```javascript
import { createDecoder } from './ez80-decoder.js';
import fs from 'fs';

const rom = fs.readFileSync(new URL('./ROM.rom', import.meta.url));
const decoder = createDecoder();

let pc = 0x060FEA;
for (let i = 0; i < 80; i++) {
  const instr = decoder.decode(rom, pc);
  console.log(`0x${pc.toString(16).padStart(6,'0')}: ${instr.mnemonic} ${instr.operands || ''} [${instr.length} bytes]`);
  pc += instr.length;
  if (instr.mnemonic === 'RET' && !instr.operands) break;
}
```

Report: each instruction, any references to D00595/D00596 (cursor position), D0059C, D008D2/D008D5 (LCD registers), VRAM addresses (0xD40000+), calls to known functions (0x0A23C0 = setLCDWindow, 0x0A239E = drawPixelBlock, 0x0A2400 = pixelRenderer, 0x0059C6 = charRenderer, 0x061003 = cursorErase, 0x05E386 = validation).

## Dynamic trace
Using the CPU runtime:
```javascript
import { createCPU } from './cpu-runtime.js';
import { createPeripheralBus } from './peripherals.js';

const cpu = createCPU();
const peripherals = createPeripheralBus({ timerInterrupt: false });
cpu.attachPeripherals(peripherals);
const rom = fs.readFileSync(new URL('./ROM.rom', import.meta.url));
cpu.loadROM(rom);
```

1. Boot CPU ~200K steps from PC=0 to reach idle
2. Snapshot VRAM (0xD40000-0xD52C00)
3. Set D00595=3, D00596=10 (cursor at row 3, col 10)
4. Set IY=0xD00080
5. Set PC=0x060FEA, run up to 50K steps
6. Compare VRAM, report changed bytes, bounding box in pixel coords
7. Repeat with D00595=7, D00596=20
8. Report whether VRAM write position moved with cursor position

## Key questions to answer
- Does 0x060FEA write NON-white pixels to VRAM? (cursor draw writes black/colored, erase writes white)
- Does it read D00595/D00596 to compute VRAM position?
- Does it reference cursor glyph codes (0xE1, 0xE2, 0xE3)?
- Does it call 0x0059C6 (character renderer) or write VRAM directly?
- How many bytes/instructions until RET?
- What is the relationship to 0x061003 (cursor erase at entry 832)?

## Important constraints
- `createPeripheralBus({ timerInterrupt: false })` — timer causes infinite loops
- Step limit 50,000 (function may not return if it's a large routine)
- IY = 0xD00080
- Memory access: `cpu.memory[addr]` for reads, `cpu.memory[addr] = val` for RAM writes (>= 0xD00000)

## Probe safety
Run ONLY via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase494-decode-060FEA.mjs`
NEVER run bare `node` on probe files — they can infinite-loop inside a lifted block.
