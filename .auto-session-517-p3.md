# Auto-Session 517 — P3: Map the Key-to-Token Table at 0x061CFA-0x061DB1

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary).

Session 516 decoded 0x061D1A as one entry in a KEY-TO-TOKEN JUMP TABLE. The region 0x061CFA-0x061DB1 contains dozens of 4-byte entries in the pattern:
- `LD A,<token>` (2 bytes: 0x3E <token>)
- `JR 0x061DB2` (2 bytes: 0x18 <offset>)

Each entry maps a key event to an OS token byte. For example, 0x061D1A loads A=0x88 (the CLEAR token).

The common handler at 0x061DB2 stores the token to D008DF, calls 0x03E1B4 to process it, clears 4 flags, and longjmps back to the event loop.

## Task
Create a probe `TI-84_Plus_CE/probe-phase517-key-token-table.mjs` that:

1. Read ROM bytes from 0x061CFA to 0x061DB1 (183 bytes)
2. Scan for all `LD A,<imm8>; JR <offset>` patterns (0x3E xx 0x18 yy)
3. For each match, extract:
   - The ROM address of the entry
   - The token byte (the xx in `LD A,xx`)
   - The JR target (verify it points to 0x061DB2 or nearby)
4. Also scan for any other instruction patterns in the region (there may be multi-byte entries or different patterns)
5. Cross-reference the entry addresses with the 0x099921 event loop dispatch table from session 514:
   - Key dispatch entries from session 514 include targets like 0x099F49 (CLEAR), 0x099F68 ((-)), 0x09AF17, 0x09B65C, 0x099EF7, 0x09AEA6, 0x099A7E, 0x09AF3C, 0x099A7A, 0x09AEBC
   - Some of these handlers may JP to entries in the 0x061CFA-0x061DB1 table
6. Also check the TI-OS token table — tokens like 0x88 = CLEAR, 0x81-0x89 might be control tokens, 0x30-0x39 = digit tokens, 0x41-0x5A = alpha, etc.
