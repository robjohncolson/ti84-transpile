# Auto-Session 376 P3: Seed 0x020100 and 0xD177BA in Coldboot Boot Init

## Context

The TI-84 Plus CE OS has two dispatch gates that must be satisfied for key processing to work:
1. **Flash self-test gate**: mem[0x020100] must contain [0x5A, 0xA5, 0x00] (the "A55A" magic value read as little-endian)
2. **System flag gate**: mem[0xD177BA] must be 0x00

Without these seeds, even when the keyboard scan detects a key and _GetCSC returns a scan code, the dispatch path at 0x001713 hits RET NZ and execution falls to DI+HALT.

Currently, the coldboot initialization in `browser-shell.html` (function `initializeColdbootRuntime()` around line 1375) does NOT set these seeds. They need to be added to the "Initialize OS event loop RAM" section (around line 1449-1453).

## Task

Edit `TI-84_Plus_CE/browser-shell.html` to add both seeds to the coldboot initialization:

1. **Find the section** in `initializeColdbootRuntime()` that says `// Initialize OS event loop RAM` (around line 1449)

2. **Add these seeds** after the existing RAM initializations (after the `mem[0xD0009B] |= 0x40;` line):

```javascript
  // Flash self-test pass gate (0x001713 checks this via CALL 0x0008BB)
  mem[0x020100] = 0x5A;
  mem[0x020101] = 0xA5;
  mem[0x020102] = 0x00;

  // System flag clear gate (0x001713 checks LD A,(0xD177BA); OR A; RET NZ)
  mem[0xD177BA] = 0x00;
```

3. **Also add the seeds to the phase200-seeds.txt** if 0x020100 and 0xD177BA are not already listed there:
   - Check `scripts/transpile-ti84-rom.mjs` for how seeds are loaded

   - If NOT present, add them so the transpiler generates blocks for code that references these memory locations

4. **Run the golden regression** to confirm no breakage:
