# Task: Trace Block 0x001D37 in Detail

## Context
TI-84 Plus CE ROM transpilation project. OS ROM (eZ80) lifted to JS, executed in Node.js. Boot reaches 318 blocks.

Block 0x001D37 was discovered in session 357 after PLL bit 3 fix. It writes/reads port 0x28 (PLL), then reads port 0x03 (GPIO -> returns 0xEF). It does BIT 4,A on port 0x03 value.

Questions: What does bit 4 of port 0x03 control? Is 0xEF (bit 4=0) correct? What path after BIT 4,A?

## Deliverables

Create `TI-84_Plus_CE/probe-phase358-block-1D37.mjs` that:

1. Disassembles block 0x001D37 from ROM bytes through next RET/JP/HALT terminator (~40-60 bytes). Show address, raw bytes, eZ80 ADL mnemonic.

2. Dynamically traces block 0x001D37 during boot (~20000 steps):
   - Step number when it first executes
   - All port reads/writes within this block
   - Register state (A, F flags, BC, DE, HL) when block executes
   - BIT 4,A test result and which branch taken

3. Static ROM scan: all IN0/OUT0 instructions targeting port 0x03. Opcode patterns: ED 38 03 = IN0 A,(0x03), ED 39 03 = OUT0 (0x03),A, ED 00 03 = IN0 B,(0x03), ED 08 03 = IN0 C,(0x03), etc. List each ROM address and instruction.

4. Analysis: based on ROM context, what does bit 4 of GPIO port 0x03 likely represent? (Battery, USB, on-calc status?)
