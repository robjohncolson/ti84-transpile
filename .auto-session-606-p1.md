# Task: Decode ROM address 0x048BFB (first wipe caller)

## Context
In the TI-84 Plus CE ROM transpilation project, we've traced the bulk RAM wipe at 0x0018F8 during key processing. Session 603 found the full call chain: cxMain→key handler→convergence→0x05899D→deep OS routines (0x0913B0/0x08F877/0x08FAFA/0x09081F)→memory management chain (0x048Bxx/0x04E0xx/0x049xxx)→flash/storage ops→0x02AF0F+0x002696 loop→0x0BCB2F→0x0013C3→0x001988→0x0158xx→0x001872→0x001879→0x0018F8.

**0x048BFB** is at frame 29 of Hit #1's call stack — where the key dispatch path enters the memory management subsystem that ultimately triggers the 82KB bulk RAM clear. We need to understand WHAT this function does and WHY it calls the wipe.

## Task
Create a probe at `TI-84_Plus_CE/probe-phase606-decode-048bfb.mjs` that:

1. **Statically decodes 0x048BFB** — read ROM bytes starting at 0x048BF0 (give 11 bytes of lead-in for context) through 0x048C80 (~144 bytes). Print hex dump + disassembly using the project's decoder.
2. **Also decode nearby functions**: 0x048B00-0x048BFA (the ~256 bytes BEFORE 0x048BFB) to understand the broader function this entry point belongs to.
3. **Cross-reference callers**: search the ENTIRE ROM (4MB, `rom` buffer) for 3-byte CALL targets and JP targets matching 0x048BFB (little-endian bytes: 0xFB, 0x8B, 0x04). Report all call sites.
4. **Decode 0x04E0xx cluster**: also decode 0x04E000-0x04E080 (~128 bytes) — another memory management function in the call chain.

## Implementation Pattern
```javascript
import { readFileSync } from 'fs';
import { decodeInstruction } from './ez80-decoder.js';

const rom = readFileSync('TI-84_Plus_CE/ROM.rom');

function disasmRange(start, end) {
  let pc = start;
  while (pc < end) {
    const instr = decodeInstruction(rom, pc);
    const bytes = Array.from(rom.slice(pc, pc + instr.length)).map(b => b.toString(16).padStart(2,'0')).join(' ');
    console.log(`  0x${pc.toString(16).padStart(6,'0')}: ${bytes.padEnd(20)} ${instr.mnemonic} ${instr.operands || ''}`);
    pc += instr.length;
  }
}

// Decode 0x048B00-0x048C80
console.log('=== 0x048B00-0x048C80 (0x048BFB context) ===');
disasmRange(0x048B00, 0x048C80);

// Decode 0x04E000-0x04E080
console.log('\n=== 0x04E000-0x04E080 (memory mgmt cluster) ===');
disasmRange(0x04E000, 0x04E080);

// Cross-reference: find all CALL/JP to 0x048BFB
const target = [0xFB, 0x8B, 0x04]; // little-endian 0x048BFB
let callers = [];
for (let i = 0; i < rom.length - 3; i++) {
  if (rom[i+1] === target[0] && rom[i+2] === target[1] && rom[i+3] === target[2]) {
    const opcode = rom[i];
    if (opcode === 0xCD || opcode === 0xC3 || (opcode >= 0xC2 && opcode <= 0xFA && (opcode & 0x07) === 0x02 || (opcode & 0x07) === 0x03)) {
      callers.push({ addr: i, opcode: opcode.toString(16) });
    }
  }
}
console.log(`\n=== Callers of 0x048BFB: ${callers.length} ===`);
callers.forEach(c => console.log(`  0x${c.addr.toString(16).padStart(6,'0')}: opcode 0x${c.opcode}`));
```
