# Task: Map the Event Dispatcher Jump Tables for USB/Link Init

## Context
You are working on the TI-84 Plus CE ROM transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile/`. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary).

## What We Know
- Three callers of 0x00CC71 (the descriptor init wrapper) are all reached via computed jumps, NOT direct CALL/JP:
  - 0x008A52 — USB init handler (439 bytes), pushes 0/2/2000
  - 0x008EB5 — Link/serial init handler (153 bytes), pushes 0/1/300
  - 0x0126F5 — USB alt-mode handler (54 bytes), pushes 0/1/1000
- Session 428 confirmed: zero direct CALL/JP references to any of these 3 addresses in the entire 4MB ROM.
- They must be reached via jump tables — arrays of addresses that a dispatcher indexes into.
- eZ80 jump table pattern: typically loads an index, multiplies by entry size (3 bytes for 24-bit addresses), adds to a base table address, then JP (HL) or equivalent.

## Deliverables
1. Create `TI-84_Plus_CE/probe-phase429-map-jump-tables.mjs` — a Node.js probe that:
   - Reads the entire ROM binary
   - For each of the 3 target addresses (0x008A52, 0x008EB5, 0x0126F5):
     - Searches the ROM for the 3-byte little-endian encoding of the address
     - Example: 0x008A52 = bytes 52 8A 00
     - Example: 0x008EB5 = bytes B5 8E 00
     - Example: 0x0126F5 = bytes F5 26 01
     - Reports every location where these bytes appear (these are likely jump table entries)
   - For each jump table found:
     - Reads adjacent entries (before and after the matching entry) to find the full table
     - A jump table is a sequence of 3-byte addresses, typically in the 0x00xxxx-0x01xxxx range
     - Reports the table base address, number of entries, and all target addresses
   - Looks backward from each table to find the dispatcher code that references it

2. Create `TI-84_Plus_CE/phase429-jump-tables-report.md` with:
   - For each of the 3 addresses: where in ROM the address appears as data
   - The jump table(s) found: base address, entry count, all entries
   - The dispatcher function(s): where they are, what index variable they use
   - What other case handlers exist in the same tables (these are sibling event handlers)
   - What event/message codes map to USB init, Link init, and alt-mode init

## Reference
- The _seqcase pattern is common in this ROM for dispatching: CALL 0x002623 (_seqcase) followed by inline case data
- But computed JP (HL) via table lookup is also used
- The ROM uses both patterns — check for both

## Approach
1. Search for each 3-byte address pattern in the ROM
2. When found, check if the surrounding bytes also look like valid code addresses (0x00xxxx-0x05xxxx range)
3. If so, you've found a jump table — read the full table
4. Look backward ~50-100 bytes for the dispatcher that computes the index and jumps through this table
