# Session 254 P2: 0x056900 Dispatch Table Populator Trace

## Context
The TI-84 Plus CE OS has a dynamic dispatch table with head pointer at RAM 0xD0231A and tail at 0xD0231D. Address 0x056900 is documented as the "dispatch table populator (dynamic-only)". Session 253 proved that handler 0x062055 has ZERO static callers and must be registered in a RAM dispatch table at runtime. We need to understand HOW handlers get registered.

## Task
Create a probe file `TI-84_Plus_CE/probe-phase254-dispatch-table-pop.mjs` that:

1. Full OS boot (z80 boot → kernelInit → memInit → homescreen stages 1-4)
2. **Watchpoints on D0231A-D0231F** (head/tail pointers) — log every write with step, PC, value
3. **Watchpoint on calls to 0x056900** — log when this address is reached during execution
4. After boot, dump the RAM region around D0231A-D02330 (hex dump, 24 bytes)
5. If D0231A/D0231D contain valid pointers after boot, follow them and dump the dispatch table entries they point to

## Boot Sequence
Look at `TI-84_Plus_CE/probe-phase99d-home-verify.mjs` for the canonical boot sequence. It uses:
- `createCPU(rom)` from cpu-runtime.js
- `createPeripheralBus({ timerInterrupt: false })` from peripherals.js
- Full boot with homescreen stages

Instrument `write8` to catch writes to 0xD0231A-0xD0231F:
```javascript
const origWrite8 = cpu.write8.bind(cpu);
cpu.write8 = function(addr, val) {
  if (addr >= 0xD0231A && addr <= 0xD0231F) {
    console.log(`[DISPATCH TABLE PTR WRITE] addr=0x${addr.toString(16)} val=0x${val.toString(16).padStart(2,'0')} step=${stepCount} PC=0x${cpu.pc.toString(16).padStart(6,'0')}`);
  }
  return origWrite8(addr, val);
};
```

Also check if execution ever reaches 0x056900 by watching for that PC value during block execution.
