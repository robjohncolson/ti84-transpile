# Auto-Session 362 — P3: Trace 0x000EA0 Alternate Path

## Context

TI-84 Plus CE ROM transpilation project. During boot, block 0x000E77 branches based on GPIO bit 4:
- GPIO bit 4 = 0 (GPIO=0xEF, our standard path): takes one branch
- GPIO bit 4 = 1 (GPIO=0xFF): jumps to 0x000EA0

The standard boot path uses GPIO=0xEF. We want to know what the 0x000EA0 alternate path does without changing our main boot path.

## Task

Write a probe script `TI-84_Plus_CE/probe-phase362-trace-EA0-path.mjs` that:

1. **Disassembles block 0x000EA0** using raw ROM bytes from `TI-84_Plus_CE/ROM.rom`. The eZ80 is in ADL mode. Use:
   ```js
   import { decodeInstruction } from './ez80-decoder.js';
   // decodeInstruction(romBuffer, offset, adlMode) returns {mnemonic, operands, length}
   ```
   Disassemble from 0x000EA0 until RET/JP/unconditional-JR or 128 bytes, whichever comes first.

2. **Also disassembles block 0x000E77** for context — show what the branch condition looks like and where each branch goes.

3. **Runs a boot with GPIO=0xFF** (bit 4 = 1):
   - Timer interrupts disabled
   - Override GPIO port 0x03 to return 0xFF
   - RAM trampoline enabled
   - Run for 5000 steps
   - Record: total unique blocks, termination reason, termination address

4. **Compares with GPIO=0xEF boot** (our standard path):
   - Run the same boot with GPIO=0xEF
   - Compare: unique block counts, termination addresses, which blocks are exclusive to each path

5. **Traces port I/O** in the GPIO=0xFF path — record all IN/OUT instructions and their port/value pairs for the first 200 steps. This reveals what hardware the alternate path configures.

6. **Identifies the function of 0x000EA0** — based on the disassembly and trace, what is this block? Flash configuration? RAM test? Keyboard init? Security check?
