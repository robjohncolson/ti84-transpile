# Auto-Session 213 P2: Test 0x080D09 "Display Result" Loop

## Context
Session 209 confirmed that block 0x080D08 contains a "display result" loop:
```
LD HL, 0xD0060E   (format buffer, near OP1 region)
loop:
  LD A, (HL)
  LD DE, 0
  LD E, A
  INC HL
  OR A
  JR Z, exit
  PUSH HL
  CALL 0x05E2A0    (BufInsert)
  POP HL
  JR NZ, loop      (actually JR loop — unconditional back to LD A,(HL))
exit:
  CALL 0x05E3AE
  RES 5,(IY+5)
  RET
```

This loop copies null-terminated ASCII from the format buffer at 0xD0060E into the edit buffer via BufInsert. It's the OS path for displaying computed numeric results.

## Task
Create a probe file `TI-84_Plus_CE/probe-phase213-display-result-loop.mjs` that:

### Part A: Basic format buffer → edit buffer test
- Boot sequence: cold boot → kernelInit → postInit → memInit (same as probe-phase212-multi-digit-entry.mjs)
- After boot, seed the format buffer at 0xD0060E with ASCII "42.5\0" (bytes: 0x34, 0x32, 0x2E, 0x35, 0x00)
- Set up edit buffer pointers:
  - editTop (0xD02437) = 0xD00A00
  - editCursor (0xD0243A) = 0xD00A00
  - editTail (0xD0243D) = 0xD00A00
  - editBtm (0xD02440) = 0xD00B00
- Zero the edit buffer region 0xD00A00-0xD00B00
- Set BIT 4,(IY+5) (edit mode flag) — OR 0x10 into mem[0xD00085]
- Push return sentinel 0x7FFFFE on stack
- Set PC = 0x080D08 (note: block entry is 0x080D08, the LD HL instruction is at 0x080D09)
- Run up to 500 steps with maxLoopIterations=256
- Report: steps taken, BufInsert call count (count how many times block 0x05E2A0 is visited), edit buffer contents at 0xD00A00-0xD00A10, final cursor position at 0xD0243A

### Part B: Longer string test
- Same setup, but seed format buffer with "3.14159265\0" (10 chars + null)
- Run and report same metrics
- Verify each character appears in edit buffer in order

### Part C: Empty string test
- Seed format buffer with just "\0" (single null byte at 0xD0060E)
- Run and verify BufInsert is NOT called (loop should exit immediately)
- Report steps and edit buffer (should remain zeroed)
