# Task: Trace the kbdKey↔kbdToken swap in 0x030300

## Context
You are working on TI-84 Plus CE ROM transpilation. The ROM file is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary).

Session 389 disassembled 0x030300 and found the normal key path at 0x03032C performs a curious swap:
- Reads D00001 → writes to D0058C (kbdKey)
- Reads D00002 → if nonzero: swaps kbdKey↔kbdToken (D0058C↔D0058E)
  - Reads old kbdKey from D0058C, writes it as kbdToken to D0058E
  - Writes D00002 value as new kbdKey to D0058C
- Then JP 0x02FE73 (loops back to caller)

Questions to answer:
1. What are D00001 and D00002? Are they the event struct bytes built by 0x0236F9 (the key event builder)?
2. If byte 0 = action code and byte 1 = context mode and byte 2 = conditional modifier, what does the swap mean?
3. Under what conditions is D00002 nonzero? What keys or modes trigger the swap?

## eZ80 Encoding Reference
- ADL mode: all addresses are 24-bit (3 bytes, little-endian)
- LD A,(nn) = 0x3A + 3-byte address (little-endian)
- LD (nn),A = 0x32 + 3-byte address (little-endian)
- LD HL,(nn) = 0xED 0x6B + 3-byte address (extended, 24-bit load)  
- OR A = 0xB7 (test if A is zero)
- JP nn = 0xC3 + 3-byte address
- JR NZ,e = 0x20 + signed offset
- CALL nn = 0xCD + 3-byte address
- RET = 0xC9

## Byte pattern scan
To find references to a RAM address like 0xD00001 in eZ80 little-endian encoding, search for bytes: 0x01, 0x00, 0xD0 in sequence anywhere in the ROM. Not all hits will be actual address references (some may be coincidental data), but cross-reference with surrounding opcode context to filter.
