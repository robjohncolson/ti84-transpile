# Task: Trace why 0x03FA09 clobbers HL in the 0x03FC1C key code converter

## Context
The function at 0x03FC1C is a key code converter that reads D0058D (compact keyboard matrix index 1-56), looks up a key code in a 56-entry table at 0x03FC41, and returns the key code in HL. The function structure is:

```
0x03FC1C: LD HL,D0058D; LD A,(HL); OR A; JR NZ,...
  zero path: LD H,A; LD L,A; JR to common tail
  nonzero path: LD DE,0; LD E,A; LD (HL),D (clears D0058D); LD HL,0x03FC41; ADD HL,DE; LD L,(HL); LD H,D (table lookup)
common tail: PUSH HL; CALL 0x03FA09; POP HL; PUSH AF; CALL 0x0AF8C4; POP AF; RET
```

**Problem**: Despite PUSH HL / CALL 0x03FA09 / POP HL, testing shows HL=0xD00604 for ALL 55 indices instead of distinct key codes. The sub-calls 0x03FA09 and/or 0x0AF8C4 clobber HL somehow.

The PUSH HL should save HL, and POP HL should restore it. But session 227 found HL=0xD00604 universally. Either:
1. 0x03FA09 corrupts the stack (modifies SP or does extra PUSH/POP that misaligns)
2. The POP HL at the common tail picks up a different value because of stack manipulation inside 0x03FA09
3. The transpiled block boundaries break the PUSH/POP pairing

## Deliverables

Create a probe file `TI-84_Plus_CE/probe-phase228-03fa09-hl-clobber.mjs` that:

1. **Static disassembly of 0x03FA09**: Read ROM.rom bytes starting at 0x03FA09 for ~100 bytes. Decode the eZ80 instructions manually (reference the decoder patterns in `TI-84_Plus_CE/ez80-decoder.js`). Identify all PUSH/POP instructions, RET instructions, and any SP modifications. Check if the function does unbalanced PUSH/POP that would misalign the stack for the caller's POP HL.

2. **Dynamic stack trace**: Set up a runtime (use `TI-84_Plus_CE/cpu-runtime.js` and the transpiled ROM), seed D0058D=34 (which should map to key code 0x8F for '1' per the table at 0x03FC41). Execute from 0x03FC1C with a step limit of 100. At each step, log: PC, SP, and the top 4 bytes of the stack. This will show exactly when HL gets pushed, what happens to the stack during 0x03FA09, and what gets popped.

3. **Verification**: After the function returns, check:
   - What value was in HL just before the PUSH HL (should be the table lookup result)
   - What value SP had before and after the CALL 0x03FA09
   - What value POP HL actually restored
