# Task: Trace inside 0x05D58F (Key Action Dispatcher) — What happens AFTER the key code arrives?

## Context

The TI-84 Plus CE ROM at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary) has a key dispatch chain:
- RAM 0xD141B5 holds the pressed key scan code
- 0x02BD96 reads D141B5, then CALLs 0x05D58F and 0x02B373
- 0x05D58F is the "key action dispatcher" (identified in session 400)

Session 400 decoded 0x05D58F at a high level but did NOT trace its internal logic deeply. Session 408 confirmed this is THE key dispatch bottleneck — all key processing funnels through 0x02BD96 → CALL 0x05D58F.

## Your task

Write a probe script at `TI-84_Plus_CE/probe-phase409-trace-05D58F.mjs` that:

1. Reads `TI-84_Plus_CE/ROM.rom` as a binary buffer
2. Disassembles 0x05D58F and follows its control flow (at least 200 bytes deep)
3. Answers these specific questions:
   - Does 0x05D58F use a dispatch table (array of JP/CALL targets indexed by key code)?
   - Does it use a CP cascade (sequential CP nn / JR Z,target comparisons)?
   - Does it use a computed jump (JP (HL) or similar)?
   - What are the first 10-20 branch targets?
   - Does it call any subroutines? If so, list their addresses.
   - What RAM addresses does it read/write?

4. Also write a report at `TI-84_Plus_CE/phase409-trace-05D58F-report.md` summarizing findings

## eZ80 reference

eZ80 is a Z80 superset with 24-bit addresses. Key opcodes:
- `CD xx xx xx` = CALL addr (4 bytes in ADL mode)
- `C3 xx xx xx` = JP addr (4 bytes)  
- `FE xx` = CP n (compare A with immediate)
- `28 xx` = JR Z,offset (relative jump if zero)
- `20 xx` = JR NZ,offset
- `CA xx xx xx` = JP Z,addr (4 bytes)
- `C2 xx xx xx` = JP NZ,addr
- `E9` = JP (HL)
- `C9` = RET
- `3A xx xx xx` = LD A,(addr) — reads RAM
- `32 xx xx xx` = LD (addr),A — writes RAM
- `21 xx xx xx` = LD HL,addr
- `CB 7F` = BIT 7,A
- `E6 xx` = AND n
- `ED B1` = CPIR (compare, increment, repeat)

Little-endian for all multi-byte values. Addresses are 3 bytes in ADL mode.
