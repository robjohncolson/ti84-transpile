# Task: Trace Missing_Block Terminators in the Text Rendering Path

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The transpiled JS is at `TI-84_Plus_CE/ROM.transpiled.js.gz`. The CPU runtime is at `TI-84_Plus_CE/cpu-runtime.js`.

Session 331's PutC pipeline probe found that during a dynamic trace, **0 PutC calls occurred** because execution hit `missing_block` before any text rendering happened. The PutC pipeline is:
- Syscall vectors (0x021E00 JP table) → ROM callers → PutC wrappers
- PutC_draw_advance at 0x0540D0 (10 callers: 1 syscall vector 0x021E00, 5 status bar 0x023Dxx-0x023Exx, 3 home screen 0x0255xx, 1 graph 0x09ED9F)
- PutC_draw_only at 0x0540F5 (1 caller: _PutMap at 0x022178)
- Inner function 0x05411A → DrawChar vtable dispatch

The home screen render path starts from the boot sequence (see `probe-phase99d-home-verify.mjs` for the working boot that does render text). The workflow probe (`probe-workflow-arithmetic.mjs`) shows that AFTER boot, keypress injection terminates at `missing_block` with lastPc=0xffffff.

## Your Task
1. **Identify which specific blocks are missing** on the path from the OS event loop entry back to PutC. The key question: after the home screen initial render succeeds (golden regression passes), what happens when a keypress is injected? Where does execution try to go that hits missing_block?

2. **Trace the event loop re-entry path**. After home screen init, the OS should enter a main loop waiting for keys. When _GetCSC returns a scan code (via ISR at 0x080259 → SDK 0x03FA09), where does the foreground code pick it up? The known chain is:
   - Key ISR deposits scan code
   - Foreground polls via _GetCSC (entry 0x021C00 or similar)
   - CoorMon dispatch (0x058xxx range) routes token
   - Eventually calls PutC for display

3. **For each missing block found**, check the ROM at that address — is it:
   - Genuinely missing from the transpiler's seed list? (check `scripts/transpile-ti84-rom.mjs` for seeds)
   - A data region misidentified as code?
   - A block that exists but has an incorrect jump target?

4. **Can any missing blocks be trivially added as seeds?** If a block is clearly code (starts with a valid instruction sequence), note its address for the next transpiler run.

## Method
- Boot the runtime using the pattern from `probe-phase99d-home-verify.mjs`
- After boot completes (home screen rendered), inject a keypress and trace execution with step counting
- When missing_block is hit, capture the PC that was being jumped to
- Check if that PC exists as a block in the transpiled JS
- Read ROM bytes at that address to determine if it's code

Reference files:
- `TI-84_Plus_CE/probe-phase99d-home-verify.mjs` — working boot sequence
- `TI-84_Plus_CE/probe-workflow-arithmetic.mjs` — shows the failure pattern
- `TI-84_Plus_CE/cpu-runtime.js` — has the missing_block handler

## Deliverables
Create `TI-84_Plus_CE/probe-phase332-missing-blocks.mjs` that:
- Boots to home screen (reuse golden regression boot pattern)
- Injects a keypress (scan code 0x41 = key '1')
- Traces execution capturing every missing_block hit
- For each missing block: reads ROM bytes at that address, attempts to identify if it's code
- Reports: [missing_address, rom_bytes_hex, likely_code_or_data, suggested_seed]
