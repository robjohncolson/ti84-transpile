# Auto-Session 379 — P3: Investigate the 0x3B0001 Action Table

## Context

The TI-84 Plus CE ROM transpilation project lifts eZ80 machine code to JavaScript. Session 378 traced the post-key handler at 0x0158DE and found it calls 0x0158BC, which reads from a linked data structure at 0x3B0001+ in ROM. This appears to be a key-action dispatch table that maps scan codes to OS actions.

From session 378:
- 0x0158DE is a post-key-action dispatcher
- It checks bit 7 of (IY+0x42)=0xD000C2 as a re-entry guard
- If clear, calls 0x0158BC which reads from 0x3B0001+ in ROM
- 0x0158BC calls through 0x001C55/0x001C33/0x001C4F/0x001CA6 which parse entries from the table
- With ENTER key, 0x0158BC returned carry/zero → Z-return path taken → returned A=0 (no action)

```javascript
import { decode } from './ez80-decoder.js';
import fs from 'fs';

const rom = fs.readFileSync('./TI-84_Plus_CE/ROM.rom');
let pc = 0x0158BC;
for (let i = 0; i < 50; i++) {
  const instr = decode(rom, pc);
  console.log(`0x${pc.toString(16).padStart(6,'0')}: ${instr.mnemonic} ${instr.operands || ''} [${instr.length} bytes]`);
  pc += instr.length;
}
```

### Part 2: Dump the table at 0x3B0001

The ROM table at 0x3B0001 is in the ROM file. Read and dump the raw bytes:

```javascript
const tableStart = 0x3B0001;
// Read first 256 bytes of the table
const tableData = rom.slice(tableStart, tableStart + 256);
console.log('Table at 0x3B0001:');
for (let i = 0; i < 256; i += 16) {
  const hex = Array.from(tableData.slice(i, i+16)).map(b => b.toString(16).padStart(2,'0')).join(' ');
  console.log(`  0x${(tableStart+i).toString(16).padStart(6,'0')}: ${hex}`);
}
```

Look for patterns: are entries fixed-size? Do they contain scan code values? Address pointers? Identify the entry format.
