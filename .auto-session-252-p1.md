# Task: Trace callers of 0x0620C4 (the single bridge to cxMain)

## Context
In the TI-84 Plus CE ROM transpilation project, session 251 discovered that **0x0620C4** is the ONLY call site in the entire ROM that calls `CALL 0x058241` (the cxMain pre-handler). This makes 0x0620C4 the single bridge between the OS event loop and cxMain (the home-screen key dispatch system).

We need to find what calls 0x0620C4 or its parent function, to understand how the event loop reaches cxMain.

## Deliverable
Create a probe file: `TI-84_Plus_CE/probe-phase252-0620c4-callers.mjs`

## What the probe must do

1. **Static ROM scan**: Read `TI-84_Plus_CE/ROM.rom` as a binary buffer. Search the ENTIRE 4MB ROM for:
   - `CD C4 20 06` (ADL CALL 0x0620C4) — 4-byte pattern
   - `C3 C4 20 06` (ADL JP 0x0620C4) — 4-byte pattern
   - `CA C4 20 06` (JP Z,0x0620C4)
   - `C2 C4 20 06` (JP NZ,0x0620C4)
   - `DA C4 20 06` (JP C,0x0620C4)
   - `D2 C4 20 06` (JP NC,0x0620C4)
   
   Also search for references to a reasonable parent function. To find the parent function boundary:
   - Scan backwards from 0x0620C4 looking for a RET (0xC9) or unconditional JP — the byte after that is likely the function entry.
   - Then search for CALL/JP to THAT entry address.

2. **Find the function containing 0x0620C4**: Disassemble ROM bytes from ~0x062080 to 0x0620D0 to understand the local context. Use the eZ80 ADL instruction encoding:
   - 0xCD = CALL nn (4 bytes: CD + 3-byte little-endian address)
   - 0xC9 = RET (1 byte)
   - 0xC3 = JP nn (4 bytes)
   - 0x18 = JR d (2 bytes: 18 + signed offset)
   - 0x20 = JR NZ,d (2 bytes)
   - 0x28 = JR Z,d (2 bytes)
   - 0xCB xx = BIT/SET/RES prefix
   - 0xFD 0xCB xx yy = IY bit operations
   - 0x3E = LD A,n (2 bytes)
   - 0x21 = LD HL,nn (4 bytes in ADL mode: 21 + 3-byte LE)

3. **Report**: Print all call/jump sites found, the parent function entry address, all callers of the parent, and the disassembly context around 0x0620C4.

## Technical details
- ROM file: `TI-84_Plus_CE/ROM.rom` (4,194,304 bytes)
- Use `import { readFileSync } from 'fs'` and `Buffer` operations
- ROM is flat binary, address 0x000000 = byte offset 0
- eZ80 ADL mode: all addresses are 3 bytes (24-bit), little-endian
- The CALL at 0x0620C4 is: bytes `CD 41 82 05` (CALL 0x058241)
