# P3: Trace 0x0AF29B — INC (HL) that increments D02662

## Context
Session 296 mapped D02662 write sites:
- 0x0AF273: save-then-clear (XOR A → LD (D02662),A = writes 0x00)
- 0x0AF2BA: POP AF → restore (writes saved value)
- 0x0AF29B: LD HL,0xD02662 → INC (HL) — INCREMENTS D02662

D02662 reaches value 0x03 by REPEATED INCREMENTS (not direct store). The 2-state predicate at 0x0AF877 checks D02661/D02662 mode state. Understanding the increment loop tells us when the 0x83/0x03 predicate activates.

## Task
Build a probe `TI-84_Plus_CE/probe-phase297-0af29b-inc-loop.mjs` that:

1. **Disassembles the function containing 0x0AF29B**. The instruction at 0x0AF29B is `LD HL,0xD02662` followed by `INC (HL)`. Find the function boundaries by looking for the entry point (search backward for a plausible function start — look for block keys near 0x0AF2xx in BLOCKS).

2. **Map the calling context**: What calls the function containing 0x0AF29B? Search the transpiled blocks for references to addresses near 0x0AF29B (grep BLOCKS keys in the 0x0AF2xx range, then search for CALL/JP instructions targeting those addresses).

3. **Dynamic trace**: Set PC=0x0AF29B (or the function entry), set up memory so D02662 starts at 0x00, and step through. Log each block, registers, and the value of mem[0xD02662] after each step. See how many increments happen and what triggers the exit.

4. **Also trace 0x0AF273** (the save-then-clear site) and **0x0AF2BA** (the restore site) to understand the save/clear/increment/restore lifecycle of D02662.
