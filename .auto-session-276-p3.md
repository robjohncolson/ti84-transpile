# Task: Investigate 0x0230E7/0x0230FD — LDIR-copy 9-byte entries after CALL 0x0846EA

## Context
This is a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB eZ80 binary). We've discovered a dispatch table mechanism:

- **0x0846EA** is a table lookup function. After it returns, the carry flag indicates found/not-found.
- At sites 0x0230E7 and 0x0230FD, after CALL 0x0846EA returns, the code does `EX DE,HL` then `LDIR BC=9` — copying a 9-byte entry
- Session 275 finding: "0/200 reached handler in 200 steps — dispatch happens AFTER the flag check, not inline. Site 0x0230E7: EX DE,HL then LDIR BC=9 — copies the 9-byte entry, NOT a jump dispatch."
- The actual handler invocation must happen further up the call chain
- Related sites that also do EX DE,HL after 0x0846EA: 0x02859C, 0x06F502

## Task
Write a Node.js probe at `TI-84_Plus_CE/probe-phase276-ldir-copy-sites.mjs` that:

1. **Statically disassembles 0x0230D0-0x023120 and 0x0230F0-0x023120** by reading ROM bytes from `TI-84_Plus_CE/ROM.rom`. Decode eZ80 ADL-mode instructions. For each LDIR-copy site, determine:
   - Source address (HL before EX DE,HL → DE after = table entry address?)
   - Destination address (DE before EX DE,HL → HL after = RAM buffer?)
   - What happens after the LDIR — does the code call a handler? Return? Jump?
   - What is the parent function? Find the nearest RET before 0x0230E7 to identify function boundaries.

2. **Statically disassembles 0x028590-0x0285C0 and 0x06F4F0-0x06F520** for the related EX DE,HL sites. Same analysis.

3. **Dynamically traces 0x0230E7** using the transpiled runtime:
   - Boot CPU (PC=0x000000) for 50,000 steps
   - Seed D0259A to 0xD3FFF6 (1 entry in table)
   - Populate a fake 9-byte entry at D3FFF6: bytes [0x41, 0x82, 0x05, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00] (handler=0x058241, rest zero)
   - Set HL to point at the entry (0xD3FFF6), or whatever register 0x0846EA returns the result in
   - Set PC to just after the CALL 0x0846EA return (the EX DE,HL instruction)
   - Run 200 steps, tracking: where does the copied entry go? What RAM address? What happens next?

4. **Report**: Where do the 9-byte entries get copied to? What uses the copy? Is this a "cache current entry" pattern?

## eZ80 ADL instruction reference
- `EB` = EX DE,HL (swap DE and HL)
- `ED B0` = LDIR (copy BC bytes from HL→DE, decrement BC)
- `01 xx xx xx` = LD BC,imm24
- `CD xx xx xx` = CALL addr24
- `C9` = RET
- `ED 6B xx xx xx` = LD HL,(xxxx)
