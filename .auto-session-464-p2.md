# Session 464 P2: Trace D00085 Bit 3 Chain + Decode 0x0059C6

## Context

The TI-84 CE OS scheduler at 0x0015F7 has this sequence after 0x0066FF returns NZ:

```
0x0015E1: SET 3,(IY+5)    ; IY=D00080, so this sets D00085 bit 3
0x0015E5: LD A,0x0A
0x0015E7: LD HL,0x001900
0x0015EA: LD (D00595),HL
0x0015ED: CALL 0x0059C6
0x0015F0: RES 3,(IY+5)    ; clear D00085 bit 3
0x0015F3: ...continues...
```

We need to understand:
1. What does 0x0059C6 do? What is it called with (A=0x0A, HL=0x001900 stored at D00595)?
2. Who else reads D00085 bit 3? (IY+5 with IY=D00080 → address D00085)
3. What is the connection between D00085 bit 3 and the key processing path at 0x03FA09?

## Task

Create a Node.js probe at `TI-84_Plus_CE/probe-phase464-d00085-bit3-chain.mjs` that:

1. Boots the OS using the standard 3-stage boot pattern (see any existing probe like `probe-phase463-real-scheduler.mjs` for the boot pattern)
2. After boot, hooks address 0x0059C6 to trace when it's called and what registers contain
3. Hooks address 0x0015E1 (SET 3,(IY+5)) to trace the scheduler key-detection path
4. Hooks address 0x03FA09 to see if key processor is ever reached
5. Also search the ROM binary for all BIT 3,(IY+5) instructions — opcode is FD CB 05 5E — to find all readers of D00085 bit 3
6. Search the ROM binary for all SET 3,(IY+5) instructions — opcode is FD CB 05 DE — to find all writers
7. Search the ROM binary for all RES 3,(IY+5) instructions — opcode is FD CB 05 9E — to find all clearers
8. Disassemble the first ~50 bytes of function 0x0059C6 from ROM to understand what it does

## Important Notes

- The IY register is set to 0xD00080 by the OS, so (IY+5) = D00085
- D00085 bit 3 is the "key available" flag in the scheduler
- D00080 bit 3 is a DIFFERENT flag used by _GetCSC in the error handler path
- You do NOT need to run the full transpiled OS for this — pure ROM binary analysis is sufficient
- Do NOT boot the OS or import cpu-runtime.js — just analyze the ROM binary
