# Auto-Session 231 — P3: Cross-Reference 09F79B Table with ConvKeyToTok Tables

## Context
Two key code mapping systems exist in the ROM:
1. **09F79B table** (ISR path): 224 entries (4 sections × 56), mapped in session 230. JSON at `phase230-09f79b-full-table.json`. Accessed via 0x03011C → writes to D0058E. Offset formula: scanCode + (alpha?0x70:0) + (2nd?0x38:0).
2. **ConvKeyToTok tables** (foreground path): Primary at 0x05BF84 (166 entries), plus 4 secondary tables. Mapped in session 186. JSON at `phase186-keytok-tables.json`.

The 09F79B table produces **key codes** (0x80+ range, written to D0058E). ConvKeyToTok takes these key codes and converts them to **tokens** (0x30-0x39 for digits, 0x70 for +, etc.). The two systems should be consistent: for any scan code, the 09F79B key code should be a valid input to ConvKeyToTok, and the resulting token should match expectations.

## Task
Create a probe `TI-84_Plus_CE/probe-phase231-table-crossref.mjs` that:

1. **Load both JSON files**: Read `phase230-09f79b-full-table.json` and `phase186-keytok-tables.json`.

2. **For each non-zero entry in the 09F79B no-mod section** (first 56 entries):
   - The entry value is a key code (e.g., 0x8F for digit 1)
   - Look up this key code in ConvKeyToTok's primary table (0x05BF84, indexed by keyCode - 0x5A since the table covers key codes 0x5A-0xFF)
   - Report: scan code index → 09F79B key code → ConvKeyToTok token
   - Flag any mismatches where the key code is in range but the token is 0x00 (unmapped)

3. **For each non-zero entry in the 09F79B 2nd section** (entries 56-111):
   - The entry value is a key code
   - Look up in ConvKeyToTok's secondary "2nd" table (0x05C1B0, 400 entries = 200 key codes × 2 bytes each)
   - Report: scan code index → 09F79B key code → ConvKeyToTok 2-byte token (or primary token if no 2nd override)

4. **For each non-zero entry in the 09F79B alpha section** (entries 112-167):
   - Look up in ConvKeyToTok's alpha table (0x05C3AA, 264 entries)
   - Report: scan code index → 09F79B key code → ConvKeyToTok token

5. **Special-path codes (0xE2-0xFB)**: These are mode-change tokens that bypass ConvKeyToTok. List them separately with a note that they're handled by the event loop, not tokenized.

6. **Summary statistics**:
   - Total non-zero entries checked
   - Number with valid ConvKeyToTok mappings
   - Number of special-path codes (0xE2+)
   - Number of mismatches or unmapped codes
   - Any key codes in 09F79B that fall OUTSIDE ConvKeyToTok's range (< 0x5A)
