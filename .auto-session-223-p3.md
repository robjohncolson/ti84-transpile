# Task: Trace 0x02F68A as a function in the _GetKey chain

## Context
You are working on a TI-84 Plus CE ROM transpilation project. Session 222 confirmed that 0x02F68A is CODE (a CALL target), not data. The only ROM reference is `CALL 0x02F68A` at 0x04AB91. This function is part of the _GetKey chain — _GetKey (0x04AB5D) HALTs, and the ISR delivers the key code. 0x02F68A appears to be called in the post-HALT processing path.

**ISR chain (from session 222)**:
- RST 38h (0x000038) → saves regs → IY=0xD00080 → JP 0x0006F3 → port check → JP 0x001713 → keyboard handlers 0x001296/0x001652/0x001783
- Post-HALT at 0x0019B5: reads port 0x5015 for interrupt source, bit-rotation dispatch (keyboard bit 3, timer bit 2, USB bit 4, ON bit 5)

**No scan-to-keycode lookup table was found in ROM** — the conversion is computed (arithmetic) or happens inside the 0x02F68A function chain.

## Deliverable
Create `TI-84_Plus_CE/probe-phase223-02f68a-function-trace.mjs` that:

1. **Part A: Static disassembly of 0x02F68A**
   - Read ROM.rom directly
   - Disassemble from 0x02F68A forward, ~100-200 bytes
   - Look for: RET instructions (to find function boundaries), CALL instructions (sub-functions), LD/CP/SUB/ADD on A (arithmetic on key codes), table lookups (LD A,(HL+offset) patterns), loop structures
   - Use the eZ80 decoder if available, or manual byte-pattern matching

2. **Part B: Identify the function boundary**
   - Find the RET that ends the function starting at 0x02F68A
   - Count total bytes / instructions in the function
   - List all CALL targets within the function

3. **Part C: Dynamic trace**
   - Boot the CPU (standard boot: z80 boot → kernelInit → postInit → memInit stages)
   - Set up a call to 0x02F68A with:
     - A register = a scan code (try 0x21, which is a known valid scan code for '2' key)
     - IY = 0xD00080
     - Seed the keyboard matrix at appropriate RAM location if needed
   - Execute with step limit ~500-1000 steps
   - Record: blocks visited, registers at entry/exit, any RAM writes (especially to D00824/D00826 which are key code storage variables)
   - Check if A on return contains a key code (0x5A-0xFF range = valid key codes)

4. **Part D: Test with multiple scan codes**
   - If Part C works, test with 3-4 different scan code values in A
   - Compare input A (scan code) vs output A/memory writes
   - Determine if this function performs scan→keycode conversion

## Setup pattern
Use the standard probe boot pattern. Read `probe-phase222-isr-keycode-chain.mjs` first — it traced the ISR chain and has the setup for 0x02F68A context.

Also read `probe-phase222-05c52c-internal-branching.mjs` for the standard CPU setup/boot pattern.

## Key constraints
- Use `createPeripheralBus({ timerInterrupt: false })` — timer IRQ causes infinite loop
- ROM is read-only in the transpiled runtime (writes < 0x400000 silently dropped)
- IY must = 0xD00080 for OS flag access
- MBASE = 0xD0 (default)
- `mem.fill(val, start, END)` — third arg is END, not length

## Success criteria
- Static disassembly shows the function's instruction sequence
- Function boundary (start/end) identified
- Dynamic trace shows what the function does with a scan code input
- Determination of whether 0x02F68A performs scan-to-keycode conversion
