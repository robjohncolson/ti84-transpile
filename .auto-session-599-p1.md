# Auto-session 599 P1: Instrument outer loop to find WHEN edit cursors / VRAM zero

## Context

In auto-session 598, we confirmed the character path for key '2' (D0058C=0x90) completes naturally through the outer loop at 0x08C331 in 276K steps, halting at 0x0019B5. However, after completion, the edit cursors (D0231A, D0243A) go from 0xD1A8CC/0xD1A8F8 → 0x000000, VRAM goes from 1348 → 0 non-white pixels, and the D02434 descriptor block is zeroed. We need to find EXACTLY when this wipe happens.

## Task

Create a probe `TI-84_Plus_CE/probe-phase599-wipe-tracker.mjs` that:

1. Uses the same boot sequence as `TI-84_Plus_CE/probe-phase598-char-completion.mjs` (cold boot → launch-init 0x09DD62 → paint 0x058241 → seed key → outer loop 0x08C331). Copy that probe's boot/init phases exactly.

2. In Phase 4 (outer loop), uses the `onBlock(pc)` callback to sample D0231A, D0243A, D007CA, and VRAM non-white pixel count at key points during execution. Specifically:
   - Track when D0231A transitions from non-zero to zero (record the PC and step number)
   - Track when D0243A transitions from non-zero to zero (record the PC and step number)
   - Track when D007CA transitions from non-zero to zero (record the PC and step number)
   - Sample VRAM non-white count every 50,000 steps (not every block — too expensive)
   - Record which of these key blocks were hit: 0x0585E9 (cxMain), 0x08C33D (post-dispatch), 0x062055 (display dispatcher), 0x058241 (repaint), 0x0019b5 (halt), 0x0019be (wipe trap)

3. Uses `maxSteps: 500_000` and `maxLoopIterations: 500_000` (the char path completes in 276K steps, so 500K is enough).

4. Outputs a JSON report with:
   - `wipePoints`: array of `{variable, fromValue, toValue, atPc, atStep}` for each transition
   - `vramSamples`: array of `{step, nonWhitePixels}` sampled every 50K steps
   - `keyBlockHits`: object mapping each key block address to its hit count
   - `execution`: termination reason, steps, lastPc, unique blocks

## File references

- Copy boot sequence from: `TI-84_Plus_CE/probe-phase598-char-completion.mjs`
- Same imports: `cpu-runtime.js`, `peripherals.js`, `ROM.rom`, `ROM.transpiled.js`
- Same helpers: `write24`, `read24`, `hex`, `countVramNonWhite`

## Constraints

- Do NOT modify any existing files
- Create ONLY `TI-84_Plus_CE/probe-phase599-wipe-tracker.mjs`
- Timer interrupt: OFF for boot/init phases, ON for paint and outer loop (same as probe-phase598)
- The `onBlock` callback must NOT call `countVramNonWhite` on every block (too slow) — only sample it at step milestones using a step counter variable incremented in `onBlock`
- Use `import.meta.url` / `fileURLToPath` for `__dirname`, not `require`

## Success criterion

Run the probe via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase599-wipe-tracker.mjs`

The probe should complete and print a JSON report showing exactly which PC/step caused each variable to zero. This tells us whether the wipe is from cxMain itself, from the 0x08C33D cleanup path, or from a second loop iteration.
