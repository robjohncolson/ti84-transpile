# Task: Decode range sub-dispatchers 0x099BB0 and 0x09AF4E

## Context
You are working on the TI-84 Plus CE ROM transpilation project. The OS event loop at 0x099921 has a cascading CP/JP key-code dispatcher (session 514, 38 entries). Two range handlers route the bulk of character input:
- 0x099BB0 = 2nd-function key range handler (codes ~0x30-0x3B)  
- 0x09AF4E = token/alpha range handler (codes ~0xB0-0xCD)

These handle the majority of keyboard input for character entry on the home screen.

## Your task
Create a probe file `TI-84_Plus_CE/probe-phase515-decode-range-dispatchers.mjs` that:

1. Disassembles starting at 0x099BB0 (at least 200 bytes to capture the full sub-dispatcher)
2. Disassembles starting at 0x09AF4E (at least 200 bytes)
3. For each, identify:
   - Sub-dispatch pattern (CP/JP cascades, jump tables, or other routing)
   - All CALL and JP targets
   - RAM addresses read/written
   - How these connect to the rendering pipeline or edit buffer system
4. Print the full disassembly and analysis

## Technical details
- ROM file: `TI-84_Plus_CE/ROM.rom` (4MB, load with `fs.readFileSync`)
- Use the decoder from `TI-84_Plus_CE/ez80-decoder.js` — import with:
  ```js
  import { createDecoder } from './ez80-decoder.js';
  ```
  Then: `const decoder = createDecoder(romBuffer);` and `decoder.decode(address)` returns `{mnemonic, operands, length, ...}`
- The ROM is eZ80 ADL mode (24-bit addresses). All addresses are 24-bit.
- Known references:
  - 0x099921 = parent event loop dispatcher
  - 0x09BBAD = get keycode into A
  - 0x05E2A0 = BufInsert (edit buffer insert)
  - 0x0ADAC3 = BufClr
  - 0x099914 = ParseInp entry
  - 0x0A1799 = glyph rasterizer

## Constraints
- Do NOT modify any existing files
- Do NOT import from cpu-runtime.js — use ez80-decoder.js directly with the ROM buffer
- File must be a standalone .mjs with `import` at top
- Run the probe via: `node scripts/run-probe.mjs --max-time 180 TI-84_Plus_CE/probe-phase515-decode-range-dispatchers.mjs`

## Success criteria
- Probe runs cleanly and prints disassembly of both sub-dispatchers
- The routing pattern for each is identified (how key codes map to handlers)
- Call targets and RAM accesses are documented
