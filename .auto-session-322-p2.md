# Task: Map the _seqcase Scanning Variant at 0x00211B

## Context
The TI-84 Plus CE ROM transpilation project lifts eZ80 ROM machine code into runnable JavaScript. This is a pure investigation/disassembly task — produce a report, do NOT modify any source files.

## Background
There are two _seqcase variants in the ROM:
- **0x002623** — the "sequential" variant, already well-documented. Format: `[u16 count][u24 base][count×u24 targets][u24 default]`. Used by 83 call sites.
- **0x00211B** — the "scanning" variant, used by `dispatch_key()` at 0x00883C. Format (from session 321): `[u16 count][count×{u8 key, u24 addr}][u24 default]`. This variant is NOT yet fully analyzed.

Session 321 found that dispatch_key uses the scanning variant at 0x00211B, NOT the sequential variant at 0x002623. The scanning format includes the key byte inline with each target address.

## What to Investigate

### 1. Disassemble 0x00211B fully
- Read the ROM file at `TI-84_Plus_CE/ROM.rom` (4MB binary, little-endian eZ80)
- Start disassembly at offset 0x00211B in the ROM
- The function is likely short (under 100 bytes) — trace until you hit a RET or equivalent
- Document every instruction with its address and purpose
- Key questions: How does it iterate? Does it use CPIR? Linear scan? Binary search? How does it handle the default case?

### 2. Compare with 0x002623
- Also disassemble 0x002623 briefly for comparison
- What's the algorithmic difference? (Linear scan vs jump table vs binary search)
- Performance implications: which is better for N cases?

### 3. Find all callers of 0x00211B
- Search the ROM for CALL 0x00211B (opcode CD 1B 21 00) and JP 0x00211B (opcode C3 1B 21 00)
- List all call sites with their addresses
- For each caller, note what function it's in if identifiable

### 4. Inline data format verification
- For at least 2 call sites, read the inline data that follows the CALL instruction
- Verify the format matches: [u16 count][count×{u8 key, u24 addr}][u24 default]
- Document a concrete example with actual key values and target addresses

## Tools Available
- ROM file: `TI-84_Plus_CE/ROM.rom` (read as binary)
- Use `node -e` with `fs.readFileSync` to read ROM bytes
- eZ80 is a Z80 superset with 24-bit addressing. Key opcodes:
  - `CD xx xx xx` = CALL addr24
  - `C3 xx xx xx` = JP addr24
  - `C9` = RET
  - `ED B1` = CPIR
  - `DD` prefix = IX operations
  - `FD` prefix = IY operations
