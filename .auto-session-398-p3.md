# Task: Map 0xD0058F and 0xD00587 Key Register Writers

## Context
You are working on a TI-84 Plus CE ROM (eZ80) transpilation project at `C:/Users/rober/Downloads/Projects/school/ti84-transpile`. The ROM is at `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 ADL mode).

Session 397 identified two key-related RAM addresses:
- **0xD0058F**: Read by both 0x04CA87 and 0x04CA94 (key handler lookup stubs). One byte past kbdToken (0xD0058E). Likely a preprocessed key code.
- **0xD00587**: Read by 0x03FA09 (result fetch function). This is the kbdGetKy result register.

We know WHO READS these addresses but NOT who WRITES to them. Understanding the writers reveals the key lifecycle.

## Your Task
Create a probe file `TI-84_Plus_CE/probe-phase398-key-registers.mjs` that:

1. Reads ROM.rom from disk
2. Scans the ENTIRE 4MB ROM for instructions that write to 0xD0058F and 0xD00587
3. Search patterns to look for:
   - `LD (0xD0058F),A` — bytes: 32 8F 05 D0 (little-endian 24-bit address in ADL mode)
   - `LD (0xD00587),A` — bytes: 32 87 05 D0
   - `LD (HL),<reg>` where HL might be loaded with these addresses (look for LD HL,0xD0058F = 21 8F 05 D0 and LD HL,0xD00587 = 21 87 05 D0 nearby)
   - Block writes (LDIR/LDIR) where DE points to these addresses
   - `INC (HL)` / `DEC (HL)` patterns where HL = these addresses
4. For each write site found:
   - Log the address, surrounding bytes, and decoded instruction
   - Disassemble 10 instructions before and after for context
   - Identify what value is being written (constant? computed? from another register?)
5. Also scan for reads (LD A,(0xD0058F) = 3A 8F 05 D0, LD A,(0xD00587) = 3A 87 05 D0) to build the complete reference map
6. Check the broader "key state block" 0xD00580-0xD0058F (16 bytes) for any bulk writes (LDIR with DE in this range)
7. Print summary: who writes, who reads, what values, and the inferred lifecycle
