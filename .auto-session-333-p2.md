# Task: Map the 0x023D14 Hook Iterator (Priority B — ★★★)

## Context
The TI-84 CE OS has a hook system with 24 slots. Address 0x023D14 is a function that iterates all 24 hook slots for lookup/matching. We need to understand: what's the search key? When is it called? What does a match trigger?

This is a ROM disassembly/analysis task — you will create a probe that traces the hook iterator.

## Key addresses
- **0x023D14** — the hook iterator function to trace
- **ROM file**: `TI-84_Plus_CE/ROM.rom` (4MB, eZ80 binary, little-endian)
- **IY base**: 0xD00080 (OS system flags)
- **Hook region**: typically in D-prefixed RAM addresses

## eZ80 instruction reference (for disassembly)
- `LD A,(addr)` = 0x3A followed by 3-byte LE address
- `CP n` = 0xFE followed by immediate byte
- `JR Z,offset` = 0x28 followed by signed byte
- `JR NZ,offset` = 0x20 followed by signed byte
- `CALL addr` = 0xCD followed by 3-byte LE address
- `RET` = 0xC9
- `RET Z` = 0xC8, `RET NZ` = 0xC0
- `INC HL` = 0x23, `DEC B` = 0x05
- `LD B,n` = 0x06 followed by immediate
- `LD HL,addr` = 0x21 followed by 3-byte LE address
- `PUSH`/`POP` for IX: 0xDD 0xE5/0xE1
- `LD A,(HL)` = 0x7E
- `ADD HL,DE` = 0x19
- In ADL mode, addresses are 3 bytes. In Z80 mode, 2 bytes.
- Prefix 0x49 = .LIL (ADL mode override), 0x40 = .SIS (Z80 mode override)

## What to do

1. **Read raw ROM bytes** starting at 0x023D14, at least 128 bytes. Disassemble by hand (or trace with the transpiled blocks).

2. **Create a probe** `TI-84_Plus_CE/probe-phase333-hook-iterator.mjs` that:
   - Loads the ROM and transpiled blocks
   - Creates an executor with `createPeripheralBus({ timerInterrupt: false })`
   - Boots to home screen (same sequence as probe-phase99d: BOOT_ENTRY z80 → KERNEL_INIT_ENTRY adl → POST_INIT_ENTRY adl → 4 STAGE_ENTRIES adl)
   - Uses `onBlock` callback to trace every block visited
   - Calls 0x023D14 with a sentinel return address pattern:
     ```js
     cpu.sp = STACK_RESET_TOP - 3;
     // Push sentinel return address
     mem[cpu.sp] = 0xFE; mem[cpu.sp+1] = 0xFE; mem[cpu.sp+2] = 0xFE;
     const result = executor.runFrom(0x023D14, 'adl', { maxSteps: 5000, ... });
     ```
   - Logs: entry register state, each block visited, memory reads to hook slot addresses, exit register state

3. **Also dump the hook slot table** — after boot, read RAM in the D-prefix region where hooks are stored. The hook slot area is typically near IY+offset. Scan memory for patterns that look like hook entries (3-byte addresses pointing into ROM 0x000000-0x3FFFFF).

4. **Identify**:
   - What register holds the "search key" on entry (likely A or HL)
   - How many slots are checked (expected: 24, but confirm from the loop counter)
   - What the slot structure looks like (size per entry, fields)
   - What happens on a match vs. no-match
   - Where the matched hook's handler address is loaded from

## Boot sequence (copy this exactly)
```js
const BOOT_ENTRY = 0x000000;
const KERNEL_INIT_ENTRY = 0x08C331;
const POST_INIT_ENTRY = 0x0802B2;
const STACK_RESET_TOP = 0xD1A87E;
const STAGE_ENTRIES = [0x0A2B72, 0x0A3301, 0x0A29EC, 0x0A2854];

// Boot
executor.runFrom(BOOT_ENTRY, 'z80', { maxSteps: 20000, maxLoopIterations: 32 });
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.sp = STACK_RESET_TOP - 3;
mem.fill(0xFF, cpu.sp, cpu.sp + 3);

executor.runFrom(KERNEL_INIT_ENTRY, 'adl', { maxSteps: 100000, maxLoopIterations: 10000 });
cpu.mbase = 0xD0; cpu._iy = 0xD00080; cpu._hl = 0;
cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0; cpu.sp = STACK_RESET_TOP - 3;
mem.fill(0xFF, cpu.sp, cpu.sp + 3);

executor.runFrom(POST_INIT_ENTRY, 'adl', { maxSteps: 100, maxLoopIterations: 32 });

for (const entry of STAGE_ENTRIES) {
  cpu.halted = false; cpu.iff1 = 0; cpu.iff2 = 0;
  cpu._iy = 0xD00080; cpu.f = 0x40; cpu._ix = 0xD1A860;
  cpu.sp = STACK_RESET_TOP - 12;
  mem.fill(0xFF, cpu.sp, cpu.sp + 12);
  executor.runFrom(entry, 'adl', { maxSteps: 50000, maxLoopIterations: 500 });
}
```
