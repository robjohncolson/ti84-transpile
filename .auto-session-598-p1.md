# Auto-session 598 P1: Extended character path completion probe

## Context
The TI-84 Plus CE ROM transpilation project lifts eZ80 machine code to JavaScript. Session 597 discovered that character keys (digits, letters) take a DIFFERENT path than command keys — they go through cxMain (0x0585E9) → 0x05877A → 0x058EDA, NOT through the 38-entry command dispatcher at 0x099921. Session 597 ran this path for 500K steps and hit 1917 unique blocks, but maxSteps cut it off before completion. We need to know if the character actually reaches the edit buffer.

## Task
Create a probe `TI-84_Plus_CE/probe-phase598-char-completion.mjs` that:

1. Boots the OS, runs launch-init (0x09DD62), paints the home screen (0x058241), then dispatches key '2' (D0058C=0x90, D0009F bit 5 SET) through the OUTER event loop at 0x08C331 with **2,000,000 steps** (maxSteps: 2_000_000, maxLoopIterations: 2_000_000).

2. After the run completes (or hits maxSteps), checks:
   - Did edit cursors D0231A and D0243A change from their pre-dispatch values? (Capture before/after)
   - Is there a '2' character (byte 0x32 = ASCII '2', or TI token 0x32) anywhere in the edit buffer region near D0231A?
   - VRAM check: count non-white pixels at 0xD40000+ (320×240 BGR565, white=0xFFFF). Compare to pre-dispatch count. Any increase = new content rendered.
   - Did execution terminate naturally (halt/return) or hit maxSteps?

3. Reports ALL of the following post-run state:
   - D0058C, D0058E, D0009F (key consumed?)
   - D007CA (cxMain vector — zeroed by cxMain during execution per session 597)
   - D0231A, D0243A (edit cursors before/after)
   - Edit buffer: hexdump 32 bytes starting at the post-run D0231A value
   - Edit buffer: hexdump 32 bytes starting at the post-run D0243A value
   - D02434 descriptor block: hexdump 16 bytes
   - VRAM non-white pixel count before and after
   - Termination reason and last PC
   - Total unique blocks visited

- Create ONLY `TI-84_Plus_CE/probe-phase598-char-completion.mjs`
- Use `mem.fill(val, start, start + length)` NOT `mem.fill(val, start, length)` — the 3rd arg is END not LENGTH

- write24 helper: `mem[a] = v & 0xFF; mem[a+1] = (v >> 8) & 0xFF; mem[a+2] = (v >> 16) & 0xFF;`

- VRAM is at 0xD40000, 320×240 pixels, BGR565 (2 bytes/pixel), white = 0xFFFF
- For counting VRAM pixels, iterate 320*240 words and count those != 0xFFFF
