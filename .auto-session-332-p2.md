# Task: Map the 54 BPP-Flag Reader Blocks

## Context
You are working on a TI-84 Plus CE ROM transpilation project. The ROM is at `TI-84_Plus_CE/ROM.rom` (4 MB eZ80). Session 331 fully mapped the 0x055743 mode-switch function which copies 13-byte config blocks for 16bpp vs 8bpp mode. The BPP flag is at IY+70 (address D000C6) bit 2: clear=16bpp, set=8bpp. There are 54 unique reader blocks that check this flag.

Session 331 found 3 access patterns:
- 12 blocks via `BIT 2,(IY+70)` — direct flag test
- 6 blocks via `LD A,(D000C6)` — direct byte load
- 1 block via indirect HL load (helper 0x08C308 used by graph renderer)

## Your Task
1. **Find all 54 reader blocks** that access (IY+70) bit 2 or read D000C6 to check the BPP flag. Use grep/search on the transpiled JS or ROM bytes.

2. **Group them by subsystem**. Categories:
   - Text rendering (0x052xxx-0x054xxx range)
   - Pixel writing (0x054xxx-0x056xxx)
   - Graph rendering (0x09Exxx, 0x08Cxxx)
   - LCD/VRAM management (0x055xxx)
   - Fill/rectangle operations
   - Other

3. **For each group, describe what behavior changes** between 16bpp and 8bpp. For example: does the stride double? Does the pixel format change (RGB565 vs palette index)? Does the VRAM base address change?

4. **Identify which readers are on the critical text rendering path** (the path from PutC → draw_inner → pixel writer → VRAM).

## Method
- Gunzip the transpiled JS: `node -e "const z=require('zlib'),f=require('fs'); f.writeFileSync('TI-84_Plus_CE/ROM.transpiled.js', z.gunzipSync(f.readFileSync('TI-84_Plus_CE/ROM.transpiled.js.gz')))"`
- Search for IY+70 bit 2 patterns: `grep -n "iy_plus_70\|0xD000C6\|IY.*70.*bit.*2\|d000c6" TI-84_Plus_CE/ROM.transpiled.js`
- Also search ROM bytes for the BIT 2,(IY+70) encoding: FD CB 46 56 (eZ80 encoding)
- Cross-reference block addresses with known subsystem ranges

## Deliverables
Create `TI-84_Plus_CE/probe-phase332-bpp-readers.mjs` that:
- Searches the ROM for all BIT 2,(IY+70) and LD A,(D000C6) patterns
- Groups found addresses by subsystem
- For each block, reads surrounding context to determine what the BPP check gates
- Outputs a structured table: [address, subsystem, access_pattern, behavior_difference]
