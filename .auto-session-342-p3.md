# Task: Trace 0x0A27DD — the scan code provider function

## Context
The TI-84 Plus CE OS event loop (CoorMon) at 0x08C331 calls `0x0A27DD` at address 0x08C3A8. This function returns a scan code in register A that feeds the key dispatch cascade. Understanding this function completes the GetCSC → event loop path.

## Raw bytes at 0x0A27DD (first ~50 bytes)
```
f5 c5 d5 e5 fd cb 1b 76 20 17 21 00 00 00 40 22
f6 05 3e 01 32 f5 05 d0 cd c3 d1 03 fb fd cb 12
c6 c3 36 1a 0a 40 2a 95 05 40 22 c4 07 3a 04 25
d0 32 c7
```

## What to do

1. Write a probe at `TI-84_Plus_CE/probe-phase342-scan-code-provider.mjs` that:
   - Reads `TI-84_Plus_CE/ROM.rom`
   - Disassembles the function starting at 0x0A27DD in ADL mode (24-bit)
   - Uses the eZ80 decoder from `TI-84_Plus_CE/ez80-decoder.js` (import it)
   - Decodes instructions sequentially until hitting a RET (0xC9), JP, or reasonable end (~60 bytes max)
   - Prints each instruction with address and hex bytes

2. Annotate the output with what the instructions do semantically:
   - Identify which RAM addresses are read (the scan code source)
   - Identify the IY flag checks (the `FD CB xx xx` patterns — BIT instructions on (IY+offset))
   - Identify any CALLs made and their targets
   - Identify the return path (what value is in A at RET)

3. Key things to look for:
   - `FD CB 1B 76` at the start = BIT 6,(IY+0x1B) — this is likely a "key available" flag
   - The `3E 01 32 F5 05 D0` = LD A,0x01; LD (0xD005F5),A — storing something
   - `CD C3 D1 03` = CALL 0x03D1C3 — identify what this subroutine does (read first few bytes at that address)
   - `3A 04 25 D0` near the end = LD A,(0xD02504) — this might be where the scan code is actually loaded

4. Also read a few bytes at the CALL target 0x03D1C3 to identify it:

