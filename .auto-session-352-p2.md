# Task: Disassemble 0x0158F8 Region + Furthest-Reached Blocks

## Context
After the GPIO port 0x03 fix in session 351, boot reaches PC 0x0158F8 at step 464 (within 1000 steps). We need to understand what code lives in this region — is it LCD init, memory controller setup, timer configuration, or something else? This helps predict what the next boot gate will be.

## Deliverable
Create `TI-84_Plus_CE/probe-phase352-region-0x0158F8.mjs` that:
1. Reads ROM.rom directly (raw bytes)
2. Disassembles the region 0x0158F8 - 0x015980 (136 bytes) in BOTH ADL mode and z80 mode
3. Also disassembles these blocks that session 351 identified as deep-OS-init territory:
   - 0x005B00 - 0x005B40 (64 bytes)
   - 0x005E00 - 0x005E40 (64 bytes)
4. For each region, reports:
   - Raw hex dump
   - Decoded instructions (use the decoder in `TI-84_Plus_CE/ez80-decoder.js`)
   - Any I/O port references (IN/OUT instructions) — note the port numbers
   - Any CALL/JP targets — list them
   - Any LD to/from 0xD0xxxx addresses (OS RAM variables)
   - Whether there are HALT instructions, infinite loops (JP to self), or conditional polling patterns

## Reference Files
- `TI-84_Plus_CE/ez80-decoder.js` — exports `decodeInstruction(mem, offset, mode)` which returns `{ mnemonic, operands, size, ... }`. Mode is 'adl' or 'z80'.
- `TI-84_Plus_CE/ROM.rom` — raw binary, 4MB
- `TI-84_Plus_CE/probe-phase351-gpio-boot-fix.mjs` — template for file structure/imports

## How to Use the Decoder
```javascript
import { decodeInstruction } from './ez80-decoder.js';  // adjust path as needed

const rom = fs.readFileSync(ROM_PATH);
let offset = 0x0158F8;
while (offset < 0x015980) {
  const instr = decodeInstruction(rom, offset, 'adl');
  console.log(`${hex(offset)}: ${instr.mnemonic} ${instr.operands.join(',')}`);
  offset += instr.size;
}
```

Note: The decoder file is an ES module. Import it using `pathToFileURL` pattern like the other probes do:
```javascript
const { decodeInstruction } = await import(pathToFileURL(path.join(__dirname, 'ez80-decoder.js')).href);
```

If `decodeInstruction` is not the exact export name, check the file's exports. The decoder might export a class or different function name — read the first ~50 lines to find the correct API.
